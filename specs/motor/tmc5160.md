# Chip Spec: TMC5160 (TMC5160 / TMC5160A)

**Manufacturer:** Trinamic (Analog Devices)
**Datasheet:** `datasheets/motor/tmc5160.pdf` (TMC5160/TMC5160A datasheet Rev. 1.17, 2022-MAY-25)
**Category:** `motor`
**Transports:** SPI (see `specs/transport_spi.md`) **or** UART single-wire (see `specs/transport_uart.md`) — selected at construction by `bus_type`; ENN/DIAG0/DIAG1 are plain GPIO

The TMC5160 is the high-power, external-MOSFET sibling of the TMC2130 (`specs/motor/tmc2130.md`) and
the TMC2209 (`specs/motor/tmc2209.md`). It shares their chopper (SpreadCycle / StealthChop2),
StallGuard2 / CoolStep / DcStep and microstep-table concepts and register layout, and the 40-bit
SPI datagram of the TMC2130 and the CRC-protected UART datagram of the TMC2209. What it adds — and
what makes this a different driver — is a **hardware motion controller**: an internal SixPoint
**ramp generator** with target-position and target-velocity modes, reference-switch inputs and an
ABN encoder interface. Motion is a register write (`XTARGET`, `VMAX`), no STEP pulses are needed.
See "Differences from the TMC2130".

## Overview

The TMC5160 is a stepper motor controller/driver IC with an **external power stage** (it drives
the gates of up to eight N-channel MOSFETs; motor supply 8–60 V, motor current set by the sense
resistors and `GLOBALSCALER`, up to 20 A or more per coil with suitable MOSFETs — a typical
breakout board is rated 2–3 A RMS). It combines:

- a **motion controller** (SixPoint ramp generator): positioning mode (`XTARGET`), velocity
  mode (`VMAX` with `AMAX`), hold mode, two acceleration and two deceleration phases around a
  threshold velocity `V1`, start / stop velocities, zero-wait time, on-the-fly parameter change;
- a 256-microstep sequencer with the **SpreadCycle** chopper, the silent **StealthChop2**
  voltage-PWM mode (with automatic tuning), the classic constant-off-time chopper,
  **StallGuard2** sensorless load measurement (also usable as an automatic stop event),
  **CoolStep** load-adaptive current and **DcStep** load-dependent speed control;
- two **reference-switch inputs** (`REFL` / `REFR`) with automatic stop, soft stop and position
  latching, a position-compare output and an interrupt output;
- an **ABN incremental encoder** interface with a prescaler and a deviation warning;
- an optional direct-current mode (`XDIRECT`) in which the host writes the coil currents itself,
  an optional user-programmable microstep table and detailed driver protection (short to GND /
  short to supply, over-temperature, open load, charge-pump undervoltage).

The chip has three interface configurations chosen by the `SD_MODE` and `SPI_MODE` pins:

| `SD_MODE` | `SPI_MODE` | Mode | Supported by this driver |
|-----------|------------|------|--------------------------|
| 0 | 1 | SPI + internal ramp generator | **yes** (`bus_type='spi'`) |
| 0 | 0 | UART single wire + internal ramp generator | **yes** (`bus_type='uart'`) |
| 1 | 1 | SPI configuration + external STEP/DIR source | no — the motion API needs the ramp generator; init rejects it (`IOIN.SD_MODE = 1`) |
| 1 | 0 | Stand-alone, pin-configured | no |

Both pins are hardware straps, not driver-controlled. **`SD_MODE` must be low** for this driver.

The driver talks to the chip over SPI or UART and optionally drives `DRV_ENN` and reads
`DIAG0` / `DIAG1` as GPIO. A single bus connection is sufficient to enable the driver and move
the motor.

## Transport Configuration

The constructor takes `bus_type` (`'spi'` default, or `'uart'`). Register access is identical
above the datagram layer; the two transports differ only in framing, so the driver implements
one private `_read_reg(reg)` / `_write_reg(reg, value)` pair with an SPI and a UART back end
(precedent: the `bus_type` parameter of other dual-bus drivers; see
`specs/feature_register_access_design.md`). Neither back end is a `RegisterConnection` register
bus (datagrams carry a pipelined reply or a CRC and echo); the driver wraps a plain SPI or UART
`Connection` and does its own framing.

### SPI

- **Mode:** CPOL=1 CPHA=1 (**Mode 3**; datasheet §4.3: the chip latches SDI on the rising SCK edge and drives SDO after the falling edge, SCK idles high)
- **Max clock:** 4 MHz with the internal oscillator (SCK ≤ ½ fCLK, with the 10 % margin for the on-chip oscillator already included), 8 MHz with an external 16 MHz clock. Default used by the driver: **1 MHz**
- **Bit order:** MSB first
- **CS active:** low (`CSN`). CSN must stay low for the whole 40-bit datagram and **high between datagrams** (≥ 2·t_CLK + 10 ns, i.e. ≥ 0.2 µs at 12 MHz)
- **Register addressing:** read = address byte `0x00 | reg`, write = address byte `0x80 | reg`; no multi-byte / auto-increment bit — every datagram carries exactly one 32-bit register word
- **Daisy chaining** (more than 40 clocks per CSN low) is a chip feature that is not modelled; the driver always sends exactly 40 clocks
- Configure the bus **with the Mode 3 setting of each platform** (MicroPython `polarity=1, phase=1`, CircuitPython `configure(polarity=1, phase=1)`, Linux `mode=3`, Arduino `SPI_MODE3`, Zephyr `SPI_MODE_CPOL | SPI_MODE_CPHA`, …); a wrong mode shows up as an `IOIN.VERSION` mismatch during init

#### SPI datagram format

Every access is a **40-bit datagram: 1 address byte + 4 data bytes** (data MSB first):

| Byte | Host → chip | Chip → host |
|------|-------------|-------------|
| 0 | `W \| reg` (`W` = `0x80` for write, `0x00` for read) | `SPI_STATUS` |
| 1 | `data[31:24]` | reply `[31:24]` |
| 2 | `data[23:16]` | reply `[23:16]` |
| 3 | `data[15:8]` | reply `[15:8]` |
| 4 | `data[7:0]` | reply `[7:0]` |

**Replies are pipelined by one datagram.** The data received in a datagram is the register that was
*requested by the previous datagram* (if that was a read), or a **mirror of the previously written
data word** (if that was a write). A read therefore always takes **two datagrams**: the first
carries the read request (its own reply is stale and ignored), the second delivers the data. The
second datagram must itself be a side-effect-free request — the driver uses a read of `GCONF`
(`0x00`).

```
read(reg):    D1 = [reg & 0x7F, dummy×4]     reply of D1 ignored
              D2 = [0x00,       dummy×4]     reply[1..4] = register value (big-endian)
write(reg,v): D  = [reg | 0x80, v[31:24] … v[7:0]]     no reply needed
verified write: D  as above, then
              D2 = [0x00, dummy×4]           reply[1..4] must equal v   (mirror check)
```

Test vectors (datasheet §23.1): write `CHOPCONF` (`0x6C`) = `0x000100C3` → `EC 00 01 00 C3`; write
`VMAX` (`0x27`) = `0x00030D40` → `A7 00 03 0D 40`; read `XACTUAL` (`0x21`) → D1 `21 xx xx xx xx`,
D2 `00 xx xx xx xx` whose last four reply bytes are the register.

**Reply byte 0 = `SPI_STATUS`** (bit 7 `status_stop_r`, 6 `status_stop_l`, 5 `position_reached`,
4 `velocity_reached`, 3 `standstill`, 2 `sg2`, 1 `driver_error`, 0 `reset_flag`). It is **not
reachable** through the base `Connection` contract: `write_read(data, n)` returns only the last `n`
bytes. The driver reads the same flags from `RAMP_STAT`, `DRV_STATUS` and `GSTAT` instead (Sigrok
decodes the status byte; the decoder has the whole frame).

**Why `write` for writes and `write_read([addr], 4)` for reads:** the base contract always
discards the bytes received while `data` is clocked out, which is exactly the unused status byte
for reads, and it never sends more than 40 clocks. Do **not** use `write` followed by `read` as
two separate transactions for one datagram — that would be two CSN-delimited 40-clock
transactions and the second would execute a dummy command.

**SPI read dummy bytes:** the bytes on SDI during a read request are ignored by the chip. The
SPI connection's MOSI idle level (`0xFF`, `specs/transport_spi.md`) is fine.

### UART (single wire)

- **Frame:** 8N1 (8 data bits, no parity, 1 stop bit), LSB first, most-significant datagram byte first
- **Baud rate:** auto-detected from the sync nibble of every datagram. 9 000 baud minimum (assuming the worst-case 20 MHz clock) up to `fCLK/16` (≈ 750 kBd at 12 MHz). Default 115 200. An abrupt reduction of the baud rate to less than 15 % of the previous value is not possible (datasheet §5.1.1)
- **Wiring:** `SWP` (`DIAG1_SWP`) is the non-inverted single-wire data pin; `SWN` (`DIAG0_SWN`) is its inverted twin for differential (RS-485 style) links — leave it open in a 5 V I/O system, tie it to half the I/O voltage for best performance in a 3.3 V single-wire system (datasheet §5.3). For single-wire use with a common MCU UART: MCU TX → 1 kΩ → `SWP`, MCU RX → `SWP` directly (common practice borrowed from the TMC2209; the TMC5160 datasheet does not mandate it). The pin is half-duplex: **everything the host transmits is echoed back into its own RX** in this wiring
- **Node address:** `SLAVECONF.SLAVEADDR` (register `0x03`, default 0, range 0…253). If the `SDI_CFG1` pin (`NAI`, next-address input) is high the effective address is `SLAVEADDR + 1`. Chip-chain addressing uses `SDO_CFG0` (`NAO`, next-address output, reset level high, polarity via `OUTPUT`) to enable the next chip's `NAI` so up to 255 chips can be assigned unique addresses one after another (datasheet §5.4). The constructor parameter `address` (0…254, default `0`) is the **effective** bus address the driver puts in the datagram; `255` is reserved for replies to the master and raises `ValueError`. `set_slave_address` (Full) reprograms `SLAVEADDR`
- **Multi-node buses:** with more than one chip on the UART, `SLAVECONF.SENDDELAY` must be ≥ 2 on every node (datasheet §5.1.2), otherwise a non-addressed node can detect a transmission error on a reply. The driver exposes `set_send_delay` (Full); `multi_node=True` in the constructor makes init write `SENDDELAY = 2` first
- **Not a register-addressed bus** in the `RegisterConnection` sense (datagrams carry a CRC, a sync nibble and an echo); the driver wraps a plain UART `Connection` and does its own framing

#### UART datagram format (all bytes sent LSB-first, 8N1)

**Write access — 8 bytes, host → chip:**

| Byte | Value | Meaning |
|------|-------|---------|
| 0 | `0x05` | sync nibble `0101` (low bits first on the wire) + 4 reserved bits (0, included in CRC) |
| 1 | `address` | node address |
| 2 | `reg \| 0x80` | register address with write bit |
| 3 | `data[31:24]` | high byte first |
| 4 | `data[23:16]` | |
| 5 | `data[15:8]` | |
| 6 | `data[7:0]` | |
| 7 | CRC8 | over bytes 0–6 |

**Read request — 4 bytes, host → chip:** `0x05`, `address`, `reg & 0x7F`, CRC8 (over bytes 0–2).

**Read reply — 8 bytes, chip → host:** `0x05`, `0xFF` (master address), `reg & 0x7F`, `data[31:24]`
… `data[7:0]`, CRC8 (over bytes 0–6). The chip waits `SENDDELAY` (default 8 bit times; multiples of
8 bit times) after the request before replying and releases the line four bit times after the
last stop bit. **Unlike SPI, a UART read is one request and one reply — no pipelining.**

**CRC8:** polynomial `x⁸ + x² + x¹ + 1` (`0x07`), initial value 0, bytes processed LSB first:

```
crc = 0
for byte in datagram[:-1]:
    for _ in 8:
        if ((crc >> 7) ^ (byte & 1)): crc = ((crc << 1) ^ 0x07) & 0xFF
        else:                         crc = (crc << 1) & 0xFF
        byte >>= 1
```

Test vectors (datasheet §23.1, address 1): write `CHOPCONF` = `0x000100C5` → `05 01 EC 00 01 00 C5 D3`;
read request `XACTUAL` (`0x21`) → `05 01 21 6B`. Computed with the algorithm above (not printed in
the datasheet), address 0: write `GCONF` (`0x00`) = `0x00000004` → `05 00 80 00 00 00 04 A9`; read
request `IOIN` (`0x04`) → `05 00 04 A8`. The reply CRC is checked on every read.

#### Echo handling

Because TX and RX share `SWP`, a connection in the standard wiring receives its own bytes back.
The driver option `echo` (default `true`) controls this:

- **write:** transmit 8 bytes, then consume 8 echo bytes (and verify they equal what was sent; mismatch ⇒ bus collision / corruption error).
- **read:** transmit 4 bytes, then receive 4 echo + 8 reply = 12 bytes in one `write_read(request, 12)`; discard the first 4, verify them, parse the last 8.
- With `echo = false` (separate RX/TX paths) the echo bytes are not read.

#### UART error recovery

The chip resets its receive state if more than 63 bit times pass between two start bits of one
datagram, and after any error (bad CRC, glitch of < 16 clock cycles) requires ≥ 12 bit times of bus
idle before the next datagram. On any timeout, short read or CRC mismatch the driver flushes the
receive buffer, waits ≥ 12 bit times (≥ 1.5 ms is always safe at ≥ 9 kBd) and retries **once**
before raising the error.

### Write acknowledge and integrity

| | SPI | UART |
|--|-----|------|
| Frame protection | none | CRC8 on every datagram, sync nibble |
| Write acknowledge | mirror of the written word in the *next* datagram ("verified write") | `IFCNT` increments by one per accepted write (wraps 255→0) |
| `verify=True` | D2 = `GCONF` read request, `reply == value` | read `IFCNT` before and after, must differ by exactly 1 (mod 256) |
| Identity check | `IOIN.VERSION == 0x30` | same |

A failed check raises a bus error; the driver does not retry silently on SPI (a retry of a write
is idempotent, so callers may retry). `IFCNT` is **disabled in SPI operation** (always reads 0).
The mirror is an SPI-integrity check only: the chip returns the last written word regardless of
whether the register exists or accepted it.

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| `DRV_ENN` | low | Enable input. High = power stage off, motor outputs floating; clears latched driver errors. `OutputPin`, optional `en_pin` (tie to GND on the board if not driven) |
| `SD_MODE` | low | **Must be low** (internal ramp generator). Hardware strap |
| `SPI_MODE` | high / low | High (internal pull-down) = SPI, low with `SD_MODE` low = UART. Hardware strap |
| `CSN_CFG3`, `SCK_CFG2`, `SDI_CFG1`, `SDO_CFG0` | — | SPI `CSN` / `SCK` / `SDI` / `SDO` (SPI mode). In UART mode `SDI_CFG1` = `NAI`, `SDO_CFG0` = `NAO` |
| `SWP` (`DIAG1_SWP`), `SWN` (`DIAG0_SWN`) | — | UART data (UART mode, `SPI_MODE` = 0) — they share the DIAG pins |
| `DIAG0` | low (open drain, default) / high (push-pull) | With `SD_MODE` = 0, SPI: **interrupt** output (ORed `RAMP_STAT` / `ENC_STATUS` events; `GCONF.diag0_step = 1` turns it into a half-frequency dual-edge STEP output for an external driver). Needs an external pull-up (≤ 47 kΩ) in open-drain mode. `InputPin`, optional `diag0_pin` |
| `DIAG1` | low (open drain, default) / high (push-pull) | With `SD_MODE` = 0, SPI: **position-compare** output (high while `XACTUAL = X_COMPARE`; `GCONF.diag1_dir = 1` turns it into a DIR output). `InputPin`, optional `diag1_pin` |
| `REFL_STEP`, `REFR_DIR` | per `SW_MODE.pol_stop_*` | Left / right reference-switch inputs (stop switches / home). Read through `RAMP_STAT` / `IOIN`; the driver does not need the pins. Tie to GND (or the inactive level) when unused. With `SD_MODE` = 1 they become STEP / DIR |
| `ENCA_DCIN_CFG5`, `ENCB_DCEN_CFG4`, `ENCN_DCO_CFG6` | — | ABN encoder inputs (`SD_MODE` = 0). With no encoder pull `ENCN` to GND or `VCC_IO`. `ENCA_DCIN` is also the emergency-stop input (`GCONF.stop_enable`) |
| `CLK` | — | Tie to GND for the internal ≈ 12 MHz oscillator (factory-trimmed), or supply an external clock (the chip fails over to the internal one if it disappears). `fclk_hz` tells the driver the real frequency |
| `SRAH/L`, `SRBH/L` | analog | Sense-resistor connections (Kelvin); `r_sense_ohm` tells the driver the value |
| `TST_MODE` | — | Tie to GND |
| `VCC_IO` | — | 3.3–5 V I/O supply for all digital pins (not the internal logic) |

`DIAG0` / `DIAG1` are polled through registers when not wired (`read_ramp_status`, `is_stalled`);
the pins merely avoid polling. In UART mode they are not available as GPIO at all (they carry
`SWN` / `SWP`).

### Bit Fields

#### `GCONF` (`0x00`)

| Bit | Name | Description |
|-----|------|-------------|
| 0 | `recalibrate` | 1 = zero-crossing recalibration while the driver is disabled (`DRV_ENN` high or `TOFF = 0`) |
| 1 | `faststandstill` | 1 = short standstill timeout (2¹⁸ clocks), 0 = normal (2²⁰ clocks) |
| 2 | `en_pwm_mode` | 1 = StealthChop enabled (subject to `TPWMTHRS`); switch from off to on only at standstill with `IHOLD = IRUN`. **0 = SpreadCycle only** |
| 3 | `multistep_filt` | 1 = step-input filtering for an external step source (datasheet default 1; irrelevant with the ramp generator) |
| 4 | `shaft` | 1 = inverse motor direction |
| 5 | `diag0_error` | `SD_MODE` = 1 only |
| 6 | `diag0_otpw` | `SD_MODE` = 1 only |
| 7 | `diag0_stall` / `diag0_step` | `SD_MODE` = 1: DIAG0 on stall. **`SD_MODE` = 0: 0 = DIAG0 is the interrupt output, 1 = DIAG0 is a half-frequency STEP output for an external driver** |
| 8 | `diag1_stall` / `diag1_dir` | `SD_MODE` = 1: DIAG1 on stall. **`SD_MODE` = 0: 0 = DIAG1 is the position-compare output, 1 = DIAG1 is a DIR output** |
| 9 | `diag1_index` | `SD_MODE` = 1 only |
| 10 | `diag1_onstate` | `SD_MODE` = 1 only |
| 11 | `diag1_steps_skipped` | `SD_MODE` = 1 only |
| 12 | `diag0_int_pushpull` | 0 = DIAG0 open collector (active low), 1 = push-pull (active high) |
| 13 | `diag1_poscomp_pushpull` | 0 = DIAG1 open collector (active low), 1 = push-pull (active high) |
| 14 | `small_hysteresis` | 0 = 1/16 step-frequency comparison hysteresis, 1 = 1/32 |
| 15 | `stop_enable` | 1 = emergency stop: `ENCA_DCIN` high stops the sequencer |
| 16 | `direct_mode` | 1 = coil currents written via `XTARGET` / `XDIRECT` (scaled by `IHOLD`) |
| 17 | `test_mode` | **Never set**; 0 for normal operation |

#### `IOIN` (`0x04`)

#### `SLAVECONF` (`0x03`, write-only) and `OUTPUT` (`0x04`, write-only)

`SLAVECONF` bits 7:0 `SLAVEADDR` (0…253; 254 cannot be incremented), bits 11:8 `SENDDELAY`
(`0, 1` = 8 bit times — not allowed with multiple slaves; `2, 3` = 3·8; `4, 5` = 5·8; …;
`14, 15` = 15·8 bit times). `OUTPUT` bit 0 = polarity of `SDO_CFG0` in UART mode (reset 1, used as
`NAO`).

#### `GLOBALSCALER` (`0x0B`, write-only)

Bits 7:0. `0` = full scale (treated as 256). `1…31` **not allowed for operation**. `32…255` =
32/256 … 255/256 of the maximum current. Datasheet hint: values > 128 for best results. Choose it
before tuning the other settings: it also influences the chopper hysteresis, and changing it (or
`VS`) invalidates the StealthChop automatic tuning.

#### `SHORT_CONF` (`0x09`) / `DRV_CONF` (`0x0A`) (write-only)

| Register | Bits | Name | Description |
|----------|------|------|-------------|
| `SHORT_CONF` | 3:0 | `S2VS_LEVEL` | short-to-VS detector level for the low-side FETs, 4 (most sensitive) … 15 (least); 1…3 trigger in normal operation. Reset OTP (6 or 12) |
| | 11:8 | `S2G_LEVEL` | short-to-GND detector level for the high-side FETs, 2 … 15; settings below 6 are not recommended above 52 V. Reset OTP (6 or 12) |
| | 17:16 | `SHORTFILTER` | spike-filter bandwidth: 0 = 100 ns, 1 = 1 µs (reset), 2 = 2 µs, 3 = 3 µs |
| | 18 | `shortdelay` | 0 = 750 ns, 1 = 1500 ns (must cover the bridge switching time) |
| `DRV_CONF` | 4:0 | `BBMTIME` | analog break-before-make, 0 = 100 ns … 24 = 375 ns (> 24 not recommended) |
| | 11:8 | `BBMCLKS` | digital BBM in clock cycles (≈ 83 ns each; the longer of `BBMTIME` / `BBMCLKS` rules). Reset OTP (4 or 2) |
| | 17:16 | `OTSELECT` | over-temperature shutdown level: 0 = 150 °C (reset), 1 = 143 °C, 2 = 136 °C (not above 24 V), 3 = 120 °C (not recommended) |

driver never writes them unless `configure_short_detection` / `configure_gate_driver` is called
(wrong values can destroy the power stage).

#### `IHOLD_IRUN` (`0x10`, write-only)

| Bits | Name | Description |
|------|------|-------------|
| 4:0 | `IHOLD` | Standstill current scale 0…31 = 1/32…32/32 (0 + StealthChop ⇒ freewheel / brake per `PWMCONF.freewheel`) |
| 12:8 | `IRUN` | Run current scale 0…31 (datasheet hint: use 16…31 for best microstep quality) |
| 19:16 | `IHOLDDELAY` | 0 = instant power down, 1…15 = delay per current-reduction step in units of 2¹⁸ clocks |

#### `TPOWERDOWN` (`0x11`)

Bits 7:0, reset 10. Delay after standstill (`stst`) before the current drops to `IHOLD`:
`0 … 255 · 2¹⁸` clocks (about 0 to 4 s at 16 MHz, 5.6 s at 12 MHz). A minimum of **2** is
required to allow the StealthChop automatic tuning of `PWM_OFS_AUTO`.

#### `TSTEP` (`0x12`) / `TPWMTHRS` (`0x13`) / `TCOOLTHRS` (`0x14`) / `THIGH` (`0x15`)

Bits 19:0. `TSTEP` = `fCLK / f_STEP,256` (clock periods per 1/256 microstep, independent of `MRES`);
`2²⁰ − 1` on overflow or standstill. With the motion controller, for a ramp velocity `VACTUAL = v`
the measured `TSTEP` is ≈ `2²⁴ / v` (the datasheet prints the bounds as "(2²⁴ / V) ≤ TSTEP ≤
2²⁴ / V − 1", which is self-contradictory; use `2²⁴ / v` as the working value, in units of 1/256
microstep independent of `MRES`). All velocity thresholds compare with a 1/16
hysteresis (1/32 with `small_hysteresis`): the lower switching velocity equals the setting, the
upper one is higher.

| Register | Condition |
|----------|-----------|
| `TPWMTHRS` | `TSTEP ≥ TPWMTHRS` ⇒ StealthChop (if `en_pwm_mode`) and DcStep disabled; faster ⇒ SpreadCycle. `0` disables the threshold |
| `TCOOLTHRS` | `TCOOLTHRS ≥ TSTEP ≥ THIGH` ⇒ CoolStep enabled (if configured) and StealthChop disabled; `TCOOLTHRS ≥ TSTEP` ⇒ stop-on-stall (`sg_stop`) and the stall output enabled. Without DcStep it is disabled again below this velocity |
| `THIGH` | `TSTEP ≤ THIGH` ⇒ CoolStep and StealthChop off, `vhighchm` → `chm=1, TFD=0`, `vhighfs` → full-step operation and DcStep stall detection. Stall detection is blanked for 2–3 electrical periods around the `THIGH` crossing |

#### Ramp generator registers (`0x20`…`0x2D`)

`RAMPMODE` bits 1:0: `0` positioning (all `A`, `D`, `V` parameters), `1` velocity mode to
positive `VMAX` (`AMAX`), `2` velocity mode to negative `VMAX`, `3` hold (velocity unchanged
unless a stop event occurs).

| Register | Bits | Unit | Range | Notes |
|----------|------|------|-------|-------|
| `XACTUAL` | 32, signed | µsteps | −2³¹…2³¹−1 | Modify only when homing; **in positioning mode a write starts a motion** |
| `VACTUAL` | 24, signed | µsteps / t | ±(2²³−1) | Sign = direction; negative moves to lower `XACTUAL` |
| `VSTART` | 18 | µsteps / t | 0…2¹⁸−1 | Set `VSTOP ≥ VSTART` for universal use |
| `A1` | 16 | µsteps / ta² | 0…2¹⁶−1 | First acceleration, `VSTART` → `V1` |
| `V1` | 20 | µsteps / t | 0…2²⁰−1 | `0` disables the `A1` and `D1` phases (only `AMAX`, `DMAX` used) |
| `AMAX` | 16 | µsteps / ta² | 0…2¹⁶−1 | Second acceleration `V1` → `VMAX`; the acceleration **and** deceleration of velocity mode |
| `VMAX` | 23 | µsteps / t | 0…2²³−512 | Target velocity; changeable any time; positioning needs `VMAX ≥ VSTART` |
| `DMAX` | 16 | µsteps / ta² | 0…2¹⁶−1 | Deceleration `VMAX` → `V1` |

Time reference `t = 2²⁴ / fCLK`; acceleration reference `ta² = 2⁴¹ / fCLK²` (see "Data
Conversion"). Initialise all velocity, acceleration and deceleration parameters **before**
writing `XTARGET`.

#### `VDCMIN` (`0x33`) / `DCCTRL` (`0x6E`)

`VDCMIN` bits 22:0 (only bits 22…8 are used): minimum DcStep velocity; non-zero enables DcStep
above that velocity with the ramp generator (the actual position is then derived from sensorless
commutation and fed back to `XACTUAL`); activate `sg_stop` to detect step loss. `DCCTRL`: bits
9:0 `DC_TIME` (upper PWM on-time limit for commutation, units of 1/fCLK, slightly above the blank
time), bits 23:16 `DC_SG` (maximum PWM on-time for DcStep stall detection, units of 16/fCLK,
slightly higher than `DC_TIME/16`; `0` = disabled). Both must be set for DcStep.

`round(248·sin(2π·i/1024 + π/1024)) − 1`. Move to a position where `MSCNT = 0` before rewriting
the table.

`MSCURACT`: bits 8:0 `CUR_B` (sine), bits 24:16 `CUR_A` (co-sine), two's complement ±255, raw

## Initialization Sequence

1. If `en_pin` is wired, drive `DRV_ENN` **high** (driver off). Configure the bus (SPI Mode 3, ≤ 4 MHz — or UART 8N1, 115 200 Bd by default). Wait ≥ 10 ms after `VS` / `VCC_IO` power-up (the datasheet gives no figure; use 10 ms).
2. Read `IOIN`: require `VERSION = 0x30` **and** `SD_MODE = 0`; any other `VERSION` (including `0x00` / `0xFF` from a floating or silent bus) ⇒ "device not found"; `SD_MODE = 1` ⇒ "chip is strapped for STEP/DIR operation" error.
3. UART only: with `multi_node = True` write `SLAVECONF` first (`SENDDELAY = 2`, `SLAVEADDR` = the driver's shadow, 0 after power-up; `set_slave_address` keeps the shadow current). `SLAVECONF` is write-only, so the driver cannot read the address back.
4. Read `GSTAT`, then write `0x00000007` to it to clear the power-on `reset` flag (and any stale error flag).
5. Write `GLOBALSCALER = 0` (full scale) and `IHOLD_IRUN` (`IRUN` = 31 until `set_current`, `IHOLD` = ⅓·`IRUN`, `IHOLDDELAY` = 6) and `TPOWERDOWN = 10`.
6. Write `CHOPCONF = 0x000100C3` (`TOFF = 3`, `TBL = 2`, `HSTRT = 4`, `HEND = 1`, `chm = 0` SpreadCycle, `MRES = 0` 256 microsteps, `intpol = 0`; datasheet §23.1).
7. Write `GCONF = 0x00000004` (`en_pwm_mode = 1`, no DIAG routing) and `TPWMTHRS = 500` (datasheet §23.1: StealthChop below ≈ 28 rpm of a 200-step motor at 12 MHz). `PWMCONF` keeps its reset value (`pwm_autoscale = 1`, `pwm_autograd = 1`, `pwm_freq = %00`).
8. Write the default ramp: `RAMPMODE = 0`, `VSTART = 0`, `V1 = 0`, `VSTOP = 10`, `TZEROWAIT = 0`, and the speed / acceleration registers converted from the defaults below (`set_speed(200)`, `set_acceleration(400)`).
9. Use the **verified write** for every write in steps 3–8, then read back `GCONF` and `CHOPCONF` and compare with the shadow copies; mismatch ⇒ error. Read `XACTUAL` into the position shadow.
10. Assert `DRV_ENN` low only when `enable()` is called: with `en_pin` wired init leaves the driver disabled, without it the driver is active as soon as step 6 has written `TOFF ≠ 0`. `enable()` waits **150 ms** afterwards: the StealthChop automatic tuning needs > 130 ms standstill at `IRUN` (datasheet §7.1) before the first move.

## Implementation Stages

### Minimal

Goal: bring the driver up on SPI or UART and move the motor to a position or at a velocity with a
given current — no knowledge of chopper or ramp registers required. The motion controller does the
work: every move command returns immediately (except the explicitly blocking `move`).

Constructor: `TMC5160Minimal(connection, bus_type='spi', r_sense_ohm=0.075, en_pin=None, address=0, echo=True, multi_node=False, fclk_hz=12_000_000)`.
`connection` is the SPI connection (Mode 3) or the UART connection. `r_sense_ohm` is the
**external sense resistor value** (0.075 Ω is typical on common breakout boards, e.g. the
BigTreeTech TMC5160 and Watterott SilentStepStick-5160) used to convert amperes to the current
scale; it is the one value the user must know. `address`, `echo` and `multi_node` apply to UART only (ignored for
SPI). `fclk_hz` is the real chip clock (12 MHz internal oscillator, or the external clock); it
scales every velocity, acceleration and time conversion. An unknown `bus_type` raises `ValueError`.

**Position and velocity units are full steps** (`usc` = 256 microsteps per full step at the fixed
`MRES = 0`): positions in full steps (`float`), velocities in full steps per second, accelerations
in full steps per second². The internal registers hold microsteps.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | — | — | Initialization Sequence with the defaults below; part of the constructor |
| `enable` | — | — | Power stage on (`en_pin` low; `TOFF` stays set); then waits 150 ms so StealthChop can set the initial current before the first move |
| `disable` | — | — | Power stage off (`en_pin` high, or `TOFF = 0` when no pin); motor outputs float |
| `set_current` | `rms_a: float` | — | Run current in A RMS; hold current ⅓ of it; quantised to the nearest scale step. Sets `GLOBALSCALER` and `IRUN`/`IHOLD` (see Data Conversion); `ValueError` if above the sense-resistor maximum or below the minimum |

### Differences from the TMC2130

| Aspect | TMC2130 | TMC5160 |
|--------|---------|---------|
| Power stage | internal MOSFETs, 1.2–1.4 A RMS, 5.5–46 V | **external MOSFETs**, 8–60 V, current set by sense resistors + `GLOBALSCALER` |
| Motion | none (STEP/DIR or `XDIRECT`) | **internal SixPoint ramp generator** (`XTARGET`, `VMAX`, `AMAX`, …); STEP/DIR only with `SD_MODE` high |
| Control bus | SPI Mode 3 only | SPI Mode 3 **or** UART single wire (CRC8, echo) |
| Identity | `IOIN.VERSION = 0x11` | `IOIN.VERSION = 0x30`, plus `SD_MODE` strap bit |
| `IOIN` bits | `STEP`, `DIR`, `DCEN`, `DCIN`, `ENN`, `DCO`, bit 6 = 1 | `REFL`, `REFR`, `ENCB`, `ENCA`, `DRV_ENN`, `ENCN`, `SD_MODE` (bit 6), `SWCOMP_IN` |
| `GSTAT` clear | read | write 1 |
| `GCONF` bits 7/8 | `diag0_stall` / `diag1_stall` | with the ramp generator (`SD_MODE` = 0): `diag0_step` / `diag1_dir` (STEP/DIR *outputs*; 0 = interrupt / position-compare) |
| Current setting | `vsense`, `IRUN`; sense adder 20 mΩ | `GLOBALSCALER` + `IRUN`; **no** `vsense`, **no** sense adder; `V_FS = 0.325 V` |
| `CHOPCONF` | `SYNC` [23:20], `rndtf` | `TPFD` [23:20] (passive fast decay), `diss2vs`; no `SYNC`, no `rndtf` |

## Data Conversion

```
# Motor current (datasheet §9; V_FS = 0.325 V; R_sense = the sense resistor, no adder)
GS_eff   = 256 if GLOBALSCALER == 0 else GLOBALSCALER
I_rms    = (GS_eff / 256) * ((CS + 1) / 32) * V_FS / R_sense / sqrt(2)
I_max    = V_FS / (R_sense * sqrt(2))                              (GS_eff = 256, CS = 31)
I_motor  = (GS_eff / 256) * (CUR_A/B / 248) * ((CS + 1) / 32) * V_FS / R_sense      (instantaneous)
```

`R_sense = 0.075 Ω` → `I_max = 3.06 A` RMS (datasheet table for the nearest standard value,
0.075 Ω: 3.1 A RMS / 4.4 A peak). The datasheet table: 0.22 Ω → 1.1 A, 0.15 → 1.6, 0.12 → 2.0,
0.10 → 2.3, 0.075 → 3.1, 0.066 → 3.5, 0.05 → 4.7, 0.033 → 7.1, 0.022 → 10.6 A RMS.

**`set_current(rms_a)`:** `r = rms_a / I_max`, `ValueError` if `r > 1` or `r < 1/64` (below the
resolution of the `IRUN` scale at `GLOBALSCALER = 128`).

```
if r >= 0.5:    IRUN = 31,  GLOBALSCALER = round(256 * r)           (128…256; 256 is written as 0)
else:           GLOBALSCALER = 128,  IRUN = round(64 * r) - 1       clamped to 0…31
IHOLD = IRUN // 3
```

Rationale: datasheet hints — `GLOBALSCALER` > 128 and `IRUN` 16…31 give the best microstep
quality; below `r = 0.5` both cannot hold, so the global scaler is pinned at the 128 floor and
`IRUN` shrinks. Example, `R_sense = 0.075 Ω`, 2.0 A: `r = 0.654` → `IRUN = 31`, `GLOBALSCALER =
167`. 0.5 A: `r = 0.163` → `GLOBALSCALER = 128`, `IRUN = round(10.45) − 1 = 9`. After changing
`GLOBALSCALER` the StealthChop auto-tune must settle again: `set_current` should be called
before `enable()`; a call while enabled is allowed and simply re-tunes.

```
# Ramp generator units (datasheet §12.1), usc = 256 >> MRES (256 with MRES = 0), fCLK = fclk_hz
v_usteps_per_s  = v_full_steps_per_s * usc
v_reg           = v_usteps_per_s * 2^24 / fCLK                    (= v / (fCLK/2 / 2^23))
a_usteps_per_s2 = a_full_steps_per_s2 * usc
a_reg           = a_usteps_per_s2 * 2^41 / fCLK^2                 (= a / (fCLK^2 / (512*256) / 2^24))
position_reg    = round(position_full_steps * usc)
TZEROWAIT_reg   = round(seconds * fCLK / 512)
ramp update rate = fCLK / 512                                     (≈ 23.4 kHz at 12 MHz; VACTUAL updates at this rate)
```

At 12 MHz: 1 `VMAX` unit = 0.7153 µsteps/s (200 000
→ 143 051 µsteps/s = 559 full steps/s); 1 `AMAX` unit = 65.48 µsteps/s². Defaults at 12 MHz
and `usc = 256`: `set_speed(200)` → `VMAX = 71 583`; `set_acceleration(400)` → `AMAX = A1 = DMAX =
D1 = 1 564`. Register range checks raise `ValueError` (`VMAX ≤ 2²³ − 512`, accelerations ≤ 2¹⁶ − 1,
`VSTART`/`VSTOP` ≤ 2¹⁸ − 1, `V1` ≤ 2²⁰ − 1). `VSTOP ≥ VSTART` is enforced; `VSTOP ≥ 1`, `D1 ≥ 1`.
`velocity()` = `VACTUAL · (fCLK/2 / 2²³) / usc`.

```
# Velocity thresholds (TSTEP units = fCLK cycles per 1/256 microstep)
TSTEP(v)          = fCLK / (v_full_steps_per_s * 256)         v in full steps/s; microstep resolution does not matter
TPWMTHRS (500 @ 12 MHz) → 93.75 full steps/s ≈ 28 rpm for a 200-step motor
TPOWERDOWN_s      = TPOWERDOWN * 2^18 / fCLK                  (datasheet: "0…(2^8-1) * 2^18 t_CLK")
IHOLDDELAY step   = IHOLDDELAY * 2^18 / fCLK per current decrement
```

```
# StallGuard2 / CoolStep (identical to the TMC2130)
stall (stop event / DRV_STATUS.StallGuard)  when  SG_RESULT = 0  and  TSTEP <= TCOOLTHRS     (SpreadCycle only)
CoolStep raises current when SG_RESULT <  SEMIN * 32
CoolStep lowers current when SG_RESULT >= (SEMIN + SEMAX + 1) * 32
sgt raises  → less sensitive (needs more load);  sgt lowers → more sensitive;  start at 0
```

The internal oscillator is factory-trimmed to ≈ 12 MHz (`FCLKTRIM`); `fclk_hz` defaults to 12 MHz.
For exact velocities and chopper timing use an external clock or calibrate it by comparing a
measured `TSTEP` at a known `VMAX`. A 16 MHz external clock moves the `pwm_freq` and every
time constant above.

Signed fields (`XACTUAL`, `XTARGET`, `VACTUAL`, `XLATCH`, `X_ENC`, `ENC_LATCH`, `XDIRECT` 9 bit,
`MSCURACT` 9 bit, `COOLCONF.sgt` 7 bit, `PWM_SCALE_AUTO` 9 bit, `OFFSET_READ` bytes) are
sign-extended two's complement; mask both source bytes before combining when reading into
JVM/Kotlin types.

A **sensorless homing and positioning** routine for a linear axis. The demo enables the driver
at 1.5 A, reads `IOIN.VERSION` (`0x30`) and `SD_MODE` to prove the link, and switches to
SpreadCycle (`set_chopper_mode(True)`) because StallGuard2 does not work in StealthChop. It
sets `sgt = 0` (`set_stall_threshold`), sets `TCOOLTHRS` slightly above the `TSTEP` of the homing
velocity, enables the automatic stall stop (`enable_stall_stop(True)`) and runs toward the end
stop in velocity mode at 150 full steps/s (`run(-150)`), waiting 0.5 s first so stall detection
is valid. When `read_ramp_status()["event_stop_sg"]` goes true the motion controller has already
stopped the motor by itself; the demo clears the event (`clear_ramp_events()`), disables the stall
stop, defines the position as zero (`set_position(0)`), then backs off to 20 full steps with
`move_to` and prints the ramp (position, velocity from `velocity()`, `read_stallguard()`) while it
moves. It then programs a two-phase ramp (`configure_ramp(vstart=0, a1=1200, v1=200, amax=600,
vmax=500, dmax=900, d1=1500, vstop=10)`) and makes three positioning moves of 400 full steps
(timed with `wait_until_reached`), enables CoolStep (`configure_coolstep(semin=5, semax=2,
seup=1, sedn=1, seimin=0)`) for the last move to show `read_current_scale()` drop as the load
falls, and finishes with `read_status()` and `read_global_status()`. If `read_fault()` becomes
non-zero at any point, the demo stops, disables the driver, prints which fault fired and exits.

## Timing Constraints

- **SPI datagram duration (`datagram`):** a 40-bit datagram takes at least 10 µs from CSN falling
  to CSN rising (40 SCK clocks at the maximum 4 MHz internal-clock SCK rate). A shorter frame
  means the host exceeded the SCK limit and the chip may mis-latch. Sigrok annotation pair:
  `datagram_start` / `datagram_end`.
- **UART read reply delay (`reply_delay`):** after the last stop bit of a read request the chip
  waits `SENDDELAY` (default 8 bit times) before sending the first reply byte. At 115 200 baud
  (8.68 µs bit time) the default is ≈ 69 µs; a conformance bound of 100 µs applies at that baud
  rate and default `SENDDELAY`. Sigrok annotation pair: `read_request_end` / `read_reply_start`.
- **CSN high time (SPI):** ≥ 2·t_CLK + 10 ns (≈ 0.2 µs at 12 MHz) between datagrams; every SPI
  peripheral meets it with the usual CS toggling.
- **UART inter-byte gap:** ≤ 63 bit times between start bits within one datagram; longer resets
  the chip's receiver. **Recovery:** ≥ 12 bit times of idle after any error.
- **Ramp-generator update:** `fCLK / 512` (≈ 43 µs); a parameter written during a motion takes
  effect on the next update. `position_reached` may still read the *old* state for one update
  after writing `XTARGET`; the driver waits ≥ 1 ms before the first poll.
- **Standstill power-down:** `TPOWERDOWN · 2¹⁸ · t_CLK` after the last step (≈ 22 ms per count at
  12 MHz), then `IHOLDDELAY · 2¹⁸ · t_CLK` per current decrement. Autonomous.
- **StealthChop start-up:** > 130 ms standstill at `IRUN` after StealthChop is first switched on
  (128 chopper periods) to initialise `PWM_OFS_AUTO`; then ≈ 8 full steps per ±1 change of
  `PWM_GRAD_AUTO`. The driver's `enable()` waits 150 ms. Autonomous afterwards.
- **StallGuard2 update rate:** once per full step; stall detection is only valid above the
  `TCOOLTHRS` velocity. Autonomous.
- **Power-up:** apply `VS` and `VCC_IO` before the first datagram; allow ≥ 10 ms (datasheet gives
  no figure) for the oscillator and charge pump.

## Implementation Notes

- **Two transports, one register layer.** Everything above `_read_reg` / `_write_reg` is
  transport-independent. SPI reads are two datagrams (stale reply ⇒ most common bug: forgetting
  the second datagram returns the previous register or the previous write's mirror); UART reads
  are request + reply with CRC and echo. The second SPI datagram is always a harmless `GCONF`
  read request, never a clear-on-write register.
- **`GSTAT` is cleared by writing 1** to the bit, not by reading (unlike the TMC2130). `reset`
  set later means the chip lost its configuration (brown-out): the driver does not re-initialise
  automatically but exposes `reset` so the caller can.
- **Write-only registers** (`SLAVECONF`, `OUTPUT`, `X_COMPARE`, `SHORT_CONF`, `DRV_CONF`,
  `GLOBALSCALER`, `IHOLD_IRUN`, `TPOWERDOWN`, `TPWMTHRS`, `TCOOLTHRS`, `THIGH`, `VSTART`, `A1`,
  `V1`, `AMAX`, `VMAX`, `DMAX`, `D1`, `VSTOP`, `TZEROWAIT`, `VDCMIN`, `ENC_CONST`,
  `ENC_DEVIATION`, `MSLUT*`, `COOLCONF`, `DCCTRL`, `PWMCONF`) cannot be read back. The driver
  shadows every value it writes (needed for the read-modify-write of fields) and exposes none of
  them through `read_register`. `GCONF`, `CHOPCONF`, `SW_MODE`, `ENCMODE` are readable and their
  shadows are verified at init.
- **Positioning mode is order sensitive.** Write all velocity, acceleration and deceleration
  parameters first, then `RAMPMODE = 0`, **then** `XTARGET` — the XTARGET write starts the
  motion. `D1` and `VSTOP` must be non-zero or the ramp never terminates. `VSTOP ≥ VSTART`.
- **Early stop options** (datasheet §12.2.4): `stop()` switches to velocity mode and sets
  `VMAX = 0` (decelerates with `AMAX`). Positioning-mode stop via `D1` / `DMAX` is done by
  copying `XACTUAL` to `XTARGET` (`move_to(position())`), which uses the full deceleration ramp;
  the driver exposes this as `move_to`, not a separate method.
- **Velocity mode does not use `A1`/`D1`:** it uses `AMAX` for both directions of acceleration.
  Set `VMAX = 0` to stop; `vzero` signals standstill.
- **Do not write `XACTUAL` in positioning mode without writing `XTARGET`**: a changed `XACTUAL`
  starts a motion. `set_position` writes both (target := actual) so nothing moves.
- **Direct mode shares `0x2D`:** with `GCONF.direct_mode = 1`, `XTARGET`'s address is the
  `XDIRECT` coil-current register. Do not mix `move_to` and `set_coil_currents`;
  `set_coil_currents` requires direct mode and `set_direct_mode(False)` restores positioning
  (the driver rewrites `XTARGET` with the shadow to avoid an unintended motion).
- **StallGuard2 needs SpreadCycle** (`en_pwm_mode = 0`, or `TSTEP < TPWMTHRS`), `TSTEP ≤ TCOOLTHRS`,
  and a velocity where back-EMF is meaningful. `sg_stop` must not be enabled during spin-up;
  program `TCOOLTHRS` first. Re-tune `sgt` after changing the run current, microstepping or
  supply voltage. `SG_RESULT` at standstill is chopper on-time, not load. Do not combine soft
  stop with `sg_stop`.
- **Soft stop and StealthChop:** use soft stop (`en_softstop`) with StealthChop at high speed;
  a hard stop there can cause severe overcurrent. The driver's `stop()` always decelerates.
- **`GLOBALSCALER` and tuning order:** set the current (`GLOBALSCALER`, `IRUN`) before tuning the
  chopper: it influences the chopper hysteresis and invalidates StealthChop auto-tuning when
  changed later. Values 1…31 are forbidden.
- **`TOFF = 0` disables the driver** (all bridges off). `disable()` without an `DRV_ENN` pin
  writes `CHOPCONF` with `TOFF = 0`; `enable()` restores the shadowed `TOFF`.
- **`DIAG0` / `DIAG1` are open drain by default (active low)** and need external pull-ups; the
  driver does not enable push-pull unless asked via `configure_diag`. `DIAG0` is also pulled low
  during reset regardless of configuration. In UART mode these pins are `SWN` / `SWP`.
- **External MOSFET power stage:** `SHORT_CONF` and `DRV_CONF` depend on the MOSFETs and sense
  resistors. The reset values (partly OTP-selected) work for the TMC5160 evaluation board; for
  other boards consult the board vendor. The driver never touches them unless asked.
- **UART echo:** with the usual single-wire connection TX and RX see each other. The driver
  validates the echo; a mismatch means a collision or a miswired pull-up.
- **UART multi-node chains:** `SLAVEADDR` of a freshly powered chip is 0 and `NAO` is high;
  assign addresses one chip at a time (datasheet §5.4). `set_slave_address` changes the address
  immediately — the acknowledge for that very write comes from the *old* address.
- **Open-load flags are unreliable** at standstill and high velocity (datasheet):
  `FAULT_OPEN_LOAD` is informative only. Short-to-GND / short-to-supply flags latch until
  `TOFF = 0` or `DRV_ENN` high.
- **`MSCURACT` order:** bits 8:0 `CUR_B` (sine), bits 24:16 `CUR_A` (co-sine);
  `read_coil_currents` returns `(CUR_A, CUR_B)`.
- **`TSTEP` with the motion controller** relates to the microstep rate of the ramp generator and
  is the basis of all `T…THRS` comparisons; in DcStep mode it shows the per-microstep velocity,
  which is not stable.
- **`MRES` and the ramp unit:** the ramp generator always counts in units of one sequencer input
  step; with `MRES = n` one full step is `256 >> n` such units. The driver's `usc` tracks `MRES`.
  `intpol` helps only with an external STEP/DIR source.
- **The register-reset values in the datasheet are partly implicit:** printed defaults are
  `CHOPCONF` (`0x10410150`), `PWMCONF` (`0xC40C001E`), `TPOWERDOWN` (10), `VSTOP` (1),
  `ENC_CONST` (1.0), `MSLUTSTART`'s `START_SIN90` (247), `SHORTFILTER` (`%01`), `shortdelay` (0),
  `BBMTIME` (0); the other zeros come from the "all registers become reset to 0 upon power up"
  note.
- **SPI status byte** is discarded by the base `Connection` contract (see SPI datagram format);
  do not extend the transport for it.
- **Shared SPI bus:** SDO is tristate when CSN is high, so the chip can share MISO with other
  devices.

## Sigrok Decoder

Decoder id `tmc5160`, `inputs = ['spi', 'uart']` (precedent: `sigrok/l3gd20h` with `['i2c', 'spi']`).
It detects the transport from the stacked decoder's output type.

**SPI** (stacked on the sigrok `spi` decoder, Mode 3, 8 bits per word, MSB first): groups the
five bytes between CSN edges into one datagram and annotates the host request (`R`/`W` bit,
register name, 32-bit value) and the chip reply. It remembers the previous datagram, so the five
MISO bytes are labelled "reply to `<previous register>` read" or "mirror of write `<value>`", and
the status byte is decoded to `status_stop_r`, `status_stop_l`, `position_reached`,
`velocity_reached`, `standstill`, `sg2`, `driver_error`, `reset_flag`.

**UART** (stacked on the sigrok `uart` decoder, 8N1, any baud ≥ 9 kBd; the single-wire bus shows
the host datagram and the chip reply on the same line, so the decoder assumes a half-duplex
capture on one channel or a RX/TX pair merged by the user): reassembles 4-byte read requests,
8-byte write datagrams and 8-byte read replies (skipping the host echo), checks the sync nibble
and the CRC8 (annotating a CRC failure), shows the node address (or `0xFF` for replies).

Common to both: names every register of the register map and decodes bit fields for `GCONF`,
`GSTAT`, `IOIN` (incl. `VERSION`), `SLAVECONF`, `SHORT_CONF`, `DRV_CONF`, `IHOLD_IRUN`,
`RAMPMODE`, `SW_MODE`, `RAMP_STAT`, `ENCMODE`, `ENC_STATUS`, `COOLCONF` (signed `sgt`),
`CHOPCONF` (microstep count from `MRES`), `DRV_STATUS`, `PWMCONF`, plus computed values (current
scale fraction, signed `XACTUAL` / `XTARGET` / `VACTUAL`, signed `MSCURACT`, `SG_RESULT`). Emits
`OUTPUT_ANN` and `OUTPUT_PYTHON` per `specs/sigrok_annotations.md`.

The `timing` annotation row carries the conformance pairs `datagram_start` (CSN falling edge) /
`datagram_end` (CSN rising edge) for SPI and `read_request_end` / `read_reply_start` for UART,
shaped per the Variable-Length Annotation Convention. Timing config
`specs/motor/tmc5160_timing.conf`: `datagram_min_us=10`, `datagram_samplerate=24m`,
`datagram_capture_ms=300` (SCK ≤ 4 MHz), `reply_delay_max_us=100`, `reply_delay_samplerate=4m`,
`reply_delay_capture_ms=500` (115 200 baud, default `SENDDELAY`). The conformance checker
applies whichever pair appears in the capture.
