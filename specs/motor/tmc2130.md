# Chip Spec: TMC2130

**Manufacturer:** Trinamic (Analog Devices)  
**Datasheet:** `datasheets/motor/tmc2130.pdf` (TMC2130 datasheet Rev. 1.15, 2022-MAY-31)  
**Category:** `motor`  
**Transports:** SPI (see `specs/transport_spi.md`); STEP/DIR/ENN/DIAG0/DIAG1 are plain GPIO

The TMC2130 is the SPI-controlled predecessor of the UART-controlled TMC2208/TMC2209
(`specs/motor/tmc2208.md`, `specs/motor/tmc2209.md`). It shares their chopper, StealthChop,
CoolStep and microstep concepts but differs in the control bus, in the register map and — most
importantly for a driver author — in **how the motor is moved**: it has **no internal step
generator (`VACTUAL`)**, so motion comes from STEP/DIR pulses (or from direct coil-current
writes, `XDIRECT`). See "Differences from the TMC2209".

## Overview

The TMC2130 is a high-voltage two-phase bipolar stepper motor driver (motor supply 5.5–46 V,
1.2 A RMS per coil in QFN36, 1.4 A RMS in TQFP48, 2.0 A peak, 2.5 A short-term peak) with a
STEP/DIR interface, a 256-microstep sequencer with the MicroPlyer interpolator, the silent
**StealthChop** voltage-PWM mode, the **SpreadCycle** and classic constant-off-time chopper
modes, **StallGuard2** sensorless load measurement, **CoolStep** load-adaptive current,
**DcStep** load-dependent speed control, an optional user-programmable microstep table and a
direct-current mode in which the host writes the two coil currents itself. Stand-alone
(`SPI_MODE` pin low) it is configured by tristate pins only; this driver always uses the SPI
mode (`SPI_MODE` pin **high** / open, it has an internal pull-up).

The driver talks to the chip over SPI and drives the STEP / DIR / ENN pins as GPIO. Because the
chip cannot generate steps itself, `STEP` and `DIR` are required for normal motion.

## Transport Configuration

### SPI
- **Mode:** CPOL=1 CPHA=1 (**Mode 3**; datasheet §4.3: the chip latches SDI on the rising SCK edge and drives SDO after the falling edge, SCK idles high)
- **Max clock:** 4 MHz when the chip runs from its internal oscillator (SCK ≤ ½ fCLK with the lowest oscillator frequency, 10 % margin already included); 8 MHz with an external 16 MHz clock. Default used by the driver: **1 MHz**
- **Bit order:** MSB first
- **CS active:** low (`CSN`). CSN must stay low for the whole 40-bit datagram and **high between datagrams** (≥ 2·t_CLK + 10 ns, i.e. ≥ 0.2 µs at 12 MHz)
- **Register addressing:** read = address byte `0x00 | reg`, write = address byte `0x80 | reg`; **no multi-byte/auto-increment bit** — every datagram carries exactly one 32-bit register word. Not a `RegisterConnection` register bus (see "Datagram format"): the driver wraps a plain SPI `Connection` and does its own 5-byte framing
- **Daisy chaining** (more than 40 clocks per CSN low) is a chip feature that is not modelled; the driver always sends exactly 40 clocks
- Configure the bus **with the Mode 3 setting of each platform** (MicroPython `polarity=1, phase=1`, CircuitPython `configure(polarity=1, phase=1)`, Linux `mode=3`, Arduino `SPI_MODE3`, Zephyr `SPI_MODE_CPOL | SPI_MODE_CPHA`, …); a wrong mode shows up as `IOIN.VERSION` mismatch during init

### Datagram format

Every access is a **40-bit datagram: 1 address byte + 4 data bytes** (data MSB first):

| Byte | Host → chip | Chip → host |
|------|-------------|-------------|
| 0 | `W \| reg` (`W` = `0x80` for write, `0x00` for read) | `SPI_STATUS` |
| 1 | `data[31:24]` | reply `[31:24]` |
| 2 | `data[23:16]` | reply `[23:16]` |
| 3 | `data[15:8]` | reply `[15:8]` |
| 4 | `data[7:0]` | reply `[7:0]` |

**Replies are pipelined by one datagram.** The data received in a datagram is the register that was
*requested by the previous datagram* (if that was a read), or a **mirror of the previously written
data word** (if that was a write). A read therefore always takes **two datagrams**: the first
carries the read request (its own reply is stale and ignored), the second delivers the data. The
second datagram must itself be a side-effect-free request (the driver uses a read of `GCONF`,
`0x00`) — never a read of `GSTAT`, which clears on read.

```
read(reg):    D1 = [reg & 0x7F, dummy×4]     reply of D1 ignored
              D2 = [0x00,       dummy×4]     reply[1..4] = register value (big-endian)
write(reg,v): D  = [reg | 0x80, v[31:24] … v[7:0]]     no reply needed
verified write: D  as above, then
              D2 = [0x00, dummy×4]           reply[1..4] must equal v   (mirror check)
```

Test vector, write `CHOPCONF` (`0x6C`) = `0x140100C3` → `EC 14 01 00 C3`; read `IOIN` (`0x04`) →
D1 `04 xx xx xx xx`, D2 `00 xx xx xx xx` whose last four reply bytes are the register.

**Reply byte 0 = `SPI_STATUS`** (bit 3 `standstill`, bit 2 `sg2` StallGuard flag, bit 1 `driver_error`,
bit 0 `reset_flag`). It is **not reachable** through the base `Connection` contract:
`write_read(data, n)` returns only the last `n` bytes. The driver therefore reads these flags
from `DRV_STATUS` and `GSTAT` instead. (Sigrok decodes the status byte; the decoder has the whole
frame.)

**Why `write` for writes and `write_read([addr], 4)` for reads:** the base contract always
discards the bytes received while `data` is clocked out, which is exactly the unused status byte
for reads, and it never sends more than 40 clocks. Do **not** use `write` followed by `read` as
two separate transactions for one datagram — that would be two CSN-delimited 40-clock
transactions and the second would execute a dummy command. A write datagram's received bytes
are simply not read.

**SPI read dummy bytes:** the bytes on SDI during a read request are ignored by the chip. The
SPI connection's MOSI idle level (`0xFF`, `specs/transport_spi.md`) is fine.

### Error handling
There is no CRC or counter. SPI-level integrity is checked by (a) `IOIN.VERSION == 0x11` at init
(a floating or miswired SDO reads `0xFF…`/`0x00…`) and (b) the write mirror in "verified write".
A failed check raises a bus error; the driver does not retry silently (a retry of a write is
idempotent, so callers may retry).

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| `ENN` (`DRV_ENN_CFG6`) | low | Enable input. High = power stage off, motor freewheels; resets latched driver errors. `OutputPin`, optional `en_pin` (tie to GND on the board if not driven) |
| `STEP` | rising edge (both with `dedge`) | One microstep per pulse. `OutputPin`, **required for normal motion** (`step_pin`) |
| `DIR` | — | Direction. `OutputPin`, **required for normal motion** (`dir_pin`); sampled 20 ns before / held 20 ns after the STEP edge |
| `DIAG0` | low (open drain, default) / high (push-pull) | Configurable: reset (always low during reset), driver error, over-temperature pre-warning, stall. Needs an external pull-up (≤ 47 kΩ) in open-drain mode. `InputPin`, optional `diag0_pin` |
| `DIAG1` | low (open drain, default) / high (push-pull) | Configurable: stall, index, chopper on-state, steps skipped (DcStep). `InputPin`, optional `diag1_pin` |
| `SPI_MODE` | high | **Must be high (or open — internal pull-up) for SPI mode**; low selects stand-alone tristate configuration. Hardware strap, not driver-controlled |
| `CLK` | — | Tie to GND for the internal ≈ 12 MHz oscillator, or supply 4–18 MHz. `fclk_hz` constructor parameter tells the driver the real frequency |
| `AIN_IREF` | analog | Analog current reference (0.5–2.4 V) when `GCONF.I_scale_analog = 1`; reference current for internal sense resistors when `GCONF.internal_Rsense = 1`. Open ≈ 2.5 V |
| `DCEN_CFG4`, `DCIN_CFG5`, `DCO` | — | DcStep enable / gating input / ready output. Tie `DCEN` to GND when DcStep is not used. Not driver-controlled |
| `TST_MODE` | — | Tie to GND |
| `VCC_IO` | — | 3.0–5.25 V I/O supply for all digital pins |

With no `step_pin`/`dir_pin` the driver can still be configured and read, and the motor can
still be moved with `XDIRECT` (Full, `set_coil_currents`). Stalls are detected by polling
`DRV_STATUS` (`read_stallguard`, `is_stalled`) when no DIAG pin is wired.

## Register Map

Add `0x80` to the address for write accesses (the datagram builder does this). **All registers
reset to 0 on power-up unless noted** — in particular `CHOPCONF.TOFF = 0` (driver off) and
`IHOLD_IRUN = 0` (1/32 current) until the host configures them.

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | GCONF | R/W | `0x00000000` | Global configuration |
| `0x01` | GSTAT | R+C | — | Global status flags (**cleared by reading**) |
| `0x04` | IOIN | R | — | Input pin states + `VERSION` |
| `0x10` | IHOLD_IRUN | W | `0` | Hold / run current scale, `IHOLDDELAY` |
| `0x11` | TPOWERDOWN | W | `0` | Delay from standstill to power down |
| `0x12` | TSTEP | R | — | Time between 1/256 microsteps (20 bit) |
| `0x13` | TPWMTHRS | W | `0` | Upper velocity for StealthChop (20 bit) |
| `0x14` | TCOOLTHRS | W | `0` | Lower velocity for CoolStep and StallGuard `DIAG` output (20 bit) |
| `0x15` | THIGH | W | `0` | Upper velocity for chopper / full-step switching (20 bit) |
| `0x2D` | XDIRECT | R/W | `0` | Direct coil currents (`direct_mode`): coil A [8:0], coil B [24:16], signed |
| `0x33` | VDCMIN | W | `0` | DcStep minimum velocity (23 bit) |
| `0x60`…`0x67` | MSLUT[0…7] | W | sine table | Microstep table (8 × 32 bit) |
| `0x68` | MSLUTSEL | W | sine table | Microstep table segmentation |
| `0x69` | MSLUTSTART | W | `0x00F70000` | `START_SIN` [7:0] = 0, `START_SIN90` [23:16] = 247 |
| `0x6A` | MSCNT | R | — | Microstep counter 0…1023 |
| `0x6B` | MSCURACT | R | — | Actual sine/cosine current: `CUR_B` [8:0], `CUR_A` [24:16], signed |
| `0x6C` | CHOPCONF | R/W | `0x00000000` | Chopper configuration |
| `0x6D` | COOLCONF | W | `0` | CoolStep + StallGuard2 configuration |
| `0x6E` | DCCTRL | W | `0` | DcStep configuration |
| `0x6F` | DRV_STATUS | R | — | StallGuard2 value and driver status flags |
| `0x70` | PWMCONF | W | `0x00050480` | StealthChop PWM configuration |
| `0x71` | PWM_SCALE | R | — | Actual PWM amplitude scaler (0…255) |
| `0x72` | ENCM_CTRL | W | `0` | Encoder-commutation mode (not exposed) |
| `0x73` | LOST_STEPS | R | — | Steps skipped in DcStep mode (20 bit, wraps) |

`MSLUT`/`MSLUTSEL` are not printed as numbers in the datasheet (only "reset default = sine wave
table"); the driver never rewrites them unless `write_microstep_table` is called.

### Bit Fields

#### `GCONF` (`0x00`)

| Bit | Name | Description |
|-----|------|-------------|
| 0 | `I_scale_analog` | 0 = internal reference (reset), 1 = use the voltage on `AIN_IREF` as current reference |
| 1 | `internal_Rsense` | 1 = internal RDSon sensing; `AIN_IREF` becomes a reference *current* input |
| 2 | `en_pwm_mode` | 1 = StealthChop enabled (subject to `TPWMTHRS`); switch only at standstill. **0 = SpreadCycle only** |
| 3 | `enc_commutation` | Special mode — **leave 0** |
| 4 | `shaft` | 1 = inverse motor direction |
| 5 | `diag0_error` | DIAG0 active on driver error (over-temperature, short to GND) |
| 6 | `diag0_otpw` | DIAG0 active on over-temperature pre-warning |
| 7 | `diag0_stall` | DIAG0 active on motor stall (set `TCOOLTHRS` first) |
| 8 | `diag1_stall` | DIAG1 active on motor stall (set `TCOOLTHRS` first) |
| 9 | `diag1_index` | DIAG1 active on index position (microstep table position 0) |
| 10 | `diag1_onstate` | DIAG1 active while the chopper is on (coil in the second half of the full step) |
| 11 | `diag1_steps_skipped` | DIAG1 toggles when DcStep skips steps (do not combine with other DIAG1 options) |
| 12 | `diag0_int_pushpull` | 0 = DIAG0 open collector (active low), 1 = push-pull (active high) |
| 13 | `diag1_pushpull` | 0 = DIAG1 open collector (active low), 1 = push-pull (active high) |
| 14 | `small_hysteresis` | 0 = 1/16 step-frequency comparison hysteresis, 1 = 1/32 |
| 15 | `stop_enable` | 1 = emergency stop: `DCIN` high stops the sequencer |
| 16 | `direct_mode` | 1 = coil currents written via `XDIRECT` |
| 17 | `test_mode` | **Never set**; 0 for normal operation |

`DIAG0` always shows the power-on reset condition (low) regardless of the `diag0_*` bits.

#### `GSTAT` (`0x01`, clear on read)

| Bit | Name | Description |
|-----|------|-------------|
| 0 | `reset` | IC was reset since the last read; all registers are at reset values |
| 1 | `drv_err` | Driver shut down by over-temperature or short since the last read; see `DRV_STATUS`. Reset only when all error conditions are gone |
| 2 | `uv_cp` | Charge-pump undervoltage; driver disabled |

#### `IOIN` (`0x04`)

| Bits | Name | Description |
|------|------|-------------|
| 0 | `STEP` | state of STEP |
| 1 | `DIR` | state of DIR |
| 2 | `DCEN_CFG4` | state of DCEN |
| 3 | `DCIN_CFG5` | state of DCIN |
| 4 | `DRV_ENN_CFG6` | state of ENN |
| 5 | `DCO` | state of DCO |
| 6 | — | always reads 1 |
| 7 | — | don't care |
| 31:24 | `VERSION` | `0x11` = first silicon version (the identity value the driver checks) |

#### `IHOLD_IRUN` (`0x10`, write-only)

| Bits | Name | Description |
|------|------|-------------|
| 4:0 | `IHOLD` | Standstill current scale 0…31 = 1/32…32/32 (0 + StealthChop ⇒ freewheel/brake per `PWMCONF.freewheel`) |
| 12:8 | `IRUN` | Run current scale 0…31 (datasheet hint: use 16…31 for best microstep quality) |
| 19:16 | `IHOLDDELAY` | 0 = instant power down, 1…15 = delay per current step in units of 2¹⁸ clocks |

#### `TPOWERDOWN` (`0x11`)

Bits 7:0. Delay after standstill (`stst`) before the current drops to `IHOLD`: `0` = no delay,
`1` = minimum, `2…255` = `(TPOWERDOWN − 1) × 2¹⁸` clocks (≈ 0…5.5 s at 12 MHz; the datasheet says
"about 0 to 4 seconds").

#### `TSTEP` (`0x12`) / `TPWMTHRS` (`0x13`) / `TCOOLTHRS` (`0x14`) / `THIGH` (`0x15`)

Bits 19:0. `TSTEP` = `fCLK / f_STEP,256` (clock periods per 1/256 microstep, independent of `MRES`);
`2²⁰ − 1` on overflow or standstill. All velocity thresholds compare with a 1/16 hysteresis
(1/32 with `small_hysteresis`): the lower switching velocity equals the setting, the upper one is
higher.

| Register | Condition |
|----------|-----------|
| `TPWMTHRS` | `TSTEP ≥ TPWMTHRS` ⇒ StealthChop (if `en_pwm_mode`); faster ⇒ SpreadCycle. `0` disables the threshold |
| `TCOOLTHRS` | `TCOOLTHRS ≥ TSTEP ≥ THIGH` ⇒ CoolStep enabled (if configured) and StealthChop disabled; `TCOOLTHRS ≥ TSTEP` ⇒ StallGuard2 output on `DIAG` enabled |
| `THIGH` | `TSTEP ≤ THIGH` ⇒ CoolStep and StealthChop off, `vhighchm` → `chm=1, TFD=0`, `SYNC=0`, `vhighfs` → full-step operation and DcStep stall detection. Stall detection is blanked for 2–3 electrical periods around the `THIGH` crossing |

#### `XDIRECT` (`0x2D`)

With `GCONF.direct_mode = 1`: bits 8:0 = signed coil A current, bits 24:16 = signed coil B current,
two's complement, ±248 normal (±255 with StealthChop). Scaled by `IHOLD`. No velocity-based
StealthChop regulation, no DcStep; CoolStep/StallGuard only with an additional STEP signal.

#### `VDCMIN` (`0x33`) / `DCCTRL` (`0x6E`)

`VDCMIN` bits 22:0: minimum DcStep velocity (time reference `2²⁴ / fCLK`); non-zero enables
DcStep by velocity, `DCEN` enables it by pin. `DCCTRL`: bits 9:0 `DC_TIME` (upper PWM on-time
limit for commutation, units of 1/fCLK, set slightly above the blank time), bits 23:16 `DC_SG`
(maximum PWM on-time for DcStep stall detection, units of 16/fCLK, slightly higher than
`DC_TIME/16`; `0` = disabled).

#### `MSLUT[0…7]` (`0x60`…`0x67`) / `MSLUTSEL` (`0x68`) / `MSLUTSTART` (`0x69`)

Programmable microstep table (differential coding of the first quarter wave, 256 entries from
8 × 32 bits) with segmentation `X1 < X2 < X3` and width select `W0…W3` in `MSLUTSEL`
(bits 31:24 `X3`, 23:16 `X2`, 15:8 `X1`, 7:6 `W3`, 5:4 `W2`, 3:2 `W1`, 1:0 `W0`) and start
values in `MSLUTSTART` (bits 7:0 `START_SIN`, 23:16 `START_SIN90`). The default is a sine table
of amplitude 248: `round(248·sin(2π·i/1024 + π/1024)) − 1`. Move to a position where `MSCNT = 0`
before rewriting the table.

#### `MSCNT` (`0x6A`) / `MSCURACT` (`0x6B`)

`MSCNT` bits 9:0 = position in the 1024-entry sine table (`CUR_B` uses an offset of 256).
`MSCURACT`: bits 8:0 `CUR_B` (sine), bits 24:16 `CUR_A` (co-sine), two's complement ±255, raw
table values (not scaled by the current setting).

#### `CHOPCONF` (`0x6C`)

| Bits | Name | Description |
|------|------|-------------|
| 31 | — | reserved, 0 |
| 30 | `diss2g` | 1 = short-to-GND protection disabled |
| 29 | `dedge` | 1 = STEP pulses on both edges |
| 28 | `intpol` | 1 = interpolate to 256 microsteps (MicroPlyer) |
| 27:24 | `MRES` | `0` = 256, `1`…`8` = 128, 64, 32, 16, 8, 4, 2, full step |
| 23:20 | `SYNC` | chopSync2: `0` off, `1…15` ⇒ `fSYNC = fCLK / (SYNC · 64)` (off above `THIGH`) |
| 19 | `vhighchm` | above `THIGH`: switch to `chm=1`, `TFD=0`, doubled `TOFF` |
| 18 | `vhighfs` | above `THIGH`: switch to full-step (at the 45° position) |
| 17 | `vsense` | 0 = low sensitivity / high sense voltage (0.325 V), 1 = high sensitivity (0.180 V) |
| 16:15 | `TBL` | comparator blank time 16, 24, 36, 54 clocks (`%01`/`%10` recommended) |
| 14 | `chm` | 0 = SpreadCycle (hysteresis), 1 = constant off time with fast decay |
| 13 | `rndtf` | 1 = random off time modulation (−24…+6 clocks) |
| 12 | `disfdcc` | `chm=1`: disable current comparator termination of fast decay |
| 11 | `fd3` | `chm=1`: MSB of fast decay time `TFD` |
| 10:7 | `HEND` | `chm=0`: hysteresis low value −3…12 (`%0000…%1111`); `chm=1`: sine wave offset −3…12 |
| 6:4 | `HSTRT` | `chm=0`: hysteresis start +1…+8 (effective `HEND + HSTRT ≤ 16`); `chm=1`: `TFD[2:0]` (`NCLK = 32·TFD`; `0` = slow decay only) |
| 3:0 | `TOFF` | off time `NCLK = 24 + 32·TOFF`; **`0` disables the driver** (all bridges off); `1` only with `TBL ≥ 2` |

#### `COOLCONF` (`0x6D`, write-only)

| Bits | Name | Description |
|------|------|-------------|
| 24 | `sfilt` | StallGuard2 filter: 1 = update once per four full steps (compensates pole tolerance) |
| 22:16 | `sgt` | StallGuard2 threshold, **signed** −64…+63; lower = more sensitive; 0 is a good start |
| 15 | `seimin` | minimum CoolStep current: 0 = ½ · IRUN, 1 = ¼ · IRUN |
| 14:13 | `sedn` | current down step speed: 0 = per 32 `SG_RESULT`, 1 = per 8, 2 = per 2, 3 = per each |
| 11:8 | `semax` | upper threshold offset: current decreases when `SG_RESULT ≥ (semin + semax + 1) · 32` |
| 6:5 | `seup` | current up step width: 0…3 = 1, 2, 4, 8 |
| 3:0 | `semin` | lower threshold: `SG_RESULT < semin · 32` raises current; **0 disables CoolStep** |

Bits 31:25, 23, 12, 7, 4 are reserved (write 0).

#### `DRV_STATUS` (`0x6F`)

| Bit | Name | Description |
|-----|------|-------------|
| 31 | `stst` | standstill (2²⁰ clocks after the last step pulse) |
| 30 | `olb` | open load phase B (informative only; false positives at standstill / fast motion) |
| 29 | `ola` | open load phase A |
| 28 | `s2gb` | short to GND phase B (driver disabled until `TOFF = 0` or ENN high) |
| 27 | `s2ga` | short to GND phase A |
| 26 | `otpw` | over-temperature pre-warning |
| 25 | `ot` | over-temperature (driver disabled until `otpw` also clears) |
| 24 | `StallGuard` | motor stall detected (`SG_RESULT = 0`) or DcStep stall |
| 20:16 | `CS_ACTUAL` | actual current scale 0…31 (reflects CoolStep / automatic scaling) |
| 15 | `fsactive` | driver switched to full-step (velocity above `THIGH` with `vhighfs`) |
| 9:0 | `SG_RESULT` | StallGuard2 load measurement 0…1023 (0 = highest load); **not valid in StealthChop**. At standstill it shows the chopper on-time of coil A (a rough motor-temperature indicator) |

Bits 23:21 and 14:10 are reserved.

#### `PWMCONF` (`0x70`, write-only, reset `0x00050480`)

| Bits | Name | Description |
|------|------|-------------|
| 21:20 | `freewheel` | standstill mode when `IHOLD = 0`: 0 normal, 1 freewheel, 2 coils shorted by LS, 3 coils shorted by HS |
| 19 | `pwm_symmetric` | 1 = force symmetric PWM cycles |
| 18 | `pwm_autoscale` | 1 = automatic current control (reset 1); 0 = user-defined amplitude |
| 17:16 | `pwm_freq` | 0: 2/1024·fCLK, 1: 2/683, 2: 2/512, 3: 2/410 (reset 1) |
| 15:8 | `PWM_GRAD` | autoscale = 1: maximum PWM amplitude change per half wave (1…15); autoscale = 0: velocity-dependent gradient `PWM_GRAD · 256 / TSTEP` (reset 4) |
| 7:0 | `PWM_AMPL` | autoscale = 1: maximum amplitude when switching from the current chopper back to StealthChop (settings above `0x40` recommended); autoscale = 0: amplitude offset (reset 128) |

The reset value `0x00050480` decodes to `pwm_autoscale = 1`, `pwm_freq = %01`, `PWM_GRAD = 4`,
`PWM_AMPL = 128`. `PWM_SCALE` (`0x71`) bits 7:0 = actual amplitude scaler (255 = maximum voltage);
in voltage-PWM mode it reveals a stall.

## Initialization Sequence

1. If `en_pin` is wired, drive ENN **high** (driver off). Configure the SPI bus (Mode 3, ≤ 4 MHz). Wait ≥ 10 ms after `VS`/`VCC_IO` power-up (the datasheet gives no figure; use 10 ms).
2. Read `IOIN`: require `VERSION = 0x11` (and bit 6 = 1); any other value (including `0x00`/`0xFF` from a floating or silent bus) ⇒ "device not found" error.
3. Read `GSTAT` once to clear the power-on `reset` flag (and any stale error flag).
4. Write `CHOPCONF`: `TOFF = 3`, `TBL = 2`, `HSTRT = 4`, `HEND = 1`, `chm = 0` (SpreadCycle), `intpol = 1`, `MRES = 4` (16 microsteps), `vsense = 0` → `0x140100C3` (datasheet §23.1 example with interpolation and 16 microsteps).
5. Write `IHOLD_IRUN` (default `IRUN` = 31 until `set_current`, `IHOLD` = ⅓·`IRUN`, `IHOLDDELAY` = 6) and `TPOWERDOWN = 10`.
6. Write `GCONF = 0x00000004` (`en_pwm_mode = 1`, internal reference, no DIAG routing) and `TPWMTHRS = 500`.
7. Write `PWMCONF = 0x000401C8` (`pwm_autoscale = 1`, `pwm_freq = 0`, `PWM_GRAD = 1`, `PWM_AMPL = 200`; datasheet §23.1).
8. Use the **verified write** (mirror check) for every write in steps 4–7, then read back `GCONF` and `CHOPCONF` and compare with the shadow copies; mismatch ⇒ error.
9. Assert ENN low only when `enable()` is called: with `en_pin` wired init leaves the driver disabled, without it the driver is active as soon as step 4 has written `TOFF ≠ 0`.

## Implementation Stages

### Minimal

Goal: bring the driver up on SPI and move the motor a given number of steps at a given speed with
a given current — no knowledge of chopper registers required.

Constructor: `TMC2130Minimal(connection, step_pin, dir_pin, r_sense_ohm=0.11, en_pin=None)`.
`connection` is the SPI connection (Mode 3). `step_pin`, `dir_pin` are `OutputPin`s (required).
`r_sense_ohm` is the **external sense resistor value** (0.11 Ω is typical on common breakout
boards) used to convert amperes to the current scale; it is the one
value the user must know.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | — | — | Initialization Sequence with the defaults below; part of the constructor |
| `enable` | — | — | Power stage on (`en_pin` low; `TOFF` stays set); then waits 100 ms so StealthChop can set the initial current before the first move |

## Data Conversion

```
# Current scale CS = 0…31 for a target RMS current (external Rsense, datasheet §9)
V_FS     = 0.325 V      (vsense = 0, low sensitivity)   or   0.180 V  (vsense = 1, high sensitivity)
I_rms    = (CS + 1)/32 * V_FS / (R_sense + 0.020 Ω) / sqrt(2)
CS       = round(I_rms * sqrt(2) * (R_sense + 0.020) * 32 / V_FS) - 1      clamped to 0…31
I_motor  = (CUR_A/B / 248) * (CS + 1)/32 * V_FS / (R_sense + 0.020 Ω)      (instantaneous, CUR from the table)
```

`V_FS` values are `V_SRTL = 325 mV` / `V_SRTH = 180 mV` (electrical characteristics). With
`I_scale_analog = 1`: `V_FS' = V_FS · V_AIN / 2.5 V` (`V_AIN` 0…2.5 V on `AIN_IREF`); the
driver does not read `AIN_IREF` and assumes the default internal reference (`I_scale_analog = 0`).
With `internal_Rsense`, `R_sense` is not applicable and `set_current` raises.

**Automatic `vsense` in `set_current`:** compute `CS` for `vsense = 0`; if `CS < 16`
and the `vsense = 1` result is ≤ 31, use `vsense = 1` instead (datasheet: "IRUN 16 to 31 for best
microstep performance"). Example, `R_sense = 0.11 Ω`, 0.5 A: `vsense = 0` → `CS = 8`; `vsense = 1`
→ `CS = 15` ⇒ the driver picks `vsense = 1` (closer to the recommended range; below 16 only
when even `vsense = 1` cannot reach it). Hold: `IHOLD = CS // 3`.

```
# Step generation (software-timed, Minimal.move)
microsteps       = 2^(8 - MRES)                          (MRES = 8 → 1 full step)
pulses           = abs(full_steps) * microsteps
f_pulse[Hz]      = full_steps_per_s * microsteps          (chip limit: fCLK/2 per STEP, fCLK/4 with dedge)
STEP high time  >= max(85 ns, t_CLK + 20 ns); DIR setup / hold >= 20 ns
```

```
# Velocity thresholds (TSTEP units = fCLK cycles per 1/256 microstep)
TSTEP(v)          = fCLK / (v_full_steps_per_s * 256)      v in full steps/s; microstep resolution does not matter
TPWMTHRS (500 @ 12 MHz) → 93.75 full steps/s ≈ 28 rpm for a 200-step motor
TPOWERDOWN_s      = (TPOWERDOWN - 1) * 2^18 / fCLK         (TPOWERDOWN >= 2)
IHOLDDELAY step   = IHOLDDELAY * 2^18 / fCLK per current decrement
```

```
# StallGuard2 / CoolStep
stall (DIAG / DRV_STATUS.StallGuard)  when  SG_RESULT = 0  and  TSTEP <= TCOOLTHRS     (SpreadCycle only)
CoolStep raises current when SG_RESULT <  SEMIN * 32
CoolStep lowers current when SG_RESULT >= (SEMIN + SEMAX + 1) * 32
sgt raises  → less sensitive (needs more load);  sgt lowers → more sensitive;  start at 0
```

The internal oscillator is specified 10.1–17.2 MHz at 50 °C (typ. 13.2 MHz, "≈ 12 MHz" in the
datasheet's examples); `fclk_hz` defaults to 12 MHz. For defined velocities and chopper timing
calibrate it by reading `TSTEP` at a known 1 kHz microstep rate (`TSTEP = 1200` ⇒ 12 MHz, datasheet
§26) or use an external clock.

Signed fields (`XDIRECT` 9 bit, `MSCURACT` 9 bit, `COOLCONF.sgt` 7 bit) are sign-extended two's
complement; mask both source bytes before combining when reading into JVM/Kotlin types.

## Examples

### Demo

A sensorless homing routine for a linear axis. The demo enables the driver at 0.8 A, selects 16
microsteps, and reads back `IOIN.VERSION` (`0x11`) to prove the SPI link. Because StallGuard2 does
not work in StealthChop it switches to SpreadCycle (`set_chopper_mode(True)`), sets `sgt = 0` and
`TCOOLTHRS` so StallGuard is active at the homing speed, then drives toward the end stop in short
`move()` bursts of 20 full steps at 150 full steps/s (after 0.5 s of spin-up during which stall
detection is not yet valid), printing `read_stallguard()` after each burst. When `SG_RESULT`
reaches 0 (`is_stalled()` goes true) it stops, prints the `SG_RESULT` history of the last bursts,
backs off 200 full steps, and enables CoolStep (`configure_coolstep(semin=5, semax=2, seup=1,
sedn=1, seimin=0)`) for a final move, showing `read_current_scale()` drop as the load falls. It
finishes with `read_status()` and `read_global_status()`. If `read_fault()` becomes non-zero at
any point, the demo stops, disables the driver, prints which fault fired and exits.

## Timing Constraints

- **Datagram duration (`datagram`):** a 40-bit datagram takes at least 10 µs from CSN falling to
  CSN rising (40 SCK clocks at the maximum 4 MHz internal-clock SCK rate). A shorter frame means the
  host exceeded the SCK limit and the chip may mis-latch. Sigrok annotation pair:
  `datagram_start` / `datagram_end`. This is the only host-observable, conformance-checkable
  constraint; the remaining chip timings below are autonomous hardware behaviour.
- **CSN high time:** ≥ 2·t_CLK + 10 ns (≈ 0.2 µs at 12 MHz) between datagrams; every SPI
  peripheral meets it with the usual CS toggling.
- **Standstill power-down:** `(TPOWERDOWN − 1) · 2¹⁸ · t_CLK` after the last step (≈ 22 ms per count
  at 12 MHz), then `IHOLDDELAY · 2¹⁸ · t_CLK` per current decrement. Autonomous.
- **StealthChop start-up:** after StealthChop is first switched on keep the motor stopped for at
  least 128 chopper periods, and allow ≥ 100 ms of rest (assuming fCLK ≥ 10 MHz) before the first
  motion so the current regulation can set the initial motor current (datasheet §6 / §22). The
  driver's `enable()` waits 100 ms after the power stage turns on.
- **StallGuard2 update rate:** once per full step; stall detection is only valid above the
  `TCOOLTHRS` velocity. Autonomous.
- **Power-up:** apply `VS` and `VCC_IO` before the first datagram; allow ≥ 10 ms (datasheet gives
  no figure) for the oscillator and charge pump.

## Implementation Notes

- **Reads are two datagrams, not one.** The reply to a datagram belongs to the *previous* request.
  Forgetting the second datagram returns stale data (the previous register, or the previous
  write's mirror) — the most common SPI bug on this chip. Always issue the second datagram as a
  harmless `GCONF` read request, never `GSTAT`.
- **`GSTAT` clears on read.** `read_global_status` reports the flags once; the power-on `reset`
  flag is consumed by init (step 3). A set `reset` flag later means the chip lost its
  configuration (brown-out): the driver does not re-initialise automatically, but exposes
  `reset` so the caller can.
- **Write-only registers** (`IHOLD_IRUN`, `TPOWERDOWN`, `TPWMTHRS`, `TCOOLTHRS`, `THIGH`, `VDCMIN`,
  `MSLUT*`, `COOLCONF`, `DCCTRL`, `PWMCONF`, `ENCM_CTRL`) cannot be read back. The driver shadows
  every value it writes (needed for the read-modify-write of `COOLCONF`/`PWMCONF`/`IHOLD_IRUN`
  fields too) and exposes none of them through `read_register`. `GCONF` and `CHOPCONF` are
  readable and the shadow is verified against them at init.
- **Mirror verification is an SPI-integrity check, not a register check:** the chip returns the
  last written data word in the next datagram regardless of whether the register exists or
  accepted it.
- **`TOFF = 0` disables the driver** (all bridges off). `disable()` without an ENN pin writes
  `CHOPCONF` with `TOFF = 0`; `enable()` restores the shadowed `TOFF`.
- **No internal step generator.** `Minimal.move` is software-timed: its maximum rate is bounded by
  the host language and GPIO speed (a few kHz in MicroPython/Node.js, tens of kHz in C++/Rust/Go).
  At 16 microsteps a rate of 1000 full steps/s needs 16 kHz STEP pulses. Lower the microstep
  count (`set_microsteps`) or move to a faster platform for high speeds; `intpol` keeps the
  motion smooth at coarse STEP rates. Hardware step generation (PWM/timer) is out of scope.
- **`XDIRECT` motion** is the alternative: with `direct_mode` the host sets both coil currents
  directly (scaled by `IHOLD`, so raise `IHOLD` to the desired current) and is responsible for the
  sine/cosine profile; useful for custom waveforms, no STEP pin needed.
- **StallGuard2 needs SpreadCycle** (`en_pwm_mode = 0`, or `TSTEP < TPWMTHRS`), `TSTEP ≤ TCOOLTHRS`,
  and a velocity where back-EMF is meaningful. Re-tune `sgt` after changing the run current,
  microstepping or supply voltage. `SG_RESULT` at standstill is chopper on-time, not load.
- **`DIAG0`/`DIAG1` are open drain by default (active low)** and need external pull-ups; the driver
  does not enable push-pull unless asked via `configure_diag`. `DIAG0` is also pulled low during
  reset regardless of configuration.
- **`vsense` auto-selection** assumes the default internal reference. With `I_scale_analog = 1`
  the full-scale voltage is scaled by `V_AIN / 2.5 V` and the conversion is off.
- **Internal sense resistors** (`internal_Rsense`, RDSon sensing) change the whole current
  conversion (reference current into `AIN_IREF`); never enable on a board with external resistors.
- **Do not trust open-load flags** at standstill or high velocity (datasheet): `FAULT_OPEN_LOAD` is
  informative only. Short-to-GND flags latch until `TOFF = 0` or ENN high.
- **`MSCURACT` order:** the TMC2130 datasheet labels bits 8:0 `CUR_B` (sine) and bits 24:16 `CUR_A`
  (co-sine); `read_coil_currents` returns `(CUR_A, CUR_B)`.
- **The register-reset values in the datasheet are partly implicit:** only `PWMCONF` (`0x00050480`)
  and `MSLUTSTART`'s `START_SIN90` (247) have printed defaults; the other zeros come from the
  "all registers become reset to 0 upon power up" note.
- **`ENCM_CTRL` and encoder commutation** are never written by the library.
- **SPI status byte** is discarded by the base `Connection` contract (see Datagram format); do
  not extend the transport for it.
- **Shared SPI bus:** SDO is tristate when CSN is high, so the chip can share MISO with other
  devices.

## Sigrok Decoder

Decoder id `tmc2130`, input `['spi']` (stacked on the sigrok `spi` decoder, Mode 3, 8 bits per
word, MSB first). It groups the five bytes between CSN edges into one datagram and annotates:

- the host request: `R`/`W` bit, register name (`GCONF`, `GSTAT`, `IOIN`, `IHOLD_IRUN`, `TPOWERDOWN`,
  `TSTEP`, `TPWMTHRS`, `TCOOLTHRS`, `THIGH`, `XDIRECT`, `VDCMIN`, `MSLUT0`…`MSLUT7`, `MSLUTSEL`,
  `MSLUTSTART`, `MSCNT`, `MSCURACT`, `CHOPCONF`, `COOLCONF`, `DCCTRL`, `DRV_STATUS`, `PWMCONF`,
  `PWM_SCALE`, `ENCM_CTRL`, `LOST_STEPS`) and the 32-bit value;
- the chip reply: it remembers the previous datagram, so the five MISO bytes are labelled "reply
  to `<previous register>` read" or "mirror of write `<value>`", and the status byte is decoded to
  `reset_flag`, `driver_error`, `sg2`, `standstill`;
- bit fields for `GCONF`, `GSTAT`, `IOIN` (incl. `VERSION`), `IHOLD_IRUN`, `COOLCONF` (signed `sgt`),
  `CHOPCONF` (microstep count from `MRES`), `DRV_STATUS`, `PWMCONF`, plus computed values (current
  scale fraction, signed `XDIRECT` coil currents, signed `MSCURACT`, `SG_RESULT`).

Emits `OUTPUT_ANN` and `OUTPUT_PYTHON` per `specs/sigrok_annotations.md`.

The `timing` annotation row carries the conformance pair `datagram_start` (CSN falling edge) /
`datagram_end` (CSN rising edge), shaped per the Variable-Length Annotation Convention. Timing
config `specs/motor/tmc2130_timing.conf`: `datagram_min_us=10`, `datagram_samplerate=24m`,
`datagram_capture_ms=300` (SCK ≤ 4 MHz).
