# Chip Spec: DS1881

**Manufacturer:** Maxim Integrated (now Analog Devices)  
**Datasheet:** `datasheets/adc_dac/ds1881.pdf` (Rev 0, 1/06; supplied by the maintainer — the Maxim/Analog Devices URLs in the issue are not reachable by script)  
**Category:** adc_dac  
**Transports:** I²C

## Overview

The DS1881 is a dual, nonvolatile (NV) **audio log-taper digital potentiometer** for audio systems with 5 V signal levels. Each of the two channels is a 45 kΩ potentiometer whose wiper position is a step in an attenuation table: **Option 1** gives 64 positions — 1 dB per step from 0 dB to −62 dB plus a mute position; **Option 2** (software-compatible with the DS1808) gives 34 positions — 12 × 1 dB, 12 × 2 dB and 8 × 3 dB steps plus mute. A zero-crossing detector makes wiper changes clickless and popless, the two channels are matched to 0.5 dB, and the wiper settings and configuration can be stored in EEPROM so they survive power cycles. The analog supply (VCC, 4.5–5.5 V) and the digital supply (VDD, 2.7–5.5 V) are separate. Three address pins give eight I²C addresses and a chip-enable pin (CE) disables the bus interface. There are no registers in the usual sense: a **command byte** selects wiper 0, wiper 1 or the configuration register and carries the new value in its low bits.

## Transport Configuration

### I²C
- **Address:** `0x28` (A2 = A1 = A0 = 0) … `0x2F` (A2 = A1 = A0 = 1); 7-bit address `0101 A2 A1 A0`; pins tied to GND or VDD
- **Max clock:** 400 kHz (fast mode); standard mode also supported
- **CE pin:** active low; **must be 0 for the I²C pins to be recognised** (tie to GND, or drive it from a GPIO). Wire a GPIO as the `Connection`'s `en_pin` with `en_active_high=False` (see `specs/feature_connection_design.md` §3.3): `enable()` then drives CE low and `disable()` drives it high; the driver itself does not manage CE
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`; the range `0x28`–`0x2F` overlaps the AD5243/AD5248, CAT5171 and others that cannot be told apart)
- **Probe safety:** `write_sensitive` — every byte written after the address is a command byte that can change a wiper or the configuration (and can trigger an EEPROM write)
- **Protocol:** no register addresses. **Write:** `[addr+W] [command byte]…` — one or more command bytes in any order in one transaction (each is `00xxxxxx` wiper 0, `01xxxxxx` wiper 1 or `10xxxxxx` configuration; `11xxxxxx` is reserved and ignored), then STOP. **Read:** `[addr+R] [byte]…` with no command byte: the chip returns wiper 0, wiper 1, then the configuration register, round-robin, as long as the master ACKs; the master NACKs the last byte. A single-byte read always returns wiper 0. The driver uses the plain `Connection` (`write`, `read`), not `RegisterConnection`

## Command Set

| Command byte | Bits | Operation |
|--------------|------|-----------|
| Wiper 0 | `00 P5 P4 P3 P2 P1 P0` | Write wiper position of potentiometer 0 |
| Wiper 1 | `01 P5 P4 P3 P2 P1 P0` | Write wiper position of potentiometer 1 |
| Configuration | `10 X X X V/NV ZC CFG` | Write the configuration register |
| Reserved | `11 …` | Do not use |

### Wiper register (one per potentiometer)

`b7:b6` = selection (00 / 01), `b5:b0` = wiper setting (position). Memory type: NV (EEPROM) or volatile per the configuration. Datasheet factory default `XX111111b` (position 63 = mute in Option 1). On a read the byte is returned with the position in its low bits.

### Configuration register

| Bits | Name | Description |
|------|------|-------------|
| 7:6 | — | `10` selects the configuration register |
| 5:3 | — | No function |
| 2 | V/NV | `0` = potentiometer registers are nonvolatile (stored in EEPROM on every write); `1` = volatile — after power-up both wipers are at mute |
| 1 | ZC | `1` = zero-crossing detection enabled, `0` = disabled |
| 0 | CFG | `0` = Option 1 (63 positions + mute, 1 dB steps); `1` = Option 2 (33 positions + mute, DS1808-compatible) |

The datasheet lists the register's factory default as `0x87` (V/NV = 1, ZC = 1, CFG = 1 → volatile, zero-crossing on, **Option 2**) while the prose says "the factory default for both potentiometers is Option 1". The two statements contradict each other, so **the driver never relies on the default**: `init` reads the three bytes and rewrites the configuration only if it differs from what the driver wants. The configuration register itself is stored in EEPROM.

### Attenuation tables

**Option 1** (CFG = 0): position `p` (0–62) = −`p` dB; position 63 = mute (≈ −80 dB).
**Option 2** (CFG = 1): positions 0–12 = −0…−12 dB (1 dB/step); 13–24 = −14…−36 dB (2 dB/step: 13 → 14, 14 → 16, … 24 → 36); 25–32 = −39…−60 dB (3 dB/step: 25 → 39, 26 → 42, … 32 → 60); position 33 = mute (≈ −80 dB).

Position values above the configured range are not specified; the driver never writes them.

## Initialization Sequence

1. Apply VCC, then VDD; wait ≥ 1 ms (tPU) before the first transaction.
2. Read three bytes (`[addr+R]` → wiper 0, wiper 1, configuration).
3. Build the desired configuration byte `0x80 | V/NV | ZC | CFG` — default for Minimal: **volatile (V/NV = 1), zero-crossing on, Option 1** = `0x86`. If the read-back configuration differs (bits 2:0 only), write it (one command byte, then STOP) and wait for the EEPROM write that the configuration byte triggers (it is stored in EEPROM; ≤ 10 ms, see Timing — use acknowledge polling). If it already matches, send nothing.
4. Do not touch the wipers: after a power-up in volatile mode they are at mute; in NV mode they hold the stored positions.

## Implementation Stages

### Minimal

Goal: set the volume of the two channels in dB with no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Waits ≥ 1 ms, runs the Initialization Sequence (volatile, zero-crossing on, Option 1); caches the configuration |
| `set_attenuation` | `channel: int` (0–1), `db: float` | — | Nearest Option 1 position (`round(db)`, clamped to 0…62 dB); one command byte `(channel << 6) + position`; invalid `channel` raises |
| `get_attenuation` | `channel: int` | `float` dB | From the read-back position (63 → `80.0`) |
| `mute` | `channel: int` | — | Position 63 |
| `set_position` | `channel: int`, `position: int` (0–63) | — | Raw Option 1 position (63 = mute); clamped |
| `get_position` | `channel: int` | `int` | Position read back (low 6 bits) |

**Sensible defaults:** Option 1 (1 dB steps, 0 to −62 dB + mute), volatile pots (no EEPROM wear; wipers at mute after power-up), zero-crossing enabled (clickless, ≤ 50 ms per change). The two channels are independent; use Full's `set_both` for stereo updates.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `set_both` | `position0: int`, `position1: int` | — | One transaction with both command bytes (no STOP between them), so both wipers update together |
| `set_attenuation_both` | `db0: float`, `db1: float \| None = None` | — | `db1` defaults to `db0` (stereo volume); nearest positions in the current option |
| `configure` | `option: int = 1` (1 or 2), `zero_crossing: bool = True`, `nonvolatile: bool = False` | — | Writes the configuration byte (only if it differs from the cached/read-back value) and updates the driver's table; rewrites nothing else |
| `get_config` | — | `dict` | `{ option, zero_crossing, nonvolatile, raw }` from a fresh read |
| `set_option` | `option: int` | — | Switch between Option 1 and 2 (the existing positions are **not** converted — they keep their numeric value and therefore change attenuation; re-set them afterwards) |
| `set_zero_crossing` | `enabled: bool` | — | ZC bit |
| `set_nonvolatile` | `enabled: bool` | — | V/NV bit: `True` → subsequent wiper writes are stored in EEPROM and restored at power-up |
| `store` | — | — | Persist the current positions: with the configuration set to nonvolatile, rewrite both wiper bytes (read back first) in one transaction; the EEPROM write starts after the STOP; waits for completion by acknowledge polling (≤ 10 ms); restores the previous V/NV state only if the caller asked for volatile operation (see Notes) |
| `wait_ready` | `timeout_s: float = 0.05` | — | Acknowledge polling: repeat a 1-byte read until the device ACKs its address (it NACKs while an EEPROM write is in progress) or the timeout expires |
| `read_all` | — | `tuple` | `(position0, position1, config_byte)` — the datasheet's three-byte round-robin read in one transaction |
| `position_to_db` | `position: int` | `float` | Table lookup for the current option (mute → `80.0`) |
| `db_to_position` | `db: float` | `int` | Nearest position for the current option (clamped; values ≥ 70 dB map to mute) |
| `max_position` | — | `int` | 62 / 32 (last non-mute position) for Option 1 / 2; mute is 63 / 33 |
| `reset` | — | — | Volatile, zero-crossing on, Option 1 configuration and both wipers to mute (one transaction) |

**Additional configuration options:** attenuation Option 1 or 2, zero-crossing detection, volatile or nonvolatile storage, EEPROM store.

## Data Conversion

```
Option 1:  dB(p) = p            for p = 0..62        mute: p = 63 (~80 dB)
Option 2:  dB(p) = p            for p = 0..12
           dB(p) = 12 + 2*(p-12) for p = 13..24       (14, 16 ... 36)
           dB(p) = 36 + 3*(p-24) for p = 25..32       (39, 42 ... 60)
           mute:  p = 33 (~80 dB)

command byte   = (channel << 6) | position              # channel 0 -> 00, channel 1 -> 01
config byte    = 0x80 | (V/NV << 2) | (ZC << 1) | CFG
read-back byte = position (b5:b0)  — upper two bits masked off
```

Attenuation is relative to the signal on the H terminal (0 dB = wiper at H); the end-to-end resistance is a fixed 45 kΩ (±20 %) and is irrelevant to the attenuation.

## Timing Constraints

- **Power-up time:** tPU ≤ 1 ms — wait ≥ 1 ms after the supplies are stable before the first transaction. **Conformance-checked** as `poweron_ready` (min 1 ms), measured from capture start to the first decoded bus transaction (no power-sense channel in `testconfig_wiring` — same pattern as the display chips) — see `specs/adc_dac/ds1881_timing.conf`.
- **EEPROM write time:** tW typ. 5 ms, max 10 ms after the STOP that ends a transaction writing an NV location; the device does not acknowledge its address while busy (acknowledge polling). With zero-crossing enabled the EEPROM write begins only after the current zero-crossing window (≤ 50 ms) has finished.
- **Zero-crossing window:** tZCD typ. 38 ms, max 50 ms — after the ACK of a wiper command the wiper moves at the next zero-crossing of that potentiometer or at the latest after 50 ms. The driver does not wait for it (the register already holds the new position and a read returns it immediately); callers sequencing mute-then-source-switch should wait ≥ 50 ms.
- **I²C:** fSCL ≤ 400 kHz, tBUF ≥ 1.3 µs, tLOW ≥ 1.3 µs, tHIGH ≥ 0.6 µs, tSU:DAT ≥ 100 ns (datasheet).
- **Supply sequencing:** VCC before VDD; VDD must never exceed VCC.

## Implementation Notes

- **Plain `Connection`:** the command byte is not a register address and a read has no address phase; use `connection.write(bytes)` (any number of command bytes per transaction) and `connection.read(n)`. Never use `write_read` for the three-byte read.
- **EEPROM wear:** with V/NV = 0 **every** wiper write triggers an EEPROM write of *all three* NV bytes (both wipers and the configuration), wearing all three cells (50 000 writes at 70 °C). The configuration register is also stored in EEPROM, so configuration writes count too. Hence Minimal runs volatile and `init` rewrites the configuration only when it differs. `store()` should switch to NV mode only for the duration of the store unless the caller made NV the standing mode with `set_nonvolatile(True)`.
- **Acknowledge polling:** while an EEPROM write is in progress the device NACKs its address — a driver call during that window raises an I²C error. Full's `wait_ready` handles it; every method that can start a write (`configure`, `set_nonvolatile`, `store`, and any wiper write in NV mode) must wait for it before returning (or at least before the next transaction).
- **Reading wipers:** the position read back is the register value; with zero-crossing on the physical wiper can lag by up to 50 ms. Reading a single byte returns wiper 0; use the three-byte read for all.
- **Datasheet inconsistency:** the default configuration `0x87` (Option 2, volatile) conflicts with the text claiming Option 1 as the factory default; the driver sets what it needs explicitly. After a power cycle in volatile mode the wipers are at mute regardless.
- **Position range per option:** do not write position 34–63 in Option 2 or any value the table does not define; the datasheet does not describe that behaviour. When switching options, rewrite the positions.
- **Relation to the DS1808:** Option 2 is software-compatible with the DS1808's 33-position table; the DS1808 itself is a different chip (not covered).
- **Audio use:** the potentiometer terminals should be biased to mid-rail (VCC/2) with AC coupling for single-supply audio (typical operating circuit); wiper current ≤ ±1 mA and THD is lowest into a high-impedance load.
- **Datasheet:** Rev 0 (1/06), supplied by the maintainer.

## Sigrok Decoder

Decoder id `ds1881`, input `['i2c']`. Matches I²C addresses `0x28`–`0x2F`. Each byte of a write is decoded as a command byte: wiper 0/1 with position and the attenuation in dB at the last-seen option (Option 1 assumed until a configuration write is seen, with `MUTE` for the mute position), configuration with `V/NV`, `ZC` and option, `11xxxxxx` flagged as reserved; multiple command bytes in one transaction are shown separately. Reads are annotated as the round-robin sequence (wiper 0, wiper 1, config, wiper 0, …) with the same decoding. Warnings: a position beyond the configured option's range and a configuration byte with bits 5:3 set. No EEPROM annotation pair is emitted (the EEPROM write is an internal event with no bus marker). For the power-on conformance check the first bus transaction after capture start is annotated `poweron_ready` (marker `poweron_start` at capture start) in the `timing` annotation row shaped per `specs/sigrok_annotations.md`'s Variable-Length Annotation Convention; the gap must be ≥ 1 ms (see `specs/adc_dac/ds1881_timing.conf`).
