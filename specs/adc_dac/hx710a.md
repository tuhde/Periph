# Chip Spec: HX710A

**Manufacturer:** Avia Semiconductor
**Datasheet:** `datasheets/adc_dac/hx710a.pdf`
**Category:** adc_dac
**Transports:** HX711 GPIO bit-bang — see `specs/transport_hx711.md`

## Overview

The HX710A is a precision 24-bit analog-to-digital converter for weigh scales and industrial force-measurement applications, with a built-in system-temperature sensor. It interfaces directly with a resistive bridge sensor (load cell) through a single differential input pair (INN/INP) and an on-chip low-noise amplifier with a **fixed** gain of 128 — unlike the HX711, there is no software-selectable gain and no second input channel. Communication reuses the HX711's 2-wire bit-bang protocol (no SPI or I²C bus required), with selectable output rates of 10 SPS or 40 SPS and an additional third pulse-count reading that returns the on-chip temperature sensor's raw code instead of a differential-input conversion.

## Transport

The HX710A uses the same chip-specific 2-wire GPIO bit-bang transport as the HX711. See `specs/transport_hx711.md` for the full protocol, timing constraints, pin types per platform, and interface contract — the driver constructs the same `HX711Connection` instance (already implemented for every supported platform) and calls `read_raw(num_pulses)` to clock conversions. No transport-level changes are needed; only the chip driver's interpretation of the pulse count differs from HX711's.

**Pulse count → reading (HX710A):**

| Pulses (N) | Reading | Rate |
|------------|---------|------|
| 25 | Differential input (INN/INP), gain 128 | 10 Hz |
| 26 | On-chip temperature sensor | 40 Hz |
| 27 | Differential input (INN/INP), gain 128 | 40 Hz |

This table replaces HX711's channel/gain table — the HX710A has no Channel B and no software gain selection; the pulse count only ever selects "differential input" vs. "temperature" and the output rate.

**HX710B note:** The HX710A and HX710B share this exact pin-out, protocol, and timing. On the HX710B, pulse count 26 reads the DVDD−AVDD supply-voltage difference instead of temperature — a different chip with its own spec (tracked separately; do not add DVDD−AVDD handling here).

## Initialization Sequence

1. Drive PD_SCK LOW to ensure chip is in normal mode
2. Wait for DOUT to go LOW (first conversion complete)
3. Issue one dummy read with 25 pulses to discard the first conversion result
4. Chip is now ready for use: differential input, gain 128, 10 SPS

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits everything and adds the rest.

### Minimal

Goal: read a raw 24-bit signed ADC value from the differential input at the default 10 SPS rate. No configuration required beyond the two GPIO pins.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `dout`, `pd_sck` | — | Construct the `HX711Connection`; drive PD_SCK LOW; wait for first conversion, discard it |
| `is_ready` | — | bool | True if DOUT is LOW (data available), non-blocking |
| `read_raw` | — | int | Block until ready; clock 25 pulses (differential input, 10 Hz); return signed 24-bit value |

**Sensible defaults:** Differential input, gain 128 (the chip's only PGA setting), 10 SPS (25 pulses); blocks indefinitely until DOUT goes LOW.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `set_rate` | `rate: int` (10 or 40) | — | Selects 25 pulses (10 Hz) or 27 pulses (40 Hz) for `read_raw`; takes effect after the next `read_raw` call — that first reading under the new rate must be discarded before relying on data |
| `read_average` | `times: int` (default 10) | int | Average of `times` raw differential-input readings; blocks until all readings complete |
| `tare` | `times: int` (default 10) | — | Capture average of `times` readings as zero offset; stores in `_offset` |
| `get_offset` | — | int | Return current tare offset |
| `set_scale` | `factor: float` | — | Set calibration scale factor; stores in `_scale` |
| `get_scale` | — | float | Return current scale factor |
| `read_weight` | `times: int` (default 1) | float | Returns `(read_average(times) - _offset) / _scale` |
| `read_temperature_raw` | — | int | Block until ready; clock 26 pulses (temperature channel, 40 Hz); return signed 24-bit raw ADC code — **not** a calibrated °C value, see Data Conversion |
| `power_down` | — | — | Drive PD_SCK HIGH for > 60 µs to enter power-down mode |
| `power_up` | — | — | Drive PD_SCK LOW; chip resets to differential input, gain 128; next reading should be discarded |

**Additional configuration options:**
- Output rate selection (10 or 40 SPS) for the differential channel
- Multi-sample averaging
- Tare offset capture and subtraction
- Scale factor calibration for real-world units (e.g., grams, kilograms)
- Raw on-chip temperature sensor access
- Power-down and wake-up

## Data Conversion

The HX710A outputs 24-bit two's complement values, transmitted MSB first, on both the differential-input and temperature channels. Sign-extend to a platform integer:

```
raw (uint24, MSB-first from wire) → signed int:
    if raw >= 0x800000: signed = raw - 0x1000000
    else:              signed = raw

signed range: -8388608 (0x800000) to +8388607 (0x7FFFFF)

weight = (raw_signed - tare_offset) / scale_factor
```

The scale factor is determined by calibration with a known weight:
1. Call `tare()` with nothing on the scale
2. Place a known weight W (in the target unit, e.g. grams)
3. `scale_factor = (read_average() - tare_offset) / W`

At 5 V reference, gain 128: full-scale differential input = ±20 mV → ±8,388,607 counts.

**Temperature channel — no absolute formula:** the datasheet gives only a typical resolution of ~20.4 LSB per °C for the on-chip temperature sensor; it explicitly states offset and gain vary significantly chip-to-chip and "need to be calibrated out" for absolute readings. No factory calibration constants are exposed over the wire, so the driver returns only the raw signed ADC code (`read_temperature_raw()`) — do not fabricate an uncalibrated raw-to-°C conversion. Applications needing absolute temperature must calibrate `_temp_offset`/`_temp_scale` against a reference thermometer themselves; applications using the sensor only for relative drift compensation (the datasheet's primary intended use) can use the raw code directly.

## Timing Constraints

| Symbol | Event | Min | Typ | Max | Unit |
|--------|-------|-----|-----|-----|------|
| T1 | DOUT falling edge to PD_SCK rising edge | 0.1 | — | — | µs |
| T2 | PD_SCK rising edge to DOUT data valid | — | — | 0.1 | µs |
| T3 | PD_SCK high time | 0.2 | 1 | 50 | µs |
| T4 | PD_SCK low time | 0.2 | 1 | — | µs |

- **Settling time after power-up, reset, or channel/rate change:** 400 ms at 10 SPS, 100 ms at 40 SPS
- **Power-down entry:** PD_SCK must be held HIGH continuously for > 60 µs
- **PD_SCK pulses per conversion:** must be exactly 25, 26, or 27 — fewer than 25 leaves the conversion incomplete; more than 27 causes serial communication errors

## Implementation Notes

- **No register map:** all chip configuration is implicit in the clock pulse count (25/26/27). There are no I²C or SPI registers.
- **Sign extension:** the 24-bit value arrives MSB-first as a raw unsigned integer. Explicitly sign-extend: `if raw >= 0x800000: raw -= 0x1000000` (Python) or `if (raw & 0x800000) raw |= 0xFF000000u` (C/C++). Do not use an XOR-based approach — it requires the caller to treat the result as signed, which is implicit and error-prone.
- **First reading after init:** the chip begins converting immediately on power-up; the first result may be invalid. `init` must clock out and discard one reading before returning.
- **Blocking reads on Linux:** `read_raw` / `read_temperature_raw` poll DOUT in a tight loop. On Linux, insert a `time.sleep(0.001)` between polls to avoid busy-waiting a CPU core (same as `specs/transport_hx711.md`'s platform notes — this is a transport-level behavior, not chip-specific).
- **Fixed gain, single channel — no Channel B:** unlike the HX711, the HX710A has no software-selectable gain and no second analog input channel; INN/INP is the only differential pair, gain is fixed at 128.
- **Temperature channel has no absolute conversion formula:** resolution is approximately 20.4 LSB/°C, but chip-to-chip offset/gain variance is significant per the datasheet. Expose the raw code only (`read_temperature_raw()`); do not fabricate a calibrated °C conversion.
- **HX710B is a different chip:** shares pin-out, protocol, and timing, but pulse count 26 reads DVDD−AVDD instead of temperature. Tracked separately — see the Transport section above.
- **Power-down clock pulse limit:** T3 (PD_SCK high time) must not exceed 50 µs during normal data clocking or the chip interprets the pulse as a power-down command.
- **Rate-change settling:** after `set_rate`, the new rate takes effect only after the *next* read completes a conversion with the new pulse count. That first reading under the new rate must be discarded — call `read_raw()` once and ignore the return value before relying on data.
- **JVM not implemented:** `specs/transport_hx711.md`'s interface contract does not define a JVM/Java configuration (its Configuration Parameters table has no JVM row), so no `HX711Connection` equivalent exists for the JVM target yet. This is a transport-level gap, not specific to this chip — the same gap applies to the existing HX711 chip driver. Extending the transport to JVM (e.g. via the sysfs `InputPin`/`OutputPin` primitives already used by the DHTxx transport) is out of scope for this chip spec.

## Sigrok Decoder

Decoder id `hx710a` (`sigrok/hx710a/`), input `['logic']`, matching two logic channels (`dout`, `sck`) — same wire-level format as the existing `hx711` decoder, but with its own pulse-count table (25 → differential input/10 Hz, 26 → temperature/40 Hz, 27 → differential input/40 Hz) in place of HX711's channel/gain map. Annotates: `ready` (DOUT goes low, conversion result ready to shift out), `bit` (each of the 24 clocked-out data bits), `conversion` (a complete 24-bit result decoded to its signed value, reading type, and rate), `powerdown` (PD_SCK held high ≥ 60 µs), `wakeup` (PD_SCK returns low after power-down), and `warning` (wrong bit count, malformed clock pulse train, or missing ready signal).
