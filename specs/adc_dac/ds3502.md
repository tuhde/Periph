# Chip Spec: DS3502

**Manufacturer:** Maxim Integrated  
**Datasheet:** `datasheets/adc_dac/ds3502.pdf` (Rev 1, March 2009, supplied as an attachment to the issue)  
**Category:** `adc_dac`  
**Transports:** I²C

## Overview

The DS3502 is a single, 7-bit (128-position), nonvolatile digital potentiometer with an I²C interface (up to 400 kHz) and a high-voltage wiper section: external voltages applied to `RL` and `RH` define the lowest and highest output voltage, up to 15.5 V (`V+` 4.5–15.5 V), while the logic runs from VCC = 2.5–5.5 V. The potentiometer is 127 equal resistors in series between `RH` and `RL` (10 kΩ end-to-end, ±20 %); the wiper `RW` is decoded from the 7-bit Wiper Register (WR). The Initial Value Register (IVR, EEPROM) holds the wiper position loaded into WR at power-up (factory default `0x40`, midscale). Two address pins allow four devices on one bus. Typical uses: TFT-LCD VCOM calibration, instrumentation and industrial controls, mechanical potentiometer replacement. The chip is intended as a **voltage divider**; the wiper may carry at most 1 mA.

## Transport Configuration

### I²C
- **Address:** `0x28` (A1 = A0 = GND) … `0x2B` (A1 = A0 = VCC); the slave address byte is `0101 0 A1 A0 R/W`, i.e. `0x50` (write) / `0x51` (read) with both pins grounded — the 7-bit address is the byte shifted right by one

| A1 | A0 | 7-bit address | Write / read byte |
|----|----|---------------|-------------------|
| GND | GND | `0x28` | `0x50` / `0x51` |
| GND | VCC | `0x29` | `0x52` / `0x53` |
| VCC | GND | `0x2A` | `0x54` / `0x55` |
| VCC | VCC | `0x2B` | `0x56` / `0x57` |

- **Max clock:** 400 kHz (fast mode); standard-mode timing also supported
- **Identity register:** none; chip has no ID register (feeds `registry/chips.json` with `"id_probe": null` and `"driver": null` until implemented, see `specs/feature_i2c_discovery.md`)
- **Probe safety:** `register_pointer` — the first byte after the address is the memory address; a 1-byte write is the datasheet's "dummy write cycle" that only loads the address counter (no data byte follows, so nothing is written to WR, CR or EEPROM)
- **Register addressing:** 1-byte memory address, then data (`RegisterConnection`, `reg_bytes = 1`). A read returns the byte at the address counter, so reads are done as address write + repeated START + read ("manipulating the address counter for reads"); the `RegisterConnection` read does exactly this. The memory address is always the second byte of a write

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| SDA, SCL | — | I²C; external pull-up resistors (4.7 kΩ typical); SCL driven open-collector or push-pull |
| A0, A1 | — | Address select, tied to GND or VCC |
| RH, RL | — | High and low potentiometer terminals; −0.3 V … `V+` (also −0.3 … +15.5 V); voltage across RH–RL ≤ `V+` |
| RW | — | Wiper terminal; −0.3 V … `V+`; wiper current ≤ 1 mA |
| V+ | — | Wiper bias supply, 4.5–15.5 V, must be above VCC; decouple with 0.01–0.1 µF |
| VCC | — | Logic supply 2.5–5.5 V; decouple with 0.01–0.1 µF |

There is no reset, interrupt or enable pin.

## Register Map

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | WR / IVR | R/W | `0x40` | Wiper Register (SRAM) and Initial Value Register (EEPROM) at one address; reads always return WR |
| `0x02` | CR | R/W | `0x00` | Control Register (volatile): bit 7 = MODE |

Only addresses `0x00` and `0x02` exist; the driver never writes other addresses. The factory / power-up default of WR/IVR is `0x40`; CR powers up as `0x00` (MODE = 0).

### Bit Fields

#### `WR` / `IVR` (`0x00`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | — | Unused (write 0) |
| 6:0 | WR | Wiper position 0–127: `0` = wiper at `RL`, `127` = wiper at `RH` |

#### `CR` (`0x02`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | MODE | 0 = a write to address `0x00` updates **both** WR and IVR (EEPROM write follows the STOP condition); 1 = a write to address `0x00` updates **only** WR (SRAM, fast, no EEPROM wear) |
| 6:0 | — | Unused (write 0) |

Regardless of MODE, a read of address `0x00` returns WR (the IVR content can never be read back). Toggling MODE does not change the data held in SRAM or EEPROM.

## Initialization Sequence

1. Power VCC (2.5–5.5 V) and `V+` (> VCC); VCC above VPOR (1.2–2.4 V) triggers the power-up recall: the IVR is loaded into WR within tD ≤ 3 ms, after which the wiper is at the stored position.
2. Do not access the chip until tD (3 ms) after VCC > VPOR; `init` retries its first access once after 3 ms if it is NACKed.
3. Write `CR` (`0x02`) ← `0x80` (MODE = 1) so that routine wiper writes only touch SRAM and never wear the EEPROM; `init` leaves WR untouched (the wiper stays where the IVR put it).
4. Read WR (`0x00`) to initialise the driver's cached wiper code.

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits everything and adds the rest.

### Minimal

Goal: set and read back the wiper position, or the divider ratio / output voltage, volatile and without wearing the EEPROM.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection, `v_high: float = 1.0`, `v_low: float = 0.0` | — | Stores the connection and the voltages (V) applied to `RH` and `RL` used by the voltage conversions; runs the Initialization Sequence (MODE = 1, caches WR) |
| `set_wiper` | `code: int` (0–127) | — | Writes `0x00` ← `code` with MODE = 1 (SRAM only); clamps to [0, 127]; the wiper moves when the byte is acknowledged |
| `get_wiper` | — | `int` (0–127) | Reads `0x00` (WR) and masks bit 7 |
| `set_voltage` | `volts: float` | — | Sets the wiper for the output voltage `RW` at the nearest code between `v_low` and `v_high` (inverse of the formula below), clamped to the reachable range |
| `get_voltage` | — | `float` V | Unloaded `RW` voltage for the current code |

**Sensible defaults:** MODE = 1 (writes to `0x00` affect WR only), wiper left at the power-up (IVR) position, divider ends `v_high` = 1.0 V (a ratio) and `v_low` = 0 V until the application states the real `RH` / `RL` voltages; assumes no load on the wiper (≤ 1 mA).

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection, `v_high=1.0`, `v_low=0.0` | — | As Minimal |
| *(inherits Minimal)* | | | |
| `set_ratio` | `ratio: float` (0.0–1.0) | — | Wiper at `round(ratio × 127)` — divider ratio `V(RW−RL) / V(RH−RL)` |
| `get_ratio` | — | `float` | `code / 127` |
| `get_resistance` | `terminal: str = "L"` | `float` Ω | Nominal wiper-to-`RL` (`"L"`) or wiper-to-`RH` (`"H"`) resistance for the current code, `RTOTAL = 10 kΩ` (±20 %, so absolute values are approximate) |
| `increment` | `steps: int = 1` | `int` | Reads the code, adds `steps` (negative to decrement), clamps to [0, 127], writes (SRAM) and returns the new code |
| `store_wiper` | `code: int = None` | — | Writes the Initial Value Register: sets MODE = 0, writes `0x00` ← `code` (default: the current WR), waits for the EEPROM write (acknowledge polling, ≤ 20 ms), sets MODE = 1 again; the wiper also moves to `code`. Counts toward the EEPROM endurance (50 000 writes at 70 °C, 200 000 at 25 °C) |
| `set_mode` | `eeprom: bool` | — | `CR` ← `0x00` (`eeprom = True`: writes to `0x00` also program the IVR) or `0x80` (`False`: SRAM only); advanced use — `store_wiper` handles the mode itself |
| `get_mode` | — | `bool` | `True` if MODE = 0 (writes reach the EEPROM) — read from `CR` |
| `wait_ready` | `timeout_ms: float = 30` | — | Acknowledge polling: repeats an access (read of `CR`) until the chip ACKs; raises `TimeoutError` after `timeout_ms`; used after any write made with MODE = 0 |
| `set_endpoints` | `v_high: float`, `v_low: float = 0.0` | — | Changes the voltages used by the conversions (no I²C traffic) |

**Additional configuration options:** MODE (SRAM-only vs. EEPROM-backed writes), persistent power-up value (IVR), ratio / increment / resistance helpers, endpoint voltages.

## Data Conversion

```
V_RW(WR) = V_RL + (V_RH - V_RL) * WR / 127            # unloaded divider, WR = 0..127

WR = round((V - V_RL) / (V_RH - V_RL) * 127)          # inverse, clamp 0..127
ratio = WR / 127

R_WL(WR) = WR / 127 * RTOTAL                           # nominal, RTOTAL = 10 kΩ ±20 % (+ RW wiper resistance, see below)
R_WH(WR) = (127 - WR) / 127 * RTOTAL
```

The step size is `(V_RH − V_RL) / 127` — about 118 mV at 15 V span. The wiper resistance `RW` (the datasheet lists 5000 Ω at V+ = 15 V; the min / typ / max column is not legible in the text extraction) adds to the resistance seen at the wiper in rheostat use; the chip is specified for divider use with light loading, so the driver reports the nominal resistances without `RW`. Accuracy: INL ±1 LSB, DNL ±0.5 LSB, zero-scale error 0–2 LSB, full-scale error −2…0 LSB (V+ = 4.5 V).

## Timing Constraints

- **Power-up memory recall:** `tD` ≤ 3 ms from VCC > VPOR (1.2–2.4 V) until the IVR is loaded into WR.
- **EEPROM write time:** `tW` = 10 ms typical, 20 ms maximum, beginning after the STOP condition of a write to `0x00` with MODE = 0. During `tW` the device does not acknowledge its slave address; use acknowledge polling (`wait_ready`) or wait 20 ms.
- **Wiper response:** `tWRS` ≤ 1 µs after the data byte is acknowledged (the wiper moves at the ACK; the EEPROM write follows the STOP).
- **Endurance:** 50 000 EEPROM writes at 70 °C, 200 000 at 25 °C; programming temperature 0 °C … +70 °C. A write to WR/IVR with MODE = 1 does not count.
- **I²C:** fSCL ≤ 400 kHz, tBUF ≥ 1.3 µs, tHD:STA ≥ 0.6 µs, tLOW ≥ 1.3 µs, tHIGH ≥ 0.6 µs, tSU:DAT ≥ 100 ns, tSU:STA ≥ 0.6 µs, tSU:STO ≥ 0.6 µs; A0 / A1 setup 0.6 µs before START and hold 0.6 µs after STOP; spikes < 50 ns suppressed.
- **Conformance:** none of these has a bus-decodable start / end annotation pair that the host must honour (the chip simply NACKs during `tW`, and the recall delay is a power-up event), so `specs/adc_dac/ds3502_timing.conf` defines no checks.

## Implementation Notes

- **Register-addressed:** accept `RegisterConnection` (1-byte memory address) and call `connection.read(reg, 1)` / `connection.write(reg, bytes([v]))` directly — no chip-local `_read_reg`/`_write_reg` and no `bus_type` branch (see `specs/feature_register_access_design.md`).
- **MODE = 1 is the working mode:** with MODE = 0 (the power-up state) every write to `0x00` also writes the EEPROM after the STOP (10–20 ms busy, finite endurance). The datasheet's alternative for a volatile write in MODE 0 is to end the write with a repeated START instead of a STOP; a `RegisterConnection` write always ends with a STOP, so the driver sets MODE = 1 in `init` and `store_wiper` is the only operation that returns to MODE = 0 (and always restores MODE = 1, also on error).
- **`store_wiper` sequence:** write `CR` ← `0x00`; write `0x00` ← `code` (WR and IVR updated; EEPROM write starts at the STOP); `wait_ready()`; write `CR` ← `0x80`. The IVR cannot be read back — the driver cannot verify what was stored; it can only read WR (after power-cycling the chip).
- **Reads always return WR:** `get_wiper` returns the wiper position, not the stored power-up value, in both MODEs.
- **Bit 7 of the data byte** is unused; the driver always writes it as 0 and masks it on read.
- **Address-counter reads:** the datasheet requires "dummy write + repeated START + read" to read a specific address (the read otherwise starts at the current address counter); the `RegisterConnection` read performs the repeated-START form. If a platform issues a STOP between the address write and the read, it still works (the address counter is retained).
- **Voltages:** `RH`, `RL`, `RW` must stay within −0.3 V … `V+`, `V+` must be above VCC and 4.5–15.5 V; the wiper carries ≤ 1 mA, so buffer the output (e.g. with an op-amp) for heavier loads. Power VCC and `V+` before applying signals to RH / RL.
- **Resistance accuracy:** RTOTAL tolerance ±20 % at 25 °C; ratios are accurate to the INL / DNL specs, absolute resistance is not. The ratiometric temperature coefficient is ±4 ppm/°C.
- **Siblings:** the DS3502 is not compatible with the AD5243 / AD5248 (7-bit nonvolatile with a MODE register vs. 8-bit volatile with an instruction byte); its address range `0x28`–`0x2B` does not overlap theirs (`0x2C`–`0x2F`), so the parts can share a bus.
- **Addressing mistake to avoid:** the datasheet quotes the *8-bit* write byte `0x50`; the 7-bit address handed to the `Connection` is `0x28`.
- **Datasheet revision:** Rev 1 (3/09), 11 pages, attached to the issue; package 10-pin µSOP (DS3502U+).

## Sigrok Decoder

Decoder id `ds3502`, input `['i2c']`. Matches I²C addresses `0x28`–`0x2B`. Annotates writes to `0x00` as the wiper code with `code/127` as a ratio and, based on the last `CR` write seen (MODE = 0 after power-up until the first `CR` write), notes "WR+IVR (EEPROM write follows STOP, tW 10–20 ms)" or "WR only"; annotates writes to `0x02` as `CR` with the decoded MODE; shows reads of `0x00` as the returned WR value and reads of `0x02` as CR. A transaction whose address byte is NACKed shortly after a MODE = 0 write is annotated "busy (EEPROM write)". Warnings: data byte with bit 7 set, writes to addresses other than `0x00` / `0x02`, and a write to `0x00` while MODE = 0 (EEPROM wear notice). No timing annotation pair is emitted, since no constraint is conformance-checked.
