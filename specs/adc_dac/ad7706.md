# Chip Spec: AD7706

**Manufacturer:** Analog Devices
**Datasheet:** `datasheets/adc_dac/ad7706.pdf`
**Category:** adc_dac
**Transports:** SPI

## Overview

The AD7706 is a 3-channel, 16-bit sigma-delta ADC intended for low-frequency measurement applications such as pressure/load-cell bridges, temperature sensors, and other low-level transducer signals. It integrates a programmable-gain front end (gain 1 to 128), a fully differential reference input, an on-chip digital low-pass filter with a selectable output rate, and self-/system-calibration logic that removes offset and gain error in the analog front end. The part is a member of the AD7705/AD7706 family; this spec covers only the AD7706 (3 pseudo-differential input channels — AIN1, AIN2, AIN3 — each measured relative to a single shared `COMMON` pin). The AD7705 (2 fully differential channels, no shared reference pin) is pin- and register-compatible but is a separate chip, tracked separately at `specs/adc_dac/ad7705.md` — do not add AD7705-specific fully-differential channel handling here.

Because all three channels share one reference node (`COMMON`), the AD7706 is well suited to multi-point measurement systems where several single-ended-ish sensors can share one return line, trading the second fully-differential input pair of the AD7705 for a third channel.

The part requires an external master clock (crystal/resonator across MCLK IN/MCLK OUT, or a driven CMOS clock on MCLK IN) at one of four supported frequencies (1 MHz, 2 MHz, 2.4576 MHz, or 4.9152 MHz); this frequency is fixed by the hardware design and must be told to the driver so it can program the matching clock-register bits.

## Transport Configuration

### SPI
- **Mode:** CPOL=1 CPHA=1 (Mode 3) — SCLK idles high between transfers, per the datasheet's microcontroller-interface recommendation; SCLK is a Schmitt-triggered input so idle polarity is not electrically required, but Mode 3 is what every reference interface (68HC11, 8XC51, ADSP-2103/2105) in the datasheet uses
- **Max clock:** 5 MHz (from t6/t7 minimum SCLK high/low pulse widths of 100 ns each)
- **Bit order:** MSB first
- **CS active:** low

All register access is two-phase: first an 8-bit write to the Communication Register selects the target register and read/write direction, then the selected register's data is transferred in the following SPI transaction (see Register Map and Initialization Sequence).

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| RESET | low | Optional. Resets logic, filter, modulator, and registers to power-on defaults. May be hardwired high in hardware if software reset is not needed — the driver treats it as optional and omits `reset()` when no pin is supplied. |
| DRDY | low, output | Data-ready status. The driver never requires a dedicated GPIO for this: `DRDY` is polled via the `0/DRDY` bit of the Communication Register over the existing SPI connection (the same technique the datasheet describes for 3-wire microcontroller interfaces), so only SCLK/DIN/DOUT/CS are needed. |

Analog pins AIN1, AIN2, AIN3, and COMMON are wiring concerns only (each channel is measured as `AINx` relative to `COMMON`) — the driver has no pin-level knowledge of them beyond the register-level channel select bits.

## Register Map

Registers are not memory-mapped; they are selected by writing the 3-bit RS2:RS0 field into the Communication Register, together with the R/W direction bit, before every access.

| RS2:RS0 | Name | R/W | Size | Power-On Reset | Description |
|---------|------|-----|------|-----------------|-------------|
| `000` | Communication Register | R/W | 8 bits | `0x00` | Selects the next register and access direction; also carries STBY and channel-select bits |
| `001` | Setup Register | R/W | 8 bits | `0x01` | Operating mode, gain, bipolar/unipolar, buffer, FSYNC |
| `010` | Clock Register | R/W | 8 bits | `0x05` | Clock scaling and filter output-rate selection |
| `011` | Data Register | R only | 16 bits | — | Latest conversion result |
| `100` | Test Register | R/W | 8 bits | `0x00` | Factory test only — never write a non-zero value |
| `101` | *(no operation)* | — | — | — | Reserved RS combination; do not select |
| `110` | Zero-Scale (Offset) Calibration Register | R/W | 24 bits | `0x1F4000` | Per-channel offset coefficient, one of three register pairs (Table 13) |
| `111` | Full-Scale (Gain) Calibration Register | R/W | 24 bits | `0x5761AB` | Per-channel gain coefficient, one of three register pairs (Table 13) |

Channel selection and calibration register-pair assignment (datasheet Table 13, "Channel Selection for AD7706"):

| CH1 | CH0 | AIN | Reference | Calibration Register Pair |
|-----|-----|-----|-----------|----------------------------|
| 0 | 0 | AIN1 | COMMON | Register Pair 0 |
| 0 | 1 | AIN2 | COMMON | Register Pair 1 |
| 1 | 0 | COMMON | COMMON | Register Pair 0 (internal noise/self-test mode — see Implementation Notes) |
| 1 | 1 | AIN3 | COMMON | Register Pair 2 |

Unlike the AD7705 — where both `CH1,CH0 = 10` and `11` select internal test modes — the AD7706 only reserves `10` for the internal COMMON-shorted-to-itself test mode; `11` selects the real third channel, AIN3, sharing calibration Register Pair 2 with that bit pattern.

### Bit Fields

#### Communication Register (`RS2:RS0 = 000`)

| Bit | Name | Description |
|-----|------|-------------|
| 7 | `0/DRDY` | Write: must be 0. Read: data-ready flag, same value as the `DRDY` pin (0 = ready) |
| 6:4 | `RS2:RS0` | Register-select bits for the *next* access |
| 3 | `R/W` | 0 = write, 1 = read (direction of the next access) |
| 2 | `STBY` | 1 = standby/power-down (retains registers, ~10 µA); 0 = normal operation |
| 1:0 | `CH1:CH0` | Channel select — `00` = AIN1, `01` = AIN2, `10` = internal test mode, `11` = AIN3 (all relative to COMMON) |

#### Setup Register (`RS2:RS0 = 001`)

| Bit | Name | Description |
|-----|------|-------------|
| 7:6 | `MD1:MD0` | Operating mode — `00` normal, `01` self-calibration, `10` zero-scale system calibration, `11` full-scale system calibration |
| 5:3 | `G2:G0` | PGA gain select: `000`=1, `001`=2, `010`=4, `011`=8, `100`=16, `101`=32, `110`=64, `111`=128 |
| 2 | `B/U` | 0 = bipolar (±V_REF/gain, offset binary output), 1 = unipolar (0 to V_REF/gain, straight binary output) |
| 1 | `BUF` | 0 = analog input buffer bypassed (lower power, restricts source impedance); 1 = buffered (handles higher source impedance) |
| 0 | `FSYNC` | 1 = hold filter/modulator in reset (no conversions); 0 = run. Used for synchronized starts across multiple parts |

#### Clock Register (`RS2:RS0 = 010`)

| Bit | Name | Description |
|-----|------|-------------|
| 7:5 | `ZERO` | Must be written as 0 |
| 4 | `CLKDIS` | 1 = disable MCLK OUT (power saving when using an external clock and not distributing it elsewhere) |
| 3 | `CLKDIV` | 1 = MCLK IN is divided by 2 internally (crystal/clock is 2× the part's internal working frequency) |
| 2 | `CLK` | 1 = internal working frequency is 2.4576 MHz (MCLK IN = 2.4576 MHz with `CLKDIV`=0, or 4.9152 MHz with `CLKDIV`=1); 0 = internal working frequency is 1 MHz (MCLK IN = 1 MHz with `CLKDIV`=0, or 2 MHz with `CLKDIV`=1) |
| 1:0 | `FS1:FS0` | Filter output-rate select within the family chosen by `CLK` — see Table below |

| `CLK` | `FS1,FS0=00` | `01` | `10` | `11` |
|-------|--------------|------|------|------|
| 0 | 20 Hz | 25 Hz | 100 Hz | 200 Hz |
| 1 | 50 Hz | 60 Hz | 250 Hz | 500 Hz |

`CLKDIV` and `CLK` together are fully determined by the external MCLK frequency:

| MCLK IN | `CLKDIV` | `CLK` | Output-rate family |
|---------|----------|-------|---------------------|
| 1 MHz | 0 | 0 | 20/25/100/200 Hz |
| 2 MHz | 1 | 0 | 20/25/100/200 Hz |
| 2.4576 MHz | 0 | 1 | 50/60/250/500 Hz |
| 4.9152 MHz | 1 | 1 | 50/60/250/500 Hz |

## Initialization Sequence

This follows the datasheet's own configuration flowchart and example code (Figure 21 / "Code for Setting Up the AD7705/AD7706"), which the Minimal class default configuration reproduces exactly (Channel 1, gain 1, bipolar, unbuffered, 50 Hz, self-calibration):

1. Write Communication Register = `0x20` (select Channel 1, next operation = write to Clock Register)
2. Write Clock Register with `CLKDIV`/`CLK` derived from `mclk_hz` and `FS1:FS0` chosen for the requested output rate (e.g. `0x0C` for a 4.9152 MHz clock at 50 Hz)
3. Write Communication Register = `0x10` (select Channel 1, next operation = write to Setup Register)
4. Write Setup Register = `0x40` (gain 1, `MD1:MD0=01` self-calibration, bipolar, unbuffered, FSYNC clear)
5. Poll the Communication Register's `0/DRDY` bit (or the `DRDY` pin) until it reads ready — self-calibration duration is `6 × 1/output_rate` typical, `DRDY` returns ready after `9 × 1/output_rate + t_P`
6. Device is ready: write Communication Register = `0x38` (select Channel 1, next operation = read Data Register) before each conversion read

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits everything and adds the rest.

### Minimal

Goal: read calibrated voltage from Channel 1 (AIN1 relative to COMMON) with sensible defaults. No configuration required beyond the connection, the external reference voltage, and the external clock frequency actually wired to the part.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection`, `vref` (V), `mclk_hz` (one of 1 000 000 / 2 000 000 / 2 457 600 / 4 915 200) | — | Runs the Initialization Sequence above: gain 1, bipolar, unbuffered, 50 Hz output rate, self-calibrates Channel 1, blocks until calibration completes |
| `read_raw` | — | int | Blocks until `DRDY`; selects Data Register read on Channel 1; returns the raw 16-bit code |
| `read_voltage` | — | float | `read_raw()` converted to volts using gain 1 and bipolar coding (see Data Conversion) |

**Sensible defaults:** Channel 1 (AIN1 vs COMMON), gain 1, bipolar mode, analog input buffer bypassed, 50 Hz output rate (2.4576 MHz/4.9152 MHz clock family) or 20 Hz (1 MHz/2 MHz clock family) depending on `mclk_hz`, self-calibration run once at `init`.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `configure` | `channel` (1, 2, or 3), `gain` (1/2/4/8/16/32/64/128), `bipolar: bool`, `buffered: bool`, `output_rate_hz` (must be one of the four rates in the family selected by `mclk_hz`) | — | Writes Setup Register + Clock Register for the given channel; does not calibrate — call a calibration method afterward |
| `read_raw` | `channel` (1, 2, or 3, default 1) | int | Blocks until `DRDY`; reads Data Register for the given channel |
| `read_voltage` | `channel` (1, 2, or 3, default 1) | float | Converts using that channel's current gain/bipolar setting |
| `self_calibrate` | `channel` (1, 2, or 3, default 1) | — | `MD1:MD0=01`; blocks until `DRDY` indicates completion |
| `system_calibrate_zero` | `channel` (1, 2, or 3, default 1) | — | `MD1:MD0=10`; caller must present the zero-scale voltage at AIN before calling and hold it stable until this returns |
| `system_calibrate_full` | `channel` (1, 2, or 3, default 1) | — | `MD1:MD0=11`; caller must present the full-scale voltage at AIN before calling and hold it stable until this returns |

**Additional configuration options:**
- Channel 2 (AIN2) and Channel 3 (AIN3) access, each with its own independent gain/bipolar/calibration state
- All eight PGA gain settings (1–128)
- Unipolar mode
- Analog input buffer enable
- All four output rates within the clock family fixed by `mclk_hz`
- System (zero-scale / full-scale) calibration in addition to self-calibration
- Direct read/write of the raw 24-bit calibration coefficients
- Standby / wake power control
- Optional hardware reset

## Data Conversion

The Data Register outputs a 16-bit code. Coding depends on the `B/U` bit (Setup Register):

```
Unipolar (B/U = 1):
    voltage = (code / 65536) * (vref / gain)
    range: 0 to +vref/gain

Bipolar (B/U = 0), offset binary:
    voltage = ((code - 32768) / 32768) * (vref / gain)
    range: -vref/gain to +vref/gain
```

`vref` is the externally-supplied reference voltage (REF IN(+) − REF IN(−)), fixed by the hardware design (e.g. 2.5 V from an AD780/REF192 at V_DD=5 V, or 1.225 V at V_DD=3 V) — the driver never measures it and takes it as a required `init` parameter.

### Demo flow

An inject node fires every 2 seconds to trigger a 3-channel read; the output splits via a function node into `channel1`, `channel2`, `channel3` (three independent points in a manifold pressure-monitoring system per the Examples § Demo scenario), each feeding its own debug node and a chart node (node-red-dashboard) for a live 3-trace comparison. ## Examples

### Demo

Implement a 3-point HVAC air-handling manifold pressure-monitoring system, taking advantage of the AD7706's shared-`COMMON` architecture to wire three independent pressure transducers with a single common return instead of three fully-differential pairs: Channel 1 (AIN1) reads filter-inlet static pressure, Channel 2 (AIN2) reads filter-outlet static pressure (the difference between Channel 1 and Channel 2 is the filter's differential pressure, an indicator of clogging), and Channel 3 (AIN3) reads duct static pressure downstream of the fan. All three are bridge-type transducers, so use gain 128 (small differential mV-level signals). At startup, self-calibrate all three channels. Then loop continuously: read all three channels every 200 ms, compute `filter_dp = channel1_reading - channel2_reading`, and print `→ filter_dp=<value> V, duct_pressure=<value> V` whenever either value changes by more than a defined threshold.

- **Self-calibration duration:** `6 × 1/output_rate` (mode bits return to `00`); `DRDY` indicates completion after `9 × 1/output_rate + t_P` (t_P never exceeds `2000 × t_CLKIN`)
- **System (zero-scale or full-scale) calibration duration:** `3 × 1/output_rate` (mode bits); `DRDY` after `4 × 1/output_rate + t_P`
- **Filter settling time after a step input:** up to `4 × 1/output_rate` (unsynchronized), or `3 × 1/output_rate` if the step is aligned with an `FSYNC` reset
- **Oscillator start-up time** (crystal/resonator, before the first calibration): ~16 ms at 2.4576 MHz, ~6 ms at 4.9152 MHz, ~20 ms at 1 MHz (typical, 5 V supply; ~20% slower at 3 V)

## Implementation Notes

- **Two-phase register access:** every register read or write is preceded by its own write to the Communication Register selecting the target register and direction. The driver must never write directly to a register without first writing the Communication Register in the same logical operation.
- **`DRDY` is polled over SPI, not a dedicated pin:** the driver reads the Communication Register and inspects bit 7 (`0/DRDY`), matching the datasheet's documented 3-wire microcontroller interface technique. This keeps the transport a plain 4-wire SPI connection (SCLK/DIN/DOUT/CS) with no extra GPIO required. Consumers who do wire the physical `DRDY` pin to a GPIO for interrupt-driven reads are outside this driver's scope (poll-based only, matching Minimal/Full's synchronous API style used throughout this library).
- **`mclk_hz` is a required, not autodetected, parameter:** the AD7706 has no way to report its own master clock frequency over the digital interface — it is fixed by the crystal/resonator or external clock the hardware designer wired to MCLK IN. Passing the wrong value silently produces a wrong output rate and wrong calibration timing (the CLK/CLKDIV bits it derives are used purely for timing math, not sampled).
- **`vref` is a required, not autodetected, parameter:** the AD7706 has no on-chip reference; REF IN is always fully external. There is no sensible default — hardcoding one (e.g. 2.5 V) would silently corrupt every reading on a 3 V/1.225 V design.
- **Calibration is required after every power-on, reset, or configuration change:** the power-on default calibration coefficients are nominal placeholders, not part-specific values. `configure()` deliberately does not auto-calibrate — callers must call `self_calibrate` (or the two-step system calibration) afterward, exactly as the Setup Register bit fields imply (`MD1:MD0` normal-mode default is `00`, calibration is a distinct explicit mode).
- **`CH1:CH0 = 10` (internal COMMON-shorted test mode) is not exposed:** per the datasheet's Communication Register description, this internally shorts COMMON to itself for noise characterization only — a factory/debug aid, not a fourth measurement channel, and intentionally left out of the driver's public API. Unlike the AD7705 (where both `10` and `11` are test modes), on the AD7706 `11` selects the real third channel, AIN3, and is fully exposed as `channel=3`.
- **Test Register (`RS2:RS0 = 100`) must never be written non-zero:** the datasheet explicitly warns this places the part into an undocumented test mode. The driver never writes to this register.
- **AD7705 is a different, separate chip:** shares the register map and SPI protocol, but has 2 fully differential channels (AIN1(±), AIN2(±)) instead of 3 pseudo-differential channels referenced to a shared COMMON pin, and the `CH1,CH0 = 11` bit pattern is a test mode on the AD7705 rather than a real channel. Tracked separately — do not add its fully-differential channel semantics here.
- **Settling time after any Setup/Clock Register change:** the filter needs up to `4 × 1/output_rate` to settle after gain, bipolar/unipolar, channel, or output-rate changes take effect — the first `read_raw`/`read_voltage` after `configure()` should be treated as potentially stale, and a recalibration is recommended (per datasheet Calibration section) whenever gain, filter notch, or bipolar/unipolar mode changes.

## Sigrok Decoder

Decoder id `ad7706` (`sigrok/ad7706/`), stacking on the `spi` decoder like the existing `rfm9x` decoder, input `['spi']`. Tracks the two-phase protocol as state: annotates each Communication Register byte (`comm`, decoded into `RS2:RS0` target register name, `R/W` direction, `STBY`, and `CH1:CH0` — including which of AIN1/AIN2/AIN3/internal-test the channel bits select), then annotates the following transaction against the register it selected — `setup` (MD/gain/B-U/BUF/FSYNC fields), `clock` (CLKDIS/CLKDIV/CLK/FS1:FS0 fields and the resulting output rate), `data` (16-bit conversion result, decoded to volts using the last-configured gain/bipolar state for that channel — annotation pair `read_start`/`read_done` marks a Data Register read for conformance checking), `calibration` (24-bit zero-scale/full-scale register access), and `warning` (a register access attempted without a preceding Communication Register write, or the Test Register selected).
