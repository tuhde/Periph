# Chip Spec: AD5252

**Manufacturer:** Analog Devices  
**Datasheet:** `datasheets/adc_dac/ad5252.pdf` (shared AD5251 / AD5252 datasheet, Rev. G)  
**Category:** adc_dac  
**Transports:** I²C

## Overview

The AD5252 is a dual-channel, 256-position, I²C-controlled digital potentiometer with **nonvolatile memory** (EEMEM): each channel's wiper setting can be stored and is automatically restored at power-on (default `128` = midscale until a value is stored). End-to-end resistance RAB: 1 kΩ, 10 kΩ, 50 kΩ or 100 kΩ. Each channel is a full 3-terminal potentiometer (A, W, B) usable as a voltage divider or a 2-terminal rheostat, with a 2.7–5.5 V supply. Beyond direct RDAC read/write the chip offers 12 quick commands (store/restore RDAC↔EEMEM, ±1 step, ±6 dB (doubling/halving) per channel or for both channels, reset), 12 bytes of user EEMEM (EEMEM4…EEMEM15), a stored factory RAB tolerance per channel, a write-protect pin and EEMEM write-acknowledge polling. The AD5252 and AD5251 share one datasheet and interface but are tracked as two chips; this spec covers only the AD5252 (8-bit wiper, `0`–`255`); its sibling AD5251 has its own spec (`specs/adc_dac/ad5251.md`).

## Transport Configuration

### I²C
- **Address:** `0x2C` + (AD1 << 1 | AD0): `0x2C`–`0x2F` (7-bit address `01011 AD1 AD0`; up to four devices per bus)
- **Max clock:** 400 kHz (fast mode)
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`)
- **Probe safety:** `write_sensitive` — a 1-byte write is an instruction byte (a quick command such as `0xB8` reset, `0x91` store to EEMEM, or an RDAC/EEMEM pointer); a bare write of a quick-command byte would change the wiper or start a 26 ms EEMEM write
- **Protocol:** instruction-byte protocol; the instruction byte works as a one-byte register pointer, so the driver uses `RegisterConnection` with `reg_bytes` = 1: `write(instr, data)` is `[addr+W][instr][data]…` and `read(instr, n)` is a dummy write of `instr` followed by a read of `n` bytes (the pointer increments for consecutive reads/writes)

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| A1, W1, B1, A3, W3, B3 | — | Potentiometer terminals of channel 1 (RDAC1) and channel 2 (RDAC3); GND/VSS to VDD |
| AD0, AD1 | — | I²C address bits |
| WP | low | write protect: low protects the EEMEM **and the RDAC registers** from writes; reads work normally; pull high (or leave per the datasheet) when programming |
| SDA, SCL | — | I²C; external pull-ups required |
| VDD, VSS, GND | — | 2.7–5.5 V; VDD and VSS must supply/sink 35 mA for ≈ 26 ms during EEMEM stores |

There is no reset or interrupt pin. Channel naming: channel 0 = RDAC1, channel 1 = RDAC3 (the datasheet uses 1 and 3).

## Register Map

The chip has no register map; the **instruction byte** addresses the RDAC and EEMEM registers.

| Instruction | Name | R/W | Reset | Description |
|-------------|------|-----|-------|-------------|
| `0x01` | RDAC1 | R/W | `128` (midscale or EEMEM1) | Channel 0 wiper (8-bit) |
| `0x03` | RDAC3 | R/W | `128` (midscale or EEMEM3) | Channel 1 wiper (8-bit) |
| `0x21` | EEMEM1 | R/W | `128` | Stored RDAC1 value, restored at power-on |
| `0x23` | EEMEM3 | R/W | `128` | Stored RDAC3 value |
| `0x24`–`0x2F` | EEMEM4…EEMEM15 | R/W | `0x00` (user data) | 12 bytes of user-defined nonvolatile data |
| `0x3A` | TOLERANCE_RDAC1_INT | R | factory | RDAC1 RAB tolerance: sign (bit 7) and 7-bit integer percent |
| `0x3B` | TOLERANCE_RDAC1_DEC | R | factory | RDAC1 tolerance decimal part (units of 2⁻⁸ %) |
| `0x3E` | TOLERANCE_RDAC3_INT | R | factory | RDAC3 tolerance sign + integer |
| `0x3F` | TOLERANCE_RDAC3_DEC | R | factory | RDAC3 tolerance decimal part |

### Bit Fields

#### Instruction byte, register access (R/W = 0 write or R/W = 1 read pointer)

| Bits | Name | Description |
|------|------|-------------|
| 7 | CMD/REG | `0` = register access, `1` = quick command |
| 6 | X | Don't care — write `0` |
| 5 | EE/RDAC | `0` = RDAC register, `1` = EEMEM register |
| 4:0 | A4:A0 | Register address (`00001` RDAC1/EEMEM1, `00011` RDAC3/EEMEM3, `00100`…`01111` EEMEM4…15; tolerance `11010`/`11011` RDAC1, `11110`/`11111` RDAC3, with EE/RDAC = 1) |

Data byte: bits 7:0 = wiper setting `0`–`255` (`0` wiper at B, `255` at A). **Consecutive write:** after the instruction byte every further data byte goes to the next register (`0x01` → RDAC1 then RDAC3). A write to an EEMEM register starts an internal write cycle (≈ 26 ms) during which the interface does not ACK.

#### Quick command byte (CMD/REG = 1): `1 C3 C2 C1 C0 A2 A1 A0`

| C3:C0 | Command | Byte (RDAC1 / RDAC3 or all) |
|-------|---------|------------------------------|
| `0000` | NOP | `0x80` |
| `0001` | Restore EEMEM(A1:A0) → RDAC(A1:A0) (follow with NOP) | `0x89` / `0x8B` |
| `0010` | Store RDAC(A1:A0) → EEMEM (needs ACK polling) | `0x91` / `0x93` |
| `0011` | Decrement RDAC 6 dB (halve) | `0x99` / `0x9B` |
| `0100` | Decrement all RDACs 6 dB | `0xA0` |
| `0101` | Decrement RDAC one step | `0xA9` / `0xAB` |
| `0110` | Decrement all RDACs one step | `0xB0` |
| `0111` | Reset: restore EEMEMs to all RDACs (needs ACK polling) | `0xB8` |
| `1000` | Increment RDAC 6 dB (double) | `0xC1` / `0xC3` |
| `1001` | Increment all RDACs 6 dB | `0xC8` |
| `1010` | Increment RDAC one step | `0xD1` / `0xD3` |
| `1011` | Increment all RDACs one step | `0xD8` |
| `11xx` | Reserved | — |

A2 is 0; A1:A0 = `01` selects RDAC1, `11` RDAC3 (the "all" commands ignore A1:A0 — send A bits as 0). A third data byte is allowed but not needed.

## Initialization Sequence

1. Power up (VDD 2.7–5.5 V). The RDACs first go to midscale, then the EEMEM contents are restored within ≈ 300 µs (depends on the VDD rise time); EEMEM can be written ≈ 540 µs after power-up.
2. No configuration is required; write RDAC1/RDAC3 to set the wipers.
3. To make a setting power-on persistent: store with the quick command (or write EEMEM1/EEMEM3) and wait for ACK polling to succeed (≈ 26 ms).

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits everything and adds the rest.

### Minimal

Goal: set and read back the wiper position or the wiper-to-B resistance of either channel.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection`, `r_ab: float = 10000.0`, `r_wiper: float = 75.0` | — | Stores the connection (`RegisterConnection`, `reg_bytes` = 1) and the part's RAB (Ω) and wiper resistance RW (Ω); no I²C traffic |
| `set_wiper` | `channel: int` (0–1), `code: int` (0–255) | — | Writes the RDAC (`0x01` / `0x03`); clamps `code` to [0, 255]; invalid `channel` raises |
| `get_wiper` | `channel: int` | `int` | Reads the RDAC |
| `set_resistance` | `channel: int`, `ohms: float` | — | W–B resistance, nearest code, clamped to the reachable range |
| `get_resistance` | `channel: int` | `float` Ω | W–B resistance for the current code |

**Sensible defaults:** RAB = 10 kΩ, RW = 75 Ω (typical); channels at their power-on value (EEMEM or midscale `128`).

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `set_both` | `code0: int`, `code1: int` | — | Consecutive write of both RDACs in one transaction |
| `set_ratio` / `get_ratio` | `channel`, `ratio: float` / `channel` | — / `float` | Divider ratio `code / 256` (clamped to `255`) |
| `set_resistance_wa` / `get_resistance_wa` | `channel`, `ohms` / `channel` | — / `float` Ω | W–A resistance |
| `increment` / `decrement` | `channel: int \| None` (`None` = both) | — | One-step quick commands |
| `double` / `halve` | `channel: int \| None` | — | ±6 dB quick commands (shift the code left / right) |
| `store` | `channel: int \| None` | — | Store RDAC → EEMEM (quick command) then ACK polling (timeout 100 ms) |
| `restore` | `channel: int \| None` | — | Restore EEMEM → RDAC, then NOP |
| `reset` | — | — | Quick command `0xB8` (restore both from EEMEM), ACK polling |
| `read_eemem` / `write_eemem` | `index: int` (4–15) / `index, value` | `int` / — | User EEMEM bytes; the write is followed by ACK polling (≈ 26 ms) |
| `read_tolerance` | `channel: int` | `float` % | Stored RAB tolerance (sign-magnitude, integer byte + decimal byte) |
| `rab_actual` | `channel: int` | `float` Ω | `r_ab × (1 + tolerance / 100)` |
| `nop` | — | — | `0x80`, returns the device to the idle power state |
| `set_rab` | `r_ab: float`, `r_wiper: float \| None = None` | — | Changes the resistance model parameters (no I²C traffic) |

**Additional configuration options:** EEMEM store/restore of wiper settings, user EEMEM, quick increment/decrement and ±6 dB commands, resistance model parameters. The WP pin is hardware only.

## Data Conversion

```
R_WB(D) = D / 256 * RAB + RW                  # wiper to B, A open  (RW ≈ 75 Ω)
R_WA(D) = (256 - D) / 256 * RAB + RW          # wiper to A, B open
V_W(D)  = D / 256 * V_A + (256 - D) / 256 * V_B   # divider mode

D = round((R - RW) / RAB * 256)               # inverse for R_WB, clamp 0..255

tolerance_pct = (-1 if int_byte & 0x80 else 1) * ((int_byte & 0x7F) + dec_byte / 256)
RAB_actual = RAB * (1 + tolerance_pct / 100)
```

Example (datasheet): integer byte `0x1C`, decimal byte `0x0F` → +28.0586 % → a 10 kΩ nominal part is 12.806 kΩ. The 6 dB commands shift the code (code × 2 or ÷ 2) and saturate at the ends.

## Timing Constraints

| Constraint | Value |
|------------|-------|
| EEMEM store (RDAC→EEMEM or EEMEM write) | ≈ 26 ms (35 mA); interface does not ACK meanwhile |
| EEMEM restore at power-on / restore command | ≈ 300 µs typ. |
| EEMEM rewritable after power-on or reset | ≈ 540 µs typ. |
| I²C clock | ≤ 400 kHz |

**Conformance:** the store/restore times are typical values only (completion is detected by ACK polling), so `specs/adc_dac/ad5252_timing.conf` defines no checks.

## Implementation Notes

- **Instruction byte = register pointer:** use `RegisterConnection` (`reg_bytes` = 1). A read is a dummy write of the instruction followed by the read; with no new instruction the next read continues at the pointer + 1.
- **ACK polling:** after an EEMEM write, `store` or `reset` the chip does not ACK its address; poll with a write-address probe until it ACKs (timeout 100 ms).
- **After `restore`** issue a NOP to return to idle (lower supply current); after an EEMEM *read* no NOP is needed.
- **WP low** blocks all RDAC and EEMEM writes (reads still work): a "stuck" wiper is usually WP.
- **Tolerance addresses:** Table 11 of the datasheet lists `11010/11011` (RDAC1) and `11110/11111` (RDAC3), while the worked example reads `11000/11001`; the driver uses the table addresses — verify on hardware.
- **Zero scale is not 0 Ω:** at code 0 the W–B resistance is RW ≈ 75 Ω; keep wiper current within the datasheet limits.
- **Address overlap:** `0x2C`–`0x2F` overlaps AD5251, AD5243 (`0x2F`) and AD5248; devices with the same address cannot share a bus.
- **Shared datasheet:** `datasheets/adc_dac/ad5251.pdf` and `ad5252.pdf` are the same file.

## Sigrok Decoder

Decoder id `ad5252`, input `['i2c']`. Matches I²C addresses `0x2C`–`0x2F`. Annotates the instruction byte (RDAC/EEMEM register, quick command by name), decodes wiper data bytes as codes and fractions of full scale, EEMEM stores/restores, tolerance bytes and the NACK while the EEMEM write cycle is running (ACK polling). No timing annotation pair is emitted.
