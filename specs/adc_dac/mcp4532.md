# Chip Spec: MCP4532

**Manufacturer:** Microchip Technology  
**Datasheet:** `datasheets/adc_dac/mcp4532.pdf` (shared MCP453X/455X/463X/465X datasheet, DS22096B, 2013; the MCP4532 is the 7-bit single-rheostat device with volatile memory)  
**Category:** `adc_dac`  
**Transports:** I²C

## Overview

The MCP4532 is a single, 7-bit (129-step), volatile digital **rheostat** (variable resistor) with an I²C interface, in an 8-pin MSOP / DFN package. The resistor network is 128 equal resistors between terminal B and the internal terminal A (which is *not* brought out on the "2" devices), with the wiper `P0W` selecting any of 129 taps (code 0 = wiper at `P0B`, code 128 = full scale). The end-to-end resistance RAB is ordered as 5 kΩ (-502), 10 kΩ (-103), 50 kΩ (-503) or 100 kΩ (-104); the wiper resistance is about 75 Ω. The wiper powers up at mid-scale (code `0x40`). The serial interface supports 100 kHz, 400 kHz and 3.4 MHz (HS mode), wiper read / write, **increment / decrement commands**, a Terminal Control (TCON) register for disconnecting terminals (shutdown), and an optional I²C **General Call** for synchronised updates. VDD is 1.8–5.5 V (2.7 V minimum for specified analog performance); the digital inputs tolerate up to 12.5 V. The MCP4531 (potentiometer), MCP4551/4552 (8-bit), MCP4631/4632/4651/4652 (dual) and the non-volatile MCP4541/4542/4561/4562/4641/4642/4661/4662 share this datasheet and command format but are separate chips; this spec covers only the MCP4532. Wiper values are **volatile**: they are lost at power-down (POR sets mid-scale).

## Transport Configuration

### I²C
- **Address:** `0x58` (A1 = A0 = GND) … `0x5B` (A1 = A0 = VDD); 7-bit address `0101 1 A1 A0` (MCP45X2: "0101 1'b + A1:A0"), up to 4 devices. The address pin **A0 is multiplexed with the high-voltage-command pin HVC/A0**: its level is latched at POR/BOR

| A1 | A0 (HVC/A0) | 7-bit address |
|----|-------------|---------------|
| GND | GND | `0x58` |
| GND | VDD | `0x59` |
| VDD | GND | `0x5A` |
| VDD | VDD | `0x5B` |

- **Max clock:** 400 kHz (the library drives ≤ 400 kHz; standard mode 100 kHz and HS mode 3.4 MHz are also supported by the chip — HS mode needs a master code that `Connection` does not provide)
- **Identity register:** none; chip has no ID register (feeds `registry/chips.json` with `"id_probe": null` and `"driver": null` until implemented, see `specs/feature_i2c_discovery.md`)
- **Probe safety:** `write_sensitive` — the first byte after the address is a **command byte**, and a command byte with the increment / decrement operation is a complete one-byte command that moves the wiper (`0x04` = increment wiper 0, `0x08` = decrement), so a stray single-byte write can change the resistance
- **Register addressing:** command byte `AD3 AD2 AD1 AD0 C1 C0 D9 D8` (`RegisterConnection`, `reg_bytes = 1`, the command byte plays the role of the register address): `AD` = memory address (`0` wiper 0, `4` TCON), `C1:C0` = operation (`00` write, `01` increment, `10` decrement, `11` read), `D9:D8` = the two most significant data bits (D9 unused, D8 used by 8-bit / 9-bit values). Write = `[addr+W] [command byte] [data byte]`; read = `[addr+W] [command byte with C=11] [Sr] [addr+R] [data high] [data low]` — a read returns **two bytes** (`0000 000D8`, `D7…D0`). The chip retains the last memory address received (POR: `0x00`)

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| SDA, SCL | — | I²C (open-drain SDA); high-voltage tolerant up to 12.5 V; the chip does not stretch SCL |
| HVC/A0 | — | Address bit 0 (latched at POR/BOR) and high-voltage-command input; not used by the MCP4532 (the high-voltage commands only matter for the non-volatile siblings); tie to GND or VDD (internal weak "smart" pull-up) |
| A1 | — | Address bit 1; tie to GND or VDD (weak pull-up while VDD < VBOR) |
| P0W | — | Wiper terminal |
| P0B | — | Terminal B (zero-scale end) |
| VDD, VSS | — | Supply 1.8–5.5 V (2.7 V for specified performance) |

There is no reset, interrupt or enable pin. All resistor terminals (`P0W`, `P0B`) must stay between VSS and VDD; their polarity relative to each other is not restricted; terminal currents ≤ 2.5 mA.

## Register Map

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | WIPER0 | R/W | `0x040` | Volatile wiper 0 (9-bit field, 7-bit device uses 0–128) |
| `0x04` | TCON | R/W | `0x1FF` | Terminal control register (9 bits) |

Addresses `0x01` (wiper 1), `0x02`, `0x03`, `0x05` (reads `0x1F7`), `0x06`–`0x0F` are reserved / not applicable to the single-pot MCP4532; an invalid address / command combination is **not acknowledged** and every following command is ignored until the master issues a new START. The driver never uses other addresses.

### Bit Fields

#### Command byte

| Bits | Name | Description |
|------|------|-------------|
| 7:4 | AD[3:0] | Memory address: `0000` wiper 0, `0100` TCON |
| 3:2 | C[1:0] | `00` write data, `01` increment (wiper only), `10` decrement (wiper only), `11` read data |
| 1 | D9 | Unused (0) |
| 0 | D8 | Bit 8 of the data (wiper value above `0xFF`, TCON bit 8) |

#### `WIPER0` (`0x00`)

| Bits | Name | Description |
|------|------|-------------|
| 8:0 | W | Wiper position: `0x000` zero scale (W = B), `0x040` mid-scale (reset), `0x080` full scale (W = A), values `0x081`–`0x3FF` are reserved and also act as full scale; increment commands are ignored at ≥ `0x080`, decrement is ignored at `0x000` |

#### `TCON` (`0x04`) — reset `0x1FF`, nine bits (D8 from the command byte)

| Bits | Name | Description |
|------|------|-------------|
| 8 | GCEN | 1 = the device accepts General Call commands (address `0x00`) |
| 7:4 | R1HW, R1A, R1W, R1B | Resistor 1 controls — **not present on the MCP4532** (write as 1) |
| 3 | R0HW | 0 = resistor 0 forced into the hardware **shutdown** configuration (A disconnected, W connected to B); 1 = normal |
| 2 | R0A | 1 = terminal A connected to the network (internal on the MCP4532) |
| 1 | R0W | 1 = wiper terminal `P0W` connected to the network |
| 0 | R0B | 1 = terminal `P0B` connected to the network |

`R0HW` = 0 overrides `R0A`/`R0W`/`R0B` without changing them or the wiper register; returning `R0HW` to 1 restores the previous state. The serial interface keeps working in shutdown. At POR/BOR TCON is loaded with `0x1FF` (all terminals connected).

## Initialization Sequence

1. Power VDD (1.8–5.5 V). At POR the wiper register is loaded with mid-scale (`0x40`), TCON with `0x1FF` and the address pointer with `0x00`; the device is ready after TBORD (10–20 µs). Latch the address: A0 is sampled at POR.
2. `init` performs no writes: the wiper stays at the value the chip holds (mid-scale after power-up; the previous value after a warm start). It reads `WIPER0` once (a bus check and to cache the wiper code) and reads `TCON` (to cache the terminal state).
3. Set the wiper with write commands. Keep VDD applied to keep the setting (brown-out below VRAM corrupts the registers; below VBOR the interface is disabled).

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits everything and adds the rest.

### Minimal

Goal: set and read back the wiper position or the W–B resistance.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection, `r_ab: float = 10000.0`, `r_wiper: float = 75.0` | — | Stores the connection and the end-to-end resistance RAB (Ω, 5 / 10 / 50 / 100 kΩ for -502 / -103 / -503 / -104) and the wiper resistance RW (Ω); reads `WIPER0` and `TCON` as a bus check |
| `set_wiper` | `code: int` (0–128) | — | Writes command `0x00` (+ D8 = 0) and the data byte; clamps to [0, 128] |
| `get_wiper` | — | `int` (0–128) | Read command `0x0C` (two bytes); returns the 9-bit value clamped to 128 |
| `set_resistance` | `ohms: float` | — | Sets the W–B resistance to the nearest code (inverse of the formula below), clamped to the reachable range |
| `get_resistance` | — | `float` Ω | W–B resistance for the current code |

**Sensible defaults:** RAB = 10 kΩ, RW = 75 Ω (typical, 5.5 V); wiper at its power-up mid-scale until written; all terminals connected (TCON `0x1FF`, no shutdown); General Call left at the chip's power-up setting (`GCEN` = 1, enabled — see Implementation Notes).

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection, `r_ab=10000.0`, `r_wiper=75.0` | — | As Minimal |
| *(inherits Minimal)* | | | |
| `set_ratio` | `ratio: float` (0.0–1.0) | — | Wiper at `round(ratio × 128)` — fraction of RAB between W and B |
| `get_ratio` | — | `float` | `code / 128` |
| `increment` | `steps: int = 1` | `int` | Sends `steps` increment commands (`0x04`) in one continuous transaction (no data bytes; each command byte increments by 1, saturating at 128) and returns the new code (read back) |
| `decrement` | `steps: int = 1` | `int` | Same with decrement commands (`0x08`), saturating at 0 |
| `get_resistance_step` | — | `float` Ω | One step: `RAB / 128` |
| `shutdown` | — | — | `TCON.R0HW` = 0: terminal A disconnected, W connected to B (≈ RW); the wiper register is kept |
| `resume` | — | — | `TCON.R0HW` = 1 |
| `is_shutdown` | — | `bool` | Read from `TCON` (R0HW = 0) |
| `set_terminals` | `a: bool = True`, `w: bool = True`, `b: bool = True` | — | `TCON.R0A` / `R0W` / `R0B` (disconnect terminals to minimise current); other TCON bits preserved |
| `get_terminals` | — | `(a, w, b)` | From `TCON` |
| `get_tcon` | — | `int` | Raw 9-bit `TCON` value |
| `set_general_call` | `enabled: bool` | — | `TCON.GCEN`; when enabled the chip answers the General Call address (`0x00`) commands "write wiper 0", "write TCON", "increment / decrement wiper 0" |
| `reset` | — | — | Emulates POR: writes wiper `0x40` and `TCON` `0x1FF` (the chip has no reset pin or command) |
| `read_register` | `address: int` | `int` | Raw 9-bit read of `0x00` or `0x04` |
| `write_register` | `address: int`, `value: int` | — | Raw write of `0x00` (0–0x3FF) or `0x04` (0–0x1FF) |
| `set_rab` | `r_ab: float`, `r_wiper: float \| None = None` | — | Changes the resistance parameters used by the conversions (no I²C traffic) |

**Additional configuration options:** increment / decrement stepping, terminal disconnect and shutdown, General Call enable, resistance model parameters (RAB, RW), ratio helpers.

## Data Conversion

```
R_WB(N) = N / 128 * RAB + RW                 # wiper to terminal B, N = 0..128 (RW wiper resistance)
R_S     = RAB / 128                          # step resistance
N       = round((R - RW) / RAB * 128)        # inverse, clamp 0..128
ratio   = N / 128

read   : value = ((high & 0x01) << 8) | low  # D8 from the first data byte, D7..D0 from the second
write  : command byte = (address << 4) | (0b00 << 2) | (value >> 8 & 0x01) ; data byte = value & 0xFF
inc/dec: command byte = (0x00 << 4) | (0b01 << 2)  = 0x04   /   (0b10 << 2) = 0x08   (no data byte)
read   : command byte = (address << 4) | (0b11 << 2)   # 0x0C for the wiper, 0x4C for TCON
```

Example (RAB = 10 kΩ, RW = 75 Ω): N = 0 → 75 Ω, 1 → 153 Ω, 64 → 5075 Ω, 128 → 10 075 Ω (zero scale is **not** 0 Ω; keep terminal current ≤ 2.5 mA). Nominal RAB tolerance is ±20 %, so absolute resistance is approximate; steps and ratios are accurate (R-INL ±0.5 LSb typ., R-DNL ±0.25 LSb typ. at 5.5 V, 7-bit). RW is 75 Ω typ. (160 Ω max at 5.5 V, 300 Ω max at 2.7 V) and varies with code, VDD, terminal voltages and temperature; temperature coefficient of RAB 50 ppm/°C (0–70 °C) to 150 ppm/°C.

## Timing Constraints

- **Power-on:** the volatile registers are loaded with their POR values when VDD crosses VPOR/VBOR (< 1.65 V); the device is operational TBORD = 10–20 µs after leaving reset. VDD must go below VBOR and the RAM-retention voltage for a power-reset; between VBOR and 2.7 V the serial interface works but analog specifications are not guaranteed.
- **Wiper update:** a write or increment / decrement command updates the wiper on the acknowledge of the command (write: after the data byte's ACK; increment / decrement: after the command byte's ACK); the wiper settles within the resistor-network settling time (not specified for the rheostat; bandwidth 2 MHz for 5 kΩ down to 100 kHz for 100 kΩ).
- **I²C:** standard mode ≤ 100 kHz, fast mode ≤ 400 kHz, HS mode ≤ 3.4 MHz (master code `0000 1XXX` after START, not acknowledged, ends at the next STOP); the device never stretches SCL; spike suppression 50 ns (FS) / 10 ns (HS). Setup / hold values: datasheet "I²C Serial Interface Timing Specifications".
- **High-voltage commands:** a delay is required between driving HVC/A0 to VIHH (~8.5 V) and the first SCL edge — irrelevant for the volatile MCP4532, whose HVC pin is just address bit 0.
- **Error recovery:** after an invalid command the chip releases SDA and ignores everything until a new START.
- **Conformance:** none of these has a bus-decodable start / end annotation pair that the host must honour (the wiper update is simultaneous with the acknowledge; the POR delay is a power event), so `specs/adc_dac/mcp4532_timing.conf` defines no checks.

## Implementation Notes

- **Register-addressed wrapper:** accept `RegisterConnection` (1-byte "register" = the command byte, no `bus_type` branch, no chip-local `_read_reg`/`_write_reg`); see `specs/feature_register_access_design.md`. Writes are `connection.write(command_byte, bytes([data]))`; reads are `connection.read(command_byte, 2)`; increment / decrement are command-byte-only transactions — `connection.write(inc_byte, bytes([inc_byte] * (steps - 1)))` sends `steps` increment commands in one continuous sequence (the datasheet's "continuous" mode). If a platform's `RegisterConnection.write` cannot send an empty data field, `increment` / `decrement` fall back to `set_wiper(clamped current ± steps)`.
- **Read returns two bytes:** the high byte only carries `D8` (bit 0, the rest 0); `get_wiper` masks `& 0x1FF` and clamps to 128 (values above 128 act as full scale).
- **Invalid commands lock the interface until START:** the chip NACKs an invalid address / operation combination and ignores everything else until a START; the driver therefore uses exactly the documented commands and, after any NACK error, restarts the transaction (a new START).
- **General Call is enabled at power-up (`GCEN` = 1):** the General Call address `0x00` is acknowledged and a host can change every MCP45XX/46XX on the bus at once (`1000 00d` write wiper 0, `1100 00d` write TCON, `1000 01x` increment, `1000 10x` decrement); the chip does not acknowledge the I²C reserved General Call commands (reset, address programming). Call `set_general_call(False)` if the bus carries devices for which a General Call write of `0x80` / `0xC0` would be harmful; the library has no General Call transmit API (`RegisterConnection` cannot address `0x00`).
- **Wiper above full scale:** writes of 129–1023 select full scale (W = A); the driver clamps to 128 and never writes more.
- **Read-modify-write of TCON:** only the documented bits are changed; bits 7:4 (resistor 1) are kept at 1 (their POR value) although the MCP4532 has no second pot; GCEN is preserved.
- **Volatile:** no EEPROM; the wiper is `0x40` after every power cycle; keep VDD applied to retain the setting. The non-volatile siblings (MCP4541 etc.) additionally have the WiperLock, EEPROM and status registers and use high-voltage commands; they are not covered by this spec.
- **Terminal limits:** `P0W` / `P0B` must stay within VSS … VDD; wiper current ≤ 2.5 mA.
- **Addressing:** the rheostat devices have only A1 and A0 (4 addresses `0x58`–`0x5B`); the MCP4531 / 4551 potentiometers use `0x2E`/`0x2F` and the dual pots `0x28`–`0x2F`. The MCP4532's `0x58`–`0x5B` do not collide with the AD5243 / AD5248 (`0x2C`–`0x2F`) or DS3502 (`0x28`–`0x2B`), but overlap the I²C address range of other chips (see the registry).
- **Siblings:** the MCP4531, MCP4551 / 4552 and MCP4631 / 4632 / 4651 / 4652 use the same command format and registers (the 8-bit parts have codes 0–256, the dual parts add wiper 1 at `0x01` and the R1 TCON bits) and could share a base class later; this spec makes no claim beyond the MCP4532.
- **Datasheet:** DS22096B (2013), family datasheet; the MCP4532 is the "single rheostat, RAM, 7-bit, mid-scale POR" row.

## Sigrok Decoder

Decoder id `mcp4532`, input `['i2c']`. Matches I²C addresses `0x58`–`0x5B` and the General Call address `0x00` (annotated as General Call). Decodes the command byte (address field, operation: write / increment / decrement / read, D9:D8) and the data bytes: writes to `0x00` as the wiper code (9-bit value from D8 + data byte, with `code/128` as a ratio and the nominal W–B resistance fraction), writes to `0x04` as TCON with the decoded GCEN, R0HW (shutdown), R0A, R0W, R0B; increment / decrement commands (including several in one transaction, each annotated "+1" / "−1"); reads, using the pointer set by the preceding command (random read) or the last one (stand-alone read), as the returned 9-bit value. Warnings: an address / operation combination the MCP4532 does not accept (e.g. wiper 1, reserved addresses, increment on TCON), a wiper value above 128 ("full scale"), a data byte after an increment / decrement command, and a NACK on a command byte followed by further traffic without a START. No timing annotation pair is emitted, since no constraint is conformance-checked.
