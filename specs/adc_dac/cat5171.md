# Chip Spec: CAT5171

**Manufacturer:** ON Semiconductor  
**Datasheet:** `datasheets/adc_dac/cat5171.pdf` (onsemi CAT5171/D, Rev. 4 June 2021 — the `onsemi.com` URL in the issue answers 403 to scripted downloads; the committed copy is the same document from onsemi's own storage mirror, `https://xonstorage.z8.web.core.windows.net/pdf/onsemiconductor_cat5171tbi50gt3_apr22_xonlink.pdf`)  
**Category:** adc_dac  
**Transports:** I²C

## Overview

The CAT5171 is a single-channel, 256-position digital potentiometer (linear taper) controlled over I²C, in an 8-lead SOT-23. It is a 3-terminal device (A, W, B) usable as a voltage divider or as a 2-terminal rheostat, with an end-to-end resistance RAB of 50 kΩ or 100 kΩ (ordering option), a power-on preset to midscale, a one-byte volatile wiper register, a midscale-reset bit and a shutdown bit. One address pin (AD0) allows two devices on a bus. It is designed as a pin-for-pin replacement for the AD5245 (a different chip, not covered here) and is the single-channel counterpart of the dual AD5243/AD5248 (`specs/adc_dac/ad5243.md`, `ad5248.md`). Typical uses are calibration, level setting, trimmer replacement and gain/offset adjustment. The wiper register is **volatile** — the setting is lost at power-down.

## Transport Configuration

### I²C
- **Address:** `0x2C` (AD0 = GND) — `0x2D` (AD0 = VDD); 7-bit address `0101 10 AD0` (address byte `0101 10 AD0 R/W`)
- **Max clock:** 400 kHz (fast mode)
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`; the addresses overlap the AD5248's `0x2C`–`0x2F`, which cannot be told apart)
- **Probe safety:** `write_sensitive` — a 1-byte write is an instruction byte (`RS` midscale reset, `SD` shutdown), not a register pointer
- **Protocol:** no register addresses. A write transaction is `[addr+W] [instruction] [data]`; a read transaction is just `[addr+R] [data]` (it returns the wiper register — there is no channel select and no instruction byte for reads). The driver uses the plain `Connection`: `write(bytes([instruction, data]))` and `read(1)` (as the PCF8576 driver does for its command stream), not `RegisterConnection`
- **Bus time-out:** none specified

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| A, W, B | — | Potentiometer terminals (top, wiper, bottom); voltage range GND to VDD; no polarity restriction between them |
| AD0 | — | Address bit 0; tie to GND or VDD (may be driven by CMOS) |
| SDA, SCL | — | I²C; external pull-ups required |
| VDD, GND | — | 2.7–5.5 V supply (< 2 mA) |

No reset, interrupt or enable pin. Power VDD before any signal on A, B, W (ESD diodes clamp to the rails).

## Register Map

No register map: one 8-bit **wiper control register (WCR)**, written by the instruction + data byte pair and read back directly.

| Name | R/W | Reset | Description |
|------|-----|-------|-------------|
| WCR | R/W | `0x80` | Wiper position 0–255 (`0x00` wiper at B, `0xFF` one LSB below A) |

### Bit Fields

#### Instruction byte (write mode, first byte after the address)

| Bits | Name | Description |
|------|------|-------------|
| 7    | X | Don't care — write `0` |
| 6    | RS | Midscale reset: `1` moves the wiper to the centre tap (`0x80`) |
| 5    | SD | Shutdown: `1` opens terminal A and shorts the wiper to B without changing the WCR; `0` = normal (the previous wiper position is restored) |
| 4:0  | X | Don't care — write `0` |

#### Data byte

| Bits | Name | Description |
|------|------|-------------|
| 7:0  | D[7:0] | Wiper position 0–255 |

Write instructions are 3 bytes (`[addr+W] [instruction] [data]`), read instructions 2 bytes (`[addr+R] [data]`). New settings can be written while in shutdown; they take effect when `SD` returns to 0.

## Initialization Sequence

1. Wait ≥ 1 ms after VDD is stable before the first read or write (tPUR/tPUW); the wiper is at midscale (`0x80`) after power-up (wiper response up to 50 µs after power is stable).
2. No initialization writes are required; `init` performs no I²C traffic and assumes the wiper is at `0x80` and not in shutdown.
3. Set the wiper with `[instruction, code]` writes.

## Implementation Stages

### Minimal

Goal: set and read back the wiper position or the wiper-to-B resistance.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection, `r_ab: float = 100000.0`, `r_wiper: float = 50.0` | — | Stores the connection and the part's end-to-end resistance RAB (Ω; 50 000 or 100 000 per ordering option) and wiper resistance RW (Ω; typ. 50 Ω at 5 V, 100 Ω at 3 V); waits ≥ 1 ms; no I²C traffic |
| `set_wiper` | `code: int` (0–255) | — | Writes `[0x00, code]` (RS = 0, SD = 0); clamps `code` to [0, 255] |
| `get_wiper` | — | `int` (0–255) | Single read transaction returning the WCR |
| `set_resistance` | `ohms: float` | — | Sets the W–B rheostat resistance to the nearest code (inverse of the formula below), clamped to the reachable range |
| `get_resistance` | — | `float` Ω | W–B resistance for the current code |

**Sensible defaults:** RAB = 100 kΩ, RW = 50 Ω; wiper at the power-up midscale (`0x80`) until written; not in shutdown.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `set_ratio` | `ratio: float` (0.0–1.0) | — | Wiper at `round(ratio × 256)` clamped to 255 — divider ratio V(W−B)/V(A−B) in potentiometer mode |
| `get_ratio` | — | `float` | `code / 256` |
| `set_resistance_wa` | `ohms: float` | — | Sets the W–A resistance (rheostat mode with B open) to the nearest code |
| `get_resistance_wa` | — | `float` Ω | `(256 − D)/256 × RAB + RW` |
| `increment` | `steps: int = 1` | `int` | Reads the code, adds `steps` (negative to decrement), clamps to [0, 255], writes and returns the new code |
| `midscale` | — | — | Writes the instruction with `RS` = 1 (`[0x40, 0x80]`, or with `SD` kept if shut down); the wiper moves to `0x80`; the driver updates its tracked code |
| `shutdown` | — | — | Writes `[0x20, current_code]` (SD = 1); terminal A opens and the wiper shorts to B; the WCR is kept |
| `resume` | — | — | Writes `[0x00, current_code]` (SD = 0); the previous wiper position is restored |
| `is_shutdown` | — | `bool` | Driver-tracked state (the chip cannot report it); `False` after `init`, `reset` and a power cycle |
| `reset` | — | — | Writes `[0x40, 0x80]` (midscale reset, SD = 0) and clears the tracked shutdown state; the chip has no reset pin |
| `set_rab` | `r_ab: float`, `r_wiper: float \| None = None` | — | Changes the resistance parameters used by the conversions (no I²C traffic) |

**Additional configuration options:** shutdown, midscale reset, resistance model parameters (RAB, RW), ratio and increment helpers.

## Data Conversion

```
R_WB(D) = D / 256 * RAB + RW                  # wiper to B, A open
R_WA(D) = (256 - D) / 256 * RAB + RW          # wiper to A, B open
V_W(D)  = D / 256 * V_A + (256 - D) / 256 * V_B   # divider mode

D = round((R - RW) / RAB * 256)               # inverse for R_WB, clamp 0..255
```

Example (RAB = 100 kΩ, RW = 50 Ω, VDD = 5 V): `D` = 0 → 50 Ω, 1 → 441 Ω, 128 → 50 050 Ω, 255 → 99 659 Ω (zero scale is **not** 0 Ω: keep the pulsed wiper current ≤ 20 mA). Nominal RAB tolerance is ±20 %, so absolute resistance is only approximate; ratios are accurate. Note the single wiper resistance `RW` (not `2 × RW` as in the dual AD5243/AD5248).

## Timing Constraints

- **Power-up:** wait ≥ 1 ms after VDD is stable before the first read or write (tPUR = tPUW = 1 ms max); the wiper is at midscale within tWRPO ≤ 50 µs after the supply is stable. **Conformance-checked** as `poweron_ready` (min 1 ms), measured from capture start to the first decoded bus transaction (no power-sense channel in `testconfig_wiring` — same pattern as the PCF8576/PCF8578) — see `specs/adc_dac/cat5171_timing.conf`.
- **Wiper response:** tWR ≤ 20 µs from the SCL falling edge after the last bit of the wiper data byte to the wiper change; VW settling tS ≈ 2 µs. Both are far below one I²C transaction, so no driver delay is needed. (In the datasheet text extraction the µ prefix of these values is rendered as "m"; the order of magnitude follows the tAA = 1 µs bus-timing neighbour and the AD5245-class parts — confirm against the PDF.)
- **I²C:** fSCL ≤ 400 kHz, tLOW ≥ 1.3 µs, tHIGH ≥ 0.6 µs, tBUF ≥ 1.3 µs, tSU:DAT ≥ 100 ns, tSU:STO ≥ 600 ns, tAA ≤ 1 µs (datasheet Table 8) — clock-rate properties, not event-to-event delays.

## Implementation Notes

- **Writes through the instruction byte, reads without it:** `get_wiper` is a bare 1-byte read transaction (`[addr+R] [data]`, last byte NACKed) — there is no register pointer, unlike the dual AD5243/AD5248 where a read first needs an instruction byte to pick the channel.
- **`RS` and the data byte:** the datasheet shows write instructions as always 3 bytes; with `RS` = 1 the data byte's role is not stated. The driver always sends a data byte (`0x80` for `midscale`/`reset`) so the frame is well-formed whatever the chip does with it; it updates its tracked code to `0x80`.
- **Shutdown state is write-only:** the chip cannot report it, so the driver tracks it. While shut down, `set_wiper` keeps `SD` = 1 in the instruction byte (new settings can be programmed during shutdown and are applied on resume). `shutdown` / `resume` send the tracked code with the instruction (after power-up that is midscale `0x80`) so they do not depend on an instruction-only frame being valid.
- **Volatile:** no EEPROM; the wiper is `0x80` after every power cycle. VDD must stay applied to retain the setting.
- **Terminal limits:** A, B, W must stay within GND…VDD; power VDD before the terminals. Zero-scale wiper-to-B current ≤ 20 mA pulsed.
- **Wiper resistance:** `RW` is single (≈ 50 Ω at 5 V, ≈ 100 Ω at 3 V, max 120 / 250 Ω) — set `r_wiper` for the supply in use if resistance accuracy matters.
- **Addresses overlap the AD5248:** the CAT5171 (`0x2C`/`0x2D`) and the AD5248 (`0x2C`–`0x2F`) cannot share addresses on one bus; the AD5243 uses `0x2F`.
- **Shared base:** may share resistance conversion and shutdown tracking with the AD5243/AD5248 drivers via a common helper; the public APIs stay as specified per chip.
- **Datasheet:** onsemi CAT5171/D Rev. 4. The `www.onsemi.com` link returns 403 to scripted downloads, so the PDF was taken from onsemi's storage mirror.

## Sigrok Decoder

Decoder id `cat5171`, input `['i2c']`. Matches I²C addresses `0x2C` and `0x2D`. For writes, decodes the instruction byte (`RS`, `SD` flags) and the following data byte as wiper code with the fraction `code/256` (RAB is unknown to the decoder, so no ohms are shown); several data bytes after one instruction are shown as successive wiper updates. For reads, shows the returned wiper value. Flags a write with instruction bits 7 or 4:0 set, a write with no data byte, and a read of more than one byte as warnings. For the power-on conformance check the first bus transaction after capture start is annotated `poweron_ready` (marker `poweron_start` at capture start) in the `timing` annotation row, shaped per `specs/sigrok_annotations.md`'s Variable-Length Annotation Convention; the gap must be ≥ 1 ms (see `specs/adc_dac/cat5171_timing.conf`).
