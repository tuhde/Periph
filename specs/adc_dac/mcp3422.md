# Chip Spec: MCP3422

**Manufacturer:** Microchip  
**Datasheet:** `datasheets/adc_dac/mcp3422.pdf` (DS22088C, covers MCP3422/3/4)  
**Category:** adc_dac  
**Transports:** I²C

## Overview

The MCP3422 is a 2-channel, 18-bit delta-sigma ADC with differential inputs, an on-board 2.048 V reference (±0.05 %, 15 ppm/°C), a programmable-gain amplifier (×1, ×2, ×4, ×8), an on-board oscillator and an I²C interface (standard, fast and high-speed modes), in an SOIC-8 / MSOP-8 / DFN-8. The resolution is selected together with the data rate: 12 bit / 240 SPS, 14 bit / 60 SPS, 16 bit / 15 SPS, 18 bit / 3.75 SPS. Offset and gain are self-calibrated on every conversion. It converts continuously or one-shot (then drops to a 0.3 µA standby). The full-scale differential input range is ±2.048 V / PGA. Typical uses: RTD/thermistor/thermocouple front ends, bridge sensors (weigh scales, pressure), battery fuel gauges.

The MCP3423 (2 channels, address pins) and MCP3424 (4 channels, address pins) share the datasheet and the exact register protocol; they are **out of scope** here (the MCP3422 has a factory-programmed address and two channels). The protocol is a single **configuration byte** plus a 2- or 3-byte result — there are no register addresses.

## Transport Configuration

### I²C
- **Address:** `0x68` (MCP3422-A0, the standard part) — the I²C address bits `A2 A1 A0` of the MCP3422 are **programmed at the factory** (orderable variants `A0`…`A7`), giving `0x68`…`0x6F`; address byte `1101 A2 A1 A0 R/W` (device code `1101`)
- **Max clock:** standard 100 kHz, fast 400 kHz, high-speed 3.4 MHz. The drivers use ≤ 400 kHz; high-speed mode needs an Hs master code the connections do not send and is out of scope
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`; `0x68`–`0x6F` coincide with the DS3231, PCF8523, DRV8830 and others, none of which can be told apart)
- **Probe safety:** `write_sensitive` — a 1-byte write is the configuration byte (it can start a conversion and change mode, rate and gain; there is no register pointer)
- **Protocol:** no register addresses. **Write** is `[addr+W] [config] P`. **Read** is `[addr+R] [data0] [data1] ([data2]) [config]`: the device streams the result bytes followed by the current configuration byte, and keeps repeating the configuration byte while the master keeps clocking. The drivers use the plain `Connection` (`write(data)` / `read(n)`) — see `specs/feature_register_access_design.md`, "no register concept"
- **General calls** (address `0x00`, second byte): `0x06` reset (aborts the conversion, restores power-on defaults, re-latches address pins), `0x08` conversion (all devices on the bus start a one-shot conversion simultaneously; PGA and rate unchanged). `0x04` (address latch) applies to the MCP3423/4 only and is not used

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| CH1+, CH1− | — | Differential input pair 1 |
| CH2+, CH2− | — | Differential input pair 2 |
| VSS, VDD | — | Supply 2.7–5.5 V; decouple VDD with 0.1 µF |
| SDA, SCL | — | I²C; external pull-ups |

The 2.048 V reference is internal only (no pin). No interrupt, enable or address pins; the MCP3422 has no conversion-ready output — completion is signalled by the `RDY` bit.

## Register Map

One 8-bit **configuration register**, written as a single byte (no address) and read back as the last byte of every read. Power-on / general-call-reset value: `0x90` (RDY = 1, channel 1, continuous, 240 SPS / 12 bit, gain ×1).

| Access | Content |
|--------|---------|
| Write | 1 byte: configuration |
| Read | 2 bytes result + config (12/14/16 bit) or 3 bytes result + config (18 bit) |

### Bit Fields

#### `CONFIG`

| Bits | Name | Description |
|------|------|-------------|
| 7 | RDY | **Read:** `0` = output register holds a new result since the last read; `1` = not updated. **Write:** in one-shot mode `1` starts a conversion, `0` = no effect; in continuous mode no effect |
| 6:5 | C1:C0 | Channel: `00` = CH1, `01` = CH2 (`10`/`11` are CH3/CH4 on the MCP3424 and alias to `00`/`01` on the MCP3422 — the driver never writes them) |
| 4 | O/C | `1` = continuous conversion (default), `0` = one-shot (single conversion, then standby) |
| 3:2 | S1:S0 | Rate / resolution: `00` = 240 SPS 12 bit, `01` = 60 SPS 14 bit, `10` = 15 SPS 16 bit, `11` = 3.75 SPS 18 bit |
| 1:0 | G1:G0 | PGA gain: `00` ×1, `01` ×2, `10` ×4, `11` ×8 |

Write semantics (datasheet Table 5-1): `O/C = 0, RDY = 1` starts a one-shot conversion; `O/C = 1` (any RDY) starts/continues continuous conversion; `O/C = 0, RDY = 0` leaves the running operation unchanged (settings still apply).

### Result bytes

| Resolution | Bytes | Layout (MSB first) |
|-----------|-------|--------------------|
| 12 bit | 2 | `byte0` bits 3:0 = D11…D8 (upper 4 bits repeat the sign), `byte1` = D7…D0 |
| 14 bit | 2 | `byte0` bits 5:0 = D13…D8 (upper 2 bits repeat the sign), `byte1` = D7…D0 |
| 16 bit | 2 | `byte0` = D15…D8, `byte1` = D7…D0 |
| 18 bit | 3 | `byte0` bits 1:0 = D17…D16 (upper 6 bits repeat the sign), `byte1` = D15…D8, `byte2` = D7…D0 |

Followed by the configuration byte (with the live `RDY` bit).

## Initialization Sequence

1. At power-up (or after the general-call reset) the chip is in continuous mode, 12 bit / 240 SPS, gain ×1, channel 1; no delay is specified beyond the power-on reset.
2. Optional but recommended once after power-up: general-call reset (`0x00 0x06`) — it also makes the chip re-latch its address in a stable condition.
3. `init` stores the connection and the defaults, then writes the configuration byte for the default setting (one-shot, 16 bit, ×1, channel 1, `RDY = 0` — nothing is started, the chip goes to standby).

### One-shot conversion sequence (all `read_*` methods)
1. `connection.write([config])` with `RDY = 1`, `O/C = 0`, selected channel, rate and gain — starts the conversion.
2. Wait the nominal conversion time (see Timing Constraints), then `connection.read(n + 1)` (`n` = 2 or 3 result bytes plus the config byte).
3. If `RDY` (bit 7 of the config byte) is still `1`, read again until it is `0` or a timeout of 2 × the conversion time + 10 ms expires (raise a timeout error).
4. Decode the result per the *Result bytes* table and sign-extend.

### Continuous mode (Full only)
`start_continuous()` writes the config with `O/C = 1`. `read_*` then only reads (no write) and polls `RDY` as in step 3; a `read` while `RDY = 1` returns the previous (stale) sample, so the driver waits for `RDY = 0`.

## Implementation Stages

### Minimal

Goal: read the two differential inputs as voltages with one call each, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Runs init step 3: one-shot, **16 bit / 15 SPS, gain ×1** |
| `read_raw` | `channel: int` (0–1) | `int` | Signed code (−32768…32767 at 16 bit); one-shot conversion on CH1 (`0`) or CH2 (`1`); clamps `channel` to [0, 1]; ~67 ms per call |
| `read_voltage` | `channel: int` (0–1) | `float` V | Differential voltage `CHn+ − CHn−`, `raw × lsb / gain`; range ±2.048 V |
| `read_all` | — | `list[float]` (2 values) | CH1, CH2 voltages, one conversion each |

**Sensible defaults:** one-shot mode (lowest power), 16 bit / 15 SPS (LSB 62.5 µV), gain ×1 (±2.048 V full scale), channel selected per call.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |

| `get_resolution` | — | `int` | Current bits |
| `set_gain` | `gain: int` (1, 2, 4, 8) | — | PGA; raises on other values |
| `get_gain` | — | `int` | Current gain |
| `set_channel` | `channel: int` (0–1) | — | Channel used by `read_continuous`; also remembered for the next `start_continuous` |
| `start_continuous` | `channel: int \| None = None` | — | Switches to continuous conversion at the current rate/gain (and channel if given) |
| `stop_continuous` | — | — | Writes `O/C = 0, RDY = 0`: back to one-shot/standby |
| `is_continuous` | — | `bool` | Current mode |

| `read_config` | — | `int` | Reads the configuration byte (last byte of a read) |
| `is_ready` | — | `bool` | `RDY = 0` (a fresh result is available) |
| `read_scan` | `channels: list[int]` | `list[float]` V | One-shot conversion per entry, in order |
| `general_call_reset` | — | — | Sends `0x00 0x06`; restores power-on defaults on the **chip** (continuous, 12 bit, ×1, CH1) and resets the driver's state to match |
| `general_call_convert` | — | — | Sends `0x00 0x08`: starts a one-shot conversion on every device on the bus at once (also non-MCP342x devices that honour it); the driver then only waits and reads with `read_pending_raw` |
| `read_pending_raw` | — | `int` | Waits for `RDY = 0` and returns the code (for the general-call-conversion case) |
| `lsb` | — | `float` V | `2 × 2.048 / 2^bits` (before gain) |
| `full_scale` | — | `float` V | `2.048 / gain` |

**Additional configuration options:** resolution/data rate, PGA gain, channel, continuous vs one-shot mode, general calls.

## Data Conversion

```
signed raw = sign-extend the result bits per resolution N (12/14/16/18)
lsb        = 2 * 2.048 V / 2^N        # 1 mV (12), 250 µV (14), 62.5 µV (16), 15.625 µV (18)
V_in       = raw * lsb / gain         # CHn+ - CHn-, range -2.048/gain ... +2.048/gain
code range : -2^(N-1) ... 2^(N-1) - 1  # -131072 ... 131071 at 18 bit

config byte = (RDY << 7) | (channel << 5) | (continuous << 4) | (S << 2) | G
  S : 12 bit = 0, 14 bit = 1, 16 bit = 2, 18 bit = 3      G : gain 1/2/4/8 = 0/1/2/3
```

Examples: one-shot start, CH1, 16 bit, ×1 → `0x88`; CH2 → `0xA8`; 18 bit, ×8 → `0x8F`; continuous CH1, 12 bit, ×1 → `0x10`; power-on value `0x90`. Input beyond full scale saturates at the minimum/maximum code.

## Timing Constraints

- **Conversion time (nominal):** `1 / rate` — 12 bit: 4.17 ms (240 SPS, spec 176–328 SPS), 14 bit: 16.7 ms (60 SPS), 16 bit: 66.7 ms (15 SPS), 18 bit: 267 ms (3.75 SPS). The one-shot conversion starts when the write is acknowledged; the driver waits the nominal time (rounded up by 10 %) before the first read and then polls `RDY`. The decoder marks the config write with `RDY = 1` / `O/C = 0` as `conversion_start` and the first subsequent read whose config byte has `RDY = 0` as `conversion_done`; `specs/adc_dac/mcp3422_timing.conf` checks `conversion_done` is not earlier than 48.8 ms after `conversion_start` at the driver's default 16 bit rate (nominal 66.7 ms divided by the datasheet's 1.37× upper rate tolerance, 328/240 SPS).
- **Standby:** one-shot mode drops to ≈ 0.3 µA after the result is ready; supply current while converting 145 µA at 5 V, 135 µA at 3 V.
- **Power-on reset:** the POR needs VDD to rise monotonically; do not transact during the reset window (not tabulated); the general-call reset (`0x06`) re-latches without power cycling.
- **I²C:** per mode (100 kHz / 400 kHz / 3.4 MHz) — see the datasheet bus timing table; clock-rate properties, not event-to-event delays.

## Implementation Notes

- **No register addresses:** the driver accepts the plain `Connection` and uses `write(data)` / `read(n)` — as the PCF8591 does. A read is always `result bytes + config byte`; the config byte is the last byte, so `read(n + 1)` and take the last byte for `RDY`. Reading more bytes keeps returning the config byte.
- **One-shot start needs `RDY = 1`:** a write with `O/C = 0, RDY = 0` (e.g. after changing only the gain) does **not** start a conversion; the driver always sets `RDY = 1` for a read in one-shot mode.
- **Settings take effect on the next conversion:** changing rate or gain does not abort a running conversion; in continuous mode discard the first sample after a change (the driver does).
- **Stale data in continuous mode:** the output register is overwritten at the conversion rate; read the config byte's `RDY` bit to see whether a new result has arrived since the last read. At 18 bit / 3.75 SPS polling every 5–10 ms is enough.
- **Input range:** each input must stay within VSS − 0.3 V … VDD + 0.3 V; the differential full scale is ±2.048 V / gain; the common-mode level is not restricted beyond that. Input impedance drops with gain (2.25 MΩ / PGA differential).
- **Variants:** `A0`…`A7` order codes give `0x68`…`0x6F`; the address cannot be changed in software. The MCP3423/3424 use the same driver with additional channel/address-pin support and are not covered by this spec.
- **Address overlap:** `0x68`–`0x6F` is shared with the DS3231, PCF8523, DRV8830 (to `0x68`) and others; a wrong-chip access returns meaningless data rather than an error, so the discovery registry marks it `write_sensitive`.
- **Datasheet:** DS22088C, downloaded from `https://ww1.microchip.com/downloads/aemDocuments/documents/OTH/ProductDocuments/DataSheets/22088c.pdf`.

## Sigrok Decoder

Decoder id `mcp3422`, input `['i2c']`. Matches I²C addresses `0x68`–`0x6F`. Decodes every write byte as the configuration byte (channel `CH1`/`CH2`, mode `one-shot`/`continuous`, rate and resolution, gain, `RDY`) and the general-call bytes `0x06` (reset) and `0x08` (convert); flags a warning for channel codes `10`/`11` (MCP3424-only). A read is shown as the 2- or 3-byte signed code (resolution taken from the last configuration write; the power-on default 12 bit if none is in the capture) with the voltage `raw × lsb / gain`, followed by the config byte with its `RDY` flag. Timing annotations: `conversion_start` on a config write with `RDY = 1` and `O/C = 0` (or on the `0x08` general call) and `conversion_done` on the first read afterwards whose config byte has `RDY = 0`, both in the `timing` annotation row (variable-length strings per `specs/sigrok_annotations.md`).
