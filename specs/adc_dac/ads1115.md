# Chip Spec: ADS1115

**Manufacturer:** Texas Instruments  
**Datasheet:** `datasheets/adc_dac/ads1115.pdf` (shared ADS1113 / ADS1114 / ADS1115 datasheet, SBAS444E)  
**Category:** adc_dac  
**Transports:** I²C

## Overview

The ADS1115 is a precision, low-power, 16-bit, I²C ΔΣ ADC in a 10-pin X2QFN / SOT / VSSOP package with an internal low-drift voltage reference and oscillator. It is the full-featured member of the ADS111x family: a 4-input multiplexer (four single-ended or two differential measurements, plus AIN0/AIN1 against AIN3), a programmable-gain amplifier with full-scale ranges from ±6.144 V to ±0.256 V, programmable data rates of 8–860 SPS, single-shot or continuous conversion, and a programmable digital comparator with an ALERT/RDY output that can also signal conversion-ready. Typical uses are battery and sensor-voltage monitoring, portable instrumentation and process control.

The ADS111x family shares one datasheet, one register map and one I²C address scheme (and, apart from resolution and data-rate table, the same layout as the 12-bit ADS101x family — see Implementation Notes). This spec covers only the ADS1115; its siblings ADS1114 and ADS1113 are separate chips with their own specs (`specs/adc_dac/ads1114.md`, `specs/adc_dac/ads1113.md`) and issues. The three drivers share the same Config-register encoding; see Implementation Notes for what is deliberately duplicated per chip versus what a shared base may hold. The 12-bit ADS1013/4/5 are different chips (different resolution and data rates) and are **not** covered here.

## Transport Configuration

### I²C
- **Address:** `0x48` (ADDR = GND) — `0x49` (ADDR = VDD), `0x4A` (ADDR = SDA), `0x4B` (ADDR = SCL)
- **Max clock:** 400 kHz (fast mode); standard mode (100 kHz) and high-speed mode (3.4 MHz, needs an Hs controller code) are also supported — drivers use up to 400 kHz only
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`). The ADS1113, ADS1114 and ADS1115 are indistinguishable on the bus and share addresses `0x48`–`0x4B` with the PCF8591 and other chips
- **Probe safety:** `register_pointer` — a 1-byte write only selects the Address Pointer register (bits 7:2 reserved, written as 0); no data is interpreted without a second and third byte
- **ADDR = SDA:** hold SDA low for ≥ 100 ns after SCL goes low so the address decodes correctly; prefer GND / VDD / SCL strapping
- **Bus time-out:** the I²C interface times out if the bus is idle for more than 25 ms

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| ALERT/RDY | low by default (`COMP_POL`), open-drain | comparator output or conversion-ready; requires an external pull-up to VDD. Disabled (high-impedance) while `COMP_QUE` = `11` (the reset state) |
| ADDR | — | I²C address select (GND / VDD / SDA / SCL); board-level strap |

## Register Map

Registers are selected through a write-only 8-bit Address Pointer; each register is 16 bits, **big-endian** (MSB first) on both read and write. The pointer persists after a write, so repeated reads of the same register need no new pointer byte.

| Pointer P[1:0] | Name | R/W | Reset | Description |
|----------------|------|-----|-------|-------------|
| `00` | CONVERSION | R | `0x0000` | Last conversion result: 16-bit two's-complement code (all bits significant) |
| `01` | CONFIG | R/W | `0x8583` | Operating mode, data rate, input mux, gain, comparator |
| `10` | LO_THRESH | R/W | `0x8000` | Comparator low threshold, 16-bit two's-complement code (same scale as CONVERSION) |
| `11` | HI_THRESH | R/W | `0x7FFF` | Comparator high threshold, 16-bit two's-complement code (same scale as CONVERSION) |

### Bit Fields

#### Address Pointer (write-only, no address)

| Bits | Name | Description |
|------|------|-------------|
| 7:2  | RESERVED | Always write `000000` |
| 1:0  | P[1:0] | Register select: `00` CONVERSION, `01` CONFIG, `10` LO_THRESH, `11` HI_THRESH |

#### `CONVERSION` (pointer `00`)

| Bits | Name | Description |
|------|------|-------------|
| 15:0 | D[15:0] | 16-bit result, two's complement |

#### `CONFIG` (pointer `01`, reset `0x8583`)

| Bits | Name | Description |
|------|------|-------------|
| 15   | OS | Write: `1` = start a single conversion (only effective from power-down; no effect while converting), `0` = no effect. Read: `0` = converting, `1` = idle |
| 14:12 | MUX[2:0] | Input mux: `000` AIN0−AIN1 (default), `001` AIN0−AIN3, `010` AIN1−AIN3, `011` AIN2−AIN3, `100` AIN0−GND, `101` AIN1−GND, `110` AIN2−GND, `111` AIN3−GND |
| 11:9 | PGA[2:0] | Full-scale range: `000` ±6.144 V, `001` ±4.096 V, `010` ±2.048 V (default), `011` ±1.024 V, `100` ±0.512 V, `101`/`110`/`111` ±0.256 V |
| 8    | MODE | `0` = continuous conversion, `1` = single-shot / power-down (default) |
| 7:5  | DR[2:0] | Data rate: `000` 8 SPS, `001` 16, `010` 32, `011` 64, `100` 128 (default), `101` 250, `110` 475, `111` 860 SPS |
| 4    | COMP_MODE | `0` traditional comparator (default), `1` window comparator |
| 3    | COMP_POL | ALERT/RDY polarity: `0` active low (default), `1` active high |
| 2    | COMP_LAT | `0` non-latching (default), `1` latching until Conversion is read or an SMBus alert response is received |
| 1:0  | COMP_QUE[1:0] | `00` assert after 1 conversion, `01` after 2, `10` after 4, `11` disable comparator and set ALERT/RDY high-impedance (default) |

#### `LO_THRESH` (pointer `10`) / `HI_THRESH` (pointer `11`)

| Bits | Name | Description |
|------|------|-------------|
| 15:0 | THRESH[15:0] | 16-bit two's-complement threshold, same scale as CONVERSION (must be rewritten whenever the PGA setting changes); reset `0x8000` (LO) / `0x7FFF` (HI) |

**Conversion-ready mode:** setting HI_THRESH bit 15 = `1` **and** LO_THRESH bit 15 = `0` switches ALERT/RDY to conversion-ready (an ≈ 8 µs pulse per conversion in continuous mode; in single-shot mode the pin asserts at the end of the conversion). `COMP_POL` still applies; `COMP_MODE` and `COMP_LAT` are ignored; `COMP_QUE` must not be `11`. For ordinary comparator operation HI_THRESH must be greater than LO_THRESH, so a negative HI_THRESH (bit 15 = 1) is only ever used to select conversion-ready.

## Initialization Sequence

1. At power-up (or after a general-call reset) all registers take their reset values and the chip is in power-down / single-shot state: `CONFIG` = `0x8583`, thresholds `0x8000` / `0x7FFF`. No delay is needed before the first access.
2. No initialization writes are required — Minimal programs the full Config word with every single-shot conversion, so `init` performs no I²C traffic.
3. Full: optionally call `reset()` (write the reset values back) before configuring, then write the desired Config and thresholds.

### Single-shot conversion (used by Minimal `read_*`)

1. Write `CONFIG` ← OS=1, MUX, PGA, MODE=1, DR, comparator bits (reset values unless configured) (3-byte write: pointer `01`, MSB, LSB).
2. Poll `CONFIG` (pointer already `01`; 2-byte read) until `OS` = `1` (idle again), or sleep ≥ 1/DR + 0.1 ms (≥ 7.9 ms at 128 SPS). The chip powers up from power-down in ≈ 25 µs.
3. Write the Address Pointer ← `00`, read 2 bytes from CONVERSION; `raw = int16(msb << 8 | lsb)`.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `ALERT/RDY`, open-drain, polarity `COMP_POL` — requires an external pull-up to VDD |
| Level | 2 (two mutually exclusive sources on one pin) |
| Condition(s) | conversion ready; comparator threshold event (traditional or window) |
| Clear mechanism | non-latching: self-clearing; latching comparator: read the CONVERSION register (or SMBus alert response `0x19`); conversion-ready: self-clearing pulse (continuous) / cleared by starting the next conversion (single-shot) |

### Interrupt sources

| Constant | Value | Condition | Enabled by |
|----------|-------|-----------|------------|
| `SOURCE_CONVERSION_READY` | `0x01` | A conversion finished | HI_THRESH ← `0x8000`, LO_THRESH ← `0x0000`, `COMP_QUE` ← `00` |
| `SOURCE_COMPARATOR` | `0x02` | Result beyond the thresholds (per `COMP_MODE`) | thresholds from `set_thresholds*`, `COMP_QUE` ← the configured queue |

The two sources share the pin and the threshold registers, so only **one** can be enabled at a time: `enable_interrupt(source)` switches the pin to that source (reprogramming the thresholds as above for `SOURCE_CONVERSION_READY`) and `disable_interrupt(source)` sets `COMP_QUE` = `11` (pin high-impedance). Enabling `SOURCE_COMPARATOR` after `SOURCE_CONVERSION_READY` requires thresholds to be written first (`enable_interrupt` raises if HI_THRESH ≤ LO_THRESH as last set through the driver).

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback)` | Subscribe on ALERT/RDY (falling edge for active-low `COMP_POL`); callback receives the `poll_interrupt` value |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | The chip has no interrupt-status register (see below). Returns the enabled source constant if the pin is asserted, else `0`; reads CONVERSION to clear a latched comparator alert |
| `enable_interrupt` | `enable_interrupt(source)` | Route one source to ALERT/RDY (the other is disabled) |
| `disable_interrupt` | `disable_interrupt(source)` | `COMP_QUE` ← `11`; pin released |

### Status register bit layout

There is no status register. `poll_interrupt()` samples the ALERT/RDY level through the optional interrupt pin in the `Connection` (asserted = level matching `COMP_POL`); without a pin configured, `SOURCE_CONVERSION_READY` falls back to `CONFIG.OS` (single-shot only; in continuous mode `OS` always reads `1`) and `SOURCE_COMPARATOR` returns `0`. Bit 0 = `SOURCE_CONVERSION_READY`, bit 1 = `SOURCE_COMPARATOR`.

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits everything and adds the rest.

### Minimal

Goal: read the input voltage with a single call and no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Stores the connection; no I²C traffic |
| `read_raw` | `channel: int = 0` (0–3) | `int` (−32768…32767) | Single-shot conversion of AIN`channel` against GND (`MUX` = `100`+`channel`); clamps `channel` to [0, 3] |
| `read_voltage` | `channel: int = 0` (0–3) | `float` V | `raw × 62.5 µV` at the default ±2.048 V range |

**Sensible defaults:** `MUX` per call, `PGA` = `010` (±2.048 V, 62.5 µV/LSB), `MODE` = `1` (single-shot), `DR` = `100` (128 SPS), comparator disabled (`COMP_QUE` = `11`). The full Config word is written for every conversion, so the chip is never left converting.

### Full

Goal: expose complete chip functionality. Extends Minimal. Constants are class attributes on the Full class.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | `read_raw` / `read_voltage` now use the configured gain and data rate |
| `set_gain` | `pga: int` (`PGA_6_144`=0 … `PGA_0_256`=5) | — | Sets the full-scale range used by all following reads; values 6/7 are rejected (they alias ±0.256 V) |
| `get_gain` | — | `int` | Currently configured `PGA` code |
| `full_scale` | — | `float` V | ±FSR of the current gain: 6.144, 4.096, 2.048, 1.024, 0.512, 0.256 |
| `lsb` | — | `float` V | `full_scale() / 32768` (187.5 µV … 7.8125 µV) |
| `set_data_rate` | `dr: int` (`DR_8`=0, `DR_16`, `DR_32`, `DR_64`, `DR_128`=4, `DR_250`, `DR_475`, `DR_860`=7) | — | |
| `get_data_rate` | — | `int` | Currently configured `DR` code |
| `data_rate_sps` | — | `int` | Samples per second of the current setting (8, 16, 32, 64, 128, 250, 475 or 860) |
| `read_differential_raw` | `pair: int` (`DIFF_0_1`=0, `DIFF_0_3`=1, `DIFF_1_3`=2, `DIFF_2_3`=3) | `int` (−32768…32767) | Single-shot signed differential conversion (`MUX` = `pair`) |
| `read_differential` | `pair: int` | `float` V | `raw × lsb()` |
| `start_continuous` | `mux: int = MUX_AIN0_GND` (0–7) | — | Starts continuous conversion on any `MUX` code (single-ended `MUX_AIN0_GND`…`MUX_AIN3_GND` or `MUX_*` differential constants); `MODE` ← `0` |
| `read_continuous_raw` | — | `int` | Reads CONVERSION without touching Config; returns the most recent completed result (valid ≥ 1/DR after `start_continuous`) |
| `read_continuous` | — | `float` V | `read_continuous_raw() × lsb()` |
| `stop_continuous` | — | — | `MODE` ← `1` (single-shot / power-down) |
| `is_converting` | — | `bool` | `CONFIG.OS` = `0` (only meaningful in single-shot mode) |
| `read_config` | — | `int` | Raw 16-bit CONFIG register |
| `reset` | — | — | Writes the reset values back (`CONFIG` ← `0x8583`, `LO_THRESH` ← `0x8000`, `HI_THRESH` ← `0x7FFF`) and clears the driver's cached settings. **Not** an I²C general-call reset (see Implementation Notes) |
| `configure_comparator` | `mode: int = COMP_TRADITIONAL`, `polarity: int = ACTIVE_LOW`, `latch: bool = False`, `queue: int = QUEUE_1` | — | Writes `COMP_MODE`, `COMP_POL`, `COMP_LAT`, `COMP_QUE` (`QUEUE_1`=0, `QUEUE_2`=1, `QUEUE_4`=2; `COMP_WINDOW` for window mode) and enables the comparator source |
| `disable_comparator` | — | — | `COMP_QUE` ← `11`; ALERT/RDY high-impedance |
| `set_low_threshold_raw` | `raw: int` (−32768…32767) | — | LO_THRESH ← `raw & 0xFFFF` |
| `set_high_threshold_raw` | `raw: int` (−32768…32767) | — | HI_THRESH ← `raw & 0xFFFF` |
| `set_thresholds` | `low: float` V, `high: float` V | — | Converts with the current `lsb()`, clamps to the code range and writes both; raises if `high ≤ low` |
| `get_thresholds_raw` | — | `(int, int)` | `(low, high)` read back and sign-extended |
| `clear_alert` | — | — | Reads CONVERSION to release a latched comparator output |
| *(interrupt API)* | | | `on_interrupt`, `off_interrupt`, `poll_interrupt`, `enable_interrupt`, `disable_interrupt` — see Interrupt section |

**Additional configuration options:**
- Input mux: 4 single-ended or 2 differential inputs plus AIN0/AIN1 against AIN3
- Full-scale range ±6.144 V … ±0.256 V
- Data rate 8–860 SPS; single-shot or continuous conversion
- Comparator: traditional or window, polarity, latching, 1/2/4-sample queue, thresholds; conversion-ready output on ALERT/RDY

## Data Conversion

```
raw   = int16((msb << 8) | lsb)                # two's complement, -32768..32767
lsb_V = FSR / 32768                          # FSR = 6.144 / 4.096 / 2.048 / 1.024 / 0.512 / 0.256
V_IN  = raw * lsb_V                          # = V(AINP) - V(AINN)

raw_threshold = int(round(V / lsb_V)) clamped to [-32768, 32767];  register = raw_threshold & 0xFFFF
```

Full-scale codes: `7FFFh` for ≥ +FS(2¹⁵−1)/2¹⁵, `0000h` for 0 V, `FFFFh` for −FS/2¹⁵, `8000h` for ≤ −FS. Single-ended measurements (AINN = GND) only use `0000h`–`7FFFh`, but offset can produce small negative codes near 0 V. Do not apply more than VDD + 0.3 V to any input: with a PGA range above VDD (e.g. ±6.144 V at VDD = 3.3 V) the upper codes are unreachable.

| PGA | FSR (V) | LSB (mV) |
|-----|---------|----------|
| `000` | ±6.144 | 0.1875 |
| `001` | ±4.096 | 0.125 |
| `010` | ±2.048 | 0.0625 |
| `011` | ±1.024 | 0.03125 |
| `100` | ±0.512 | 0.015625 |
| `101` | ±0.256 | 0.0078125 |

## Timing Constraints

- **Conversion time:** `1 / DR` — single-cycle settling, so 125 ms at 8 SPS, 7.8 ms at 128 SPS, 1.2 ms at 860 SPS (the data rates scale with the ±10 % internal oscillator). **Conformance-checked** at the driver's default 128 SPS: from the Config write with `OS` = 1 — sigrok marker `conversion_start` — to the first subsequent read of the CONVERSION register — `conversion_done` — the gap must be ≥ 7.8125 ms. See `specs/adc_dac/ads1115_timing.conf`.
- **Power-up from power-down:** ≈ 25 µs after `OS` is written before the conversion starts.
- **Reset:** power-up reset values take effect immediately; the chip then idles in power-down.
- **I²C bus time-out:** 25 ms of bus idle.
- **Duty cycling:** in single-shot mode the host sets the effective rate (e.g. 860 SPS conversions every 125 ms (8 SPS) ≈ 1/100 of the continuous power).

## Implementation Notes

If this chip is register-addressed (I²C), accept `RegisterConnection` (not the bare `Connection`) and call `connection.read(reg, length)` / `connection.write(reg, data)` directly — no chip-local `_read_reg`/`_write_reg` and no `bus_type` branch. See `specs/feature_register_access_design.md`. Registers are 16-bit big-endian: `connection.write(0x01, bytes([msb, lsb]))`, `connection.read(0x00, 2)`.

- **Config writes are whole-word:** never read-modify-write; the driver tracks `mux`, `pga`, `dr`, and the comparator bits and rebuilds the 16-bit word each time, writing every reserved bit at its reset value.
- **`OS` semantics:** writing `OS` = 1 starts a conversion only from power-down; during continuous mode it is ignored. Reading `OS` = 1 means idle — in continuous mode it always reads 1, so do not use it there.
- **Single-shot read order:** because the pointer persists, poll Config **before** moving it to CONVERSION; after the poll write pointer `00` then read. Moving the pointer then reading CONFIG without re-pointing would return CONVERSION.
- **Single-ended input:** only the positive code range is used; code 0 can read slightly negative. Never exceed VDD + 0.3 V on an input (ESD diodes).
- **Siblings:** ADS1114 and ADS1113 share the register map and Config layout; a shared `_ADS111xBase` (Config-word builder, sign extension, single-shot sequence) is allowed, but each chip keeps its own Minimal/Full API as specified. Chip-feature gating: `mux` only on the ADS1115, `pga` on the ADS1114/ADS1115, comparator and ALERT/RDY on the ADS1114/ADS1115; the ADS1113 ignores unsupported Config fields in hardware, so the driver must not expose them.
- **ADS101x family:** the 12-bit ADS1013/4/5 (`specs/adc_dac/ads1013.md`, `ads1014.md`, `ads1015.md`) use the same address scheme, register map and Config layout but a different resolution (result in bits 15:4, thresholds in bits 15:4) and DR table (128–3300 SPS, default 1600 SPS). They are separate chips; the two families **cannot be told apart on the bus** (no ID register) and a shared base across both families is allowed only if resolution, data-rate table and threshold alignment are parameters.
- **No general-call reset:** the chip responds to I²C general call `0x00` / `0x06`, but the per-device `Connection` addresses only the chip's own address, so `reset()` rewrites the registers instead. A bus-level general-call reset would need a transport extension.
- **SMBus alert response:** a latched comparator can also be released by the SMBus Alert Response Address (`0x0C`, read) — not supported; use `clear_alert()`.
- **Datasheet:** SBAS444E (May 2009, revised December 2024), downloaded from `http://www.ti.com/lit/ds/symlink/ads1115.pdf`; one datasheet covers ADS1113, ADS1114 and ADS1115.

## Sigrok Decoder

Decoder id `ads1115`, input `['i2c']`. Matches I²C addresses `0x48`–`0x4B`. Annotates the Address Pointer byte (register name), 16-bit reads/writes of CONVERSION (raw code and volts at the last-seen full-scale range; the decoder assumes ±2.048 V until a Config write is seen), CONFIG (named fields: `OS`, `MUX`, `PGA` with full scale, `MODE`, `DR` as samples per second, `COMP_MODE`, `COMP_POL`, `COMP_LAT`, `COMP_QUE`) and LO_THRESH / HI_THRESH (code and volts; a HI_THRESH bit 15 = 1 with LO_THRESH bit 15 = 0 pair is flagged as conversion-ready mode). Flags a read or write of length ≠ 2 as a warning. For the single-shot conformance check the Config write with `OS` = 1 is annotated `conversion_start` and the first subsequent CONVERSION read `conversion_done`, in the `timing` annotation row, shaped per `specs/sigrok_annotations.md`'s Variable-Length Annotation Convention (`['conversion_start: Config write with OS=1', 'conversion_start', '→CONV']`). The gap must be ≥ 7.8125 ms at 1600 SPS (see `specs/adc_dac/ads1115_timing.conf`).
