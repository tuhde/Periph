# Chip Spec: CS43L22

**Manufacturer:** Cirrus Logic  
**Datasheet:** `datasheets/adc_dac/cs43l22.pdf` (DS792F2, "Confidential Draft 3/4/10" revision marking on the downloaded copy)  
**Category:** adc_dac  
**Transports:** I²C (control port only; audio data travels over a separate I²S/PCM serial port the driver does not touch)

## Overview

The CS43L22 is a low-power stereo DAC (audio codec output stage) with a stereo **headphone/line amplifier** (charge-pump driven, ground-centred output, no coupling capacitors), a **Class-D mono/stereo speaker amplifier** (PWM, up to 1 W, full-bridge), a fixed-function DSP engine (PCM volume, bass/treble shelving, channel mixing/swap, de-emphasis, peak limiter), a beep generator, an analog passthrough from four stereo line inputs to the headphone output, battery compensation / VP monitor for the speaker supply, and soft-ramp / zero-cross volume transitions. It receives digital audio on a serial port (SDIN, SCLK, LRCK, MCLK — I²S, left-justified, right-justified or DSP/TDM format, slave or master) and is **configured entirely through an I²C control port** (single slave address pair `0x4A`/`0x4B`). This spec covers that control port. The audio clock/data source (an I²S master such as a microcontroller's I²S/SAI peripheral producing MCLK, SCLK, LRCK, SDIN) is board-level and outside the driver, which only needs to know the clocking configuration and when MCLK is running.

## Transport Configuration

### I²C
- **Address:** `0x4A` (AD0 = DGND) — `0x4B` (AD0 = VL); 7-bit address `100101 AD0`; **AD0 is latched on the rising edge of RESET**
- **Max clock:** **100 kHz** (standard mode only; the datasheet gives no fast-mode timing)
- **Identity register:** `0x01` = `0xE0 | REVID` (CHIPID[4:0] = `11100` in bits 7:3; revision A0 = 0, A1 = 1, B0 = 2, B1 = 3 in bits 2:0) — mask `0xF8`, expected `0xE0`; feeds `registry/chips.json` (`"driver": null` until implemented)
- **Probe safety:** `register_pointer` — a 1-byte write only loads the Memory Address Pointer (MAP); registers change only with a following data byte
- **Register addressing:** 1-byte MAP, `RegisterConnection` with `reg_bytes = 1`. MAP bit 7 is **INCR**: set it (`reg | 0x80`) to auto-increment the pointer for block reads/writes. The datasheet performs a read as an *aborted write* (address+W, MAP, **STOP**) followed by a new START, address+R and data; the driver uses the connection's register read (which may use a repeated START instead — verify on hardware; the chip is documented only with the STOP form)
- **RESET pin:** active low; required (see Initialization). The driver takes an optional `res_pin` (`OutputPin`)

### Bit Fields

#### `POWER_CTL_1` (`0x02`)
`0x01` or `0x9F` = powered down; `0x9E` = powered up. All other values are reserved.

#### `POWER_CTL_2` (`0x04`)
| Bits | Name | Description |
|------|------|-------------|
| 7:6 | PDN_HPB | Headphone B: `00` on when SPKR/HP_SW low (off when high), `01` on when SW high, `10` always on, `11` always off |
| 5:4 | PDN_HPA | Headphone A (same coding) |
| 3:2 | PDN_SPKB | Speaker B (same coding) |
| 1:0 | PDN_SPKA | Speaker A (same coding) |

Reset `0x05`: both headphone channels `00` (on when the SPKR/HP_SW pin is low), both speaker channels `01` (on when it is high).

#### `CLOCKING_CTL` (`0x05`)
| Bits | Name | Description |
|------|------|-------------|
| 7 | AUTO | `1` auto-detect speed mode from the MCLK/LRCK ratio (slave mode); SPEED bits ignored |
| 6:5 | SPEED[1:0] | Slave: `00` double speed (50–100 kHz Fs), `01` single (4–50 kHz), `10` half (12.5–25 kHz), `11` quarter (4–12.5 kHz); master: sets MCLK/LRCK ratio 512/256/128/128 |
| 4 | 32kGROUP | `1` for 8, 16 or 32 kHz sample rates |
| 3 | VIDEOCLK | `1` if MCLK = 27 MHz |
| 2:1 | RATIO[1:0] | Internal MCLK/LRCK ratio: `00` 128, `01` 125, `10` 132, `11` 136 |
| 0 | MCLKDIV2 | `1` divides MCLK by 2 |

#### `INTERFACE_CTL_1` (`0x06`)
| Bits | Name | Description |
|------|------|-------------|
| 7 | M/S | `0` slave (clocks are inputs), `1` master (outputs) |
| 6 | INV_SCLK | SCLK polarity invert |

| 4 | DSP | DSP (data-packed) mode; requires left-justified format |
| 3:2 | DACDIF | `00` left-justified, `01` I²S, `10` right-justified, `11` reserved |
| 1:0 | AWL | Word length: DSP mode `00` 32 / `01` 24 / `10` 20 / `11` 16 bit; right-justified `00` 24 / `01` 20 / `10` 18 / `11` 16 bit |

#### `PLAYBACK_CTL_1` (`0x0D`)
| Bits | Name | Description |

#### Volume registers

| Register | Format | Range |
|----------|--------|-------|
| `MASTER_x_VOL` (`0x20/0x21`) | signed 8-bit, 0.5 dB/step | `0x18` = +12 dB … `0x00` = 0 dB … `0xFF` = −0.5 dB … `0x34` = −102 dB (`0x19`–`0x33` also −102 dB) |
| `HP_x_VOL` (`0x22/0x23`) | signed 8-bit, 0.5 dB/step | `0x00` = 0 dB … `0xFF` = −0.5 dB … down to −96 dB; `0x01` = muted. The table prints −96 dB at `0x34`, which is inconsistent with 0.5 dB steps (−96 dB = `0x40`) — treat the exact codes below about −90 dB as unverified |
| `SPK_x_VOL` (`0x24/0x25`) | signed 8-bit, 0.5 dB/step | `0x00` = 0 dB … `0xFF` = −0.5 dB … `0x40` = −96 dB; below that muted |
| `PCM_x_VOL` (`0x1A/0x1B`) | bit 7 mute, bits 6:0 signed 0.5 dB | `0x18` = +12 dB … `0x00` = 0 dB … `0x7F` = −0.5 dB … `0x19` = −51.5 dB |
| `PASSTHRU_x_VOL` (`0x14/0x15`) | signed 8-bit, 0.5 dB | `0x18`–`0x7F` = +12 dB (max), `0x00` = 0 dB, `0xFF` = −0.5 dB … `0x80`–`0x88` = −60 dB |

dB value = signed (two's-complement) code × 0.5 (clamped as listed).

#### Other registers

- `TONE_CTL` (`0x1F`): `TREB[3:0]` (7:4) and `BASS[3:0]` (3:0): `0000` = +12 dB, `1000` = 0 dB (reset), 1.5 dB per step, `1111` = −10.5 dB.
- `BEEP_TONE_CFG` (`0x1E`): `BEEP[1:0]` (7:6) off / single / multiple / continuous; `BEEPMIXDIS` (5); `TREBCF[1:0]` (4:3) 5/7/10/15 kHz; `BASSCF[1:0]` (2:1) 50/100/200/250 Hz; `TCEN` (0) tone-control enable.
- `BEEP_FREQ_ON` (`0x1C`): frequency 260.87 Hz (C4) … 2181.82 Hz (C7) over 16 codes (`0x0` C4 260.87, `0x1` C5 521.74, `0x2` 585.37, `0x3` 666.67, `0x4` 705.88, `0x5` 774.19, `0x6` 888.89, `0x7` 1000.00, `0x8` 1043.48, `0x9` 1200.00, `0xA` 1333.33, `0xB` 1411.76, `0xC` 1600.00, `0xD` 1714.29, `0xE` 2000.00, `0xF` 2181.82 Hz); on time ~86 ms … ~5.2 s over 16 codes (`0x0` 86 ms, `0x1` 430 ms, `0x2` 780 ms, `0x3` 1.20 s, … `0xF` 5.2 s). **Must not change while a beep is active.**
- `BEEP_VOL_OFF` (`0x1D`): off time `OFFTIME[2:0]` 1.23 s … 10.8 s (8 codes); beep volume `BPVOL[4:0]` 2 dB steps from +6 dB (`00110`) down through `00000` = −6 dB, `11111` = −8 dB … `00111` = −56 dB.
- `PCM_MIXER_SWAP` (`0x26`): `PCMASWP[1:0]` / `PCMBSWP[1:0]`: `00` left/right as is, `01`/`10` (L+R)/2, `11` swapped.
- `LIMIT_CTL_1` (`0x27`): `LMAX[2:0]` (7:5) and `CUSH[2:0]` (4:2) thresholds `000` 0 dB, 3, 6, 9, 12, 18, 24, `111` −30 dB; `LIMSRDIS` (1), `LIMZCDIS` (0).
- `LIMIT_CTL_2` (`0x28`): `LIMIT` (7) enable, `LIMIT_ALL` (6), `LIMRRATE[5:0]` release (00 fastest … 3F slowest); `LIMIT_ATTACK` (`0x29`): `LIMARATE[5:0]`.
- `STATUS` (`0x2E`, read-clear): bit 6 `SPCLKERR` (MCLK/LRCK ratio invalid; reads 1 right after clocks start), bit 5 `DSPAOVFL`, bit 4 `DSPBOVFL`, bit 3 `PCMAOVFL`, bit 2 `PCMBOVFL`.
- `BATTERY_COMP` (`0x2F`): `BATTCMP` (7), `VPMONITOR` (6), `VPREF[3:0]` (3:0): reference 1.5 … 5.0 V in 0.5 V steps (codes `0`–`7` for VA = 1.8 V, `8`–`F` for VA = 2.5 V). `VP_LEVEL` (`0x30`): VP voltage = code × VA / 63.3.
- `SPEAKER_STATUS` (`0x31`): bit 5 `SPKASHRT`, bit 4 `SPKBSHRT` (shorted to ground), bit 3 SPKR/HP pin level.
- `CHARGE_PUMP_FREQ` (`0x34`): `CHGFREQ[3:0]` (7:4) N; frequency = 64 × Fs / (N + 2) (reset N = 5).

## Initialization Sequence

Datasheet §4.9 (recommended power-up sequence) and §4.11 (required initialization settings):

1. Hold RESET low until all supplies are stable (RESET low ≥ 1 ms); then bring RESET high (AD0 is sampled now). Wait ≥ 550 ns (tirs) before the first I²C transaction.
2. The chip is powered down: `POWER_CTL_1` = `0x01`. Load the desired register settings **while keeping `POWER_CTL_1` at `0x01`**: `POWER_CTL_2`, `CLOCKING_CTL`, `INTERFACE_CTL_1`, volumes, etc.
3. Required initialization settings (after the settings above, before power-up):
   1. write `0x99` to register `0x00`;
   2. write `0x80` to register `0x47`;
   3. set bit 7 of register `0x32` (read-modify-write, i.e. `0x32` ← `0xBB` from its reset value `0x3B`);
   4. clear bit 7 of register `0x32` (`0x32` ← `0x3B`);
   5. write `0x00` to register `0x00`.
4. Apply MCLK at the frequency matching the clocking settings (SCLK may be applied at any time; LRCK only while the power-down bit is 1 — i.e. before step 5).
5. Write `POWER_CTL_1` ← `0x9E` (powered up).
6. If RESET must be driven low again when the supplies drop below the operating range, do so (to avoid supply-glitch problems).

After power-up the charge pump ramps up slowly, then the amplifiers power up in a muted state, and the chip measures the MCLK/LRCK ratio once LRCK is valid. `STATUS.SPCLKERR` reads 1 until the serial port has re-synchronised.

### Power-down sequence (§4.10)
1. Mute the DAC and PWM outputs; 2. disable soft ramp and zero-cross volume transitions; 3. write `POWER_CTL_1` ← `0x9F`; 4. **wait ≥ 100 µs** (before removing MCLK — removing it earlier can stop the charge pump abruptly, drive the headphone outputs up to +VHP and leave DC across the speaker); 5. MCLK may now be removed; 6. bring RESET low for minimum quiescent current (all registers return to their defaults).

## Implementation Stages

### Minimal

Goal: bring the DAC to playing state for an I²S source and control volume and mute of the headphone output. No clock arithmetic beyond MCLK auto-detect.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection, `res_pin: OutputPin \| None = None` | — | Pulses RESET if `res_pin` is given (low ≥ 1 ms, then high, then wait ≥ 1 ms), verifies the chip ID (`0x01` & `0xF8` = `0xE0`; raises otherwise), loads the Minimal defaults below with `POWER_CTL_1` = `0x01`, then runs the required initialization (§4.11). The chip is **not** powered up yet — it needs MCLK first |
| `start` | — | — | Call after MCLK/SCLK/LRCK are running: writes `POWER_CTL_1` ← `0x9E` |
| `stop` | — | — | Power-down sequence: mute, disable soft ramp/zero-cross, `POWER_CTL_1` ← `0x9F`, wait ≥ 100 µs (the caller removes MCLK only after `stop` returns) |
| `set_volume` | `db: float` (−102.0 … +12.0) | — | Master volume A and B (`0x20`/`0x21`) in one block write, 0.5 dB steps (`code = round(db × 2) & 0xFF`, clamped) |
| `get_volume` | — | `float` dB | Master volume A (read back) |
| `mute` | `on: bool = True` | — | `HPAMUTE`/`HPBMUTE` (`PLAYBACK_CTL_2` bits 7:6); the speaker is off in Minimal |

**Sensible defaults:** serial port is an I²S **slave** (`DACDIF` = `01`, `M/S` = 0), 24-bit I²S, clocking auto-detect (`AUTO` = 1, speed from the MCLK/LRCK ratio — works with 12.288 MHz, 11.2896 MHz, 18.432 MHz, 16.9344 MHz MCLK at the standard 256·Fs ratio family), headphone amplifiers always on (`POWER_CTL_2` = `0xAF`: HP `10`/`10`, speaker `11`/`11` off), headphone gain G = 0.6047, master volume 0 dB, digital soft ramp on (reset), zero-cross off, no beep/tone/limiter/passthrough. MCLK must be supplied by the user's I²S source.

## Data Conversion

```
volume code    = round(dB * 2) & 0xFF            (two's complement; 0x00 = 0 dB, 0x18 = +12 dB, 0xFF = -0.5 dB)
master range   : -102.0 .. +12.0 dB   (codes 0x34 .. 0x00 .. 0x18)
headphone vol  : code 0x01 = muted; otherwise 0 dB .. -96 dB
tone gain code = 8 - round(dB / 1.5)             (0 -> +12 dB, 8 -> 0 dB, 15 -> -10.5 dB)
beep volume    : +6 dB .. -56 dB in 2 dB steps (BPVOL 00110 = +6 dB; 00000 = -6 dB; 11111 = -8 dB ... 00111 = -56 dB)
VP voltage     = VPLVL * VA / 63.3
charge pump f  = 64 * Fs / (N + 2)
```

## Timing Constraints

- **RESET:** low pulse ≥ 1 ms; the first I²C transaction ≥ 550 ns after RESET rises (tirs); AD0 is sampled at that rising edge.
- **Power-up:** write `POWER_CTL_1` = `0x9E` only after MCLK is valid; the charge pump then ramps slowly and the outputs enter a muted state (no time given); `SPCLKERR` clears once LRCK is valid and the MCLK/LRCK ratio has been measured.
- **Power-down:** ≥ 100 µs between writing `POWER_CTL_1` = `0x9F` and removing MCLK (datasheet §4.10).
- **Volume transitions:** soft ramp 1/8 dB per LRCK cycle (digital), 1/2 dB per 16 LRCK (analog passthrough); zero-cross changes time out after 1024–2048 samples (21.3–42.7 ms at 48 kHz); analog zero-cross timeout 1024 samples (≈ 10.7 ms).
- **I²C:** fSCL ≤ 100 kHz, tBUF ≥ 4.7 µs, tHD:STA ≥ 4.0 µs, tLOW ≥ 4.7 µs, tHIGH ≥ 4.0 µs, tSU:DAT ≥ 250 ns, tSU:STO ≥ 4.7 µs.
- **Conformance:** none of these has a bus-decodable start/end annotation pair (RESET and MCLK are pins outside the I²C bus), so `specs/adc_dac/cs43l22_timing.conf` defines no checks.

## Implementation Notes

- **Control port only:** there is no audio data over I²C. The driver cannot know whether MCLK/LRCK are running — `start()` must be called by the application after the I²S source is up, and `stop()` before it goes away.
- **Order matters:** configuration writes happen while `POWER_CTL_1` is `0x01`; the required-initialization block (writes to `0x00`, `0x47`, `0x32`) must run after them and before `0x9E`. Doing the required block with the chip already powered up is not documented.
- **Register reads use an aborted write:** the datasheet reads by writing MAP, issuing a STOP, then a new START + read; check whether the target platform's register read (repeated START) works, otherwise issue the two transactions separately.
- **Auto-increment:** for block writes (master volume A/B, tone registers) the driver can set MAP bit 7; the chip auto-increments through consecutive register addresses — reserved registers must not be crossed (e.g. `0x23` → `0x24` is fine, `0x21` → `0x22` fine, `0x29` → `0x2A` is not).
- **Status is read-clear:** `read_status` clears the flags; a read during startup returns `SPCLKERR` = 1 until the serial port re-synchronises.
- **SPKR/HP_SW pin:** the power-control default (`POWER_CTL_2` = `0x05`) routes power by this pin; Minimal overrides it to "always on" for the headphone and "always off" for the speaker so behaviour does not depend on pin wiring.
- **Sample-rate dependent settings:** the 8/16/32 kHz group, 27 MHz video clock and the 125/132/136 MCLK/LRCK ratios need explicit settings (`set_clocking`) and are not covered by auto-detect; `clocking_for` encodes the datasheet table for the listed MCLK/Fs combinations.
- **Headphone volume codes near the bottom are inconsistent in the datasheet** (−96 dB listed at `0x34`); the driver clamps the practical range to ≥ −96 dB using the 0.5 dB step formula and treats `0x01` as mute.
- **Speaker amplifier:** requires VP (up to 5.25 V) and a proper LC-free PWM layout; short-circuit flags are in `SPEAKER_STATUS`; battery compensation lowers the speaker level as VP falls below `VPREF`.
- **Revision:** the committed datasheet copy is a "Confidential Draft 3/4/10" watermarked DS792F2; verify the register details against the final release before relying on unverified items (the headphone-volume table, the power-up register defaults).
- **Datasheet:** DS792F2 from `https://statics.cirrus.com/pubs/proDatasheet/CS43L22_F2.pdf`.

## Sigrok Decoder

Decoder id `cs43l22`, input `['i2c']`. Matches I²C addresses `0x4A` and `0x4B`. Decodes each write as MAP byte (register name, INCR flag) followed by data bytes mapped to consecutive registers when INCR is set, and each read from the last written MAP; every documented register is annotated with its fields (power state `0x9E`/`0x9F`/`0x01`, clocking AUTO/speed/ratio, interface format and word length, headphone gain G, mute flags, volumes in dB, tone gains, beep frequency/times/volume/mode, limiter thresholds, status flags, VP level) and the chip ID read-back is checked against `0xE0` in bits 7:3. The three-write required-initialization block (`0x00`←`0x99`, `0x47`←`0x80`, `0x32` bit toggle, `0x00`←`0x00`) is shown as a single labelled group. Warnings: a write to a reserved register (other than the required-initialization ones), `POWER_CTL_1` values other than `0x01`/`0x9E`/`0x9F`, a `POWER_CTL_1` = `0x9E` write that comes before the required initialization in the capture, and beep timing registers written while a beep mode is active. No timing annotation pair is emitted.
