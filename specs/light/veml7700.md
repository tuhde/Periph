# Chip Spec: VEML7700

**Manufacturer:** Vishay Semiconductors  
**Datasheet:** `datasheets/light/veml7700.pdf` (Document 84286, Rev. 1.8, 28-Nov-2024)  
**Category:** light  
**Transports:** I²C

## Overview

The VEML7700 is a high-accuracy digital ambient light sensor: a high-sensitivity photodiode, low-noise amplifier and 16-bit ADC in a 6.8 × 2.35 × 3.0 mm package. It gives a 16-bit ALS count from 0 lx to about 140 000 lx with a resolution down to 0.0042 lx/step, plus a second 16-bit **WHITE** channel, with programmable gain (×1/8 … ×2), integration time (25 ms … 800 ms), power-saving modes (refresh time 0.6 s … 4.8 s, 2 µA … 28 µA) and a persistence-filtered high/low threshold window whose crossing flags can be read from a status register (there is **no interrupt pin** on this package). 100 Hz / 120 Hz flicker is rejected, temperature compensation is built in, supply 2.5–3.6 V, shutdown 0.5 µA. The chip powers up **shut down**.

## Transport Configuration

### I²C
- **Address:** `0x10` (7-bit, fixed; the datasheet's 8-bit write/read addresses are `0x20` / `0x21`)
- **Max clock:** 400 kHz (10–400 kHz); I²C input high level 1.3–3.6 V; clock/data-low time-out 25–35 ms
- **Identity register:** `0x07` = `0xC481` (low byte device ID `0x81`, high byte slave-address option code `0xC4` for the `0x10` part; a `0x90`-address option exists with `0xD4`), read as a little-endian word; feeds `registry/chips.json`
- **Probe safety:** `register_pointer` — a 1-byte write only selects the command code
- **Register addressing:** 1-byte command code (`RegisterConnection`, `reg_bytes = 1`); all registers are 16-bit **little-endian** (LSB first, SMBus word order); a read is write-command / repeated START / read 2 bytes

## Pin Configuration

| Pin | Notes |
|-----|-------|
| 1 SCL | I²C clock; external pull-up (> 1 kΩ, e.g. 2.2–4.7 kΩ) |
| 2 VDD | 2.5–3.6 V; 100 nF (optionally 10 µF + 10 Ω) decoupling |
| 3 GND | Ground |
| 4 SDA | I²C data; external pull-up |

No interrupt output: "Interrupt pin not available for VEML7700". The threshold window sets flags in register `0x06` only.

## Register Map

| Command | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | ALS_CONF_0 | R/W | `0x0001` (shut down) | Gain, integration time, persistence, interrupt enable, shutdown |
| `0x01` | ALS_WH | R/W | — | ALS high threshold window (16 bit) |
| `0x02` | ALS_WL | R/W | — | ALS low threshold window (16 bit) |
| `0x03` | POWER_SAVING | R/W | — | Power saving mode and enable (bits 2:0; bits 15:3 = 0) |
| `0x04` | ALS | R | — | ALS output data (16 bit) |
| `0x05` | WHITE | R | — | White channel output data (16 bit) |
| `0x06` | ALS_INT | R | — | Interrupt status flags |
| `0x07` | ID | R | `0xC481` | Device ID |

Command `0x03` is the power-saving register (the datasheet says "03 not defined / reserved" in the address note but defines it as register #3 in the table); only `0x00`–`0x07` exist.

### Bit Fields

#### `ALS_CONF_0` (`0x00`)

| Bits | Name | Description |
|------|------|-------------|
| 15:13 | — | Reserved, write `000` |
| 12:11 | ALS_GAIN | `00` = ×1, `01` = ×2, `10` = ×1/8, `11` = ×1/4 |
| 10 | — | Reserved, write `0` |
| 9:6 | ALS_IT | Integration time: `1100` = 25 ms, `1000` = 50 ms, `0000` = 100 ms, `0001` = 200 ms, `0010` = 400 ms, `0011` = 800 ms |
| 5:4 | ALS_PERS | Persistence: `00` = 1, `01` = 2, `10` = 4, `11` = 8 consecutive threshold crossings |
| 3:2 | — | Reserved, write `00` |
| 1 | ALS_INT_EN | `0` = threshold interrupt flags disabled, `1` = enabled |
| 0 | ALS_SD | `0` = power on, `1` = shut down |

#### `POWER_SAVING` (`0x03`)

| Bits | Name | Description |
|------|------|-------------|
| 15:3 | — | Reserved, write 0 |
| 2:1 | PSM | Power-saving mode 1–4 (`00` … `11`); sets the refresh time |
| 0 | PSM_EN | `0` = disabled, `1` = enabled |

#### `ALS_INT` (`0x06`)

| Bits | Name | Description |
|------|------|-------------|
| 15 | int_th_low | Low threshold exceeded |
| 14 | int_th_high | High threshold exceeded |
| 13:0 | — | Reserved |

#### `ID` (`0x07`)

Low byte `0x81` = device ID; high byte = slave-address option code (`0xC4` for `0x10`).

## Initialization Sequence

1. At power-up `ALS_CONF_0` = `0x0001` (shut down); the chip does not measure until `ALS_SD` is cleared.
2. `init` writes `ALS_CONF_0` = `0x0000`: gain ×1, integration time 100 ms, persistence 1, interrupt flags off, power on; power saving off.
3. The first valid ALS result is available after at least one integration time (derived: wait ≥ 2 × `ALS_IT` for the first read after power-on or after changing gain/integration time).

## Implementation Stages

### Minimal

Goal: read the illuminance in lux with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Runs the Initialization Sequence (gain ×1, 100 ms) and waits for the first conversion |
| `read_lux` | — | float | Illuminance in lux (`raw × resolution`, linear; resolution 0.0672 lx/step at the defaults, full scale ≈ 4400 lx) |

**Sensible defaults:** gain ×1, integration time 100 ms, persistence 1, power saving off, interrupt flags off.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `read_raw` | — | int | ALS count (0–65535) |
| `read_white` | — | int | WHITE channel count (0–65535, no lux conversion specified) |
| `set_gain` | `gain: float` (1/8, 1/4, 1, 2) | — | `ALS_GAIN`; raises on other values; waits 2 integration times |
| `set_integration_time` | `ms: int` (25, 50, 100, 200, 400, 800) | — | `ALS_IT`; raises on other values; waits 2 integration times |
| `get_gain` / `get_integration_time` | — | float / int | Current settings |
| `resolution` | — | float | lx per count for the current gain/IT |
| `set_persistence` | `count: int` (1, 2, 4, 8) | — | `ALS_PERS` |
| `set_thresholds` | `low: int`, `high: int` (raw counts) | — | `ALS_WL` / `ALS_WH` |
| `get_thresholds` | — | `(low, high)` | Raw counts |
| `enable_threshold_flags` | `enable: bool` | — | `ALS_INT_EN` |
| `read_interrupt_flags` | — | int | `ALS_INT`: bit 15 low, bit 14 high (`FLAG_LOW = 0x8000`, `FLAG_HIGH = 0x4000`) |
| `set_power_saving` | `mode: int` (1–4), `enable: bool = True` | — | `POWER_SAVING`; mode raises outside 1–4 |
| `shutdown` | — | — | `ALS_SD` ← 1 (the last data stays readable) |
| `wake` | — | — | `ALS_SD` ← 0; waits one integration time |
| `read_id` | — | int | `ID` (`0xC481`) |
| `auto_range` | — | float | Steps gain/integration time (×1/8 @ 25 ms → ×2 @ 800 ms) until the count lies within 1000…30000 (or the limits are reached), then returns the lux for the final setting |

Configuration writes are read-modify-write on `ALS_CONF_0` through a shadow value so unrelated fields are preserved.

**Additional configuration options:** gain, integration time, persistence, threshold window and flags, power saving, shutdown.

## Data Conversion

```
raw        = (msb << 8) | lsb                              # ALS (0x04), 16 bit
resolution = 0.0042 * (800 / IT_ms) * (2 / gain)           # lx per count
lux        = raw * resolution

examples:  gain x2,  IT 800 ms -> 0.0042 lx/count (max 275 lx)
           gain x2,  IT 100 ms -> 0.0336 lx/count
           gain x1,  IT 100 ms -> 0.0672 lx/count (default, max ~4404 lx)
           gain x1/8, IT 25 ms -> 2.1504 lx/count (max ~140 900 lx)
config word = (gain_code << 11) | (it_code << 6) | (pers_code << 4) | (int_en << 1) | sd
```

The datasheet's note "light level = ALS output / ALS gain × responsivity" and the 0.0042 lx/step reference (gain ×2, 800 ms) define the linear resolution table above (consistent with its refresh-time table: 0.0336 / 0.0168 / 0.0084 / 0.0042 lx/bit at ×2 and 100 / 200 / 400 / 800 ms). At high illuminance (above about 1000 lx) the vendor application note adds a non-linear correction polynomial; it is **not** in this datasheet and the drivers return the linear value.

## Timing Constraints

- **Integration time:** 25 / 50 / 100 / 200 / 400 / 800 ms (`ALS_IT`); there is no data-ready flag, so the driver waits.
- **Power-saving refresh time** (gain ×2, datasheet table): mode 1 / 2 / 3 / 4 at 100 ms IT = 600 / 1100 / 2100 / 4100 ms; at 200 ms: 700 / 1200 / 2200 / 4200; at 400 ms: 900 / 1400 / 2400 / 4400; at 800 ms: 1300 / 1800 / 2800 / 4800 ms (supply current 28 … 2 µA). With power saving off the refresh time is the integration time.
- **Power:** shutdown 0.5 µA; operation 45 µA at 100 ms refresh (power saving off).
- **I²C:** 10–400 kHz, clock/data-low time-out 25–35 ms — clock-rate properties, not event-to-event delays.
- **Conformance:** none of these has a bus-decodable start/end annotation pair, so `specs/light/veml7700_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection, little-endian words:** `connection.read(cmd, 2)` returns `[lsb, msb]`; `connection.write(cmd, [lsb, msb])`. No chip-local `_read_reg`/`_write_reg`, no `bus_type` branch (see `specs/feature_register_access_design.md`).
- **Shutdown by default:** forgetting to clear `ALS_SD` leaves the chip idle returning the last (zero) value; `init` clears it.
- **Settling after a change:** a new gain/IT takes effect on the next integration; discard one result (the driver waits 2 × IT).
- **Gain/IT vs saturation:** the 16-bit count saturates at 65535; the high-resolution settings clip in daylight. Use `auto_range` outdoors.
- **No interrupt pin:** the threshold-window flags are polled from register `0x06`; the datasheet does not say how they clear (read the register and compare). The drivers do not offer an `on_interrupt` callback.
- **Auto-memorization:** in shutdown the last ALS value stays readable; waking starts a new detection.
- **Reserved bits:** keep `ALS_CONF_0` bits 15:13, 10 and 3:2 at 0.
- **Address option:** a `0x90`-address variant exists per the ID-register note (ID high byte `0xD4`); this spec covers the `0x10` part.
- **Datasheet:** Vishay document 84286 Rev. 1.8, from `https://www.vishay.com/docs/84286/veml7700.pdf`.

## Sigrok Decoder

Decoder id `veml7700`, input `['i2c']`. Matches I²C address `0x10`. Annotates each write and each repeated-START read by command name; decodes `ALS_CONF_0` field by field (gain, integration time, persistence, interrupt enable, shutdown), `POWER_SAVING`, the ALS and WHITE counts (raw and lux at the gain/IT of the last configuration seen), the threshold registers, the `ALS_INT` flags and the ID (verified against `0xC481`); warns on writes to read-only registers, on non-zero reserved bits and on command codes above `0x07`. No timing annotation pair is emitted.
