# Chip Spec: MAX44009

**Manufacturer:** Maxim Integrated (now Analog Devices)  
**Datasheet:** `datasheets/light/max44009.pdf` (19-5719; Rev 0; 1/11, supplied as an attachment to the issue)  
**Category:** `light` (the issue form listed "ADC / DAC"; the chip is an ambient light sensor, which belongs to the `light` category)  
**Transports:** I²C (SMBus-compatible)

## Overview

The MAX44009 is an ultra-low-power ambient light sensor with an on-chip photodiode (spectral response matched to the human eye, with IR and UV blocking), a second IR photodiode for light-source compensation, and an ADC with automatic ranging. It reports illuminance directly as a 12-bit floating-point value (4-bit exponent, 8-bit mantissa) from 0.045 lux to 188 000 lux (a 22-bit dynamic range, > 4 000 000 : 1) with no conversion formulas beyond `lux = 2^exponent × mantissa × 0.045`. It draws 0.65 µA typical at 1.8 V (VCC 1.7–3.6 V), has a programmable interrupt (upper / lower threshold window plus a delay timer, open-drain `INT` pin) so the host need not poll, an automatic mode (current divider and 100–800 ms integration time chosen by the chip) and a manual mode (6.25–800 ms integration, current divider 1 or 1/8). It comes in a 2 × 2 × 0.6 mm UTDFN-Opto package with one address pin. Typical uses: display / keyboard backlight control, phones, tablets, TVs, industrial sensors.

## Transport Configuration

### I²C
- **Address:** `0x4A` (A0 = GND) — `0x4B` (A0 = VCC); the address byte is `1001 010x` / `1001 011x` (`0x94`/`0x95` and `0x96`/`0x97` including R/W), the 7-bit address is that byte shifted right by one

| A0 | 7-bit address | Write / read byte |
|----|---------------|-------------------|
| GND | `0x4A` | `0x94` / `0x95` |
| VCC | `0x4B` | `0x96` / `0x97` |

- **Max clock:** 400 kHz; the chip is I²C / SMBus compatible
- **Identity register:** none; chip has no ID register (feeds `registry/chips.json` with `"id_probe": null` and `"driver": null` until implemented, see `specs/feature_i2c_discovery.md`)
- **Probe safety:** `register_pointer` — the first data byte after the address is the register pointer; a 1-byte write only sets the pointer
- **Register addressing:** 1-byte register address (`RegisterConnection`, `reg_bytes = 1`); reads are "write pointer, repeated START, read one byte". Whether the pointer auto-increments for multi-byte reads is **not stated**; the datasheet reads two registers by repeating the pointer + repeated-START sequence (Figure 8), so the driver reads one register per transfer

## Register Map

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | INT_STATUS | R | `0x00` | Interrupt status (bit 0 INTS); cleared by reading |
| `0x01` | INT_ENABLE | R/W | `0x00` | Interrupt enable (bit 0 INTE) |
| `0x02` | CONFIG | R/W | `0x03` | Continuous mode, manual mode, current division ratio, integration time |
| `0x03` | LUX_HIGH | R | `0x00` | Exponent (7:4) and mantissa bits 7:4 (3:0) |
| `0x04` | LUX_LOW | R | `0x00` | Mantissa bits 3:0 (3:0) |
| `0x05` | UPPER_THRESHOLD | R/W | `0xFF` | Upper threshold, exponent + mantissa MSBs |
| `0x06` | LOWER_THRESHOLD | R/W | `0x00` | Lower threshold, exponent + mantissa MSBs |
| `0x07` | THRESHOLD_TIMER | R/W | `0xFF` | Threshold timer, units of 100 ms |

Only registers `0x00`–`0x07` exist; the driver never writes other pointer values.

### Bit Fields

#### `INT_STATUS` (`0x00`) and `INT_ENABLE` (`0x01`)

| Register | Bit | Name | Description |
|----------|-----|------|-------------|
| `0x00` | 0 | INTS | 1 = ambient light was outside the threshold window for longer than the threshold timer (only set if `INTE` = 1); reset to 0 when the register is read; mirrored on the `INT` pin (asserted low) |
| `0x01` | 0 | INTE | 1 = interrupt events set `INTS` and pull `INT` low; 0 = no event is signalled. Writing 0 also clears a pending `INTS` |

#### `CONFIG` (`0x02`) — reset `0x03`

| Bits | Name | Description |
|------|------|-------------|
| 7 | CONT | 0 = default mode: one measurement every 800 ms regardless of integration time (lowest current); 1 = continuous: a new measurement starts as soon as one finishes (readings every integration time; slightly higher current). Independent of `MANUAL` |
| 6 | MANUAL | 0 = automatic: `CDR` and `TIM` are chosen by the chip and read back as read-only; 1 = manual: `CDR` and `TIM` are written by the host |
| 5:4 | — | Unused |
| 3 | CDR | Current division ratio: 0 = all photodiode current to the ADC; 1 = divide by 8 (high brightness) |
| 2:0 | TIM | Integration time: 000 = 800 ms, 001 = 400 ms, 010 = 200 ms, 011 = 100 ms (reset), 100 = 50 ms, 101 = 25 ms, 110 = 12.5 ms, 111 = 6.25 ms (100 – 6.25 ms writable only in manual mode; in automatic mode the chip uses 100 / 200 / 400 / 800 ms) |

#### `LUX_HIGH` (`0x03`) / `LUX_LOW` (`0x04`)

| Register | Bits | Name | Description |
|----------|------|------|-------------|
| `0x03` | 7:4 | E[3:0] | Exponent 0–14; `1111` = overrange |
| `0x03` | 3:0 | M[7:4] | Four most significant bits of the 8-bit mantissa |
| `0x04` | 3:0 | M[3:0] | Four least significant bits of the mantissa (bits 7:4 unused) |

#### Threshold registers `0x05`, `0x06`

| Bits | Name | Description |
|------|------|-------------|
| 7:4 | E[3:0] | Exponent (0–14) |
| 3:0 | M[7:4] | Four most significant bits of the mantissa; the low nibble is implied as `1111` (upper threshold) or `0000` (lower threshold) |

#### `THRESHOLD_TIMER` (`0x07`)

| Bits | Name | Description |
|------|------|-------------|
| 7:0 | T | Delay = T × 100 ms (0–25.5 s); `0x00` asserts the interrupt as soon as the light level leaves the window |

## Initialization Sequence

1. Power VCC (1.7–3.6 V). The registers are at their reset values; there is no reset command and the datasheet gives no start-up delay for the interface.
2. Write `INT_ENABLE` (`0x01`) ← `0x00` (interrupt off, clears a pending status), `CONFIG` (`0x02`) ← `0x03` (default mode, automatic ranging, 100 ms), `UPPER_THRESHOLD` (`0x05`) ← `0xFF`, `LOWER_THRESHOLD` (`0x06`) ← `0x00`, `THRESHOLD_TIMER` (`0x07`) ← `0xFF` (the reset values; guarantees a known state when the chip was used before).
3. Read `INT_STATUS` (`0x00`) once to clear any stale `INTS`.
4. Wait 900 ms (driver choice: one 800 ms measurement cycle plus the 100 ms integration time) so that the first `lux()` call returns a real measurement; the lux registers are `0x00` until the first conversion completes.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `INT`, open-drain, active low — requires an external pull-up |
| Level | 1 (single fixed condition) |
| Condition | the lux level is above the upper threshold or below the lower threshold for longer than the threshold timer, with `INTE` = 1 |
| Clear mechanism | read `INT_STATUS` (`INTS` and the `INT` pin release when the register is read), or write 0 to `INT_ENABLE` |

The `INT` pin follows `INTS`. Both thresholds compare against the 12-bit lux value in the high-byte format (exponent + 4 mantissa MSBs).

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on INT (falling edge); `callback(status)` receives the status int (`1` = threshold event). Uses `connection.int_pin` (or `int_pin`), otherwise a poll of the driver; the callback fires after the driver has read (and thereby cleared) `INT_STATUS` |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Read `INT_STATUS` (clearing it) and return the status int (bit 0 = `INTS`) |
| `enable_interrupt` | `enable_interrupt()` | `INT_ENABLE` ← `0x01` |
| `disable_interrupt` | `disable_interrupt()` | `INT_ENABLE` ← `0x00` (also clears a pending status) |

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits everything and adds the rest.

### Minimal

Goal: read the ambient illuminance in lux with no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Runs the Initialization Sequence (known state, automatic mode, 900 ms wait) |
| `lux` | — | `float` | Illuminance in lux (`2^E × M × 0.045`); on overrange (`E` = 15) returns the maximum 188 006.4 lux |

**Sensible defaults:** automatic range and integration time (`MANUAL` = 0, chip chooses 100–800 ms and the current divider), default (non-continuous) mode with one measurement per 800 ms, interrupt disabled, threshold window fully open (`0xFF` / `0x00`), timer `0xFF`.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | As Minimal |
| *(inherits Minimal's `lux`)* | | | |
| `read_raw` | — | `(exponent, mantissa, overrange)` | Exponent 0–14, 8-bit mantissa, `overrange` = (`E` = 15); one consistent two-register read (see Implementation Notes) |
| `is_overrange` | — | `bool` | `True` if the last reading had `E` = 15 |
| `resolution` | — | `float` | Lux per LSB for the current reading: `2^E × 0.045` |

**Additional configuration options:** continuous vs. low-power measurement mode, automatic vs. manual range (integration time 6.25–800 ms, current division 1 / 1/8), interrupt threshold window and delay.

## Data Conversion

```
E = LUX_HIGH >> 4                              # exponent, 0..14 (15 = overrange)
M = ((LUX_HIGH & 0x0F) << 4) | (LUX_LOW & 0x0F)   # mantissa, 0..255
lux = 2**E * M * 0.045                          # 0.045 lux per LSB at the highest sensitivity
max lux = 2**14 * 255 * 0.045 = 188006.4        # E = 14, M = 255

# reading only the high byte: lux ≈ 2**E * (M7..M4 << 4) * 0.045 = 2**E * (nibble * 16) * 0.045   (0.72 lux/step at E = 0)

# threshold registers (0x05 upper, 0x06 lower): exponent + 4 mantissa MSBs, format as LUX_HIGH
upper_lux = 2**E * ((UT_nibble << 4) | 0x0F) * 0.045
lower_lux = 2**E * ((LT_nibble << 4)) * 0.045
```

Threshold encoding of a lux value `x` (automatic mode, from the datasheet's two rules): if `x` < 11.5 lux use exponent 0 and code `0000 MMMM` with `MMMM = min(15, round(x / (16 × 0.045)))`; otherwise choose the exponent `E` ∈ 1…14 such that `x / (2^E × 0.045)` lies in 128…255 (mantissa with M7 = 1) and code `EEEE 1MMM` with `MMMM = (mantissa >> 4)`, limited to the maximum usable code `1110 1111`. The resolution of a threshold is therefore a factor 1/16 to 1/8 of its value. In manual mode the exponent must lie within the range of Table 9 for the chosen `TIM` / `CDR`.

Integration time and resolution in automatic mode (Table 8): lux 0–11.5 → 0.045 lux/LSB … 94 372.8–188 006.4 → 737.28 lux/LSB (each doubling of range doubles the step).

Delay: `threshold_delay_s = THRESHOLD_TIMER × 0.1`.

### Demo

Adaptive backlight controller. Initialise the Full driver, print the configuration (`get_config`) and a first `lux()`, read the resolution. ## Timing Constraints

- **Measurement cycle:** in the default mode (`CONT` = 0) one measurement every 800 ms regardless of integration time; in continuous mode (`CONT` = 1) one per integration time (readings every 6.25 ms … 800 ms).
- **Integration time:** automatic mode 100 / 200 / 400 / 800 ms (50/60 Hz rejection); manual mode 6.25 ms … 800 ms (the datasheet quotes the 50 / 60 Hz rejection for the 100 ms and longer integration times of the automatic mode). ADC conversion time ACT = 100 ms nominal (99.6–100.4 ms in a 100 ms range; 97–107 ms over temperature).
- **Lux registers freeze during a read:** the high / low registers are not updated from the start of a valid address transmission until the next STOP; read both without a STOP in between (repeated START) to obtain one sample (see Implementation Notes).
- **Threshold delay:** `THRESHOLD_TIMER × 100 ms`.
- **Dark level:** 0 lux → 0 to 0.045 lux.
- **No start-up delay is specified;** the driver waits 900 ms in `init` for the first conversion (driver choice).
- **I²C:** fSCL ≤ 400 kHz, tBUF ≥ 1.3 µs, tHD,STA ≥ 0.6 µs, tLOW ≥ 1.3 µs, tHIGH ≥ 0.6 µs, tSU,STA ≥ 0.6 µs, tSU,DAT ≥ 100 ns, tHD,DAT 0–0.9 µs (the master must provide ≥ 300 ns hold), tSU,STO ≥ 0.6 µs; spikes < 50 ns suppressed.
- **Conformance:** none of these constraints has a bus-decodable start / end annotation pair the host must honour, so `specs/light/max44009_timing.conf` defines no checks.

## Implementation Notes

- **Register-addressed:** accept `RegisterConnection` (1-byte register address) and call `connection.read(reg, 1)` / `connection.write(reg, bytes([v]))` directly — no chip-local `_read_reg`/`_write_reg` and no `bus_type` branch (see `specs/feature_register_access_design.md`).
- **Consistent two-register lux read:** the datasheet asks for `0x03` and `0x04` to be read without a STOP between them (pointer + repeated START per register, Figure 8) so no internal update can fall between the reads. A `RegisterConnection` read ends with a STOP, so the driver reads `0x03`, `0x04`, `0x03` and, if the two reads of `0x03` differ (a new conversion arrived), repeats once; a mantissa-low-nibble tear within the same exponent and high nibble is an error of at most 15 counts and is accepted. A connection that can chain reads without a STOP should use that form. Auto-increment for a 2-byte burst read from `0x03` is not documented and is not relied on.
- **Overrange:** `E` = 15 is overload (not a number); `lux()` returns 188 006.4 lux in that case, `read_raw` / `is_overrange` expose the condition. The valid maximum code is `1110 1111 1111`.
- **Resolution scales with the reading:** the exponent grows with the light level, so a reading is accurate to about 1/256 of its value; the low-light resolution is 0.045 lux.
- **Accuracy:** total error 15 % (green 538 nm LED, 25 °C), light-source matching 10 % (fluorescent vs. incandescent), IR transmittance ≤ 0.5 %, UV 1.2 %; the part is calibrated so that 100 lux fluorescent light reads 100 lux. Optical placement: the sensitive area is 0.37 × 0.37 mm (datasheet Figure 9) behind the package window; use a light guide only over that area.
- **Manual mode and thresholds:** in manual mode the threshold exponents must stay within the range of Table 9 for the selected `TIM` / `CDR`; exceeding the maximum lux of a manual setting yields `E` = 15 (overload).
- **Interrupt flow (datasheet Figure 2):** read lux → set thresholds around it → set the delay → sleep until `INT` → read `INT_STATUS` → act. Setting `INTE` to 0 clears a pending `INTS`. The pin is open-drain: use a pull-up (10 kΩ typical) to a supply ≤ 3.6 V.
- **Supply and bus:** VCC 1.7–3.6 V; SDA / SCL / A0 inputs are not 5 V tolerant (absolute maximum 4 V on all pins except `INT`); pull-ups ≥ 500 Ω, typically 10 kΩ; every I²C bit can cost up to 1 mA on a low-impedance pull-up, so minimise transactions — the interrupt scheme avoids polling.
- **Customisation:** the datasheet mentions a customised enhanced-sensitivity version for dark-glass applications; the standard part is covered here.
- **Siblings:** no compatibility with other light sensors is assumed; the MAX44009 shares no register layout with the APDS-9930 / APDS-9960 ALS channels already in the library.
- **Datasheet revision:** Rev 0, January 2011, 20 pages, supplied as an attachment to the issue.

## Sigrok Decoder

Decoder id `max44009`, input `['i2c']`. Matches I²C addresses `0x4A` and `0x4B`. Annotates each register access by name (INT_STATUS, INT_ENABLE, CONFIG, LUX_HIGH, LUX_LOW, thresholds, timer); decodes `CONFIG` into `CONT`, `MANUAL`, `CDR` and the integration time in ms; assembles reads of `LUX_HIGH` / `LUX_LOW` (in one transaction or in two consecutive reads) into exponent, mantissa and lux (`2^E × M × 0.045`), and the high byte alone as an approximate lux; decodes the threshold registers as lux (upper with the implied `1111` nibble) and the timer as seconds; shows `INTS` and `INTE`. Warnings: a STOP between the reads of `LUX_HIGH` and `LUX_LOW` (the registers may update between the reads), an exponent of `1111` ("overrange"), a threshold code with exponent ≠ 0 and M7 = 0 in automatic mode (invalid format), and writes to the read-only registers (`0x00`, `0x03`, `0x04`). No timing annotation pair is emitted, since no constraint is conformance-checked.
