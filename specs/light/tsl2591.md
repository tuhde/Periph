# Chip Spec: TSL2591

**Manufacturer:** ams OSRAM  
**Datasheet:** `datasheets/light/tsl2591.pdf` (TSL2591 Very-High Sensitivity Light-to-Digital Converter, v3-00, 2023-Feb-08)  
**Category:** light  
**Transports:** I²C

## Overview

The TSL2591 is a very-high-sensitivity ambient-light sensor with a dynamic range of about 600 000 000 : 1. Two photodiodes (channel 0: visible + infrared, channel 1: infrared) feed two 16-bit ADCs; the host reads both raw counts and derives the illuminance in lux with the ams empirical formula, which cancels the infrared component. Gain is selectable in four steps (low 1×, medium ≈ 25×, high ≈ 428×, maximum ≈ 9876×) and the integration time in six steps (100–600 ms). A programmable interrupt (persistence-filtered threshold window, plus a no-persist window) drives the open-drain `INT` pin. Supply 2.7–3.6 V, I²C up to 400 kHz. Typical uses: display/backlight control, lighting and street-light control, photography, industrial and wearables.

## Transport Configuration

### I²C
- **Address:** `0x29` (7-bit, fixed). The part also answers on `0x28` for **read-only** registers so that all read registers can be fetched in one block read
- **Max clock:** 400 kHz
- **Register addressing:** every access starts with a **command byte** `0xA0 | register` (`CMD` bit 7 = 1, `TRANSACTION` bits 6:5 = `01` normal operation, bits 4:0 = register address); multi-byte reads/writes auto-increment
- **Identity register:** `ID` (`0x12`) = `0x50` (registered with the command bit: wire address `0xB2`); `PID` (`0x11`) holds the package ID in bits 5:4. Registered in `registry/chips.json` as `id_probe` register `0xB2`, `reg_bytes` 1, `length` 1, mask `0xFF`, expected `[0x50]`
- **Probe safety:** `write_sensitive` — a one-byte write is interpreted as a command byte; a byte with bits 6:5 = `11` (special function, e.g. `0xE4` forced interrupt) has side effects. Probe with the `0xB2` read only

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| INT | low, open-drain | interrupt output; requires an external pull-up; shows `STATUS.AINT`/`NPINTR` while `ENABLE.AIEN`/`NPIEN` is set |
| SDA, SCL | — | I²C; pull-ups required |
| VDD, GND | — | 2.7–3.6 V (3.0 V typ.); the TSL25911 variant sets the I²C logic levels from VDD |

### Special function commands (command byte)

| Byte | Function |
|------|----------|
| `0xE4` | Set interrupt (forces `AINT`/`NPINTR`; must be cleared with a clear command) |
| `0xE6` | Clear ALS interrupt |
| `0xE7` | Clear ALS and no-persist ALS interrupt |
| `0xEA` | Clear no-persist ALS interrupt |

### Bit Fields

#### `ENABLE` (`0x00`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | NPIEN | no-persist interrupt enable (bypasses the persist filter) |
| 6 | SAI | sleep after interrupt: power down at the end of the ALS cycle after an interrupt |
| 5 | — | reserved, write 0 |
| 4 | AIEN | ALS interrupt enable (persist filter applies) |
| 3:2 | — | reserved, write 0 |
| 1 | AEN | ALS enable |
| 0 | PON | power on (oscillator enabled) |

#### `CONFIG` (`0x01`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | SRESET | system reset (self-clearing) |
| 6 | — | reserved, write 0 |
| 5:4 | AGAIN | `00` low (1×), `01` medium (≈ 25×), `10` high (≈ 428×), `11` maximum (≈ 9876×) |
| 3 | — | reserved, write 0 |
| 2:0 | ATIME | integration time: `000` 100 ms (max count 36863), `001` 200 ms, `010` 300 ms, `011` 400 ms, `100` 500 ms, `101` 600 ms (max count 65535 for 200 ms and longer) |

#### `PERSIST` (`0x0C`), bits 3:0 `APERS`

`0000` every ALS cycle generates an interrupt; `0001` any value outside the threshold range; `0010` 2, `0011` 3, `0100` 5, `0101` 10, `0110` 15, `0111` 20, `1000` 25, `1001` 30, `1010` 35, `1011` 40, `1100` 45, `1101` 50, `1110` 55, `1111` 60 consecutive out-of-range values.

#### `STATUS` (`0x13`)

| Bits | Name | Description |
|------|------|-------------|
| 5 | NPINTR | no-persist interrupt |
| 4 | AINT | ALS interrupt |
| 0 | AVALID | the ADC channels completed an integration cycle since `AEN` was set |

## Initialization Sequence

1. Power up VDD; read `ID` (`0x12`, command `0xB2`) and check `0x50`.
2. Write `CONFIG` = gain and integration time (e.g. `0x10` = medium gain, 100 ms).
3. Write `ENABLE = 0x03` (`PON | AEN`).
4. Wait one integration time (plus a few ms); poll `STATUS.AVALID`.
5. Read `0x14`–`0x17` (command `0xB4`, 4 bytes: `C0L, C0H, C1L, C1H`) in one block read; compute the lux.
6. To save power after a one-shot reading, write `ENABLE = 0x00`.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | active-low, open-drain — requires external pull-up |
| Level | 2 (selectable sources) |
| Condition(s) | channel-0 count outside the persist window for `APERS` cycles, or outside the no-persist window |
| Clear mechanism | special function commands `0xE6` / `0xE7` / `0xEA` |

### Interrupt sources

| Constant | Value | Condition |
|----------|-------|-----------|
| `SOURCE_ALS` | `0x10` | `STATUS.AINT`: channel 0 outside `AILT`/`AIHT` for the persistence count |
| `SOURCE_NO_PERSIST` | `0x20` | `STATUS.NPINTR`: channel 0 outside `NPAILT`/`NPAIHT` immediately after an integration |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on INT (falling edge) via `connection.int_pin` (or `int_pin`), otherwise a polling task calling `poll_interrupt`; `callback(status)` receives the masked `STATUS` |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Reads `STATUS`, clears the reported interrupts with the matching special function, returns the masked sources (0 = none) |

| `disable_interrupt` | `disable_interrupt(source)` | clears the enable bit |

## Implementation Stages

### Minimal

Goal: read the illuminance in lux with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Stores the register-addressed `Connection`; verifies `ID = 0x50`, writes `CONFIG` = medium gain, 100 ms (`0x10`) and `ENABLE = 0x03`, waits for `AVALID` |
| `read` | — | float | Illuminance in lux: waits for `AVALID` (≤ 110 ms), reads the four data bytes, applies the ams formula (see Data Conversion); returns `0.0` when `C0 = 0`; saturated readings (`C0` or `C1` at the maximum count) raise an error |

**Sensible defaults:** continuous ALS at medium gain (≈ 25×), 100 ms integration, interrupts off.

## Data Conversion

```
ch0 = (C0DATAH << 8) | C0DATAL            # visible + infrared
ch1 = (C1DATAH << 8) | C1DATAL            # infrared

# ams DN40 empirical formula (the same constants as the ams/Adafruit reference code)
atime_ms = (ATIME + 1) * 100
again    = {low: 1.0, medium: 25.0, high: 428.0, max: 9876.0}[AGAIN]
cpl      = (atime_ms * again) / 408.0     # counts per lux; 408.0 is the glass attenuation factor (GA x DF)
lux      = ((ch0 - ch1) * (1.0 - ch1 / ch0)) / cpl     # ch0 > 0

saturated = ch0 >= (36863 if ATIME == 0 else 65535) or ch1 >= (36863 if ATIME == 0 else 65535)
```

The datasheet's measured gain scaling relative to low gain is 24.5× (medium), 400× (high) and 9200× (maximum, ch0) / 9900× (ch1); the formula above uses the nominal 25/428/9876 values of the ams application note. Both `ch0` and `ch1` change with the gain/integration setting, so the lux value is only valid when neither channel is saturated; the datasheet gives the maximum counts as 36863 (100 ms) and 65535 (200 ms and longer). The irradiance responsivity is 264.1 counts/(µW/cm²) (ch0) and 34.9 (ch1) for white light at 100 ms, high gain. Add a cover-glass attenuation factor to `cpl` if an overlay is used.

## Timing Constraints

| Constraint | Value |
|------------|-------|
| ADC integration time | 100, 200, 300, 400, 500, 600 ms (step size 95–105 ms per 100 ms) |
| Integration steps | 1–6 |
| Max ADC count | 36863 (100 ms), 65535 (200–600 ms) |
| First valid result | after one integration cycle (`STATUS.AVALID`) |
| I²C clock | ≤ 400 kHz |

`AVALID` marks the end of an integration but the datasheet gives it as an integration time rather than a separate bus-checked constraint, so `tsl2591_timing.conf` defines no checks.

## Implementation Notes

- **Register-addressed connection with command byte:** every register address on the wire is `0xA0 | reg`; the driver uses a `RegisterConnection` and adds the command bits itself (the cleanest form: the chip class maps `reg` → `0xA0 | reg`), or reads/writes with the plain `Connection`. Do not send raw register addresses without the command bit (the chip ignores them).
- **Block read:** read `0x14`–`0x17` in one transaction (command `0xB4`) so that both channels belong to the same integration; the shadow registers update only at the end of an integration.
- **Two-step enable:** `PON` first, then `AEN` (or both in one write); the first valid reading arrives after one integration time.
- **Saturation:** a saturated channel makes the lux formula meaningless; lower the gain or the integration time. At 100 ms the maximum count is 36863 (not 65535).
- **Clear interrupts explicitly:** `AINT`/`NPINTR` stay set (and INT low) until a special-function clear is written; the status read does not clear them.
- **Threshold comparison uses channel 0 only.**
- **Gain constants:** use the nominal 25/428/9876 factors for the lux formula; the datasheet's measured typical values differ by about ±8 % and part-to-part variation applies.
- **Address:** `0x29` is shared with the TSL2561/TSL2563 (`0x29`/`0x39`/`0x49`), VL53L0X/VL53L1X (`0x29`), APDS-9930 (`0x39`) and others; the TSL2591 ID at `0xB2` identifies it (a TSL2561 would NACK or return a different value). Probe with `0xB2` only.
- **TSL25911:** the pin-compatible TSL25911 (I/O voltage = VDD) has the same register map and `ID`.

## Sigrok Decoder

Decoder id `tsl2591`, input `['i2c']`. Matches I²C address `0x29` (and `0x28` for reads). Annotates every command byte with the register name (or special function), decodes `ENABLE`, `CONFIG` (gain, integration time), `PERSIST`, `STATUS`, `ID`, the thresholds and the 4-byte data block, and computes the lux with the formula above using the last seen gain/integration time; warns on a data read before `AVALID`, on saturated channels, on a missing command bit and on an undocumented special function. No conformance annotation pair is emitted (no checked timing constraint).
