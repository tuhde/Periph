# Chip Spec: BH1750FVI

**Manufacturer:** ROHM Semiconductor  
**Datasheet:** `datasheets/light/bh1750.pdf` (BH1750FVI Technical Note, No. 11046EDT01, Rev. D, 2011.11)  
**Category:** light  
**Transports:** I²C

## Overview

The BH1750FVI is a digital ambient-light sensor IC with a 16-bit I²C output in lux and a spectral response close to the human eye, with little IR sensitivity. It needs no calibration: the illuminance is `raw / 1.2` lx. It is command driven (no register pointer): single-byte opcodes select power-down/power-on, reset of the data register, and one of six measurement modes — continuous or one-time, each in high resolution (1 lx, ≈ 120 ms typ. / 180 ms max), high resolution mode 2 (0.5 lx, ≈ 120 ms) or low resolution (4 lx, 16 ms typ. / 24 ms max). A measurement-time register (MTreg, 31–254, default 69) adjusts the sensitivity to extend the range (≈ 0.11 lx up to ≈ 100 000 lx) or to compensate an optical window. The long integration time of the high-resolution modes rejects 50/60 Hz noise. After a one-time measurement the chip powers down by itself. Supply 2.4–3.6 V, 120 µA measuring, 0.01 µA power-down. Typical uses: display and keypad backlight control, lighting control, mobile devices, consumer electronics.

## Transport Configuration

### I²C
- **Address:** `0x23` (7-bit `0100011`, `ADDR` ≤ 0.3 × VCC) or `0x5C` (7-bit `1011100`, `ADDR` ≥ 0.7 × VCC); the `ADDR` pin is a tri-state input: do not float it (use ≈ 100 kΩ to the intended level if the DVI sequencing is not controlled)
- **Max clock:** 400 kHz (the datasheet specifies fast mode)
- **Write format:** one opcode per transaction (START, address+W, opcode, STOP); the chip does **not** accept several opcodes without a STOP in between
- **Read format:** START, address+R, high byte, low byte (NACK on the last), STOP
- **Identity register:** none; the chip has no ID register (`id_probe: null` in `registry/chips.json`). The address `0x5C` is shared with the LPS22HB/LPS33HW pressure sensors (`0x5C`–`0x5D`)
- **Probe safety:** `write_sensitive` — every written byte is an opcode; opcodes other than those documented ("Don't input the other opecode") must not be sent. A read in power-down returns stale data

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| DVI | low | I²C reference voltage **and** asynchronous reset input: hold ≤ 0.4 V for ≥ 1 µs after VCC is applied (internal 150 kΩ pull-down while low); in the `DVI = L` period the chip is in power-down. DVI must come up after VCC |
| ADDR | — | address select: low = `0x23`, high = `0x5C` |
| SDA, SCL | — | I²C; pull-ups required |
| VCC, GND | — | 2.4–3.6 V (3.0 V typ.); 0.1 µF decoupling |

## Command Set

| Command | Opcode | Description |
|---------|--------|-------------|
| Power down | `0x00` | No active state |
| Power on | `0x01` | Waiting for a measurement command |
| Reset | `0x07` | Clears the illuminance data register (not accepted in power-down; power on first) |
| Continuous H-resolution | `0x10` | 1 lx resolution, ≈ 120 ms typ. per measurement, repeated |
| Continuous H-resolution mode 2 | `0x11` | 0.5 lx resolution, ≈ 120 ms |
| Continuous L-resolution | `0x13` | 4 lx resolution, ≈ 16 ms |
| One-time H-resolution | `0x20` | 1 lx, ≈ 120 ms; powers down afterwards |
| One-time H-resolution mode 2 | `0x21` | 0.5 lx, ≈ 120 ms; powers down afterwards |
| One-time L-resolution | `0x23` | 4 lx, ≈ 16 ms; powers down afterwards |
| Change measurement time, high bits | `01000_MT[7:5]` | `0x40` \| `(mtreg >> 5)` |
| Change measurement time, low bits | `011_MT[4:0]` | `0x60` \| `(mtreg & 0x1F)` |

The measurement-time opcodes must be sent as a pair (high bits, then low bits). The default MTreg is `0b01000101` = 69 (`0x45`); the range is 31–254.

## Initialization Sequence

1. Power up VCC and pull DVI low for ≥ 1 µs, then release (the chip starts in power-down mode).
2. Write power on (`0x01`) — optional (a measurement opcode also powers the chip on).
3. Optionally write reset (`0x07`) to clear a previous result, and the MTreg pair.
4. Write a measurement opcode (e.g. `0x20`), wait for the measurement time (max. 180 ms for H-resolution at the default MTreg), read two bytes.

## Implementation Stages

### Minimal

Goal: read the illuminance in lux with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Stores the plain `Connection`; writes power on (`0x01`) |
| `read` | — | float | Illuminance in lux: one-time H-resolution measurement (`0x20`), waits 180 ms, reads 2 bytes, returns `raw / 1.2` |

**Sensible defaults:** one-time H-resolution mode (1 lx), MTreg = 69 (default), power-down between measurements (the chip powers down automatically).

### Full

Goal: complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `read_raw` | — | int | 16-bit raw count of one one-time measurement in the current mode |
| `measure_once` | `mode: int = MODE_H` | float | One-time measurement in `MODE_H` (1 lx), `MODE_H2` (0.5 lx) or `MODE_L` (4 lx); waits `measurement_time()`; returns lux |
| `start_continuous` | `mode: int = MODE_H` | — | Starts continuous measurements (`0x10`, `0x11` or `0x13`) |
| `read_continuous` | — | float | Latest result of continuous mode in lux (no wait); the first result is available after the measurement time |
| `power_down` / `power_on` | — | — | `0x00` / `0x01` |
| `reset` | — | — | `0x07` (powers on first, as the command is not accepted in power-down) |
| `set_measurement_time` | `mtreg: int` (31–254) | — | Writes the high/low MTreg opcode pair; raises outside 31–254 |
| `get_measurement_time_register` | — | int | The last written MTreg (cached; the chip has no read-back; default 69) |
| `set_sensitivity` | `factor: float` | — | Convenience: `mtreg = round(69 × factor)` (factor 0.45 … 3.68 per the datasheet's range) |
| `measurement_time` | `mode: int = MODE_H` | float | Seconds: maximum measurement time for the mode and MTreg (`180 ms` / `24 ms` × `mtreg / 69`) |
| `lux_per_count` | `mode: int = MODE_H` | float | `1 / 1.2 × (69 / mtreg)` (halved for `MODE_H2`) |

**Mode constants:** `MODE_H` (1 lx), `MODE_H2` (0.5 lx), `MODE_L` (4 lx).

**Additional configuration options:** measurement mode, continuous vs. one-time, measurement-time register (sensitivity), power state.

## Data Conversion

```
raw = (high << 8) | low                     # 16-bit unsigned

# default MTreg = 69
lux = raw / 1.2                             # H-resolution mode and L-resolution mode
lux = raw / 1.2 / 2                         # H-resolution mode 2 (0.5 lx steps)

# with another MTreg (31 ... 254)
lux = raw / 1.2 * (69 / mtreg)              # H and L mode
lux = raw / 1.2 * (69 / mtreg) / 2          # H mode 2

measurement_time_s = nominal_time_s * mtreg / 69
```

Datasheet examples: `0x8342` (33602) → 28 001 lx at the default MTreg (the datasheet text rounds to about 28 067); `0x0012` → 15 lx in H mode / 7.5 lx in H mode 2. A larger MTreg raises the sensitivity (range down to ≈ 0.11 lx in H mode 2), a smaller one extends the maximum range (≈ 100 000 lx); a sensitivity change by a factor `x` changes the measurement time by the same factor.

## Timing Constraints

| Constraint | Value |
|------------|-------|
| H-resolution / H-resolution mode 2 measurement | 120 ms typ., 180 ms max at MTreg = 69 |
| L-resolution measurement | 16 ms typ., 24 ms max at MTreg = 69 |
| Scaling with MTreg | time × `MTreg / 69` |
| DVI reset pulse | ≥ 1 µs low after VCC (reset section) |
| I²C clock | ≤ 400 kHz |

There is no bus-decodable end-of-conversion event (no status register or interrupt; the host waits and then reads), so `bh1750_timing.conf` defines no checks.

## Implementation Notes

- **Plain Connection, command protocol:** there is no register pointer; opcodes are written with `write`, the result is read with a 2-byte `read`. Do not use a register-addressed connection.
- **One opcode per transaction:** each opcode needs its own START … STOP; the MTreg pair is two separate transactions.
- **Wait the full measurement time:** a read before the measurement has completed returns the previous result (or 0 after power-on/reset). The driver waits the datasheet maximum (180 ms / 24 ms, scaled with MTreg).
- **One-time modes power down automatically** after the measurement; re-send the opcode for the next result. A read after power-down returns the last result.
- **Reset only clears the data register,** not MTreg or the mode, and is ignored in power-down; the driver powers on first.
- **MTreg has no read-back:** keep the value in the driver; a hardware reset (DVI low) or power cycle returns it to 69.
- **Dark readings:** use H-resolution or H-resolution mode 2 for values below 10 lx; L mode has a dark offset of up to 3 counts.
- **Optical window:** a cover glass attenuates the light; compensate by raising MTreg (datasheet's adjust-measurement-result note) rather than scaling the lux afterwards, to keep the resolution.
- **DVI sequencing:** DVI must rise after VCC with ≥ 1 µs of low; otherwise ADDR/SDA/SCL may be unstable (use ≈ 100 kΩ on ADDR in that case). Breakout boards normally handle this.
- **Address overlap:** `0x5C` is shared with the LPS22HB/LPS33HW (`0x5C`–`0x5D`); `0x23` has no other supported chip in this repo. Probe the BH1750 only with `active=True` (every written byte is an opcode).

## Sigrok Decoder

Decoder id `bh1750`, input `['i2c']`. Matches I²C addresses `0x23` and `0x5C`. Annotates each opcode (power down/on, reset, continuous and one-time modes, MTreg high/low bits with the assembled MTreg value), decodes 2-byte reads into the raw count and lux using the last seen mode and MTreg, and warns on undocumented opcodes, a reset in power-down state and a read directly after a measurement opcode within the minimum measurement time. No conformance annotation pair is emitted (no checked timing constraint).
