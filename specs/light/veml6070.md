# Chip Spec: VEML6070

**Manufacturer:** Vishay Semiconductors  
**Datasheet:** `datasheets/light/veml6070.pdf` (VEML6070 UVA Light Sensor with I²C Interface, Vishay Semiconductors, document 84277)  
**Category:** light  
**Transports:** I²C

## Overview

The VEML6070 is a UVA light sensor (peak sensitivity 355 nm, spectral range 320–410 nm) with a 16-bit digital output and a refresh time set by an external resistor `RSET` and the integration-time bits (½T, 1T, 2T, 4T). It has built-in temperature compensation, flicker immunity, a software shutdown mode and an open-drain `ACK` output that asserts when the measured value exceeds a programmable threshold (102 or 145 steps), released through the I²C Alert Response Address. The interface is unusual: **one 8-bit command register** written at one address and a **16-bit result read as two bytes from two different addresses**, no register pointers. Supply 2.7–5.5 V (I²C bus 1.7–5.5 V), about 100 µA operating, 1 µA shutdown. Typical uses: solar UV exposure and UV-index measurement in handheld and wearable devices.

## Transport Configuration

### I²C
- **Addresses (7-bit):** `0x38` for the command write **and** the low byte (LSB) read; `0x39` for the high byte (MSB) read. `0x39` must not be used for a write. The Alert Response Address `0x18` is read to release `ACK`
- **Max clock:** standard I²C, 100 kHz (the datasheet gives 4.7 µs bus-free time and 25–35 ms clock/data low timeout)
- **Identity register:** none; chip has no ID register (feeds `registry/chips.json` with `id_probe: null`)
- **Probe safety:** `write_sensitive` — the chip has no register pointer: any byte written to `0x38` is interpreted as the command register. A probe may only read a byte (`0x38`/`0x39`); a read from `0x39` or `0x38` has no side effect
- **Register addressing:** none — the command is a single byte written to `0x38`; the result is two separate one-byte reads (`0x39` = MSB, then `0x38` = LSB). The driver takes **two plain `Connection`s** (command/LSB at `0x38`, MSB at `0x39`) on the same bus, the same two-connection pattern as `LSM303`

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| ACK | low, open-drain | asserted when the UV value exceeds the `ACK_THD` threshold; released by an Alert Response Address read (`0x18`) — requires external pull-up |
| RSET | — | external resistor to ground sets the refresh time (e.g. 240 kΩ = 100 ms/1T, 300 kΩ = 125 ms, 600 kΩ = 250 ms) |
| SDA, SCL | — | I²C, external pull-ups (2.2 kΩ) |
| VDD, GND | — | 2.7–5.5 V |

## Register Map

The only writable register is the 8-bit command register:

| Bit | Name | Description |
|-----|------|-------------|
| 7:6 | — | Reserved, write 0 |
| 5 | ACK | 1 = acknowledge (alert) activity enabled |
| 4 | ACK_THD | 0 = threshold 102 steps, 1 = 145 steps |
| 3:2 | IT | Integration time: `00` ½T, `01` 1T, `10` 2T, `11` 4T |
| 1 | — | Reserved, write 1 |
| 0 | SD | 1 = shutdown mode enabled |

Reads: address `0x39` returns bits 15:8, address `0x38` returns bits 7:0 of the 16-bit UV value. The datasheet's initialisation writes `0x06` (1T, shutdown off, ACK off) after clearing the ACK state.

## Initialization Sequence

1. Power VDD (2.7–5.5 V); initialise within 150 ms of power-on.
2. Read the Alert Response Address (`0x18`, 1 byte) to clear any ACK state.
3. Write the command `0x06` (1T, ACK disabled, running) to `0x38`.
4. Wait the refresh time (e.g. 125 ms at 1T with `RSET` = 300 kΩ); read the MSB from `0x39`, then the LSB from `0x38`; value = `MSB << 8 | LSB`.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `ACK`, active-low, open-drain — requires external pull-up |
| Level | 1 |
| Condition(s) | UV value above 102 or 145 steps (`ACK_THD`) with `ACK` = 1 |
| Clear mechanism | read the Alert Response Address `0x18` (returns the sensor's address), or read it before every other access |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback)` | Subscribe; callback receives 1 when the sensor responded to the ARA |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Reads the ARA (a `Connection` at address `0x18` supplied by the caller) and returns 1 if the VEML6070 answered, 0 otherwise |
| `enable_interrupt` | `enable_interrupt(threshold_steps: int = 102)` | Sets `ACK` (and `ACK_THD` for 145) |
| `disable_interrupt` | `disable_interrupt()` | Clears `ACK` |

`poll_interrupt` needs the ARA connection; if the host does not provide one, the driver raises `Unsupported` and the user watches the `ACK` pin as a GPIO instead.

## Implementation Stages

### Minimal

Goal: read the UVA value with one call, no configuration beyond the connections.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` (`0x38`), `connection_msb` (`0x39`) | — | Writes `0x06` (1T, running, ACK off) to `0x38` |
| `read_uva` | — | int | Reads the MSB from `0x39` then the LSB from `0x38`; 16-bit UV steps. The caller waits at least the refresh time between samples (the driver does not block) |

**Sensible defaults:** integration time 1T, shutdown off, ACK off.

### Full

Goal: complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `read_irradiance` | `rset_kohm: float = 300` | float | UVA irradiance in W/m² from the step count (see Data Conversion) |
| `set_integration_time` / `get_integration_time` | `factor: float` (0.5, 1, 2, 4) / — | — / float | `IT` |
| `refresh_time` | `rset_kohm: float` | float | Seconds for the current `IT` and `RSET` |
| `shutdown` / `wake` | — | — | `SD` |
| `set_ack` | `enabled: bool, threshold_steps: int = 102` | — | `ACK`, `ACK_THD` (102 or 145) |
| `command` | — | int | Last written command byte (kept in the driver; the chip has no read-back) |
| `on_interrupt` / `off_interrupt` / `poll_interrupt` / `enable_interrupt` / `disable_interrupt` | see Interrupt | | |

**Additional configuration options:** integration time, shutdown, ACK threshold.

## Data Conversion

```
uv_steps = msb << 8 | lsb                            # 16 bit
refresh_time_ms = RSET_kohm / 2.4 * IT_factor       # 1T = RSET/2.4 ms: 240k -> 100 ms, 300k -> 125 ms, 600k -> 250 ms
# datasheet sensitivity: 5 uW/cm^2 per step at RSET = 240 kohm, IT = 1T  (= 0.05 W/m^2 per step)
irradiance_w_m2 = uv_steps * 0.05 * (100 / refresh_time_ms)
```

The datasheet gives the sensitivity only for `RSET` = 240 kΩ, 1T (maximum detection 328 mW/cm² at that setting, dark offset 0–5 steps, output offset about 2 steps at 500 lx); the scaling with the refresh time (steps proportional to the integration time) is inferred from the datasheet's refresh-time table and must be confirmed on hardware. The UV index requires an application-specific calibration (the datasheet defines none).

## Timing Constraints

| Constraint | Value |
|------------|-------|
| Initialisation after power-on | ≤ 150 ms |
| Refresh time | ½T/1T/2T/4T = 62.5/125/250/500 ms at `RSET` = 300 kΩ (twice that at 600 kΩ) |
| Bus free time / clock-low timeout | ≥ 4.7 µs / 25–35 ms |
| I²C clock | ≤ 100 kHz |

The refresh time depends on an external resistor, so there is no fixed datasheet bound to check; `veml6070_timing.conf` defines no checks.

## Implementation Notes

- **Plain Connections, no register file:** use `connection.write(data)` / `connection.read(1)`; there is no register pointer, so a `RegisterConnection` does not fit. The two addresses need two connection objects on the same bus.
- **Read order:** read the MSB (`0x39`) first, then the LSB (`0x38`), as in the datasheet.
- **No read-back:** the command register cannot be read; the driver keeps a shadow copy of the last written byte and always writes bit 1 = 1 and bits 7:6 = 0.
- **Pin-level ACK:** after an ACK the chip keeps the line low until the ARA is read; a host without ARA support must read `0x18` before each access or leave `ACK` disabled (`0x06`).
- **Soft shutdown:** `SD` = 1 puts the chip in 1 µA shutdown; wake it by writing the command with `SD` = 0 and wait one refresh time before reading.
- **RSET:** the refresh time depends on the board's `RSET`; the driver cannot measure it, so `RSET` is a constructor/helper parameter for the conversions.
- **Addresses:** `0x38`/`0x39` are also used by other chips (PCF8574A family, FT6x06 touch controllers); no ID register exists, so a probe cannot identify the chip.

## Sigrok Decoder

Decoder id `veml6070`, input `['i2c']`. Matches the I²C addresses `0x38` and `0x39` and the Alert Response Address `0x18`. Decodes every written command byte into its fields (`ACK`, `ACK_THD`, `IT`, `SD`), combines an MSB read from `0x39` with the following LSB read from `0x38` into a 16-bit UV value, and annotates ARA reads; warns on a write to `0x39`, on a command with reserved bits other than `0x06` pattern (bits 7:6 ≠ 0 or bit 1 = 0) and on a missing MSB/LSB pair. No conformance annotation pair is emitted (no checked timing constraint).
