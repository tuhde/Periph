# Chip Spec: TSL2561

**Manufacturer:** TAOS / ams (ams OSRAM)  
**Datasheet:** `datasheets/light/tsl2561.pdf` (TSL2560, TSL2561 Light-to-Digital Converter, TAOS059N, March 2009)  
**Category:** light  
**Transports:** I²C (the TSL2560, same silicon with an SMBus interface, is the other part of this datasheet)

## Overview

The TSL2561 is a second-generation ambient light sensor with two integrating ADCs fed by two photodiodes: **channel 0** responds to visible and infrared light, **channel 1** mainly to infrared. The two 16-bit counts are combined with an empirical formula into **lux** that approximates the human eye response (it removes the infrared error of silicon detectors). Gain is selectable (1× or 16×), the integration time 13.7 ms, 101 ms or 402 ms (or manual timing), and a programmable **interrupt** (level or SMBAlert style, persistence of 0–15 integration cycles, 16-bit low/high thresholds on channel 0) simplifies polling. Supply 2.7–3.6 V, I²C up to 400 kHz, three addresses via the ADDR SEL pin. The TSL2560 is the SMBus variant (ID `PARTNO = 0000`) and is not covered.

## Transport Configuration

### I²C
- **Address:** `0x29` (ADDR SEL = GND), `0x39` (ADDR SEL floating), `0x49` (ADDR SEL = VDD); 7-bit; the SMBus Alert Response Address is `0x0C`
- **Max clock:** 400 kHz (I²C fast mode)
- **Identity register:** `ID` (`0x0A`, command byte `0x8A`): `PARTNO` in bits 7:4 = `0001` for the TSL2561 (`0000` = TSL2560), `REVNO` in bits 3:0 varies: mask `0xF0`, expected `0x10`; feeds `registry/chips.json`
- **Probe safety:** `register_pointer` — a 1-byte write sends the command (register select) byte only
- **Command byte:** every register access starts with a **command byte**: `CMD(7)=1 | CLEAR(6) | WORD(5) | BLOCK(4) | ADDRESS(3:0)`. `CLEAR` = 1 clears a pending interrupt (self-clearing, write-one-to-clear); `WORD` = 1 selects word transfers (low byte at the address, high byte at address + 1); `BLOCK` = 1 selects block transfers (continue until STOP). The register address is the lower four bits. Read = write command byte, repeated START, read; the drivers use `RegisterConnection` (`reg_bytes = 1`) with the command byte as the "register": `connection.read(0x80 | addr, n)` / `connection.write(0x80 | addr, data)`; word access uses `0xA0 | addr`, I²C block read of the four ADC bytes uses `0x9C`

## Register Map

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x0` | CONTROL | R/W | `0x00` | Power: write `0x03` = on, `0x00` = off (reads `0x03` when on) |
| `0x1` | TIMING | R/W | `0x02` | Gain, manual timing, integration time |
| `0x2` | THRESHLOWLOW | R/W | `0x00` | Low interrupt threshold, low byte |
| `0x3` | THRESHLOWHIGH | R/W | `0x00` | Low interrupt threshold, high byte |
| `0x4` | THRESHHIGHLOW | R/W | `0x00` | High interrupt threshold, low byte |
| `0x5` | THRESHHIGHHIGH | R/W | `0x00` | High interrupt threshold, high byte |
| `0x6` | INTERRUPT | R/W | `0x00` | Interrupt mode and persistence |
| `0x8` | CRC | — | — | Factory test, not a user register |
| `0xA` | ID | R | — | Part number / revision |
| `0xC`–`0xD` | DATA0LOW/HIGH | R | `0x00` | Channel 0 ADC (visible + IR) |
| `0xE`–`0xF` | DATA1LOW/HIGH | R | `0x00` | Channel 1 ADC (IR) |

Addresses `0x7`, `0x9`, `0xB` are reserved.

### Bit Fields

#### `CONTROL` (`0x0`)

Bits 1:0 `POWER`: `11` = powered up (starts integrating), `00` = powered down. Bits 7:2 reserved (write 0).

#### `TIMING` (`0x1`) — reset `0x02` (1× gain, 402 ms)

| Bits | Name | Description |
|------|------|-------------|
| 4 | GAIN | `0` = low gain (1×), `1` = high gain (16×) |
| 3 | MANUAL | With `INTEG = 11`: `1` starts, `0` stops an integration cycle |
| 1:0 | INTEG | `00` = 13.7 ms (scale 0.034), `01` = 101 ms (0.252), `10` = 402 ms (1.0), `11` = manual |

#### `INTERRUPT` (`0x6`)

| Bits | Name | Description |
|------|------|-------------|
| 5:4 | INTR | `00` disabled, `01` level interrupt, `10` SMBAlert style, `11` test mode (sets the interrupt, behaves as mode `10`) |
| 3:0 | PERSIST | `0000` = every ADC cycle, `0001` = any value outside the window, `N` (2–15) = N consecutive cycles outside the window |

The interrupt is based on **channel 0 only**: it asserts (INT low) when channel 0 is below or equal to the low threshold or above the high threshold (for `PERSIST` cycles); it stays asserted until cleared by a command byte with `CLEAR` = 1 (level mode) or an Alert Response read (SMBAlert mode).

## Initialization Sequence

1. Power-up: the command, timing and control registers hold their defaults (powered down, 1× gain, 402 ms).
2. Write `CONTROL` ← `0x03` (read back to verify: it returns `0x03` when the chip is communicating and powered).
3. Write `TIMING` ← `GAIN<<4 | INTEG` (the driver default is 1× gain, 402 ms = `0x02`).
4. Wait one integration time (≥ 402 ms nominal at the default; 13.7 / 101 ms otherwise) plus margin before the first valid read; the first conversion completes after the first full integration.
5. Read the four data bytes (block read `0x9C`, 4 bytes: DATA0LOW, DATA0HIGH, DATA1LOW, DATA1HIGH).

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `INT`, active-low, open-drain — requires an external pull-up |
| Level | 1 (single fixed condition: channel 0 outside the threshold window) |
| Condition | Channel 0 ≤ low threshold or > high threshold for `PERSIST` integration cycles |
| Clear mechanism | Write a command byte with `CLEAR` = 1 (level mode), or an SMBus Alert Response read of address `0x0C` (SMBAlert mode); there is no status register |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on INT (falling edge) via `connection.int_pin` (or `int_pin`), otherwise a polling task (one integration time) calling `poll_interrupt`; `callback(channel0)` receives the current channel-0 count |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> bool` | Read channel 0 and return `True` if it lies outside the programmed window (the persistence filter is not modelled); does not clear the chip's interrupt |
| `clear_interrupt` | `clear_interrupt()` | Send the command byte `0xC0` (`CMD` + `CLEAR`) — releases a level interrupt |

## Implementation Stages

### Minimal

Goal: read the illuminance in lux with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Runs the Initialization Sequence (power up, 1× gain, 402 ms) and waits for the first integration |

**Sensible defaults:** 1× gain, 402 ms integration (best resolution and flicker averaging; range ≈ 0–30 000 lx, the high gain is for dim light), T/FN/CL package lux formula, interrupt disabled.

## Data Conversion

```
ch0 = DATA0HIGH << 8 | DATA0LOW       ch1 = DATA1HIGH << 8 | DATA1LOW        # channel 0 visible+IR, channel 1 IR
scale (integration):  13.7 ms: 0.034   101 ms: 0.252   402 ms: 1.0          # nominal Tint = clock cycles / fosc (735 kHz typ.)
normalised counts   :  ch0n = ch0 / scale * (16 / gain)    ch1n = ch1 / scale * (16 / gain)      # the datasheet formula assumes 402 ms and 16x
ratio r = ch1n / ch0n

T, FN, CL package:                                    CS package:
  0    < r <= 0.50 : lux = 0.0304*ch0n - 0.062*ch0n*r^1.4         0    < r <= 0.52 : lux = 0.0315*ch0n - 0.0593*ch0n*r^1.4
  0.50 < r <= 0.61 : lux = 0.0224*ch0n - 0.031*ch1n               0.52 < r <= 0.65 : lux = 0.0229*ch0n - 0.0291*ch1n
  0.61 < r <= 0.80 : lux = 0.0128*ch0n - 0.0153*ch1n              0.65 < r <= 0.80 : lux = 0.0157*ch0n - 0.0180*ch1n
  0.80 < r <= 1.30 : lux = 0.00146*ch0n - 0.00112*ch1n            0.80 < r <= 1.30 : lux = 0.00338*ch0n - 0.00260*ch1n
  r > 1.30         : lux = 0                                      r > 1.30         : lux = 0
```

The datasheet's reference code (`CalculateLux`) does the same scaling in fixed point. Full-scale count limits: 5047 (13.7 ms), 37177 (101 ms), 65535 (402 ms) — a channel at or above its limit is saturated and the lux result is invalid (the driver raises, `auto_range` steps down). The coefficients apply to open-air operation only (light pipes change the incident light).

## Timing Constraints

- **Integration time:** nominal 13.7 ms / 101 ms / 402 ms (`INTEG` 00 / 01 / 10), derived from the internal oscillator (690–780 kHz around 735 kHz typ. → about ±6 %); both channels integrate simultaneously and a new cycle starts automatically after the data transfer. The decoder marks the `CONTROL` write that powers the device up as `conversion_start` and the first ADC data register read as `conversion_done`; `specs/light/tsl2561_timing.conf` checks ≥ 378 ms (402 ms − 6 %) at the driver's default setting.
- **After changing gain or integration time:** wait one full new integration cycle before trusting the data (the in-progress conversion uses the old settings).
- **Interrupt persistence:** `PERSIST` integration cycles (e.g. 10 × 402 ms ≈ 4 s).
- **I²C:** 400 kHz max — a clock-rate property, not an event-to-event delay.

## Implementation Notes

- **Command byte is the register address:** `0x80 | addr` for bytes, `0xA0 | addr` for words (low byte first), `0x9C` for the 4-byte I²C block read of the data registers; word writes must be used for the threshold pairs (a Send Byte with the MSB set would be taken as a command).
- **Read both channels in one transaction** so the pair belongs to one integration (the data registers are double-buffered; reading ch0 then ch1 in separate transactions can straddle an update).
- **Power-down:** `CONTROL` = `0x00` stops everything; the registers keep their values. Writing `0x03` powers up and restarts integration; reading `CONTROL` back as `0x03` verifies the bus connection.
- **Gain vs range:** 16× saturates indoors at about 1–2 klux (counts/lux 36 fluorescent / 144 incandescent at 402 ms), 1× extends the range ~16×; use `auto_range` for scenes with wide dynamic range.
- **Manual timing** (`INTEG` = 11) lets the host synchronise with an external light source (LED): start with `MANUAL` = 1, stop with 0, then read.
- **Package matters:** the CS package has its own coefficients; the Minimal driver assumes T/FN/CL (the common breakout boards).
- **Datasheet:** TAOS059N (March 2009), downloaded from `https://cdn-shop.adafruit.com/datasheets/TSL2561.pdf`.

## Sigrok Decoder

Decoder id `tsl2561`, input `['i2c']`. Matches the addresses `0x29`, `0x39` and `0x49`. Decodes the command byte (CMD, CLEAR, WORD, BLOCK, register name), and the register data: CONTROL power state, TIMING gain/manual/integration time, INTERRUPT mode and persistence, thresholds as 16-bit values, ID part number/revision, and the ADC data (CH0, CH1 counts and the lux for the default gain/integration of the last TIMING write seen, T/FN/CL coefficients); warns on writes with the CMD bit clear, on word writes to non-paired registers and on `CLEAR`-bit commands. Timing annotations in the `timing` row (variable-length strings per `specs/sigrok_annotations.md`): `conversion_start` on a CONTROL write of `0x03` and `conversion_done` on the first following read of a data register (`0x0C`–`0x0F`).
