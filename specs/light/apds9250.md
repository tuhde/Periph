# Chip Spec: APDS-9250

**Manufacturer:** Broadcom  
**Datasheet:** `datasheets/light/apds9250.pdf` (APDS-9250-DS101, May 24, 2021)  
**Category:** light  
**Transports:** I²C

## Overview

The APDS-9250 is a digital RGB, IR and ambient-light (ALS) sensor with four simultaneously integrating photodiode channels (red, green, blue, IR; the green channel doubles as the ALS channel), 13- to 20-bit ADC resolution, a dynamic range of 18 000 000 : 1, five selectable gains (×1, ×3, ×6, ×9, ×18) and a programmable measurement rate of 25 ms to 2 s. Results are unsigned counts in 3-byte registers. A threshold or variation interrupt on any one of four channels with a programmable persistence (1–16 events) drives the open-drain `INT` pin. The device has one function mode switch: ALS/IR (green + IR only) or colour-sensing (CS, all four channels). Typical uses: display and lighting colour matching, ambient-light brightness control, colour sampling and IR/ambient discrimination. Supply 1.7–3.6 V (3.8 V absolute maximum), 130 µA active at 2.8 V, I²C up to 400 kHz.

## Transport Configuration

### I²C
- **Address:** `0x52` (7-bit, fixed; "contact the factory for other addressing options")
- **Max clock:** 400 kHz (Fast-mode)
- **Identity register:** `0x06` (`PART_ID`) = `0xB5` — upper nibble `0xB` is the part number, lower nibble `0x5` the revision; the probe masks `0xF0` and expects `0xB0`. Registered in `registry/chips.json`
- **Probe safety:** `register_pointer` — plain register-addressed reads; reading `MAIN_STATUS` (`0x07`) clears the status flags, so a probe should read only `PART_ID`
- **Register addressing:** 8-bit register address, auto-increment on block read/write, reserved registers are skipped and the address counter does not roll over at the end; access to a non-readable/non-writable register is NACKed. While a read is active in `0x07`–`0x18` the data registers are locked so a multi-byte read is consistent

### Bit Fields

#### `MAIN_CTRL` (`0x00`)

| Bits | Name | Description |
|------|------|-------------|
| 4 | SW_RESET | 1 = trigger a software reset (all registers to defaults) |
| 2 | CS_MODE | 0 = ALS/IR mode (green + IR active), 1 = CS mode (R, G, B, IR active) |
| 1 | LS_EN | 0 = standby, 1 = light sensor active |

#### `LS_MEAS_RATE` (`0x04`)

| Bits | Name | Description |
|------|------|-------------|
| 6:4 | LS_RESOLUTION | `000` 20 bit (400 ms), `001` 19 bit (200 ms), `010` 18 bit (100 ms, default), `011` 17 bit (50 ms), `100` 16 bit (25 ms), `101` 13 bit (3.125 ms); `110`/`111` reserved |
| 2:0 | LS_MEAS_RATE | `000` 25 ms, `001` 50 ms, `010` 100 ms (default), `011` 200 ms, `100` 500 ms, `101` 1000 ms, `110`/`111` 2000 ms |

If the rate is faster than the integration time allows, the measurement runs at the maximum possible speed. Writing this register restarts the measurement.

#### `LS_GAIN` (`0x05`)

| Bits | Name | Description |
|------|------|-------------|
| 2:0 | LS_GAIN | `000` ×1, `001` ×3 (default), `010` ×6, `011` ×9, `100` ×18; all channels share the gain. Writing restarts the measurement |

#### `MAIN_STATUS` (`0x07`)

| Bits | Name | Description |
|------|------|-------------|
| 5 | POWER_ON | 1 = part went through a power-up (or supply disturbance); thresholds are back at their defaults; cleared on read |
| 4 | LS_INT | 1 = interrupt condition fulfilled; cleared on read |
| 3 | LS_DATA | 1 = new data not yet read; cleared on read |

#### `INT_CFG` (`0x19`)

| Bits | Name | Description |
|------|------|-------------|
| 5:4 | LS_INT_SEL | `00` IR, `01` green/ALS (default), `10` red, `11` blue |
| 3 | LS_VAR_MODE | 0 = threshold mode, 1 = variation mode |
| 2 | LS_INT_EN | 1 = LS interrupt enabled |

#### `INT_PERSISTENCE` (`0x1A`)

| Bits | Name | Description |
|------|------|-------------|
| 7:4 | LS_PERSIST | `0` = every out-of-range value asserts the interrupt; `n` = n + 1 consecutive values (up to 16) |

#### `LS_THRES_VAR` (`0x27`)

| Bits | Name | Description |
|------|------|-------------|
| 2:0 | LS_THRES_VAR | Variation (|current − previous|) that triggers the variation interrupt: `000` 8 counts, `001` 16, `010` 32, `011` 64, … `111` 1024 counts (8 << n) |

## Initialization Sequence

1. Power up VDD; the device loads its I²C address and trim values from NVM (it NACKs every access until then; allow ≈ 1 ms) and enters standby.
2. Read `PART_ID` (`0x06`) and check the upper nibble is `0xB`.
3. Optionally write `MAIN_CTRL` = `0x10` (software reset) and wait for it to complete.
4. Write `LS_MEAS_RATE`, `LS_GAIN` (defaults: 18 bit/100 ms, ×3).
5. Write `MAIN_CTRL` with `LS_EN` = 1 (and `CS_MODE` = 1 for all four colour channels); the support blocks settle in about 5 ms, then the first conversion runs for the integration time.
6. Poll `MAIN_STATUS.LS_DATA` (or wait for `INT`), then block-read `0x0A`–`0x15` (12 bytes, one consistent set).

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | active-low, open-drain — requires external pull-up |
| Level | 2 |
| Condition(s) | threshold: the selected channel is above `LS_THRES_UP` or below `LS_THRES_LOW`; variation: the channel changed by more than `LS_THRES_VAR` between two results; both for `LS_PERSIST` + 1 consecutive measurements |
| Clear mechanism | read `MAIN_STATUS` (`0x07`) |

### Interrupt sources

| Constant | Value | Condition |
|----------|-------|-----------|
| `SOURCE_THRESHOLD` | `0x01` | Selected channel outside the threshold window (`LS_VAR_MODE` = 0) |
| `SOURCE_VARIATION` | `0x02` | Selected channel changed by more than the variance threshold (`LS_VAR_MODE` = 1) |

The two sources are mutually exclusive (one `LS_VAR_MODE` bit); `enable_interrupt(source)` selects the mode and sets `LS_INT_EN`.

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback)` | Subscribe; callback receives the `MAIN_STATUS` byte |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Read `MAIN_STATUS` (clears the flags) and return it |
| `enable_interrupt` | `enable_interrupt(source)` | Select threshold/variation mode and enable the interrupt |
| `disable_interrupt` | `disable_interrupt(source)` | Clear `LS_INT_EN` |

### Status register bit layout

| Bit | Constant | Meaning |
|-----|----------|---------|
| 5 | `STATUS_POWER_ON` | Power-up event occurred |
| 4 | `STATUS_INTERRUPT` | Interrupt condition fulfilled |
| 3 | `STATUS_DATA_READY` | New data available |

## Implementation Stages

### Minimal

Goal: read the four channels with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Takes the `RegisterConnection`; reads `PART_ID` (upper nibble must be `0xB`), starts the sensor in CS mode with the chip defaults (18 bit/100 ms, rate 100 ms, gain ×3) |
| `read` | — | `{red, green, blue, ir}` | Waits for `LS_DATA` (up to the integration time plus margin), block-reads `0x0A`–`0x15`, returns the four counts (unsigned integers) |

**Sensible defaults:** `MAIN_CTRL` = `0x06` (`LS_EN`, `CS_MODE`), `LS_MEAS_RATE` = `0x22`, `LS_GAIN` = `0x01`, interrupt disabled.

### Full

Goal: complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `read_red` / `read_green` / `read_blue` / `read_ir` | — | int | One channel (3-byte read) |
| `read_channels` | — | `(red, green, blue, ir)` | Block read without waiting (call after `data_ready`) |
| `data_ready` | — | bool | Reads `MAIN_STATUS` and returns `LS_DATA` (clears the flags — see Implementation Notes) |
| `set_mode` | `colour: bool` | — | `CS_MODE` (False = ALS/IR only) |
| `enable` / `disable` | — | — | `LS_EN` (read-modify-write) |
| `set_resolution` | `bits: int` (13, 16, 17, 18, 19, 20) | — | `LS_RESOLUTION`; restarts the measurement |
| `set_measurement_rate` | `milliseconds: int` (25, 50, 100, 200, 500, 1000, 2000) | — | `LS_MEAS_RATE` |

**Additional configuration options:** resolution, measurement rate, gain, ALS/CS mode, interrupt channel, mode (threshold/variation), thresholds, persistence, variance threshold.

## Data Conversion

```
count(channel) = b0 | b1 << 8 | (b2 & 0x0F) << 16        # 3 bytes, LSB first, 13..20 bit LSB aligned
full_scale     = 2**resolution_bits - 1                   # e.g. 262143 at 18 bit
integration_time_s = {20:0.4, 19:0.2, 18:0.1, 17:0.05, 16:0.025, 13:0.003125}[bits]
gain           = {0:1, 1:3, 2:6, 3:9, 4:18}[LS_GAIN]
normalized     = count / (gain * integration_time_s)      # counts per gain-second
variance_counts = 8 << LS_THRES_VAR                       # 8 .. 1024
```

The datasheet specifies no lux formula: it gives the count value of 1000 for the ALS channel at 530 nm, 50 ms integration and gain ×3 with an irradiance of 0.62 W/m² (62 µW/cm²), a dark count of 0–3 counts and an integration time accuracy of 2.97–3.28 ms at 13 bit. The driver therefore reports counts; the IR channel is already temperature compensated internally. A colour/lux calibration is application specific (cover glass, light source).

## Timing Constraints

| Constraint | Value |
|------------|-------|
| Support-block settling after `LS_EN` | ≈ 5 ms |
| Integration time | 3.125 ms (13 bit), 25 / 50 / 100 / 200 / 400 ms (16–20 bit) |
| Measurement rate | 25 ms … 2 s (slower of rate and integration time wins) |
| After power-up | address/trim loaded from NVM; NACK until done |
| I²C clock | ≤ 400 kHz |

No constraint has a datasheet bound that can be checked as a bus-decodable start/end pair (the integration time is a programmable setting, completion is shown by `MAIN_STATUS.LS_DATA`), so `apds9250_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection:** register-addressed I²C — accept `RegisterConnection` and call `connection.read(reg, length)` / `connection.write(reg, data)` directly; no chip-local helpers. See `specs/feature_register_access_design.md`.
- **Read the status carefully:** reading `MAIN_STATUS` clears `POWER_ON`, `LS_INT` and `LS_DATA`. The driver reads it once per poll and keeps the interrupt bit for `poll_interrupt`; do not poll the status in the interrupt handler and the data path concurrently.
- **Block read:** read `0x0A`–`0x15` as one 12-byte transfer so all four channels come from the same conversion; the result registers are locked during a read in `0x07`–`0x18`.
- **Restart on config write:** writes to `LS_MEAS_RATE` and `LS_GAIN` stop and restart the measurement; discard the first result after a change and wait one integration time.
- **Power-up flag:** if `POWER_ON` is set after a read, the thresholds were reset to defaults and must be re-written.
- **Gain 18 and 20 bit:** a high gain with a long integration saturates in daylight; the full scale is `2**bits − 1` counts.
- **Variation mode** compares consecutive results, so it needs one result before it can fire.
- **Address:** fixed `0x52`; other addresses are only available from the factory. Confirm the chip with the `PART_ID` mask before use.

## Sigrok Decoder

Decoder id `apds9250`, input `['i2c']`. Matches I²C address `0x52`. Annotates every register access with its name, decodes `MAIN_CTRL`, `LS_MEAS_RATE` (resolution, rate), `LS_GAIN`, `PART_ID`, `MAIN_STATUS`, `INT_CFG`, `INT_PERSISTENCE`, `LS_THRES_VAR`, the 20-bit thresholds and the 3-byte channel counts (with the channel name), and shows normalised counts; warns on writes to reserved registers, on a data read without a preceding `LS_DATA` status of 1, on an interrupt enabled in variation mode with a variance of 8 counts at 13 bit, and on a mismatched `PART_ID`. No conformance annotation pair is emitted (no checked timing constraint).
