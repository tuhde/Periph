# Chip Spec: HDC1080

**Manufacturer:** Texas Instruments  
**Datasheet:** `datasheets/humidity/hdc1080.pdf` (HDC1080 datasheet, SNAS672)  
**Category:** humidity  
**Transports:** I²C

> **Note:** The HDC1080 measures relative humidity and temperature (no pressure); it is placed in `humidity` next to the DHT11 and SHTC3.

## Overview

The HDC1080 is a low-power digital humidity sensor with an integrated temperature sensor: 14-bit relative humidity and temperature results (typical accuracy ±2 %RH and ±0.2 °C), 14/11/8-bit humidity and 14/11-bit temperature resolution, 3.85–6.5 ms conversion times, an integrated **heater**, a **battery-low** flag (VDD < 2.8 V) and 100 nA sleep current. It has **one fixed address**, no address pins and **no data-ready pin**, and adds manufacturer-ID and device-ID registers. After power-up it needs at most 15 ms before it can measure (only the ID/serial registers answer meanwhile) and then sleeps until addressed. Registers are 16 bit, **MSB first**. Supply 2.7–5.5 V. It is the successor of the HDC1008 (`specs/humidity/hdc1080.md`) with the same register map and measurement protocol.

## Transport Configuration

### I²C
- **Address:** `0x40` (7-bit `1000000`, fixed — no address pins; only one HDC1080 per bus)
- **Max clock:** 400 kHz (fast mode); 100 kHz standard
- **Identity register:** `0xFF` Device ID = `0x1050` (big-endian word); `0xFE` Manufacturer ID = `0x5449` (Texas Instruments); feeds `registry/chips.json` (address `0x40` is shared with the HDC1008, whose datasheet lists no ID register, and with the ADS1x1x/INA2xx families)
- **Probe safety:** `register_pointer` — a 1-byte write sets the pointer; writing pointer `0x00`/`0x01` also **triggers a measurement** (harmless, sleep mode returns afterwards)
- **Register addressing:** 1-byte pointer; reads return 16-bit MSB-first words; the pointer persists. A measurement is **triggered by a pointer write** to `0x00` (temperature, or temperature + humidity in sequence mode) or `0x01` (humidity), and the result is read in a *separate* transaction (read header) once ready — the read header is NACKed while the data are not ready. The drivers use the plain `Connection` (`write(pointer)` / `read(n)`), not a repeated-START register read

## Register Map

| Pointer | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | Temperature | R | `0x0000` | 14-bit temperature (bits 15:2), bits 1:0 = 0; write-pointer triggers a measurement |
| `0x01` | Humidity | R | `0x0000` | 14-bit humidity (bits 15:2), bits 1:0 = 0; write-pointer triggers a measurement |
| `0x02` | Configuration | R/W | `0x1000` | Reset, heater, mode, resolution, battery status |
| `0xFB` | Serial ID | R | device | Serial ID bits 39:24 |
| `0xFC` | Serial ID | R | device | Serial ID bits 23:8 |
| `0xFD` | Serial ID | R | device | Serial ID bits 7:0 in bits 15:7 (bits 6:0 = 0) |
| `0xFE` | Manufacturer ID | R | `0x5449` | Texas Instruments |
| `0xFF` | Device ID | R | `0x1050` | HDC1080 |

Registers `0x03`–`0xFA` are reserved. The pointer resets to `0x00`. Writing a read-only register is NACKed after each data byte; access to an unused address is NACKed after the pointer.

### Bit Fields

#### `Configuration` (`0x02`) — reset `0x1000`

| Bits | Name | Description |
|------|------|-------------|
| 15 | RST | `1` = software reset (self-clears) |
| 14 | — | Reserved, write 0 |
| 13 | HEAT | `1` = heater enabled (runs only during measurements) |
| 12 | MODE | `0` = temperature **or** humidity acquired (per the trigger pointer), `1` = temperature and humidity acquired in sequence (temperature first) |
| 11 | BTST | Read only: `1` = battery (VDD) below 2.8 V |
| 10 | TRES | Temperature resolution: `0` = 14 bit, `1` = 11 bit |
| 9:8 | HRES | Humidity resolution: `00` = 14 bit, `01` = 11 bit, `10` = 8 bit |
| 7:0 | — | Reserved, write 0 |

Note the reset value `0x1000` has MODE = 1 (sequence mode, 14-bit) already set.

## Initialization Sequence

1. Power-up: wait ≥ 15 ms (the sensor needs at most 15 ms before it can measure; only the serial/ID registers answer meanwhile); the chip then sleeps and waits for I²C input; BTST is updated after POR.
2. `init` writes `Configuration` ← `0x1000` (MODE = 1, 14-bit T and RH, heater off) so the state is known.
3. A measurement (sequence mode): write pointer `0x00`; wait for the conversion (typically ≈ 13 ms for both at 14 bit; there is no DRDYn pin, so wait and retry the read header); read 4 bytes: temperature word, then humidity word, in one transaction.

## Implementation Stages

### Minimal

Goal: read temperature and humidity with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Writes the configuration `0x1000` (14-bit, sequence mode, heater off) |
| `read` | — | `{temperature_c, humidity_pct}` | Triggers a sequence measurement (pointer `0x00`), waits 15 ms, reads 4 bytes (retrying the read header until it is ACKed, timeout 50 ms), converts |

**Sensible defaults:** 14-bit temperature and humidity, sequence mode (temperature first), heater off, 15 ms wait before the first read attempt.

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |

**Additional configuration options:** temperature/humidity resolution, heater, single vs sequence mode (selected implicitly by `read_temperature`/`read_humidity` vs `read`).

## Data Conversion

```
raw_t = (msb << 8) | lsb              # bits 15:2 are the 14-bit value, bits 1:0 are 0
temperature_c = raw_t / 65536 * 165 - 40
raw_h = (msb << 8) | lsb
humidity_pct  = raw_h / 65536 * 100
serial_id = (word(0xFB) << 24) | (word(0xFC) << 8) | (word(0xFD) >> 7)        # 40 bits
```

The result is always a 14-bit value in the register; the selected resolution only affects the conversion time/accuracy (the low bits of the 11/8-bit results are just less precise). Example: `0x6666` → 26.0 °C (T), `0x8000` → 50 %RH.

## Timing Constraints

- **Conversion time (typical):** humidity 2.50 ms (8 bit), 3.85 ms (11 bit), 6.50 ms (14 bit); temperature 3.65 ms (11 bit), 6.35 ms (14 bit); in sequence mode the two add up (≈ 12.85 ms at 14/14 bit). The read header is NACKed until the result is ready (no DRDYn pin).
- **Power-up:** ≤ 15 ms until the first measurement can start.
- **Sleep:** 100–200 nA between measurements; the chip returns to sleep after each measurement.
- **Abort:** a pointer write to `0x00`/`0x01` while a measurement is running aborts it; reading the output registers during a measurement does not disturb it.
- **I²C:** 100 / 400 kHz — clock-rate properties, not event-to-event delays.
- **Conformance:** the conversion times have only typical values (no minimum to check), so `specs/humidity/hdc1080_timing.conf` defines no checks.

## Implementation Notes

- **Plain Connection:** the trigger and the read are separate transactions (the read header is NACKed while busy); do not use a repeated-START register read.
- **Sequence read:** in MODE = 1 one read of 4 bytes returns the temperature word then the humidity word (pointer `0x00`).
- **Heater:** the heater only runs during measurements and warms the sensor (a few °C); enable it only to dry the element or test it, then wait for the temperature to settle before trusting readings.
- **Power-up time:** at most 15 ms before measurements start; the ID/serial registers answer earlier.
- **BTST** is updated after POR and after every measurement.
- **Reserved bits:** keep reserved configuration bits 0.
- **ID check:** `device_id()` = `0x1050` and `manufacturer_id()` = `0x5449` identify the chip; the HDC1008 at the same address has no documented ID register.
- **Datasheet:** TI HDC1080, downloaded from `https://www.ti.com/lit/gpn/hdc1080`.

## Sigrok Decoder

Decoder id `hdc1080`, input `['i2c']`. Matches I²C address `0x40`. Annotates pointer writes (Temperature/Humidity/Configuration/Serial ID, noting that pointer `0x00`/`0x01` triggers a measurement), 2-byte configuration reads/writes decoded by field (RST, HEAT, MODE, BTST, TRES, HRES), temperature and humidity words converted to °C and %RH (a 4-byte read as temperature then humidity), serial-ID, manufacturer-ID (verified against `0x5449`) and device-ID (verified against `0x1050`) words; warns on reads that are NACKed after the address (data not ready), on writes to read-only registers and on non-zero reserved configuration bits. No timing annotation pair is emitted.
