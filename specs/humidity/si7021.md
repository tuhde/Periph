# Chip Spec: Si7021

**Manufacturer:** Silicon Labs  
**Datasheet:** `datasheets/humidity/si7021.pdf` (Si7021-A10, Rev. 1.0, 3/14)  
**Category:** humidity  
**Transports:** I²C

## Overview

The Si7021 is a monolithic CMOS relative-humidity and temperature sensor with factory calibration, 12-bit RH (±3 %RH max, 0–80 %RH) and 14-bit temperature (±0.4 °C max, −10…85 °C) results, an on-chip heater and 1.9–3.6 V supply. It is command-driven (no register pointer): single-byte commands start a measurement, read or write the one user register, read the electronic serial number or reset the chip. A measurement can be read with clock stretching ("hold master") or by polling (the read header is NACKed until the result is ready). Every RH measurement also measures the temperature, which can be fetched without a second conversion. Typical uses: HVAC, thermostats, weather stations, dew-point measurement, asset tracking.

## Transport Configuration

### I²C
- **Address:** `0x40` (7-bit `1000000`, fixed — no address pins; one Si7021 per bus)
- **Max clock:** 400 kHz (fast mode); the chip may stretch SCL briefly (< 10 µs at 400 kHz) for user-register and ID transactions
- **Identity:** no ID register; the electronic ID command `0xFC 0xC9` returns SNB_3 as its first byte (`0x15` = Si7021, `0x14` = Si7020, `0x0D` = Si7013, `0x00`/`0xFF` = engineering samples). Registered in `registry/chips.json` as `id_probe` register `0xFCC9` (`reg_bytes` 2), `length` 4, mask `0xFF000000`, expected `0x15000000`. The address `0x40` is shared with HDC1008/HDC1080/HTU21D and the INA2xx family.
- **Probe safety:** `write_sensitive` — every written byte is a command (`0xFE` resets the chip, `0xE5`/`0xF5`/`0xE3`/`0xF3` start measurements, `0xE6` writes the user register); commands other than those documented are undefined and must not be sent.

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| SDA, SCL | — | I²C; pull-ups required |
| VDD, GND | — | 1.9–3.6 V; GND is connected via a trace, not directly to the plane (the exposed paddle is the thermal input of the temperature sensor and is soldered to a floating pad) |
| DNC (3, 4) | — | solder for mechanical stability; float or tie to VDD, never to GND |

## Command Set

| Command | Code | Description |
|---------|------|-------------|
| Measure RH, hold master | `0xE5` | Stretches SCL during the conversion, then returns RH |
| Measure RH, no hold master | `0xF5` | Read header NACKed until done |
| Measure temperature, hold master | `0xE3` | |
| Measure temperature, no hold master | `0xF3` | |
| Read temperature from previous RH measurement | `0xE0` | No new conversion; no checksum available |
| Reset | `0xFE` | Software reset; ready again after ≤ 15 ms (5 ms typ.) |
| Write user register 1 | `0xE6` | followed by one data byte |
| Read user register 1 | `0xE7` | one byte, no checksum |
| Read electronic ID, first access | `0xFA 0x0F` | 8 bytes: SNA_3, CRC, SNA_2, CRC, SNA_1, CRC, SNA_0, CRC |
| Read electronic ID, second access | `0xFC 0xC9` | 6 bytes: SNB_3, SNB_2, CRC, SNB_1, SNB_0, CRC |
| Read firmware revision | `0x84 0xB8` | one byte (`0xFF` = firmware 1.0) |

A measurement command is a 1-byte write; the result (MSB, LSB and optional CRC byte) is read in a separate transaction. The checksum follows the LSB when the master ACKs it (NACK the LSB to omit it). Checksum: CRC-8, polynomial x⁸ + x⁵ + x⁴ + 1 (`0x31`), initial value `0x00`, over the two data bytes.

## Register Map

One user register, accessed through the commands above (not addressed by pointer).

| Command | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0xE7` / `0xE6` | USER_REG_1 | R/W | `0x3A` | Resolution, VDD status, heater enable |

### Bit Fields

#### `USER_REG_1`

| Bits | Name | R/W | Description |
|------|------|-----|-------------|
| 7, 0 | RES1:RES0 | R/W | Resolution (RH / temperature): `00` 12 / 14 bit (default), `01` 8 / 12 bit, `10` 10 / 13 bit, `11` 11 / 11 bit |
| 6 | VDDS | R | `0` VDD OK, `1` VDD low (1.8–1.9 V; below 1.8 V the device no longer operates correctly) |
| 5:3 | RSVD | R/W | Reserved; read back as 1 |
| 2 | HTRE | R/W | On-chip heater: `1` on, `0` off |
| 1 | RSVD | R/W | Reserved; reads back as 1 |

Reserved bits are not affected by writes; the datasheet recommends read-modify-write and writing the read reserved bits back unchanged.

## Initialization Sequence

1. Power up (VDD ≥ 1.9 V). The chip is ready for a conversion after ≤ 25 ms (typ. 18 ms; ≤ 80 ms over the full temperature range).
2. Optionally software reset (`0xFE`), wait ≥ 15 ms.
3. Measure: `0xF5`, poll the read header until ACKed, read 3 bytes (MSB, LSB, CRC), convert; read the temperature with `0xE0`.

## Implementation Stages

### Minimal

Goal: read humidity and temperature with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Stores the plain `Connection`; no bus access (power-on defaults: 12-bit RH / 14-bit T, heater off) |
| `read` | — | `{temperature_c, humidity_pct}` | `0xF5`, polls the read header until ACKed (timeout 50 ms), reads RH + CRC (verified), then `0xE0` for the temperature from the same measurement; RH clamped to 0–100 %RH |

**Sensible defaults:** the power-on user register (12-bit RH, 14-bit temperature, heater off), no-hold-master measurement, CRC verified on the RH result.

## Data Conversion

```
rh_code = (msb << 8) | lsb              # LSB bits 1:0 are 10 for humidity
humidity_pct = 125 * rh_code / 65536 - 6      # clamp to 0 … 100

t_code = (msb << 8) | lsb               # LSB bits 1:0 are 00 for temperature
temperature_c = 175.72 * t_code / 65536 - 46.85

# dew point (Magnus, over water; T in °C, RH in %)
g = ln(humidity_pct / 100) + 17.62 * T / (243.12 + T)
dew_point_c = 243.12 * g / (17.62 - g)
```

Lower resolutions use the same formulas with the unused low bits zero. The conversion time at the default resolution is ≈ 10 ms (RH) + 7 ms (T) typical, 12 + 10.8 ms max. The Magnus constants are the common Sonntag-style values and not part of the datasheet.

## Timing Constraints

| Constraint | Value |
|------------|-------|
| RH conversion (12 / 11 / 10 / 8 bit) | 10 / 5.8 / 3.7 / 2.6 ms typ.; 12 / 7 / 4.5 / 3.1 ms max |
| Temperature conversion (14 / 13 / 12 / 11 bit) | 7 / 4 / 2.4 / 1.5 ms typ.; 10.8 / 6.2 / 3.8 / 2.4 ms max |
| RH measurement total | RH time + temperature time (an RH measurement also measures T) |
| Power-up to ready | 18 ms typ., 25 ms max (80 ms over temperature) |
| After software reset | 5 ms typ., 15 ms max |
| I²C clock | ≤ 400 kHz |

**Conformance-checked constraint:** the maximum RH-measurement time at the default resolution (12 + 10.8 ≈ 23 ms) via the `conversion_start` / `conversion_done` annotation pair (the `0xF5` command write → the first read header that is ACKed); see `si7021_timing.conf`.

## Implementation Notes

- **Plain Connection, command protocol:** there is no register pointer; commands are written with `write`, results read in separate transactions, the user register and ID with `write_read`. Do not use a register-addressed connection.
- **No-hold polling:** after `0xF5`/`0xF3` the read header is NACKed until the result is ready; retry (timeout 50 ms). Hold-master commands stretch SCL, which many host controllers (some Raspberry Pi buses) handle badly — polling is the default.
- **LSB status bits:** an RH result ends in `10`, a temperature result in `00`; do not shift them away before converting.
- **Clamp RH** to 0–100 %: the result can be slightly outside this range near the limits (expected).
- **Heater:** raises the die temperature (3.1 mA); use to drive off condensation or test the sensor, then let the temperature settle before trusting readings.
- **ID CRCs:** the datasheet does not state whether the CRC bytes of the first ID access (SNA) are chained; the driver does not verify them (verify against hardware before enabling).
- **Rehydration after soldering:** the humidity reading shifts after reflow; leave the board 48 h at 45–55 %RH (datasheet §4.4.2). Bake/hydrate recovery is described in §4.6.
- **Address overlap:** `0x40` is shared with HDC1080 (ID register `0xFF`), HTU21D and INA2xx; probe the Si7021 only with `active=True`.
- **A10 datasheet:** this revision documents only the `HTRE` heater bit (no heater-current register) and firmware `0xFF` = 1.0.

## Sigrok Decoder

Decoder id `si7021`, input `['i2c']`. Matches I²C address `0x40`. Annotates every command (measurement, reset, user-register read/write, ID, firmware), decodes RH and temperature results (with their LSB status bits and CRC check) as %RH and °C, decodes USER_REG_1 into RES, VDDS and HTRE, and decodes the electronic ID and device type. It warns on undocumented command bytes and CRC mismatches. It emits the conformance pair `conversion_start` (the `0xF5` write) and `conversion_done` (the first read header that is ACKed).
