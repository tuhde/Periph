# Chip Spec: HDC1008

**Manufacturer:** Texas Instruments  
**Datasheet:** `datasheets/humidity/hdc1008.pdf` (HDC1008 datasheet, SNAS642)  
**Category:** humidity  
**Transports:** I²C

> **Note:** The HDC1008 measures relative humidity and temperature (no pressure); it is placed in `humidity` next to the DHT11 and SHTC3.

## Overview

The HDC1008 is a low-power digital humidity sensor with an integrated temperature sensor: 14-bit relative humidity and temperature results (typical accuracy ±3 %RH and ±0.2 °C), 14/11/8-bit humidity and 14/11-bit temperature resolution, 3.85–6.5 ms conversion times, an integrated **heater** (to drive off condensation), a **battery-low** flag (VDD < 2.8 V), a **data-ready (DRDYn)** output pin and 200 nA sleep current. Two address pins give four addresses. After power-up it sleeps and waits for I²C input. Registers are 16 bit, **MSB first**. Supply 3.0–5.5 V. The HDC1080 (`specs/humidity/hdc1080.md`) is the register-compatible successor with fixed address and ID registers.

## Transport Configuration

### I²C
- **Address:** `0x40` (ADR1 = ADR0 = GND) … `0x43` (both VDD); 7-bit `10000 ADR1 ADR0`; the address pins are sampled at the start of **every** bus communication and must be hard-wired
- **Max clock:** 400 kHz (fast mode); 100 kHz standard
- **Identity register:** the datasheet documents only the serial-number registers `0xFB`–`0xFD`; no manufacturer/device ID register is listed (`registry/chips.json` entry has `"id_probe": null`; `0x40`–`0x43` are shared with the HDC1080, ADS1x1x and INA2xx families)
- **Probe safety:** `register_pointer` — a 1-byte write sets the pointer; writing pointer `0x00`/`0x01` also **triggers a measurement** (harmless, sleep mode returns afterwards)
- **Register addressing:** 1-byte pointer; reads return 16-bit MSB-first words; the pointer persists. A measurement is **triggered by a pointer write** to `0x00` (temperature, or temperature + humidity in sequence mode) or `0x01` (humidity), and the result is read in a *separate* transaction (read header) once ready — the read header is NACKed while the data are not ready. The drivers use the plain `Connection` (`write(pointer)` / `read(n)`), not a repeated-START register read

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| DRDYn | low, open-drain | Data ready; pulls low when a measurement completes and stays low until the result is read or the next measurement is triggered; requires a pull-up to VDD; tie to GND if unused |
| ADR0, ADR1 | — | Address select, hard-wired to GND or VDD |
| SDA, SCL | — | I²C; external pull-ups |
| VDD, GND | — | 3.0–5.5 V supply |

## Register Map

| Pointer | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | Temperature | R | `0x0000` | 14-bit temperature (bits 15:2), bits 1:0 = 0; write-pointer triggers a measurement |
| `0x01` | Humidity | R | `0x0000` | 14-bit humidity (bits 15:2), bits 1:0 = 0; write-pointer triggers a measurement |
| `0x02` | Configuration | R/W | `0x1000` | Reset, heater, mode, resolution, battery status |
| `0xFB` | Serial ID | R | device | Serial ID bits 39:24 |
| `0xFC` | Serial ID | R | device | Serial ID bits 23:8 |
| `0xFD` | Serial ID | R | device | Serial ID bits 7:0 in bits 15:7 (bits 6:0 = 0) |

Registers `0x03`–`0xFA` are reserved. The pointer resets to `0x00`. Writing a read-only register is NACKed after each data byte; access to an unused address is NACKed after the pointer.

### Bit Fields

#### `Configuration` (`0x02`) — reset `0x1000`

| Bits | Name | Description |
|------|------|-------------|
| 15 | RST | `1` = software reset (self-clears) |
| 14 | — | Reserved, write 0 |
| 13 | HEAT | `1` = heater enabled (runs only during measurements) |
| 12 | MODE | `0` = temperature **or** humidity acquired (per the trigger pointer), `1` = temperature and humidity acquired in sequence (temperature first) |
| 11 | BTST | Read only: `1` = battery (VDD) below 2.8 V |
| 10 | TRES | Temperature resolution: `0` = 14 bit, `1` = 11 bit |
| 9:8 | HRES | Humidity resolution: `00` = 14 bit, `01` = 11 bit, `10` = 8 bit |
| 7:0 | — | Reserved, write 0 |

Note the reset value `0x1000` has MODE = 1 (sequence mode, 14-bit) already set.

## Initialization Sequence

1. Power-up: the chip is in sleep mode and waits for I²C input; BTST is updated after POR.
2. `init` writes `Configuration` ← `0x1000` (MODE = 1, 14-bit T and RH, heater off) so the state is known.
3. A measurement (sequence mode): write pointer `0x00`; wait for the conversion (DRDYn low, or the read header ACKed; typically ≈ 13 ms for both); read 4 bytes: temperature word, then humidity word, in one transaction.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `DRDYn`, active-low, open-drain — requires an external pull-up |
| Level | 1 (single fixed condition: a measurement completed) |
| Condition | The triggered measurement (temperature, humidity or both) is complete and its result has not been read |
| Clear mechanism | Read the result register(s); DRDYn also stays low until the next measurement is triggered if the newest result was not read |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on DRDYn (falling edge) via `connection.int_pin` (or `int_pin`), otherwise a 5 ms polling task on `poll_interrupt`; `callback(result)` receives the converted result of the completed measurement |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> bool` | `True` when the data-ready condition holds, determined by a read header: ACK = data ready (the 4/2 data bytes are then read and cached for the next `read`), NACK = not ready |

## Implementation Stages

### Minimal

Goal: read temperature and humidity with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Writes the configuration `0x1000` (14-bit, sequence mode, heater off) |
| `read` | — | `{temperature_c, humidity_pct}` | Triggers a sequence measurement (pointer `0x00`), waits (poll the read header, timeout 50 ms), reads 4 bytes, converts |

**Sensible defaults:** 14-bit temperature and humidity, sequence mode (temperature first), heater off, 20 ms read timeout poll.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `read_temperature` | — | float | °C only (single mode, pointer `0x00`) |
| `read_humidity` | — | float | %RH only (single mode, pointer `0x01`) |
| `read_raw` | — | `(raw_temperature, raw_humidity)` | Raw 16-bit words (bits 1:0 zero) |
| `set_resolution` | `temperature_bits: int` (14, 11), `humidity_bits: int` (14, 11, 8) | — | `TRES` / `HRES`; raises on other values |
| `set_heater` | `on: bool` | — | `HEAT` bit (read-modify-write) |
| `is_heater_on` | — | bool | |
| `battery_low` | — | bool | `BTST` (VDD < 2.8 V) |
| `read_config` | — | int | Configuration word |
| `software_reset` | — | — | `RST` ← 1; waits 15 ms (derived) then rewrites the stored configuration |
| `serial_id` | — | int | 40-bit serial number from `0xFB`–`0xFD` |
| `conversion_time` | — | float | Seconds for the current resolutions (sum of the datasheet typical times, see Timing) |
| `on_interrupt` / `off_interrupt` / `poll_interrupt` | see Interrupt | | |

**Additional configuration options:** temperature/humidity resolution, heater, single vs sequence mode (selected implicitly by `read_temperature`/`read_humidity` vs `read`).

## Data Conversion

```
raw_t = (msb << 8) | lsb              # bits 15:2 are the 14-bit value, bits 1:0 are 0
temperature_c = raw_t / 65536 * 165 - 40
raw_h = (msb << 8) | lsb
humidity_pct  = raw_h / 65536 * 100
serial_id = (word(0xFB) << 24) | (word(0xFC) << 8) | (word(0xFD) >> 7)        # 40 bits
```

The result is always a 14-bit value in the register; the selected resolution only affects the conversion time/accuracy (the low bits of the 11/8-bit results are just less precise). Example: `0x6666` → 24.99 °C (T), `0x8000` → 50 %RH.

## Timing Constraints

- **Conversion time (typical):** humidity 2.50 ms (8 bit), 3.85 ms (11 bit), 6.50 ms (14 bit); temperature 3.65 ms (11 bit), 6.35 ms (14 bit); in sequence mode the two add up (≈ 12.85 ms at 14/14 bit). The read header is NACKed until the result is ready; DRDYn goes low at completion.
- **Sleep:** 110–200 nA between measurements; the chip returns to sleep after each measurement.
- **Abort:** a pointer write to `0x00`/`0x01` while a measurement is running aborts it; reading the output registers during a measurement does not disturb it.
- **I²C:** 100 / 400 kHz — clock-rate properties, not event-to-event delays.
- **Conformance:** the conversion times have only typical values (no minimum to check), so `specs/humidity/hdc1008_timing.conf` defines no checks.

## Implementation Notes

- **Plain Connection:** the trigger and the read are separate transactions (the read header is NACKed while busy); do not use a repeated-START register read.
- **Sequence read:** in MODE = 1 one read of 4 bytes returns the temperature word then the humidity word (pointer `0x00`).
- **Heater:** the heater only runs during measurements and warms the sensor (a few °C); enable it only to dry the element or test it, then wait for the temperature to settle before trusting readings.
- **Address pins sampled every transaction** — hard-wire them; do not toggle.
- **BTST** is updated after POR and after every measurement.
- **Reserved bits:** keep reserved configuration bits 0.
- **No ID register documented:** use the serial number or an acknowledge test; a wrong-chip access at `0x40`–`0x43` returns meaningless data.
- **Datasheet:** TI HDC1008, downloaded from `http://www.ti.com/lit/ds/symlink/hdc1008.pdf`.

## Sigrok Decoder

Decoder id `hdc1008`, input `['i2c']`. Matches I²C addresses `0x40`–`0x43`. Annotates pointer writes (Temperature/Humidity/Configuration/Serial ID, noting that pointer `0x00`/`0x01` triggers a measurement), 2-byte configuration reads/writes decoded by field (RST, HEAT, MODE, BTST, TRES, HRES), temperature and humidity words converted to °C and %RH (a 4-byte read as temperature then humidity), serial-ID words; warns on reads that are NACKed after the address (data not ready), on writes to read-only registers and on non-zero reserved configuration bits. No timing annotation pair is emitted.
