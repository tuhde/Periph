# Chip Spec: AM2315

**Manufacturer:** ASAIR / Aosong (Guangzhou Aosong Electronics)  
**Datasheet:** `datasheets/environmental/am2315.pdf` (AM2315 temperature and humidity sensor manual; the PDF is image-only — values below were read from the page images)  
**Category:** environmental  
**Transports:** I²C

> **Note:** The AM2315 measures temperature and humidity only (no pressure); it is placed in `environmental` next to the AM2320 (`specs/environmental/am2320.md`), whose I²C protocol it shares **exactly** (same Modbus-style frames, CRC-16, wake-up, register table and timing). The AM2315 is the cabled probe version (4 wires: VDD red, SDA yellow, GND black, SCL white).

## Overview

The AM2315 is a digital capacitive humidity and temperature sensor probe with a 16-bit temperature value (0.1 °C resolution, accuracy ±0.1 °C typical, ±1 °C max; range −40…125 °C) and a 0.1 %RH humidity value (±2 %RH at 25 °C, range 0–99.9 %RH; response < 5 s, drift < 0.5 %RH/yr), calibrated and temperature-compensated in the sensor. Supply **3.5–5.5 V (5 V recommended)**. It speaks the same **Modbus-style** protocol over standard-mode I²C (≤ 100 kHz) as the AM2320: the host sends a function code (`0x03` read registers, `0x10` write registers), every response carries a CRC-16, and the sensor **sleeps between transactions** (wake-up required) and measures only after a communication, so a read returns the **previous** measurement — reads must be ≥ 2 s apart. Unlike the AM2320 it has no one-wire mode.

## Transport Configuration

### I²C
- **Address:** `0x5C` (7-bit; the datasheet's address byte `0xB8` is the write address; fixed, one AM2315 per bus)
- **Max clock:** 100 kHz (standard mode only; Table 6 gives no fast-mode limits)
- **Identity register:** the device-information registers `0x08`–`0x0E` (model, version, device ID) exist but need a wake-up and a protocol frame (no plain register pointer), so `registry/chips.json` has `"id_probe": null`; the address `0x5C` is shared with the AM2315 and the BH1750 (ADDR high)
- **Probe safety:** `write_sensitive` — the chip does not acknowledge while asleep and a stray byte after the address is parsed as a function code (error response `0x80`+); there is no register pointer
- **Protocol:** Modbus-style frames, no register-addressed repeated-START reads. A read is **two separate transactions** (command write, then a read after ≥ 1.5 ms), so the drivers use the plain `Connection` (`write(data)` / `read(n)`) — see `specs/feature_register_access_design.md`, "no register concept"

### Frame format

```
write (host -> sensor):  [addr+W] [function] [start address] [count] [data ...]   (+ CRC-16 for 0x10 only)
read  (sensor -> host):  [addr+R] [function] [byte count] [data ...] [CRC low] [CRC high]
```

- Function `0x03`: read `count` registers starting at `start` (max 10 registers per read; more returns error `0x81`/`0x80`+). The read command carries **no CRC**; the response always does (the host may ignore it by stopping early, but the drivers always read and verify it).
- Function `0x10`: write `count` registers (max 10); the write frame **must** carry the CRC; the response is `[0x10] [start] [count] [CRC low] [CRC high]`.
- **CRC-16 (Modbus):** init `0xFFFF`, polynomial `0xA001` (reflected), over the function code, length/start/count and data bytes (the I²C address byte is **not** included), transmitted **low byte first**. Datasheet examples: response `03 04 01 F4 00 FA` → CRC bytes `31 A5`; response `03 04 03 39 01 15` → `E1 FE`; write frame `10 10 02 01 02` → `C0 92`.
- **Error responses** (function code with bit 7 set): `0x80` function code not supported, `0x81` read of an illegal address, `0x82` write data out of range, `0x83` CRC error, `0x84` write disabled.

## Register Map

All registers are 8 bits; `0x03` reads up to 10 consecutive bytes (multi-byte values are big-endian).

| Address | Name | R/W | Description |
|---------|------|-----|-------------|
| `0x00` | Humidity high | R | Humidity ×10, high byte |
| `0x01` | Humidity low | R | |
| `0x02` | Temperature high | R | Temperature ×10, high byte (bit 15 = sign) |
| `0x03` | Temperature low | R | |
| `0x04`–`0x07` | — | — | Reserved |
| `0x08` | Model high | R | Model number (16-bit) |
| `0x09` | Model low | R | |
| `0x0A` | Version | R | Version number (8-bit) |
| `0x0B`–`0x0E` | Device ID | R | 32-bit device ID, `0x0B` = bits 31–24 … `0x0E` = bits 7–0 |
| `0x0F` | Status | R/W | Status register (bits reserved); can only be written on its own |
| `0x10`–`0x11` | User register 1 | R/W | User data, high / low byte |
| `0x12`–`0x13` | User register 2 | R/W | User data, high / low byte |
| `0x14`–`0x1F` | — | — | Reserved |

The datasheet's register list says write access is for the user registers (`0x0F`–`0x13`); other registers must not be written, and the status register must be written alone (an attempt to combine it with others returns an error).

## Initialization Sequence

1. After power-up wait **2 s** before the first transaction (the sensor needs it to settle; no commands may be sent meanwhile). The first reading after power-up is the measurement taken at power-up.
2. `init` stores the connection; it performs no bus access (the sensor sleeps).

### Transaction sequence (every read or write)

1. **Wake:** START + address (write) → the sensor does **not** ACK → wait ≥ 800 µs (max 3 ms) → STOP. The driver sends a dummy write (an empty write where the connection supports it, otherwise a single `0x00` byte) and **ignores the NACK / bus error**.
2. **Command:** `write([function, start, count])` (read) or the CRC-framed write; the whole transaction from wake to the end of the read must finish within **3 s**, otherwise the sensor drops back to sleep and the wake-up must be repeated.
3. **Wait ≥ 1.5 ms** (the driver waits 2 ms).
4. **Read** `count + 4` bytes (`function`, `byte count`, data, CRC low, CRC high), verify the function code, byte count and CRC (error responses have bit 7 set in byte 0); after the address byte the sensor needs ≥ 30 µs before the first clock for the data (a hardware I²C controller usually inserts this gap; bit-banged hosts must add it).
5. A communication triggers the next measurement; the sensor then sleeps again.

## Implementation Stages

### Minimal

Goal: return temperature and humidity with no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Stores the connection; no bus access |
| `read` | — | `{temperature_c, humidity_pct}` | Runs a transaction reading registers `0x00`–`0x03` (4 bytes), verifies the CRC, decodes both values. Enforces ≥ 2 s since the previous transaction by sleeping the remainder; returns the **previous** measurement's result |

**Sensible defaults baked into Minimal:** 2 s power-up wait handled lazily (the first `read` waits until 2 s after construction), one retry on a CRC or bus error (after a new wake), ≥ 2 s minimum interval.

### Full

Goal: expose all device capabilities. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `read_temperature` | — | float | °C only (registers `0x02`–`0x03`) |
| `read_humidity` | — | float | %RH only (registers `0x00`–`0x01`) |
| `read_raw` | — | `(raw_humidity, raw_temperature)` | Raw 16-bit words (temperature as sign + magnitude word) |
| `read_fresh` | — | `{temperature_c, humidity_pct}` | Two reads ≥ 2 s apart; returns the second (the real-time value) |
| `read_registers` | `start: int`, `count: int` (1–10) | bytes | Function `0x03`, CRC verified |
| `write_registers` | `start: int`, `data: bytes` (1–10) | — | Function `0x10` with CRC; verifies the response; only the user registers `0x10`–`0x13` are allowed (raises otherwise) |
| `read_device_info` | — | `{model, version, device_id}` | Registers `0x08`–`0x0E` (7 bytes) |
| `read_user_registers` | — | `(user1, user2)` | Two 16-bit values (registers `0x10`–`0x13`) |
| `write_user_registers` | `user1: int`, `user2: int` | — | Registers `0x10`–`0x13` |
| `wake` | — | — | Wake-up only (dummy write, ignore the NACK, wait 1 ms) |

**Additional capabilities:** raw values, fresh-value read, arbitrary register read, user register read/write, device information. Exceptions: a sensor error response raises a driver error carrying the code (`0x80`–`0x84`).

## Data Conversion

```
raw_rh = (b0 << 8) | b1                       # register 0x00-0x01
raw_t  = (b2 << 8) | b3                       # register 0x02-0x03

humidity_pct  = raw_rh / 10.0                 # 0..99.9 %RH, 0.1 %RH resolution
temperature_c = (raw_t & 0x7FFF) / 10.0       # sign-magnitude: bit 15 = 1 -> negative
if raw_t & 0x8000: temperature_c = -temperature_c

crc16(bytes): init 0xFFFF; for each byte: crc ^= byte; 8 times { crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1 }
              (the I2C address byte is not included; sent/received low byte first)
```

Examples: `01 F4 00 FA` → 50.0 %RH, 25.0 °C; `03 39 01 15` → 82.5 %RH, 27.7 °C; temperature word `0x8065` → −10.1 °C (**sign-magnitude, not two's complement**).

## Timing Constraints

| Event | Time | Notes |
|-------|------|-------|
| Power-up settling | 2 s | No commands during this time |
| Wake-up | START + address, wait ≥ 800 µs (max 3 ms), STOP | The sensor does not ACK the address; the host must still clock the ACK bit |
| Command to read | ≥ 1.5 ms | After the command write, before the read address. The decoder marks the command write (function `0x03`) as `read_delay_start` and the following read address byte as `read_delay_done`; `am2315_timing.conf` checks ≥ 1.5 ms |
| Data after read address | ≥ 30 µs | Before the first data clock |
| Whole communication | ≤ 3 s | From wake to the end of the read; else the sensor sleeps again |
| Minimum measurement interval | ≥ 2 s | Reading more often returns old data or fails |
| Response time τ63 | < 5 s | 1 m/s air flow |

## Implementation Notes

- **Previous-measurement semantics:** the sensor measures *after* a communication and returns that result on the *next* one, so `read` after a long idle returns an old value. `read_fresh` (two reads) gives the real-time value; the drivers keep ≥ 2 s between transactions.
- **Wake-up NACK is normal:** a bus error on the wake write must be swallowed; only errors on the command write and the read are real.
- **Plain Connection, two transactions:** a repeated-START register read (as on most chips) is **not** the sensor's protocol — the command and the read are separate transactions with a ≥ 1.5 ms gap, so the driver uses `write`/`read` on the plain `Connection`.
- **Standard-mode I²C only:** the sensor needs ≤ 100 kHz and the timing in Table 6 (e.g. 4.7 µs clock low); fast mode may fail.
- **Sign-magnitude temperature:** bit 15 is a sign flag; the other 15 bits are the magnitude (not two's complement).
- **CRC low byte first:** unlike many Modbus implementations that show the CRC as one big-endian word, the wire order is low byte then high byte.
- **User registers:** only `0x10`–`0x13` are written by the drivers; the status register `0x0F` is reserved and must be written alone, so it is not exposed.
- **Self-heating:** keeping the 2 s interval (or longer) keeps self-heating low; the sensor idles at ≈ 10 µA.
- **Address overlap:** `0x5C` is shared with the AM2320 and BH1750; wrong-chip access returns meaningless data rather than an error, so the discovery registry marks it `write_sensitive`.
- **Datasheet:** downloaded from `https://cdn-shop.adafruit.com/datasheets/AM2315.pdf` (image-only manual: the protocol pages were read from the images; the example frames in the datasheet are `03 04 03 39 01 15 E1 FE` = 82.5 %RH / 27.7 °C and verified against the CRC definition).

## Sigrok Decoder

Decoder id `am2315`, input `['i2c']`. Matches I²C address `0x5C`. Decodes the wake-up (address write with no ACK and no data), read commands (`0x03`, start address, register count), write commands (`0x10`, start, count, data, CRC) and the responses (function code, byte count, data, CRC low/high) — registers `0x00`–`0x03` decoded as humidity %RH and temperature °C (sign-magnitude), `0x08`–`0x0E` as model/version/device ID — and **verifies the CRC-16** (init `0xFFFF`, poly `0xA001`, low byte first, address excluded), flagging a warning on mismatch and an error annotation for response function codes with bit 7 set (`0x80`–`0x84`). Timing annotations in the `timing` row (variable-length strings per `specs/sigrok_annotations.md`): `read_delay_start` on the end of a `0x03` command write and `read_delay_done` on the following read address byte.
