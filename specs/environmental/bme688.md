# Chip Spec: BME688

**Manufacturer:** Bosch Sensortec  
**Datasheet:** `datasheets/environmental/bme688.pdf` (BST-BME688-DS000-03, Revision 1.3, February 2024)  
**Category:** environmental  
**Transports:** I²C (the chip also has a paged 3-/4-wire SPI interface, deferred like the BME680's)

## Overview

The BME688 is Bosch's 4-in-1 environmental sensor and the successor of the BME680: temperature, pressure, relative humidity and a **metal-oxide (MOX) gas sensor** whose heater runs programmable hot-plate temperature profiles (up to 10 steps) for gas/VOC sensing, in a 3.0 × 3.0 × 0.93 mm LGA. It keeps the BME680's register map, calibration block and T/P/H compensation but adds a **parallel mode** (continuous TPHG cycling through a heater profile without host intervention, three data "fields"), a **variant ID** register and a different, simpler gas-resistance conversion. The "indoor air quality" index and the AI classification features belong to Bosch's closed-source BSEC/BME AI-Studio software, not to the chip: this driver exposes the raw gas resistance in Ω.

Differences from the BME680 worth flagging up front (so a BME680 driver is **not** simply reusable):

- **New mode:** `mode` = `10` is **parallel mode** (the BME680 only has sleep and forced); `gas_wait_shared` (`0x6E`) and the repetition semantics of `gas_wait_x` change in parallel mode.
- **Data layout:** three 17-byte fields at `0x1D`–`0x2D`, `0x2E`–`0x3E`, `0x3F`–`0x4F` with a `sub_meas_index` byte each; the gas data of field 0 are at `0x2C`/`0x2D` (the BME680 has them at `0x2A`/`0x2B`, in a 15-byte field).
- **`run_gas` is bit 5** of `ctrl_gas_1` (`run_gas_h`); the BME680's bit 4 (`run_gas_l`) is the legacy position (the Bosch API sets both; this spec uses bit 5).
- **Gas resistance** is `1e6 · (262144 >> gas_range) / (4096 + 3·(gas_adc − 512))` — no lookup tables, no 64-bit math, no `range_switching_error`.
- **Variant ID** `0xF0` = `0x01`; `chip_id` (`0xD0`) is `0x61` like the BME680.
- Temperature, pressure and humidity compensation, the calibration layout (including `par_T1` at `0xE9`/`0xEA`), the heater-resistance formula and the `ctrl_hum`-before-`ctrl_meas` write order are **identical** to the BME680 (`specs/environmental/bme680.md`).

## Transport Configuration

### I²C
- **Address:** `0x76` (SDO = GND) or `0x77` (SDO = VDDIO); CSB tied to VDDIO selects I²C mode
- **Max clock:** 3.4 MHz (high-speed mode); the drivers use ≤ 400 kHz
- **Identity register:** `0xD0` `chip_id` = `0x61` (same as the BME680) and `0xF0` `variant_id` = `0x01` for the BME688; the registry probes `0xF0` (expected `0x01`) to tell the two apart
- **Probe safety:** `register_pointer` — a 1-byte write only sets the register pointer
- **Register addressing:** 1-byte register address (`RegisterConnection`, `reg_bytes = 1`); auto-increment on reads and writes
- **`0x77` collides** with the BMP180 / BMP280 / BME280 / BME680 / BMP388 — use `0x76` if any share a bus.

### SPI
Deferred, as for the BME680: the memory map is paged (page 0 mirrors I²C `0x80`–`0xFF`, page 1 mirrors `0x00`–`0x7F`, `spi_mem_page` is bit 4 of `0x73`, SPI address = I²C address with bit 7 as R/W); the drivers are I²C only.

| `par_P2`  | `0x90` / `0x91` | int16 | |
| `par_P3`  | `0x92`          | int8 | |
| `par_P4`  | `0x94` / `0x95` | int16 | |

| `par_H3`  | `0xE4` | int8 | |

| `par_H7`  | `0xE8` | int8 | |
| `par_G1`  | `0xED` | int8 | |
| `par_G2`  | `0xEB` / `0xEC` | int16 | |
| `par_G3`  | `0xEE` | int8 | |
| `res_heat_val`        | `0x00` | int8 | Heater resistance correction (calibration) |
| `res_heat_range`      | `0x02<5:4>` | uint8 | Heater range — mask and shift; values 0–3 |
| `range_switching_error` | `0x04<7:4>` | int8 | Gas-range switching error — sign-extend from 4-bit signed |

Burst-read both calibration blocks (23 bytes from `0x8A` and 14 bytes from `0xE1`) plus three single-byte reads at `0x00`, `0x02`, `0x04`. The three single bytes are not in either contiguous block.

`par_H1` and `par_H2` share register `0xE2` — `par_H1` uses the lower nibble, `par_H2` uses the upper nibble. Both are 12-bit **unsigned** values stored in 16-bit slots. (This packing differs from the BME280's `dig_H4` / `dig_H5`, which are signed and use different shared bits.)

The calibration block layout, packing and the `par_H1`/`par_H2` shared byte are **identical to the BME680**; burst-read both blocks plus the single bytes `0x00` (`res_heat_val`) and `0x02<5:4>` (`res_heat_range`). The BME680's `range_switching_error` (`0x04<7:4>`) is **not used** by the BME688 gas formula.

### Bit Fields

#### `ctrl_hum` (`0x72`), `ctrl_meas` (`0x74`), `config` (`0x75`)

- `osrs_h<2:0>`, `osrs_t<7:5>`, `osrs_p<4:2>`: `000` = skipped (output set to `0x8000` / `0x80000`), `001` = ×1, `010` = ×2, `011` = ×4, `100` = ×8, `101` and above = ×16.
- `mode<1:0>`: `00` = sleep, `01` = forced, `10` = **parallel**. Mode-change and other control-register writes are ignored until a running measurement finished; set all control registers before writing `mode`.
- `filter<4:2>`: IIR for temperature and pressure only: `000` = 0, `001` = 1, `010` = 3, `011` = 7, `100` = 15, `101` = 31, `110` = 63, `111` = 127.
- `spi_3w_en` / `spi_3w_int_en`: SPI only.

#### `ctrl_gas_0` (`0x70`) and `ctrl_gas_1` (`0x71`)

| Register | Bits | Name | Description |
|----------|------|------|-------------|
| `0x70` | 3 | `heat_off` | `1` turns the heater current off |
| `0x71` | 5 | `run_gas` | `1` enables gas conversions (in forced mode for the next cycle, in parallel mode for the profile) |
| `0x71` | 3:0 | `nb_conv` | **Forced mode:** index 0–9 of the heater step to use. **Parallel mode:** length of the heater profile: `0000` = no conversion, `0001` = step 0, `0010` = steps 0–1, … `1001` = steps 0–8, `1010`–`1111` = steps 0–9 |

#### `gas_wait_x` (`0x64`–`0x6D`) and `gas_wait_shared` (`0x6E`)

- **Forced mode:** `gas_wait_x<5:0>` heater-on timer in 1 ms steps (0 = no wait), `<7:6>` multiplier ×1 / ×4 / ×16 / ×64 (1 ms … 4032 ms). Example: 100 ms = `0x59` (×4, 25).
- **Parallel mode:** `gas_wait_x<7:0>` is the number of TPHG sequences (repetitions) of heater step x (1 … 255; 0 = one sequence with the shared wait skipped); `gas_wait_shared<5:0>` is the wait before every TPHG sequence in 0.477 ms steps with multiplier `<7:6>` ×1/4/16/64 (0 behaves as 1). Duration of a step = `gas_wait_x × (wait_shared + T_TPHG)`.

#### Field status registers (`meas_status_0/1/2` at `0x1D`, `0x2E`, `0x3F`) and `sub_meas_index`

| Bit | Name | Description |
|-----|------|-------------|
| 7 | `new_data` | The field holds data not yet read |
| 6 | `gas_measuring` | Gas conversion running |
| 5 | `measuring` | Any conversion running |
| 3:0 | `gas_meas_index` | Index (0–9) of the heater step of this field's data |

`sub_meas_index` counts the TPHG sub-measurements. Gas LSB register (`gas_r_lsb` at `0x2D` / `0x3E` / `0x4F`): bits 7:6 = `gas_r<1:0>`, bit 5 = `gas_valid_r` (a real gas conversion, not a dummy slot), bit 4 = `heat_stab_r` (heater reached the target; in forced mode checked only during the auto-ranging sequences), bits 3:0 = `gas_range_r`.

## Initialization Sequence

### Minimal (forced mode)

1. Optionally read `chip_id` (`0xD0` = `0x61`) and `variant_id` (`0xF0` = `0x01`).
2. Read calibration (23 bytes from `0x8A`, 14 bytes from `0xE1`, single bytes `0x00`, `0x02`) and unpack it.
3. Write `ctrl_hum` (`osrs_h`), then `ctrl_meas` (`osrs_t`, `osrs_p`, `mode = 00`), `config` (`filter`).
4. Configure heater step 0: `res_heat_0` for 320 °C at 25 °C ambient, `gas_wait_0` for 150 ms (×4, timer 37 = `0x65`), `ctrl_gas_1` = `0x20` (`run_gas` = 1, `nb_conv` = 0).
5. A measurement: write `ctrl_meas` with `mode = 01`, wait until `meas_status_0.new_data` is set and `measuring` clear (the chip returns to sleep by itself), burst-read `0x1D`–`0x2D`.

### Full (parallel mode)

Same configuration, then: `nb_conv` = profile length (1–10), `gas_wait_shared`, `gas_wait_x` (repetitions) and `res_heat_x` for each step, at least one of T/P/H enabled (`osrs` ≠ skip), then `mode = 10`. Read the three fields (burst from `0x1D`, 51 bytes) whenever a field's `new_data` is set; the chip keeps cycling until `mode` is set to `00`.

## Implementation Stages

### Minimal

Goal: read calibrated temperature (°C), pressure (hPa), humidity (%RH) and gas resistance (Ω) with no configuration beyond the connection.

Constructor parameter: `connection`. The constructor reads the calibration and configures forced mode, ×1/×1/×1 oversampling, filter off, heater step 0 (320 °C, 150 ms, ambient 25 °C) and gas enabled.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `temperature()` | — | float | °C; caches `t_fine` and updates the heater ambient |
| `pressure()` | — | float | hPa |
| `humidity()` | — | float | %RH |
| `gas_resistance()` | — | float | Ω; `NaN` when `gas_valid_r` or `heat_stab_r` is 0 |

One forced trigger per call samples T, P, H and G; the driver waits for `new_data` (poll the status bit, timeout = heater time + 500 ms) instead of a fixed sleep.

### Full

Extends Minimal; adds modes, oversampling, filter, the heater profiles and parallel mode.

| `set_heater_profile()` | `index` (0–9), `temp_c`, `duration_ms` | — | Forced-mode step: `res_heat_x` + `gas_wait_x` |

## Data Conversion

Use the **integer** formulas (the datasheet floating-point variants are reference only). T, P, H and the heater resistance are identical to the BME680.

```
# One field = 17 bytes starting at 0x1D + 17*n  (n = 0..2); offsets within the field:
press_adc = (b[2] << 12) | (b[3] << 4) | (b[4] >> 4)               # 0x1F..0x21 (field 0)
temp_adc  = (b[5] << 12) | (b[6] << 4) | (b[7] >> 4)               # 0x22..0x24
hum_adc   = (b[8] << 8)  |  b[9]                                   # 0x25..0x26
gas_adc   = (b[15] << 2) | (b[16] >> 6)                            # 0x2C / 0x2D<7:6>
gas_range = b[16] & 0x0F        gas_valid = (b[16] >> 5) & 1       heat_stab = (b[16] >> 4) & 1
new_data  = b[0] >> 7           gas_meas_index = b[0] & 0x0F       sub_meas_index = b[1]

# Temperature (returns °C; updates t_fine, signed 32-bit):
var1 = (temp_adc >> 3) - (par_T1 << 1)
var2 = (var1 * par_T2) >> 11
var3 = (((var1 >> 1) * (var1 >> 1)) >> 12) * (par_T3 << 4) >> 14
t_fine = var2 + var3
T = ((t_fine * 5 + 128) >> 8) / 100.0                              # °C

# Pressure (32-bit; returns Pa):
var1 = (t_fine >> 1) - 64000
var2 = ((((var1 >> 2) * (var1 >> 2)) >> 11) * par_P6) >> 2
var2 = var2 + ((var1 * par_P5) << 1)
var2 = (var2 >> 2) + (par_P4 << 16)
var1 = (((((var1 >> 2) * (var1 >> 2)) >> 13) * (par_P3 << 5)) >> 3) + ((par_P2 * var1) >> 1)
var1 = var1 >> 18
var1 = ((32768 + var1) * par_P1) >> 15
press_comp = 1048576 - press_adc
press_comp = ((press_comp - (var2 >> 12)) * 3125)
if press_comp >= (1 << 30):
    press_comp = (press_comp // var1) << 1
else:
    press_comp = (press_comp << 1) // var1
var1 = (par_P9 * (((press_comp >> 3) * (press_comp >> 3)) >> 13)) >> 12
var2 = ((press_comp >> 2) * par_P8) >> 13
var3 = ((press_comp >> 8) * (press_comp >> 8) * (press_comp >> 8) * par_P10) >> 17
press_comp = press_comp + ((var1 + var2 + var3 + (par_P7 << 7)) >> 4)   # Pa
return press_comp / 100.0                                                # hPa

# Humidity (32-bit; returns %RH):
temp_scaled = t_fine
var1 = hum_adc - ((par_H1 << 4) + (((temp_scaled * par_H3) // 100) >> 1))
var2 = (par_H2 * (((temp_scaled * par_H4) // 100) +
                 (((temp_scaled * ((temp_scaled * par_H5) // 100)) >> 6) // 100) +
                 (1 << 14))) >> 10
var3 = var1 * var2
var4 = ((par_H6 << 7) + ((temp_scaled * par_H7) // 100)) >> 4
var5 = ((var3 >> 14) * (var3 >> 14)) >> 10
var6 = (var4 * var5) >> 1
hum_comp = (((var3 + var6) >> 10) * 1000) >> 12
return clamp(hum_comp, 0, 100000) / 1000.0                                # %RH

# Heater target resistance (run once at heater configuration):
# target_temp_c is desired heater temp; amb_temp_c is ambient (e.g. 25 or last on-chip temp)
var1 = (((amb_temp_c * par_G3) // 10) << 8)
var2 = (par_G1 + 784) * (((((par_G2 + 154009) * target_temp_c * 5) // 100) + 3276800) // 10)
var3 = var1 + (var2 >> 1)
var4 = var3 // (res_heat_range + 4)
var5 = (131 * res_heat_val) + 65536
res_heat_x100 = ((var4 // var5) - 250) * 34
res_heat_x = (res_heat_x100 + 50) // 100                                  # u8 to write to res_heat_x

# Gas-wait encoding (target_ms ∈ [1, 4032]):
if   target_ms <= 0x3F:    gw = target_ms                  # ×1, no shift
elif target_ms <= 0x3F * 4: gw = (1 << 6) | (target_ms // 4)
elif target_ms <= 0x3F * 16: gw = (2 << 6) | (target_ms // 16)
else:                       gw = (3 << 6) | min(target_ms // 64, 0x3F)

# Gas resistance (BME688: no lookup tables, no calibration term; 32-bit):
var1 = 262144 >> gas_range
var2 = 4096 + 3 * (gas_adc - 512)
gas_res_ohms = (10000 * var1 // var2) * 100                        # integer path (avoids overflow); float: 1e6 * var1 / var2
```

Gas range 0 gives the highest resistances (var1 = 262144), range 15 the lowest (8). Skipped measurements read `0x8000` / `0x80000` / gas `0` — treat as invalid. Altitude, sea-level pressure and dew point use the same formulas as `specs/environmental/bme280.md`.

## Timing Constraints

- **Start-up:** wait ≥ 2 ms after power-up or soft reset (derived from the BME680 spec; the BME688 datasheet gives no separate figure).
- **Measurement completion:** signalled by `meas_status` (`measuring`, `new_data`); the TPHG cycle length depends on the oversampling and on `gas_wait`; no fixed minimum is stated. The datasheet notes that about 20–30 ms of heating are needed to reach the target temperature (shorter `gas_wait` gives `heat_stab_r` = 0); heating durations 1 ms – 4032 ms are possible in forced mode.
- **Parallel mode:** step duration = `gas_wait_x × (gas_wait_shared + T_TPHG)`; the heater runs in parallel to the TPH measurements and the chip keeps cycling until `mode` is set to sleep; each field is updated at the end of its TPHG sequence.
- **Mode switching:** a mode change (and other control-register writes) is ignored/delayed while a measurement runs.
- **Burn-in:** a new gas sensor needs days of operation before its baseline stabilizes (BSEC handles this); raw values early on are not comparable across days.
- **I²C:** up to 3.4 MHz — a clock-rate property, not an event-to-event delay.
- **Conformance:** none of these has a bus-decodable start/end annotation pair with a datasheet bound, so `specs/environmental/bme688_timing.conf` defines no checks.

## Implementation Notes

- **Not a BME680 drop-in:** field offsets (gas at `0x2C`/`0x2D`, 17-byte fields), `run_gas` bit 5, the gas formula and the parallel mode differ; reuse the BME680 calibration parsing and T/P/H compensation, not its gas or data-readout code.
- **`ctrl_hum` before `ctrl_meas`:** always write `ctrl_hum` first; in forced mode also set all other control registers before the `mode` write.
- **Poll, don't sleep:** after a forced trigger poll `new_data` (and `measuring` clear); in parallel mode poll each field's `new_data`, read the whole 51-byte block in one transaction to avoid tearing.
- **Dummy gas slots:** in parallel mode a TPHG sequence may contain a dummy gas conversion; use only fields with `gas_valid_r` = 1 and `heat_stab_r` = 1.
- **At least one of T, P, H** must be enabled in parallel mode.
- **Heater target needs ambient:** same as the BME680 (25 °C default; re-apply after a real temperature is known).
- **`run_gas` position:** the datasheet places `run_gas` at bit 5 of `ctrl_gas_1`; bit 4 is the BME680-compatible location (the Bosch API writes both) — this spec's drivers set bit 5 only.
- **`0x77` collisions** with other Bosch chips; `variant_id` (`0xF0` = `0x01`) separates the BME688 from the BME680 at runtime.
- **BSEC / AI:** IAQ and gas classification are out of scope.
- **Datasheet:** BST-BME688-DS000-03 Rev. 1.3, from `https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bme688-ds000.pdf`.

## Sigrok Decoder

Decoder id `bme688`, input `['i2c']`. Matches `0x76`/`0x77`. Annotates register writes and reads by name and decodes: `ctrl_hum`/`ctrl_meas`/`config` fields (oversampling, mode incl. parallel, filter), `ctrl_gas_0/1` (heat_off, run_gas, nb_conv), `gas_wait_x`/`gas_wait_shared` (ms in forced mode, repetitions in parallel mode), `res_heat_x`, the three data fields (raw ADC values; status bits `new_data`, `measuring`, `gas_measuring`, `gas_meas_index`, `sub_meas_index`, `gas_valid_r`, `heat_stab_r`, gas range and gas resistance in Ω), the IDs (`chip_id` verified against `0x61`, `variant_id` against `0x01`) and the soft-reset write; warns on writes to `ctrl_meas` before `ctrl_hum` in a configuration burst, on `mode` writes while a measurement is running and on a `ctrl_gas_1` write that sets bit 4 only (BME680 layout). No timing annotation pair is emitted.
