# Chip Spec: RRH46410

**Manufacturer:** Renesas  
**Datasheet:** `datasheets/gas/rrh46410.pdf` (RRH46410 Digital Gas Sensor Module for Indoor Air Quality Applications, R36DS0035EU0102 Rev. 1.02, 26 March 2025)  
**Category:** gas  
**Transports:** I²C

## Overview

The RRH46410 is a digital metal-oxide (MOx) gas sensor module for indoor air quality, combining the Renesas ZMOD4410 MEMS sensing element with a signal-processing ASIC that runs the vendor algorithms on-chip. It reports a calibrated **Indoor Air Quality (IAQ) index** (UBA levels 1–5), the **total volatile organic compounds (TVOC)** concentration in mg/m³, an **ethanol equivalent** in ppm, an **estimated CO₂ (eCO₂)** in ppm and a **relative IAQ** value, depending on the operation mode: *IAQ 2nd Gen* (sample every 3 s), *ULP* (ultra-low-power, sample every 90 s, 0.23 mW) and *PBAQ* (public-building air-quality, TVOC and ethanol only, every 5 s). Every mode needs a warm-up (100 samples ≈ 5 min, 10 samples ≈ 15 min, 60 samples ≈ 5 min respectively) before the results are valid; a one-time "sensor cleaning" mode (1 minute) is used once in the sensor's lifetime. The host talks to the module with a request/response command protocol with a 1-byte checksum over I²C (up to 400 kHz) or UART (9600 baud); an `INT` pin signals new data. Optionally the host can supply the ambient relative humidity for compensation. Supply 1.8–3.6 V; 6.02 mW in IAQ 2nd Gen mode, 0.7–4.1 µA in suspend. Typical uses: air purifiers, thermostats, ventilation control, smart-home environment monitors.

## Transport Configuration

### I²C
- **Address:** `0x38` (7-bit, fixed default; one module per bus)
- **Max clock:** 400 kHz (standard mode ≤ 100 kHz also supported); the module **stretches the clock**, so the master must support clock stretching
- **Command protocol:** a **write** transaction carries `command byte, parameter bytes…, checksum`; the **response** is read in a **separate read transaction** (a repeated START or a new START after the write, or a STOP between them): `status byte, parameter bytes…, checksum`. A READ without a preceding write returns `0xFF` bytes and sets error bit 7. A new START + write aborts an unfinished response read and starts a new request
- **Checksum:** `checksum = ~LSB(command + parameters…)` (the sum of the bytes and the checksum is `0xFF`), identical for requests (command + parameters) and responses (status byte + parameters)
- **Register addressing:** none (command protocol)
- **Identity register:** none; `Get Product ID` (`0x00`) returns product ID `0x2310` (2 bytes) and a 3-byte firmware version. Registered in `registry/chips.json` with `id_probe: null`
- **Probe safety:** `write_sensitive` — any written bytes are parsed as a command (`0x8F` resets, `0x11` changes the operation mode, `0x42` writes flash). A probe should only send the read-only `Get Product ID` request

The UART interface (9600 baud, 8N1, same frame format, needs a resynchronisation procedure after reset) is not part of this spec.

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| INT | high, push-pull | high when new data is available, low after the host read the result (`Get Measurement Results` or `Set Operation Mode` sets it low); no external pull-up |
| RESET_ | low | external reset (active low); a rising edge restarts the module |
| GPIO1, GPIO2 | — | host-controlled I/O (`Config GPIO`, `Get GPIO`, `Set GPIO`, `Clear GPIO`); GPIO3, GPIO4 are inputs and must not float |
| SDA, SCL | — | I²C; pull-ups required (clock stretching) |
| RXD, TXD | — | UART (not used for I²C) |
| REGC | — | regulator capacitor: 0.47–1 µF to VSS |
| VDD, VSS | — | 1.8–3.6 V |

## Command Set

| Code | Command | Request parameters | Response parameters |
|------|---------|--------------------|---------------------|
| `0x00` | Get Product ID | — | 5 bytes: product ID (2), firmware version (3) |
| `0x01` | Get Tracking Number | — | 6 bytes (ASIC tracking number) |
| `0x10` | Get Operation Mode | — | 1 byte: the current mode |
| `0x11` | Set Operation Mode | 1 byte: new mode | — |
| `0x12` | Set Humidity | 1 byte: `round(humidity_percent / 100 × 255)` | — |
| `0x18` | Get Measurement Results | — | N bytes (mode dependent, see Data Conversion) |
| `0x20` | Config GPIO | 1 byte: bit 0 GPIO1 output, bit 1 GPIO2 output | — |
| `0x21` | Get GPIO | — | 1 byte: bits 0–3 = GPIO1–4 levels |
| `0x22` | Set GPIO | 1 byte mask (bits 0–1) | — |
| `0x23` | Clear GPIO | 1 byte mask (bits 0–1) | — |
| `0x31` | Read Debug Data | — | N bytes |
| `0x40` | Read Flash Shadow | 1 byte: index | 1 byte |
| `0x41` | Write Flash Shadow | 2 bytes: index, value | — |
| `0x42` | Write Flash | — | 1 byte |
| `0x8F` | Reset | — | **no response**; up to 500 ms until all functions are available again |

**Operation modes** (`Set Operation Mode` / `Get Operation Mode`): `0x00` SUSPEND (default after power-up), `0x01` IAQ 2nd Gen, `0x02` ULP, `0x03` SUSPEND, `0x04` do not use, `0x05` PBAQ, `0x80` sensor cleaning, other values = SUSPEND. `Set Operation Mode` stops a running measurement, changes the mode (not the start-up mode) and sets INT low.

**Status byte** (first byte of every response except Reset): bit 7 invalid command / I²C read without a preceding write / I²C or UART error; bit 6 request checksum wrong; bit 5 internal gas-sensor I²C NACK; bit 4 an asynchronous command was not complete when the result was requested; bits 3:0 the operation-mode error code (`0x0` OK, `0xA` damage).

The data flash holds the product ID (`0x2310`) and the sensor configuration; the flash commands (`0x40`–`0x42`) are for factory use and are not exposed by the Minimal driver.

## Initialization Sequence

1. Power up VDD (1.8–3.6 V); wait ≥ 500 ms (or after `RESET_`/`Reset` command: up to 500 ms) for the module to become available.
2. Send `Get Product ID`; verify the product ID `0x2310` and the checksum.
3. Optionally send `Set Humidity` (ambient RH, default 50 %).
4. Send `Set Operation Mode` (`0x01` IAQ 2nd Gen, `0x02` ULP or `0x05` PBAQ).
5. Wait for `INT` to go high (or poll `Get Measurement Results` every sample period: 3 s / 90 s / 5 s); the first results are valid only after the warm-up (100 / 10 / 60 samples; values are fixed during warm-up).
6. Read the results with `Get Measurement Results`; the sample counter in the first byte increments with every new sample.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `INT` — active-high, push-pull (high when data is available, low when read out) |
| Level | 1 |
| Condition(s) | a new measurement result is available |
| Clear mechanism | `Get Measurement Results` (or `Set Operation Mode`) sets INT low |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on INT (rising edge) via `connection.int_pin` (or `int_pin`), otherwise a 200 ms polling task comparing the sample counter; `callback(result)` receives the decoded measurement and the driver reads it (clearing INT); a repeated edge without a new sample counter is ignored. C++ calls `callback()` (no arguments, interrupt context) only when an INT pin is wired and the caller reads the result with `read_results`; Rust offers `poll_interrupt` only |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> bool` | `True` if the INT pin is high (pin available) or the sample counter changed since the last decoded result; the result is not consumed (the counter is compared, not stored) |

## Implementation Stages

### Minimal

Goal: read the air-quality values with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Stores the plain `Connection`; waits for the module (retries `Get Product ID` for up to 1 s), verifies the product ID `0x2310`, selects the IAQ 2nd Gen mode (`0x01`) |
| `read` | — | `{iaq, tvoc_mg_m3, etoh_ppm, eco2_ppm, relative_iaq, sample, warmed_up}` | `Get Measurement Results`; waits for a new sample (sample counter different from the last decoded one; the first result after a mode change counts as new) by polling every 200 ms — when `connection.int_pin` is wired only while INT is high — up to the sample period plus 2 s, then raises; decodes the values; `warmed_up` is `False` until 100 samples (≈ 5 minutes) after the start, counted from the sample counter (the modulo-256 differences between decoded results are summed, so the count survives the wrap) |

**Sensible defaults:** IAQ 2nd Gen mode (3 s sample), ambient humidity 50 % (module default), no GPIO use.

### Full

Goal: complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `product_id` | — | `(product_id, firmware)` | `Get Product ID` decoded: product ID (`0x2310`) and the firmware version `(major, minor, patch)` |
| `tracking_number` | — | `bytes` (6) | `Get Tracking Number` |
| `get_mode` / `set_mode` | — / `mode: int` | int / — | `Get Operation Mode` / `Set Operation Mode`; constants `MODE_SUSPEND`, `MODE_IAQ_2ND_GEN`, `MODE_ULP`, `MODE_PBAQ`, `MODE_CLEANING`; `set_mode` accepts only `MODE_SUSPEND`, `MODE_IAQ_2ND_GEN`, `MODE_ULP` and `MODE_PBAQ` (cleaning goes through `clean_sensor`) and resets the warm-up count |

| interrupt API | | | see Interrupt section |

**Additional configuration options:** operation mode, ambient humidity, GPIO direction/state.

## Data Conversion

```
# request:  [command, params..., checksum]    checksum = (~(command + sum(params))) & 0xFF
# response: [status, params..., checksum]     checksum over status + params; the sum of all bytes' LSB is 0xFF

# Get Measurement Results, response parameter bytes (big-endian 16-bit values):
# IAQ 2nd Gen / ULP:   [sample][iaq][tvoc_hi tvoc_lo][etoh_hi etoh_lo][eco2_hi eco2_lo][rel_iaq]   (9 bytes)
# PBAQ:                [sample][tvoc_hi tvoc_lo][etoh_hi etoh_lo]                                  (5 bytes)

iaq_level      = raw_iaq / 10                 # UBA level 1.0 .. 5.0
tvoc_mg_m3     = raw_tvoc / 100               # IAQ 2nd Gen and ULP
tvoc_mg_m3     = raw_tvoc / 1000              # PBAQ
etoh_ppm       = raw_etoh / 100               # IAQ 2nd Gen and ULP
etoh_ppm       = raw_etoh / 1000              # PBAQ
eco2_ppm       = raw_eco2                     # ppm, no scaling
relative_iaq   = raw_rel * 10                 # see note on the datasheet notation

humidity_code  = round(percent / 100 * 255)   # Set Humidity
```

UBA / Renesas IAQ rating (Table 4): IAQ ≤ 1.9 level 1 "very good" (< 0.3 mg/m³ TVOC), 2.0–2.9 level 2 "good" (0.3–1.0), 3.0–3.9 level 3 "medium" (1.0–3.0), 4.0–4.9 level 4 "poor" (3.0–10.0), ≥ 5.0 level 5 "bad" (> 10.0 mg/m³). The datasheet notes that 10 mg/m³ is about 5 ppm TVOC (conversion factor about 0.5). Values saturate at `0xFF` (1 byte) and `0xFFFF` (2 bytes) and never overflow. The datasheet's "bit encoding" column writes the divisors as `IAQ / 10`, `TVOC / 100`, … and `RELIAQ * 10`; the driver interprets them as the conversion from the raw byte to the physical value (`physical = raw / 10` etc.); verify the relative-IAQ factor on hardware and in the Renesas ZMOD4410 application notes. The sample counter in the first byte is 0 when a measurement starts and increments with each sample; it wraps at 256.

## Timing Constraints

| Constraint | Value |
|------------|-------|
| Sample period: IAQ 2nd Gen / ULP / PBAQ | 3 s / 90 s / 5 s |
| Warm-up: IAQ 2nd Gen / ULP / PBAQ | 100 samples (5 min) / 10 samples (15 min) / 60 samples (5 min); results fixed during warm-up |
| Stability | 48 hours of continuous operation recommended for best stability |
| After `Reset` (`0x8F`) | up to 500 ms until all functions are available |
| Sensor cleaning | 1 minute, once in the sensor's lifetime |
| I²C clock | ≤ 400 kHz; the master must support clock stretching |

The sample periods are measurement-cycle times, not bus-checked limits (the module is a free-running sensor with only an `INT` pin as marker), so `rrh46410_timing.conf` defines no checks.

## Implementation Notes

- **Plain Connection, command protocol:** write the request with `write`, then read the response with `read(1 + n + 1)`; each request and response carries a checksum. Do not use a register-addressed connection. The response is only valid after the matching request; a read without a request returns `0xFF` bytes and sets status bit 7.
- **Clock stretching:** the module stretches SCL; on hosts without clock-stretching support (some SoC I²C controllers) lower the bus speed or use a software bus.
- **Verify the checksum of every response** and the status byte; raise on a non-zero error nibble (`0xA` = sensor damaged).
- **Asynchronous commands:** the measurement is produced by the module on its own; if `Get Measurement Results` is requested before the first result of a mode exists, status bit 4 is set — retry after the sample period.
- **Sample counter:** use the counter byte (not just INT) to detect a new sample; do not read faster than the sample period.
- **Mode changes** stop the running measurement and restart the warm-up; the module always starts in SUSPEND after power-up or reset (the start-up mode cannot be changed by `Set Operation Mode`).
- **Cleaning:** execute the 1-minute cleaning at most once, must not be interrupted by a power loss (three starts at most); a repeated start returns the module straight to SUSPEND, which also tells whether cleaning has been done.
- **Units:** TVOC in mg/m³ and ethanol equivalent/eCO₂ in ppm are the module's units (SI-derived/mole fraction); no non-SI units are used. Humidity is %RH in the API and an 8-bit code on the wire.
- **Environment:** the MOx element reacts to humidity, temperature changes and cross-sensitivities (Section "Environmental Influences" of the datasheet); readings need a stable warm-up and are not absolute outside the IAQ definition.
- **Driver behaviour:** the result is read with 1 + 9 + 1 bytes (1 + 5 + 1 in PBAQ mode, selected from the mode last set or read); every response checksum is verified, and a non-zero status byte raises (except status `0x10` from `Get Measurement Results`, which means "no result yet"). `init` and `reset` retry `Get Product ID` every 50 ms for up to 1 s. Errors raise the language's I/O error type carrying the status byte where there is one: Python `RRH46410Error.status`, JavaScript `RRH46410Error.status`, JVM `Rrh46410Exception.status()`, Go `*RRH46410StatusError` (plus `ErrRRH46410Checksum`, `ErrRRH46410Timeout`, `ErrRRH46410ProductID`, `ErrRRH46410Argument`), Rust `Error::Status` (plus `Checksum`, `Timeout`, `InvalidProductId`, `InvalidArgument`), C++ `last_error()` (a positive status byte or a negative `ERR_*` value) with `false` / `-1` returns.
- **Address overlap:** `0x38` is shared with the FT6x06 touch controller, PCF8574A (`0x38`–`0x3F`) and AHT10/AHT20/AHT21 (`0x38`); the chip has no ID register, so probe with `active=True` only and verify with `Get Product ID` (`0x2310`).

## Sigrok Decoder

Decoder id `rrh46410`, input `['i2c']`. Matches I²C address `0x38`. Annotates each write transaction as a request (command name, parameters, checksum validity) and each read transaction as a response (status byte decoded bit by bit, parameters, checksum validity); decodes `Get Product ID`, the operation mode names, `Set Humidity` (percent) and `Get Measurement Results` into IAQ, TVOC, ethanol equivalent, eCO₂ and relative IAQ using the mode last seen. Warns on checksum errors, on a read without a preceding request and on error bits in the status byte. No conformance annotation pair is emitted (no checked timing constraint).
