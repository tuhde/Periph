# Chip Spec: CCS811

**Manufacturer:** ScioSense (ams)  
**Datasheet:** `datasheets/gas/ccs811.pdf` (CCS811 Ultra-Low Power Digital Gas Sensor for Monitoring Indoor Air Quality, ams datasheet v1-00, 2016-Dec-23)  
**Category:** gas  
**Transports:** I²C

## Overview

The CCS811 is a MOx gas sensor with an on-chip microcontroller and ADC that reports an equivalent CO₂ (eCO₂, 400–8192 ppm) and a total volatile organic compound (TVOC, 0–1187 ppb) value from its internal algorithm, plus the raw sense current/voltage. Four drive modes trade update rate and power: mode 1 (constant power, every second), mode 2 (pulse heating, every 10 s), mode 3 (low-power pulse heating, every 60 s) and mode 4 (constant power, raw data every 250 ms, no algorithm output). Temperature and relative humidity can be written to improve the compensation, an optional NTC thermistor circuit lets the chip measure the ambient temperature, an interrupt pin signals new data or threshold crossings and a baseline register lets the host save and restore the learned baseline. After power-up the chip starts in a **bootloader** mode and must be switched to **application** mode with `APP_START`. Supply 1.8–3.6 V, I²C up to 400 kHz with clock stretching. Typical uses: indoor air quality monitoring, HVAC, smart home. New sensors need a 48 h burn-in and each power-up a 20 min warm-up (see Implementation Notes).

## Transport Configuration

### I²C
- **Address:** `0x5A` (`ADDR` low) — `0x5B` (`ADDR` high)
- **Max clock:** 400 kHz (10–400 kHz); the chip **stretches the clock**, the master must support it
- **Identity register:** `0x20` (`HW_ID`) = `0x81` (works in boot and application mode). Registered in `registry/chips.json`
- **Probe safety:** `register_pointer` — reads of `HW_ID` are side-effect free; writing to `0xF1`–`0xF4`, `0xFF` and `0x01` changes chip state
- **Register addressing:** 8-bit register ("mailbox") address; a read must not exceed the register size; only one register per transaction (no auto-increment across registers). Reads of `ALG_RESULT_DATA` clear `DATA_READY`
- **nWAKE:** the pin must be low (asserted) before and during every I²C transaction (`tAWAKE` ≥ 50 µs before, ≥ 20 µs de-asserted between); it may be tied to ground if the pin is not available

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| nINT | low, open-drain | interrupt on new data and/or threshold crossing — requires external pull-up |
| nWAKE | low | wake input; assert low before and during I²C; may be tied to GND |
| nRESET | low | hardware reset (≥ 20 µs low; active again within 1–2 ms) |
| ADDR | — | selects `0x5A` (low) or `0x5B` (high) |
| NTC (AUX) | — | optional NTC thermistor circuit (R_REF/R_NTC) for temperature |
| SCL, SDA | — | I²C, external pull-ups |
| VDD, GND | — | 1.8–3.6 V |

## Register Map

| Address | Name | R/W | Size | Description |
|---------|------|-----|------|-------------|
| `0x00` | STATUS | R | 1 | Mode, application-valid, data-ready, error flags |
| `0x01` | MEAS_MODE | R/W | 1 | Drive mode and interrupt configuration |
| `0x02` | ALG_RESULT_DATA | R | 2–8 | eCO₂ (2 bytes), TVOC (2), STATUS, ERROR_ID, RAW_DATA (2) |
| `0x03` | RAW_DATA | R | 2 | Sense current (bits 15:10, µA) and ADC voltage (bits 9:0, 1023 = 1.65 V) |
| `0x05` | ENV_DATA | W | 4 | Humidity (1/512 %RH, 2 bytes) and temperature (1/512 °C + 25 °C offset, 2 bytes) |
| `0x06` | NTC | R | 4 | Voltage across R_REF and R_NTC (mV, 2 bytes each) |
| `0x10` | THRESHOLDS | W | 5 | Low/medium threshold (2), medium/high threshold (2), hysteresis (1), in ppm |
| `0x11` | BASELINE | R/W | 2 | Encoded baseline |
| `0x20` | HW_ID | R | 1 | `0x81` |
| `0x21` | HW_VERSION | R | 1 | `0x1X` |
| `0x23` | FW_BOOT_VERSION | R | 2 | Bootloader firmware version |
| `0x24` | FW_APP_VERSION | R | 2 | Application firmware version |
| `0xE0` | ERROR_ID | R | 1 | Error source |
| `0xF1` | APP_ERASE | W | 4 | Bootloader: `0xE7 0xA7 0xE6 0x09` erases the application |
| `0xF2` | APP_DATA | W | 9 | Bootloader: firmware chunk |
| `0xF3` | APP_VERIFY | W | 0 | Bootloader: verify the application |
| `0xF4` | APP_START | W | 0 | Bootloader → application mode (write with no data) |
| `0xFF` | SW_RESET | W | 4 | `0x11 0xE5 0x72 0x8A` resets the chip into boot mode |

### Bit Fields

#### `STATUS` (`0x00`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | FW_MODE | 0 = boot mode, 1 = application mode (ready for measurements) |
| 6 | APP_ERASE_DONE | Bootloader: 1 after an application erase (cleared by reset or app start) |
| 4 | APP_VALID | 1 = valid application firmware loaded |
| 3 | DATA_READY | 1 = new sample in `ALG_RESULT_DATA` (cleared when it is read) |
| 0 | ERROR | 1 = error on the I²C interface or the sensor (see `ERROR_ID`) |

#### `MEAS_MODE` (`0x01`)

| Bits | Name | Description |
|------|------|-------------|
| 6:4 | DRIVE_MODE | `000` idle, `001` mode 1 (1 s), `010` mode 2 (10 s), `011` mode 3 (60 s), `100` mode 4 (250 ms, raw data only) |
| 3 | INT_DATARDY | 1 = `nINT` asserts when a new sample is ready (released when `ALG_RESULT_DATA` is read) |
| 2 | INT_THRESH | 1 = interrupt only when eCO₂ crosses a `THRESHOLDS` boundary by more than the hysteresis |

#### `ERROR_ID` (`0xE0`)

| Bit | Name | Meaning |
|-----|------|---------|
| 0 | WRITE_REG_INVALID | Write to an invalid register |
| 1 | READ_REG_INVALID | Read of an invalid register |
| 2 | MEASMODE_INVALID | Invalid `DRIVE_MODE` requested |
| 3 | MAX_RESISTANCE | Sensor resistance reached its maximum |
| 4 | HEATER_FAULT | Heater current out of range |
| 5 | HEATER_SUPPLY | Heater voltage not applied correctly |

## Initialization Sequence

1. Power VDD (1.8–3.6 V) with `nWAKE` low; wait `tSTART` ≤ 20 ms after power-on (≤ 2 ms after `nRESET`).
2. Read `HW_ID` (`0x20`), expect `0x81`.
3. Read `STATUS`; if `APP_VALID` = 0 the chip has no application and cannot measure. If `FW_MODE` = 0, write `APP_START` (`0xF4`, no data) and wait ≥ 1 ms (the datasheet allows up to 20 ms after reset); re-read `STATUS` for `FW_MODE` = 1.
4. Optionally write `ENV_DATA` (humidity/temperature) and `THRESHOLDS`, and restore a saved `BASELINE`.
5. Write `MEAS_MODE` with the drive mode (e.g. `0x10` = mode 1, no interrupt).
6. Poll `STATUS.DATA_READY` (or watch `nINT`); read `ALG_RESULT_DATA` (4–8 bytes) and verify `STATUS.ERROR`.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | active-low, open-drain — requires external pull-up |
| Level | 2 |
| Condition(s) | new data ready, or (with `INT_THRESH`) eCO₂ crossing the low/medium or medium/high threshold by more than the hysteresis |
| Clear mechanism | read `ALG_RESULT_DATA` (`0x02`) |

### Interrupt sources

| Constant | Value | Condition |
|----------|-------|-----------|
| `SOURCE_DATA_READY` | `0x01` | New sample (`INT_DATARDY`) |
| `SOURCE_THRESHOLD` | `0x02` | Threshold crossing (`INT_DATARDY` + `INT_THRESH`) |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback)` | Subscribe; callback receives the `STATUS` byte |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Read `STATUS` (does not clear the pin; the pin is released by reading `ALG_RESULT_DATA`) |
| `enable_interrupt` | `enable_interrupt(source)` | Set `INT_DATARDY` (and `INT_THRESH` for the threshold source) preserving `DRIVE_MODE` |
| `disable_interrupt` | `disable_interrupt(source)` | Clear the bits |

### Status register bit layout

| Bit | Constant | Meaning |
|-----|----------|---------|
| 3 | `SOURCE_DATA_READY` | New sample ready |
| 0 | `STATUS_ERROR` | Error flag |

## Implementation Stages

### Minimal

Goal: read eCO₂ and TVOC with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Takes the `RegisterConnection`; checks `HW_ID` = `0x81`, starts the application (`APP_START`) if in boot mode (raises if `APP_VALID` = 0), sets drive mode 1 (1 s) with interrupts off |
| `read` | — | `{eco2_ppm, tvoc_ppb}` | Waits for `DATA_READY` (up to 1.5 s), reads `ALG_RESULT_DATA` (5 bytes), raises on the `ERROR` flag, returns eCO₂ and TVOC |

**Sensible defaults:** mode 1 (constant power, 1 s), no environment data (the chip defaults of 50 %RH and 25 °C), interrupts off.

### Full

Goal: complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `read_eco2` / `read_tvoc` | — | int | One value |
| `read_raw` | — | `(current_ua, voltage_v)` | `RAW_DATA`: current 0–63 µA, voltage = ADC × 1.65 / 1023 |
| `data_ready` | — | bool | `STATUS.DATA_READY` |
| `set_mode` | `mode: int` (0–4) | — | `DRIVE_MODE` (keeps the interrupt bits); mode 4 yields raw data only |
| `set_environment` | `humidity_rh: float, temperature_c: float` | — | `ENV_DATA`: humidity × 512 (2 bytes), (temperature + 25) × 512 (2 bytes) |
| `read_ntc` | — | `(v_ref_mv, v_ntc_mv)` | `NTC` register |
| `ntc_resistance` | `r_ref_ohm: float` | float | `V_NTC × R_REF / V_REF` |
| `set_thresholds` | `low_medium_ppm: int, medium_high_ppm: int, hysteresis_ppm: int = 50` | — | `THRESHOLDS` (defaults 1500/2500 ppm) |
| `get_baseline` / `set_baseline` | — / `baseline: int` | int / — | `BASELINE` (restore only after ≥ 20 min of operation, see notes) |
| `status` | — | int | `STATUS` |
| `error` | — | int | `ERROR_ID` |
| `hardware_version` | — | `(hw_id, hw_version)` | `0x20`, `0x21` |
| `firmware_version` | — | `{boot: (major, minor, trivial), app: (...)}` | `0x23`, `0x24` |
| `soft_reset` | — | — | `SW_RESET` sequence, then re-runs the application start |
| `on_interrupt` / `off_interrupt` / `poll_interrupt` / `enable_interrupt` / `disable_interrupt` | see Interrupt | | |

**Additional configuration options:** drive mode, interrupt mode and thresholds, environment compensation, baseline save/restore, NTC temperature circuit.

## Data Conversion

```
eco2_ppm   = b0 << 8 | b1            # 400 .. 8192 (clipped)
tvoc_ppb   = b2 << 8 | b3            # 0 .. 1187 (clipped)
raw        = b6 << 8 | b7
current_ua = raw >> 10               # 0 .. 63 uA
adc        = raw & 0x3FF             # 1023 = 1.65 V -> voltage_v = adc * 1.65 / 1023

humidity_word    = round(humidity_rh * 512)               # default 50 %RH = 0x6400
temperature_word = round((temperature_c + 25) * 512)      # 0 maps to -25 degC, default 25 degC = 0x6400
r_ntc            = V_NTC * R_REF / V_REF                  # ohms, then use the thermistor datasheet curve
```

Units: ppm for eCO₂, ppb for TVOC, °C, %RH, µA and volts for the raw data.

## Timing Constraints

| Constraint | Value |
|------------|-------|
| Time until active after power-on (`tSTART`) | ≤ 20 ms (typ. 18 ms) |
| Time until active after `nRESET` | ≤ 2 ms (typ. 1 ms) |
| `nWAKE` setup before I²C (`tAWAKE`) / minimum de-assert (`tDWAKE`) | ≥ 50 µs / ≥ 20 µs |
| `nRESET` low pulse | ≥ 20 µs |
| Measurement interval | 250 ms / 1 s / 10 s / 60 s per mode |
| Burn-in / warm-up | 48 h burn-in on first use; about 20 min warm-up after power-up |
| I²C clock | 10–400 kHz, clock stretching |

The datasheet bounds are host waits on pins and power-up and not bus-decodable start/end pairs, so `ccs811_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection:** accept `RegisterConnection` and use `connection.read(reg, length)` / `connection.write(reg, data)` directly; one register per transaction. See `specs/feature_register_access_design.md`.
- **Boot vs. application mode:** after reset the chip is in boot mode and only the bootloader registers and `STATUS`/`HW_ID`/versions respond; `APP_START` is a write with no data bytes (register address only). The driver verifies `FW_MODE` = 1 afterwards.
- **Clock stretching:** required; on hosts without it lower the bus speed (e.g. 10–50 kHz) or use a bit-banged bus.
- **nWAKE:** if the wake pin is wired, the driver drives it low around each transaction (optional `OutputPin`); tying it low is the simplest option.
- **Read size:** never read more bytes than a register holds; `ALG_RESULT_DATA` may be read as 2, 4, 5 or 8 bytes.
- **Mode 4:** `ALG_RESULT_DATA` is not updated, only `RAW_DATA`; mode changes should pass through idle (mode 0) and take effect on the next cycle; after a mode change from a higher update rate to a lower one, the data at the old rate may be stale.
- **Burn-in and warm-up:** sensor resistance changes most over the first 48 h; run it that long once. After each power-up allow about 20 min before trusting eCO₂/TVOC, and only write a stored baseline after the sensor has run for at least that long; save the baseline periodically (e.g. every 24 h) in non-volatile storage.
- **ENV_DATA:** supplying real temperature and humidity improves accuracy; default is 50 %RH, 25 °C.
- **Algorithm values:** eCO₂ is an estimate derived from the TVOC, not a measured CO₂; ranges clip at 400–8192 ppm and 0–1187 ppb.
- **Address:** `0x5A`/`0x5B` are shared with other chips; `HW_ID` = `0x81` identifies the CCS81x family (CCS811 and the compatible CCS810 variants).

## Sigrok Decoder

Decoder id `ccs811`, input `['i2c']`. Matches I²C addresses `0x5A` and `0x5B`. Annotates register accesses by name and decodes `STATUS`, `MEAS_MODE` (drive mode, interrupt bits), `ALG_RESULT_DATA` (eCO₂, TVOC, status, error, raw), `RAW_DATA`, `ENV_DATA` (humidity %RH and temperature °C), `NTC`, `THRESHOLDS`, `BASELINE`, `ERROR_ID`, versions and the `APP_START`/`SW_RESET` sequences; warns on reads longer than the register size, on writes to `MEAS_MODE` in boot mode, on a `SW_RESET` with a wrong key and on error flags. No conformance annotation pair is emitted (no checked timing constraint).
