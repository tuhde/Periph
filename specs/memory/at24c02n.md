# Chip Spec: AT24C02N

**Manufacturer:** Microchip Technology (formerly Atmel)  
**Datasheet:** `datasheets/memory/at24c02n.pdf` (doc0180 (AT24C01A/02/04/08A/16A family))  
**Category:** memory  
**Transports:** I²C

## Overview

The AT24C02N is a 2 Kbit (256 × 8) serial EEPROM with a two-wire (I²C) interface. Writes are self-timed (5 ms max) with 8-byte page-write buffering; after the STOP that ends a write the chip does not ACK until the cycle is finished (**ACK polling**). Reads are unrestricted and auto-increment through the whole array. Typical uses: configuration, calibration and parameter storage, small logs. The same datasheet also covers AT24C01A (128 B), AT24C04 (512 B), AT24C08A (1 KiB) and AT24C16A (2 KiB). They differ in page size (16 B for 4–16 Kbit), use fewer A-pins and take upper address bits from the device address byte (block select); they are **not** covered by this spec. AT24C02 is marked "not recommended for new designs" by the manufacturer (replaced by AT24C02B/C).

## Transport Configuration

### I²C
- **Address:** `0x50` + (A2 A1 A0) — `0x50`…`0x57`; A0–A2 select `0x50`–`0x57` (all three are compared on the 2 Kbit part); up to eight devices per bus. The device-select byte is `1010 A2 A1 A0 R/W`.
- **Max clock:** 400 kHz (VCC ≥ 2.7 V); 100 kHz (VCC = 1.8 V)
- **Supply:** 1.8–5.5 V (1.8 V and 2.7 V grade versions)
- **Memory addressing:** 1 address byte (word address `0x00`–`0xFF`), so the chip is driven as a `RegisterConnection` with `reg_bytes` = 1 (see `specs/feature_register_access_design.md`).
- **Identity register:** none — the address range is shared with all 24xx EEPROMs and FRAMs (`id_probe: null` in `registry/chips.json`).
- **Probe safety:** `register_pointer` — a lone address write only sets the internal address pointer; no data is written until a data byte follows.

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| A0, A1, A2 | — | device address; tie to VCC or GND |
| WP | high | write protect: WP high protects the **entire array** against writes (reads unaffected); WP low or open (internally pulled down) allows writes |
| SDA | — | open drain, external pull-up required |
| SCL | — | clock |
| VCC | — | 1.8–5.5 V (1.8 V and 2.7 V grade versions) |

No interrupt pins.

## Memory Map

| Address Range | Name | R/W | Description |
|---------------|------|-----|-------------|
| `0x0`–`0xFF` | EEPROM | R/W | 256 bytes in 32 pages of 8 bytes |

There are no control or status registers. Page boundaries fall at multiples of 8.

## Initialization Sequence

No registers to initialise. After power-up (VCC stable) the chip is ready; presence can be checked by issuing a write-address (or a selective read) and checking for an ACK. The internal address pointer is undefined after power-up.

## Write Operations

- **Byte write:** S, `1010 A2A1A0 0`, address, data, P.
- **Page write:** the same with up to 8 data bytes before P; all bytes must lie in the same page. If more than 8 bytes are sent, the address counter wraps **within the page** and earlier bytes of that page are overwritten.
- **Write cycle:** starts at the STOP; the chip does not ACK its address until it completes (5 ms max).
- **ACK polling:** repeatedly send S + `1010 A2A1A0 0`; an ACK means the cycle is done (preferred over a fixed delay).
- **Write protect:** WP high protects the **entire array** against writes (reads unaffected); WP low or open (internally pulled down) allows writes.

## Read Operations

- **Random read:** S, device byte (W), address, rS, device byte (R), data, NACK, P (driver: `connection.read(address, 1)`).
- **Sequential read:** as random read, ACK each byte; the address wraps from `0xFF` to `0x0`.
- **Current address read:** S, device byte (R), data — address is the last accessed + 1. Not exposed.

## Interrupt

Level 0 — the chip has no interrupt output.

## Implementation Stages

### Minimal

Goal: persistent single-byte storage with no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Stores the connection (`RegisterConnection` with `reg_bytes` = 1); no bus traffic |
| `read_byte` | `address: int` (0–255) | `int` (0–255) | Random read; raises on an out-of-range address |
| `write_byte` | `address: int`, `value: int` | — | Byte write, then ACK-poll until the write cycle completes (timeout 5 ms + margin) |

**Sensible defaults:** none to set; `write_byte` always waits for completion via ACK polling.

### Full

Goal: complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `read` | `address: int`, `length: int` | `bytes` | Sequential read, split into chunks of `max_chunk` bytes; range must lie inside the array (no silent wrap) |
| `write` | `address: int`, `data: bytes` | — | Writes arbitrary data, split at 8-byte page boundaries (and `max_chunk`), ACK-polling after every page |
| `write_page` | `address: int`, `data: bytes` | — | One page write; raises if the data would cross a page boundary |
| `fill` | `address: int`, `length: int`, `value: int=0` | — | Writes `value` over a range (page-wise) |
| `size` | — | `int` | `256` |
| `page_size` | — | `int` | `8` |
| `wait_ready` | `timeout_ms: int` | `bool` | ACK-poll until the chip responds |
| `max_chunk` | property, default 30 | `int` | Maximum data bytes per transaction (Arduino `Wire` 32-byte limit including address bytes); settable |

**Additional configuration options:** `max_chunk` only. Write protect is a hardware pin.

## Data Conversion

None; data is raw bytes. Multi-byte addresses are big-endian on the wire.

## Examples

### Demo

Persistent boot counter and page-write benchmark. Read a 4-byte big-endian boot counter at address `0x0`, increment it, write it back and print it. Then write a 8-byte-aligned pattern across three pages with `write`, time it and print the achieved bytes per second including the ACK-polled write cycles, read it back with `read` and verify, show that `write_page` raises when crossing a page boundary, and `fill` the area with zero. ## Timing Constraints

| Constraint | Value |
|------------|-------|
| Write cycle time (tWR) | 5 ms max |
| Max I²C clock | 400 kHz (VCC ≥ 2.7 V); 100 kHz (VCC = 1.8 V) |
| ACK polling | poll immediately after the STOP; chip does not ACK until the cycle ends |
| Endurance / retention | 1,000,000 write cycles; 100 years |

**Conformance-checked constraint:** write cycle time via the `write_cycle_start` / `write_cycle_done` annotation pair (see Sigrok Decoder below); bound in `at24c02n_timing.conf`.

## Implementation Notes

- **Register-addressed:** accept `RegisterConnection` with `reg_bytes` = 1 and call `connection.read(address, length)` / `connection.write(address, data)` directly — no chip-local helpers.
- **Page wrap:** a write that crosses a 8-byte page boundary wraps to the start of the same page and silently corrupts data; `write` must split at page boundaries.
- **Write cycle:** no ACK during the cycle must not be mistaken for a missing device; ACK-poll with a timeout of the datasheet maximum plus margin.
- **Write protect is silent:** the driver cannot detect WP; verify with a read-back if the pin is wired.
- **Wrap-around on reads:** reads past `0xFF` continue at `0x0`; the driver refuses such ranges.
- **Address overlap:** `0x50`–`0x57` is shared with 24xx EEPROMs and FRAM; none has an identity register, so discovery cannot tell them apart (`specs/feature_i2c_discovery.md`).

## Sigrok Decoder

Decoder id `at24c02n`, input `['i2c']`. Matches I²C addresses `0x50`–`0x57`, annotates byte/page writes (address, data), random/sequential/current-address reads, and ACK polling (start + device byte with a missing ACK). It emits the conformance annotation pair `write_cycle_start` (at the STOP of a data write) and `write_cycle_done` (at the first ACKed device byte afterwards). Writes that wrap inside a page and access above `0xFF` are flagged as warnings.
