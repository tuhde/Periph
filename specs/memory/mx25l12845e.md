# Chip Spec: MX25L12845E

**Manufacturer:** Macronix International  
**Datasheet:** `datasheets/memory/mx25l12845e.pdf` (PM1428, REV. 1.8, Feb 2012)  
**Category:** memory  
**Transports:** SPI

## Overview

The MX25L12845E is a 128-Mbit (16 MiB) serial NOR flash with a 2.7–3.6 V supply. It is organised as 4096 sectors of 4 KiB, 512 blocks of 32 KiB and 256 blocks of 64 KiB, programmed in 256-byte pages. Flash can only be programmed from 1 to 0; any bit that must return to 1 needs an erase of its whole sector (4 KiB), block (32 / 64 KiB) or the whole chip. The chip also offers dual/quad-I/O reads, double-transfer-rate reads, a 4 Kbit secured OTP area (with a factory-programmed 128-bit electronic serial number), block-protect bits and individual block locks, deep power-down and SFDP. This spec covers **plain single-I/O SPI** (Mode 0); dual, quad, DTR, parallel (8-bit) and CP modes are not used.

The Full class implements `BlockDevice` (`specs/feature_block_device.md`): 512-byte blocks, 4 KiB erase units, `needs_erase = true`.

The command set used here (`READ`, `FAST_READ`, `PP`, `SE`, `BE`, `CE`, `RDSR`, `WRSR`, `WREN`, `RDID`, `DP`/`RDP`, `RDSFDP`) is the common JEDEC NOR subset that Winbond W25Q, GigaDevice GD25Q and many other 3-byte-addressed NOR chips share; the driver keeps the chip-specific parts (ID, geometry, protection table, OTP, timings) in constants so a later generic NOR driver can reuse it. This part has **no software reset** (`66h`/`99h`) and no 4-byte address mode; do not send command codes that are not listed here (the datasheet warns that unlisted codes may enter a hidden mode).

## Transport Configuration

### SPI
- **Mode:** 0 (CPOL=0 CPHA=0) or 3; the driver uses mode 0
- **Max clock:** 50 MHz for `READ` (`03h`); 104 MHz for `FAST_READ`, `PP`, `SE`, `BE`, `CE`, `RDSR`, `WRSR`, `RDID`, … (VCC 2.7–3.6 V)
- **Bit order:** MSB first
- **CS active:** low; CS must go high **exactly on a byte boundary** for every command that changes state (WREN, WRDI, WRSR, PP, SE, BE, CE, DP, …), otherwise the command is silently rejected
- **Register addressing:** none. Every command is an opcode byte, an optional 24-bit big-endian address and optional dummy/data bytes within one CS-low frame. This does not fit the `read_bit`/`multi_byte_bit` convention of `specs/feature_register_access_design.md`, so the driver takes the bare `Connection` (`write`, `write_read`) like `23X1024`.
- **Power-up:** wait `tVSL` = 300 µs after VCC reaches 2.7 V before the first command.

| Command | Code | Frame (after CS↓) | Notes |
|---------|------|-------------------|-------|
| `WREN` | `06h` | — | sets WEL; required before every program/erase/WRSR |
| `WRDI` | `04h` | — | clears WEL |
| `RDID` | `9Fh` | → `C2h 20h 18h` | manufacturer, memory type, density |
| `RES` | `ABh` | 3 dummy bytes → `17h` | electronic ID; also releases deep power-down |
| `REMS` | `90h` | 2 dummy, `00h` → `C2h 17h` | manufacturer + device ID (`01h` address swaps the order) |
| `RDSR` | `05h` | → status byte | readable at any time, even while busy |
| `WRSR` | `01h` | status byte | BP3:0, QE, SRWD; needs WREN; `tW` ≤ 100 ms |
| `READ` | `03h` | A23..A0 → data | ≤ 50 MHz, no dummy cycles; address wraps at the end of the array |
| `FAST_READ` | `0Bh` | A23..A0, 1 dummy byte → data | ≤ 104 MHz |
| `PP` | `02h` | A23..A0, 1–256 data bytes | programs within one 256-byte page; bytes past the page end wrap to the page start |
| `SE` | `20h` | A23..A0 | erase 4 KiB sector |
| `BE32K` | `52h` | A23..A0 | erase 32 KiB block |
| `BE` | `D8h` | A23..A0 | erase 64 KiB block |
| `CE` | `C7h` or `60h` | — | erase whole chip; only when BP3:0 = 0 |
| `DP` | `B9h` | — | deep power-down; only `RDP`/`RES` accepted afterwards |
| `RDP` | `ABh` | — | release deep power-down (same opcode as `RES`) |
| `RDSFDP` | `5Ah` | A23..A0, 1 dummy byte → data | SFDP parameter table |
| `ENSO` / `EXSO` | `B1h` / `C1h` | — | enter / exit the 4 Kbit secured OTP |
| `RDSCUR` | `2Bh` | → security register | |
| `WRSCUR` | `2Fh` | — | sets LDSO (OTP lock-down), irreversible |
| `CLSR` | `30h` | — | clears P_FAIL / E_FAIL |
| `WPSEL`, `SBLK`, `SBULK`, `GBLK`, `GBULK`, `RDBLOCK` | `68h`, `36h`, `39h`, `7Eh`, `98h`, `3Ch` | | individual block lock mode; **not used** (WPSEL is one-time and irreversible) |

Dual/quad/DTR reads (`BBh`, `EBh`, `0Dh`, `BDh`, `EDh`), `4PP` (`38h`), `CP` (`ADh`), `HPM` (`A3h`) and parallel mode (`55h`/`45h`) exist but are **not used**.

## Memory Map

| Address range | Unit | Count | Notes |
|---------------|------|-------|-------|
| `000000h`–`FFFFFFh` | 4 KiB sector | 4096 | `SE` granularity |
| | 32 KiB block | 512 | `BE32K` |
| | 64 KiB block | 256 | `BE`; BP protection granularity |
| | 256-byte page | 65 536 | `PP` granularity |

Total 16 777 216 bytes; 3-byte addressing only. Secured OTP: 4 Kbit (512 bytes), addresses `000h`–`1FFh` while in OTP mode; `000h`–`00Fh` are the 128-bit electronic serial number (ESN) area and `010h`–`1FFh` are free for the customer until locked. Whether the ESN is actually programmed depends on the part: security register bit 0 = 1 marks a factory-locked OTP; **the sample on the reference bench reads all `FFh` with bit 0 = 0**, i.e. no factory ESN, so `serial_number()` returns whatever the OTP holds and callers must check `read_security() & 1` before trusting it.

### Registers

#### Status register (`RDSR` / `WRSR`)

| Bit | Name | Description |
|-----|------|-------------|
| 7 | SRWD | status register write disable (non-volatile); with WP# low → hardware protected mode |
| 6 | QE | quad enable (non-volatile); **keep 0** — QE=1 disables WP# |
| 5:2 | BP3:BP0 | block protect (non-volatile), see table |
| 1 | WEL | write enable latch (volatile), set by `WREN`, cleared after program/erase/WRSR/WRDI |
| 0 | WIP | write in progress (volatile): 1 while a program, erase or WRSR runs |

Block protect (top of the array is protected): `BP=0` none; `1` top 2 × 64 KiB blocks; `2` top 4; `3` top 8; `4` top 16; `5` top 32; `6` top 64; `7` top 128 blocks (upper half); `8`–`15` all 256 blocks. `CE` is only accepted when BP3:0 = 0. A program/erase aimed at a protected area is ignored, resets WEL and sets P_FAIL/E_FAIL in the security register.

#### Security register (`RDSCUR`, read-only except via `WRSCUR`/`CLSR`)

| Bit | Name | Description |
|-----|------|-------------|
| 7 | WPSEL | individual block lock mode active (one-time, irreversible) |
| 6 | E_FAIL | last erase failed or hit a protected area (clear with `CLSR`) |
| 5 | P_FAIL | last program failed or hit a protected/locked area (clear with `CLSR`) |
| 4 | CP | continuous program mode active |
| 3:2 | — | reserved |
| 1 | LDSO | secured OTP locked down (customer; irreversible) |
| 0 | — | 1 = secured OTP locked at the factory |

## Initialization Sequence

1. Wait ≥ 300 µs after power-up (`tVSL`). CS high.
2. If a previous session left the chip in deep power-down, send `RDP` (`ABh`) and wait `tRES2` = 100 µs (harmless when it was not).
3. `RDID` (`9Fh`): expect `C2h 20h 18h`; anything else → `NotReady`.
4. `RDSR`: wait until WIP = 0 (a reset during a long erase can leave the chip busy for up to the erase time).
5. Nothing else is configured: QE stays 0, BP3:0 are left as found (the Full class exposes them).

## Interrupt

None.

## Implementation Stages

### Minimal

Class `MX25L12845EMinimal` — works out of the box as a 16 MiB byte-addressable store with transparent erase.

| Method | Description |
|--------|-------------|
| `MX25L12845EMinimal(connection)` | runs the init sequence; `NotReady` if the ID is wrong |
| `read_bytes(address, length)` | `READ` (`03h`), any length, any alignment |
| `write_bytes(address, data)` | **erase-aware write**: for each 4 KiB sector touched it reads the sector, and if only 1→0 transitions are needed it programs just the changed pages; otherwise it erases the sector and reprograms the merged contents. Needs a 4 KiB scratch buffer owned by the driver. Blocks until the chip is ready |
| `erase_sector(address)` | `SE`; the sector containing `address` |
| `size()` | 16 777 216 |
| `jedec_id()` | the three `RDID` bytes |

### Full

Class `MX25L12845EFull(Minimal)` — raw chip control, protection, power management, OTP; implements `BlockDevice`.

| Method | Description |
|--------|-------------|
| `fast_read(address, length)` | `FAST_READ` (`0Bh`) |
| `page_program(address, data)` | one `PP` of 1–256 bytes inside a single page (error if it would cross the page end); caller guarantees the bytes are erased |
| `erase_block_32k(address)`, `erase_block_64k(address)`, `chip_erase()` | `BE32K`, `BE`, `CE`; `chip_erase()` takes 80 s typ / 200 s max and polls with ≥ 10 ms spacing |
| `read_status()` / `write_status(value)` | `RDSR` / `WREN`+`WRSR` (waits for `tW`) |
| `protection()` / `set_protection(bp)` | BP3:0 (0–15) |
| `is_busy()`, `wait_ready(timeout_ms)` | WIP polling |
| `read_security()`, `clear_fail_flags()` | `RDSCUR`, `CLSR` |
| `deep_power_down()`, `release_deep_power_down()` | `DP` (≥ `tDP` 10 µs before the next command is meaningful) / `RDP` (wait `tRES2` 100 µs) |
| `electronic_id()`, `device_ids()` | `RES` → `17h`; `REMS` → `(C2h, 17h)` |
| `read_sfdp(address, length)` | `RDSFDP` |
| `read_otp(offset, length)`, `program_otp(offset, data)`, `lock_otp()` | `ENSO` … `EXSO` around normal read/program; `lock_otp()` sets LDSO via `WRSCUR` and is **irreversible**; the driver refuses to touch OTP bytes `000h`–`00Fh` (ESN) |
| `serial_number()` | the 16 bytes of OTP `000h`–`00Fh` (the factory ESN when `read_security() & 1`; blank `FFh` otherwise) |
| `auto_erase` (constructor option / property) | see "Block device" |
| BlockDevice: `block_size()`, `block_count()`, `erase_size()`, `needs_erase()`, `read`, `write`, `erase`, `sync`, `info` | see "Block device" |

## Block device

The Full class implements `BlockDevice` (`specs/feature_block_device.md`). The byte-addressed Minimal methods are named `read_bytes` / `write_bytes` so they do not collide with the block-addressed `BlockDevice.read` / `write`.

| `block_size` | `block_count` | `erase_size` | `needs_erase` | `bad_blocks` |
|--------------|---------------|--------------|---------------|--------------|
| 512 | 32 768 | 4096 (8 blocks) | true | false |

- `read(block, count)`: `READ` (or `FAST_READ`) of `count × 512` bytes.
- `write(block, data)`: before programming, each target page is read; if a 0→1 transition would be needed, `auto_erase = false` fails with `NotErased`, `auto_erase = true` performs the same sector read-modify-erase-write as `Minimal.write_bytes()`. Pages whose target bytes are all `FFh`-compatible are programmed directly with `PP` (≤ 256 B each, page-aligned chunks).
- `erase(block, count)`: the range must be 4 KiB-aligned (`OutOfRange` otherwise); uses `SE`, and `BE32K`/`BE` for aligned stretches of 32 / 64 KiB.
- `sync()`: waits for WIP = 0.
- After every program/erase the driver reads the security register; P_FAIL/E_FAIL set → `CLSR`, then `WriteProtected` if any BP bit is set, else `Io`.
- `info().name` = `"MX25L12845E"`; `read_only` is true when BP = 8…15 (everything protected).

## Data Conversion

| Quantity | Formula |
|----------|---------|
| Address bytes | `A23..A16`, `A15..A8`, `A7..A0` (big endian) |
| Sector / block of an address | `address >> 12`, `address >> 15` (32 KiB), `address >> 16` (64 KiB) |
| Logical block ↔ byte address | `block × 512` |
| BP → protected bytes | `BP = 0`: 0; `1…7`: `2^BP × 64 KiB` from the top; `8…15`: all |
| Page boundary | `address & ~0xFF`; a `PP` must satisfy `(address & 0xFF) + length ≤ 256` |

## Examples

### Demo

**Scenario:** an append-only **record log** on bare flash — the way settings or sensor samples are stored on a NOR chip without a filesystem.

1. Construct `MX25L12845EFull`, print the JEDEC ID, capacity and the serial-number area (the factory ESN if the part has one).
2. Treat sectors 0–3 as a ring. Find the write position by scanning for the first `FFh` record slot (32-byte records, 128 per sector).
3. Append 100 records (counter + tick) with `page_program` — no erase is needed while the slot is blank.
4. When a sector fills, erase the next sector (`erase_sector`) and continue there; print how long the erase took.
5. Read all records back, verify, and print program and erase timings.

## Timing Constraints

| Constraint | Value |
|------------|-------|
| `tVSL` (VCC min → CS low) | 300 µs |
| `tW` (WRSR) | 40 ms typ / 100 ms max |
| `tPP` (page program, 256 B) | 1.4 ms typ / 5 ms max |
| `tSE` (4 KiB sector erase) | 60 ms typ / 300 ms max |
| `tBE` (32 KiB / 64 KiB block erase) | 0.5 s / 0.7 s typ, 2 s max |
| `tCE` (chip erase) | 80 s typ / 200 s max |
| `tDP` (CS↑ → deep power-down) | 10 µs max |
| `tRES1` / `tRES2` (CS↑ → standby after RDP/RES) | 100 µs max |
| `tSHSL` (CS deselect) | ≥ 15 ns (read), ≥ 50 ns (program/erase) |
| `tSLCH` / `tCHSH` (CS setup / hold) | ≥ 5 ns |
| Max SCK | 50 MHz `READ`; 104 MHz everything else |

Operations are self-timed: after CS↑ the chip drops WIP only when done; the driver polls `RDSR` and gives up after the **max** value above (`Timeout`). No timing constraint gets a conformance check (all waits are bounded by WIP, not fixed times), so there is no `mx25l12845e_timing.conf`.

## Implementation Notes

- Always `WREN` before `PP`/`SE`/`BE`/`CE`/`WRSR`; WEL clears itself afterwards, so it must be set again for every operation.
- Poll WIP with `RDSR`; do not rely on the typical times. While WIP = 1 the chip ignores everything except `RDSR`, `RDSCUR`, `RDID`-class reads and `CLSR`.
- `PP` wraps inside the page: never let a program frame cross a 256-byte boundary — split writes at page boundaries (the datasheet's "address wraps within the page" would otherwise overwrite the start of the same page).
- The `Connection` write path needs one contiguous buffer per frame: a `PP` frame is up to 260 bytes (opcode + 3 address + 256 data).
- Keep **QE = 0**: with QE = 1 the WP# pin becomes SIO2 and hardware protection is disabled; the driver never sets it.
- BP bits and SRWD are non-volatile; a previous program may have left parts of the chip protected. `Full.protection()` shows it; `Minimal.write_bytes()` reports `WriteProtected` instead of silently losing data.
- Do not use `WPSEL` (one-time, irreversible individual-lock mode) or `WRSCUR` outside `lock_otp()`.
- The ESN area (OTP `000h`–`00Fh`) is only a unique serial number when security register bit 0 = 1 (factory locked); on the reference-bench sample it is blank (`FFh`). The driver refuses to program bytes `000h`–`00Fh` either way; bytes `010h`–`1FFh` are writable until `lock_otp()`.
- Shared SPI bus: when other devices (an SD card, …) share the bus, a driver that changes the bus clock (the SD driver does) must restore it, or each device must use its own SPI configuration; the connection object here never changes the speed.
- The chip does not support the common `66h`/`99h` software reset; after an interrupted operation just wait for WIP = 0.

## Sigrok Decoder

Stack on the built-in `spi` decoder (CS, MOSI and MISO required). Annotated: the opcode, the 24-bit address (with its 4 KiB sector, 64 KiB block and 256-byte page), dummy bytes, the data bytes (length and preview), a one-line summary per transaction (RDSR polling loops are collapsed to "poll xN … → final status"), the decoded status register (WIP, WEL, BP3:0 with the protected size, QE, SRWD), the security register, and the JEDEC / electronic / REMS ids checked against `C2 20 18` / `17` / `C2 17`.

State is kept across CS assertions, which allows these warnings: a program, erase or WRSR **without a preceding WREN**; a command other than RDSR / RDSCUR while the last operation may still be running (no RDSR with WIP = 0 seen since); any command other than RDP / RES in deep power-down; a page program that **crosses a 256-byte page boundary** or sends more than 256 bytes; a program or erase **aimed at the area protected by BP3:0**; a chip erase while BP3:0 ≠ 0; WRSR setting **QE** (disables WP#) or SRWD; OTP accesses outside 0x000–0x1FF or touching the ESN bytes; `WRSCUR` (irreversible OTP lock); wrong ids; valid-but-unused command codes (dual / quad / DTR / parallel / block-lock) and unknown opcodes. A command that the chip ignores (no WEL, or a protected target) does not start a busy period. A CS that rises off a byte boundary cannot be seen through the `spi` decoder and is not flagged. Annotation conventions per `specs/sigrok_annotations.md`.
