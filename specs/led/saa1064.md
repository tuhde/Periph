# Chip Spec: SAA1064

**Manufacturer:** Philips Semiconductors / NXP  
**Datasheet:** `datasheets/led/saa1064.pdf` (SAA1064 product specification, February 1991, hosted by tronixstuff.com)  
**Category:** led  
**Transports:** I²C

## Overview

The SAA1064 is a bipolar 4-digit LED driver with an I²C-bus slave interface: it drives four 7-segment displays with decimal point by **multiplexing between two pairs of digits**. It has **16 current-sink segment outputs** (P1–P16, software-controllable up to 21 mA), two multiplex outputs for common-anode displays (MX1, MX2, emitter followers for direct drive of two displays), an on-chip multiplex oscillator whose frequency is set by an external capacitor (CEXT), control bits to select **static, dynamic and blank mode**, a **segment test** bit and a **POWER RESET** flag in a one-byte status register. It has four I²C addresses chosen by the voltage on the ADR pin. Supply 4.5–15 V (5 V typ.). The chip has no clock/decimal helper logic: the host supplies the segment pattern for every digit.

## Transport Configuration

### I²C
- **Address:** `0x38`, `0x39`, `0x3A`, `0x3B` (7-bit `0111 0 A1 A0`; write bytes `0x70`, `0x72`, `0x74`, `0x76`, read bytes `0x71`, `0x73`, `0x75`, `0x77`), selected by the voltage on ADR: VEE (0 V) = `0x38`, 3/8 VCC = `0x39`, 5/8 VCC = `0x3A`, VCC = `0x3B` (ranges: `A1A0 = 00`: VEE…3/16 VCC; `01`: 5/16…7/16 VCC; `10`: 9/16…11/16 VCC; `11`: 13/16 VCC…VCC); no other address is acknowledged
- **Max clock:** 100 kHz (standard I²C mode; the 1991 datasheet gives no timing table; SDA/SCL inputs: VIL ≤ 1.5 V, VIH ≥ 3.0 V, max 5.5 V)
- **Identity register:** none (`registry/chips.json` entry has `"id_probe": null`; `0x38`–`0x3B` are shared with the PCF8574A range and others)
- **Probe safety:** `write_sensitive` — the first byte after the address is an instruction (subaddress) byte and the following bytes change the display/control registers; there is no pure register pointer
- **Protocol:** **write:** `[addr+W] [instruction byte] [byte] [byte] …` — the instruction byte is `0000 0 SC SB SA` and selects the **subaddress**, the following data bytes are stored in consecutive subaddresses (auto-increment, wraps from 7 to 0); **read:** `[addr+R] [status byte]` (only the status byte exists). Plain `Connection` (`write` / `read`), not `RegisterConnection`

## Pin Configuration

| Pin | Notes |
|-----|-------|
| ADR | Address select (VEE, 3/8 VCC, 5/8 VCC, VCC) |
| CEXT | External capacitor for the multiplex oscillator (2.7 nF gives a 5–10 ms period); in static mode tie to VEE/VCC or leave open (the oscillator is off) |
| P1–P8 | Segment current sinks for digits 1 and 3 (bit 0 = P1 … bit 7 = P8) |
| P9–P16 | Segment current sinks for digits 2 and 4 (bit 0 = P9 … bit 7 = P16) |
| MX1, MX2 | Multiplex outputs (emitter followers, ≥ 50 mA) for the common anodes; use external transistors if the dissipation limit would be exceeded |
| SDA, SCL | I²C |
| VCC, VEE | 4.5–15 V supply |

No interrupt pin.

## Registers (subaddresses)

| SC SB SA | Subaddress | Name | Description |
|----------|------------|------|-------------|
| `000` | `0x00` | control | Control bits C6…C0 (bit 7 don't care) |
| `001` | `0x01` | digit 1 | Segment pattern: bit 0 = P1 … bit 7 = P8 |
| `010` | `0x02` | digit 2 | bit 0 = P9 … bit 7 = P16 |
| `011` | `0x03` | digit 3 | bit 0 = P1 … bit 7 = P8 (shown in dynamic mode) |
| `100` | `0x04` | digit 4 | bit 0 = P9 … bit 7 = P16 (shown in dynamic mode) |

A segment is on when its data bit is 1. After power-on-reset all bits are 0 (completely blank display).

### Control byte

| Bit | Name | Meaning |
|-----|------|---------|
| 0 | C0 | `0` static mode (continuous display of digits 1 and 2), `1` dynamic mode (alternating digits 1+3 and 2+4) |
| 1 | C1 | `0` digits 1+3 blanked, `1` not blanked |
| 2 | C2 | `0` digits 2+4 blanked, `1` not blanked |
| 3 | C3 | `1` = all segment outputs on (segment test) |
| 4 | C4 | `1` adds 3 mA to the segment output current |
| 5 | C5 | `1` adds 6 mA |
| 6 | C6 | `1` adds 12 mA |

Segment current = 0 mA with C4–C6 = 0 and 3 / 6 / 9 / 12 / 15 / 18 / 21 mA for the combinations (typical per-bit currents 3.0, 6.0 and 12.0 mA; 21 mA with all three set).

### Status byte (read)

Bit 7 = **PR** (POWER RESET flag): `1` means a power failure/reset occurred since the status byte was last read; it clears after the read. The other bits carry no information (the datasheet's figure shows `PR 0000000` followed by the final bit of the address-read acknowledge).

## Initialization Sequence

1. Power-up: the internal power-on reset blanks the display and sets PR.
2. Write the control byte and the digit data in one transaction starting at subaddress 0: `[addr+W] [0x00] [control] [d1] [d2] [d3] [d4]`; e.g. dynamic mode, all four digits unblanked, 12 mA (`C6`): control = `0x47` (see Data Conversion).
3. Optionally read the status byte and discard the PR flag.

## Implementation Stages

### Minimal

Goal: show four 7-segment digits with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Writes control `0x47` (dynamic mode, all digits on, 12 mA) and blanks the four digits |
| `show_digits` | `digits: list[int \| None]` (4 values) | — | Digits 0–9 (or `None` for blank) as 7-segment patterns using the default segment mapping; one write `[0x01, d1, d2, d3, d4]` |
| `show_number` | `value: int` | — | Right-aligned decimal number (0–9999; blank leading zeros; raises outside) |
| `clear` | — | — | Blank all digits |
| `write_raw` | `patterns: list[int]` (1–4), `first_digit: int = 1` | — | Raw segment bytes starting at digit `first_digit` (1–4) |

**Sensible defaults:** dynamic mode (all four digits), digits unblanked, 12 mA segment current (control `C6` = 1), default segment mapping `a = bit 0 … g = bit 6, dp = bit 7`.

## Data Conversion

```
control = C0 | C1<<1 | C2<<2 | C3<<3 | C4<<4 | C5<<5 | C6<<6          # bit 7 = 0
current_ma = 3*C4 + 6*C5 + 12*C6                                       # 0 .. 21 mA (nominal)
instruction byte = subaddress (0..4), data then auto-increments (7 wraps to 0)

write control + 4 digits:  [addr+W] [0x00] [control] [d1] [d2] [d3] [d4]
write digits only:         [addr+W] [0x01] [d1] [d2] [d3] [d4]

default 7-segment patterns (bit0=a, bit1=b, bit2=c, bit3=d, bit4=e, bit5=f, bit6=g, bit7=dp):
  0 0x3F  1 0x06  2 0x5B  3 0x4F  4 0x66  5 0x6D  6 0x7D  7 0x07  8 0x7F  9 0x6F  blank 0x00
```

Examples: dynamic mode, all digits on, 12 mA (`C6`): control `0b0100_0111` = `0x47`; dynamic mode, all on, 21 mA (`C4`+`C5`+`C6`): `0x77`; static mode (`C0` = 0) with digits 1 and 2 shown, 12 mA: `0x46`; segment test with dynamic mode: `0x4F`.

## Timing Constraints

- **Multiplex period:** set by the external capacitor on CEXT (2.7 nF gives 5–10 ms, duty factor 48.4 %); dynamic mode alternates digits 1+3 and 2+4 at this rate; no multiplexing oscillator runs in static mode.
- **Data latching:** data are latched on the rising edge of the acknowledge clock pulse of each byte, so the display updates byte by byte during a transfer.
- **Power-on:** the reset is internal, no delay is specified; the display is blank after reset.
- **I²C:** the 1991 datasheet gives no clock-rate table; the drivers use ≤ 100 kHz.
- **Conformance:** none of these has a bus-decodable start/end annotation pair, so `specs/led/saa1064_timing.conf` defines no checks.

## Implementation Notes

- **Instruction byte = subaddress:** unlike register chips there is no read pointer; every write begins with the subaddress. Writing the control byte and the digits in one transaction (subaddress 0) is the quickest initialization.
- **Digit-to-output mapping:** digits 1 and 3 share outputs P1–P8, digits 2 and 4 share P9–P16 (that is the multiplexing); the default segment mapping of the helper is an assumption for the usual module wiring — boards differ, so use `set_segment_map` or the raw patterns.
- **Dissipation:** 21 mA per segment on a 4-digit display can exceed the package's power limit; the datasheet suggests external transistors on MX1/MX2 for large displays.
- **Static mode** shows only digits 1 and 2 (with MX1 on and the oscillator off); in dynamic mode all four digits are shown, each lit about half of the time, so choose a higher segment current for equal brightness.
- **PR flag:** reading the status byte clears it; a set flag after a read-back means the chip was reset (supply glitch) and the display must be rewritten.
- **Address pin:** the voltage steps (VEE, 3/8, 5/8, VCC) must be generated by a resistor divider with 10 µA input current taken into account.
- **Supply:** 4.5–15 V; the SDA/SCL pins tolerate at most 5.5 V, so for supplies above 5 V use level shifting.
- **Datasheet:** SAA1064 (February 1991), downloaded from `http://tronixstuff.com/wp-content/uploads/2011/07/nxp-saa1064.pdf`.

## Sigrok Decoder

Decoder id `saa1064`, input `['i2c']`. Matches I²C addresses `0x38`–`0x3B`. Decodes the instruction byte (subaddress, auto-increment position), the control byte (mode, blanking, test, segment current in mA) and the digit bytes (hex, segments lit and, for the default mapping, the displayed character), and the status byte (PR flag); warns on subaddresses above 4 and on control bytes with bit 7 set. No timing annotation pair is emitted.
