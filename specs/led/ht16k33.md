# Chip Spec: HT16K33

**Manufacturer:** Holtek Semiconductor  
**Datasheet:** `datasheets/led/ht16k33.pdf` (HT16K33 Rev. 1.10, May 16, 2011)  
**Category:** led  
**Transports:** I²C

## Overview

The HT16K33 is a memory-mapped LED controller/driver: a 16 × 8-bit display RAM drives up to **16 segments (ROW outputs) × 8 commons (COM outputs) = 128 LEDs** in a 1/8-duty multiplex (the datasheet's scan is 9 time slots: 8 display slots plus a key-scan slot, frame 9.504 ms), with **16-step digital dimming** (1/16 … 16/16 duty), blinking at 2 / 1 / 0.5 Hz, a built-in RC oscillator and an I²C interface up to 400 kHz. It also contains a **key scan** circuit for up to 13 × 3 = 39 keys (ROW3…ROW15 × COM1…COM3) with a 13 × 3-bit key-data RAM and an interrupt output (shared with the ROW15 pin, selectable polarity). It comes in 20-, 24- and 28-pin SOP packages; the 28-pin version has three address pins (A0–A2 shared with ROW2–ROW0) and the 24-pin one two. Supply 4.5–5.5 V. It is the chip on the common 8×8 and 7-segment "LED backpack" boards.

## Transport Configuration

### I²C
- **Address:** `0x70` + `A2 A1 A0` → `0x70`–`0x77` for the **28-pin** package (`1110 A2 A1 A0`); the **24-pin** package has A2 fixed 0 (`0x70`–`0x73`), the **20-pin** package no address pins (`0x70`). The address pins are read at every frame through the COM0/AD source (floating = 0; a diode + resistor to COM0/AD sets a 1)
- **Max clock:** 400 kHz (tLOW ≥ 1.3 µs, tHIGH ≥ 0.6 µs, tBUF ≥ 1.3 µs, tSU;DAT ≥ 100 ns, tSU;STO ≥ 0.6 µs)
- **Identity register:** none (`registry/chips.json` entry has `"id_probe": null`; `0x70`–`0x77` are shared with the PCA9548/TCA9548 I²C muxes, SHTC3 and others)
- **Probe safety:** `write_sensitive` — every byte after the address is a command or display data; there is no register pointer
- **Protocol:** the first byte after the address is a **command / address byte**, selecting the function by its high bits; following bytes (display data) auto-increment the address:
  - write display RAM: `[addr+W] [0x00 | A3..A0] [data] [data] …` — the RAM address pointer wraps from `0x0F` to `0x00`;
  - write a command: `[addr+W] [command byte]` (one byte, STOP);
  - read key data: `[addr+W] [0x40]` then (repeated START or STOP + START) `[addr+R] [6 bytes]`;
  - read the INT flag: `[addr+W] [0x60]` then `[addr+R] [1 byte]`.
  The plain `Connection` (`write` / `read`) is used for the command, display and read transfers (`write` then `read` for the reads), not `RegisterConnection`.

## Commands

All commands are single bytes (written as `[addr+W] [byte]`); the upper bits identify the command:

| Name | Byte | Description |
|------|------|-------------|
| Display data address pointer | `0000 A3 A2 A1 A0` (`0x00`–`0x0F`) | Sets the display RAM address; subsequent data bytes are stored from here (auto-increment, wraps `0x0F` → `0x00`) |
| System setup | `0010 xxx S` (`0x20`/`0x21`) | `S` = 1 oscillator on (normal), `S` = 0 oscillator off (**standby**) |
| Key data address pointer | `0100 0 K2 K1 K0` (`0x40`) | Read only: key RAM `0x40`–`0x45`; read the six bytes continuously starting at `0x40` |
| INT flag address pointer | `0110 0000` (`0x60`) | Read only: the INT flag |
| Display setup | `1000 x B1 B0 D` (`0x80`–`0x87`) | `D` display on/off; `B1:B0` blink: `00` off, `01` 2 Hz, `10` 1 Hz, `11` 0.5 Hz |
| ROW/INT set | `1010 xx act row/int` (`0xA0`–`0xA3`) | bit 1 = `act`, bit 0 = `row/int`: `row/int` = 0: pin is the ROW15 output (`0xA0`); `row/int` = 1: INT output, `act` = 0 active low (`0xA1`) or `act` = 1 active high (`0xA3`) |
| Dimming set | `1110 P3 P2 P1 P0` (`0xE0`–`0xEF`) | Brightness (P+1)/16 duty, `0xEF` = 16/16 (default) |
| Test mode | `0xD9` | Holtek use only — never send |

Undefined command data do not affect the function. In standby mode the chip accepts only the system setup command.

### Display RAM layout

16 bytes `0x00`–`0x0F`: COM`n` uses two bytes — address `2n` holds ROW7…ROW0 (bit 0 = ROW0) and address `2n + 1` holds ROW15…ROW8 (bit 0 = ROW8). A `1` lights the LED between ROW and COM. In other words the RAM is eight little-endian 16-bit words, one per COM, bit `r` = ROW`r`.

### Key data RAM

Six bytes `0x40`–`0x45`: key rows K1…K13 (ROW3…ROW15) × key sources KS0…KS2 (COM1…COM3). `0x40`/`0x41` = KS0 (COM1), `0x42`/`0x43` = KS1 (COM2), `0x44`/`0x45` = KS2 (COM3) — each pair is a 13-bit key row word (low byte K1–K8, high byte K9–K13; the datasheet's mapping figure assigns the bits to the K inputs); a set bit means the key was detected since the last read. The RAM is cleared by reading, there is **no FIFO**, and a held key is reported once. Read all six bytes starting at `0x40` in one transaction.

## Initialization Sequence

1. Power-up: wait ≥ 1 ms (no bus traffic during the reset). State after reset: oscillator off, display off, rows as outputs (ROW/INT = ROW), dimming 16/16, key scan stopped.
2. System setup `0x21` (oscillator on).
3. Optional: ROW/INT set `0xA0` (ROW) or `0xA1` / `0xA3` (INT active low / high); dimming `0xE0 | (brightness)`; blink `0x80 | B<<1`.
4. Write the display RAM: `[0x00] [16 data bytes]` (clear = 16 zeros).
5. Display setup `0x81` (display on, no blink).

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | The ROW15/K13/INT pin when ROW/INT = INT; active low (`act` = 0) or active high (`act` = 1) |
| Level | 1 (single fixed condition: a key press detected) |
| Condition | After two completed key-scan cycles with a key pressed the INT flag goes active |
| Clear mechanism | Read the whole key data RAM (`0x40`–`0x45`): INT and the flag clear; the INT flag can also be read at `0x60` |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on the INT pin (edge per the configured polarity) via `connection.int_pin` (or `int_pin`), otherwise a 20 ms polling task on `poll_interrupt`; `callback(keys)` receives the key bitmask read |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Reads the INT flag (`0x60`); if set, reads the key data RAM (clearing it) and returns the 39-bit key bitmask, else 0 |

## Implementation Stages

### Minimal

Goal: light LEDs of a 16 × 8 matrix (or 7-segment) display with a framebuffer; no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Runs the Initialization Sequence: oscillator on, ROW outputs, brightness 16/16, blink off, RAM cleared, display on |
| `clear` | — | — | Zero the shadow RAM and write it |
| `set_pixel` | `com: int` (0–7), `row: int` (0–15), `on: bool = True` | — | Updates the 16-byte shadow RAM (does not write) |
| `write_raw` | `data: bytes` (1–16), `address: int = 0` | — | Write raw RAM bytes at `address` (updates the shadow); raises if `address + len` > 16 |
| `show` | — | — | Write the whole shadow RAM `[0x00] [16 bytes]` |
| `set_brightness` | `level: int` (0–15) | — | Dimming set (`0xE0 | level`) |

**Constants:** `COMMONS = 8`, `ROWS = 16`.

**Sensible defaults:** oscillator on, display on, blink off, brightness 15 (16/16 duty), ROW15 pin as a ROW output (no interrupt), key scan unused.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `display_on` / `display_off` | — | — | Display setup `D` bit (keeps the blink setting) |
| `set_blink` | `frequency: float` (0, 2, 1, 0.5 Hz) | — | `B1:B0`; 0 = off; raises on other values |
| `standby` | — | — | System setup `S` = 0 (oscillator off, display off, key scan stopped; key data and the INT flag are cleared) |
| `wake` | — | — | System setup `S` = 1, then re-sends the display setup, dimming and ROW/INT settings and rewrites the RAM |
| `set_int_output` | `enable: bool`, `active_high: bool = False` | — | ROW/INT set; `enable` makes ROW15/K13/INT an interrupt output (ROW15 and K13 are then unusable) |
| `read_keys` | — | int | Reads `0x40` + 6 bytes (clears the key RAM) and returns the key bitmask (bit `n` = key `n`, see Data Conversion) |
| `key_pressed` | — | bool | Reads the INT flag (`0x60`) |
| `get_pixel` | `com`, `row` | bool | From the shadow RAM |
| `on_interrupt` / `off_interrupt` / `poll_interrupt` | see Interrupt | | |

**Additional configuration options:** blink, standby, INT pin function and polarity, key scan reading. Module-specific helpers (7-segment glyph tables, 14-segment alphanumeric mappings of the common backpack boards) are not part of the chip driver.

## Data Conversion

```
RAM (16 bytes):   byte[2*com]     = ROW7..ROW0   (bit r = ROWr)           com = 0..7
                  byte[2*com + 1] = ROW15..ROW8  (bit r-8 = ROWr)
set_pixel(com, row, on):  word = byte[2*com] | byte[2*com+1] << 8;  word |= 1 << row  (or &= ~(1 << row))
show():                    write [0x00] + byte[0..15]
brightness level L (0..15): command 0xE0 | L  ->  (L + 1)/16 duty
blink f: 0x80 | (b << 1) | display_on,  b = 0 off, 1 = 2 Hz, 2 = 1 Hz, 3 = 0.5 Hz

key data (6 bytes b[0..5] from 0x40):  KS_k word = b[2k] | b[2k+1] << 8   (k = 0..2 for KS0..KS2 = COM1..COM3)
                                       key index = k * 13 + (K number - 1)  # 13 keys per key source (K1..K13)
```

Examples: brightness 50 % (8/16) is `0xE7`; blinking at 1 Hz with the display on is `0x85` (`0x80 | 2<<1 | 1`); oscillator on is `0x21`; INT output active low is `0xA1`, active high `0xA3`.

## Timing Constraints

- **Power-on:** avoid I²C traffic for ≥ 1 ms after power-up (reset action). Conformance-checked as `poweron_ready` (min 1 ms), measured from capture start to the first decoded bus transaction (same pattern as `display/pcf8576`); see `specs/led/ht16k33_timing.conf`.
- **Frame:** 9 slots × 1056 µs = 9.504 ms per frame (1024 µs display + 32 µs key-scan share per slot); an INT is raised after two completed key-scan cycles (≈ 19 ms) with a key pressed.
- **Standby / wake:** in standby the chip accepts only the system-setup command; a key press or `S = 1` wakes it and the previous display data are output again after the mode commands.
- **Key data:** read all six key bytes (`0x40`–`0x45`) in one transaction before the next key-scan cycle completes; there is no FIFO.
- **I²C:** ≤ 400 kHz.

## Implementation Notes

- **Command byte first:** unlike register chips, there is no register pointer — each transaction starts with a command/address byte; display data may be streamed after the address pointer byte.
- **Key reads clear the RAM:** read the whole 6-byte block every time; a partial read leaves the INT flag set.
- **Wiring:** ROW outputs are active high, COM outputs active low during display; the key matrix shares ROW3–ROW15 and COM1–COM3 with the LEDs, so a key matrix and an LED matrix use the same pins (key diodes recommended per the datasheet).
- **28-pin vs 24-pin vs 20-pin:** the number of address pins, ROW outputs and key inputs shrinks with the package (24-pin: ROW0–ROW1 address, ROW2–ROW10 keys, INT on ROW11; 20-pin: ROW0–ROW6 keys, INT on ROW7); the drivers expose the 28-pin geometry and document the limits.
- **Standby clears key data** and the INT flag; read the keys before entering standby.
- **Dimming** affects all LEDs together (the PWM duty of the ROW outputs).
- **Address pins sampled every frame:** change them only with power off.
- **Datasheet:** Holtek HT16K33 Rev. 1.10, from `https://cdn-shop.adafruit.com/datasheets/ht16K33v110.pdf`.

## Sigrok Decoder

Decoder id `ht16k33`, input `['i2c']`. Matches I²C addresses `0x70`–`0x77`. Decodes the first byte of each write by command (display data address pointer + the following RAM bytes as ROW/COM bitmaps, system setup, display setup with blink, ROW/INT set, dimming set, key data/INT flag pointers) and the reads (key data bytes as pressed-key lists, INT flag); warns on the test-mode command `0xD9`, on writes after a standby command other than system setup and on display data past RAM address `0x0F`. The `poweron_ready` check is measured from capture start (no annotation pair).
