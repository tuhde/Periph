# Chip Spec: BNO055

**Manufacturer:** Bosch Sensortec  
**Datasheet:** `datasheets/imu/bno055.pdf` (BST-BNO055-DS000-18, Revision 1.8, October 2021)  
**Category:** imu  
**Transports:** I²C

> **Scope:** The BNO055 also has a UART interface; only **I²C** is specified (as requested in the issue). The accelerometer/gyroscope/magnetometer *sensor configuration* registers on page 1 (`ACC_Config`, `GYR_Config_0/1`, `MAG_Config`, sleep configs, motion/high-g/high-rate thresholds) are **not** part of this spec; in the fusion modes the chip controls those settings itself (datasheet Table 3-7). The driver uses page 1 only for the interrupt registers.

## Overview

The BNO055 is a 9-axis absolute-orientation sensor: a 14-bit 3-axis accelerometer, a 16-bit 3-axis gyroscope and a 3-axis magnetometer together with a 32-bit ARM Cortex-M0+ microcontroller running Bosch's sensor-fusion firmware. It outputs, besides the raw sensor data, **fused absolute orientation** (Euler angles heading/roll/pitch and a quaternion), **linear acceleration**, **gravity vector** and a temperature, with automatic per-sensor calibration whose status is exposed in `CALIB_STAT`. Typical uses: robotics and drones, AR/VR head tracking, wearables, compass headings.

## Transport Configuration

### I²C
- **Address:** `0x28` (COM3 pin low) or `0x29` (COM3 pin high; the datasheet calls `0x29` the default)
- **Max clock:** 400 kHz (fast mode); the chip stretches the clock (host must support clock stretching — many Linux/RP2040 setups do)
- **Supply:** VDD 2.4–3.6 V, VDDIO 1.7–3.6 V
- **Interface select:** PS0/PS1 pins low = I²C (high/high = UART)
- **Register access:** 1-byte register address; all data registers are little-endian (LSB at the lower address); registers auto-increment on multi-byte reads, which also gives **shadowed (consistent)** LSB/MSB pairs — always burst-read.
- **Pages:** `PAGE_ID` (`0x07`) selects page 0 (default: data, status, config) or page 1 (sensor configuration, interrupts)
- **Identity register:** `CHIP_ID` (`0x00`) = `0xA0`; also `ACC_ID` (`0x01`) = `0xFB`, `MAG_ID` (`0x02`) = `0x32`, `GYR_ID` (`0x03`) = `0x0F` (feeds `registry/chips.json` `id_probe`)
- **Probe safety:** `register_pointer` — reading `CHIP_ID` only moves the pointer.

### Bit Fields

#### `OPR_MODE` (`0x3D`), bits 3:0
| Value | Mode | Type | Output |
|-------|------|------|--------|
| `0x0` | CONFIGMODE | — | All outputs zero; the only mode in which most registers can be written |
| `0x1` | ACCONLY | non-fusion | raw accelerometer |
| `0x2` | MAGONLY | non-fusion | raw magnetometer |
| `0x3` | GYROONLY | non-fusion | raw gyroscope |
| `0x4` | ACCMAG | non-fusion | |
| `0x5` | ACCGYRO | non-fusion | |
| `0x6` | MAGGYRO | non-fusion | |
| `0x7` | AMG | non-fusion | all three raw sensors |
| `0x8` | IMU | fusion | relative orientation, accelerometer + gyroscope, 100 Hz |
| `0x9` | COMPASS | fusion | absolute heading, 20 Hz |
| `0xA` | M4G | fusion | relative orientation (magnet for gyroscope), 50 Hz |
| `0xB` | NDOF_FMC_OFF | fusion | 9-DOF, fast magnetometer calibration off, 100 Hz |
| `0xC` | NDOF | fusion | 9-DOF absolute orientation, 100 Hz |

Switching time: CONFIGMODE → any mode **7 ms**; any mode → CONFIGMODE **19 ms**. The reset value is CONFIGMODE (`0x10` shows bit 4 reserved/read as set).

#### `PWR_MODE` (`0x3E`), bits 1:0
`00` normal (default), `01` low power (accelerometer only, enters after 5 s without motion), `10` suspend (all sensors and the microcontroller asleep), `11` invalid (do not use).

#### `UNIT_SEL` (`0x3B`)
| Bit | Name | `0` | `1` |
|-----|------|-----|-----|
| 0 | ACC_Unit | m/s² | mg |
| 1 | GYR_Unit | deg/s (dps) | rad/s (rps) |
| 2 | EUL_Unit | degrees | radians |
| 4 | TEMP_Unit | °C | °F |
| 7 | ORI_Android_Windows | Windows | Android |

Reset `0x80` (Android orientation, m/s², dps, degrees, °C). The datasheet's register-description table lists the unit bits at 1/2/3/5, which contradicts its Table 3-11; this spec follows Table 3-11 (0/1/2/4). Unit changes apply only in CONFIGMODE.

#### `CALIB_STAT` (`0x35`)
Bits 7:6 SYS, 5:4 GYR, 3:2 ACC, 1:0 MAG; each 0 (uncalibrated) … 3 (fully calibrated).

#### `ST_RESULT` (`0x36`)
Bit 3 ST_MCU, 2 ST_GYR, 1 ST_MAG, 0 ST_ACC: `1` = passed (reset `0x0F`).

#### `SYS_STATUS` (`0x39`)
`0` idle, `1` system error, `2` initializing peripherals, `3` system initialization, `4` executing self-test, `5` sensor fusion algorithm running, `6` running without fusion.

#### `SYS_ERR` (`0x3A`)
`0` none, `1` peripheral init error, `2` system init error, `3` self-test failed, `4` register value out of range, `5` register address out of range, `6` register write error, `7` low-power mode not available for the selected mode, `8` accelerometer power mode not available, `9` fusion algorithm configuration error, `0xA` sensor configuration error.

#### `SYS_TRIGGER` (`0x3F`)
Bit 7 CLK_SEL (`1` external crystal; set only if fitted), bit 6 RST_INT (clear interrupt status and the INT pin), bit 5 RST_SYS (system reset), bit 0 Self_Test (trigger self-test).

#### `TEMP_SOURCE` (`0x40`)
`00` accelerometer (default), `01` gyroscope.

#### `AXIS_MAP_CONFIG` (`0x41`) / `AXIS_MAP_SIGN` (`0x42`)
`AXIS_MAP_CONFIG`: bits 1:0 remapped X, 3:2 remapped Y, 5:4 remapped Z (`00` = X, `01` = Y, `10` = Z); reset `0x24` (X→X, Y→Y, Z→Z). `AXIS_MAP_SIGN`: bit 2 X sign, bit 1 Y sign, bit 0 Z sign (`1` = inverted). Write only in CONFIGMODE; the datasheet's section 3.4 lists the valid placements.

#### `INT_STA` (`0x37`, page 0), `INT_EN` (`0x10`, page 1), `INT_MSK` (`0x0F`, page 1)
Same bit layout: 7 ACC_NM (no/slow motion), 6 ACC_AM (any motion), 5 ACC_HIGH_G, 4 GYR_DRDY, 3 GYR_HIGH_RATE, 2 GYRO_AM (any motion), 1 MAG_DRDY, 0 ACC_BSX_DRDY (accelerometer/fusion data ready). `INT_EN` enables the source (updates `INT_STA`); `INT_MSK` routes it to the INT pin. `INT_STA` is cleared on read. Data-ready interrupts require firmware 3.14 or newer (the chip ships with 3.11 in the datasheet's example).

## Initialization Sequence

1. Power up (VDD/VDDIO); wait **≥ 400 ms** (start-up time from off to configuration mode; the datasheet's POR time from reset to configuration mode is 650 ms).
2. Read `CHIP_ID` (`0x00`) — must be `0xA0`; if not, wait and retry for up to 650 ms (the chip does not ACK before boot completes).
3. The chip is in CONFIGMODE. Set `PWR_MODE` = normal (`0x00`), `PAGE_ID` = 0.
4. Write `UNIT_SEL` (Minimal: `0x86` — Android orientation, radians, rad/s, m/s², °C).
5. Write `OPR_MODE` = NDOF (`0x0C`); wait **7 ms**.
6. Poll `CALIB_STAT` until the magnetometer (and system) reach 3, rotating the board through a figure-eight; data is valid immediately but absolute heading is only accurate when calibrated.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `INT`, active high, rising edge, latched; push-pull |
| Level | 2 (selectable sources on a single line) |
| Condition(s) | accelerometer/gyro motion and high-g/high-rate events, gyro/mag/accelerometer data ready |
| Clear mechanism | read `INT_STA` (clears all bits) or set `SYS_TRIGGER[RST_INT]` |

### Interrupt sources

| Constant | Value | Condition |
|----------|-------|-----------|
| `SOURCE_ACC_BSX_DRDY` | `0x01` | accelerometer / fusion data ready |
| `SOURCE_MAG_DRDY` | `0x02` | magnetometer data ready |
| `SOURCE_GYRO_AM` | `0x04` | gyroscope any motion |
| `SOURCE_GYR_HIGH_RATE` | `0x08` | gyroscope high rate |
| `SOURCE_GYR_DRDY` | `0x10` | gyroscope data ready |
| `SOURCE_ACC_HIGH_G` | `0x20` | accelerometer high-g |
| `SOURCE_ACC_AM` | `0x40` | accelerometer any motion |
| `SOURCE_ACC_NM` | `0x80` | accelerometer no/slow motion |

The thresholds and durations of the motion/high-g/high-rate engines (page 1) are not configured by this driver; only the data-ready sources are fully usable without them.

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on the INT output (rising edge) via `connection.int_pin` (or `int_pin`), otherwise a 100 ms polling task calling `poll_interrupt`; `callback(status)` receives the `INT_STA` bits |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Read `INT_STA` (clears it) |
| `enable_interrupt` | `enable_interrupt(source)` | Set the source bit in page-1 `INT_EN` and `INT_MSK` (restores page 0) |
| `disable_interrupt` | `disable_interrupt(source)` | Clear the bit in both |

### Status register bit layout

`INT_STA`: bit 0 `SOURCE_ACC_BSX_DRDY`, 1 `SOURCE_MAG_DRDY`, 2 `SOURCE_GYRO_AM`, 3 `SOURCE_GYR_HIGH_RATE`, 4 `SOURCE_GYR_DRDY`, 5 `SOURCE_ACC_HIGH_G`, 6 `SOURCE_ACC_AM`, 7 `SOURCE_ACC_NM`.

## Data Conversion

All outputs are signed 16-bit little-endian (`value = LSB | MSB << 8`), except `TEMP` (signed 8 bit). With the Minimal `UNIT_SEL` = `0x86`:

| Output | Raw → physical |
|--------|----------------|
| Euler angle | `rad = raw / 900.0` (degrees mode: `raw / 16.0`) |
| Quaternion | `q = raw / 16384.0` (2¹⁴ LSB = 1) |
| Acceleration, linear acceleration, gravity | `m/s² = raw / 100.0` (mg mode: 1 mg = 1 LSB) |
| Magnetic field | `µT = raw / 16.0` |
| Angular rate | `rad/s = raw / 900.0` (dps mode: `raw / 16.0`) |
| Temperature | `°C = raw` (signed 8 bit; Fahrenheit mode: 2 LSB = 1 °F) |

Rotation conventions (Android, the default): pitch −180…+180° (turning clockwise decreases), roll −90…+90°, heading 0…360° (clockwise increases). Windows orientation changes the pitch sign. Fusion output rates: IMU/NDOF/NDOF_FMC_OFF 100 Hz, COMPASS 20 Hz, M4G 50 Hz.

Offsets/radii are in the sensor LSB units of the current `UNIT_SEL`; read them only after `is_calibrated`, and write all six bytes of a block (the last byte commits it).

## Timing Constraints

| Constraint | Value |
|------------|-------|
| Start-up (off → configuration mode) | 400 ms |
| POR / reset → configuration mode | 650 ms |
| CONFIGMODE → any operation mode | 7 ms |
| Any operation mode → CONFIGMODE | 19 ms |
| Fusion output rate | 20–100 Hz (mode dependent) |
| Low-power entry | after 5 s without motion (default) |
| I²C clock | ≤ 400 kHz (clock stretching) |

The datasheet gives these as single values without a bus-decodable start/end annotation pair that can be measured against a guaranteed bound (the chip simply does not ACK during boot), so `bno055_timing.conf` defines no checks.

## Implementation Notes

- **Burst reads:** read all six bytes of a vector (or the whole `0x08`–`0x33` block) in one transaction; single-byte reads can mix LSB/MSB of different samples.
- **CONFIGMODE rules:** most writable registers (units, remap, offsets, clock select) can only be changed in CONFIGMODE; `OPR_MODE`, `INT_EN` and `INT_MSK` can be written in any mode. The driver's helpers switch to CONFIGMODE and back, honouring the 19 ms / 7 ms delays.
- **Boot:** the chip does not ACK for up to 650 ms after power-up or reset; retry `CHIP_ID` instead of failing at the first NACK.
- **Calibration is volatile:** offsets are lost at power-off; the host must store `get_calibration()` data and restore it with `set_calibration` (a fully calibrated sensor reads 3/3/3/3; the magnetometer needs figure-eight motion, the accelerometer six static orientations, the gyroscope stillness).
- **Unit register bit positions:** Table 3-11 (bits 0/1/2/4/7) is used; the register-description table's positions disagree (see UNIT_SEL).
- **Euler register order:** heading, roll, pitch (datasheet labels them X, Y, Z under Android/Windows conventions).
- **Firmware version:** data-ready interrupts need ≥ 3.14; early parts ship with 3.11 and the interrupt sources behave differently.
- **Clock stretching:** the BNO055 stretches SCL; hosts without clock-stretching support (e.g. some Raspberry Pi hardware I²C revisions) need a reduced bus speed or a software I²C driver. This is the best-known BNO055 interoperability pitfall.
- **Address overlap:** `0x28`/`0x29` are also used by other devices; the `CHIP_ID` `0xA0` identifies the BNO055.

## Sigrok Decoder

Decoder id `bno055`, input `['i2c']`. Matches I²C addresses `0x28` and `0x29`. Annotates register accesses by name, decodes `OPR_MODE`/`PWR_MODE`/`UNIT_SEL`/`SYS_TRIGGER` fields, burst reads of the data registers as vectors in physical units (using the unit bits seen earlier in the capture, default m/s², dps, degrees), `CALIB_STAT` as four 0–3 values, `INT_STA`, `SYS_STATUS`/`SYS_ERR` as text, and calibration offset blocks.
