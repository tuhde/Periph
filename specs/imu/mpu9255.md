# Chip Spec: MPU-9255

**Manufacturer:** InvenSense  
**Datasheet:** `datasheets/imu/mpu9255.pdf`  
**Category:** `imu`  
**Transports:** I²C, SPI

## Overview

The MPU-9255 is a 9-axis MotionTracking multi-chip module (MCM) in a 3×3×1 mm QFN package, pin-compatible with the MPU-9250 and positioned as InvenSense's upgrade from the MPU-6515. One die houses the 3-axis MEMS gyroscope and 3-axis MEMS accelerometer; the second die is an AK8963 3-axis magnetometer from Asahi Kasei Microdevices. All three sensors, plus a Digital Motion Processor (DMP) and a 512-byte FIFO, are reachable over a single I²C or SPI interface to the host, with the magnetometer optionally exposed via I²C bypass or through the MPU's internal I²C master. The MPU-9255's register map is functionally identical to the MPU-9250's (same gyro/accel sensitivity tables, same AK8963 sub-device); the only architecturally significant difference is the WHO_AM_I identification value. Primary use case: orientation, stabilisation, dead-reckoning, and 9-DOF sensor fusion, with a dedicated wake-on-motion path for low-power motion-triggered wake-up.

## Transport Configuration

### I²C
- **Address:** `0x68` (AD0 = GND) — `0x69` (AD0 = VCC)
- **Max clock:** 400 kHz (Fast mode)

### SPI
- **Mode:** CPOL=1 CPHA=1 (Mode 3)
- **Max clock:** 1 MHz for all registers (read/write); 20 MHz for sensor and interrupt registers (read only)
- **Bit order:** MSB first
- **CS active:** low
- **First byte:** `[R/W̄][A6..A0]` — R/W̄=1 for read, 0 for write; supports burst read/write (auto-increment)

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| INT | configurable (open-drain or push-pull; active-high or active-low) via INT_PIN_CFG | interrupt output; connect to a host GPIO capable of waking the host from suspend |
| FSYNC | high | frame-sync digital input; connect to GND if unused |

## Initialization Sequence

### MPU-9255

1. Write PWR_MGMT_1 (`0x6B`) = `0x80` (DEVICE_RESET)
2. Wait 100 ms
3. Write PWR_MGMT_1 = `0x01` (wake up; CLKSEL=1 = auto-select PLL)
4. Verify WHO_AM_I (`0x75`) = `0x73`; raise error otherwise
5. Write GYRO_CONFIG (`0x1B`) = `0x00` (±250 dps, DLPF active)
6. Write ACCEL_CONFIG (`0x1C`) = `0x00` (±2 g)
7. Write ACCEL_CONFIG2 (`0x1D`) = `0x03` (ACCEL_FCHOICE_B=0, A_DLPFCFG=3 → accel DLPF 44.8 Hz)
8. Write CONFIG (`0x1A`) = `0x03` (DLPF_CFG=3 → gyro DLPF 41 Hz, 1 kHz internal sample rate; unlike the MPU-6050, CONFIG does not filter the accelerometer — ACCEL_CONFIG2 does)
9. Write SMPLRT_DIV (`0x19`) = `0x04` (200 Hz output rate = 1 kHz / 5)
10. When using SPI: write USER_CTRL (`0x6A`) = `0x10` (I2C_IF_DIS — disable I²C to prevent spurious mode switch)
11. Wait 35 ms (gyroscope startup from Table 1)

### AK8963 Magnetometer (I²C bypass mode)

12. Write INT_PIN_CFG (`0x37`) = `0x22` (BYPASS_EN=1, INT_ANYRD_2CLEAR=1)
13. Write AK8963 CNTL1 (`0x0A`) = `0x00` (power down)
14. Wait 10 ms
15. Write AK8963 CNTL1 = `0x0F` (fuse ROM access mode)
16. Wait 10 ms
17. Read ASAX (`0x10`), ASAY (`0x11`), ASAZ (`0x12`) — store as calibration
18. Write AK8963 CNTL1 = `0x00` (power down)
19. Wait 10 ms
20. Write AK8963 CNTL1 = `0x16` (16-bit, continuous measurement mode 2 at 100 Hz)

### Wake-on-Motion (optional, Full only)

21. Write PWR_MGMT_1 = `0x01` (CYCLE=0, SLEEP=0), PWR_MGMT_2 = `0x07` (accel on: DIS_XA/YA/ZA=0; gyro off: DIS_XG/YG/ZG=1)
22. Write ACCEL_CONFIG2 (`0x1D`) = `0x01` (ACCEL_FCHOICE_B=0, A_DLPFCFG=1 — the datasheet's “184 Hz” wake-on-motion setting; the register map lists 218.1 Hz). The datasheet's flowchart box says ACCEL_FCHOICE_B=1, but that bypasses the DLPF entirely (1.13 kHz); the bulleted steps' ACCEL_FCHOICE_B=0 is the setting that matches the heading
23. Write INT_ENABLE (`0x38`) = `0x40` (WOM_EN only)
24. Write MOT_DETECT_CTRL (`0x69`) = `0xC0` (ACCEL_INTEL_EN=1, ACCEL_INTEL_MODE=1)
25. Write WOM_THR (`0x1F`) = threshold (1–255 LSB ≈ 4–1020 mg)
26. Write LP_ACCEL_ODR (`0x1E`) = wake-up frequency selector (0.24 Hz–500 Hz)
27. Write PWR_MGMT_1 = `0x21` (CYCLE=1) — enters accelerometer low-power duty-cycled mode

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits everything and adds the rest.

### Minimal

Goal: expose 3-axis acceleration and 3-axis angular rate with no configuration required beyond the connection. No magnetometer and no wake-on-motion in Minimal — both require non-trivial secondary initialization paths.

| Operation   | Parameters  | Returns                  | Notes |
|-------------|-------------|--------------------------|-------|
| `init`      | connection  | —                        | Reset, WHO_AM_I check, enable all sensors at defaults; 35 ms startup wait |
| `accel`     | —           | `(float, float, float)`  | Linear acceleration (x, y, z) in m/s² |
| `gyro`      | —           | `(float, float, float)`  | Angular rate (x, y, z) in rad/s |

**Sensible defaults baked into Minimal:**
- Gyroscope full-scale: ±250 dps (GYRO_FS_SEL=0)
- Accelerometer full-scale: ±2 g (ACCEL_FS_SEL=0)
- Gyroscope DLPF: 41 Hz bandwidth (CONFIG DLPF_CFG=3)
- Accelerometer DLPF: 44.8 Hz bandwidth (ACCEL_CONFIG2 A_DLPFCFG=3) — below the 100 Hz Nyquist limit of the 200 Hz output rate, and matched to the gyro filter
- Sample rate: 200 Hz (SMPLRT_DIV=4)
- Clock: auto PLL (CLKSEL=1)
- All six axes enabled
- SPI only: I2C_IF_DIS set to prevent accidental I²C re-enable

### Full

Goal: expose complete chip functionality. Extends Minimal.

|-----------------------------|---------------------------------------------------|----------------------------------|-------|

Gyro (CONFIG.DLPF_CFG): 0=250 Hz, 1=184, 2=92, 3=41, 4=20, 5=10, 6=5, 7=3600 Hz. **Additional configuration options:**
- Gyroscope full-scale: ±250 / ±500 / ±1000 / ±2000 dps
- Accelerometer full-scale: ±2 / ±4 / ±8 / ±16 g
- Digital low-pass filter: 7 settings (0=bypass ~260 Hz, 1–6 progressively narrower down to 5 Hz)
- Sample rate divider: 0–255 (effective only when DLPF active)
- Magnetometer: 14-bit or 16-bit; 8 Hz or 100 Hz continuous; single-shot
- FIFO: 512 bytes; configurable sources
- Wake-on-motion: threshold 4–1020 mg in 4 mg steps; wake-up ODR 0.24–500 Hz

## Data Conversion

### Accelerometer

Sensitivity (LSB/g) depends on ACCEL_FS_SEL:

| AFS_SEL | Full-scale | Sensitivity  |
|---------|------------|--------------|
| `00`    | ±2 g       | 16384 LSB/g  |
| `01`    | ±4 g       | 8192 LSB/g   |
| `10`    | ±8 g       | 4096 LSB/g   |
| `11`    | ±16 g      | 2048 LSB/g   |

```
accel_g     = raw_signed_16 / sensitivity
accel_m_s2  = accel_g * 9.80665
```

Data is big-endian (high byte at lower address). Combine as:
```
raw = (ACCEL_XOUT_H << 8) | ACCEL_XOUT_L
if raw >= 0x8000: raw -= 0x10000
```

### Gyroscope

Sensitivity (LSB/(°/s)) depends on GYRO_FS_SEL:

| FS_SEL | Full-scale  | Sensitivity      |
|--------|-------------|------------------|
| `00`   | ±250 dps    | 131.0 LSB/(°/s)  |
| `01`   | ±500 dps    | 65.5 LSB/(°/s)   |
| `10`   | ±1000 dps   | 32.8 LSB/(°/s)   |
| `11`   | ±2000 dps   | 16.4 LSB/(°/s)   |

```
gyro_dps   = raw_signed_16 / sensitivity
gyro_rad_s = gyro_dps * π / 180.0
```

### Temperature

```
temperature_C = raw_signed_16 / 333.87 + 21.0
```

Sensitivity 333.87 LSB/°C; 0 LSB at 21 °C (from Table 4 A.C. Electrical Characteristics).

### Magnetometer (AK8963)

Sensitivity depends on output bit resolution (BIT in CNTL1):

| BIT | Resolution | Sensitivity    |
|-----|------------|----------------|
| 0   | 14-bit     | 0.6 µT/LSB     |
| 1   | 16-bit     | 0.15 µT/LSB    |

Factory sensitivity adjustment (ASA values read from fuse ROM):

```
scale = (ASA - 128) / 256.0 + 1.0          # per axis (ASAX, ASAY, ASAZ)
mag_uT = raw_signed_16 * sensitivity * scale
```

Note: the magnetometer Z-axis is oriented differently from the accelerometer/gyroscope axes (see Figure 5 in the datasheet). The driver exposes raw-axis values without remapping; users performing sensor fusion must account for this.

### Wake-on-Motion threshold

```
threshold_lsb = clamp(round(threshold_mg / 4), 1, 255)   # 1 LSB ≈ 4 mg
```

## Examples

### Demo

"Motion-triggered wake logger": Configure Full with wake-on-motion at a 64 mg threshold and a 31.25 Hz wake-up rate, then put the chip into accelerometer-only cycle mode. Poll `motion_detected()` in a loop with a short sleep; while idle, print a periodic "sleeping…" heartbeat at ~1 Hz. When motion is detected, disable cycle mode, re-enable the gyroscope and magnetometer (100 Hz), and for 5 seconds print roll/pitch (from accel) and heading (from mag) at ~10 Hz using the same formulas as the levelling calculation below, then return to low-power wake-on-motion mode. Visually interesting when the board is left still and then picked up. Roll = atan2(ay, az), pitch = atan2(-ax, sqrt(ay²+az²)), heading = atan2(my, mx), all in degrees (heading uncompensated for tilt).

## Timing Constraints

- **Power-on to register access:** 11 ms typical, 100 ms maximum (use 100 ms in driver)
- **After DEVICE_RESET:** wait 100 ms before writing configuration
- **Gyroscope startup from sleep:** 35 ms
- **Accelerometer startup from sleep:** 20 ms; from cold start (1 ms VDD ramp): 30 ms
- **Magnetometer data valid (cold start):** 7.3 ms
- **AK8963 power-down to mode change:** 10 ms minimum
- **SPI config registers:** 1 MHz max; sensor and interrupt registers: 20 MHz max
- **Supply ramp:** monotonic, 0.1–100 ms (10%–90% of final value)

## Implementation Notes

- **WHO_AM_I:** Register 0x75; value is always `0x73` for MPU-9255 (the MPU-9250 reads `0x71` at the same address — do not accept it as a valid ID here). Raise a descriptive error for any other value.
- **Register map parity with MPU-9250:** Every register address, bit field, and sensitivity table in this spec is identical to the MPU-9250's, confirmed against the MPU-9255 Wake-on-Motion flowchart and electrical characteristic tables in this datasheet. The two drivers are independent files per the repo's per-chip layout, but implementers may use the existing `mpu9250` driver in each language as a structural reference — only the WHO_AM_I check and (optionally) the wake-on-motion helpers differ.
- **Magnetometer access — I²C transport:** Enable BYPASS_EN in INT_PIN_CFG (`0x37` bit 1). The host can then address the AK8963 directly at 0x0C. This is the recommended approach for I²C transport.
- **Magnetometer access — SPI transport:** SPI shares its pins with the I²C bypass bus; BYPASS_EN cannot be used. Instead, configure the MPU's internal I²C master (USER_CTRL I2C_MST_EN=1) and set up I2C_SLV0 to auto-read 7 bytes from AK8963 starting at register 0x03 (ST1). The results land in EXT_SENS_DATA (0x49–0x4F). Implementation complexity is significant; the Full driver must handle both transports.
- **I2C_IF_DIS (SPI only):** When initialising via SPI, set bit 4 of USER_CTRL immediately after reset to disable the I²C interface and prevent inadvertent I²C transactions from switching the chip into I²C mode.
- **ST2 must be read:** After each magnetometer data read, read AK8963 ST2 (`0x09`). Without this read, the AK8963 does not refresh its output registers. Include ST2 in the burst read (read 7 bytes 0x03–0x09).
- **Factory ASA calibration:** Must be read once during `enable_mag` in fuse ROM access mode (CNTL1=0x0F). Cache the three scale factors; do not re-read on every measurement.
- **SPI burst read:** For maximum throughput, read all 14 sensor bytes (accel + temp + gyro: 0x3B–0x48) in a single burst transaction.
- **Magnetometer axis orientation:** The magnetometer die has a different coordinate system from the accelerometer/gyroscope (Figure 4 vs Figure 5 in the datasheet). The driver does not remap axes; document this clearly in the API.
- **FIFO ordering:** When multiple sources are enabled in FIFO_EN, data is packed in this order: ACCEL → GYRO → TEMP → EXT_SENS (if configured). Each field is 2 bytes, big-endian.
- **Wake-on-motion requires the gyro off:** The hardware WOM path only operates while the gyroscope is disabled and the accelerometer is in duty-cycled (CYCLE=1) low-power mode; `configure_wake_on_motion` must disable the gyro (PWR_MGMT_2 DIS_XG/YG/ZG=1) and the caller must re-enable it explicitly after motion is detected if gyro data is needed.
- **Datasheet typo (16-bit magnetometer sensitivity):** §2.3 states "16 bit (15µT/LSB)", which is physically inconsistent with a ±4800 µT full-scale range at 16-bit resolution. Treat this as a typo for 0.15 µT/LSB (matches the known AK8963 16-bit sensitivity, consistent with the sibling MPU-9250 spec).

## Sigrok Decoder

The `mpu9255` decoder matches I²C addresses `0x68` and `0x69` (primary device) and `0x0C` (AK8963 magnetometer, when bypass mode is active). For SPI, it matches any CS channel. It annotates register writes with decoded field values (e.g., "GYRO_CONFIG: FS=±250dps DLPF_active"), burst reads of 0x3B–0x48 as computed accel (m/s²), temperature (°C), and gyro (rad/s) on all three axes, and AK8963 burst reads 0x03–0x09 as magnetic field strength in µT with calibration applied. PWR_MGMT_1 writes annotate the power state change. WHO_AM_I reads annotate the ID value and flag any value other than `0x73` as unexpected. Writes to WOM_THR, LP_ACCEL_ODR, and MOT_DETECT_CTRL are annotated as wake-on-motion configuration; INT_STATUS reads with bit 6 set are annotated as a motion interrupt.
