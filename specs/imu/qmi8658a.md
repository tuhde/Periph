# Chip Spec: QMI8658A

**Manufacturer:** QST Corporation  
**Datasheet:** `datasheets/imu/qmi8658a.pdf`  
**Category:** `imu`  
**Transports:** I²C, SPI (4-wire and 3-wire)

## Overview

The QMI8658A is a 6-axis inertial measurement unit in a 2.5 × 3.0 × 0.86 mm 14-pin LGA package: a 3-axis MEMS gyroscope (±16 … ±2048 dps in eight ranges, 13 mdps/√Hz noise), a 3-axis MEMS accelerometer (±2 / ±4 / ±8 / ±16 *g*, 150 µg/√Hz noise) and a 16-bit temperature sensor. Both sensors have programmable output data rates and low-pass filters; the accelerometer also has low-power modes (3–128 Hz). A 1536-byte FIFO, two interrupt pins, and a built-in motion co-processor (any-motion, no-motion, significant-motion, single/double tap, pedometer, wake-on-motion) are included, plus gyroscope calibration-on-demand (COD) and sensor self-test. The host interface is I²C (≤ 400 kHz), I3C, or 3-/4-wire SPI (≤ 15 MHz). The DMP-style AttitudeEngine and the I3C interface are not covered. Supply is 1.71–3.6 V (VDD and VDDIO). Typical uses: wearables, game controllers, robot vacuums, gesture and step detection, tilt and orientation.

## Transport Configuration

### I²C
- **Address:** `0x6B` (SA0 = GND) — `0x6A` (SA0 = VDDIO or floating; internal 200 kΩ pull-up)
- **Max clock:** 400 kHz (standard and fast mode)
- **Identity register:** `0x00` = `0x05` (`WHO_AM_I`)
- **Probe safety:** `register_pointer` — the first data byte after the slave address selects the register pointer, so a 1-byte write only moves the pointer

The interface is selected by the `CS` pin: `CS` high = I²C/I3C enabled, `CS` low = SPI. The I²C address is latched during the reset process (SA0 is sampled, then its internal pull-up is disabled).

### SPI
- **Mode:** CPOL=0 CPHA=0 (Mode 0) or CPOL=1 CPHA=1 (Mode 3) — the chip detects the mode automatically; the driver uses Mode 3 like the other IMUs
- **Max clock:** 15 MHz
- **Bit order:** MSB first
- **CS active:** low
- **Register addressing:** read bit `0x80` (bit 7 = 1 for read, 0 for write; address in bits 6:0); multi-byte bit none — burst transfers auto-increment the address only while `CTRL1.ADDR_AI` = 1 (see Implementation Notes) — see `specs/feature_register_access_design.md` §4
- **4-wire vs 3-wire:** `CTRL1.SIM` = 0 (default) selects 4-wire (SDI, SDO separate); `CTRL1.SIM` = 1 selects 3-wire (bidirectional SDIO). The driver supports 4-wire; 3-wire needs a host bus that can turn the data line around and is not exposed as a driver option.

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| INT1 | high, push-pull | Programmable interrupt 1: CTRL9 handshake (not used by the driver — it polls `STATUSINT`), FIFO watermark/full (if `CTRL1.FIFO_INT_SEL` = 1), motion-engine events (if `CTRL8.ACTIVITY_INT_SEL` = 1), wake-on-motion. High-Z while `CTRL1.INT1_EN` = 0 |
| INT2 | high, push-pull | Interrupt 2 / data ready (DRDY): data-ready pulse (if `CTRL7.DRDY_DIS` = 0 and the FIFO is in bypass), FIFO interrupt (if `FIFO_INT_SEL` = 0), motion-engine events (if `ACTIVITY_INT_SEL` = 0). High-Z while `CTRL1.INT2_EN` = 0 |
| SA0 / SDO | — | I²C address select (I²C) or SPI data out (4-wire SPI) |
| CS | low | Chip select; high selects I²C |

The INT pins are push-pull when enabled (high-Z otherwise); no external pull-up is needed. Both pins are active-high; the polarity is not programmable (only the wake-on-motion initial level is selectable, see Wake-on-motion). Unused pins SDx, SCx, RESV (pin 10) should be tied to VDDIO or left floating; RESV-NC (pin 11) must be left unconnected. Internal 200 kΩ pull-ups exist on SCL, SDA, CS, SDx, SCx, RESV and can be switched off with `CTRL_CMD_SET_RPU`.

|---------|------|------|-------------|

| `CTRL_CMD_REQ_FIFO` | `0x05` | Ctrl9R | Enter FIFO read mode (`FIFO_CTRL.FIFO_RD_MODE` = 1) |
| `CTRL_CMD_WRITE_WOM_SETTING` | `0x08` | WCtrl9 | Configure / enable / disable wake-on-motion |
| `CTRL_CMD_ACCEL_HOST_DELTA_OFFSET` | `0x09` | WCtrl9 | Accelerometer offset, `CAL1`–`CAL3` = X, Y, Z in signed 4.12 (1/4096 *g*) |
| `CTRL_CMD_GYRO_HOST_DELTA_OFFSET` | `0x0A` | WCtrl9 | Gyroscope offset, `CAL1`–`CAL3` = X, Y, Z in signed 11.5 (1/32 dps) |
| `CTRL_CMD_CONFIGURE_TAP` | `0x0C` | WCtrl9 | Tap parameters (two commands) |
| `CTRL_CMD_CONFIGURE_PEDOMETER` | `0x0D` | WCtrl9 | Pedometer parameters (two commands) |
| `CTRL_CMD_CONFIGURE_MOTION` | `0x0E` | WCtrl9 | Any / no / significant-motion parameters (two commands) |
| `CTRL_CMD_RESET_PEDOMETER` | `0x0F` | WCtrl9 | Clear the step count |

## Initialization Sequence

1. Power up (VDD/VDDIO ramp ≥ 40 V/s through 1.1 V → 1.71 V; VDDIO no later than VDD). Wait ≥ 15 ms (system turn-on time) before any register access.
2. Write `RESET` (`0x60`) ← `0xB0` (soft reset); wait ≥ 15 ms. The reset returns every register to its reset value and the I²C address is re-sampled from SA0.
3. Read `0x4D`; it should equal `0x80` (successful reset). The value is only valid immediately after the reset; the driver does not treat a different value as an error.
4. Read `WHO_AM_I` (`0x00`); verify it equals `0x05`, raise a descriptive error otherwise.
5. Write `CTRL1` (`0x02`) ← `0x40` (`ADDR_AI` = 1, `BE` = 0, 4-wire SPI, both INT pins high-Z, high-speed oscillator on).
6. Write `CTRL8` (`0x09`) ← `0x80` (CTRL9 handshake by polling `STATUSINT.bit7`, all engines off).
7. Write `CTRL2` (`0x03`) ← `0x05` (±2 *g*, 224.2 Hz) and `CTRL3` (`0x04`) ← `0x45` (±256 dps, 224.2 Hz).
8. Write `CTRL5` (`0x06`) ← `0x77` (both low-pass filters enabled, mode 3 = 13.37 % of ODR ≈ 30 Hz).
9. Write `CTRL7` (`0x08`) ← `0x03` (accelerometer and gyroscope on, FIFO bypass so DRDY is active).
10. Wait ≥ 165 ms (gyroscope turn-on: 150 ms + 3/ODR = 163.4 ms; the accelerometer needs 3 ms + 3/ODR) before the first read.

Configuration registers (`CTRL1`–`CTRL9`) are written one register per transaction — burst writes to them are not supported.

## Interrupt

| Property | Value |
|----------|-------|
| INT pins | `INT1` and `INT2`, active-high push-pull when enabled (`CTRL1.INT1_EN` / `INT2_EN`), high-Z otherwise |
| Level | 3 (two interrupt lines, each carrying a selectable group of sources) |
| Condition(s) | data ready (INT2 only); FIFO watermark / full (INT1 or INT2); any-motion, no-motion, significant-motion, step, tap (INT1 or INT2, one choice for the whole group); wake-on-motion (INT1 or INT2, set in the WoM command) |
| Clear mechanism | data ready: pulse, self-clearing; FIFO flags: clear when the FIFO is drained below the threshold and `FIFO_RD_MODE` is cleared; engine flags in `STATUS1`: cleared by reading `STATUS1` (WoM explicitly; the engines' level interrupts follow their detection conditions) |

Multiple sources routed to one pin are OR-ed. The driver does not use the CTRL9 handshake interrupt on INT1 (it sets `CTRL8.bit7`).

SyncSample mode (`CTRL7.bit7` = 1) is incompatible with the FIFO and the motion engines; in that mode DRDY is on INT2 and engine events are on INT1.

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits everything and adds the rest.

### Minimal

Goal: expose 3-axis acceleration and 3-axis angular rate with no configuration required beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Runs the Initialization Sequence (reset, `WHO_AM_I` check, ±2 *g*, ±256 dps, 224.2 Hz); returns after the gyroscope start-up wait |
| `accel` | — | `(float, float, float)` | Linear acceleration (x, y, z) in m/s² |
| `gyro` | — | `(float, float, float)` | Angular rate (x, y, z) in rad/s |

**Sensible defaults baked into Minimal:** accelerometer ±2 *g*, gyroscope ±256 dps, both ODRs code 5 (224.2 Hz in 6DOF), both low-pass filters enabled at mode 3 (13.37 % of ODR), both sensors enabled, `CTRL1` = `0x40` (auto-increment on, little-endian, 4-wire SPI), CTRL9 handshake by polling, FIFO bypass (DRDY active), all INT pins high-Z, all motion engines off.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|

## Data Conversion

```
accel_raw    = int16(AX_H << 8 | AX_L)                      # low byte first (CTRL1.BE = 0)
acceleration = accel_raw / sensitivity * 9.80665            # m/s^2
    # sensitivity (LSB/g): 16384 (±2 g), 8192 (±4 g), 4096 (±8 g), 2048 (±16 g) = 16384 >> aFS

gyro_raw     = int16(GX_H << 8 | GX_L)
angular_rate = gyro_raw / sensitivity * pi / 180            # rad/s
    # sensitivity (LSB/dps): 2048 >> gFS = 2048 (±16), 1024 (±32), 512 (±64), 256 (±128),
    #                        128 (±256), 64 (±512), 32 (±1024), 16 (±2048)

temp_raw     = int16(TEMP_H << 8 | TEMP_L)
temperature  = temp_raw / 256.0                             # °C   (T = TEMP_H + TEMP_L / 256, signed)

timestamp    = TIMESTAMP_HIGH << 16 | TIMESTAMP_MID << 8 | TIMESTAMP_LOW   # samples, wraps at 0xFFFFFF
fifo_bytes   = 2 * ((FIFO_STATUS & 0x03) << 8 | FIFO_SMPL_CNT)
step_count   = STEP_CNT_HIGH << 16 | STEP_CNT_MIDL << 8 | STEP_CNT_LOW
```

Parameter encodings:

```
any/no-motion threshold code = round(threshold_g * 32)      # u3.5, 1/32 g, 0..255
tap alpha / gamma code       = round(value * 128)           # u0.7
tap peak / quiet threshold   = round(value_g2 * 1024)       # 16-bit, 1/1024 g^2
pedometer peak thresholds    = round(value_mg / 1000 * 1024)  # 16-bit, 1/1024 g (1 mg ≈ 1/1024 g)
wake-on-motion threshold     = threshold_mg                 # 1 mg per LSB, 8 bit
accel offset code            = round(offset_m_s2 / 9.80665 * 4096)   # signed 4.12, 16-bit
gyro offset code             = round(offset_rad_s * 180 / pi * 32)   # signed 11.5, 16-bit
accel self-test result       = int16(dV_H << 8 | dV_L) / 2048.0      # g   (u5.11 signed, 0.5 mg)
gyro self-test result        = int16(dV_H << 8 | dV_L) / 16.0        # dps (u12.4 signed, 62.5 mdps)
```

Effective output data rate: if both sensors are on, both run at the gyroscope-derived rate of their (identical) code (7174.4 Hz × 2⁻ᶜᵒᵈᵉ for codes 0–8); accelerometer-only operation uses the internal oscillator (1000 Hz × 2^(3−code) for codes 3–8, or the low-power rates). Low-pass filter bandwidth = mode % × ODR.

## Timing Constraints

- **Power-on / reset to register access:** system turn-on time 15 ms maximum (from the release of POR or the soft reset, which starts ≈ 200 µs after the event); no write or configuration during this time. **Conformance-checked** as `reset_recovery` (min 15 ms): from the `RESET` write (`0x60` ← `0xB0`) to the next transaction, against the sigrok decoder's `reset_recovery_start` / `reset_recovery_done` annotation pair — see [Sigrok Decoder](#sigrok-decoder) and `specs/imu/qmi8658a_timing.conf`.
- **Gyroscope turn-on:** 150 ms (t1, typical) plus 3/ODR (filter settling, t5) from setting `CTRL7.gEN` to usable data; the first samples before that are not valid. **Conformance-checked** as `gyro_startup` (min 150 ms), from the `CTRL7` write that sets `gEN` to the first read of a sensor-data register (any read starting in `0x33`–`0x40`), via the `gyro_startup_start` / `gyro_startup_done` pair — see `specs/imu/qmi8658a_timing.conf`. The 3/ODR part is ODR-dependent and not checked.
- **Accelerometer turn-on:** 3 ms (t2) plus 3/ODR from setting `CTRL7.aEN`.
- **Sensor off transition (t6):** 1/ODR to 2/ODR after clearing the enables.
- **Mode transition between sensor-off states (t7):** < 100 µs at 400 kHz I²C, ≈ 40 µs at 11 Mbit/s SPI.
- **ODR change on the fly:** the new data is stable after at least 3 samples (filter settling); discard the first few.
- **Data-lock delay (SyncSample, after `Avail`):** gyroscope on: 2 µs (codes 0–1), 4 µs (code 2), 6 µs (code 3), 12 µs (codes 4–8); accelerometer only: 6 µs (1000 Hz), 12 µs (500 Hz), 24 µs (250 Hz), 48 µs (≤ 125 Hz), 40 µs (128 Hz low power), 100 µs (21 Hz), 200 µs (11 Hz), 270 µs (3 Hz). The driver polls `STATUSINT.Locked` instead of sleeping.
- **FIFO read mode:** while `FIFO_RD_MODE` = 1 new samples are discarded; read the FIFO and clear the mode within 1/ODR.
- **Self-test duration:** accelerometer ≈ 25 ODR periods (25 ms at 1 kHz, 800 ms at 32 Hz, 2.2 s at 11 Hz); gyroscope ≈ 400 ms. The driver polls `STATUSINT.Avail` with a 3 s timeout.
- **Calibration-on-demand:** ≈ 1.5 s; the driver polls `CmdDone` with a 3 s timeout.
- **Temperature refresh:** 8 Hz.
- **SPI:** 15 MHz max, CS setup 6 ns, hold 8 ns; I²C 400 kHz, bus-free time 1.3 µs.

## Implementation Notes

- **Register-addressed:** accept `RegisterConnection` (1-byte register address) and call `connection.read(reg, length)` / `connection.write(reg, data)` directly — no chip-local `_read_reg`/`_write_reg` and no `bus_type` branch (see `specs/feature_register_access_design.md`). The SPI connection is built with `read_bit=0x80` and no multi-byte bit.
- **`ADDR_AI` and `BE` must be set up first:** reset values are `ADDR_AI` = 0 (address stays on one register during a burst — a 14-byte read returns the same byte 14 times) and `BE` = 1 (big-endian reads). `init` writes `CTRL1` = `0x40` (`ADDR_AI` = 1, `BE` = 0) before the first burst read. Tables in the datasheet list `BE` default as `1`; the driver never relies on the reset value. The driver keeps a `CTRL1` shadow and preserves the INT enables and `FIFO_INT_SEL`.
- **Burst writes to configuration registers are unsupported:** write `CTRL1`–`CTRL9` one register per transaction. The `CAL` registers are also written one byte per transaction (the datasheet's restriction names only the configuration registers; single writes are correct under either reading).
- **Shadow registers:** `CTRL1`, `CTRL7` and `CTRL8` hold fields owned by different features (INT pins, sensors, engines, handshake type); the driver caches the last written value of each and modifies only its own bits. Reads of these registers are never needed.
- **CTRL9 protocol:** write parameters to `CAL1`–`CAL4`, write the command to `CTRL9`, poll `STATUSINT.bit7` (`CmdDone`) until set (timeout 100 ms, 3 s for COD), write `CTRL9` ← `0x00` (`CTRL_CMD_ACK`), then poll `STATUSINT.bit7` until clear. Because `CTRL8.bit7` is set to 1, the INT1 line is not used for the handshake. The reset-time `CTRL_CMD_COPY_USID` data is overwritten once sensors are enabled, so `device_info` always issues the command.
- **Engine and offset configuration needs sensors off:** the datasheet requires `aEN` = `gEN` = 0 for the tap, pedometer, motion and WoM configuration commands; the driver clears `CTRL7`'s enables, issues the command, and restores the previous enables (paying the gyroscope turn-on time again if the gyroscope was on).
- **Data tearing in non-SyncSample mode:** the data registers are updated at the ODR; read them within the DRDY high period (or accept a rare mix of two samples on a very slow bus). The 14-byte burst takes ≈ 0.4 ms at 400 kHz and ≈ 10 µs at 10 MHz SPI, well under 1/ODR at the default rate. `set_sync_sample(True)` gives torn-free reads by locking: read `STATUSINT`; when `Avail` = 1 the chip locks the sample (poll `Locked`), then burst-read to `GZ_H` (or `AZ_H` for accelerometer only), which releases the lock. Enable with `CTRL7` = `0x83` / `0x82` / `0x81` (6DOF / gyro / accel); disable the AHB clock gating (CTRL9 `0x12`, `CAL1_L` = 1) first on I²C (and on SPI in accelerometer-only mode below 500 Hz); re-enable it (`CAL1_L` = 0) when leaving the mode.
- **FIFO and DRDY are exclusive:** `FIFO_MODE` ≠ 0 disables DRDY and `STATUS0` data flags may not update; `FIFO_MODE` = 0 disables the FIFO. SyncSample mode does not support the FIFO. Both sensors must use the same ODR code when both are written to the FIFO.
- **FIFO read procedure** (datasheet §8.8): read `FIFO_STATUS` / `FIFO_SMPL_CNT`; CTRL9 `REQ_FIFO` (`0x05`); read `FIFO_DATA` (`0x17`) for the byte count; write `FIFO_CTRL.FIFO_RD_MODE` ← 0 (preserving the mode and size bits). `FIFO_SMPL_CNT` counts 2-byte words. Reading `FIFO_DATA` with `ADDR_AI` = 1 would walk into `0x18…`; the driver therefore clears `CTRL1.ADDR_AI` for the drain (§16.1: with `ADDR_AI` = 0 the same register is output repeatedly) and restores it afterwards — **this behaviour is derived from §16.1 and not stated for FIFO_DATA specifically; verify on hardware** (fallback: one 1-byte read per FIFO byte). Read in chunks of at most 32 bytes (SMBus/I²C limits). Frame layout: little-endian X, Y, Z per sensor; accelerometer frame first when both are enabled (12 bytes per sample, 6 for one sensor). FIFO capacity is 128 samples (1536 bytes at 12 bytes per sample).
- **Reset value mismatches in the datasheet:** `REVISION_ID` is listed as `0x68` in Table 19 but `0x7C` in Table 21; the soft-reset value is `0xB0` in Table 27 and the §5.9 summary but "`0x0B`" in §7.4. The driver writes `0xB0` (the register-table value) and does not check `REVISION_ID`; confirm the reset on hardware via the `0x4D` = `0x80` read.
- **Wake-on-motion:** Table 31 lists WoM as "accelerometer on, gyroscope off, `aODR` = 11xx" (low-power code), while §12.3 only says to configure ODR and range. The driver uses code 12 (128 Hz) and ±2 *g* for WoM. There is no sensor data in WoM mode. The selected pin toggles on every event (initial value from `CAL1_H[7:6]`: `01` INT2 low, `11` INT2 high, `00` INT1 low, `10` INT1 high); reading `STATUS1` clears the `WoM` flag and resets the pin. The pin must also be enabled in `CTRL1` (`INT1_EN` / `INT2_EN`). To exit: sensors off, WoM command with threshold 0, then reconfigure.
- **Self-test:** requires sensors off; the chip forces ±16 *g* (accelerometer) and its own range/ODR (gyroscope) and restores `CTRL2` / `CTRL3` when finished. The result registers `dVX`–`dVZ` double as `COPY_USID` and COD output and may be overwritten by later operations — read them immediately after the `Avail` flag. Thresholds: accelerometer > 200 mg per axis, gyroscope > 300 dps per axis.
- **COD:** requires both sensors disabled and a still device; ≈ 1.5 s; `COD_STATUS` = `0x00` is success. New gains apply to the gyroscope X and Y axes (Z is not affected) until reset; save them with `get_gyro_gains` and restore with `set_gyro_gains` (not advisable after a significant PCB stress change). The gain registers are General Purpose registers shared with self-test and USID.
- **Offsets:** the delta-offset commands add to the factory calibration; behaviour of repeated calls (replace vs accumulate) is not stated in the datasheet — call once after reset, and re-apply after every `reset()` / power cycle.
- **Pedometer / tap / motion:** all engines need the accelerometer on and FIFO/SyncSample modes compatible (non-SyncSample). The tap engine runs best above 200 Hz ODR; the tap window values in the defaults are for 500 Hz, the pedometer values for 50 Hz — scale the sample-count parameters for other ODRs. `CTRL8.Pedo_EN` 0→1 resets the step count; clearing the accelerometer enable does not. The significant-motion engine depends on any- and no-motion being configured and enabled.
- **Sibling QMI8658C:** QST also sells the QMI8658C; this spec covers only the QMI8658A datasheet and no compatibility is assumed.
- **Not covered:** I3C, 3-wire SPI as a driver option, the AttitudeEngine (removed from this datasheet revision), per-axis calibration beyond COD/offsets.
- **Datasheet revision:** the committed datasheet is document 13-52-25 Rev A (20 June 2022), 88 pages, supplied by URL in the issue.

## Sigrok Decoder

Decoder id `qmi8658a`, input `['i2c', 'spi']`. Matches I²C addresses `0x6A` and `0x6B` and any SPI chip-select channel. For SPI the read bit (`0x80`) is stripped from the first byte and the register is named from the remaining address. The decoder annotates every register of the register map by name; decodes `CTRL1` (SIM, ADDR_AI, BE, INT enables, FIFO_INT_SEL, SensorDisable), `CTRL2` / `CTRL3` (self-test, full-scale in *g* / dps, ODR in Hz — accelerometer-only vs 6DOF read from the current `CTRL7`), `CTRL5` (filter enables and bandwidth %), `CTRL7`, `CTRL8`, `FIFO_CTRL`, `FIFO_STATUS`, `STATUSINT`, `STATUS0`, `STATUS1`, `TAP_STATUS`, `COD_STATUS` into named flags; names every `CTRL9` command write; assembles burst reads of `0x33`–`0x40` as temperature (°C), acceleration (m/s²) and angular rate (rad/s) at the last-seen full scales; assembles reads of `0x30`–`0x32` as the timestamp and `0x5A`–`0x5C` as the step count; shows `WHO_AM_I` reads checked against `0x05`; flags a burst read at `ADDR_AI` = 0 and a write to a configuration register longer than one byte as warnings. For the conformance checks the decoder emits, in the `timing` annotation row shaped per `specs/sigrok_annotations.md`'s Variable-Length Annotation Convention: `reset_recovery_start` on the `RESET` write of `0xB0` and `reset_recovery_done` on the next transaction (the `reset_recovery` check); `gyro_startup_start` on a `CTRL7` write that sets `gEN` (bit 1) and `gyro_startup_done` on the next read whose start address is in `0x33`–`0x40` (the `gyro_startup` check). The checks' bounds are in `specs/imu/qmi8658a_timing.conf`.
