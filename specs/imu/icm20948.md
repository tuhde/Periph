# Chip Spec: ICM-20948

**Manufacturer:** TDK InvenSense  
**Datasheet:** `datasheets/imu/icm20948.pdf`  
**Category:** `imu`  
**Transports:** I²C (the chip also supports 4-wire SPI at up to 7 MHz; out of scope for this issue — see Implementation Notes)

## Overview

The ICM-20948 is a 9-axis MotionTracking device in a 3 × 3 × 1 mm 24-pin QFN: a 3-axis MEMS gyroscope (±250 / ±500 / ±1000 / ±2000 dps), a 3-axis MEMS accelerometer (±2 / ±4 / ±8 / ±16 *g*) and an AK09916 3-axis magnetometer (±4900 µT, 16-bit, 0.15 µT/LSB) in one package, with a 4 KiB FIFO, a wake-on-motion interrupt, per-sensor programmable low-pass filters and sample-rate dividers, low-power duty-cycled modes, an on-chip temperature sensor, an auxiliary I²C master that reads the magnetometer (or other sensors) without host involvement, and a Digital Motion Processor (DMP). All sensors are 16-bit. Typical uses: orientation / heading (AHRS), gesture and motion detection, wearables, drones, wake-on-motion for battery devices.

The registers are organised in **four user banks** selected through `REG_BANK_SEL` (`0x7F`, present in every bank) — the main structural difference from the MPU-9250. The DMP firmware and its memory are not documented in this datasheet and are **not** covered; the driver reads sensor registers directly. VDDIO is 1.71–1.95 V only (not 3.3 V compatible, unlike the MPU-9250); VDD is 1.71–3.6 V.

## Transport Configuration

### I²C
- **Address:** `0x68` (AD0 = GND) — `0x69` (AD0 = VDDIO)
- **Max clock:** 400 kHz (fast mode); 100 kHz standard mode also supported
- **Identity register:** `0x00` = `0xEA` (`WHO_AM_I`, **user bank 0 only**) — read with mask `0xFF`, expected `0xEA`
- **Probe safety:** `register_pointer` — the identity read has no side effects. The identity is only visible while bank 0 is selected; a bank left at 1–3 by an earlier program reads that bank's register `0x00` instead (see Implementation Notes).

Plain register-pointer I²C: write the register address, repeated START, read. Multi-byte reads and writes auto-increment the register address. There is no auto-increment bit. Power-up with SCL held low is not a supported use case (software reset is then required before initialisation). After power-up the device **comes up in sleep mode**.

The magnetometer (AK09916, 7-bit address `0x0C`) is on the **auxiliary** I²C bus (`AUX_CL` / `AUX_DA`), not on the host bus. The driver reads it through the ICM-20948's own I²C master (no second connection required).

The magnetometer uses a different map from the AK8963 of the MPU-9250 (data at `0x10…0x18`, mode in `CNTL2`, no fuse-ROM adjustment). Address auto-increment: `0x00 → 0x01 → 0x02 → 0x03 → 0x10 → … → 0x18 → 0x00`; `0x30 → 0x32 → 0x30`. On VDD power-on all magnetometer registers are initialised.

| `MODE<4:0>` | Operation |
|-------------|-----------|

## Initialization Sequence

1. Power up; wait for the start-up time before register access: 11 ms typical, 100 ms maximum from power-up. The chip is in sleep mode.
2. Write `REG_BANK_SEL` (`0x7F`) ← `0x00` (bank 0).
3. Read `WHO_AM_I` (`0x00`); verify it equals `0xEA`.
4. Write `PWR_MGMT_1` (`0x06`) ← `0x80` (`DEVICE_RESET`); wait ≥ 100 ms (the datasheet gives no reset time; the same wait as the MPU-9250 is used). The reset returns the bank to 0.
5. Write `PWR_MGMT_1` ← `0x01` (`SLEEP` = 0, `LP_EN` = 0, `CLKSEL` = 1 auto).
6. Write `PWR_MGMT_2` ← `0x00` (accelerometer and gyroscope on).
7. Select bank 2: write `GYRO_SMPLRT_DIV` ← `0x0A` (102.3 Hz), `GYRO_CONFIG_1` ← `0x19` (±250 dps, `DLPFCFG` = 3 / 51.2 Hz, filter on), `ACCEL_SMPLRT_DIV_1` ← `0x00`, `ACCEL_SMPLRT_DIV_2` ← `0x0A` (102.3 Hz), `ACCEL_CONFIG` ← `0x19` (±2 *g*, `DLPFCFG` = 3 / 50.4 Hz, filter on).
8. Select bank 0 again.
9. Wait ≥ 35 ms (gyroscope start-up from sleep; the accelerometer needs 20 ms) before the first sample.

### Magnetometer enable (Full `enable_mag`)

1. Bank 0: `USER_CTRL` ← `I2C_MST_EN` (`0x20`; keep other bits). Bank 3: `I2C_MST_CTRL` ← `0x07` (345.6 kHz).
2. Soft-reset the AK09916 through slave 4: `I2C_SLV4_ADDR` ← `0x0C` (write), `I2C_SLV4_REG` ← `0x32`, `I2C_SLV4_DO` ← `0x01`, `I2C_SLV4_CTRL` ← `0x80`; wait for `I2C_MST_STATUS.I2C_SLV4_DONE` (or `EN` to self-clear); wait ≥ 1 ms.
3. Read `WIA2` through slave 4 (`I2C_SLV4_ADDR` ← `0x8C`, `I2C_SLV4_REG` ← `0x01`, `I2C_SLV4_CTRL` ← `0x80`, wait, read `I2C_SLV4_DI`); verify it equals `0x09`.
4. Set the mode: slave 4 write of `CNTL2` (`0x31`) ← `0x08` (continuous 4, 100 Hz).
5. Configure slave 0 to read the data block continuously: `I2C_SLV0_ADDR` ← `0x8C`, `I2C_SLV0_REG` ← `0x10` (`ST1`), `I2C_SLV0_CTRL` ← `0x89` (`EN`, 9 bytes: `ST1`, `HXL`…`HZH`, `TMPS`, `ST2`). Bank 0: the 9 bytes appear in `EXT_SLV_SENS_DATA_00…08` at the sensor sample rate.

## Data Conversion

```
accel_raw     = int16(ACCEL_xOUT_H << 8 | ACCEL_xOUT_L)         # high byte first
acceleration  = accel_raw / sensitivity * 9.80665               # m/s^2
    # sensitivity (LSB/g): 16384 (±2 g), 8192 (±4 g), 4096 (±8 g), 2048 (±16 g)

gyro_raw      = int16(GYRO_xOUT_H << 8 | GYRO_xOUT_L)
angular_rate  = gyro_raw / sensitivity * pi / 180               # rad/s
    # sensitivity (LSB/dps): 131 (±250), 65.5 (±500), 32.8 (±1000), 16.4 (±2000)

temp_raw      = int16(TEMP_OUT_H << 8 | TEMP_OUT_L)
temperature_C = (temp_raw - 0) / 333.87 + 21                    # room-temperature offset 0 LSB at 21 °C, untrimmed sensitivity

mag_raw       = int16(HxH << 8 | HxL)                           # LOW byte first on the wire: HXL, HXH, HYL, HYH, HZL, HZH
flux_uT       = mag_raw * 0.15                                  # ±32752 counts = ±4912 µT; -32768 is not a valid value
```

Output data rates: gyro and accelerometer `ODR = 1125 Hz / (1 + SMPLRT_DIV)` (filter enabled); filter bypassed: 9 kHz (gyro), 4.5 kHz (accel). When the gyroscope is on, every sensor (including the I²C master) runs at the gyroscope ODR; with the gyroscope off, at the accelerometer ODR; with both off, the master uses `1.1 kHz / 2^I2C_MST_ODR_CONFIG`.

Offsets: gyro offset code (signed 16-bit) = round(offset_dps / 0.0305); accelerometer offset code = 15-bit, 0.98 mg per LSB (stored left-justified: `<14:7>` in the high register, `<6:0>` in bits 7:1 of the low register). Wake-on-motion: `ACCEL_WOM_THR` = round(threshold_mg / 4), 0–255. PLL time base: `deviation_% = int8(TBC_PLL) * 0.079`.

## Timing Constraints

- **Power-on to register access:** 11 ms typical, 100 ms maximum from power-up before registers can be read or written. **Conformance-checked** as for the MPU-9250: from the `PWR_MGMT_1` write with `DEVICE_RESET` set (`0x80`) — sigrok marker `poweron_start` — to the first subsequent register read — `poweron_ready` — the gap must be ≥ 100 ms. See `specs/imu/icm20948_timing.conf`.
- **Reset:** no duration is given for `DEVICE_RESET`; the driver waits ≥ 100 ms and re-selects bank 0.
- **Sensor start-up from sleep:** gyroscope 35 ms, accelerometer 20 ms (cold start 30 ms, 1 ms VDD ramp); allow 35 ms after waking.
- **PLL ready:** `PLL_RDY_INT` indicates the PLL is running; a 4 ms delay after it ensures lock. The gyroscope needs `CLKSEL` 1–5 for full performance.
- **Gyroscope low-power → low-noise transition:** several unsettled output samples (number depends on filter and ODR) — discard the first few samples after changing the power mode.
- **Duty-cycled on-time:** gyro `Ton` 1.15–57.59 ms and accelerometer `Ton` 0.821–7.71 ms depending on averaging (datasheet Tables 17, 19).
- **I²C master:** a slave-4 transfer takes a few master-clock periods; the driver polls `I2C_SLV4_DONE` / `EN` instead of sleeping. `I2C_MST_CLK` ≤ 7 keeps the bus below 400 kHz.
- **SPI (not used):** after disabling the gyroscope over SPI, wait 22 µs before writing most registers, reading the FIFO or reading memory.

## Implementation Notes

- **Register-addressed, banked:** accept `RegisterConnection` (1-byte register address) and call `connection.read(reg, length)` / `connection.write(reg, data)` directly — no chip-local `_read_reg`/`_write_reg` and no `bus_type` branch (see `specs/feature_register_access_design.md`). Every bank-1/2/3 access is a pair: write `REG_BANK_SEL` ← `bank << 4`, then the register access. The driver caches the selected bank, always returns to bank 0 after a bank-1–3 operation, and re-selects bank 0 in `init` (the bank is unknown after a warm start). The bank register is write-only in effect (value is `bank << 4`; bits 7:6 and 3:0 reserved).
- **WHO_AM_I only in bank 0:** a probe or `init` after a program left the bank at 1–3 reads the wrong register. `init` writes `REG_BANK_SEL` ← 0 first. The registry probe (`0x00`) assumes bank 0.
- **Sleep at power-up:** `PWR_MGMT_1` resets to `0x41` (`SLEEP` = 1, `CLKSEL` = 1); `init` clears `SLEEP` and keeps `CLKSEL` = 1 (the datasheet requires `CLKSEL` 1–5 for full gyroscope performance).
- **`LP_EN` blocks register writes:** with `LP_EN` = 1 most registers (all of banks 1–3 except `REG_BANK_SEL`; in bank 0 everything except `LP_CONFIG`, `PWR_MGMT_1`, `PWR_MGMT_2`, `INT_PIN_CFG`, `INT_ENABLE`, `FIFO_COUNTH/L`, `FIFO_R_W`, `FIFO_CFG`, `REG_BANK_SEL`) cannot be written. The driver clears `LP_EN` before every configuration write and sets it again afterwards only if the user enabled low-power mode via `set_low_power`.
- **Magnetometer via the I²C master (not bypass):** the master reads the 9-byte block `ST1 … ST2` continuously, so `ST2` is always read after the data (required to release the AK09916 data registers) and the three axes belong to one sample. While `I2C_MST_EN` = 1 the host cannot reach the auxiliary bus; `aux_read_byte` / `aux_write_byte` use slave 4 for that. `BYPASS_EN` pass-through (host talks to `0x0C` directly) is not used by the driver. `I2C_MST_RST` must only be set when the master has hung — setting it during a transfer hangs the slave.
- **Byte orders differ:** accelerometer / gyro / temperature are high byte first; the AK09916 (and therefore `EXT_SLV_SENS_DATA`) is low byte first. In the JVM drivers mask each byte with `0xFF`, narrow with `.toShort()` / `(short)` to sign-extend, and cast to `double` before multiplying.
- **Magnetometer overflow:** `HOFL` in `ST2` means the measurement is invalid; `mag` raises (and `mag_raw` returns the raw values anyway).
- **Magnetometer axes:** Figure 13 (compass) vs Figure 12 (gyro / accelerometer) in the datasheet shows the same +X but opposite +Y and +Z (+Z points down for the compass, up for the inertial sensors), i.e. the magnetometer frame is rotated 180° about X relative to the accelerometer frame. The driver returns the values as the chip reports them; a heading routine must map them with `(mx, -my, -mz)` into the accelerometer frame before tilt compensation. Verified from the figures only — check on hardware.
- **Sample rate:** the gyro ODR drives all sensors when the gyroscope is on; the accelerometer divider only matters in accelerometer-only operation. The datasheet text says "1.1 kHz" in one place and 1125 Hz in the tables — the driver uses 1125 Hz.
- **FIFO layout is not documented here:** the datasheet describes which sources can be written to the FIFO (`FIFO_EN_2`: accel 6 bytes, gyro 2 bytes per axis, temperature 2 bytes; `FIFO_EN_1` external slaves) but not the frame order. `read_fifo` returns raw bytes; `enable_fifo` with accel + gyro is documented in the examples as 12-byte frames (accel X, Y, Z then gyro X, Y, Z) per the vendor driver — verify on hardware. Reading the FIFO through I²C in a multithreaded environment can return wrong data (datasheet use note 14.3) — serialise access (mutex).
- **FIFO count latch:** read `FIFO_COUNTH` first; it latches both bytes. `FIFO_RST` must be asserted and then de-asserted to reset the FIFO. The size is 4 KiB (the datasheet notes it varies with the DMP feature set).
- **Self-test:** enabling `XGYRO_CTEN`…, `AX_ST_EN_REG`… actuates the sensors; the response (enabled minus disabled output) must be within limits from the specification tables, which are not tabulated in this revision. TDK recommends the MotionApps software for self-test. `self_test` configures ±2 *g* / ±250 dps, averages a few samples, enables the self-test bits, waits, averages again, restores the configuration and returns the responses — **no pass/fail**.
- **Wake-on-motion procedure is derived:** the datasheet gives the register fields (`ACCEL_INTEL_EN`, `ACCEL_INTEL_MODE_INT`, `ACCEL_WOM_THR`, `WOM_INT_EN`) but no enable sequence. The driver writes the threshold, sets `ACCEL_INTEL_CTRL` = `0x03` (enabled, compare with previous sample), enables `WOM_INT_EN`, and needs the accelerometer on with its filter enabled; verify the threshold semantics on hardware.
- **Per-part trims:** accelerometer offset registers (bank 1) hold per-part factory trims (reset value "trimmed on a per-part basis"); never overwrite them blindly. `TIMEBASE_CORRECTION_PLL` is a per-part calibration of the gyro clock (≈ 0.079 %/LSB) the user may apply to integrated angles.
- **Not covered:** the DMP (firmware load, quaternions, FIFO frames from the DMP), FSYNC capture (`DELAY_TIME*`, `EXT_SYNC_SET`), and SPI. The chip's SPI is mode 3 (the usual InvenSense mode) at up to 7 MHz with a read bit `0x80`, but the mode is not restated in this datasheet; a future SPI issue would need it verified. On SPI, `I2C_IF_DIS` must be set to keep the I²C slave off.
- **Siblings:** the ICM-20948 is not register-compatible with the MPU-9250 / MPU-9255 (banked registers, different `WHO_AM_I` `0xEA` at `0x00`, different magnetometer); no compatibility is assumed.
- **Datasheet revision:** the committed datasheet is the DS-000189 revision 1.6 (03/12/2024), 89 pages, supplied as an attachment to the issue; it includes the register map (a separate "Register Map and Register Descriptions" document is referenced but the same content is in this file).

## Sigrok Decoder

Decoder id `icm20948`, input `['i2c']`. Matches I²C addresses `0x68` and `0x69` (primary device) and `0x0C` (AK09916, only visible when the pass-through bypass is active). The decoder tracks `REG_BANK_SEL` writes and annotates every register of the current bank by name (the bank number is shown in each annotation); decodes `PWR_MGMT_1` / `PWR_MGMT_2`, `USER_CTRL`, `INT_PIN_CFG`, `INT_ENABLE*`, `INT_STATUS*`, `GYRO_CONFIG_1` / `ACCEL_CONFIG` (full scale and DLPF), the sample-rate dividers (as Hz), `I2C_MST_CTRL` (clock in kHz) and the `I2C_SLVx_*` registers into named flags; assembles burst reads of `0x2D–0x3A` (bank 0) as acceleration (m/s²), angular rate (rad/s) and temperature (°C) at the last-seen full scale, and reads of `EXT_SLV_SENS_DATA_00…08` as the magnetometer block in µT. `WHO_AM_I` reads are checked against `0xEA`. For the power-on conformance check the `PWR_MGMT_1` write with `DEVICE_RESET` set (`0x80`) is annotated `poweron_start` and the first subsequent register read of any kind `poweron_ready`, in the `timing` annotation row, shaped per `specs/sigrok_annotations.md`'s Variable-Length Annotation Convention. The gap must be ≥ 100 ms (see `specs/imu/icm20948_timing.conf`).
