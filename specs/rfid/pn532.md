# Chip Spec: PN532

**Manufacturer:** NXP Semiconductors  
**Datasheet:** `datasheets/rfid/pn532.pdf` (PN532/C1 Near Field Communication (NFC) controller, Rev. 3.6, 28 November 2017). The datasheet describes the chip and the host-interface selection; the **host command protocol** (frame format, command codes) is defined in the separate NXP *PN532 User Manual* (UM0701-02) and the NXP *PN532 Application Note*, which this spec follows (they are not part of this PDF)  
**Category:** rfid  
**Transports:** I²C

## Overview

The PN532 is a highly integrated 13.56 MHz NFC transceiver with an embedded 80C51 microcontroller and firmware. It supports ISO/IEC 14443 A/B (MIFARE, NTAG, ISO-DEP), FeliCa, ISO/IEC 18092 NFC peer-to-peer (initiator and target) and card emulation, as reader/writer, card emulator or NFC target. The host (here over I²C; the chip also offers SPI and a high-speed UART) exchanges **frames** with the firmware: it sends a command frame (`TFI = 0xD4`), the chip answers with an ACK frame and, once the operation is finished, with a response frame (`TFI = 0xD5`). A status byte in front of every I²C read tells the host whether the response is ready, and the `IRQ` pin (P70_IRQ) goes low when it is. Supply 2.7–5.5 V on `VBAT` (an internal LDO supplies the core), I²C up to 400 kHz. Typical uses: NFC/RFID readers for access control and ticketing, tag programming, NFC tag emulation, payment-terminal front ends.

## Transport Configuration

### I²C
- **Address:** `0x24` (7-bit, fixed; the 8-bit write address `0x48`, read `0x49`); one chip per bus
- **Interface selection:** `I0` and `I1` pins select the host interface: `I0 = 0, I1 = 0` HSU (UART); `I0 = 1, I1 = 0` SPI; `I0 = 0, I1 = 1` I²C (`Selif[1:0] = 10`); both `1` reserved. Hard-wire `I0` low and `I1` high for I²C (breakouts provide jumpers)
- **Max clock:** 400 kHz (fast mode); the chip may stretch the clock
- **Framing:** a write is the raw **command frame**; every read returns a **status byte** (`0x01` = response/ACK ready, `0x00` = not ready; bit 0) followed by the frame bytes — always read `1 + frame length` bytes (the ACK frame is 6 bytes, a response frame `8 + data` bytes)
- **Register addressing:** none (command protocol)
- **Identity register:** none; `GetFirmwareVersion` (`0x02`) answers `IC = 0x32`. Registered in `registry/chips.json` with `id_probe: null`
- **Probe safety:** `write_sensitive` — any written byte stream is parsed as a command frame; a probe should only check the address ACK and may read the status byte, which is harmless

SPI and HSU are out of scope for this spec (transport-specific framing: SPI uses `0x01` data write, `0x02` status read, `0x03` data read; HSU needs a long preamble to wake from power-down).

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| IRQ (P70_IRQ) | low | goes low when an ACK or response is ready for the host (I²C/SPI); returns high after the host read; pull-up needed |
| RSTPD_N | low | hardware reset / power-down input (hard power down while low, low time ≥ 20 ns; after release the chip needs 0.1–2 ms (0.4 ms typ.) to reset) |
| I0, I1 | — | host interface select (see above) |
| SDA, SCL | — | I²C; pull-ups required |
| VBAT, GND | — | 2.7–5.5 V |

## Frame Format

```
Normal frame:   00 | 00 FF | LEN | LCS | TFI | PD0 ... PDn | DCS | 00
                preamble + start code (00 00 FF), LEN = n + 2 (TFI + data), LCS = (0x100 - LEN) & 0xFF
                TFI = 0xD4 host -> PN532 (command), 0xD5 PN532 -> host (response)
                the first data byte PD0 is the command code (response: command code + 1)
                DCS = (0x100 - (TFI + sum(PD))) & 0xFF
ACK frame:      00 00 FF 00 FF 00
NACK frame:     00 00 FF FF 00 00
Error frame:    00 00 FF 01 FF 7F 81 00           (application-level error, TFI = 0x7F)
Extended frame: 00 00 FF FF FF LENM LENL LCS TFI PD0..PDn DCS 00   (payload > 254 bytes; length bytes in 16 bits)
```

An I²C command exchange: (1) write the command frame, (2) read the status byte until bit 0 = 1 (or wait for `IRQ` low), then read the 6-byte ACK frame (preceded by the status byte), (3) poll again until the response is ready, read the response frame (preceded by the status byte). A command that is not ACKed within a few milliseconds is resent (the host may send a NACK frame to request the last response again).

## Command Set (used by the driver)

| Command | Code | Request data | Response (`code + 1`) |
|---------|------|--------------|-----------------------|
| `Diagnose` | `0x00` | `test` … | `0x01` … (self-tests: communication line, ROM, RAM, antenna) |
| `GetFirmwareVersion` | `0x02` | — | `0x03`: `IC` (`0x32`), `Ver`, `Rev`, `Support` (bit 0 ISO/IEC 14443 A, bit 1 ISO/IEC 14443 B, bit 2 ISO/IEC 18092) |
| `GetGeneralStatus` | `0x04` | — | `0x05`: `Err`, `Field`, `NbTg`, per-target `Tg/BrRx/BrTx/Type`, `SAMStatus` |
| `ReadRegister` | `0x06` | `ADR1 ADR0` (16-bit address, repeated) | `0x07`: values |
| `WriteRegister` | `0x08` | `ADR1 ADR0 Value` (repeated) | `0x09` |
| `SetParameters` | `0x12` | `flags` | `0x13` |
| `SAMConfiguration` | `0x14` | `Mode` (1 = normal), `Timeout`, `IRQ` | `0x15` |
| `PowerDown` | `0x16` | `WakeUpEnable`, `GenerateIRQ` | `0x17`: status |
| `RFConfiguration` | `0x32` | `CfgItem`, config data | `0x33` (item `0x01` RF field: bit 0 AutoRFCA, bit 1 RF on; item `0x05` MaxRetries: `MxRtyATR`, `MxRtyPSL`, `MxRtyPassiveActivation`) |
| `InDataExchange` | `0x40` | `Tg`, `DataOut` | `0x41`: `Status`, `DataIn` |
| `InCommunicateThru` | `0x42` | `DataOut` | `0x43`: `Status`, `DataIn` (raw frames, no PN532 protocol handling) |
| `InDeselect` | `0x44` | `Tg` | `0x45`: `Status` |
| `InListPassiveTarget` | `0x4A` | `MaxTg` (1–2), `BrTy` (`0x00` = 106 kbps ISO/IEC 14443 A), `InitiatorData` | `0x4B`: `NbTg`, then per target `Tg`, `SENS_RES` (2), `SEL_RES`, `NFCIDLength`, `NFCID1…`, optional ATS |
| `InSelect` | `0x54` | `Tg` | `0x55`: `Status` |
| `InRelease` | `0x52` | `Tg` (0 = all) | `0x53`: `Status` |
| `InAutoPoll` | `0x60` | `PollNr`, `Period`, `Type1..` | `0x61`: found targets |

`Status` bits: bit 7 `NAD` present, bit 6 `MI` more information, bits 5:0 error code (`0x00` OK, `0x01` timeout, `0x02` CRC error, `0x03` parity error, `0x04` bit count error, `0x05` framing error, `0x06` bit collision, `0x07` buffer too small, `0x09` RF buffer overflow, `0x0A` RF field absent timeout, `0x0B` RF protocol error, `0x0D` temperature error, `0x0E` internal buffer overflow, `0x10` invalid parameter, `0x12` DEP command not supported, `0x13` DEP data format mismatch, `0x14` MIFARE authentication error, `0x23` UID check byte wrong, `0x25` invalid device state, `0x26` operation not allowed, `0x27` command not acceptable, `0x29` target released by initiator, `0x2A` card ID mismatch, `0x2B` card discarded, `0x2C` NFCID3 mismatch).

## Initialization Sequence

1. Power the chip (`VBAT`), release `RSTPD_N`, select I²C with `I0`/`I1`; wait for the chip to boot (the first command may need to be repeated: after reset or power-down the I²C interface wakes on the first address match, and the first transaction can be NACKed).
2. Send `GetFirmwareVersion`; read the ACK (6 bytes) and the response; check `IC = 0x32`.
3. Send `SAMConfiguration` with `Mode = 0x01` (normal mode, the SAM is not used), `Timeout = 0x14` (virtual card mode only), `IRQ = 0x01` (use the IRQ pin).
4. Optionally `RFConfiguration` item `0x05` (MaxRetries) with `MxRtyPassiveActivation = 0x02` (a finite retry count so that `InListPassiveTarget` returns when no card is present; the default `0xFF` retries forever).
5. Detect a card: `InListPassiveTarget (MaxTg = 1, BrTy = 0x00)`; read the response (wait for the status/IRQ); parse `NbTg`, `SENS_RES`, `SEL_RES`, `NFCID1`.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `IRQ` (P70_IRQ) — active-low; requires an external pull-up |
| Level | 1 |
| Condition(s) | the chip has an ACK or a response frame ready for the host (including a card detection from `InListPassiveTarget` with `MxRtyPassiveActivation = 0xFF`) |
| Clear mechanism | reading the frame; `IRQ` goes high after the read |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on `IRQ` (falling edge) via `connection.int_pin` (or `int_pin`), otherwise a polling task checking the status byte; `callback()` is called when a frame is ready and the driver reads it with `read_response` |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> bool` | `True` if the status byte reports a ready frame |

## Implementation Stages

### Minimal

Goal: detect an ISO/IEC 14443 A card or tag and read its UID, with no NFC-protocol knowledge needed.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Stores the plain `Connection`; wakes the chip (retries the first write), checks `GetFirmwareVersion` (`IC = 0x32`), `SAMConfiguration` (normal mode, IRQ on), `MxRtyPassiveActivation = 2` |
| `read_uid` | `timeout: float = 1.0` | `bytes` \| `None` | `InListPassiveTarget` (106 kbps type A, one target); returns the NFCID1 (4, 7 or 10 bytes) or `None` if no card answered within `timeout`; releases the target (`InRelease`) before returning |

**Sensible defaults:** 106 kbps ISO/IEC 14443 A, one target, a finite activation retry count, SAM in normal mode, RF field on after `SAMConfiguration`.

### Full

Goal: complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `firmware_version` | — | `{ic, version, revision, support}` | `GetFirmwareVersion`, `support` bit flags decoded |
| `general_status` | — | dict | `GetGeneralStatus` decoded (error, field present, number of targets, SAM status) |
| `list_passive_targets` | `baud: int = BAUD_106_A, max_targets: int = 1, initiator_data: bytes = b""` | `list[Target]` | `InListPassiveTarget`; `Target` has `tg`, `sens_res`, `sel_res`, `uid`, `ats`; `BAUD_106_A` = `0x00`, `BAUD_212_F` = `0x01`, `BAUD_424_F` = `0x02`, `BAUD_106_B` = `0x03` |
| `data_exchange` | `target: int, data: bytes` | `bytes` | `InDataExchange`; raises on a non-zero status |
| `communicate_thru` | `data: bytes` | `bytes` | `InCommunicateThru` (raw RF exchange) |
| `release` / `select` / `deselect` | `target: int = 0` | — | `InRelease` / `InSelect` / `InDeselect` |
| `mifare_authenticate` | `target: int, block: int, key: bytes (6), uid: bytes (4), key_b: bool = False` | — | `InDataExchange` with `0x60` (key A) / `0x61` (key B) + block + key + UID (the last 4 UID bytes) |

| `send_command` | `command: int, data: bytes = b"", timeout: float = 1.0` | `bytes` | Raw command/response with frame handling, ACK and error-frame detection |
| `wait_ready` | `timeout: float` | bool | Polls the status byte (or the `IRQ` pin) |
| interrupt API | | | see Interrupt section |

**Additional configuration options:** baud rate/modulation, retry counts, RF field control, SAM mode (virtual/wired/dual card, optional), power-down wake-up sources, raw register access.

## Data Conversion

```
# frame helpers
LCS = (0x100 - LEN) & 0xFF                                  # LEN = len(data) + 1 (TFI)
DCS = (0x100 - ((TFI + sum(data)) & 0xFF)) & 0xFF
frame = [0x00, 0x00, 0xFF, LEN, LCS, TFI, *data, DCS, 0x00]

# InListPassiveTarget (106 kbps type A) response payload (after TFI 0xD5, code 0x4B):
#   NbTg, Tg, SENS_RES[2], SEL_RES, NFCIDLength, NFCID1[NFCIDLength], (ATS...)
uid = bytes(payload[6 : 6 + payload[5]])

# MIFARE Classic authentication (InDataExchange data): [0x60|0x61, block, key[6], uid[4]]
```

Datasheet/UM example: `GetFirmwareVersion` command frame `00 00 FF 02 FE D4 02 2A 00`, ACK `00 00 FF 00 FF 00`, response `00 00 FF 06 FA D5 03 32 01 06 07 E8 00` (IC `0x32`, version 1.6, support `0x07`).

## Timing Constraints

| Constraint | Value |
|------------|-------|
| ACK after a command frame | within a few milliseconds (the driver waits up to 15 ms for the ACK, then resends) |
| Response time | depends on the command (`InListPassiveTarget` with a finite retry count: each activation attempt takes a few milliseconds, so the response arrives after at most `MxRtyPassiveActivation` attempts; infinite retries block until a target appears) |
| Hard power-down low time (`RSTPD_N`) | ≥ 20 ns (`THPD`) |
| Reset time after `RSTPD_N` release / at power-on | 0.1–2 ms, 0.4 ms typ. (`TresetRSTPD_N`, `Tresetpon`) |
| I²C clock | ≤ 400 kHz |

There is no bus-decodable start/end annotation pair with a datasheet bound (the ACK/response times are protocol-dependent waits), so `pn532_timing.conf` defines no checks.

## Implementation Notes

- **Plain Connection, frame protocol:** write the whole command frame with `write`; read with `read(1 + n)` (status byte first). Do not use a register-addressed connection. Repeat the read while the status byte is `0x00`; give up after the command's timeout.
- **Always read the ACK:** after every command read the 6-byte ACK frame (`00 00 FF 00 FF 00`) before polling for the response; a missing ACK means the chip did not understand the frame (resend the command; the chip may answer an error frame instead).
- **Status byte:** every I²C read starts with the status byte; the response frame bytes follow. Do not drop the status byte when parsing, and do not read more than `1 + frame length` bytes (extra bytes read `0xFF`/garbage).
- **Wake-up:** after power-down or a hard reset the first I²C access can be NACKed; retry (e.g. up to 10 times with a 2 ms pause) and then send `SAMConfiguration` before any RF command (the SAM mode has to be set after every reset).
- **`InListPassiveTarget` retry count:** the default `MxRtyPassiveActivation = 0xFF` retries forever, so a `read_uid` without a card would block (no response, `IRQ` stays high). The driver sets a finite count in `init` (`2`) and treats an empty list (`NbTg = 0`) as "no card". For `on_interrupt`-driven operation set `0xFF` and wait for `IRQ`.
- **Release targets:** `InListPassiveTarget` leaves the target active (and its logical number `Tg` valid until the next list command); the driver calls `InRelease` in `read_uid`. Re-listing a card that is still in the field returns it again only after it was released or left the field.
- **MIFARE Classic:** needs authentication per sector before read/write (`0x60`/`0x61`); the 4-byte UID argument is the last four bytes of NFCID1 (7-byte UIDs are not MIFARE Classic). Writing sector trailers with wrong keys/access bits makes a sector permanently unreadable; the Full driver does not guard against it.
- **Antenna:** the antenna matching circuit (breakout board) determines the read range; the driver does not tune RF registers beyond `RFConfiguration`.
- **I²C vs. other pins:** `I0/I1` must be wired for I²C (breakouts expose DIP switches); with the wrong setting the chip does not answer at `0x24`.
- **Address overlap:** `0x24` is shared with some other devices (e.g. PCF8574 expanders at `0x20`–`0x27`); the chip has no ID register, probe only with `active=True`.

## Sigrok Decoder

Decoder id `pn532`, input `['i2c']`. Matches I²C address `0x24`. Annotates write transactions as command frames (frame structure, LEN/LCS/DCS validation, TFI, command name, decoded request fields such as `InListPassiveTarget` parameters and MIFARE operation codes) and read transactions as status byte plus ACK, NACK, error or response frames (response command name, `Status` error text, parsed target list with UID). Warns on bad LCS/DCS checksums, a read without a preceding command, a response frame without an ACK, and on TFI values other than `0xD4`/`0xD5`/`0x7F`. No conformance annotation pair is emitted (no checked timing constraint).
