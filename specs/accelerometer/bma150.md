# Chip Spec: BMA150

**Manufacturer:** Bosch Sensortec  
**Datasheet:** `datasheets/accelerometer/bma150.pdf`  
**Category:** accelerometer  
**Transports:** I²C (the chip also supports 4-/3-wire SPI; out of scope for this issue — see Implementation Notes)

## Overview

The BMA150 is a triaxial, low-g MEMS accelerometer with 10-bit digital output and ±2/±4/±8 *g* selectable full-scale range. It also provides an 8-bit on-chip temperature reading (0.5 °C/LSB), selectable digital bandwidth from 25 Hz to 1500 Hz, and a data-ready/event interrupt output with built-in low-g (free-fall), high-g, any-motion and alert logic that works without host intervention. A self-wake-up mode lets the chip sleep at ~1 µA and wake periodically to evaluate interrupt criteria. It is the LGA-package sibling of the SMB380. Typical uses: tilt/orientation sensing, shock and free-fall detection, menu scrolling, pedometers.

## Transport Configuration

### I²C
- **Address:** `0x38` (fixed by metal option; no address-select pin)
- **Max clock:** 3.4 MHz (high-speed mode); use ≤ 400 kHz on typical hosts
- **Identity register:** `0x00` bits 2:0 = `0b010` (`chip_id`) — read with mask `0x07`, expected `0x02`
- **Probe safety:** `register_pointer` — the identity read is a plain register read with no side effects; reads outside `0x00–0x15` return `0xFF` when `ee_w=0`

I²C framing: write-address `0x70`, read-address `0x71`. A write is `[addr, reg, data]`; the control byte after the slave address is a dummy bit (MSB) plus the 7-bit register address, i.e. the plain register number as an ordinary byte. A read is a register-address write, a repeated start (stop+start is also accepted), then data bytes with automatic address increment. CSB must be tied to VDDIO in I²C mode; SDO is unused (tie to GND).

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| INT | high, push-pull | interrupt output — all enabled criteria are OR-ed; latched or self-resetting depending on `latch_INT` |
| CSB | — | tie to VDDIO for I²C |

## Register Map

Only the operational registers `0x00–0x15` are directly accessible (the EEPROM / default-setting region `0x16–0x3D` requires `ee_w=1` and is not used by the driver). Reset values for `0x0B–0x15` are loaded from EEPROM defaults.

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | CHIP_ID | R | `0x02` (bits 2:0) | Chip identification, bits 2:0 = `010` |
| `0x01` | VERSION | R | — | `al_version` bits 7:4, `ml_version` bits 3:0 |
| `0x02` | ACC_X_LSB | R | — | X bits 1:0 in 7:6; `new_data_x` in bit 0 |
| `0x03` | ACC_X_MSB | R | — | X bits 9:2 |
| `0x04` | ACC_Y_LSB | R | — | Y bits 1:0 in 7:6; `new_data_y` in bit 0 |
| `0x05` | ACC_Y_MSB | R | — | Y bits 9:2 |
| `0x06` | ACC_Z_LSB | R | — | Z bits 1:0 in 7:6; `new_data_z` in bit 0 |
| `0x07` | ACC_Z_MSB | R | — | Z bits 9:2 |
| `0x08` | TEMP | R | — | Temperature, 0.5 °C/LSB, `0x00` = −30 °C |
| `0x09` | STATUS | R | — | Self-test result and interrupt status |
| `0x0A` | CTRL | R/W | `0x00` | Sleep, soft reset, self-test, EEPROM enable, interrupt reset |

| `0x0C` | LG_THRES | R/W | `0x14` (20) | Low-g threshold |
| `0x0D` | LG_DUR | R/W | `0x96` (150) | Low-g duration, 1 ms/LSB |
| `0x0E` | HG_THRES | R/W | `0xA0` (160) | High-g threshold |
| `0x0F` | HG_DUR | R/W | `0x96` (150) | High-g duration, 1 ms/LSB |
| `0x10` | ANY_MOTION_THRES | R/W | `0x00` | Any-motion threshold |
| `0x11` | HYST_DUR | R/W | `0x00` | `any_motion_dur` 7:6, `HG_hyst` 5:3, `LG_hyst` 2:0 |

| `0x13` | CUSTOMER_2 | R/W | — | Free scratch byte (no effect on chip) |
| `0x14` | RANGE_BW | R/W | `xxx01110` | `range` bits 4:3, `bandwidth` bits 2:0; **bits 7:5 are factory calibration** |
| `0x15` | CONFIG | R/W | `0x80` | SPI4, adv. interrupt enable, new-data int, latch, shadow, wake-up |

### Bit Fields

#### `RANGE_BW` (`0x14`)

| Bits | Name | Description |
|------|------|-------------|
| 7:5 | — | **Calibration data — must be preserved.** Always read-modify-write |
| 4:3 | range | `00` = ±2 *g*, `01` = ±4 *g* (reset default), `10` = ±8 *g*, `11` = not authorised |
| 2:0 | bandwidth | `000` = 25 Hz, `001` = 50, `010` = 100, `011` = 190, `100` = 375, `101` = 750, `110` = 1500 (reset default), `111` = not authorised |

#### `CTRL` (`0x0A`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | — | Reserved, leave 0 |
| 6 | reset_INT | Write 1 to clear a latched interrupt (INT pin goes low) |
| 5 | update_image | Write 1 to copy EEPROM to image registers (self-clears; may overwrite SPI4) |
| 4 | ee_w | 1 = unlock EEPROM / registers `0x16–0x3D`; driver keeps 0 |
| 3 | self_test_1 | Emulates 0 *g* at the ADC input to verify the interrupt path |
| 2 | self_test_0 | Electrostatic self-test; result in `STATUS.st_result` |
| 1 | soft_reset | Write 1 for a power-on-equivalent reset |
| 0 | sleep | 1 = sleep mode (bus access forbidden except wake / soft reset) |

#### `STATUS` (`0x09`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | st_result | 1 = self-test passed |
| 4 | alert_phase | 1 = alert mode active and any-motion detected |
| 3 | LG_latched | Low-g interrupt occurred (cleared by `reset_INT`) |
| 2 | HG_latched | High-g interrupt occurred (cleared by `reset_INT`) |
| 1 | status_LG | Low-g criterion currently true |
| 0 | status_HG | High-g criterion currently true |

#### `INT_CTRL` (`0x0B`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | alert | any-motion criterion puts chip in alert mode (preloads LG/HG); exclusive with `any_motion`; needs `enable_adv_INT=1` |
| 6 | any_motion | any-motion criterion drives INT; needs `enable_adv_INT=1` |
| 5:4 | counter_HG | High-g debounce counter when criterion false: `00` reset, `01`/`10`/`11` count down 1/2/3 per ms |
| 3:2 | counter_LG | Low-g debounce counter, same encoding |
| 1 | enable_HG | Enable high-g interrupt |
| 0 | enable_LG | Enable low-g interrupt |

#### `HYST_DUR` (`0x11`)

| Bits | Name | Description |
|------|------|-------------|
| 7:6 | any_motion_dur | `00`=1, `01`=3, `10`=5, `11`=7 consecutive samples |
| 5:3 | HG_hyst | High-g hysteresis, 32 threshold-codes per LSB |
| 2:0 | LG_hyst | Low-g hysteresis, 32 threshold-codes per LSB |

#### `CONFIG` (`0x15`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | SPI4 | 1 = 4-wire SPI (default), 0 = 3-wire SPI; irrelevant for I²C, keep unchanged |
| 6 | enable_adv_INT | 1 = allow `any_motion` / `alert` bits to take effect |
| 5 | new_data_INT | 1 = INT pulses when all axes updated (exclusive with internal interrupt logic; latched; cleared by reading `0x02–0x07`) |
| 4 | latch_INT | 1 = interrupts latched until `reset_INT` |
| 3 | shadow_dis | 0 = MSB update blocked after LSB read (prevents LSB/MSB mixing); 1 = allow MSB-only reads |
| 2:1 | wake_up_pause | Sleep between wake-ups: `00` 20 ms, `01` 80 ms, `10` 320 ms, `11` 2560 ms (±30 %) |
| 0 | wake_up | 1 = chip cycles between sleep and normal mode, evaluating interrupt criteria |

## Initialization Sequence

1. Power up; wait ≥ 3 ms (start-up time).
2. Read `CHIP_ID` (`0x00`); verify `(value & 0x07) == 0x02`. A value of `0x00` or `0xFF` indicates wiring / address error (or a blank-EEPROM SPI mode problem on SPI).
3. Read `RANGE_BW` (`0x14`); set range = `00` (±2 *g*) and bandwidth = `010` (100 Hz) preserving bits 7:5; write back.
4. Wait ≥ 1/(2·bandwidth) (5 ms at 100 Hz) for filtered data to replace stale registers.

The chip comes up in normal mode, so there is no separate "measure" bit.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | active-high, push-pull |
| Level | 2 |
| Condition(s) | new data; low-g (free-fall); high-g; any-motion; alert (preloads low/high-g) |
| Clear mechanism | non-latched: automatic when criterion clears; latched: write `reset_INT`; new-data: read `0x02–0x07` |

### Interrupt sources

| Constant | Value | Condition |
|----------|-------|-----------|
| `SOURCE_LOW_G` | `0x01` | Free-fall: all three |a| ≤ LG_thres for LG_dur ms |
| `SOURCE_HIGH_G` | `0x02` | Any axis |a| ≥ HG_thres for HG_dur ms |
| `SOURCE_ANY_MOTION` | `0x04` | Moving difference ≥ any_motion_thres for `any_motion_dur` samples |
| `SOURCE_ALERT` | `0x08` | Any-motion arms alert mode (shortens LG/HG durations); mutually exclusive with any-motion |
| `SOURCE_NEW_DATA` | `0x10` | All axes updated; exclusive with the four sources above |

Mutual-exclusion rules (new data vs. the others; any-motion vs. alert) are enforced by the driver: enabling one source disables its exclusive partner(s). Any-motion and alert additionally set `enable_adv_INT=1`.

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback)` | Subscribe; callback receives status int (`STATUS` byte) |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Read `STATUS`; returns the status byte (`LG_latched`/`HG_latched` bits). Does not clear |
| `enable_interrupt` | `enable_interrupt(source)` | Enable one interrupt source |
| `disable_interrupt` | `disable_interrupt(source)` | Disable one interrupt source |

`clear_interrupt()` (Full) writes `reset_INT` and is the clear mechanism for latched interrupts.

### Status register bit layout

| Bit | Constant | Meaning |
|-----|----------|---------|
| 7 | `STATUS_ST_RESULT` | Self-test passed |
| 4 | `STATUS_ALERT_PHASE` | Alert phase active |
| 3 | `STATUS_LG_LATCHED` | Low-g latched |
| 2 | `STATUS_HG_LATCHED` | High-g latched |
| 1 | `STATUS_LG` | Low-g criterion true now |
| 0 | `STATUS_HG` | High-g criterion true now |

### Minimal

Goal: read X, Y, Z acceleration in *g* with sensible defaults; no configuration required beyond the connection.

| Operation | Parameters | Returns | Notes |

| `init` | connection | — | Verifies chip ID, sets ±2 *g* / 100 Hz (read-modify-write of `0x14`) |
| `read` | — | `(x, y, z)` floats | Acceleration in *g*; burst-reads `0x02–0x07` |

**Sensible defaults:** range ±2 *g*, bandwidth 100 Hz, all interrupts left at EEPROM defaults but INT unused, calibration bits 7:5 of `0x14` preserved, `shadow_dis=0`.

**Additional configuration options:**
- Range ±2/±4/±8 *g*; bandwidth 25–1500 Hz
- Low-g / high-g thresholds with duration, hysteresis and debounce counters

- Self-wake-up mode (20 ms – 2.56 s pause)
- Sleep, soft reset, self-test, temperature

## Data Conversion

Acceleration, per axis (10-bit two's complement, LSB register first):

```
raw = (MSB << 2) | (LSB >> 6)          # 0..1023
if raw >= 512: raw -= 1024             # sign-extend
acceleration_g = raw / sensitivity     # sensitivity = 256 (±2 g), 128 (±4 g), 64 (±8 g) LSB/g
```

Equivalent: 3.91 mg/LSB at ±2 *g*, 7.81 mg/LSB at ±4 *g*, 15.6 mg/LSB at ±8 *g*. Bit 0 of each LSB register is the `new_data` flag and must be masked out (the shift above does so). Acceleration in m/s² is not provided; examples print *g*.

Temperature:
```
temperature_C = raw * 0.5 - 30.0       # raw is unsigned 8-bit; range -30 .. 97.5 °C
```

Thresholds (`range_g` = 2, 4, 8):
```
LG_thres_code = round(threshold_g / range_g * 255)        # unsigned 8-bit
HG_thres_code = round(threshold_g / range_g * 255)
hyst_code     = round(hysteresis_g / range_g * 255 / 32)  # 0..7
any_motion_thres_code = round(threshold_g / (0.0156 * range_g / 2))  # 15.6 mg/LSB at ±2 g, scales with range
duration_ms   = LG_dur / HG_dur code (1 ms/LSB; interrupt fires at code + 1 ms)
```
Constraints: `LG_thres + 32·LG_hyst < 511`; `HG_thres − 32·HG_hyst > 0`. Thresholds are recomputed against the current range, so re-apply them after `set_range`.

## Examples

### Demo

Free-fall / shock logger. Configure ±8 *g*, 190 Hz bandwidth; arm the low-g interrupt (0.4 *g*, 40 ms duration, latched) and the high-g interrupt (4 *g*, 2 ms duration, latched). Poll `poll_interrupt()` every 50 ms and print a timestamped line whenever `STATUS_LG_LATCHED` or `STATUS_HG_LATCHED` is set ("FREE FALL detected" / "SHOCK detected") plus the latest x, y, z and temperature, then `clear_interrupt()`. ## Timing Constraints

- **Start-up:** 3 ms from power-off to first valid bus access (`t_su`, typ.).
- **Wake-up from sleep:** ≤ 1.5 ms (1 ms typ.) after clearing `CTRL.sleep` until stable data (>99 %). **Conformance-checked**: `wake_up` — sigrok annotation pair `wake_start` (write to `CTRL` `0x0A` with `sleep=0`) → `wake_done` (next acceleration-data read, `0x02`). See `specs/accelerometer/bma150_timing.conf`.
- **Soft reset:** no serial transaction within 10 µs after the write; data valid after ~1.3 ms; up to 30 ms if issued while asleep. The driver waits 30 ms.
- **Data refresh:** registers update at 3 kHz (≈ 330 µs for T/X/Y/Z), independent of bandwidth. After a range change, allow 1/(2·bandwidth) for filtered data.
- **New-data interrupt read-out:** read within 20 µs of INT high (window 0–80 µs) to avoid conversion crosstalk; with I²C the read-out can exceed 330 µs, so the interrupt may not clear in time — prefer polling `new_data_available` on I²C.
- **EEPROM:** not used by the driver (30 ms per write, ≥ 14 ms between writes, ≥ 10 ms after sleep exit).

## Implementation Notes

- **Calibration bits:** bits 7:5 of `RANGE_BW` (`0x14`) hold factory calibration. Writing the register without preserving them corrupts the reported acceleration. Always read-modify-write.
- **LSB first:** with `shadow_dis=0`, the MSB of an axis is frozen after its LSB is read; always read LSB then MSB (the 6-byte burst from `0x02` does this). Never read MSB-only unless `shadow_dis=1`.
- **Mask `new_data` bit:** bit 0 of each LSB register is a flag, not data.
- **Reserved codes:** range `11` and bandwidth `111` are not authorised; the driver must reject them.
- **Bit 7 of `CTRL`** must remain 0.
- **Sleep mode:** all bus access except wake / soft reset is forbidden while asleep; the Full class tracks sleep state and raises on other calls.
- **`0x16–0x3D` / EEPROM:** never touched; `ee_w` stays 0.
- **Exclusive interrupt modes:** `new_data_INT` cannot run in parallel with internal interrupt logic; `alert` and `any_motion` cannot both be on.
- **SPI mode:** the chip also supports SPI (mode 3, ≤10 MHz, read bit `0x80`, auto-increment, 4-/3-wire via `SPI4`). This spec and the issue cover I²C only; SPI can be added later as a small extension since the driver is register-based.
- **Datasheet erratum:** the datasheet text (§3.4.4) lists `status_HG` at bit 2; the memory map (Figure 1) and this spec place `status_LG` at bit 1 and `status_HG` at bit 0.
- **Sibling:** the SMB380 (QFN) is register-compatible; a future issue can reuse this driver.

If this chip is register-addressed (I²C, SMBus, or SPI), accept `RegisterConnection` (not
the bare `Connection`) and call `connection.read(reg, length)` / `connection.write(reg,
data)` directly — no chip-local `_read_reg`/`_write_reg` and no `bus_type` branch. See
`specs/feature_register_access_design.md`.

## Sigrok Decoder

Decoder id `bma150`, input `['i2c']`. Matches I²C address `0x38`. Annotates every register in the Register Map by name; decodes `CTRL`, `STATUS`, `INT_CTRL`, `HYST_DUR`, `RANGE_BW` and `CONFIG` bit fields into named flags; assembles the burst read of `0x02–0x07` into 10-bit signed values converted to *g* at the last-seen range, and `TEMP` into °C. `CHIP_ID` reads are checked against `0x02` (mask `0x07`). For the Wake-up Timing Constraint the decoder emits the `timing` annotation row markers `wake_start` (write to `0x0A` with `sleep=0`) and `wake_done` (next read starting at `0x02`), shaped per `specs/sigrok_annotations.md`'s Variable-Length Annotation Convention.
