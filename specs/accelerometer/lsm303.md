# Chip Spec: LSM303

**Manufacturer:** STMicroelectronics  
**Datasheet:** `datasheets/accelerometer/lsm303.pdf`  
**Category:** accelerometer  
**Transports:** I²C (the chip is I²C-only; the accelerometer's `SIM` bit in `CTRL_REG4_A` is a leftover SPI option that is not usable on this part)

## Overview

The LSM303 (the datasheet covers the **LSM303DLHC** e-compass module) is a system-in-package combining a three-axis MEMS accelerometer and a three-axis magnetometer behind **two independent I²C slave addresses** on one bus. The accelerometer (`0x19`) has four full-scale ranges (±2, ±4, ±8, ±16 *g*), 12-bit output at 1 mg/LSB (±2 *g*), output data rates from 1 Hz to 5.376 kHz, a 32-level FIFO, a selectable high-pass filter, two programmable inertial interrupt generators (threshold, free-fall, 6D/4D orientation) and single/double-click detection. The magnetometer (`0x1E`) has seven full-scale ranges (±1.3 to ±8.1 gauss = ±130 to ±810 µT), 12-bit output, output data rates from 0.75 Hz to 220 Hz, and a relative-only temperature sensor. Typical uses: tilt-compensated electronic compass, map rotation, orientation and shock detection, tap gestures, motion wake-up.

The driver treats the module as **one logical device with two connections** (accelerometer + magnetometer), the same pattern as `MPU9250`. The compass heading is computed in software from both sensors.

## Transport Configuration

### I²C
- **Address (accelerometer):** `0x19` (`0011001b`, fixed — no address pin); write byte `0x32`, read byte `0x33`
- **Address (magnetometer):** `0x1E` (`0011110b`, fixed); write byte `0x3C`, read byte `0x3D`
- **Max clock:** 400 kHz (fast mode); 100 kHz standard mode also supported
- **Identity register:** accelerometer — none (the datasheet documents no `WHO_AM_I`; registers `0x00–0x1F` are reserved). Magnetometer — `0x0A` = `0x48`, `0x0B` = `0x34`, `0x0C` = `0x33` (`IRA_REG_M`/`IRB_REG_M`/`IRC_REG_M`, ASCII "H43"), read as one 3-byte value `0x483433` with mask `0xFFFFFF`. **This is identical to the HMC5883L identity**, so the two chips cannot be told apart by ID at `0x1E` (see Implementation Notes and `registry/known_ambiguities.json`).
- **Probe safety:** `register_pointer` for both slaves — a 1-byte write only selects the sub-address / address pointer.

I²C framing differs between the two slaves:

- **Accelerometer** — after the slave address the master sends an 8-bit sub-address `SUB`: the 7 LSbs are the register address and the **MSb enables address auto-increment**. A single-register access uses `SUB = reg`; a multi-byte access uses `SUB = reg | 0x80` (e.g. `0xA8` to burst-read the six output registers). A read is `SUB` write, repeated START, slave address with R/W = 1.
- **Magnetometer** — an address pointer, **no auto-increment bit**; the pointer always auto-increments by one after each byte, with two special rules: after register `0x08` the pointer rolls back to `0x03`, and from `0x0C` or higher it wraps to `0x00`. A 6-byte read from `0x03` therefore returns all output registers in one transaction, and reading on past `0x08` keeps returning the output block. Reads of invalid addresses return 0; writes to invalid addresses or undefined bits are ignored.

**Reset-value caveat:** datasheet Table 17 prints the magnetometer reset values as 7-bit strings (`CRA` `0001000`, `CRB` `0010000`, `MR` `00000011`) that disagree with the field descriptions (Table 71: `DO` default `100`). The values above follow the field descriptions (`CRA` = `0x10` → 15 Hz, `CRB` = `0x20` → ±1.3 gauss is the lowest gain code `001`). The `MR_REG_M` reset value `0x03` is **sleep mode**. The driver never relies on reset values: `init` writes all three registers.

Note the magnetometer output order is **X, Z, Y**, not X, Y, Z, and the byte order is **high byte first** (opposite of the accelerometer).

| Reg | Bit 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |

| `INTx_CFG_A` | AOI | 6D | ZHIE | ZLIE | YHIE | YLIE | XHIE | XLIE |
| `INTx_SOURCE_A` | 0 | IA | ZH | ZL | YH | YL | XH | XL |

| `AOI` | `6D` | Interrupt mode |
|-------|------|----------------|
| 0 | 0 | OR combination of the enabled events |
| 0 | 1 | 6-direction movement recognition (fires when the orientation moves from an unknown to a known zone; lasts one ODR period) |

| 1 | 1 | 6-direction position recognition (stays active while the orientation is inside a known zone) |

Reading `INTx_SOURCE_A` clears `IA` and the INT pin and, if latched, allows the register to refresh. `INTx_THS_A` / `INTx_DURATION_A` bit 7 must stay 0.

## Initialization Sequence

1. Power up (Vdd and Vdd_IO); wait for the boot download of the trim values (the datasheet gives no figure for the DLHC; allow ≥ 5 ms as for sibling parts).
2. Magnetometer: read `IRA/IRB/IRC` (`0x0A`, 3 bytes) and verify `0x48 0x34 0x33`.
3. Accelerometer: put the control registers in a known state — there is no soft reset: write `CTRL_REG2_A`, `CTRL_REG3_A`, `CTRL_REG5_A`, `CTRL_REG6_A` and `FIFO_CTRL_REG_A` ← `0x00`.
4. Accelerometer: write `CTRL_REG4_A` ← `0x88` (`BDU` = 1, `FS` = `00` ±2 *g*, `HR` = 1).
5. Accelerometer: write `CTRL_REG1_A` ← `0x57` (`ODR` = `0101` 100 Hz, `LPen` = 0, X/Y/Z enabled) — leaves power-down and starts conversions.
6. Magnetometer: write `CRA_REG_M` ← `0x10` (15 Hz, temperature off), `CRB_REG_M` ← `0x20` (±1.3 gauss), `MR_REG_M` ← `0x00` (continuous conversion — the part resets into sleep).
7. Wait ≥ 7/ODR (70 ms at 100 Hz) for the accelerometer turn-on and ≥ 1/15 Hz ≈ 67 ms for the first magnetometer sample; the first sample of both sensors is then valid.

## Interrupt

| Property | Value |
|----------|-------|
| INT pins | accelerometer `INT1` and `INT2` (polarity set by `H_LACTIVE`), plus magnetometer `DRDY` |
| Level | 3 (multiple INT lines) |
| Condition(s) | accelerometer: new data; FIFO watermark / overrun; inertial generator 1 / 2 (threshold, free-fall, 6D/4D orientation); single / double click; boot. Magnetometer: new data (`DRDY` pin) |
| Clear mechanism | generators: read `INTx_SOURCE_A`; click: read `CLICK_SRC_A`; data-ready: read the output registers; FIFO flags: read the FIFO; magnetometer `DRDY`: read the output registers |

### Interrupt sources

| Constant | Value | Condition | Pin(s) |
|----------|-------|-----------|--------|
| `SOURCE_DATA_READY` | `0x0001` | New accelerometer XYZ sample (`ZYXDA`) | INT1 |
| `SOURCE_WATERMARK` | `0x0002` | FIFO content exceeds watermark (`WTM`) | INT1 |
| `SOURCE_OVERRUN` | `0x0004` | FIFO overrun (`OVRN_FIFO`) | INT1 |
| `SOURCE_IA1` | `0x0008` | Inertial generator 1 event (`INT1_SOURCE_A.IA`) | INT1 or INT2 |
| `SOURCE_IA2` | `0x0010` | Inertial generator 2 event (`INT2_SOURCE_A.IA`) | INT1 or INT2 |
| `SOURCE_CLICK` | `0x0020` | Single / double click (`CLICK_SRC_A.IA`) | INT1 or INT2 |
| `SOURCE_BOOT` | `0x0040` | Boot procedure running | INT2 |
| `SOURCE_MAG_DATA_READY` | `0x0080` | New magnetometer sample (`SR_REG_M.DRDY`) | `DRDY` pin (not routable) |

`SOURCE_BOOT` is pin-only (no register flag), so `poll_interrupt()` never reports it. `SOURCE_MAG_DATA_READY` is reported by `poll_interrupt()` but is always on the dedicated `DRDY` pin; `enable_interrupt` / `disable_interrupt` reject it (nothing to route).

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, pin=1)` | Subscribe on INT`pin` (1 or 2); callback receives the status int |
| `off_interrupt` | `off_interrupt(pin=1)` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Read the source registers of every currently enabled source and return the combined status int; **reading `INTx_SOURCE_A` / `CLICK_SRC_A` clears their latched flags** |
| `enable_interrupt` | `enable_interrupt(source, pin=1)` | Route one source to INT`pin`; `pin` is ignored for INT1-only / INT2-only sources |
| `disable_interrupt` | `disable_interrupt(source, pin=1)` | Remove one source from INT`pin` |

`enable_interrupt` only routes the source; the generator or function behind it is configured with the `set_*` methods in the Full class.

## Implementation Stages

### Minimal

Goal: read acceleration and magnetic field with sensible defaults; no configuration required beyond the two connections.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `accel_connection`, `mag_connection` | — | Runs the Initialization Sequence (±2 *g*, 100 Hz, high-resolution, ±130 µT, 15 Hz, continuous) |
| `read_acceleration` | — | `(x, y, z)` floats | Acceleration in *g*; burst-reads `0x28–0x2D` with `SUB` = `0xA8` |
| `read_magnetic` | — | `(x, y, z)` floats | Magnetic flux density in µT; burst-reads `0x03–0x08` and reorders from X, Z, Y |

**Sensible defaults:** accelerometer ±2 *g* (1 mg/LSB), 100 Hz ODR, high-resolution mode, all three axes enabled, `BDU` = 1, high-pass filter bypassed, FIFO bypassed, all interrupt routing cleared; magnetometer ±1.3 gauss (±130 µT), 15 Hz ODR, continuous conversion, temperature sensor off.

## Data Conversion

Acceleration, per axis (16-bit two's complement, left-justified; LSB register first because `BLE` = 0):

```
raw16 = int16(OUT_x_L | OUT_x_H << 8)        # sign-extend the 16-bit pair
counts = raw16 >> shift                      # arithmetic shift: 4 (12-bit high-resolution), 6 (10-bit normal), 8 (8-bit low-power)
acceleration_g = counts * sensitivity_mg / 1000
```

| Mode (resolution) | ±2 *g* | ±4 *g* | ±8 *g* | ±16 *g* |
|-------------------|--------|--------|--------|---------|
| High-resolution (12-bit), mg/LSB | 1 | 2 | 4 | 12 |
| Normal (10-bit), mg/LSB | 4 | 8 | 16 | 48 |
| Low-power (8-bit), mg/LSB | 16 | 32 | 64 | 192 |

Only the high-resolution row is printed in the committed datasheet (Table 3: 1 / 2 / 4 / 12 mg/LSB). The normal and low-power rows are derived (×4, ×16 for 2 / 4 fewer bits) and follow the sibling LIS3DH; verify on hardware. The ±16 *g* value is 12 mg/LSB, **not** 8 mg/LSB.

Magnetic field, per axis (16-bit two's complement, **high byte first**, 12-bit range −2048…2047, right-justified, i.e. already sign-extended):

```
raw = int16(OUT_x_H << 8 | OUT_x_L)         # reading order on the wire: X, Z, Y
flux_density_uT = raw / gain_LSB_per_gauss * 100     # 1 gauss = 100 µT
```

| `GN<2:0>` | Full scale (gauss) | Full scale (µT) | X, Y gain (LSB/gauss) | Z gain (LSB/gauss) |
|-----------|--------------------|-----------------|-----------------------|--------------------|
| `001` | ±1.3 | ±130 | 1100 | 980 |
| `010` | ±1.9 | ±190 | 855 | 760 |
| `011` | ±2.5 | ±250 | 670 | 600 |
| `100` | ±4.0 | ±400 | 450 | 400 |
| `101` | ±4.7 | ±470 | 400 | 355 |
| `110` | ±5.6 | ±560 | 330 | 295 |
| `111` | ±8.1 | ±810 | 230 | 205 |

Note that Z uses a **different** gain from X and Y at every setting.

Temperature (magnetometer, `TEMP_EN` = 1; 12-bit two's complement, left-justified in `TEMP_OUT_H_M:TEMP_OUT_L_M`, 8 LSB/°C):

```
raw = int16(TEMP_OUT_H << 8 | TEMP_OUT_L) >> 4
temperature_delta_C = raw / 8                # relative to an unspecified reference
```

Heading (software, in the sensor frame; the datasheet documents neither the axis alignment between the two dies nor a declination):

```
# flat compass
heading_deg = atan2(my, mx) * 180 / pi, wrapped to 0..360

# tilt-compensated (ax, ay, az from the accelerometer, normalised, same sensor-axis convention)
roll  = atan2(ay, az)
pitch = atan2(-ax, ay * sin(roll) + az * cos(roll))
xh = mx * cos(pitch) + mz * sin(pitch)
yh = mx * sin(roll) * sin(pitch) + my * cos(roll) - mz * sin(roll) * cos(pitch)
heading_deg = atan2(yh, xh) * 180 / pi, wrapped to 0..360
```

Thresholds and times (`FS_g` = current full-scale in *g*, `ODR` = current accelerometer output data rate in Hz):

```
INTx_THS_A code  = round(threshold_g * 128 / FS_g)     # 7-bit, clamp 0..127; 1 LSb = full-scale / 128 (stated for CLICK_THS_A, assumed for INTx_THS_A)
INTx_DURATION_A  = round(duration_ms * ODR / 1000)     # 7-bit, 1 LSb = 1/ODR
CLICK_THS_A code = round(threshold_g * 128 / FS_g)     # 7-bit, 1 LSb = full-scale / 128
TIME_LIMIT_A / TIME_LATENCY_A / TIME_WINDOW_A = round(time_ms * ODR / 1000)   # 1 LSb = 1/ODR
```

## Timing Constraints

- **Boot:** the datasheet does not state a boot time for the DLHC; wait ≥ 5 ms after power-up and after a `BOOT` reboot (as for sibling parts). `INTx_CFG_A` writes are only possible after boot completes.
- **Accelerometer turn-on:** low-power mode 1 ms, normal / high-resolution 7/ODR (datasheet Table 8) — 70 ms at the default 100 Hz.
- **First accelerometer data after leaving power-down:** ready after the turn-on time. **Conformance-checked**: `first_data_ready` — sigrok annotation pair `odr_start` (write to `CTRL_REG1_A` `0x20` with `ODR` ≠ `0000`) → `odr_ready` (first read of `STATUS_REG_A` `0x27` returning `ZYXDA` = 1). See `specs/accelerometer/lsm303_timing.conf`.
- **Magnetometer first data:** the datasheet gives no turn-on or single-conversion time. The driver waits one output period (1/`DO` rate, 67 ms at 15 Hz) after leaving sleep or starting a single conversion, and otherwise polls `SR_REG_M.DRDY`. Not conformance-checked.
- **Mode / range / ODR changes:** discard the next few samples (≥ 1/ODR) after changing `FS`, `ODR`, mode or high-pass settings, and re-read `REFERENCE_A` in `HPM` = `00` before trusting threshold events.
- **Update rate:** at 1.344 kHz and above, a 6-byte accelerometer burst (~0.2–0.25 ms at 400 kHz) is a large share of the 0.74 ms sample period — use the FIFO or poll `ZYXDA`.
- **FIFO burst:** reading `OUT_X_L_A`…`OUT_Z_H_A` pops one sample set per 6-byte read; a full drain is 32 reads.

## Implementation Notes

- **Two slaves, two connections:** the accelerometer and magnetometer are separate I²C slaves with different framing. Both classes take `accel_connection` (`0x19`) and `mag_connection` (`0x1E`) as `RegisterConnection` (1-byte register addresses); the driver calls `connection.read(reg, length)` / `connection.write(reg, data)` directly, with no chip-local `_read_reg`/`_write_reg` and no `bus_type` branch (see `specs/feature_register_access_design.md`). Both connections must be on the same bus.
- **Accelerometer auto-increment:** every multi-byte accelerometer transfer sets bit 7 of the sub-address (`reg | 0x80`); single-register accesses do not. The driver does this itself — `RegisterConnection` has no I²C multi-byte parameter (same pattern as `LIS3DH` / `L3GD20H`). The magnetometer needs **no** such bit.
- **Magnetometer is in sleep after reset:** `MR_REG_M` resets to `0x03` (sleep). `init` must write `MR_REG_M` ← `0x00`; without it the output registers never update.
- **Magnetometer register order and endianness:** outputs are X, **Z**, Y, high byte first. Combine as `int16(high << 8 | low)` (in the JVM drivers mask both bytes with `0xFF`, narrow with `.toShort()` / `(short)`) and reorder to X, Y, Z. Reading past `0x08` wraps the pointer to `0x03`, so a 6-byte read from `0x03` is safe.
- **Output lock:** `SR_REG_M.LOCK` is set while a read of the output block is in progress; read all six bytes in one burst so the three axes belong to the same sample.
- **BDU:** `init` sets `BDU` = 1 for the accelerometer so the six output bytes of a burst belong to one sample. Always read LSB before MSB (a 6-byte burst does).
- **No soft reset:** neither slave has a reset command. `init` writes the control registers back to known values; the only "reset" is `BOOT` (`CTRL_REG5_A` bit 7), which reloads the factory trim and is not needed in normal use. Reserved registers are never written.
- **Mode select is under-specified in this datasheet revision:** the committed datasheet (Doc ID 018771 Rev 1, "Preliminary data", 21-Apr-2011) defines only `LPen` / `HR` (Table 8: low-power `LPen`=1 `HR`=0 1 ms turn-on; normal `LPen`=0 `HR`=1 7/ODR) and the high-resolution sensitivities. The 8 / 10 / 12-bit resolution split and the mode-dependent sensitivities in Data Conversion are taken from later ST documentation and the LIS3DH sibling; the three-way `set_mode` mapping (`LPen`/`HR` = `10` / `00` / `01`) is likewise derived. `LPen` = 1 with `HR` = 1 is rejected. Verify on hardware.
- **ODR codes:** `1000` (1.620 kHz) exists in low-power mode only; `1001` means 1.344 kHz in normal / high-resolution and 5.376 kHz in low-power. The driver validates and raises on an illegal combination.
- **Left-justified accelerometer data:** sign-extend the 16-bit pair first, then arithmetic-shift right — do not mask-and-shift a 12-bit field.
- **Temperature is relative:** the sensor is in the magnetometer block (`TEMP_EN` in `CRA_REG_M`, 8 LSB/°C, 12-bit) and the datasheet gives no zero-degree reference or absolute calibration; expose a relative delta only, never absolute °C. It updates at the magnetometer data rate. The driver sets `TEMP_EN` by read-modify-write on first use.
- **Magnetometer register defaults are inconsistent in the datasheet:** see the reset-value caveat under Register Map; `init` writes explicitly.
- **Set/reset (S/R):** Vdd_IO and the SETC / SETP capacitors (datasheet §4.1) must be fitted; the datasheet mentions an S/R pulse to restore sensitivity after a disturbing field > 20 gauss but documents no register to trigger it. No S/R method is exposed.
- **Axis alignment unspecified:** the datasheet does not state the axis orientation relation between accelerometer and magnetometer, so `heading()` assumes both report in the same body frame. Verify on hardware before relying on tilt compensation.
- **Interrupt units:** `INTx_THS_A` has no units stated in this revision; the driver assumes the same 1 LSb = full-scale / 128 stated for `CLICK_THS_A`. Click `TIME_*` are 1/ODR as stated. High-pass cutoff has no tabulated Hz values; Full exposes the raw 0–3 code.
- **Interrupt generator writes:** `INT1_CFG_A` / `INT2_CFG_A` may be written only after boot completes.
- **6D / 4D:** `AOI`/`6D` = `01` is *movement* recognition (a pulse of one ODR period), `11` is *position* recognition (level). 4D disables the Z-axis zone and is enabled with `D4D_INTx` plus `6D`.
- **FIFO:** only bypass mode empties the buffer; to restart FIFO mode after a drain go through bypass (`set_fifo(0)` then `set_fifo(1)`). In stream mode the oldest samples are overwritten once full.
- **Identity collisions:** at `0x1E` the magnetometer identity `0x483433` is the same as HMC5883L, so discovery cannot distinguish them — both are listed as candidates (see `registry/known_ambiguities.json`); the user must pick the right driver. At `0x19` the accelerometer has no ID register and shares the address with LIS3DH (SA0 = VDD_IO); reading `0x0F` (reserved on the DLHC) is undocumented.
- **No SPI:** `SIM` in `CTRL_REG4_A` exists but the module's pinout (SCL/SDA only) is I²C-only; SPI is out of scope.
- **Siblings:** the LSM303DLH, LSM303DLM, LSM303D and LSM303AGR have different register maps and I²C addresses; no compatibility is assumed or claimed — each needs its own spec if added. The issue's datasheet URL (`DM00027543`) is the current LSM303DLHC document; the committed PDF is the earlier Doc ID 018771 Rev 1 copy (st.com was unreachable at spec time; later revisions add detail — see the notes above).

## Sigrok Decoder

Decoder id `lsm303`, input `['i2c']`. Matches I²C addresses `0x19` (accelerometer) and `0x1E` (magnetometer). For `0x19` annotates every register in the Accelerometer register map by name (the auto-increment bit in the sub-address is stripped and shown separately); decodes `CTRL_REG1_A`–`CTRL_REG6_A`, `STATUS_REG_A`, `FIFO_CTRL_REG_A`, `FIFO_SRC_REG_A`, `INTx_CFG_A`, `INTx_SOURCE_A`, `CLICK_CFG_A`, `CLICK_SRC_A` and `CLICK_THS_A` into named flags; decodes `ODR`, `FS`, `LPen` / `HR` (as the operating mode), `HPM` and `FM` into human-readable values; assembles the burst read of `0x28–0x2D` into signed values converted to *g* at the last-seen range and mode. For `0x1E` annotates every magnetometer register by name, decodes `CRA_REG_M`, `CRB_REG_M` (as full scale in µT), `MR_REG_M` (as mode) and `SR_REG_M`, assembles the 6-byte read of `0x03–0x08` (X, Z, Y) into µT at the last-seen gain, `TEMP_OUT` into relative °C, and checks `IRA/IRB/IRC` reads against `0x48 0x34 0x33`. For the First-data-ready Timing Constraint the decoder emits the `timing` annotation row markers `odr_start` (write to `CTRL_REG1_A` `0x20` with `ODR` ≠ `0000`) and `odr_ready` (first read of `STATUS_REG_A` `0x27` returning `ZYXDA` = 1), shaped per `specs/sigrok_annotations.md`'s Variable-Length Annotation Convention.
