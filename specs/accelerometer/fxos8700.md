# Chip Spec: FXOS8700CQ

**Manufacturer:** NXP Semiconductors  
**Datasheet:** `datasheets/accelerometer/fxos8700.pdf`  
**Category:** accelerometer  
**Transports:** I²C (the chip also has a point-to-point SPI mode; not covered here — the issue requests I²C only)

## Overview

The FXOS8700CQ is a 6-axis e-compass sensor: a 14-bit three-axis MEMS accelerometer (±2 / ±4 / ±8 *g*, 0.244 / 0.488 / 0.976 mg/LSB) and a 16-bit three-axis magnetometer (fixed ±1200 µT range, 0.1 µT/LSB) behind **one I²C address** and **one shared ADC**. In **hybrid mode** both sensors are sampled in an interleaved fashion at half the programmed output data rate (ODR) and the 12 data bytes can be read in a single burst (`hyb_autoinc_mode`). ODRs span 1.5625 Hz – 800 Hz (400 Hz in hybrid mode). The accelerometer side offers a 32-sample FIFO, a high-pass-filtered output, four oversampling modes, per-axis offset registers, and embedded freefall/motion, transient, tap ("pulse"), orientation and vector-magnitude detectors plus Auto-SLEEP/WAKE; the magnetometer side offers eight oversampling ratios, hard-iron offset registers, an autonomous min/max tracker with hardware auto-calibration, threshold and vector-magnitude detectors, and a (relative, uncalibrated) die-temperature sensor. Two interrupt pins (INT1, INT2) can be routed from every source. Typical uses: tilt-compensated electronic compass, orientation and tap/shake gestures, motion wake-up, UAV/robot heading.

**Category note:** issue #383 selected `imu`, but `imu` is defined as accelerometer + **gyroscope**. The chip has no gyroscope; following the precedent of `lsm303` (accelerometer + magnetometer, category `accelerometer`) this spec and the driver live under `accelerometer`.

The FXOS8700CQ is register-compatible with the NXP MMA845x accelerometer family (see `specs/accelerometer/mma8451q.md`) for registers `0x00–0x31`; the differences are the added magnetometer / hybrid registers (`0x32–0x78`), `WHO_AM_I` (`0xC7`), the I²C addresses, the vector-magnitude additions to `CTRL_REG3/4/5` and `INT_SOURCE`, and a few reset values.

## Transport Configuration

### I²C
- **Address:** selected by `SA1`/`SA0`: `0x1E` (SA1=0, SA0=0), `0x1D` (SA1=0, SA0=1), `0x1C` (SA1=1, SA0=0), `0x1F` (SA1=1, SA0=1)
- **Max clock:** 400 kHz (Fast mode); the chip does not stretch the clock
- **Identity register:** `0x0D` = `0xC7` (`WHO_AM_I`; `0xC4` on pre-production parts) — read with mask `0xFF`, expected `0xC7`; the driver also accepts `0xC4`
- **Probe safety:** `register_pointer` — the identity read has no side effects

I²C framing is the plain register-pointer protocol: write the register address, **repeated START**, read. There is no auto-increment bit; multi-byte reads/writes auto-increment within one transaction (the pointer is cleared at STOP). Reserved registers (everything not in the Register Map, incl. `0x07–0x08`, `0x19–0x1C`, `0x79+`) must not be written.

The interface mode is latched from the state of `SA0` at power-up/reset (floating `SA0` selects SPI, GND or VDDIO select I²C). **Do not leave `SA0` floating.** VDDIO should be applied before or together with VDD; otherwise pulse `RST` (active high) or power-cycle VDD.

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| INT1 | low (default), push-pull | interrupt output; polarity `IPOL` and drive `PP_OD` in `CTRL_REG3`; also pulses low→high (≈500 ns) when a reset completes |
| INT2 | low (default), push-pull | interrupt output; same settings (shared with INT1) |
| SA0 / SA1 | — | I²C address bits (see above); `SA0/MISO` must not float |
| RST | high | hardware reset; connect to GND if unused |
| BYP | — | regulator bypass capacitor |
| Crst | — | magnetic reset capacitor |
| VDD / VDDIO | — | VDD 1.95–3.6 V; VDDIO 1.62–3.6 V (no sequencing required if VDDIO ≥ VDD at power-up) |

Both interrupt pins share the polarity / drive configuration. Open-drain (`PP_OD` = 1) needs an external pull-up.

### Bit Fields

The following registers have identical bit layouts to the MMA8451Q (`specs/accelerometer/mma8451q.md`, Bit Fields): `STATUS`/`F_STATUS`, `F_SETUP`, `TRIG_CFG`, `SYSMOD`, `XYZ_DATA_CFG`, `HP_FILTER_CUTOFF`, `PL_*`, `A_FFMT_CFG/SRC/THS` (named `FF_MT_*` there), `TRANSIENT_*`, `PULSE_*`, `CTRL_REG1`, `CTRL_REG2`. The detector tables there apply unchanged (the datasheet tables are 70–78 for orientation, 79–93 for FFMT, 114–121 transient, 123–144 pulse). Reset values differ for `PL_BF_ZCOMP` (`0x84`: `bkfr` = `10`, `zlock` = `100`) and `PL_THS_REG` (`0x44`: `pl_ths` = 8, `hys` = `100`). `STATUS` bit names: `zyxow, zow, yow, xow, zyxdr, zdr, ydr, xdr`.

#### `CTRL_REG3` (`0x2C`)

| Bit 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|-------|---|---|---|---|---|---|---|
| FIFO_GATE | WAKE_TRANS | WAKE_LNDPRT | WAKE_PULSE | WAKE_FFMT | WAKE_A_VECM | IPOL | PP_OD |

`IPOL` 0 = active-low (default), 1 = active-high. `PP_OD` 0 = push-pull (default), 1 = open-drain. (The wake enables for the magnetic threshold / vector-magnitude detectors live in `M_THS_CFG` / `M_VECM_CFG`.)

#### `INT_SOURCE` (`0x0C`), `CTRL_REG4` (`0x2D`), `CTRL_REG5` (`0x2E`)

| Bit 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|-------|---|---|---|---|---|---|---|
| ASLP | FIFO | TRANS | LNDPRT | PULSE | FFMT | A_VECM | DRDY |

`INT_SOURCE` bits are `src_*` (read-only); `CTRL_REG4` bits are `int_en_*` (1 = source enabled); `CTRL_REG5` bits are `int_cfg_*` (1 = routed to INT1, 0 = INT2). Cleared by reading: `SYSMOD` (ASLP), `F_STATUS` (FIFO), `TRANSIENT_SRC`, `PL_STATUS`, `PULSE_SRC`, `A_FFMT_SRC`, `INT_SOURCE` itself (A_VECM), and the output data (DRDY: the accelerometer data in accel-only mode, the **magnetic** data in mag-only or hybrid mode). In hybrid mode `src_drdy` signals new accelerometer **and/or** magnetic data.

#### `CTRL_REG1` details (differences from MMA8451Q)

`dr<2:0>` is the **system ODR**: accel-only/mag-only `000` 800 Hz, `001` 400, `010` 200, `011` 100, `100` 50, `101` 12.5, `110` 6.25, `111` 1.5625 Hz; **in hybrid mode each sensor runs at half** (400 / 200 / 100 / 50 / 25 / 6.25 / 3.125 / 0.78125 Hz). `aslp_rate` sleep rates 50 / 12.5 / 6.25 / 1.56 Hz (halved in hybrid mode). All fields other than `active` need STANDBY.

#### `CTRL_REG2` details

`rst` (bit 6) software reset: all registers reset, the chip goes to STANDBY and **does not ACK the write** — the driver must tolerate a NACK. Allow ≥ 1 ms before the next transaction. `smods`/`mods`: `00` normal, `01` low-noise low-power, `10` high resolution, `11` low power.

#### `M_CTRL_REG1` (`0x5B`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | m_acal | 1 = hardware hard-iron auto-calibration: `M_OFF_X/Y/Z` ← (MAX + MIN)/2 at the end of every ODR cycle (needs `m_raw` = 0 and min/max tracking enabled) |
| 6 | m_rst | 1 = one-shot magnetic reset (degauss); hardware-cleared |
| 5 | m_ost | 1 = one-shot magnetic measurement (STANDBY only); hardware-cleared when done |
| 4:2 | m_os<2:0> | Magnetometer oversampling ratio 0–7 (see Data Conversion) |
| 1:0 | m_hms<1:0> | `00` accelerometer only, `01` magnetometer only, `11` hybrid (`10` reserved) |

Switching from mag-only/hybrid active mode to STANDBY can take 0–300 ms: after clearing `active`, poll `SYSMOD` until it reads `00`.

#### `M_CTRL_REG2` (`0x5C`)

| Bits | Name | Description |
|------|------|-------------|
| 5 | hyb_autoinc_mode | 1 = the burst-read pointer jumps from `0x06` (or `0x05` when `f_read` = 1) to `0x33`, so `0x01…0x0C` returns accel then mag in 12 bytes |
| 4 | m_maxmin_dis | 1 = disable min/max tracking |
| 3 | m_maxmin_dis_ths | 1 = freeze min/max on a magnetic threshold event |
| 2 | m_maxmin_rst | 1 = reset `MIN`/`MAX` registers to `0x7FFF`/`0x8000`; self-clears |
| 1:0 | m_rst_cnt<1:0> | Automatic magnetic reset: `00` every ODR cycle (default), `01` every 16, `10` every 512, `11` disabled (only on STANDBY→ACTIVE or `m_rst`) |

#### `M_CTRL_REG3` (`0x5D`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | m_raw | 1 = `M_OFF_*` are **not** applied to the output (raw readings); 0 = offsets applied (required for auto-calibration to take effect) |
| 6:4 | m_aslp_os<2:0> | Magnetometer OSR while in Auto-SLEEP |
| 3 | m_ths_xyz_update | Threshold-detector reference update mode |

#### `M_DR_STATUS` (`0x32`)

| Bit 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|-------|---|---|---|---|---|---|---|
| ZYXOW | ZOW | YOW | XOW | ZYXDR | ZDR | YDR | XDR |

Overwrite flags clear when the corresponding MSB register is read; `xDR` bits clear on reading the axis' MSB register (`M_OUT_X_MSB` etc.).

## Initialization Sequence

1. Power up; VDDIO on before or with VDD. Wait ≥ 1 ms (boot time ≤ 1000 µs) before the first I²C access.
2. Read `WHO_AM_I` (`0x0D`); verify `0xC7` (or `0xC4`).
3. Software reset: write `CTRL_REG2` ← `0x40` (`rst`). The chip resets its I²C interface and does not ACK — ignore a NACK. Wait ≥ 1 ms, then re-read `WHO_AM_I` (retry on NACK up to 10 ms).
4. Write `CTRL_REG1` ← `0x00` (STANDBY; explicit, as in the datasheet example).
5. Write `M_CTRL_REG1` ← `0x1F` (`m_acal` = 0, `m_os` = 7, `m_hms` = `11` hybrid).
6. Write `M_CTRL_REG2` ← `0x20` (`hyb_autoinc_mode` = 1).
7. Write `XYZ_DATA_CFG` ← `0x00` (±2 *g*, no high-pass output).
8. Write `CTRL_REG2` ← `0x00` (normal accelerometer oversampling, Auto-SLEEP off).
9. Write `CTRL_REG1` ← `0x11` (`dr` = `010` → system ODR 200 Hz = **100 Hz per sensor in hybrid mode**, `lnoise` = 0, `f_read` = 0, `active` = 1).
10. Wait ≥ 2/ODR + 1 ms for the STANDBY → ACTIVE turn-on (≈ 11 ms at 200 Hz system ODR; 2/ODR + 2 ms from power-down); the first hybrid sample set is valid after that plus one hybrid period (10 ms).

## Interrupt

| Property | Value |
|----------|-------|
| INT pins | `INT1` and `INT2`; polarity `IPOL` (default active-low) and drive `PP_OD` (default push-pull), shared by both pins |
| Level | 3 (multiple INT lines; every source individually routable) |
| Condition(s) | new data (accel and/or mag); FIFO watermark / overflow; freefall / motion; transient; tap (single / double); orientation change; accel vector-magnitude change; Auto-SLEEP / WAKE transition |
| Clear mechanism | per source: read the corresponding source register (see `INT_SOURCE`); data-ready: read the output data |

The magnetometer-only interrupt sources (threshold, vector-magnitude; `M_INT_SRC`) are not exposed by the driver API (see Register Map).

### Interrupt sources

The source constants equal the `INT_SOURCE` / `CTRL_REG4` / `CTRL_REG5` bit positions:

| Constant | Value | Condition | Cleared by reading |
|----------|-------|-----------|--------------------|
| `SOURCE_DATA_READY` | `0x01` | New sample (`DRDY`); accel in accel-only mode, mag in mag-only/hybrid mode | the output data |
| `SOURCE_ACCEL_VECM` | `0x02` | Accelerometer vector-magnitude change | `INT_SOURCE` |
| `SOURCE_FF_MT` | `0x04` | Freefall / motion (`A_FFMT_SRC.ea`) | `A_FFMT_SRC` |
| `SOURCE_PULSE` | `0x08` | Single / double tap (`PULSE_SRC.ea`) | `PULSE_SRC` |
| `SOURCE_ORIENTATION` | `0x10` | Orientation change (`PL_STATUS.newlp`) | `PL_STATUS` |
| `SOURCE_TRANSIENT` | `0x20` | Transient (`TRANSIENT_SRC.ea`) | `TRANSIENT_SRC` |
| `SOURCE_FIFO` | `0x40` | FIFO overflow or watermark | `F_STATUS` (`0x00`) |
| `SOURCE_AUTO_SLEEP` | `0x80` | WAKE ↔ SLEEP transition | `SYSMOD` |

`SOURCE_ACCEL_VECM` is only routable/pollable; configuring the detector itself is via the raw register accessors.

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, pin=1)` | Subscribe on INT`pin` (1 or 2); callback receives the status int |
| `off_interrupt` | `off_interrupt(pin=1)` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Read `INT_SOURCE` and return it; for every set bit except `SOURCE_DATA_READY` and `SOURCE_ACCEL_VECM` the driver also reads the matching source register so the flag (and the pin) clears. `SOURCE_DATA_READY` is left set — clear it by reading the data |
| `enable_interrupt` | `enable_interrupt(source, pin=1)` | Set `int_en_*` in `CTRL_REG4` and route to INT`pin` in `CTRL_REG5` (STANDBY handling is internal) |
| `disable_interrupt` | `disable_interrupt(source)` | Clear `int_en_*` |

`enable_interrupt` only routes the source; the detector behind it is configured with the `set_*` methods in the Full class.

### Status register bit layout (`poll_interrupt()` return value)

Same as `INT_SOURCE` (bit 7 `SOURCE_AUTO_SLEEP` … bit 1 `SOURCE_ACCEL_VECM`, bit 0 `SOURCE_DATA_READY`).

## Implementation Stages

### Minimal

Goal: read acceleration and magnetic field with sensible defaults (e-compass, hybrid mode); no configuration required beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Runs the Initialization Sequence (hybrid, ±2 *g*, 100 Hz per sensor, mag OSR 7) |
| `read_accel` | — | `(x, y, z)` floats | Acceleration in *g*; one burst read of `0x01–0x06` |
| `read_mag` | — | `(x, y, z)` floats | Magnetic flux density in µT; reads `0x33–0x38` starting with `M_OUT_X_MSB` |

**Sensible defaults:** hybrid mode (`m_hms` = `11`), system ODR 200 Hz (100 Hz per sensor), ±2 *g* (4096 counts/*g*), accelerometer normal oversampling, magnetometer OSR 7, low-noise off, 14-bit output, high-pass output off, FIFO disabled, all detectors and interrupt routing off, interrupts active-low push-pull, offsets 0, `hyb_autoinc_mode` = 1, automatic magnetic reset every ODR cycle, min/max tracking on, auto-calibration off.

### Full

Goal: expose complete chip functionality. Extends Minimal. Methods that change a "STANDBY-only" register call `standby()`, write, and restore `ACTIVE` internally (waiting for the mode change and turn-on time); the user need not manage the mode.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `read_hybrid` | — | `(accel(x,y,z), mag(x,y,z))` | One 12-byte burst from `0x01` (requires hybrid mode and `hyb_autoinc_mode`; raises otherwise); accel in *g*, mag in µT |
| `read_raw_accel` | — | `(x, y, z)` ints | Signed counts at the current resolution (14-bit right-aligned, or 8-bit) |

## Data Conversion

Accelerometer (14-bit, two's complement, left-justified in the 16-bit MSB:LSB pair):

```
raw16 = int16(OUT_x_MSB << 8 | OUT_x_LSB)      # bits 1:0 of LSB are always 0
counts = raw16 >> 2                             # 14-bit, arithmetic shift
acceleration_g = counts / counts_per_g          # 4096 (±2 g), 2048 (±4 g), 1024 (±8 g)
```

8-bit (fast read, `f_read` = 1): `counts = int8(OUT_x_MSB)`, `acceleration_g = counts / (counts_per_g / 64)` (64 / 32 / 16 counts/*g*). Sensitivities are 0.244 / 0.488 / 0.976 mg/LSB. Output values are in *g* (no m/s²).

Magnetometer (16-bit, two's complement, fixed ±1200 µT range, sensitivity 0.1 µT/LSB):

```
raw = int16(M_OUT_x_MSB << 8 | M_OUT_x_LSB)
field_uT = raw * 0.1                            # 10 counts per µT; 1 gauss = 100 µT
```

Read `M_OUT_X_MSB` first (it latches the X/Y/Z set). In hybrid mode with `hyb_autoinc_mode`, the 12-byte burst `0x01…0x0C` returns `[axH axL ayH ayL azH azL mxH mxL myH myL mzH mzL]`.

Temperature: `temperature_C = int8(TEMP) * 0.96`. The sensor is uncalibrated and device-dependent; use it for relative changes only (valid −40…125 °C).

Hard-iron offsets: `M_OFF_x` holds a 15-bit two's-complement value in bits 15:1 of the MSB:LSB pair (bit 0 of the LSB is unused), 0.1 µT/LSB, range −1638.4…+1638.3 µT. The register value is **subtracted** from the measurement: to correct an offset of +60 µT write 600 LSB = `0x0258 << 1` = `0x04B0`. `set_mag_offset(x, y, z)` takes the offset to subtract and writes `round(x / 0.1) << 1`.

Accelerometer offsets: `OFF_x = clamp(round(offset_g / 0.002), -128, 127)` as signed 8-bit (2 mg/LSB, ±0.256 *g*; the value is *added* to the measurement, so to remove +60 mg write −30 = `0xE2`).

Thresholds (7-bit, 0.063 *g*/LSB, valid to 8 *g* regardless of full scale; 4 *g* max with `lnoise`): `ths = clamp(round(threshold_g / 0.063), 0, 127)` for `A_FFMT_THS`, `TRANSIENT_THS`, `PULSE_THSx`.

**Time steps** are the MMA845x family values (datasheet Tables 70, 122, 135–144) at the **effective** ODR (ODR/2 in hybrid mode → steps double). Debounce step for `PL_COUNT`, `A_FFMT_COUNT`, `TRANSIENT_COUNT` (ms; max = 255 × step), at the effective ODR and accelerometer oversampling mode (N normal, LPLN low-noise low-power, HR high resolution, LP low power):

| Effective ODR (Hz) | N | LPLN | HR | LP |
|--------------------|---|------|----|----|
| 800 | 1.25 | 1.25 | 1.25 | 1.25 |
| 400 | 2.5 | 2.5 | 2.5 | 2.5 |
| 200 | 5 | 5 | 2.5 | 5 |
| 100 | 10 | 10 | 2.5 | 10 |
| 50 | 20 | 20 | 2.5 | 20 |
| 12.5 | 20 | 80 | 2.5 | 80 |
| 6.25 | 20 | 80 | 2.5 | 160 |
| 1.56 | 20 | 80 | 2.5 | 160 |

`COUNT = clamp(round(debounce_ms / step_ms), 0, 255)`. (In hybrid mode "effective ODR" is the user-selected system ODR divided by two, e.g. system 200 Hz → look up the 100 Hz row. The datasheet text gives this doubling explicitly for the debounce counters.)

Pulse time steps (`PULSE_TMLT`: Tables 135/136; `PULSE_LTCY`: 139/140; `PULSE_WIND`: 143/144): identical to the MMA8451Q tables in `specs/accelerometer/mma8451q.md` § Data Conversion (with `pulse_lpf_en` = 1 and = 0), again indexed by the effective ODR; `TMLT / LTCY / WIND = clamp(round(time_ms / step_ms), 0, 255)`.

Auto-SLEEP timeout: `ASLP_COUNT = clamp(round(timeout_s / step_s), 0, 255)`, `step_s` = 0.32 s for system ODR 800 … 6.25 Hz and 0.64 s for 1.56 Hz (datasheet Table 48; its "max inactivity time" for 1.56 Hz is printed as 63 s, which is inconsistent with 255 × 0.64 s = 163 s — likely a typo).

High-pass cutoff (Hz) for `sel` = 0…3: datasheet Table 64 (depends on ODR and oversampling mode, halved ODR in hybrid mode); the driver exposes the raw `sel` code and documents the table in its docstring.

Magnetometer oversampling ratio `m_os` = 0…7 at system ODR (datasheet Table 203; value = oversampling ratio):

| 1.56 | 16 | 16 | 32 | 64 | 128 | 256 | 512 | 1024 |
| 6.25 | 4 | 4 | 8 | 16 | 32 | 64 | 128 | 256 |
| 12.5 | 2 | 2 | 4 | 8 | 16 | 32 | 64 | 128 |
| 50 | 2 | 2 | 2 | 2 | 4 | 8 | 16 | 32 |

Tilt-compensated heading (software, from one accel + one mag sample, both in the chip's frame, X forward, Y right, Z down per datasheet Fig. 1/§7.1):

```
roll  = atan2(ay, az)
pitch = atan(-ax / (ay*sin(roll) + az*cos(roll)))
mx2 = mx*cos(pitch) + mz*sin(pitch)
my2 = mx*sin(roll)*sin(pitch) + my*cos(roll) - mz*sin(roll)*cos(pitch)
heading = degrees(atan2(-my2, mx2)) + declination      # wrapped to [0, 360)
```

Axis sign conventions must be checked on hardware (the datasheet orientation figure shows the sensor frame; the MPU-9250 spec documents the same caveat for its AK8963).

## Timing Constraints

- **Boot time:** ≤ 1000 µs after power-up/reset (datasheet Table 6, `TBOOT`). The driver waits ≥ 1 ms. A software or hardware reset also resets the I²C interface (no ACK on the `rst` write).
- **Turn-on STANDBY → ACTIVE:** 2/ODR + 1 ms; power-down → ACTIVE 2/ODR + 2 ms (`TSTBY→ACT`, `TPOR→ACT`), with ODR the system ODR. The driver waits 2/ODR + 2 ms after setting `active` (≈ 12 ms at 200 Hz, 1.28 s at 1.56 Hz).
- **First data after ACTIVE:** the first sample set is ready after the turn-on time plus one effective sample period (10 ms at the default hybrid 100 Hz per sensor). **Conformance-checked**: `first_data_ready` — sigrok annotation pair `active_start` (write to `CTRL_REG1` `0x2A` setting `active` = 1) → `active_ready` (first read of `STATUS` `0x00` returning `zyxdr` = 1). See `specs/accelerometer/fxos8700_timing.conf`.
- **ACTIVE → STANDBY in mag-only/hybrid mode:** 0 – 300 ms; poll `SYSMOD` until `00` rather than waiting a fixed time.
- **Reset:** after `rst` or a pulse on `RST` wait ≥ 1 ms; INT1 toggles high-low-high (≈ 500 ns) when the reset sequence completes.
- **Hybrid ODR:** each sensor's rate is half the programmed ODR; debounce/pulse time steps and high-pass cutoffs use the effective (halved) ODR.
- **Debounce counters:** a write to `*_THS`, `*_COUNT`, `M_OFF_*` or `M_CTRL_REG1/3` resets the corresponding internal counter; any ODR change or STANDBY ↔ ACTIVE transition resets the orientation debounce counters and flushes the FIFO.
- **One-shot magnetic measurement:** in STANDBY `m_ost` takes one measurement set and clears itself; the driver polls it (≤ 1 s).

## Implementation Notes

- **Register-addressed:** accept `RegisterConnection` (1-byte register address) and call `connection.read(reg, length)` / `connection.write(reg, data)` directly — no chip-local `_read_reg`/`_write_reg` and no `bus_type` branch (see `specs/feature_register_access_design.md`). The datasheet requires repeated START for reads.
- **Reset NACK:** writing `CTRL_REG2.rst` resets the I²C interface mid-transaction; the chip does not ACK the data byte. The driver must treat a NACK on that single write as success (then wait ≥ 1 ms and re-probe `WHO_AM_I`).
- **STANDBY-only configuration:** footnote [5] of datasheet Table 16 — most configuration registers can only be changed in STANDBY (except `XYZ_DATA_CFG.fs` and the `active` bit). Full wraps writes (read `CTRL_REG1`, clear `active`, poll `SYSMOD` = 0, write, set `active`, wait turn-on). Registers marked [4] (`PL_BF_ZCOMP`, `PL_THS_REG`, `A_FFMT_THS/COUNT`, `TRANSIENT_THS/COUNT`, `PULSE_THSx`, `M_OFF_*`, `M_CTRL_REG1/3`, vector-magnitude registers) can be written while ACTIVE.
- **Magnetometer read order:** reading `M_OUT_X_MSB` latches/updates the whole `M_OUT_X/Y/Z` set; the MSB of each pair must be read before its LSB (footnotes [6], [7]). Always read the six bytes `0x33–0x38` as one burst.
- **`hyb_autoinc_mode` and the FIFO:** with `hyb_autoinc_mode` = 1 a burst read from `0x01` jumps from `0x06` to `0x33`. FIFO draining only wants the six accelerometer bytes per sample, so `read_fifo` reads exactly 6 bytes (3 in 8-bit mode) per transaction and never relies on the pointer after `0x06`; reading 6 bytes does not trigger the jump. The FIFO holds accelerometer data only (no magnetometer data).
- **CMP_x registers:** the time-aligned accelerometer sample in `0x39–0x3E` is **right-justified** 14-bit (MSB register contains bits 13:8), unlike `OUT_x`; the driver does not use them (`read_hybrid` uses the 12-byte burst).
- **Interrupt polarity default is active-low** (`ipol` = 0); `init` leaves it as reset.
- **Temperature:** only valid when the magnetometer is active (`m_hms` ≠ `00`); uncalibrated and unit-to-unit variable.
- **Low-noise mode:** limits the accel range to ±4 *g*; `set_low_noise` and `set_range` enforce the combination.
- **Self-test:** `self_test()` — STANDBY, ±2 *g*, 100 Hz accel-only (`m_hms` = `00`), normal oversampling, ACTIVE; average a few samples; set `st` = 1; wait ≥ 2/ODR; average again; clear `st`; restore the previous configuration; `d = after − before` in 14-bit counts. The datasheet (Table 3, `STOCACC`, ±2 *g* mode) specifies a minimum output change of **X ≥ +192, Y ≥ +270, Z ≥ +1275 LSB** ("exercised along one direction for each axis"); `ok` is true if every axis meets its minimum.
- **Auto-calibration:** `m_acal` writes `(MAX + MIN)/2` to `M_OFF_*` every ODR cycle; it only has an effect when `m_raw` = 0 and min/max tracking is enabled. The user must rotate the device through all orientations while it is on. See NXP application note AN4399.
- **SPI mode trap:** a floating `SA0` at power-up latches SPI mode; and with other devices on the I²C bus the `SA0/MISO` pin must be tied low or high.
- **Datasheet revision:** the committed datasheet is Rev. 8 (25 April 2017); some figures and the Table 203 rows for low ODR are partly garbled in text extraction — verify those on a real part.

## Sigrok Decoder

Decoder id `fxos8700`, input `['i2c']`. Matches I²C addresses `0x1C`–`0x1F`. Annotates every register in the Register Map by name; decodes `STATUS` / `F_STATUS`, `SYSMOD`, `INT_SOURCE`, `XYZ_DATA_CFG`, `HP_FILTER_CUTOFF`, `PL_STATUS`, `PL_CFG`, `PL_BF_ZCOMP`, `PL_THS_REG`, `A_FFMT_CFG` / `SRC`, `TRANSIENT_CFG` / `SRC`, `PULSE_CFG` / `SRC`, `CTRL_REG1`–`CTRL_REG5`, `F_SETUP`, `TRIG_CFG`, `M_DR_STATUS`, `M_CTRL_REG1`–`M_CTRL_REG3` and `M_INT_SRC` into named flags; decodes `dr`, `fs`, `mods`, `m_os`, `m_hms` and `f_mode` into human-readable values; assembles the burst read of `0x01–0x06` into 14-bit signed values converted to *g* at the last-seen range (8-bit when `f_read` is set), the burst `0x33–0x38` into 16-bit values converted to µT, a 12-byte burst from `0x01` into both, and `TEMP` into °C. `WHO_AM_I` reads are checked against `0xC7`. For the first-data-ready Timing Constraint the decoder emits the `timing` annotation row markers `active_start` (write to `CTRL_REG1` `0x2A` setting `active` = 1) and `active_ready` (first read of `STATUS` `0x00` returning `zyxdr` = 1), shaped per `specs/sigrok_annotations.md`'s Variable-Length Annotation Convention.
