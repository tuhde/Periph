# Chip Spec: TMP117

**Manufacturer:** Texas Instruments
**Datasheet:** `datasheets/temperature/tmp117.pdf`
**Category:** temperature
**Transports:** I²C, SMBus

## Overview

The TMP117 is a high-precision digital temperature sensor with NIST-traceable ±0.1°C
(max) accuracy from -20°C to 50°C and a 16-bit, 0.0078125°C-resolution result — accurate
enough to serve as a calibration-free replacement for a PT100/PT500/PT1000 RTD at a
fraction of the power. It operates over a two-wire bus that is simultaneously I²C- and
SMBus-compatible (including SMBus Alert Response support), offers continuous, one-shot,
and shutdown conversion modes with selectable averaging (up to 64 conversions) and cycle
time, and drives a programmable `ALERT` output as either a window-limit alert, a
latching thermostat ("Therm") output, or a plain Data-Ready signal. A 64-bit
user-programmable EEPROM can persist the power-on defaults for the configuration and
limit registers, plus 48 bits of general-purpose scratch storage. Up to four devices can
share one bus via a single 4-level address pin.

## Transport Configuration

### I²C
- **Address:** `0x48`–`0x4B`, selected by connecting `ADD0` to `GND` (`0x48`), `V+`
  (`0x49`), `SDA` (`0x4A`), or `SCL` (`0x4B`) — 4 combinations, sampled once at power-up
- **Max clock:** 400 kHz (Fast mode); the two-wire interface is simultaneously SMBus- and
  I²C-compatible

### SMBus
- Same 4-level `ADD0` addressing and register map as I²C above; additionally supports the
  SMBus Alert Response Address (ARA) protocol and the SMBus general-call reset command
  (see Implementation Notes) — neither is wrapped by this driver's per-chip API, since
  both operate against a bus-wide address rather than this chip's own

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| ALERT | configurable (active-low POR default), open-drain | requires an external pull-up; carries either the alert/Therm status or a Data-Ready pulse — see Interrupt section |

`ADD0` is a board-level address strap (four-level, not binary), not a runtime-controllable
pin.

## Register Map

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|--------------|
| `0x00` | TEMP_RESULT | R | `0x8000` | Most recent temperature conversion result, two's complement, 0.0078125°C/LSB |
| `0x01` | CONFIGURATION | R/W | `0x0220` | Conversion mode, cycle time, averaging, Therm/Alert select, polarity, ALERT pin function, status flags, soft reset |
| `0x02` | THIGH_LIMIT | R/W | `0x6000` (EEPROM-backed) | High temperature limit, same format as `TEMP_RESULT` |
| `0x03` | TLOW_LIMIT | R/W | `0x8000` (EEPROM-backed) | Low temperature limit / Therm-mode hysteresis threshold, same format |
| `0x04` | EEPROM_UL | R/W | `0x0000` | EEPROM unlock control and busy status |
| `0x05` | EEPROM1 | R/W | factory-programmed | General-purpose EEPROM-backed scratch — factory holds part of a NIST-traceable unique ID; **do not overwrite** |
| `0x06` | EEPROM2 | R/W | `0x0000` (EEPROM-backed) | General-purpose EEPROM-backed scratch — freely usable |
| `0x07` | TEMP_OFFSET | R/W | `0x0000` (EEPROM-backed) | User calibration offset, added to the linearized result, same format as `TEMP_RESULT` |
| `0x08` | EEPROM3 | R/W | factory-programmed | General-purpose EEPROM-backed scratch — factory holds the remainder of the unique ID; **do not overwrite** |
| `0x0F` | DEVICE_ID | R | `0x0117` | Bits 11:0 fixed device ID (`0x117`); bits 15:12 silicon revision |

Registers are accessed through an 8-bit write-only pointer, matching this repository's
other pointer-addressed I²C temperature sensor (MCP9808): write the pointer, then transfer
16-bit data MSB-first. Repeated access to the same register does not require resending the
pointer; switching registers does.

### Bit Fields

#### `CONFIGURATION` (`0x01`)

| Bits | Name | Description |
|------|------|--------------|
| 15 | HIGH_Alert | **Read-only.** Alert mode: `1` if the result exceeded `THIGH_LIMIT`, cleared on reading this register. Therm mode: `1` if the result exceeded `THIGH_LIMIT`, cleared only once the result drops below `TLOW_LIMIT` |
| 14 | LOW_Alert | **Read-only.** Alert mode: `1` if the result fell below `TLOW_LIMIT`, cleared on reading this register. Therm mode: always `0` (disabled) |
| 13 | Data_Ready | **Read-only.** `1` when a fresh conversion result is available; cleared by reading either this register or `TEMP_RESULT` |
| 12 | EEPROM_Busy | **Read-only.** `1` while an EEPROM programming operation or the power-up EEPROM load is in progress |
| 11:10 | MOD[1:0] | Conversion mode: `00`/`10`=Continuous Conversion (default; `10` reads back as `00`), `01`=Shutdown, `11`=One-Shot |
| 9:7 | CONV[2:0] | Conversion cycle time — see Timing Constraints (default `100` = 1 s) |
| 6:5 | AVG[1:0] | Averaging: `00`=none, `01`=8 conversions (default), `10`=32, `11`=64 |
| 4 | T/nA | `0`=Alert mode (default), `1`=Therm mode |
| 3 | POL | ALERT polarity: `0`=active-low (default), `1`=active-high |
| 2 | DR/Alert | ALERT pin function: `0`=reflects the alert/Therm status (default), `1`=reflects `Data_Ready` |
| 1 | Soft_Reset | Write `1` to trigger a 2 ms software reset (see Timing Constraints); always reads `0` |
| 0 | — | Unused |

`MOD[1:0]` cannot be stored in EEPROM as `11` (One-Shot) — a device can only be
factory/EEPROM-programmed to start up in Continuous Conversion or Shutdown mode.

#### `THIGH_LIMIT` / `TLOW_LIMIT` / `TEMP_OFFSET` (`0x02` / `0x03` / `0x07`)

16-bit, two's complement, 0.0078125°C per LSB — the identical format used by
`TEMP_RESULT` (see Data Conversion). Range ±256°C.

#### `EEPROM_UL` (`0x04`)

| Bits | Name | Description |
|------|------|--------------|
| 15 | EUN | EEPROM unlock: `0`=locked (default) — writes to `CONFIGURATION`/`THIGH_LIMIT`/`TLOW_LIMIT`/`TEMP_OFFSET`/`EEPROM1`/`EEPROM2`/`EEPROM3` only affect the volatile register; `1`=unlocked — the same writes additionally program the corresponding EEPROM cell as the new power-on default |
| 14 | EEPROM_Busy | **Read-only**, mirrors `CONFIGURATION` bit 12 |
| 13:0 | — | Unused |

#### `DEVICE_ID` (`0x0F`, read-only)

| Bits | Name | Description |
|------|------|--------------|
| 15:12 | Rev[3:0] | Silicon revision |
| 11:0 | DID[11:0] | Fixed device ID, `0x117` |

## Initialization Sequence

1. Construct the driver with a `Connection` at whichever address (`0x48`–`0x4B`) matches
   the board's `ADD0` strapping.
2. Read `DEVICE_ID` (`0x0F`) and confirm the lower 12 bits equal `0x117` — a genuine
   identity check, like this repository's MCP9808 driver.
3. No further register writes are required at `init` time: the POR/EEPROM default
   (Continuous Conversion, 8-conversion averaging, 1 s cycle, Alert mode with `ALERT`
   reflecting the alert status) is already the primary use case. `TEMP_RESULT` reads the
   `-256°C` power-up sentinel until the first conversion completes (see Timing
   Constraints).

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `ALERT`, open-drain, polarity/pin-function configurable (`POL`/`DR/Alert`) — requires an external pull-up |
| Level | 2 (selectable behavior: Alert vs. Therm mode, and repurposable as a Data-Ready signal instead) |
| Condition(s) | Result > `THIGH_LIMIT`; result < `TLOW_LIMIT` (Alert mode only) |
| Clear mechanism | Alert mode: reading `CONFIGURATION` clears both flags. Therm mode: `HIGH_Alert` clears itself only once the result drops below `TLOW_LIMIT` — it cannot be cleared by a register read |

### Interrupt sources

| Constant | Value | Condition |
|----------|-------|-----------|
| `SOURCE_HIGH` | `0x01` | Result > `THIGH_LIMIT` |
| `SOURCE_LOW` | `0x02` | Result < `TLOW_LIMIT` (Alert mode only; always `0` in Therm mode) |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|--------------|
| `on_interrupt` | `on_interrupt(callback)` | Subscribe; callback receives the status int (mask with `SOURCE_HIGH`/`SOURCE_LOW`) |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Reads `CONFIGURATION` and returns `HIGH_Alert`/`LOW_Alert` as a status mask. In Alert mode this read also clears both flags (an unavoidable hardware side effect, not something this driver adds) |
| `configure_alert` | `configure_alert(mode="alert"\|"therm", polarity="active_low"\|"active_high", pin_function="alert"\|"data_ready")` | Sets `T/nA`, `POL`, and `DR/Alert` together |

There is no separate alert-enable bit — the comparison against `THIGH_LIMIT`/`TLOW_LIMIT`
is always active; `set_low_limit`/`set_high_limit` at the register's extreme values
(`-256`/`+256°C`) effectively disable that side.

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits
everything and adds the rest.

### Minimal

Goal: read ambient temperature accurately, with no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Confirms `DEVICE_ID`'s lower 12 bits equal `0x117`; makes no register writes |
| `read_temperature` | — | float °C | Reads `TEMP_RESULT` and decodes the two's-complement 0.0078125°C value (see Data Conversion). Returns `-256.0` until the first conversion completes after power-up |

**Sensible defaults:** no register writes at `init` — the POR/EEPROM default (Continuous
Conversion, 8-conversion averaging, 1 s cycle, Alert mode) already serves the primary use
case; `Full` exposes conversion-mode/averaging/cycle-time trade-offs, both temperature
limits, calibration offset, the Alert/Therm output, and EEPROM persistence.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `configure` | mode="continuous"\|"shutdown"\|"one_shot", averaging=8 (0\|8\|32\|64), cycle_seconds=1.0 | — | Sets `MOD[1:0]`, `AVG[1:0]`, and `CONV[2:0]` (nearest match to `cycle_seconds` from the no-averaging column of the conversion-cycle-time table — see Timing Constraints; actual cycle time grows automatically at higher averaging per hardware behavior) |
| `get_config` | — | `(mode, averaging, cycle_seconds)` | Reads and decodes `CONFIGURATION`'s mode/averaging/cycle fields |
| `is_shutdown` | — | bool | `True` if `MOD[1:0]`==Shutdown |
| `trigger_one_shot` | — | — | Rewrites `CONFIGURATION` with `MOD[1:0]`=One-Shot, starting a fresh conversion (also usable to take a single reading while otherwise in Shutdown) |
| `is_data_ready` | — | bool | Reads `Data_Ready`. Note: this read clears the flag, the same side effect a `TEMP_RESULT`/`CONFIGURATION` read has |
| `get_high_limit` / `set_high_limit` | — / celsius | float °C / — | Reads/writes `THIGH_LIMIT` |
| `get_low_limit` / `set_low_limit` | — / celsius | float °C / — | Reads/writes `TLOW_LIMIT` |
| `get_temperature_offset` / `set_temperature_offset` | — / celsius | float °C / — | Reads/writes `TEMP_OFFSET`, added to every result after linearization |
| `reset` | — | — | Sets `Soft_Reset`=1 (2 ms duration, see Timing Constraints); reloads `CONFIGURATION`/`THIGH_LIMIT`/`TLOW_LIMIT`/`TEMP_OFFSET` from EEPROM |
| `unlock_eeprom` / `lock_eeprom` | — | — | Sets/clears `EUN`. While unlocked, writes to `CONFIGURATION`/`THIGH_LIMIT`/`TLOW_LIMIT`/`TEMP_OFFSET`/`EEPROM2` through their normal setters additionally commit to EEPROM as the new power-on default (see Timing Constraints and Implementation Notes) |
| `is_eeprom_busy` | — | bool | Reads `EEPROM_Busy` |
| `read_eeprom_scratch` | slot (1, 2, or 3) | int (16-bit) | Reads `EEPROM1`/`EEPROM2`/`EEPROM3` |
| `write_eeprom_scratch` | slot (must be `2`), value (16-bit) | — | Writes `EEPROM2` only — `EEPROM1`/`EEPROM3` hold factory NIST-traceability data and are deliberately not writable through this method (see Implementation Notes) |
| *(interrupt/Alert API)* | | | See Interrupt section above |

**Additional configuration options:** conversion mode/averaging/cycle time, one-shot
triggering, both temperature limits, calibration offset, software reset, EEPROM unlock
and persistence of the four EEPROM-backed registers, and general-purpose EEPROM scratch
storage.

## Data Conversion

```
# TEMP_RESULT / THIGH_LIMIT / TLOW_LIMIT / TEMP_OFFSET: 16-bit two's complement,
# 0.0078125 degC per LSB (identical format across all four registers).
temperature_c = raw - 0x10000 if raw & 0x8000 else raw   # sign-extend
temperature_c = temperature_c * 0.0078125

# Encoding a value for a write rounds to the nearest 0.0078125 degC step and
# wraps to the 16-bit two's-complement representation.
```

### Demo flow

An Inject node fires every 5 s, triggering the `periph-tmp117` node to read and log
temperature. The node is configured with `THIGH_LIMIT` set to a server-room "too hot"
threshold and `mode`="therm"; when the ALERT pin trips, the node emits
`{ source: "high" }`, which a Function node turns into a cooling-fan trigger via a second
flow, deasserting automatically once the room cools below `TLOW_LIMIT`.

## Examples

### Demo

A PT100-replacement electronic thermometer for a cold-chain shipping container. On
startup, the demo calls `configure(mode="continuous", averaging=64, cycle_seconds=1.0)`
for the lowest achievable noise, then sets `THIGH_LIMIT`=`8°C` and `TLOW_LIMIT`=`-25°C`
(the safe transport range) with `configure_alert(mode="alert", polarity="active_low")`.
It subscribes with `on_interrupt`; the callback masks the returned status against
`SOURCE_HIGH`/`SOURCE_LOW`, printing `read_temperature()` and which boundary tripped. It
also demonstrates one-time calibration against a reference thermometer: it computes the
observed offset, calls `unlock_eeprom()`, `set_temperature_offset(offset)` (persisting
the correction across power cycles), polls `is_eeprom_busy()` until clear, then
`lock_eeprom()`. Before exiting after a fixed number of alerts, it calls `off_interrupt()`.

## Timing Constraints

- **EEPROM write ready (`eeprom_write_ready`):** after writing an EEPROM-backed register
  while unlocked (`EUN`=1), `EEPROM_Busy` clears within approximately 7 ms typical
  (no datasheet-specified maximum; this spec budgets 20 ms as a conservative bound) —
  poll `is_eeprom_busy()` before the next EEPROM write. This is the only
  host-observable, conformance-checkable timing this chip has.
- Power-up: the device needs 1.5 ms after `V+` reaches the operating range before the
  first conversion begins; `TEMP_RESULT` reads the `-256°C` sentinel until then —
  autonomous, not driver-actionable.
- Conversion time: 15.5 ms (no averaging, fastest `CONV` setting) up to 16 s (slowest
  `CONV` setting, any averaging); a single active conversion at 8-conversion averaging
  (POR default) is approximately 124 ms. Governed by `CONV[2:0]`/`AVG[1:0]` together
  (see the datasheet's Table 7-7) — autonomous once configured, not something the driver
  waits out.
- Software reset (`Soft_Reset`): 2 ms duration — a host-side wait requirement with no
  bus-observable busy flag to poll (`EEPROM_Busy` is unrelated).
- Bus time-out: 20–40 ms typical (35 ms typical) — if `SCL` is held low, or `SDA` is held
  low by the TMP117, between a `START` and `STOP`, the serial interface resets and a new
  `START` is required. A fault-recovery behavior, not something the driver triggers
  intentionally; avoid clock speeds below 1 kHz to prevent spuriously tripping it.
- I²C/SMBus bus AC timing: up to 400 kHz — covered by `specs/transport_i2c.md`.

## Implementation Notes

- The `node-red-contrib-periph-temperature` package already exists (created for this
  repository's MCP9808 driver) — no new-category setup is needed here, unlike that spec.
- `EEPROM1` (`0x05`) and `EEPROM3` (`0x08`) are factory-programmed with a NIST-traceable
  unique ID and the datasheet explicitly warns against reprogramming either — this driver
  only exposes writing `EEPROM2` (`0x06`) through `write_eeprom_scratch`; `EEPROM1`/
  `EEPROM3` are read-only through this API even though the hardware register itself is
  R/W.
- Persisting `CONFIGURATION`/`THIGH_LIMIT`/`TLOW_LIMIT`/`TEMP_OFFSET` to EEPROM reuses
  the *same* setter methods used for volatile-only changes — the only difference is
  whether `EUN` is set first. There is no separate "write to EEPROM" method for those
  four registers, only for the general-purpose scratch cells. `MOD[1:0]`=One-Shot
  specifically cannot be committed to EEPROM as a start-up default (falls back to
  Shutdown or Continuous Conversion only).
- EEPROM write endurance is rated 1,000 minimum / 50,000 typical cycles — `Full`'s EEPROM
  methods are for infrequent calibration/configuration persistence, not a per-loop data
  store; use `EEPROM2` for anything written more than a handful of times over the
  product's life.
- Therm mode repurposes `TLOW_LIMIT` as `HIGH_Alert`'s hysteresis/reset threshold rather
  than an independent low-temperature alarm — `LOW_Alert` is hard-disabled (always reads
  `0`) in this mode, and `HIGH_Alert` cannot be cleared by reading `CONFIGURATION`; it
  only clears autonomously once the result drops below `TLOW_LIMIT`.
- The TMP117 supports the SMBus Alert Response Address (ARA) protocol and the SMBus
  general-call reset command (`0x00` address, `0x06` data byte resets all registers to
  power-up values) — both operate against a bus-wide address rather than this chip's own,
  so they are not wrapped by this driver's per-chip API; a host wanting ARA support
  implements it once at the bus/transport level, not per chip.
- `trigger_one_shot()` assumes rewriting `CONFIGURATION` with `MOD[1:0]`=`11` starts a
  fresh conversion even if the register already read `11` — the datasheet does not fully
  spell out repeat-trigger semantics for successive one-shot writes; verify this
  assumption against real hardware during implementation.
- The chip has a real Device ID register (`0x0117`) — like this repository's MCP9808
  driver (and unlike DS3231/PCF8523), `init()` performs a genuine identity check.

## Sigrok Decoder

Decoder `tmp117` (`sigrok/tmp117/`) stacks on the `i2c` decoder and recognizes any address
in the `0x48`–`0x4B` range (the 4 valid `ADD0` strap positions), tracking the last-written
(non-auto-incrementing) register pointer across transactions.

| Row | Annotation | Meaning |
|-----|------------|---------|
| Data | `data` | `THIGH_LIMIT`/`TLOW_LIMIT`/`TEMP_RESULT`/`TEMP_OFFSET` decoded to °C per Data Conversion; `EEPROM1`/`EEPROM2`/`EEPROM3` shown as raw hex |
| Status | `status` | `CONFIGURATION` decoded to its named bit fields; `EEPROM_UL` decoded to `EUN`/`EEPROM_Busy` |
| Timing | `timing` | `eeprom_write_ready_start`/`eeprom_write_ready_done` marker pair: start at a write to an EEPROM-backed register while `EUN`=1; end at the first subsequent `EEPROM_Busy` read that shows `0` |
| Warnings | `warning` | A write to `EEPROM1`/`EEPROM3` while unlocked (destroys factory unique-ID data); access to an undefined pointer (`0x09`–`0x0E`) |
