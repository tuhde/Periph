# Chip Spec: MLX90632

**Manufacturer:** Melexis  
**Datasheet:** `datasheets/temperature/mlx90632.pdf` (MLX90632 FIR sensor datasheet, DOC#3901090632 Revision 13 – JUN, 2025)  
**Category:** temperature  
**Transports:** I²C

## Overview

The MLX90632 is a miniature factory-calibrated far-infrared (FIR) thermometer (2–14 µm passband) that measures the object temperature without contact and the sensor (ambient) temperature with one I²C interface. It exists in a standard-accuracy version (object range −20…+85 °C, ±1 °C) and a medical-accuracy version (±0.2 °C in 35–42 °C) that adds an extended-range measurement mode. Raw 16-bit values are read from RAM and converted with the factory calibration constants stored in the EEPROM using fixed formulas (ambient temperature from a second-order polynomial, object temperature from a Stefan–Boltzmann-based equation solved iteratively). The device supports continuous, step and sleeping-step modes, refresh rates from 0.5 Hz to 64 Hz (medical/standard) and 0.16 Hz to 20 Hz (extended range), a configurable I²C address, and is available with a 3.3 V or 1.8 V I²C reference. Supply 3.3 V. Typical uses: contactless fever/body temperature, industrial and HVAC temperature control, presence/occupancy detection.

## Transport Configuration

### I²C
- **Address:** `0x3A` (7-bit default; bit 0 follows the `ADDR` pin — GND = `0x3A`, VDD = `0x3B`; the upper 6 bits are configurable at EEPROM `0x24D5`)
- **Max clock:** 1 MHz (standard, fast and fast-mode-plus are supported)
- **Identity register:** `0x2409` (`EE_PRODUCT_CODE`, EEPROM, 16-bit) holds the sensor information (version/FOV bits); the three words `ID0`–`ID2` at `0x2405`–`0x2407` form a unique chip ID. There is no constant ID value, so the chip is registered in `registry/chips.json` with `id_probe: null`
- **Probe safety:** `register_pointer` — plain addressed reads of the EEPROM/RAM have no side effects; writes to `0x3001`/`0x3FFF`, `0x24xx` and the reset commands change state
- **Register addressing:** **16-bit** register address, MSB first (`reg_bytes = 2`); data are 16-bit big-endian words; sequential reads auto-increment (the calibration block `0x240C`–`0x2430` and the RAM block can be read in one burst). The datasheet defines a "direct read" and the two reset commands below; the driver uses addressed reads/writes

## Register Map

| Address | Name | R/W | Description |
|---------|------|-----|-------------|
| `0x2405`–`0x2407` | ID0, ID1, ID2 | R | Chip ID (3 × 16 bit); `0x2408` ID_CRC16 |
| `0x2409` | EE_PRODUCT_CODE | R | Sensor information (version, field of view) |
| `0x240B` | EE_VERSION | R | EEPROM version |
| `0x240C`–`0x2430` | EE_P_R … EE_Kb | R | Calibration constants, 32-bit values stored as two words (**LS word at the lower address**, `0x240C` = EE_P_R[15:0], `0x240D` = EE_P_R[31:16]): P_R, P_G, P_T, P_O, Aa, Ab, Ba, Bb, Ca, Cb, Da, Db, Ea, Eb, Fa, Fb, Ga (32-bit at `0x240C`–`0x242D`), then Gb (`0x242E`), Ka (`0x242F`), Kb (`0x2430`) (16-bit) |
| `0x2481`, `0x2482` | EE_Ha, EE_Hb | R/W | Customer calibration constants (16 bit, gain `Ha` and offset `Hb`) |
| `0x24C0`–`0x24CF` | Customer data | R/W | Customer storage |
| `0x24D4` | EE_CONTROL | R/W | EEPROM copy of the initial `REG_CONTROL` |
| `0x24D5` | EE_I2C_ADDRESS | R/W | I²C address configuration |
| `0x24E1`, `0x24E2` | EE_MEAS_1, EE_MEAS_2 | R/W | Measurement settings 1/2 (refresh rate in bits 10:8) |
| `0x3000` | REG_I2C_ADDRESS | R/W | I²C slave address >> 1 (RAM copy) |
| `0x3001` | REG_CONTROL | R/W | Mode, measurement select, `soc`, `sob` |
| `0x3FFF` | REG_STATUS | R/W | Busy, brown-out, cycle position, new-data flags |
| `0x4000`–`0x403B` | RAM_1 … RAM_60 | R | Raw measurement data (signed 16 bit) |

### Bit Fields

#### `REG_CONTROL` (`0x3001`)

| Bits | Name | Description |
|------|------|-------------|
| 11 | sob | Starts a full measurement table in (sleeping) step mode |
| 8:4 | meas_select | Measurement type: `0x00` medical (default on the medical version), `0x11` extended range |
| 3 | soc | Starts a single measurement in (sleeping) step mode |
| 2:1 | mode | `00` halt (for EEPROM operations), `01` sleeping step, `10` step, `11` continuous (default) |

#### `REG_STATUS` (`0x3FFF`)

| Bits | Name | Description |
|------|------|-------------|
| 10 | device_busy | 1 = measurement running (always 1 in continuous mode, 0 in sleep) |
| 9 | eeprom_busy | 1 = EEPROM busy (start-up copy phase, write/erase) |
| 8 | brown_out | Customer sets 1 at start-up; reads 0 after a reset |
| 6:2 | cycle_position | Index of the measurement in the table that wrote the latest RAM data (1 or 2 for the medical/standard table) |
| 0 | new_data | 1 when a measurement is complete; the customer clears it by writing 0 |

#### `EE_MEAS_1` / `EE_MEAS_2` refresh rate (bits 10:8)

| Value | Medical/standard rate | Extended range rate (EE_MEAS_17–19 codes) |
|-------|----------------------|-------------------------------------------|
| 0 | 0.5 Hz (2000 ms) | 0.16 Hz (6000 ms) |
| 1 | 1 Hz | 0.32 Hz |
| 2 | 2 Hz | 0.65 Hz |
| 3 | 4 Hz | 1.3 Hz |
| 4 | 8 Hz | 2.6 Hz |
| 5 | 16 Hz | 5 Hz |
| 6 | 32 Hz | 10 Hz |
| 7 | 64 Hz (15.625 ms) | 20 Hz (50 ms) |

The refresh rate must be the same in both measurements. In the extended range mode the measurement words `EE_MEAS_17`–`EE_MEAS_19` (`0x24F1`–`0x24F3`) hold the full setting, e.g. 0.16 Hz = `0x8000`/`0x8012`/`0x800C`, 1.3 Hz = `0x8300`/`0x8312`/`0x830C`, 20 Hz = `0x8700`/`0x8712`/`0x870C`.

## Initialization Sequence

1. Power VDD (3.3 V); wait until `REG_STATUS.eeprom_busy` = 0 (the EEPROM copy at start-up).
2. Read the calibration block `0x240C`–`0x2430` once (and `0x2481`, `0x2482`), assemble the 32-bit constants (`LS` word first) and keep them.
3. Check `EE_PRODUCT_CODE` (`0x2409`) for the sensor variant and FOV.
4. Set `REG_STATUS.brown_out` to 1 (the customer must do this at start-up) and clear `new_data` by writing 0 (read-modify-write of the status word, leaving the read-only bits).
5. Leave the device in continuous mode (default) or select another mode in `REG_CONTROL`.
6. For each result: wait for `new_data`, read `cycle_position`, read the RAM words, write `new_data` = 0 and compute the temperatures.

## Implementation Stages

### Minimal

Goal: read the object and ambient temperature with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Takes the `RegisterConnection` configured for 16-bit register addresses; waits for `eeprom_busy` = 0, reads the calibration constants, sets `brown_out`, uses continuous medical/standard measurement (the chip default, 2 Hz-class table, not rewritten) |
| `read` | — | `{object_c, ambient_c}` | Waits for `new_data`, reads `cycle_position` and RAM_4–RAM_9, clears `new_data`, computes the ambient temperature and the object temperature (three iterations, emissivity 1.0) |

**Sensible defaults:** continuous mode, default refresh rate (the EEPROM value), emissivity 1.0, medical/standard measurement, calibration constants read once in `init`.

### Full

Goal: complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `read_object` / `read_ambient` | — | float | One temperature (still reads the full RAM block) |
| `read_raw` | — | `list[int]` | RAM_4–RAM_9 (or RAM_52–RAM_60 in extended range) as signed 16-bit values |
| `new_data` / `clear_new_data` | — | bool / — | `REG_STATUS.new_data` |
| `cycle_position` | — | int | `REG_STATUS[6:2]` |
| `set_emissivity` / `get_emissivity` | `epsilon: float` (0.1–1.0) / — | — / float | Driver-side emissivity used in the object formula (not stored in the chip) |
| `set_mode` | `mode: str` (`"halt"`, `"sleep_step"`, `"step"`, `"continuous"`) | — | `REG_CONTROL.mode` |
| `measure_once` | — | `(object_c, ambient_c)` | In step modes: sets `soc`, waits for `new_data`, reads and converts (two cycles for the first result, see notes) |
| `set_measurement_type` | `extended: bool` | — | Performs the datasheet routine: addressed reset, set `mode` = halt and `meas_select`, then restore the mode (extended range exists only on the medical version) |
| `set_refresh_rate` | `hertz: float` | — | Writes the refresh-rate bits of `EE_MEAS_1`/`EE_MEAS_2` (requires the EEPROM write sequence of the datasheet, see Implementation Notes) — an EEPROM write; the driver raises unless `allow_eeprom_write=True` |
| `get_refresh_rate` | — | float | From `EE_MEAS_1` |
| `product_code` | — | int | `0x2409` |
| `chip_id` | — | `(id0, id1, id2)` | `0x2405`–`0x2407` |
| `soft_reset` | — | — | Addressed reset (`0x3005` ← `0x0006`), waits 150 µs, re-initialises |
| `read_register` / `write_register` | `address: int` / `address: int, value: int` | int / — | Raw 16-bit access (diagnostics; writes to the EEPROM region are refused) |

**Additional configuration options:** operating mode, measurement type (medical/extended), emissivity, refresh rate.

## Data Conversion

```
# constants (EE_* are signed; 32-bit = (hi_word << 16) | lo_word with hi at the higher address)
P_R = EE_P_R * 2^-8     P_O = EE_P_O * 2^-8     P_G = EE_P_G * 2^-20    P_T = EE_P_T * 2^-44
Ea  = EE_Ea  * 2^-16    Eb  = EE_Eb  * 2^-8
Fa  = EE_Fa  * 2^-46    Fb  = EE_Fb  * 2^-36    Ga  = EE_Ga  * 2^-36
Gb  = EE_Gb  * 2^-10    Ka  = EE_Ka  * 2^-10
Ha  = EE_Ha  * 2^-14    Hb  = EE_Hb  * 2^-10        # 16-bit signed customer constants

# medical / standard measurement (RAM words are signed 16-bit)
VR_TA = RAM_9 + Gb * (RAM_6 / 12)
AMB   = ((RAM_6 / 12) / VR_TA) * 2^19
Ta_C  = P_O + (AMB - P_R) / P_G + P_T * (AMB - P_R)^2            # sensor temperature, deg C

S     = (RAM_4 + RAM_5) / 2        # cycle_position = 1   (or (RAM_7 + RAM_8) / 2 for cycle_position = 2)
VR_TO = RAM_9 + Ka * (RAM_6 / 12)
STO   = ((S / 12) / VR_TO) * 2^19
TA_DUT = (AMB - Eb) / Ea + 25
Ta_K   = TA_DUT + 273.15
TO     = fourth_root( STO / (epsilon * Fa * Ha * (1 + Ga * (TO_DUT - 25) + Fb * (TA_DUT - 25))) + Ta_K^4 ) - 273.15 - Hb
# iterate three times: TO_DUT = 25 in the first pass, then the previous TO result

# extended-range measurement (needs all three groups RAM_52..RAM_60)
VR_TA = RAM_57 + Gb * (RAM_54 / 12);   AMB = ((RAM_54 / 12) / VR_TA) * 2^19      # Ta_C as above
S     = (RAM_52 - RAM_53 - RAM_55 + RAM_56) / 2 + RAM_58 + RAM_59
VR_TO = RAM_57 + Ka * (RAM_54 / 12);   STO = ((S / 12) / VR_TO) * 2^19
TO    = fourth_root( STO / (epsilon * (Fa / 2) * Ha * (1 + Ga * (TO_DUT - 25) + Fb * (TA_DUT - 25))) + Ta_K^4 ) - 273.15 - Hb
```

All temperatures are in °C (Kelvin only inside the formula). The first result needs two measurements (twice the refresh time); afterwards one result per refresh period uses the current and the previous measurement. The reference implementation is the Melexis `mlx90632-library` on GitHub (the datasheet states all functions are available there); this spec follows the datasheet formulas and must be cross-checked against the worked example in section 11.1.4 (RAM_6 = 22500, RAM_9 = 23000, Gb = 9.5, Ka = 10.5 give AMB = 24086.738) in the unit test.

## Timing Constraints

| Constraint | Value |
|------------|-------|
| Refresh period | 15.625 ms … 2000 ms (medical/standard), 50 ms … 6000 ms (extended) |
| First valid result | two measurements (about 2 × refresh period) |
| After a reset command | ≥ 150 µs before the next communication |
| Sleeping-step reset/command timing | last SCL falling edge to last rising edge ≤ 1.8 µs |
| I²C clock | up to 1 MHz |

None of these has a bus-decodable start/end annotation pair with a datasheet bound that a decoder can mark, so `mlx90632_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection, 16-bit register addresses:** construct the connection with `reg_bytes = 2` (see `specs/feature_register_access_design.md`); all values are big-endian 16-bit words.
- **Calibration constants:** read once in `init`; the 32-bit values are stored low word first (`EE_x[15:0]` at the lower address, `EE_x[31:16]` at the next); all are signed. Cache them in the driver.
- **Two-measurement table:** the very first temperature needs two measurements; after that each new measurement updates one half (`cycle_position` 1 or 2) and the previous half remains in RAM. The driver clears `new_data`, waits for the next set and uses `cycle_position` to pick RAM_4/RAM_5 or RAM_7/RAM_8; RAM_6 and RAM_9 are always used.
- **`brown_out` and `new_data`:** write `brown_out` = 1 at start-up (reads 0 after any reset) and `new_data` = 0 after each readout; writing the whole `REG_STATUS` word preserves read-only bits.
- **Emissivity, Ha/Hb:** emissivity is not stored in the chip; `Ha` (gain) and `Hb` (offset) are customer calibration constants in the EEPROM; the driver reads them and applies them as in the formula.
- **Extended range and refresh-rate changes** alter the measurement table in the EEPROM/registers; EEPROM writes need the datasheet's unlock sequence (a halt-mode write with the customer-access unlock command) and the datasheet allows only a limited number of write cycles — they are opt-in in the driver. The measurement-type switch uses the documented routine: addressed reset (`0x30 0x05 0x00 0x06` = write `0x0006` to `0x3005`), wait 150 µs, read `REG_CONTROL`, set `mode` = 00 and `meas_select`, read it again, set the final mode.
- **Global reset:** the general-call reset (`0x06` to address `0x00`) resets every device on the bus; the driver offers only the addressed reset.
- **Sleeping-step mode:** needs fast bus access around commands (tP ≤ 1.8 µs between the last SCL edges); hosts that cannot guarantee this should use step mode before issuing resets.
- **Accuracy:** the object temperature accuracy requires the whole FOV filled by the object and thermal equilibrium of the package (the ambient reading is the package temperature); avoid air flow and heat sources near the sensor.
- **Supply and logic level:** the chip is a 3.3 V part; the 1.8 V I²C variant needs a 1.8 V bus.
- **Address:** `0x3A` is used by few other chips; with `id_probe` null a discovery scan cannot confirm it — read the EEPROM product code.

## Sigrok Decoder

Decoder id `mlx90632`, input `['i2c']`. Matches I²C addresses `0x3A`/`0x3B` (and the general-call reset). Tracks 16-bit register addresses, annotates EEPROM, control, status and RAM accesses by name, decodes `REG_CONTROL`, `REG_STATUS`, the calibration constants (scaled) and RAM words, and when the calibration block has been seen in the capture computes the ambient and object temperature for each complete RAM set; warns on a `REG_CONTROL` write with `meas_select` values other than `0x00`/`0x11`, on EEPROM writes, on a communication within 150 µs after a reset and on a missing `new_data` clear. No conformance annotation pair is emitted (no checked timing constraint).
