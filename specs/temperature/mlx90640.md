# Chip Spec: MLX90640

**Manufacturer:** Melexis  
**Datasheet:** `datasheets/temperature/mlx90640.pdf` (MLX90640 32×24 IR array datasheet, 3901090640, Revision 13)  
**Category:** temperature  
**Transports:** I²C

## Overview

The MLX90640 is a factory-calibrated 32 × 24 (768 pixel) far-infrared thermal array in a 4-lead TO39 package, available with a 55° × 35° (BAA) or 110° × 75° (BAB) field of view. It measures target temperatures from −40 to +300 °C (noise equivalent temperature difference 0.1 K RMS at 1 Hz), with the ambient temperature `Ta` and the supply voltage measured on chip. The device stores raw pixel data in RAM, per-pixel and common calibration constants in EEPROM and exposes a status register and two control registers. A frame is made of two **subpages** (chess-pattern interleaved pixels, factory-calibrated in this mode) that are measured alternately, so a complete image needs both subpages; the refresh rate (0.5–64 Hz) is the rate per subpage. The host computes the temperatures itself from RAM and EEPROM data with the algorithm of datasheet section 11 (Melexis publishes a reference library). Supply 3.0–3.6 V (3.3 V ± 0.05 V recommended), 15–25 mA, I²C up to 1 MHz (EEPROM access at ≤ 400 kHz). Typical uses: presence detection and people localisation, thermal imaging, building air-conditioning and microwave ovens, industrial temperature monitoring.

## Transport Configuration

### I²C
- **Address:** `0x33` (7-bit default; programmable in the EEPROM cell `0x240F` (register `0x8010`), `0x00` must be avoided; up to 127 addresses)
- **Max clock:** 1 MHz (FM+); EEPROM operations at ≤ 400 kHz. SDA/SCL are 5 V tolerant; the SDA driver current limit is selectable in `0x800F` (maximum 10 mA)
- **Identity register:** none with a fixed value (the EEPROM words `0x2407`–`0x2409` carry a chip ID, device-unique); chip is registered in `registry/chips.json` with `id_probe: null`
- **Probe safety:** `register_pointer` — addressed reads are side-effect free; the only state-changing accesses are writes to the registers `0x8000`/`0x800D`–`0x8010` and the EEPROM
- **Register addressing:** **16-bit** register address, MSB first (`reg_bytes = 2`); all data are 16-bit big-endian words; reads auto-increment, so the 832-word RAM block can be read in chunks (a `RegisterConnection` with a limited read length needs the driver to split the frame into several reads)

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| SDA, SCL | — | I²C, external pull-ups, 5 V tolerant |
| VDD, VSS | — | 3.0–3.6 V (power-on reset at about 2.2–2.6 V rising) |

The device has no interrupt output; new data is signalled in the status register.

### Bit Fields

#### Status register (`0x8000`)

| Bits | Name | Description |
|------|------|-------------|
| 5 | start_of_measurement | Write 1 to start a measurement (step mode); self-clearing |
| 4 | en_overwrite | 1 = RAM may be overwritten while `data hold` is on |
| 3 | new_data | 1 = a new subpage is available in RAM; **must be cleared by the host** (write 0) |
| 2:0 | last_subpage | `000` subpage 0 last measured, `001` subpage 1 last measured (others reserved) |

A status word of `0xXXX8` after a subpage-0 read, `0xXXX9` for subpage 1 (new data set).

#### Control register 1 (`0x800D`, EEPROM copy `0x240C`, default `0x1901` after POR)

| Bits | Name | Description |
|------|------|-------------|
| 12 | reading_pattern | 0 = interleaved (TV) mode, 1 = chess pattern (default, factory calibration) |
| 11:10 | resolution | ADC resolution: `00` 16 bit, `01` 17, `10` 18 (default), `11` 19 bit |
| 9:7 | refresh_rate | `000` 0.5 Hz, `001` 1 Hz, `010` 2 Hz (default), `011` 4 Hz, `100` 8 Hz, `101` 16 Hz, `110` 32 Hz, `111` 64 Hz |
| 6:4 | select_subpage | `000` subpage 0, `001` subpage 1 (used when the subpage repeat bit is 1) |
| 3 | subpage_repeat | 0 = toggle between subpage 0 and 1 (default), 1 = measure only the selected subpage |
| 2 | data_hold | 0 = transfer data to RAM every frame (default), 1 = only if `en_overwrite` = 1 |
| 1 | — | reserved, keep 0 |
| 0 | subpages_mode | 1 = subpage mode active (default), 0 = a single page is measured |

(Priorities of the subpage controls: subpage mode off → subpage 0 only; mode on and repeat off → alternate 0/1; mode on and repeat on → the selected subpage only.)

#### I²C configuration register (`0x800F`)

SDA driver current limit and I²C threshold levels (datasheet Figure 13); the driver leaves the register at its default.

## Initialization Sequence

1. Power VDD (3.3 V); after POR wait **80 ms plus one refresh period** (e.g. 2 s at 0.5 Hz, 31 ms at 64 Hz) before the first valid data.
2. Read the **whole EEPROM** (`0x2400`–`0x273F`, 832 words) once and extract the calibration parameters (Implementation Notes).
3. Optionally write control register 1 (refresh rate, resolution, pattern) — do this before measurements, then wait at least one refresh period.
4. Loop per subpage: wait for `new_data`, read the status register (for `last_subpage`), read the RAM (`0x0400`–`0x073F`, 832 words), **clear `new_data`** (write the status register with bit 3 = 0), compute the temperatures of the subpage; combine two subpages into a frame.
5. For absolute accuracy leave the device running about 4 minutes after power-up (thermal equilibrium, see the measurement flow).

## Implementation Stages

### Minimal

Goal: read a complete thermal image with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Takes the `RegisterConnection` with 16-bit addresses; waits for the start-up time, reads the EEPROM and extracts the calibration parameters; leaves the chip at its EEPROM defaults (chess pattern, 2 Hz, 18 bit) |
| `read_frame` | — | `list[float]` (768 values, row-major, 24 rows × 32 columns, °C) | Waits for both subpages (clearing `new_data` after each), computes `To` for every pixel with emissivity 1.0 and the reflected temperature `Tr = Ta − 8 °C`, returns the frame; failed pixels (EEPROM word `0x0000`) are returned as NaN |
| `read_ambient` | — | float | `Ta` in °C (from the latest subpage data) |

**Sensible defaults:** chess pattern, 2 Hz per subpage (1 Hz frame rate), 18-bit ADC, emissivity 1.0.

## Data Conversion

The temperature calculation is the algorithm of datasheet section 11 (restoring the calibration data in 11.1 and the temperature calculation in 11.2) and is implemented in the Melexis reference library (`mlx90640-library`, `MLX90640_ExtractParameters` and `MLX90640_CalculateTo`); the formulas are not repeated verbatim here. The steps, in order, are:

```
# once after POR (section 11.1) - all EEPROM data are two's complement unless noted
#   kVdd, vdd25            from EE[0x2433]        (Vdd sensor parameters)
#   KvPTAT, KtPTAT, vPTAT25, alphaPTAT   from EE[0x2432], EE[0x2431], EE[0x2410]   (Ta sensor)
#   offset(i,j)  = Offset_average + OCC_row*2^scale_row + OCC_column*2^scale_col + offset_pixel*2^scale_rem
#   alpha(i,j)   from ACC row/column, Alpha scale, pixel word (0x2420.., pixel words 0x2440..)
#   Kv(i,j) (row/column parity, EE[0x2434]), Kta(i,j) (parity bytes EE[0x2436], EE[0x2437], pixel word, Kta scales EE[0x2438])
#   GAIN = EE[0x2430];  KsTa = EE[0x243C] >> 8 / 2^13;  TGC = EE[0x243C] & 0xFF / 2^5   (signed)
#   corner temperatures: CT3, CT4 from EE[0x243F] with step = 10 * ((EE[0x243F] & 0x3000) >> 12); CT1 = -40, CT2 = 0
#   KsTo1..4 from EE[0x243D], EE[0x243E] (scaled), sensitivity corrections alpha_corr_range1..4
#   compensation pixel alphaCP, offsetCP, KvCP, KtaCP for each subpage (EE[0x2439]..EE[0x243B])
#   resolution_control calibration value from EE[0x2438]
# per subpage (section 11.2.2)
#   resolution correction = 2^cal_resolution / 2^current_resolution
#   Vdd  = (res_corr * RAM[0x072A] - vdd25) / kVdd + 3.3
#   Ta   = ptat_art / (1 + KvPTAT*(Vdd - 3.3)) ... -> Ta in degC using Ta_Vbe (RAM[0x0700]), Ta_PTAT (RAM[0x0720])
#   gain = GAIN_ee / RAM[0x070A];   pixel_gain = RAM[pixel] * gain
#   ir   = pixel_gain - offset(i,j)*(1 + Kta(i,j)*(Ta-25))*(1 + Kv(i,j)*(Vdd-3.3))
#   ir   = ir / emissivity
#   compensation pixel: ir_cp (same gain/offset/Ta/Vdd steps), ir -= TGC * ir_cp   (gradient compensation)
#   alpha_comp = (alpha(i,j) - TGC*alphaCP) * (1 + KsTa*(Ta-25))
#   Tr4 = (Tr + 273.15)^4;  Ta_Tr = Tr4 - (Tr4 - Ta_K^4) / emissivity
#   Sx  = KsTo2 * (alpha_comp^3 * ir + alpha_comp^4 * Ta_Tr)^(1/4)
#   To  = (ir / (alpha_comp*(1 - KsTo2*273.15) + Sx) + Ta_Tr)^(1/4) - 273.15
#   extended ranges (To outside 0..CT3): pick the range from To and repeat with the range KsTo and alpha correction (section 11.2.2.9.1)
```

The step list reproduces the structure of section 11 and the reference library; the complete formulas and bit masks must be taken from the datasheet sections cited and checked against the worked example of section 11.2.1 (example input data: `Vbe` = `0x4BF2`, CP subpage 0 = −54, CP subpage 1 = −56, `GAIN` = 6273, `PTAT` = 1711, `VDDpix` = −13115, calibration for pixel (12, 16)), which the unit test must reproduce. The reading of this PDF's extracted text lost most mathematical symbols, so the lines above summarise the algorithm and are **not** a substitute for the datasheet formulas. Units: °C for all temperatures (Kelvin only inside the radiation terms).

## Timing Constraints

| Constraint | Value |
|------------|-------|
| First valid data after POR | 80 ms + one refresh period |
| Refresh period (per subpage) | 2 s, 1 s, 500 ms, 250 ms, 125 ms, 62.5 ms, 31.25 ms, 15.625 ms for 0.5 … 64 Hz |
| Full frame (both subpages) | two refresh periods; the Ta value updates at half the subpage rate |
| EEPROM write | erase (write `0x0000`) then write the value; ≥ 5 ms after each write; 10 erase/write cycles in total; EEPROM access at ≤ 400 kHz |
| Settling for absolute accuracy | about 4 minutes after power-up |
| I²C clock | up to 1 MHz |

None of these has a bus-decodable start/end annotation pair with a datasheet bound that a decoder can mark, so `mlx90640_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection, 16-bit addresses:** construct with `reg_bytes = 2` (see `specs/feature_register_access_design.md`); chunk the 832-word EEPROM and RAM reads to the bus/connection maximum (typically 32–128 bytes per transaction on Arduino-class hosts). The calibration parameters are extracted once in `init` and cached (per-pixel offset, α, Kta, Kv for 768 pixels), so the driver documents its RAM use; very memory-poor targets may not be able to hold them.
- **Algorithm source:** port `MLX90640_ExtractParameters`, `MLX90640_CalculateTo` and the bad-pixel/outlier handling of the Melexis library (see the references in the datasheet), and validate against the datasheet example data. The library is Apache-licensed; record the licence and source commit in the driver header.
- **Subpage handling:** both subpages must be read to obtain a full image; `Ta` needs both (its update rate is half the refresh rate). The driver clears `new_data` immediately after reading the RAM and before the next subpage completes; at 32/64 Hz the I²C transfer time (≈ 1.7 kB per subpage) limits the usable rate (at 400 kHz about 40 ms) — the driver documents the achievable rate per bus speed.
- **Chess vs. interleaved:** the factory calibration is for the chess pattern; changing to interleaved mode needs the interleaved offset correction (11.1.3.1) and degrades accuracy.
- **Failed pixels and outliers:** an EEPROM pixel word of `0x0000` marks a failed pixel (do not trust `To`); the LSB of the pixel words flags outliers/long-term deviating pixels; at most four deviating pixels, never adjacent. `correct_bad_pixels` replaces them by the mean of valid neighbours.
- **Reflected temperature:** the reference library uses `Tr = Ta − 8 °C` (TA_SHIFT); expose it as a parameter.
- **TGC:** the compensation-pixel gradient coefficient is 0 on the BAA devices and must not be changed; on BCA/BCB devices it may be adjusted but increases noise.
- **EEPROM writes** are limited (10 cycles); the driver only writes the address or refresh-rate defaults on explicit opt-in. Writing the control register in RAM is unlimited.
- **Supply:** keep VDD at 3.3 V ± 0.05 V for best accuracy; the device is a 15–25 mA load; 5 V-tolerant I²C pins allow a 5 V bus.
- **Address:** `0x33` is also used by some other chips; no ID register exists, so use the EEPROM and a plausible temperature read as presence check.

## Sigrok Decoder

Decoder id `mlx90640`, input `['i2c']`. Matches the I²C address `0x33` (and any address configured via the decoder option). Tracks 16-bit register addresses, annotates the memory regions (RAM pixels, auxiliary RAM words with their names, EEPROM calibration words, status and control registers), decodes the status register (`new_data`, `last_subpage`) and control register 1 (pattern, resolution, refresh rate, subpage controls), and prints the raw pixel values with their pixel index; warns on a RAM read without a preceding `new_data`, on a subpage read that is not followed by a `new_data` clear, on EEPROM writes without a preceding erase and on writes to reserved registers. No conformance annotation pair is emitted (no checked timing constraint).
