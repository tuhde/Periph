# Chip Spec: MCP9808

**Manufacturer:** Microchip Technology
**Datasheet:** `datasheets/temperature/mcp9808.pdf`
**Category:** temperature
**Transports:** I²C

## Overview

The MCP9808 is a high-accuracy digital temperature sensor (±0.5°C max, -20°C to +100°C;
±1°C max over the full -40°C to +125°C range) built around a band-gap sensor and a
delta-sigma ADC, exposed over a 400 kHz I²C/SMBus-compatible interface. Measurement
resolution is user-selectable from 0.5°C down to 0.0625°C (trading off conversion time,
30 ms to 250 ms). Three programmable 0.25°C-resolution temperature boundaries (`TUPPER`,
`TLOWER`, `TCRIT`) drive an open-drain `Alert` output, configurable as either a
thermostat-style comparator or a latching interrupt, with selectable polarity and
programmable hysteresis (0°C to 6°C) to avoid chatter near a boundary. Up to eight devices
can share one I²C bus via three address-strap pins (`A0`, `A1`, `A2`).

## Transport Configuration

### I²C
- **Address:** `0x18`–`0x1F`, selected by strapping `A0`/`A1`/`A2` each to `VDD` (`1`) or
  `GND` (`0`) — 8 combinations, sampled once at power-up
- **Max clock:** 400 kHz

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| Alert | configurable (active-low POR default), open-drain | requires an external pull-up; asserted per the boundary/mode configuration in `CONFIG` — see Interrupt section |

`A0`/`A1`/`A2` are board-level address straps, not runtime-controllable pins.

## Register Map

Registers are accessed through an 8-bit write-only Register Pointer: write the pointer
value, then read or write the addressed register's data bytes. Unlike this repository's
auto-incrementing RTC chips, the pointer does **not** advance to the next register after a
transaction — repeated access to the *same* register never needs the pointer re-sent, but
switching to a different register always does.

| Pointer | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | *(reserved)* | R | — | Reserved for future use — do not access |
| `0x01` | CONFIG | R/W | `0x0000` | Hysteresis, shutdown, lock, and Alert output configuration |
| `0x02` | TUPPER | R/W | `0x0000` | Alert temperature upper boundary, 0.25°C resolution |
| `0x03` | TLOWER | R/W | `0x0000` | Alert temperature lower boundary, 0.25°C resolution |
| `0x04` | TCRIT | R/W | `0x0000` | Critical temperature boundary, 0.25°C resolution |
| `0x05` | TA | R | `0x0000` | Ambient temperature, 0.0625°C resolution, plus 3 boundary-status flag bits |
| `0x06` | MANUFACTURER_ID | R | `0x0054` | Fixed manufacturer ID |
| `0x07` | DEVICE_ID_REV | R | `0x0400` | Bits 15:8 device ID (`0x04`), bits 7:0 silicon revision |
| `0x08` | RESOLUTION | R/W | `0x03` | Bits 1:0 select measurement resolution / conversion time |

### Bit Fields

#### `CONFIG` (`0x01`)

| Bits | Name | Description |
|------|------|--------------|
| 15:11 | — | Unimplemented, read `0` |
| 10:9 | THYST[1:0] | Hysteresis applied to `TUPPER`/`TLOWER`/`TCRIT` on the *falling* (cooling) edge only: `00`=0°C (default), `01`=+1.5°C, `10`=+3.0°C, `11`=+6.0°C. Cannot be changed while either lock bit is set |
| 8 | SHDN | `0`=continuous conversion (default), `1`=Shutdown (low-power; ADC and sampling stop, `TA` holds its last value, serial interface stays active). Cannot be set while either lock bit is set, but can always be cleared |
| 7 | CRIT_LOCK | `TCRIT` lock: `0`=unlocked (default), `1`=locked — `TCRIT` becomes read-only until the next power-on reset. **One-way**: cannot be cleared except by POR |
| 6 | WIN_LOCK | `TUPPER`/`TLOWER` lock: `0`=unlocked (default), `1`=locked — both become read-only until the next power-on reset. **One-way**: cannot be cleared except by POR |
| 5 | INT_CLEAR | Write `1` to clear an asserted interrupt-mode Alert output; always reads back `0` |
| 4 | ALERT_STAT | **Read-only.** `0`=Alert output not asserted (default), `1`=asserted |
| 3 | ALERT_CNT | Alert output enable: `0`=disabled (default), `1`=enabled |
| 2 | ALERT_SEL | `0`=Alert driven by `TUPPER`/`TLOWER`/`TCRIT` (default), `1`=Alert driven by `TCRIT` only. Cannot be changed while `WIN_LOCK` is set |
| 1 | ALERT_POL | `0`=active-low, requires pull-up (default), `1`=active-high |
| 0 | ALERT_MOD | `0`=comparator output (default), `1`=interrupt output |

Setting `CRIT_LOCK` or `WIN_LOCK` also freezes `ALERT_SEL`/`ALERT_POL`/`ALERT_MOD` (all
three become unwritable until POR, per the datasheet's per-bit lock notes), not just the
limit register(s) named in the lock bit itself.

While `TA` ≥ `TCRIT`, the Alert output is unconditionally forced into comparator behavior
regardless of `ALERT_MOD`, and only returns to the configured mode once `TA` drops below
`TCRIT - THYST`.

#### `TUPPER` / `TLOWER` / `TCRIT` (`0x02` / `0x03` / `0x04`)

| Bits | Name | Description |
|------|------|--------------|
| 15:13 | — | Unimplemented, read `0` |
| 12 | SIGN | `0`=boundary ≥ 0°C, `1`=boundary < 0°C |
| 11:2 | value | Boundary temperature, two's-complement, 0.25°C per LSB (10-bit magnitude+sign field) |
| 1:0 | — | Unimplemented, read `0` — boundaries are always a multiple of 0.25°C |

#### `TA` (`0x05`, read-only)

| Bits | Name | Description |
|------|------|--------------|
| 15 | `TA` vs `TCRIT` | `1` if `TA` ≥ `TCRIT` |
| 14 | `TA` vs `TUPPER` | `1` if `TA` > `TUPPER` |
| 13 | `TA` vs `TLOWER` | `1` if `TA` < `TLOWER` |
| 12 | SIGN | `0`=`TA` ≥ 0°C, `1`=`TA` < 0°C |
| 11:0 | value | Ambient temperature, two's-complement, 0.0625°C per LSB. Bits 2:0 read `0` unless `RESOLUTION` selects a finer step than they represent |

Bits 15:13 reflect live comparator state and are **always computed**, independent of
`CONFIG`'s Alert enable/select bits (per the datasheet's own note) — they are this driver's
basis for `poll_interrupt()`.

#### `RESOLUTION` (`0x08`)

| Bits | Name | Description |
|------|------|--------------|
| 7:2 | — | Unimplemented, read `0` |
| 1:0 | Resolution | `00`=0.5°C (t_CONV 30 ms typ.); `01`=0.25°C (65 ms); `10`=0.125°C (130 ms); `11`=0.0625°C (250 ms, POR default) |

## Initialization Sequence

1. Construct the driver with a `Connection` at whichever address (`0x18`–`0x1F`) matches
   the board's `A0`/`A1`/`A2` strapping.
2. Read `MANUFACTURER_ID` (`0x06`) and confirm it equals `0x0054`; read `DEVICE_ID_REV`
   (`0x07`) and confirm the upper byte equals `0x04` (ignoring the revision byte) — this is
   a genuine identity check, unlike this repository's other pointer-addressed chips that
   have no such register.
3. No further register writes are required at `init` time: the POR default (continuous
   conversion, 0.0625°C resolution, Alert output disabled) is already the primary use case.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `Alert`, open-drain, polarity/mode configurable (`ALERT_POL`/`ALERT_MOD`) — requires an external pull-up |
| Level | 2 (selectable sources, coarser than a per-source enable bit — see Implementation Notes) |
| Condition(s) | `TA` ≥ `TCRIT`; `TA` > `TUPPER`; `TA` < `TLOWER` |
| Clear mechanism | Comparator mode clears itself once `TA` recrosses the boundary (minus hysteresis); Interrupt mode requires `clear_interrupt()` (`INT_CLEAR`=1) |

### Interrupt sources

| Constant | Value | Condition |
|----------|-------|-----------|
| `SOURCE_LOWER` | `0x01` | `TA` < `TLOWER` |
| `SOURCE_UPPER` | `0x02` | `TA` > `TUPPER` |
| `SOURCE_CRITICAL` | `0x04` | `TA` ≥ `TCRIT` |

These three bits are read directly from `TA`'s top three bits (see Bit Fields above) and
reflect live hardware comparator state regardless of whether the Alert output itself is
enabled or which mode it is routed through.

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|--------------|
| `on_interrupt` | `on_interrupt(callback)` | Subscribe; callback receives the status int (mask with `SOURCE_LOWER`/`SOURCE_UPPER`/`SOURCE_CRITICAL`) |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Reads `TA` and returns its top 3 bits as a status mask; does not clear anything (there is nothing latched to clear at this level — see `clear_interrupt`) |
| `clear_interrupt` | `clear_interrupt()` | Writes `INT_CLEAR`=1 in `CONFIG`. Only has an effect in Interrupt output mode (`ALERT_MOD`=1); a no-op otherwise |
| `configure_alert` | `configure_alert(mode="all"\|"critical_only", output="comparator"\|"interrupt", polarity="active_low"\|"active_high")` | Sets `ALERT_SEL`/`ALERT_MOD`/`ALERT_POL` together. Raises/fails if either lock bit is set (see Implementation Notes) |
| `enable_alert` | `enable_alert()` | Sets `ALERT_CNT`=1 |
| `disable_alert` | `disable_alert()` | Clears `ALERT_CNT`=0 |
| `is_alert_asserted` | `is_alert_asserted() -> bool` | Reads `ALERT_STAT` (read-only) |

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits
everything and adds the rest.

### Minimal

Goal: read ambient temperature accurately, with no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Confirms `MANUFACTURER_ID`==`0x0054` and the `DEVICE_ID_REV` upper byte==`0x04`; makes no register writes |
| `read_temperature` | — | float °C | Reads `TA`, masks off the 3 status bits, decodes the two's-complement 0.0625°C value (see Data Conversion) |

**Sensible defaults:** no register writes at `init` — the POR default (continuous
conversion at the finest 0.0625°C/250 ms resolution, Alert output disabled) already serves
the primary use case; `Full` exposes resolution trade-offs, Shutdown mode, boundary
limits, and the Alert output.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `set_resolution` | celsius (one of 0.5, 0.25, 0.125, 0.0625) | — | Writes `RESOLUTION`; trades measurement noise against conversion time (30–250 ms, see Timing Constraints) |
| `get_resolution` | — | float °C | Reads `RESOLUTION` and decodes it |
| `shutdown` | — | — | Sets `SHDN`=1 (Shutdown/low-power mode). No-op if either lock bit is set to *set* (clearing always works) |
| `wake` | — | — | Clears `SHDN`=0, resuming continuous conversion |
| `is_shutdown` | — | bool | Reads `SHDN` |
| `get_upper_limit` / `set_upper_limit` | — / celsius | float °C / — | Reads/writes `TUPPER` (see Data Conversion for the 0.25°C quantization) |
| `get_lower_limit` / `set_lower_limit` | — / celsius | float °C / — | Reads/writes `TLOWER` |
| `get_critical_limit` / `set_critical_limit` | — / celsius | float °C / — | Reads/writes `TCRIT` |
| `set_hysteresis` | celsius (one of 0, 1.5, 3.0, 6.0) | — | Writes `THYST[1:0]`; applies only to the cooling-direction (falling) edge of each boundary |
| `get_hysteresis` | — | float °C | Reads `THYST[1:0]` |
| `lock_critical_limit` | — | — | Sets `CRIT_LOCK`=1. **Irreversible except by power-on reset** |
| `lock_window_limits` | — | — | Sets `WIN_LOCK`=1. **Irreversible except by power-on reset** |
| `is_critical_limit_locked` / `is_window_limits_locked` | — | bool | Read back the two lock bits |
| *(interrupt/Alert API)* | | | See Interrupt section above |

**Additional configuration options:** measurement resolution, Shutdown mode, all three
temperature boundaries, hysteresis, the two one-way register locks, and full Alert output
configuration (source selection, comparator/interrupt mode, polarity, enable).

## Data Conversion

```
# TA (0x05): bits 15:13 are the boundary-status flags (always live, independent of
# CONFIG); bits 12:0 are the signed temperature, two's-complement, 1/16 degC per LSB.
raw = ta_register & 0x1FFF
temperature_c = (raw - 0x2000) / 16.0 if raw & 0x1000 else raw / 16.0
status_bits   = (ta_register >> 13) & 0x07   # SOURCE_CRITICAL<<2 | SOURCE_UPPER<<1 | SOURCE_LOWER

# TUPPER / TLOWER / TCRIT (0x02 / 0x03 / 0x04): bit 12 = SIGN, bits 11:2 = magnitude,
# two's-complement, 0.25 degC per LSB; bits 1:0 unimplemented (always 0).
raw_limit = (limit_register >> 2) & 0x3FF
limit_c   = (raw_limit - 1024) / 4.0 if limit_register & 0x1000 else raw_limit / 4.0
# Encoding a limit rounds the requested Celsius value to the nearest 0.25 degC step.
```

### Demo flow

An Inject node fires every 5 s, triggering the `periph-mcp9808` node to read and log
temperature and Alert status. The node is configured with `TCRIT` set to a freezer
door's "too warm" threshold and `ALERT_SEL`="critical_only", `output`="interrupt"; when it
fires, the node emits `{ source: "critical" }`, which a Function node turns into an
alarm notification and calls `clear_interrupt()` to re-arm.

## Examples

### Demo

An industrial freezer temperature monitor. On startup, the demo sets a comfortable
`0.25°C` resolution (fast enough sampling, low enough noise), configures `TLOWER`=`-25°C`
and `TUPPER`=`-15°C` (the healthy freezer range) with `TCRIT`=`-5°C` (door left open too
long) and a `3.0°C` hysteresis to avoid chatter, then calls `configure_alert(mode="all",
output="interrupt", polarity="active_low")` and `enable_alert()`. It subscribes with
`on_interrupt`; the callback masks the returned status against `SOURCE_LOWER`/
`SOURCE_UPPER`/`SOURCE_CRITICAL` and prints which boundary tripped alongside
`read_temperature()`, calling `clear_interrupt()` each time to re-arm. Before exiting after
a fixed number of alerts, it calls `disable_alert()` and `off_interrupt()`.

## Timing Constraints

- **Register access cycle (`register_access`):** a single register read or write
  (`START`, address, pointer byte, data, `STOP`) at 400 kHz takes approximately 100–150 µs
  — the only host-observable, conformance-checkable timing this chip has.
- Temperature conversion time (`t_CONV`), typical: 30 ms at 0.5°C resolution, 65 ms at
  0.25°C, 130 ms at 0.125°C, 250 ms at 0.0625°C (POR default). Conversion runs
  continuously and autonomously in the background — there is no host-triggered
  "start conversion" bit or busy flag to poll, so this bounds how quickly a resolution
  change or a wake from Shutdown produces a fresh reading, but is not itself
  bus-observable as a start/end pair.
- Bus time-out (`t_OUT`), 25–35 ms typical: if `SCL` is held low or high longer than this,
  the MCP9808 resets its serial interface and a repeated `START` is required to resume
  communication — a fault-recovery behavior, not something the driver triggers
  intentionally.
- I²C bus AC timing: up to 400 kHz — covered by `specs/transport_i2c.md`.

## Implementation Notes

- **This is the first `temperature`-category chip.** `nodejs/packages/node-red-contrib-periph-temperature/`
  does not yet exist and must be created (with its own `package.json`, mirroring another
  category's Node-RED package) before the Node-RED Implementation Checklist items below can
  be completed; see the repo's "New category" guidance for what else that entails (e.g. a
  lockfile regen at the npm workspace root).
- The Register Pointer does **not** auto-increment to the next logical register the way
  this repository's RTC chips' address pointers do — each pointer write only ever selects
  one register for subsequent transactions; repeated reads of the *same* register can skip
  re-sending the pointer, but switching registers always requires it.
- `CRIT_LOCK` and `WIN_LOCK` are one-way: once set, the corresponding limit register(s) —
  and the `ALERT_SEL`/`ALERT_POL`/`ALERT_MOD` bits — become unwritable until the next
  power-on reset. `lock_critical_limit()`/`lock_window_limits()` are provided for
  completeness but callers should treat them as effectively permanent for the life of the
  power cycle.
- `Alert`'s interrupt-vs-comparator distinction only matters while `TA` stays within
  `TCRIT - THYST`: once `TA` reaches `TCRIT`, the output is forced into comparator
  behavior regardless of `ALERT_MOD`, so a `TCRIT` breach is never something the host can
  fail to observe by not calling `clear_interrupt()` in time.
- `THYST` only affects the falling (cooling) edge — there is no equivalent hysteresis
  band on the rising edge into `TUPPER`/`TCRIT`.
- `poll_interrupt()` reads `TA`'s three status bits directly rather than a dedicated
  status register — unlike this repository's other interrupt-capable chips, there is
  nothing to "clear" at that level (the bits are a live comparison, always current); only
  the Alert *output's* latched interrupt-mode assertion needs `clear_interrupt()`.
- The MCP9808 has a real Manufacturer ID (`0x0054`) and Device ID (`0x04`) register pair —
  unlike this repository's other pointer-addressed I²C chips (DS3231, PCF8523), `init()`
  performs a genuine identity check rather than a bare presence read.
- `TA` bits 2:0 may read `0` even at finer resolutions than 0.0625°C would suggest,
  depending on the current `RESOLUTION` setting — the register always reports 13
  significant bits, but the low bits are only meaningful once `RESOLUTION` selects a step
  size that resolves them.

## Sigrok Decoder

Decoder `mcp9808` (`sigrok/mcp9808/`) stacks on the `i2c` decoder and recognizes any
address in the `0x18`–`0x1F` range (the 8 valid `A0`/`A1`/`A2` strap combinations),
tracking the last-written Register Pointer value across transactions (since it is not
auto-incrementing).

| Row | Annotation | Meaning |
|-----|------------|---------|
| Data | `data` | `TUPPER`/`TLOWER`/`TCRIT`/`TA` reads/writes decoded to °C per Data Conversion; `RESOLUTION` decoded to its °C step |
| Status | `status` | `CONFIG` reads/writes decoded to its named bit fields; `TA`'s top 3 status bits decoded as boundary flags |
| Timing | `timing` | `register_access_start`/`register_access_done` marker pair bounding any register read or write transaction |
| Warnings | `warning` | A write to pointer `0x00` (reserved) or `0x09`+ (undefined); a write attempting to alter a locked register or a locked `CONFIG` bit |
