# Chip Spec: MAX31341

**Manufacturer:** Maxim Integrated (Analog Devices)  
**Datasheet:** `datasheets/rtc/max31341.pdf` (MAX31341B/MAX31341C Low-Current, Real-Time Clock with I²C Interface and Power Management, 19-100537; Rev 4; 3/20)  
**Category:** rtc  
**Transports:** I²C

## Overview

The MAX31341B (12-bump WLP) and MAX31341C (10-pin TDFN) are low-current BCD real-time clocks with 180 nA timekeeping current, an integrated load capacitance for 6 pF high-ESR 32.768 kHz crystals, two time-of-day alarms (alarm 1 with seconds, alarm 2 without), an 8-bit countdown timer (1024/256/64/16 Hz, repeat and pause), a 64-byte battery-backed RAM, a Schmitt-trigger digital input (`D1`) and a programmable-threshold analog input (`AIN`, 1.3/1.7/2.0/2.2 V) usable as comparator or as the backup-battery input of the power-management mode with trickle charger (3/6/11 kΩ, with one or two diodes) for a super-capacitor or rechargeable cell. A programmable square-wave output (1 Hz, 4.096 kHz, 8.192 kHz, 32.768 kHz), a synchronisation input (`CLKIN`: 1 Hz, 50 Hz, 60 Hz or 32.768 kHz reference, e.g. GPS 1PPS), a data-retention mode (5 nA) and an I²C bus timeout complete the part. Calendar data is 24-hour only, with automatic leap-year correction and a century bit. Supply 1.6–3.6 V, I²C up to 400 kHz. Both variants share the same register map; the package is the only difference. Typical uses: wearables, medical devices, point-of-sale, telematics, portable instruments.

## Transport Configuration

### I²C
- **Address:** `0x69` (7-bit; the datasheet gives the 8-bit address as `0xD2`, left-justified with the R/W bit 0); fixed
- **Max clock:** 400 kHz; minimum clock 10 kHz because of the bus timeout (an SCL held low for 25–35 ms resets the interface)
- **Identity register:** `0x59` (`RevID_reg`), upper nibble `REVID[3:0]` = `0x1` (reset value `0x10`); the probe reads 1 byte with mask `0xF0` and expects `0x10`. Registered in `registry/chips.json`
- **Probe safety:** `register_pointer` — plain register-addressed reads; reading `Int_status_reg` (`0x05`) clears the flags, which a probe does not touch
- **Register addressing:** 8-bit register address, auto-increment, wraps from the last register (`0x59`) to `0x00`; burst read/write supported. The interface is guaranteed for VCC between 1.6 V and 3.6 V (do not access it below 1.6 V)

#### `Config_reg1` (`0x00`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | ECLK | 1 = enable the external clock input (`CLKIN`) |
| 6 | INTCN | 0 = `INTB/CLKOUT` outputs a square wave, 1 = interrupt output |

| 3 | OSCONZ | 0 = oscillator on, 1 = oscillator off (reset: 1) |
| 2:1 | RS | Square-wave frequency: `00` 1 Hz, `01` 4.096 kHz, `10` 8.192 kHz, `11` 32.768 kHz (reset `11`) |
| 0 | SWRSTN | 0 = digital block held in reset (reset value!), 1 = normal operation |

| Bits | Name | Description |
|------|------|-------------|
| 6 | DATA_RETEN | 1 = data-retention mode (see Implementation Notes) |

| 3 | I2C_TIMEOUT_EN | 1 = I²C bus timeout enabled (reset 1) |

| Bits | Name | Description |

| 6 | AIP | 0 = analog interrupt on falling edge of `AIN`, 1 = rising edge |

#### Alarm registers (`0x0D`–`0x13`)

Bit 7 of each alarm register is the mask bit (`A1M1`–`A1M4`, `A2M2`–`A2M4`); `DY_DT` (bit 6 of the day/date registers) selects date (0) or day-of-week (1) match.

| `DY_DT` | M4 | M3 | M2 | M1 | Alarm 1 rate |
|---------|----|----|----|----|--------------|
| x | 1 | 1 | 1 | 1 | once per second |
| x | 1 | 1 | 1 | 0 | seconds match |
| x | 1 | 1 | 0 | 0 | minutes and seconds match |
| x | 1 | 0 | 0 | 0 | hours, minutes and seconds match |
| 0 | 0 | 0 | 0 | 0 | date and time match |
| 1 | 0 | 0 | 0 | 0 | day and time match |

Alarm 2 has no seconds register; its rate table (datasheet Table 5) uses `A2M4`–`A2M2` the same way.

#### `Pwr_mgmt_reg` (`0x56`)

| Bits | Name | Description |
|------|------|-------------|
| 3 | D_VBACK_SEL | With `D_MAN_SEL` = 1: 0 = supply from `VCC`, 1 = supply from `AIN` (backup) |
| 2 | D_MAN_SEL | 0 = automatic supply selection, 1 = manual via `D_VBACK_SEL` |
| 1:0 | D_MODE | `00` comparator mode, `01` power-management/trickle-charger mode, `10`/`11` reserved |

#### `Trickle_reg` (`0x57`, `D_TRICKLE[3:0]`)

`0x8` 3 kΩ + Schottky, `0xA` 6 kΩ + Schottky, `0xB` 11 kΩ + Schottky, `0xC` 3 kΩ + diode + Schottky, `0xE` 6 kΩ + diode + Schottky, `0xF` 11 kΩ + diode + Schottky; every other value = no connection (charger off).

#### `Clock_sync_reg` (`0x58`)

`SYNC_DELAY[1:0]`: `00` external 1 Hz clock (delay < 1 s), `01` external 50/60 Hz/32 kHz clock (< 100 ms), `10` internal oscillator (< 10 ms, reset), `11` reserved.

## Initialization Sequence

1. Power VCC (1.6–3.6 V); `SWRSTN` is 0 and `OSCONZ` is 1 after reset (digital block in reset, oscillator off).
2. Write `Config_reg1` with `SWRSTN` = 1 and `OSCONZ` = 0 (oscillator on); startup is usually < 1 s, plus 4 s until the chip reaches stable low-current operation.
3. Write the time registers `0x06`–`0x0C` (BCD, 24-hour, in one burst).
4. Write `Config_reg2` with `Set_RTC` = 1 (0 → 1), wait 10 ms, write `Set_RTC` = 0. The next clock update occurs one second later (synchronisation delay < 10 ms with the default `Clock_sync_reg` = `0x02`).
5. Optionally configure alarms, timer, output and power management; read `Int_status_reg` to clear stale flags (`OSF` = 1 after the first power-up).

## Implementation Stages

### Minimal

Goal: read and set the clock; no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Takes the `RegisterConnection`; reads `RevID_reg` as a presence check (upper nibble `0x1`); if the digital block is in reset or the oscillator is off (`Config_reg1` bit `SWRSTN` = 0 or `OSCONZ` = 1) it writes `SWRSTN` = 1, `OSCONZ` = 0 (preserving the other bits); keeps `Rd_RTC` = 1 |
| `get_datetime` | — | `(year, month, day, weekday, hour, minute, second)` | One burst read `0x06`–`0x0C`; `year` 2000–2199 (the century bit adds 100 years: 0 = 20xx, 1 = 21xx), `weekday` 1–7 (1 = Monday) |

**Sensible defaults:** 24-hour format (the only mode), internal oscillator, `Clock_sync_reg` `0x02`, square wave at the reset default (32.768 kHz on `INTB/CLKOUT`), alarms and timer off, trickle charger off.

## Data Conversion

```
bcd_to_int(b)  = (b >> 4) * 10 + (b & 0x0F)
int_to_bcd(v)  = ((v // 10) << 4) | (v % 10)

second = bcd_to_int(Seconds & 0x7F)
hour   = bcd_to_int(Hours & 0x3F)                  # 24-hour only
weekday = Day & 0x07                               # 1..7, user defined (driver: 1 = Monday)
month  = bcd_to_int(Month & 0x1F);  century = Month >> 7
year   = 2000 + bcd_to_int(Year)  (+ 100 if century == 1)
timer_period_s = count / {1024, 256, 64, 16}[TFS]  # time to zero
```

## Timing Constraints

| Constraint | Value |
|------------|-------|
| I²C clock | 10–400 kHz (tLOW ≥ 1.3 µs, tHIGH ≥ 0.6 µs) |
| I²C bus timeout | an SCL held low 25–35 ms resets the interface |
| Oscillator start-up | usually < 1 s, plus 4 s to stable low-current operation |
| `Set_RTC` pulse | hold `Set_RTC` = 1 for ≥ 10 ms; the new time runs one second later (sync delay < 10 ms, < 100 ms with an external 50/60 Hz/32 kHz clock, < 1 s with an external 1 Hz clock) |
| Time registers after an interrupt | updated 2 ms after the interrupt asserts |

The `Set_RTC` hold time is a host wait without a bus-decodable bound the decoder can mark as a start/end pair on its own, so `max31341_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection:** accept `RegisterConnection` and call `connection.read(reg, length)` / `connection.write(reg, data)` directly. See `specs/feature_register_access_design.md`.
- **Reset state:** the chip comes up with `SWRSTN` = 0 (digital block in reset) and the oscillator off, so nothing works until `Config_reg1` is written; `Minimal.init()` therefore writes `SWRSTN` = 1 and `OSCONZ` = 0 when needed but never *clears* an already running clock (no software reset on init).
- **Setting the time:** writing `0x06`–`0x0C` only fills the holding registers; the countdown chain loads them on the 0 → 1 transition of `Set_RTC`, and the new time starts running one second later. `set_datetime` holds `Set_RTC` = 1 for 10 ms (per the datasheet startup procedure) and clears it again.
- **Reading the time:** keep `Rd_RTC` = 1 (the reset value); with 0 the registers show the last programmed value, not the running clock.
- **`Int_status_reg` clears on read:** a read clears all flags, so `oscillator_stopped`, `alarm_flag` and `poll_interrupt` share one read; the Full driver caches the last status byte and returns individual flags from it. The `OSF` flag is only meaningful with `DOSF` = 0.
- **BCD / 24 h / day:** all calendar fields are BCD; the chip supports 24-hour mode only; `Hours` bit 6 must be 0; `Day` is a free-running 1–7 counter with user-defined meaning — the driver uses 1 = Monday, as the DS3231 driver does.
- **Alarm 2** has no seconds register; the driver ignores `second` for it and raises on a non-`None` value. Alarm configurations not in the rate table give illogical operation, so `set_alarm` only accepts the documented combinations.
- **Countdown timer:** `TPAUSE` is valid only while `TE` = 1 and must be 0 before `TE` is set; `Timer_Init` may be programmed only while `TE` = 0. In repeat mode the first timer interrupt marks the start of counting.
- **Power management:** `D_MODE` = 01 puts `AIN` on the backup battery with automatic switch-over; the analog flag then serves as the power-fail flag. The trickle charger shares the same mode; the maximum charging current is (VCC − VD − VBAT)/R. Comparator mode (`D_MODE` = 00) uses `AIN` as a generic threshold input.
- **Data retention:** enter with `DATA_RETEN` = 1 then `OSCONZ` = 1; exit with `DATA_RETEN` = 0 then `OSCONZ` = 0. The chip draws 5 nA, keeps RAM, registers and last time; the clock stops counting.
- **RAM map quirk:** the datasheet table swaps the labels of `0x50`/`0x51` (Ram_Reg 59/58); this has no effect for a contiguous RAM block.
- **Bus timeout:** the interface resets if SCL stays low for 25–35 ms, so the host clock must stay above 10 kHz; disable with `I2C_TIMEOUT_EN` = 0 only for slow bit-banged buses.
- **Address:** the chip uses `0x69`, which other chips (e.g. ITG-3200, L3G4200D with SA0 high) also use; use `RevID_reg` to confirm.

## Sigrok Decoder

Decoder id `max31341`, input `['i2c']`. Matches I²C address `0x69`, tracks the register pointer (auto-increment, wrap `0x59` → `0x00`) and annotates register accesses by name. Decodes the BCD time/date, alarm registers with their mask bits and match rates, `Config_reg1`/`Config_reg2` fields, interrupt enable/status flags, the timer registers, `Pwr_mgmt_reg`, `Trickle_reg`, `Clock_sync_reg`, `RevID_reg` and the RAM range; warns on a time write without a following `Set_RTC` 0 → 1 pulse, on `Hours` bit 6 set, on `TPAUSE` with `TE` = 0, on reserved `D_MODE`/`SYNC_DELAY` values and on an SCL clock below 10 kHz. No conformance annotation pair is emitted (no checked timing constraint).
