# Chip Spec: DS1307

**Manufacturer:** Maxim Integrated  
**Datasheet:** `datasheets/rtc/ds1307.pdf` (DS1307 64 x 8, Serial, I²C Real-Time Clock, REV 3/15)  
**Category:** rtc  
**Transports:** I²C

## Overview

The DS1307 is a low-power BCD real-time clock/calendar with 56 bytes of battery-backed general-purpose SRAM and a programmable square-wave output (1 Hz, 4.096 kHz, 8.192 kHz, 32.768 kHz). It keeps seconds, minutes, hours (12 or 24 hour mode), day of week, date, month and year (leap-year compensation valid up to 2100) from an external 32.768 kHz crystal, switches automatically to a 3 V backup cell on power failure (under 500 nA in backup mode with the oscillator running; more than 10 years from a 48 mAh cell) and talks I²C in standard mode (100 kHz). It runs from 5 V (4.5–5.5 V), so on 3.3 V hosts the I²C pull-ups must go to 3.3 V (the pins tolerate pull-ups up to 5.5 V independent of VCC). It has no alarms, no interrupt output and no temperature compensation (accuracy is set by the crystal). Typical uses: data loggers, clocks, time stamping on Arduino-class boards.

## Transport Configuration

### I²C
- **Address:** `0x68` (7-bit `1101000`, fixed; one device per bus)
- **Max clock:** 100 kHz (standard mode only)
- **Identity register:** none; chip has no ID register (feeds `registry/chips.json` with `id_probe: null`). Shares address `0x68` with other RTCs (DS3231, PCF8523) — only one of them can be on a bus
- **Probe safety:** `register_pointer` — an address-pointer write plus read has no side effect; the register pointer is the only state changed
- **Register addressing:** 8-bit register pointer, auto-increment, wraps from `0x3F` to `0x00`; a read without a pointer write continues from the last pointer. A repeated START is supported for the usual write-pointer/read sequence

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| SQW/OUT | — | open-drain square-wave / logic output (needs an external pull-up; pull-up up to 5.5 V); works on VCC or VBAT; leave floating if unused |
| X1, X2 | — | 32.768 kHz crystal, 12.5 pF load capacitance (X1 can take an external 32.768 kHz oscillator, then leave X2 floating) |
| VBAT | — | 3 V lithium backup cell (2.0–3.5 V); ground it if no backup is used; no series diode |
| VCC | — | 4.5–5.5 V main supply; access is inhibited below 1.25 × VBAT |
| SCL, SDA | — | I²C, open-drain, external pull-ups |

## Register Map

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | SECONDS | R/W | `0x80` (typ.) | BCD seconds 00–59; bit 7 = `CH` (clock halt) |
| `0x01` | MINUTES | R/W | — | BCD minutes 00–59 |
| `0x02` | HOURS | R/W | — | BCD hours; bit 6 = 12/24 mode, bit 5 = AM/PM or 20 h |
| `0x03` | DAY | R/W | — | Day of week 01–07 (user defined, sequential) |
| `0x04` | DATE | R/W | — | BCD date 01–31 |
| `0x05` | MONTH | R/W | — | BCD month 01–12 |
| `0x06` | YEAR | R/W | — | BCD year 00–99 |
| `0x07` | CONTROL | R/W | `0x03` (typ.) | Square-wave / output control |
| `0x08`–`0x3F` | RAM | R/W | — | 56 bytes battery-backed SRAM |

On first power-up the time registers are typically `01/01/00 01 00:00:00` with `CH` = 1 (oscillator stopped).

### Bit Fields

#### `SECONDS` (`0x00`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | CH | Clock halt: 1 = oscillator disabled, 0 = running |
| 6:4 | 10 SECONDS | BCD tens |
| 3:0 | SECONDS | BCD units |

#### `HOURS` (`0x02`)

| Bits | Name | Description |
|------|------|-------------|
| 6 | 12/24 | 1 = 12-hour mode, 0 = 24-hour mode (re-enter the hours whenever this bit changes) |
| 5 | AM/PM / 10 HOUR | 12-hour mode: 1 = PM; 24-hour mode: second 10-hour bit (20–23 h) |
| 4 | 10 HOUR | tens of hours |
| 3:0 | HOURS | BCD units |

#### `CONTROL` (`0x07`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | OUT | Level of SQW/OUT when `SQWE` = 0 (1 = high, 0 = low) |
| 4 | SQWE | 1 = square-wave output enabled |
| 1:0 | RS1:RS0 | `00` 1 Hz, `01` 4.096 kHz, `10` 8.192 kHz, `11` 32.768 kHz |

At 1 Hz the clock registers update on the falling edge of the square wave.

## Initialization Sequence

1. Power VCC (4.5–5.5 V) and optionally VBAT; the oscillator typically starts in under one second once `CH` = 0.
2. Read `SECONDS` (`0x00`); `CH` = 1 means the clock is halted (first power-up or battery lost) and the time is not valid.
3. To set the time, write `0x00`–`0x06` in one transaction with `CH` = 0 and `12/24` = 0.
4. Optionally write `CONTROL` (`0x07`) for the square-wave output.

## Implementation Stages

### Minimal

Goal: read and set the clock; no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Takes the `RegisterConnection`; reads `SECONDS` to confirm the chip answers; no writes |
| `get_datetime` | — | `(year, month, day, weekday, hour, minute, second)` | One burst read `0x00`–`0x06`; `year` 2000–2099, `hour` 0–23 (a 12-hour setting is converted), `weekday` 1–7 (1 = Monday, ISO 8601, matching the DS3231 driver) |
| `set_datetime` | `year, month, day, weekday, hour, minute, second` | — | Writes `0x00`–`0x06` in one transaction with `CH` = 0 and 24-hour mode; starts the oscillator |

**Sensible defaults:** 24-hour format, oscillator started by `set_datetime`, square-wave output left as found.

### Full

Goal: complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `is_running` | — | bool | `CH` = 0 |
| `halt` / `start` | — | — | `CH` (read-modify-write of `SECONDS`; minimises backup current while halted) |
| `valid` | — | bool | `CH` = 0 (False after a battery loss); the driver cannot detect other corruption |
| `get_time` / `get_date` | — | `(hour, minute, second)` / `(year, month, day, weekday)` | Partial reads |
| `set_time` / `set_date` | as above | — | Single-field-group writes (`set_time` keeps `CH`) |
| `set_hour_mode` | `hour12: bool` | — | Converts and rewrites `HOURS` |
| `set_square_wave` | `frequency_hz: int \| None` (1, 4096, 8192, 32768 or `None` = off) | — | `SQWE`, `RS`; `None` clears `SQWE` |
| `set_output` | `level: bool` | — | `OUT` with `SQWE` = 0 |
| `get_control` | — | int | Raw `CONTROL` byte |
| `read_ram` | `address: int` (0–55), `length: int` | bytes | Block read from `0x08 + address`; no wrap past 55 |
| `write_ram` | `address: int`, `data: bytes` | — | Battery-backed SRAM write |

**Additional configuration options:** 12/24-hour mode, square-wave frequency or static output level, clock halt, 56-byte RAM.

## Data Conversion

```
bcd_to_int(b)  = (b >> 4) * 10 + (b & 0x0F)
int_to_bcd(v)  = ((v // 10) << 4) | (v % 10)

second = bcd_to_int(SECONDS & 0x7F)
hour (24 h)    = bcd_to_int(HOURS & 0x3F)
hour (12 h)    = bcd_to_int(HOURS & 0x1F) % 12 + (12 if HOURS & 0x20 else 0)
year           = 2000 + bcd_to_int(YEAR)
```

## Timing Constraints

| Constraint | Value |
|------------|-------|
| I²C clock | 0–100 kHz (tLOW ≥ 4.7 µs, tHIGH ≥ 4.0 µs, tBUF ≥ 4.7 µs) |
| Time-register write | after the seconds register is written the divider chain is reset; the remaining time/date registers must be written within one second |
| Oscillator start-up | usually less than one second |
| Power-up | inputs recognised when VCC > 1.25 × VBAT; switch to VCC when VCC > VBAT + 0.2 V |

The clock reads use user buffers that are synchronised on every I²C START, so a read never tears. The one-second write window is a host-side rule satisfied by writing `0x00`–`0x06` in one transaction; there is no bus-decodable start/end pair with a datasheet bound, so `ds1307_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection:** accept `RegisterConnection` and call `connection.read(reg, length)` / `connection.write(reg, data)` directly — no chip-local helpers. See `specs/feature_register_access_design.md`.
- **BCD everywhere:** all time/date fields are BCD; `CONTROL` and RAM are binary. `CH` (bit 7 of `0x00`) must be preserved or deliberately cleared in every write to `SECONDS`; `set_datetime` clears it, `halt` sets it.
- **24-hour mode only:** the driver always writes 24-hour mode; 12-hour data on read is converted. The hours value must be re-entered whenever the mode bit changes (`set_hour_mode` rewrites it).
- **Weekday:** the `DAY` register is a free-running 1–7 counter incremented at midnight with user-defined meaning; the driver uses 1 = Monday … 7 = Sunday (ISO 8601, as the DS3231 driver does). Illogical date/time values give undefined operation, so the driver validates ranges before writing.
- **Single write:** write `0x00`–`0x06` in one transaction (the divider chain is reset on the seconds write; the rest must follow within one second).
- **No halted-clock detection beyond `CH`:** `CH` = 1 after first power-up or a lost backup supply; after `CH` = 0 the chip gives no further sign of an earlier power loss. The reset values after VCC and VBAT loss are only "typically" `0x80` for `SECONDS` and `0x03` for `CONTROL` (RS = 11, SQWE = 0, OUT = 0).
- **Supply:** the chip needs 4.5–5.5 V; on 3.3 V systems it is commonly run from 5 V with the bus pulled up to 3.3 V. Negative undershoots below −0.3 V in battery-backed mode can corrupt data.
- **Accuracy:** no oscillator compensation or trim register exists; accuracy is that of the crystal (12.5 pF load, ≤ 45 kΩ ESR), the layout and the temperature (see application note 58). Keep noise away from X1/X2.
- **Square wave:** `SQW/OUT` is open drain and needs a pull-up; with `SQWE` = 0 it follows `OUT`.
- **Address:** the pin-less `0x68` is shared with DS3231, DS1371 and PCF8523; only one can be on a bus.

## Sigrok Decoder

Decoder id `ds1307`, input `['i2c']`. Matches I²C address `0x68`, tracks the register pointer (auto-increment, wrap at `0x3F` → `0x00`) and annotates register accesses by name. Decodes the BCD time/date registers into a time string (including the `CH` flag and 12/24-hour mode), `CONTROL` (`OUT`, `SQWE`, `RS` frequency) and the RAM range; warns on illogical BCD values, on a time-register write that leaves the seconds register more than one second before the remaining registers, and on an SCL clock above 100 kHz. No conformance annotation pair is emitted (no checked timing constraint).
