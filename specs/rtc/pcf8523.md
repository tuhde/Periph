# Chip Spec: PCF8523

**Manufacturer:** NXP Semiconductors
**Datasheet:** `datasheets/rtc/pcf8523.pdf`
**Category:** rtc
**Transports:** I²C

## Overview

The PCF8523 is a CMOS real-time clock (RTC) and calendar optimized for low power
consumption, transferring data serially over I²C at up to 1000 kbit/s (Fm+). It maintains
seconds, minutes, hours, days, weekdays, months, and years in auto-incrementing BCD
registers (with automatic leap-year correction), backed by a battery switch-over circuit
that monitors the main supply (`VDD`) and automatically switches to a backup battery
(`VBAT`) on power failure, plus a battery-low detection flag. Beyond timekeeping, the chip
offers a single freely-configurable alarm (independently matchable on minute, hour, day,
and/or weekday), two general-purpose timers (Timer A selectable as a watchdog or countdown
timer; Timer B as a countdown timer, with its own dedicated interrupt pin), a programmable
clock output (32.768 kHz down to 1 Hz), and a two's-complement offset register for
fine-tuning long-term accuracy via periodic correction pulses.

## Transport Configuration

### I²C
- **Address:** `0x68` (fixed — no address pins; only one device per bus; other addresses
  producible on request per the datasheet)
- **Max clock:** 1000 kHz (Fast-mode Plus); also supports 400 kHz (Fast mode) and
  100 kHz (Standard mode)

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| INT1/CLKOUT | low, open-drain | requires external pull-up; multiplexed — carries either the alarm/timer/battery interrupt signals or the CLKOUT square wave, never both (the two functions share one physical pin) |
| INT2 | low, open-drain | requires external pull-up; sourced only from Timer B's countdown flag |

`OSCI`/`OSCO` (crystal connections) and `VBAT` (battery backup supply) are not wired to
the `Connection` and are not part of the API; `VBAT` is a power pin, not a signal the
driver reads or writes.

All 20 registers auto-increment the address pointer on every byte transferred and wrap
from `0x13` back to `0x00`. Reads/writes of the time/date registers (`0x03`–`0x09`) freeze
the RTC's internal counters for the duration of the access — see Implementation Notes for
the resulting "one access must finish within 1 s" constraint.

### Bit Fields

#### `CONTROL_1` (`0x00`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | CAP_SEL | Oscillator load capacitance: `0`=7 pF (default), `1`=12.5 pF — a board-design constant matching the crystal, never toggled at runtime by this driver |
| 6 | T | Unused; must always be written `0` |
| 5 | STOP | `0`=RTC time circuits running (default); `1`=frozen (divider chain held reset; CLKOUT at 32.768/16.384/8.192 kHz still available) |
| 4 | SR | Write `1` (as part of the `01011000` / `0x58` byte, see Initialization Sequence) to trigger a software reset; always reads `0` |
| 3 | 12_24 | `0`=24-hour mode (default, and the only mode this driver uses), `1`=12-hour mode |
| 2 | SIE | Second interrupt enable |
| 1 | AIE | Alarm interrupt enable |
| 0 | CIE | Correction (clock-offset pulse) interrupt enable — not exposed by this driver (see Implementation Notes) |

#### `CONTROL_2` (`0x01`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | WTAF | Watchdog Timer A flag — **read-only**, set on timeout, cleared automatically by reading this register |
| 6 | CTAF | Countdown Timer A flag — set on timeout, cleared by writing `0` |
| 5 | CTBF | Countdown Timer B flag — set on timeout, cleared by writing `0` |
| 4 | SF | Second flag — set every second while `SIE`=1, cleared by writing `0` |
| 3 | AF | Alarm flag — set when all enabled alarm fields match, cleared by writing `0` |
| 2 | WTAIE | Watchdog Timer A interrupt enable |
| 1 | CTAIE | Countdown Timer A interrupt enable |
| 0 | CTBIE | Countdown Timer B interrupt enable |

Clearing follows AND semantics (per the datasheet's flag-clear convention): writing `0` to
`CTAF`/`CTBF`/`SF`/`AF` clears that flag; writing `1` leaves it unchanged. `WTAIE`/`CTAIE`/
`CTBIE` are ordinary read/write enable bits, not flags — any write to this register must
re-supply their current value or they will be corrupted.

#### `CONTROL_3` (`0x02`)

| Bits | Name | Description |
|------|------|-------------|
| 7:5 | PM[2:0] | Battery switch-over / low-detection mode — see Power Management Modes table below |
| 4 | — | Unused, reads `0` |
| 3 | BSF | Battery switch-over flag — set when a switch-over occurs, cleared by writing `0` |
| 2 | BLF | Battery low flag — **read-only**, cleared automatically by the battery-low detection circuit when the battery is replaced |
| 1 | BSIE | Battery switch-over interrupt enable |
| 0 | BLIE | Battery low interrupt enable |

#### Power Management Modes (`PM[2:0]`)

| PM[2:0] | Battery switch-over | Battery low detection |
|---------|---------------------|------------------------|
| `000` | Standard mode | Enabled |
| `001` | Direct switching mode | Enabled |
| `010`, `011` | Disabled (`VDD` only) | Enabled |
| `100` | Standard mode | Disabled |
| `101` | Direct switching mode | Disabled |
| `110` | *(not allowed)* | — |
| `111` (POR default) | Disabled (`VDD` only) | Disabled |

Standard mode switches to `VBAT` when `VDD` < `VBAT` **and** `VDD` < 2.5 V (typ.); direct
switching mode switches whenever `VDD` < `VBAT`, at lower power but only recommended when
`VDD` is reliably well above `VBAT` (e.g. 5 V vs. 3.5 V). When switch-over is disabled,
`VBAT` must be tied to `VDD`.

#### `HOURS` (`0x05`, and `HOUR_ALARM`)

| Bits | Name | Description |
|------|------|-------------|
| 7:6 | — | Unused, read as `0` |
| 5:4 | HOURS (tens) | 24-hour mode: tens-of-hours BCD digit, `0`–`2` |
| 3:0 | HOURS (units) | Units-of-hours BCD digit |

This driver always operates in 24-hour mode (`12_24`=0) — `set_datetime`/`set_alarm` write
`hour` 0–23 directly; the chip's 12-hour/AM-PM encoding is never used or exposed.

#### `WEEKDAYS` (`0x07`, and `WEEKDAY_ALARM`)

| Day | Value |
|-----|-------|
| Sunday | `0` |
| Monday | `1` |
| Tuesday | `2` |
| Wednesday | `3` |
| Thursday | `4` |
| Friday | `5` |
| Saturday | `6` |

The counter itself is a free-running 0–6 value with no hardware-enforced meaning — this
driver adopts the datasheet's own suggested assignment table above as its `weekday`
convention (see Implementation Notes).

#### Alarm registers (`0x0A`–`0x0D`)

Each alarm register's bit 7 is an **active-low** enable (`AEN_x`): `0`=this field
participates in the match, `1`=this field is ignored (POR default). The alarm flag `AF`
sets on the next second where every enabled field matches simultaneously; an alarm with
all four fields disabled never fires. `MINUTE_ALARM`/`HOUR_ALARM`/`DAY_ALARM` are BCD;
`WEEKDAY_ALARM` bits 2:0 use the same 0–6 convention as `WEEKDAYS`.

#### `OFFSET` (`0x0E`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | MODE | `0`=correction applied once every two hours (default, lower power); `1`=once every minute (faster convergence, more correction pulses) |
| 6:0 | OFFSET[6:0] | Two's-complement offset, `+63` to `−64` LSB. Each LSB is 4.34 ppm (`MODE`=0) or 4.069 ppm (`MODE`=1) |

#### `TMR_CLKOUT_CTRL` (`0x0F`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | TAM | `0`=permanently active interrupt for Timer A and the second timer (default); `1`=pulsed |
| 6 | TBM | `0`=permanently active interrupt for Timer B (default); `1`=pulsed |
| 5:3 | COF[2:0] | CLKOUT frequency — see CLKOUT Frequency Selection table below |
| 2:1 | TAC[1:0] | Timer A mode: `00`=disabled (default), `01`=countdown timer, `10`=watchdog timer, `11`=disabled |
| 0 | TBC | Timer B: `0`=disabled (default), `1`=enabled |

#### CLKOUT Frequency Selection (`COF[2:0]`)

| COF[2:0] | Frequency | Notes |
|----------|-----------|-------|
| `000` (default) | 32768 Hz | Unaffected by `STOP` |
| `001` | 16384 Hz | Unaffected by `STOP` |
| `010` | 8192 Hz | Unaffected by `STOP` |
| `011` | 4096 Hz | High-Z while `STOP`=1 |
| `100` | 1024 Hz | High-Z while `STOP`=1 |
| `101` | 32 Hz | High-Z while `STOP`=1 |
| `110` | 1 Hz | High-Z while `STOP`=1 |
| `111` | Disabled (high-Z) | |

#### `TMR_A_FREQ_CTRL` (`0x10`) / `TMR_B_FREQ_CTRL` (`0x12`) source clocks (`TAQ[2:0]`/`TBQ[2:0]`)

| Value | Frequency | Countdown range (T_x 1–255) |
|-------|-----------|-------------------------------|
| `000` | 4096 Hz | 244 µs – 62.256 ms |
| `001` | 64 Hz | 15.625 ms – 3.984 s |
| `010` | 1 Hz | 1 s – 255 s |
| `011` | 1/60 Hz | 1 min – 255 min |
| `111` (default; `110`/`100` equivalent) | 1/3600 Hz | 1 hour – 255 hours |

`TMR_B_FREQ_CTRL` additionally has `TBW[2:0]` (bits 6:4) selecting Timer B's pulsed-mode
interrupt low-pulse width, from 46.875 ms (`000`, default) to 218.75 ms (`111`) in
15.625 ms steps.

## Initialization Sequence

1. Construct the driver with a fixed-address (`0x68`) `Connection`.
2. Read the `CONTROL_1` register once to confirm the device answers on the bus — the
   PCF8523 has no WHO_AM_I/identity register, so this doubles as the presence check.
3. Write `CONTROL_3` with `PM[2:0]`=`000` (battery switch-over standard mode, battery-low
   detection enabled), preserving `BSF`/`BSIE`/`BLIE` at their POR-default `0`. This is a
   deliberate deviation from the chip's own POR default (`PM[2:0]`=`111`, single-supply
   only) — see Sensible Defaults below.
4. No time/date register writes are required at `init` time: contents are undefined until
   the caller calls `set_datetime()`.

## Interrupt

| Property | Value |
|----------|-------|
| INT pins | `INT1`/`CLKOUT` (all sources) and `INT2` (Timer B only), both active-low, open-drain — require external pull-ups |
| Level | 3 (multiple INT lines) |
| Condition(s) | Second tick; Timer A timeout (countdown or watchdog); Timer B timeout; alarm match; battery switch-over; battery low |
| Clear mechanism | write `0` to the corresponding flag bit in `CONTROL_2`/`CONTROL_3` (`WTAF`/`BLF` are read-only and self-clear) |

Using `INT1` for interrupts requires `CLKOUT` to be disabled (`COF[2:0]`=`111`), since the
two functions share one physical pin — `enable_interrupt`/`on_interrupt` do not do this
automatically (see Implementation Notes); call `disable_clock_output()` first if CLKOUT was
left at its POR default.

### Interrupt sources

| Constant | Value | Condition | Pin(s) |
|----------|-------|-----------|--------|
| `SOURCE_SECOND` | `0x01` | Second timer ticks (while `SIE`=1) | INT1 |
| `SOURCE_TIMER_A` | `0x02` | Timer A timed out (countdown `CTAF` or watchdog `WTAF`, whichever mode is configured) | INT1 |
| `SOURCE_TIMER_B` | `0x04` | Timer B timed out (`CTBF`) | INT1, INT2 |
| `SOURCE_ALARM` | `0x08` | All enabled alarm fields matched (`AF`) | INT1 |
| `SOURCE_BATTERY_SWITCH` | `0x10` | Battery switch-over occurred (`BSF`) | INT1 |
| `SOURCE_BATTERY_LOW` | `0x20` | Battery voltage below threshold (`BLF`) | INT1 |

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits
everything and adds the rest.

### Minimal

Goal: expose the chip's primary use case — reading and setting the calendar clock with
battery backup active — with no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Confirms the device answers; sets `PM[2:0]`=`000` (see Sensible Defaults); makes no time-register writes |
| `get_datetime` | — | `(year, month, day, weekday, hour, minute, second)` (all int) | `year` is 2000–2099; `hour` is always 0–23; `weekday` is 0–6, Sunday=0 (see Implementation Notes) |
| `set_datetime` | year, month, day, weekday, hour, minute, second | — | Uses the `STOP`-bit precision-start sequence (see Implementation Notes) to write all seven clock/calendar registers, forces 24-hour mode, and writes `OS`=0 (clock integrity now known-good) |

**Sensible defaults:** 24-hour time format (enforced on every `set_datetime`); battery
switch-over standard mode with battery-low detection enabled (`PM[2:0]`=`000`, written at
`init`) — a deliberate override of the chip's own `PM[2:0]`=`111` POR default, since the
PCF8523's headline feature is `VBAT` backup and boards using this driver are assumed to
wire a backup battery or supercap to `VBAT`; call `Full.configure_battery_backup()` to
restore single-supply (`VDD`-only) operation if `VBAT` is left unconnected. CLKOUT is left
at its POR default (32.768 kHz active) and the alarm/timers/interrupts are left disabled —
inert until `Full` configures them.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |

| `set_alarm` | minute=None, hour=None, day=None, weekday=None | — | Each parameter left `None` disables that field (`AEN_x`=1); a non-`None` value enables and writes it (`AEN_x`=0). The alarm fires when every enabled field matches |
| `configure_timer_a` | mode ("countdown" \| "watchdog"), value (int, 0–255), source_clock ("4096hz" \| "64hz" \| "1hz" \| "1_60hz" \| "1_3600hz"), pulsed=False | — | Sets `TAQ[2:0]`, writes `TMR_A_REG`, sets `TAM`, and sets `TAC[1:0]` to enable the chosen mode |

## Data Conversion

```
bcd_to_int(b)  = (b >> 4) * 10 + (b & 0x0F)
int_to_bcd(v)  = ((v // 10) << 4) | (v % 10)

offset_ppm = offset_value * (4.34 if mode == "every_two_hours" else 4.069)
    # offset_value: two's-complement value of OFFSET[6:0], range +63 to -64
```

### Demo flow

An Inject node fires every 10 s, triggering the `periph-pcf8523` node to read and log the
current date/time and battery status. A second, one-shot Inject node sends
`msg.payload.datetime` built from `Date.now()` to synchronize the RTC to the host clock on
deploy. The node is configured with Timer B enabled as a 10-minute countdown heartbeat
(source clock `1/60hz`, value `10`); each time it fires, the node emits a
`{ source: "timer_b" }` message that a Function node turns into a "still alive" log line,
demonstrating `INT2`'s dedicated Timer B path alongside the polled read.

## Examples

### Demo

A battery-backed environmental logger's scheduling core. On startup, the demo checks
`oscillator_stopped()`; if `True` (fresh chip, or the backup battery was disconnected too
long), it reseeds the clock from a fixed reference timestamp with `set_datetime`. It then
calls `configure_battery_backup("standard")` (redundant with `Minimal.init`'s default, but
shown explicitly) and checks `is_battery_low()` once, logging a warning if the coin cell
needs replacing. The demo configures the alarm to fire once per hour (`set_alarm(minute=0)`,
leaving `hour`/`day`/`weekday` disabled) to wake the host and take a reading, and configures
Timer B as a 30-second countdown (`configure_timer_b(30, "1hz")`) as a watchdog "still
running" pulse on `INT2` independent of the hourly wake. It subscribes with `on_interrupt`,
and the callback masks the returned status against `SOURCE_ALARM`/`SOURCE_TIMER_B`: on an
alarm match it prints the current `get_datetime()`; on a Timer B match it just toggles an
LED. Before exiting after a fixed number of alarm matches, it calls `disable_interrupt` for
both sources, `disable_timer_b()`, and `off_interrupt()`.

## Timing Constraints

- **Time/date register access window (`time_access`):** every read or write touching the
  time/date registers (`SECONDS` `0x03` through `YEARS` `0x09`) must complete — from the
  `START` condition through the terminating `STOP` — within 1 s (Section 8.6.8). The chip
  freezes its counters for the duration of the access and services at most one pending
  1 Hz increment afterward; an access slower than 1 s can silently drop a second. This is
  the only host-observable, conformance-checkable constraint the chip has.
- Oscillator startup after first power/`VBAT` application: 200 ms to 2 s depending on
  crystal/temperature/supply, fully autonomous — the I²C interface is accessible
  immediately regardless, so no driver-side wait is needed.
- `STOP`-bit release timing: the first 1 Hz increment after clearing `STOP` occurs between
  0.499878 s and 0.500000 s later (0 to 122 µs of uncertainty from the two lowest
  prescaler stages not being reset). Informational — it bounds `set_datetime`'s achievable
  start-time accuracy, not a delay the driver must wait out.
- Software reset (`SR`/`0x58` sequence): takes effect on the write's `STOP` condition; no
  additional wait is required before the next access.
- Countdown timer first-period accuracy after enabling: −1 tick to +1 tick relative to the
  programmed value, depending on the chosen source clock (Table 41 of the datasheet) —
  hardware behavior, not driver-actionable.

## Implementation Notes

- All clock/calendar/alarm register value fields are BCD, not binary — every read/write
  goes through `bcd_to_int`/`int_to_bcd` (see Data Conversion). The alarm enable bits
  (`AEN_x`) and `MODE`/timer/CLKOUT control fields are plain binary.
- This driver always operates the `HOURS` registers in 24-hour mode; the chip's native
  12-hour/AM-PM encoding is never written or exposed.
- `WEEKDAYS` (`0x07`) is a free-running 0–6 counter with no hardware-enforced meaning —
  this driver adopts the datasheet's own suggested assignment (Table 18: `0`=Sunday …
  `6`=Saturday) as its `weekday` convention for both `get_datetime`/`set_datetime` and the
  weekday alarm field. This differs from this repository's DS3231 driver, which uses a
  1–7 ISO 8601 (`1`=Monday) convention on that chip's *own* freely-defined day counter —
  each RTC driver follows its own datasheet's suggested table rather than a repo-wide
  convention, since neither chip enforces one in hardware.
- **`STOP`-bit precision start.** `set_datetime` sets `STOP`=1, writes all seven time/date
  registers in one transaction (satisfying the Timing Constraints access-window rule
  above), then clears `STOP`=0. This freezes the divider chain before loading new values
  and is the datasheet-recommended way to start the clock at a known instant, accurate to
  within the `STOP`-bit release uncertainty noted above.
- Alarm field enable bits are **active-low** (`AEN_x`=`0` enables, `=1` disables) — the
  inverse polarity of a typical enable bit; `set_alarm`'s `None`-means-disabled parameter
  convention exists specifically to keep this inversion out of the driver's public API.
- `CIE` (`CONTROL_1` bit 0, correction-pulse interrupt enable) is not exposed by this
  driver. It only emits a diagnostic ¹⁄₄₀₉₆ s pulse per clock-correction cycle applied by
  the `OFFSET` register and has no use outside oscillator-calibration bench work; the
  register bit is documented above for completeness but wiring it up added API surface no
  caller of this driver needs.
- `INT1` is shared with `CLKOUT` (`Full.set_clock_output`) — enabling alarm/timer/battery
  interrupts on `INT1` while CLKOUT is also enabled leaves the pin driving CLKOUT, not the
  interrupt condition. This driver does not automatically disable CLKOUT when
  `enable_interrupt`/`on_interrupt` is called; call `disable_clock_output()` first if the
  POR-default CLKOUT was never turned off.
- `read_timer_a`/`read_timer_b` return the *live* countdown value, not the originally
  loaded one, and the chip cannot freeze the counter for a clean read the way it does for
  the time/date registers — the datasheet recommends reading twice and checking for a
  consistent result if precision matters.
- Software reset (`SR`) resets `CONTROL_1`/`CONTROL_2`/`CONTROL_3`/`OFFSET`/
  `TMR_CLKOUT_CTRL`/`TMR_A_FREQ_CTRL`/`TMR_B_FREQ_CTRL` to their POR values (see the
  datasheet's Table 10) but leaves the *contents* of the time/date/alarm/timer value
  registers unchanged — it re-arms configuration, it does not erase the clock. Because it
  also resets `PM[2:0]` back to `111` (battery backup disabled), `Minimal.init()` does
  **not** call `software_reset()` — doing so on every driver construction would silently
  disable a previously-configured battery backup on every host reboot.
- **Offset calibration workflow:** measure the actual `CLKOUT` frequency (`f_meas`) against
  a reference, compute the ppm deviation `E_ppm = 1e6 * (1/32768 - 1/f_meas) / (1/f_meas)`,
  then `offset = round(E_ppm / 4.34)` for `mode="every_two_hours"` or
  `round(E_ppm / 4.069)` for `mode="every_minute"`; pass the result to `set_offset`. See
  Figure 18 of the datasheet for the full worked example.
- The chip has no WHO_AM_I/identity register; `init()` presence detection is a plain
  register read, matching this repository's other address-fixed RTC drivers.
- A repeated `START` is not allowed on this device — every transaction must end with a
  `STOP` before the next `START`.

## Sigrok Decoder

Decoder `pcf8523` (`sigrok/pcf8523/`) stacks on the `i2c` decoder and recognizes the fixed
address `0x68`, tracking the register pointer (auto-increment, wraps at `0x13`→`0x00`)
across multi-byte transactions.

| Row | Annotation | Meaning |
|-----|------------|---------|
| Data | `data` | Register read/write decoded per field: BCD time/date (`0x03`–`0x09`), alarm registers with active-low enable decode (`0x0A`–`0x0D`), `OFFSET` two's-complement value + mode (`0x0E`), timer/CLKOUT control fields (`0x0F`–`0x13`) |
| Status | `status` | `CONTROL_1`/`CONTROL_2`/`CONTROL_3` reads/writes decoded to their named bit fields and flags |
| Timing | `timing` | `time_access_start`/`time_access_done` marker pair: start at the `START` condition of any transaction whose first accessed register address falls in `0x03`–`0x09`; end at that same transaction's `STOP` condition |
| Warnings | `warning` | Access to an undefined register address (`0x14`+); a write attempting `PM[2:0]`=`110` (not allowed); a write to the read-only `WTAF`/`BLF` bit positions |
