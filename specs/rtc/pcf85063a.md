# Chip Spec: PCF85063A

**Manufacturer:** NXP Semiconductors  
**Datasheet:** `datasheets/rtc/pcf85063a.pdf`  
**Category:** `rtc`  
**Transports:** I²C

## Overview

The PCF85063A is a CMOS real-time clock and calendar optimised for low power consumption (typically 0.22 µA at 3.3 V, 25 °C), operating from 0.9 V to 5.5 V and transferring data over I²C at up to 400 kbit/s. It keeps seconds, minutes, hours, days, weekdays, months and years in auto-incrementing BCD registers with automatic leap-year correction (2000–2099), driven by a 32.768 kHz crystal with selectable integrated load capacitors (7 pF or 12.5 pF). It also provides a five-field alarm (second, minute, hour, day, weekday), an 8-bit countdown timer with four source clocks (244 µs … 4 h 15 min), minute and half-minute interrupts, a programmable square-wave clock output (32.768 kHz … 1 Hz), an offset register for ±ppm frequency trimming, one free RAM byte and oscillator-stop detection. There is no battery switch-over or backup-supply management — the chip is fed from the single `VDD` supply. Typical uses: cameras, printers, mobile and battery-powered equipment, and any board that needs a small timekeeping chip (e.g. Waveshare ESP32 and M5Stack boards).

## Transport Configuration

### I²C
- **Address:** `0x51` (fixed; target address byte `1010 001R/W` = `0xA2` write / `0xA3` read)
- **Max clock:** 400 kHz (fast mode, at VDD 1.8–5.5 V)
- **Identity register:** none; chip has no ID register (feeds `registry/chips.json` with `"id_probe": null` and `"driver": null` until implemented, see `specs/feature_i2c_discovery.md`)
- **Probe safety:** `register_pointer` — the byte after the address selects the register, and the address register only advances after data bytes; a 1-byte write cannot change a register

The register address is a 5-bit value (upper 3 bits unused). The address register auto-increments after every byte read or written up to `0x11`, then wraps to `0x00`. SDA and SCL need pull-ups to the same supply as VDD (NXP recommendation). A stuck bus is recovered by nine clock pulses on SCL.

## Initialization Sequence

1. Power up with VDD rising from 0 V (the datasheet requires this to guarantee default registers; with a residual VDD level a software reset is required once the supply is stable — see Implementation Notes). The I²C interface is accessible immediately; the crystal needs 200 ms to 2 s to start oscillating, during which `OS` = 1.
2. Read `Control_1` (`0x00`) as a bus check; raise a descriptive error if the transfer fails (the chip has no identity register).
3. Write `Control_1` with `STOP` = 0, `12_24` = 0 (24-hour mode), `CIE` and the other bits preserved (read-modify-write). `init` does **not** reset the chip (a software reset would also reset the time) and does not write any time register.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `INT`, active-low, open-drain — requires an external pull-up |
| Level | 2 (selectable sources on one pin) |
| Condition(s) | alarm match (`AF`); countdown timer, minute or half-minute tick (`TF`); offset-correction pulse (`CIE`, no flag) |
| Clear mechanism | write 0 to `AF` / `TF` in `Control_2` (writing 1 leaves a flag unchanged, so a read-modify-write preserves the other flag); in pulse mode (`TI_TP` = 1) `INT` releases by itself |

With `TI_TP` = 0 the `INT` pin follows `TF` (stays low until `TF` is cleared, and no new `INT` is generated if `TF` is not cleared before the next trigger); with `TI_TP` = 1 an `INT` pulse is generated regardless of `TF`, and the countdown timer runs in a loop. `AF` always makes `INT` follow the flag when `AIE` is set. The minute and half-minute interrupts are pulses 1/64 s wide.

### Interrupt sources

| Constant | Value | Condition |
|----------|-------|-----------|
| `SOURCE_ALARM` | `0x01` | All enabled alarm fields matched (`AF`); enabled by `AIE` |
| `SOURCE_TIMER` | `0x02` | Countdown timer expired (`TF`); enabled by `TIE` |
| `SOURCE_MINUTE` | `0x04` | Once per minute (`TF` is set); enabled by `MI` — enable only, status is reported as `SOURCE_TIMER` |
| `SOURCE_HALF_MINUTE` | `0x08` | Every 30 s (`TF` is set); enabled by `HMI` — enable only, status is reported as `SOURCE_TIMER` |
| `SOURCE_CORRECTION` | `0x10` | Offset-correction pulse; enabled by `CIE` — enable only, no flag |

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits everything and adds the rest.

### Minimal

Goal: read and set the calendar clock with no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Bus check, forces 24-hour mode and `STOP` = 0; writes no time register and does not reset the chip |
| `get_datetime` | — | `(year, month, day, weekday, hour, minute, second)` (all int) | One 7-byte burst of `0x04`–`0x0A`; `year` is 2000–2099, `hour` 0–23, `weekday` 0–6 with Sunday = 0 |
| `set_datetime` | year, month, day, weekday, hour, minute, second | — | `STOP`-bit precision start (see Implementation Notes): writes all seven registers in one transaction, writes `OS` = 0 |

**Sensible defaults:** 24-hour time format (enforced by `init` and every `set_datetime`); CLKOUT, alarm, timer, minute / half-minute and correction interrupts and the offset register are left at their power-on values (CLKOUT active at 32.768 kHz, everything else inert) until Full configures them.

## Data Conversion

```
bcd_to_int(b)  = (b >> 4) * 10 + (b & 0x0F)
int_to_bcd(v)  = ((v // 10) << 4) | (v % 10)

second  = bcd_to_int(Seconds & 0x7F)         # bit 7 is OS
minute  = bcd_to_int(Minutes & 0x7F)
hour    = bcd_to_int(Hours & 0x3F)           # 24-hour mode
day     = bcd_to_int(Days & 0x3F)
weekday = Weekdays & 0x07                    # 0 = Sunday ... 6 = Saturday
month   = bcd_to_int(Months & 0x1F)
year    = 2000 + bcd_to_int(Years)

offset_value = int7(Offset & 0x7F)           # two's complement, -64 ... +63
offset_ppm   = offset_value * 4.34           # MODE = 0 (normal)
offset_ppm   = offset_value * 4.069          # MODE = 1 (course)

timer_period = T / source_clock_hz           # T = 1..255 (see Table below)
```

## Timing Constraints

- **Time / date register access window (`time_access`):** every read or write that touches the time and date registers (`Seconds` `0x04` through `Years` `0x0A`) must complete — from the `START` condition through the terminating `STOP` — within 1 s (datasheet §7.4, Figure 15). The chip freezes its counters during the access and services at most one pending 1 Hz increment afterwards; an access slower than 1 s can silently drop a second. Seconds through years must be read or written in one single access, never in several. **Conformance-checked** as `time_access` (max 1000 ms), via the sigrok decoder's `time_access_start` / `time_access_done` annotation pair — see [Sigrok Decoder](#sigrok-decoder) and `specs/rtc/pcf85063a_timing.conf`.
- **Oscillator start-up:** after first power-up the oscillator is considered stopped (`OS` = 1) for 200 ms to 2 s depending on crystal, temperature and supply; fully autonomous, the I²C interface works immediately. Use VDD above 1.2 V for reliable start-up (0.9 V works but is slow); a full 0 V supply is recommended for a restart.
- **`STOP`-bit release:** the first 1 Hz increment after clearing `STOP` occurs between 0.507813 s and 0.507935 s later (0 to 122 µs uncertainty because the two lowest prescaler stages are not reset). Informational — it bounds `set_datetime`'s start-time accuracy.
- **Software reset:** takes effect when the write completes; the datasheet recommends re-initialising the interface with a `STOP` and `START` afterwards. No other delay is specified.
- **Countdown timer first period:** after enabling, the first period may range from T − 1 to T + 1 source-clock periods (Figure 17; Table 36 gives T … T + 1 for the 4.096 kHz and 64 Hz clocks); later periods are exact. Hardware behaviour, not driver-actionable.
- **Timer reload:** change `Timer_value` only with `TE` = 0, otherwise the first period is undetermined (the value is stored correctly and loaded on later periods).
- **Minute / half-minute interrupt:** the first interrupt after enabling comes after 1–59 s (MI) or 1–29 s (HMI).
- **Offset correction:** in normal mode every two hours (pulses once per minute until applied); in course mode every four minutes (pulses once per second up to 60, then extra pulses in the 59th second). Timer source clocks of 1 Hz and 1/60 Hz and CLKOUT = 1 Hz are affected by correction pulses.

## Implementation Notes

- **Register-addressed:** accept `RegisterConnection` (1-byte register address) and call `connection.read(reg, length)` / `connection.write(reg, data)` directly — no chip-local `_read_reg`/`_write_reg` and no `bus_type` branch (see `specs/feature_register_access_design.md`).
- **All value fields are BCD** (`Seconds` … `Years`, alarm value fields); the alarm `AEN_x` bits, `Weekdays`, `Offset`, timer and control fields are plain binary. Every conversion goes through `bcd_to_int` / `int_to_bcd`.
- **Always 24-hour mode:** the driver never writes the 12-hour / AM-PM encoding; `init` and `set_datetime` keep `12_24` = 0. Alarm hours are written in the same 24-hour format.
- **Weekday convention:** `Weekdays` is a free-running 0–6 counter with no hardware-enforced meaning; the driver uses the datasheet's suggested assignment (Table 24: `0` = Sunday … `6` = Saturday) for `get_datetime` / `set_datetime` and the weekday alarm, like the PCF8523 driver (and unlike DS3231).
- **Years 2000–2099:** the chip adds 29 February to every year divisible by 4, including `00`; 2100 would be mishandled, so `set_datetime` rejects years outside 2000–2099.
- **One-shot access for the time registers:** read `Seconds` … `Years` as one 7-byte transaction and write them as one 7-byte transaction; the counters are frozen while the bus is accessed, which prevents carry corruption. Never read or write time registers in separate accesses.
- **`STOP`-bit precision start:** `set_datetime` sets `STOP` = 1, writes the seven time registers in one transaction (with `OS` = 0 in `Seconds`), then clears `STOP` = 0. The clock starts at a known instant (see Timing Constraints).
- **`OS` handling:** `OS` stays 1 until cleared by command; `set_datetime` clears it by writing `Seconds` with bit 7 = 0. If it reads 1 again the oscillator is not running (supply or crystal problem). The datasheet reset value of `Seconds` has `OS` = 1.
- **`AF` / `TF` write semantics:** writing 0 clears the flag, writing 1 leaves it unchanged (hardware AND). Every read-modify-write of `Control_2` must write the flag bits it does not intend to clear as 1; `poll_interrupt` writes 0 only to the flags it saw set.
- **Alarm enable polarity is inverted:** `AEN_x` = 0 enables a field, 1 disables it — `set_alarm`'s `None`-means-disabled convention keeps this out of the public API. The alarm fires only on the increment that makes all enabled fields match; if the time is set to a matching value, the alarm does not fire until the next match. Writing the alarm registers does not clear `AF`; the driver clears it explicitly.
- **Timer details:** loading T = 0 stops the timer; T = 1–255 are valid. When unused, set `TCF` = `11` (1/60 Hz) for power saving. Changing `Timer_value` without first clearing `TE` can corrupt the first period. Reading the countdown while it runs can return a changing value; read twice and compare. With `TI_TP` = 0 the countdown timer stops after the first countdown and `INT` follows `TF`; with `TI_TP` = 1 it keeps looping and `INT` pulses (1/8192 s for T = 1 on the 4.096 kHz clock, 1/4096 s for T > 1; 1/128 s or 1/64 s on the 64 Hz clock; 1/64 s on the 1 Hz and 1/60 Hz clocks — Table 37).
- **Minute and half-minute interrupts share `TF` with the timer:** a minute interrupt on top of a half-minute interrupt is indistinguishable; they must only be used with offset `MODE` = 0. `SOURCE_MINUTE`, `SOURCE_HALF_MINUTE` and `SOURCE_TIMER` all report as `SOURCE_TIMER` in the status mask.
- **Offset Calibration Workflow:** measure the frequency on CLKOUT (set a 32768 Hz output), `Eppm = 1e6 × (1/32768 − 1/f_meas) / (1/f_meas)`, then `offset = round(Eppm / 4.34)` for normal mode or `round(Eppm / 4.069)` for course mode; accuracy ±2 ppm (0.5 LSB). A positive offset value corrects a fast clock; the sign convention follows the datasheet's worked example (Figures 11–12: a clock measured 14.648 ppm fast gives offset +3, leaving about 1.6 ppm error).
- **`CIE` correction interrupt:** exposed only as `enable_interrupt(SOURCE_CORRECTION)` for bench calibration; the pulses are 1/64 s (normal mode) or 1/1024 s (course mode) wide on `INT`.
- **CLKOUT:** push-pull, enabled at power-on at 32.768 kHz (which costs current on a battery device — `disable_clock_output()` is the usual first call); `STOP` = 1 forces frequencies below 8 kHz low; CLKOUT stays low when `COF` = `111` or `CLKOE` is low. `CLKOUT` is a separate pin from `INT`, so alarm / timer interrupts and the clock output can be used together.
- **Software reset resets everything:** the `0x58` write to `Control_1` sets *all* registers to their Table 7 values, including the time (2000-01-01 00:00:00, `OS` = 1), unlike the PCF8523. The datasheet requires a software reset after power-up only when VDD did not start at 0 V; run it before `set_datetime`, never as a routine. Re-initialise with a `STOP` and `START` afterwards.
- **`EXT_TEST` is not exposed:** the external-clock test mode turns CLKOUT into an input and is for board test only.
- **12.5 pF load capacitor:** choose `CAP_SEL` to match the crystal's specified load capacitance (7 pF reset value).
- **Not covered:** `EXT_TEST` test mode, 12-hour mode.
- **Siblings:** the PCF85063A is **not** register-compatible with the PCF8523 (different address, different registers) and is a close relative of the PCF8563 (same address `0x51`, different register layout and extra offset / RAM registers); no compatibility is assumed. It shares address `0x51` with I²C EEPROMs (`0x50`–`0x57`); with no identity register discovery cannot tell them apart.
- **Datasheet revision:** the committed datasheet is NXP PCF85063A Rev. 7.3 (14 July 2026), 58 pages, supplied by URL in the issue.

## Sigrok Decoder

Decoder `pcf85063a` (`sigrok/pcf85063a/`), input `['i2c']`. Matches the fixed address `0x51` and tracks the register pointer (auto-increment, wraps at `0x11` → `0x00`) across multi-byte transactions.

| Row | Annotation | Meaning |
|-----|------------|---------|
| Data | `data` | Register read / write decoded per field: BCD time and date (`0x04`–`0x0A`, with the `OS` flag), alarm registers with active-low enable decode (`0x0B`–`0x0F`), `Offset` (two's complement value in LSB and ppm for the current mode), `Timer_value`, `RAM_byte` |
| Status | `status` | `Control_1`, `Control_2` and `Timer_mode` reads / writes decoded to their named bit fields and flags (`STOP`, `SR`, `CIE`, `CAP_SEL`, `AIE`, `AF`, `MI`, `HMI`, `TF`, `COF` frequency, `TCF`, `TE`, `TIE`, `TI_TP`) |
| Timing | `timing` | `time_access_start` / `time_access_done` marker pair, shaped per `specs/sigrok_annotations.md`'s Variable-Length Annotation Convention: start at the `START` condition of any transaction whose accessed register range includes an address in `0x04`–`0x0A`; end at that same transaction's `STOP` condition |
| Warnings | `warning` | Access to an undefined register address (`0x12`+, a read past `0x11` wraps); a software-reset write (`Control_1` = `0x58`) noted as "resets time"; a 12-hour mode write |
