# Chip Spec: PCF8573

**Manufacturer:** NXP Semiconductors (Philips Semiconductors)  
**Datasheet:** `datasheets/rtc/pcf8573.pdf` (PCF8573 product specification, 1997 Mar 28)  
**Category:** rtc  
**Transports:** I²C

## Overview

The PCF8573 is a low-threshold CMOS clock/calendar with a power-fail detector, driven by a 32.768 kHz crystal. Its time counter holds **minutes, hours, days and months** (BCD; no seconds, weekday or year register) and a 24-bit **alarm register** (minutes, hours, days, months) is compared with the time counter once per minute. Three flags — `COMP` (alarm match), `NODA` (compare hours/minutes only, ignoring the date) and `POWF` (power failure, latched) — are readable and clearable over I²C; `SEC`, `MIN` and `COMP` are also pulse outputs and `FSET` outputs 128 Hz for crystal trimming. The clock supply (VDD − VSS1, 1.1 V min.) is separate from the interface supply (VDD − VSS2, 2.5–6 V), so the clock keeps running while the interface is unpowered. This is an old Philips part; the datasheet is the 1997 specification.

## Transport Configuration

### I²C
- **Address:** `1101 0 A1 A0` → `0x68`–`0x6B` (A0, A1 tied to VSS/VDD; up to four per bus)
- **Max clock:** 100 kHz (standard mode)
- **Protocol:** after the address byte a **mode-pointer byte** `0 C2 C1 C0 0 B2 B1 B0` follows (control nibble in bits 6:4, address nibble in bits 2:0; bit 7 and bit 3 must be 0, otherwise the mode pointer is not acknowledged), then data bytes. With control = *execute address* the address bits B1:B0 auto-increment after every data byte (no carry into B2). Reads return data for the current mode pointer (set by a preceding write; the control nibble persists until re-written). Used through `RegisterConnection` (`reg_bytes` = 1) with the mode-pointer byte as the register argument
- **Identity register:** none (`"id_probe": null` in `registry/chips.json`); the address range overlaps DS3231, PCF8523, BQ32000 (`0x68`), MPU-6050 and others
- **Probe safety:** `write_sensitive` — the first byte after the address is a mode pointer that can reset the prescaler (`0x20`), adjust the time (`0x30`) or change the NODA/COMP flags (`0x40`–`0x60`)

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| A0, A1 | — | address select |
| OSCI, OSCO | — | 32.768 kHz crystal (trimmer between OSCI and VDD) |
| FSET | — | 128 Hz output for crystal adjustment |
| SEC | — | 1 Hz output (1:1 mark-space); falling edge triggers MIN |
| MIN | — | 1/60 Hz output; its falling edge advances the minute counter |
| COMP | high (flag set) | alarm comparator output; also readable as the COMP flag |
| EXTPF, PFIN | — | power-fail selection: `EXTPF = 0, PFIN = 0` power fail sensed internally (VTH1 ≈ 1.2 V), `1 / 0` externally (PFIN low = power fail), `1 / 1` none, `0 / 1` test mode |
| VDD, VSS1, VSS2 | — | VDD − VSS1 clock supply 1.1 V min. (1.5 V typ.); VDD − VSS2 interface supply 2.5–6 V; on-chip power-on reset when VDD − VSS2 < VTH2 (≈ 2.0 V) |
| SDA, SCL | — | I²C; pull-ups required |

## Register Map

Time counter, alarm register and flags are addressed through the mode-pointer byte.

### Mode-pointer byte

| Bits | Name | Description |
|------|------|-------------|
| 7 | — | must be 0 |
| 6:4 | C2:C0 | Control: `000` execute address (data transfer), `001` read control/status flags, `010` reset prescaler incl. seconds counter (no carry to minutes), `011` time adjust (seconds < 30: no carry, i.e. max. −30 s; ≥ 30: carry, i.e. max. +30 s), `100` reset NODA, `101` set NODA, `110` reset COMP, `111` not used |
| 3 | — | must be 0 |
| 2:0 | B2:B0 | Address (only for *execute address*): `000` time hours, `001` time minutes, `010` time days, `011` time months, `100` alarm hours, `101` alarm minutes, `110` alarm days, `111` alarm months |

Only *execute address* is followed by data bytes; the other controls are complete after the mode-pointer byte (the chip acknowledges data only for control `000`).

### Data bytes (BCD)

| Field | Bits | Range |
|-------|------|-------|
| hours | 6 (`0 0 T T U U U U`) | 00–23 |
| minutes | 7 (`0 T T T U U U U`) | 00–59 |
| days | 6 | 01–28/29/30/31 |
| months | 5 | 01–12 |

### Flags byte (control `001`, read)

| Bit | Name | Description |
|-----|------|-------------|
| 7:5 | — | 0 |
| 4 | m | level of the MIN output |
| 3 | s | level of the SEC output |
| 2 | NODA | `1` = compare hours/minutes only (no date); undefined until first set or reset |
| 1 | COMP | alarm flag, set 4 ms after the falling edge of MIN when the alarm register equals the time counter (once per minute); latched, cleared by control `110` |
| 0 | POWF | power-fail flag, latched; cleared by a write with *execute address* |

## Initialization Sequence

1. Power up the clock supply (VDD − VSS1 ≥ 1.1 V) with the crystal fitted; the interface supply VDD − VSS2 ≥ 2.5 V. After a power failure `POWF` = 1 and the counters are undefined.
2. Read the flags (mode pointer `0x10`, 1 byte). If `POWF` = 1, write the time counter (execute address `0x00`: hours, minutes, days, months in one transfer — this also clears `POWF`), then reset the prescaler (`0x20`) at the moment the seconds should start from 0.
3. Set `NODA` (`0x50` or `0x40`) according to whether the alarm compares the date.
4. Read the time: write `0x00`, then read 4 bytes (hours, minutes, days, months).

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `COMP` output (also the `COMP` flag); active high while the flag is set |
| Level | 1 (single fixed condition) |
| Condition | alarm register equals the time counter (evaluated once per minute) |
| Clear mechanism | mode-pointer control `110` (reset COMP) |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on the COMP output (rising edge) via `connection.int_pin` (or `int_pin`), otherwise a 1 s polling task calling `poll_interrupt`; `callback(flags)` |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> bool` | Reads the flags; if `COMP` is set clears it and returns `True` |

## Implementation Stages

### Minimal

Goal: read and set the clock; no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Stores the `RegisterConnection` (`reg_bytes` = 1); no bus access |
| `get_time` | — | `(month, day, hour, minute)` | Mode pointer `0x00`, one 4-byte read (hours, minutes, days, months, BCD) |
| `set_time` | `month, day, hour, minute` | — | One execute-address write (`0x00` + 4 BCD bytes), then reset prescaler (`0x20`) so the seconds restart at 0; also clears `POWF`; validates ranges |

**Sensible defaults:** 24-hour time, seconds restart at 0 on `set_time`, no alarm use.

**Additional configuration options:** alarm register, `NODA`, leap-day correction, time adjustment.

## Data Conversion

```
bcd(v)       = ((v // 10) << 4) | (v % 10)
hours        = bcd_to_int(byte & 0x3F)
minutes      = bcd_to_int(byte & 0x7F)
days         = bcd_to_int(byte & 0x3F)
months       = bcd_to_int(byte & 0x1F)
```

There is no year register; the application must track the year and leap years. In February of a leap year the day counter rolls 28 → 01, so software must write day 29 directly (`set_day(29)`) in a leap year before the counter rolls over from 28 February.

## Timing Constraints

| Constraint | Value |
|------------|-------|
| COMP flag set | 4 ms after the falling edge of MIN, once per minute |
| Power-on reset threshold (interface) | VTH2 ≈ 2.0 V (1.5–2.5 V) |
| Power-fail threshold (internal) | VTH1 ≈ 1.2 V (1.0–1.4 V) |
| I²C clock | ≤ 100 kHz; tBUF/tSU;STA 4.7 µs, tHD;STA/tHIGH 4.0 µs |

**Conformance:** the 4 ms COMP delay is referenced to the MIN pin edge (not bus-visible) and the others are supply thresholds or clock-rate limits, so `specs/rtc/pcf8573_timing.conf` defines no checks.

## Implementation Notes

- **Mode-pointer byte** must have bits 7 and 3 equal 0; otherwise it is not acknowledged. Controls other than *execute address* take no data bytes — a following data byte is not acknowledged.
- **Seconds are not readable.** The `s` bit (SEC level) in the flags byte is only the instantaneous level of the 1 Hz output; use `reset_prescaler` right when the time is set to define second 0.
- **No year/weekday:** the driver exposes month/day/hour/minute only; keep the year in the application (and the leap-day via `set_day`).
- **POWF** is latched and cleared only by a write with *execute address*; after power loss the counters and `NODA` are undefined.
- **Alarm** is compared once per minute; with `NODA` set only hours and minutes are compared.
- **Dual supply:** the clock runs from VDD − VSS1 (≥ 1.1 V); the interface needs VDD − VSS2 ≥ 2.5 V. With the interface supply absent the SEC/MIN/COMP outputs lose drive.
- **Crystal trimming:** use the 128 Hz FSET output (not the crystal pins) to trim the oscillator.
- **Address overlap:** `0x68`–`0x6B` overlaps DS3231, PCF8523 and BQ32000 (`0x68`), MPU-6050/9250 and ITG3200 (`0x68`/`0x69`); the PCF8573 has no ID register, so probing is unsafe.
- **Datasheet vintage:** the supplied datasheet is the 1997 Philips specification; the part is not recommended for new designs.

## Sigrok Decoder

Decoder id `pcf8573`, input `['i2c']`. Matches I²C addresses `0x68`–`0x6B`. Annotates the mode-pointer byte (control and address nibbles by name), decodes BCD time/alarm bytes as hours, minutes, days and months, the flags byte (NODA, COMP, POWF and the SEC/MIN levels), and warns when bit 7 or bit 3 of the mode pointer is set or a data byte follows a control that takes none. No timing annotation pair is emitted.
