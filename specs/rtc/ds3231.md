# Chip Spec: DS3231

**Manufacturer:** Analog Devices (Maxim Integrated)
**Datasheet:** `datasheets/rtc/ds3231.pdf`
**Category:** rtc
**Transports:** I²C

## Overview

The DS3231 is a low-cost, extremely accurate I²C real-time clock (RTC) with an integrated
temperature-compensated crystal oscillator (TCXO) and crystal, in a single 16-pin SO
package — no external crystal, load capacitors, or trim components required. The TCXO
holds ±2 ppm accuracy (±3.5 ppm over the full industrial range), automatically measuring
and correcting the oscillator every 64 seconds using an on-chip digital temperature sensor,
whose 10-bit reading (±3 °C accuracy) is also exposed to the host as a bonus. The chip
maintains seconds, minutes, hours, day, date, month, and year (with automatic leap-year and
short-month correction, valid up to year 2100) in battery-backed BCD registers, provides two
independently programmable time-of-day/date alarms, and a selectable square-wave/interrupt
output pin (`INT/SQW`). A `VBAT` input keeps the clock running through main-power loss.

## Transport Configuration

### I²C
- **Address:** `0x68` (fixed — no address pins; only one device per bus)
- **Max clock:** 400 kHz (Fast mode); also supports 100 kHz (Standard mode)

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| INT/SQW | low, open-drain | requires external pull-up; outputs either a square wave (`INTCN`=0, default) or an alarm interrupt (`INTCN`=1) — the two functions share one physical pin and are mutually exclusive |

`RST` (pushbutton reset / power-fail indicator) and `32kHz` (free-running TCXO output) are
independent open-drain pins with no register control relevant to this driver; they are not
wired to the `Connection` and are not part of the API.

## Register Map

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | SECONDS | R/W | undefined | Seconds, BCD `00`–`59` |
| `0x01` | MINUTES | R/W | undefined | Minutes, BCD `00`–`59` |
| `0x02` | HOURS | R/W | undefined | Hours, BCD; bit 6 selects 12-/24-hour mode |
| `0x03` | DAY | R/W | undefined | Day-of-week counter, `1`–`7` (see Implementation Notes) |
| `0x04` | DATE | R/W | undefined | Day-of-month, BCD `01`–`31` |
| `0x05` | MONTH_CENTURY | R/W | undefined | Bits 4:0 month BCD `01`–`12`; bit 7 century flag |
| `0x06` | YEAR | R/W | undefined | Year within century, BCD `00`–`99` |
| `0x07` | ALARM1_SECONDS | R/W | undefined | Bit 7 = `A1M1` mask; bits 6:0 seconds BCD |
| `0x08` | ALARM1_MINUTES | R/W | undefined | Bit 7 = `A1M2` mask; bits 6:0 minutes BCD |
| `0x09` | ALARM1_HOURS | R/W | undefined | Bit 7 = `A1M3` mask; hour field encoded as `0x02` |
| `0x0A` | ALARM1_DAY_DATE | R/W | undefined | Bit 7 = `A1M4` mask; bit 6 = `DY/DT`; bits 5:0 day (`1`–`7`) or date (`01`–`31`) BCD |
| `0x0B` | ALARM2_MINUTES | R/W | undefined | Bit 7 = `A2M2` mask; bits 6:0 minutes BCD |
| `0x0C` | ALARM2_HOURS | R/W | undefined | Bit 7 = `A2M3` mask; hour field encoded as `0x02` |
| `0x0D` | ALARM2_DAY_DATE | R/W | undefined | Bit 7 = `A2M4` mask; bit 6 = `DY/DT`; bits 5:0 day/date BCD |
| `0x0E` | CONTROL | R/W | `0x1C` | `EOSC`, `BBSQW`, `CONV`, `RS2`, `RS1`, `INTCN`, `A2IE`, `A1IE` |
| `0x0F` | CONTROL_STATUS | R/W | `0x08`* | `OSF`, `EN32kHz`, `BSY`, `A2F`, `A1F` (*`A2F`/`A1F` undefined at power-on) |
| `0x10` | AGING_OFFSET | R/W | `0x00` | Two's-complement oscillator trim code |
| `0x11` | TEMP_MSB | R | `0x00` | Integer part of temperature, °C, two's-complement |
| `0x12` | TEMP_LSB | R | `0x00` | Bits 7:6 = fractional °C (0.25 resolution); bits 5:0 unused |

The address pointer auto-increments on every byte and wraps from `0x12` back to `0x00`.
Reads of the time/date registers (`0x00`–`0x06`) go through an internal secondary buffer
synchronized on every `START`/rollover, so a multi-byte read is torn-free without needing
a read-verify-reread loop.

### Bit Fields

#### `HOURS` (`0x02`, and `ALARM1_HOURS`/`ALARM2_HOURS`)

| Bits | Name | Description |
|------|------|-------------|
| 6 | 12/24 | `0` = 24-hour mode, `1` = 12-hour mode |
| 5 | AM/PM or 20-HOUR | 12-hour mode: `0`=AM, `1`=PM. 24-hour mode: bit 5 of the tens-of-hours field (20–23 h) |
| 4 | 10-HOUR | Tens-of-hours BCD digit (bit meaning depends on bit 6/5 above) |
| 3:0 | HOUR | Units-of-hours BCD digit |

This driver always operates in 24-hour mode — `set_datetime`/`set_alarm1`/`set_alarm2`
write bit 6 = `0` and encode `hour` 0–23 directly; 12-hour/AM-PM mode is never used or
exposed.

#### `MONTH_CENTURY` (`0x05`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | CENTURY | Toggles every time `YEAR` rolls over from `99` to `00`; combine with `YEAR` for a `year = 1900/2000/2100 + YEAR` computation if a >100-year range must be disambiguated. This driver assumes the 2000–2099 century and ignores this bit on read, matching every other two-digit-year RTC driver in this repository. |
| 6:5 | — | Unused, read as `0` |
| 4:0 | MONTH | BCD `01`–`12` (bit 4 = tens digit, only ever `0` or `1`) |

#### `ALARM1_DAY_DATE` (`0x0A`) / `ALARM2_DAY_DATE` (`0x0D`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | A1M4/A2M4 | Mask bit — see Alarm Mask Bits table below |
| 6 | DY/DT | `0` = bits 5:0 hold day-of-month (date match), `1` = bits 5:0 hold day-of-week (day match) |
| 5:0 | DAY or DATE | BCD day-of-week (`1`–`7`) or day-of-month (`01`–`31`), per `DY/DT` |

#### Alarm Mask Bits (Table 2 of the datasheet)

| DY/DT | A1M4 | A1M3 | A1M2 | A1M1 | Alarm 1 rate |
|-------|------|------|------|------|--------------|
| X | 1 | 1 | 1 | 1 | Once per second |
| X | 1 | 1 | 1 | 0 | When seconds match |
| X | 1 | 1 | 0 | 0 | When minutes, seconds match |
| X | 1 | 0 | 0 | 0 | When hours, minutes, seconds match |
| 0 | 0 | 0 | 0 | 0 | When date, hours, minutes, seconds match |
| 1 | 0 | 0 | 0 | 0 | When day, hours, minutes, seconds match |

| DY/DT | A2M4 | A2M3 | A2M2 | Alarm 2 rate |
|-------|------|------|------|--------------|
| X | 1 | 1 | 1 | Once per minute (at `00` seconds) |
| X | 1 | 1 | 0 | When minutes match |
| X | 1 | 0 | 0 | When hours, minutes match |
| 0 | 0 | 0 | 0 | When date, hours, minutes match |
| 1 | 0 | 0 | 0 | When day, hours, minutes match |

Both tables are collapsed into a single `match_mode` parameter on `set_alarm1`/`set_alarm2`
(see Implementation Stages) so callers never manipulate the mask/`DY/DT` bits directly.

#### `CONTROL` (`0x0E`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | EOSC | Active-low enable oscillator on `VBAT`. `0`=oscillator continues on battery (default); `1`=oscillator stops when switched to `VBAT`. Always running while `VCC` is valid regardless of this bit. |
| 6 | BBSQW | Battery-backed square-wave enable — `1` keeps `INT/SQW` driven while running on `VBAT` (only meaningful with `INTCN`=0 and `A1IE`=`A2IE`=0) |
| 5 | CONV | Write `1` to force an immediate temperature conversion; self-clears (with `BSY`) when done |
| 4:3 | RS2:RS1 | Square-wave output frequency: `00`=1 Hz, `01`=1.024 kHz, `10`=4.096 kHz, `11`=8.192 kHz (default) |
| 2 | INTCN | `0`=`INT/SQW` outputs the square wave (default); `1`=`INT/SQW` outputs alarm interrupts |
| 1 | A2IE | Alarm 2 interrupt enable |
| 0 | A1IE | Alarm 1 interrupt enable |

#### `CONTROL_STATUS` (`0x0F`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | OSF | Oscillator Stop Flag — set to `1` whenever the oscillator has stopped (first power-up, insufficient `VCC`/`VBAT`, `EOSC` disabled on battery, or external disturbance); sticky until written `0` |
| 6:4 | — | Unused, read as `0` |
| 3 | EN32kHz | `1` enables the separate `32kHz` output pin (default) |
| 2 | BSY | Set while a TCXO/temperature-conversion is in progress |
| 1 | A2F | Alarm 2 Flag — set on a match regardless of `INTCN`/`A2IE`; cleared by writing `0` |
| 0 | A1F | Alarm 1 Flag — set on a match regardless of `INTCN`/`A1IE`; cleared by writing `0` |

## Initialization Sequence

1. Construct the driver with a fixed-address (`0x68`) `Connection`.
2. Read the `CONTROL` register (`0x0E`) once to confirm the device answers on the bus — the
   DS3231 has no WHO_AM_I/identity register, so this doubles as the presence check.
3. No register writes are required at `init` time: `EOSC`=0 (oscillator running) and every
   other `CONTROL`/`CONTROL_STATUS` bit is already at a usable power-on default (see Register
   Map). Time/date register contents are undefined until the caller calls `set_datetime()` —
   `init()` does not write them, and `get_datetime()` before the first `set_datetime()` call
   returns whatever was last written (or garbage, on a brand-new chip with no prior `VBAT`).

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `INT/SQW`, active-low, open-drain — requires external pull-up |
| Level | 2 (selectable sources) |
| Condition(s) | Alarm 1 match; Alarm 2 match |
| Clear mechanism | write `0` to the corresponding flag bit (`A1F`/`A2F`) in `CONTROL_STATUS` (`0x0F`) |

### Interrupt sources

| Constant | Value | Condition |
|----------|-------|-----------|
| `SOURCE_ALARM1` | `0x01` | Alarm 1 registers matched the current time/date |
| `SOURCE_ALARM2` | `0x02` | Alarm 2 registers matched the current time/date |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback)` | Subscribe; callback receives status int (see Status register bit layout). Also sets `INTCN`=1 so `INT/SQW` carries alarm interrupts instead of the square wave. |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Read `CONTROL_STATUS`; clear `A1F`/`A2F` (leaving `OSF`/`EN32kHz`/`BSY` untouched); return the pre-clear byte, mask with `SOURCE_ALARM1`/`SOURCE_ALARM2` to test each source |
| `enable_interrupt` | `enable_interrupt(source)` | Set `A1IE` or `A2IE` for the given source, and set `INTCN`=1 |
| `disable_interrupt` | `disable_interrupt(source)` | Clear `A1IE` or `A2IE` for the given source |

### Status register bit layout

| Bit | Constant | Meaning |
|-----|----------|---------|
| 0 | `SOURCE_ALARM1` | Alarm 1 matched |
| 1 | `SOURCE_ALARM2` | Alarm 2 matched |

`A1F`/`A2F` latch on a match regardless of `INTCN`/`A1IE`/`A2IE`, so `poll_interrupt()` can
be used to observe alarm matches by polling even when `INT/SQW` is wired as a square wave
or not wired at all.

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits
everything and adds the rest.

### Minimal

Goal: expose the chip's primary use case — reading and setting the calendar clock, plus
the free on-chip temperature reading — with no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Confirms the device answers; makes no register writes |
| `get_datetime` | — | `(year, month, day, weekday, hour, minute, second)` (all int) | `year` is 2000–2099 (see `MONTH_CENTURY` bit field); `hour` is always 0–23; `weekday` is 1–7 (see Implementation Notes) |
| `set_datetime` | year, month, day, weekday, hour, minute, second | — | Writes all seven clock/calendar registers, forces 24-hour mode, and clears `OSF` (the time is now known-good) |
| `read_temperature` | — | float °C | Reads the last completed conversion from `TEMP_MSB`/`TEMP_LSB` — no wait, since the chip converts autonomously every 64 s and on power-up; may be up to 64 s stale |

**Sensible defaults:** 24-hour time format (enforced on every `set_datetime`); oscillator
continuously enabled on `VBAT` (`EOSC`=0, power-on default); alarms and `INT/SQW` left at
their power-on state (`A1IE`=`A2IE`=0, `INTCN`=0 but no square wave is driven since `BBSQW`=0
and nothing enables it) — the pin is inert until `Full` configures it.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `get_alarm1` | — | `(second, minute, hour, day_or_date, is_day_of_week, match_mode)` | Decodes `0x07`–`0x0A` |
| `set_alarm1` | second, minute, hour, day_or_date, is_day_of_week, match_mode | — | `match_mode` selects one of the 6 rows of the Alarm 1 mask table; `day_or_date`/`is_day_of_week` are ignored for the first 4 (mask-only) modes |
| `get_alarm2` | — | `(minute, hour, day_or_date, is_day_of_week, match_mode)` | Decodes `0x0B`–`0x0D` |
| `set_alarm2` | minute, hour, day_or_date, is_day_of_week, match_mode | — | `match_mode` selects one of the 5 rows of the Alarm 2 mask table |
| `enable_square_wave` | rate_hz=8192, battery_backed=False | — | Sets `INTCN`=0, `RS2:RS1` per `rate_hz` (1/1024/4096/8192), `BBSQW`=`battery_backed`. Mutually exclusive with alarm interrupts — overrides whichever `enable_interrupt`/`enable_square_wave` call happened last, since both share `INTCN` |
| `disable_square_wave` | — | — | Sets `INTCN`=1, returning the pin to interrupt mode |
| `is_32khz_enabled` | — | bool | Reads `EN32kHz` |
| `enable_32khz_output` | — | — | Sets `EN32kHz`=1 |
| `disable_32khz_output` | — | — | Clears `EN32kHz`=0 |
| `oscillator_stopped` | — | bool | Reads `OSF` — `True` means timekeeping data may be invalid since the last check |
| `clear_oscillator_stopped` | — | — | Writes `0` to `OSF` only, preserving `EN32kHz` |
| `enable_battery_oscillator` | — | — | Clears `EOSC` — oscillator keeps running on `VBAT` (power-on default) |
| `disable_battery_oscillator` | — | — | Sets `EOSC` — oscillator stops when switched to `VBAT`, saving battery current |
| `force_temperature_conversion` | — | — | Sets `CONV`, polls `BSY` until clear (max 200 ms, see Timing Constraints), then behaves like `read_temperature` for the caller's next read |
| `get_aging_offset` | — | int | Raw signed 8-bit trim code from `AGING_OFFSET` (see Implementation Notes) |
| `set_aging_offset` | offset (int, −128 to 127) | — | Writes `AGING_OFFSET` |
| *(interrupt API)* | | | See Interrupt section above |

**Additional configuration options:** alarm 1/2 match mode and target time/date, square-wave
output enable/rate/battery-backed behavior, 32 kHz output enable, oscillator battery-backed
behavior, forced temperature conversion, and aging-offset trim.

## Data Conversion

```
bcd_to_int(b)  = (b >> 4) * 10 + (b & 0x0F)
int_to_bcd(v)  = ((v // 10) << 4) | (v % 10)

temperature_c = msb_signed + (lsb >> 6) * 0.25
    # msb_signed: two's-complement value of TEMP_MSB (0x11)
    # lsb:        TEMP_LSB (0x12); only bits 7:6 carry the 0.25 °C fractional step
```

Node name: `periph-ds3231`
Package: `node-red-contrib-periph-rtc`

| Input trigger | Output `msg.payload` fields | Notes |

Config panel fields:
- **I²C bus** — bus number (e.g., `1` for `/dev/i2c-1`); no address field, the DS3231's
  address is fixed
- **Alarm 1 / Alarm 2** — optional enable checkbox per alarm, match-mode dropdown (mirrors
  the mask tables above), and target time/date fields; enabling either wires up
  `enable_interrupt`
- **Square wave** — enable checkbox + rate dropdown (1 Hz / 1.024 kHz / 4.096 kHz /
  8.192 kHz); mutually exclusive with the alarm checkboxes in the panel UI, matching the
  shared `INTCN` bit

### Demo flow

An Inject node fires every 10 s, triggering the `periph-ds3231` node to read and log the
current date/time and temperature. A second, one-shot Inject node sends
`msg.payload.datetime` built from `Date.now()` to synchronize the RTC to the host clock on
deploy. The node is configured with Alarm 1 enabled in "once per minute" mode; each time it
fires, the node emits a separate `{ source: "alarm1" }` message that a Function node turns
into a "heartbeat" log line, demonstrating the interrupt-driven path alongside the polled
read.

## Examples

### Demo

A backup-clock module for a data logger. On startup, the demo checks
`oscillator_stopped()`; if it returns `True` (fresh chip, or the coin cell died and was just
replaced), it reseeds the clock from a fixed reference timestamp with `set_datetime` (which
also clears `OSF`) rather than trusting stale/garbage registers. It then configures Alarm 1
to match once per minute (`match_mode` = "once per minute", the all-mask-bits-set row) and
Alarm 2 to match once per hour (`match_mode` = "hours and minutes match", `minute`=0),
enables both via `enable_interrupt`, and subscribes with `on_interrupt`. The callback masks
the returned status against `SOURCE_ALARM1`/`SOURCE_ALARM2`, and for each source that fired
prints the current date/time plus `read_temperature()` — a one-line "log entry". Both alarms
repeat automatically (their registers are never rewritten), so the demo just runs for a
fixed number of minute-alarms then calls `disable_interrupt` for both sources and
`off_interrupt` before exiting.

## Timing Constraints

- **Temperature conversion (`temp_conversion_ready`):** typ. 125 ms, max 200 ms from
  `force_temperature_conversion()` writing `CONV`=1 until `BSY` reads `0`. This is the only
  host-triggerable, bus-observable delay in the chip — everything else below is either
  autonomous hardware behavior with no I²C signature, or generic I²C bus AC timing already
  covered by `specs/transport_i2c.md`.
- Oscillator startup after first power/`VBAT` application: typically <1 s, fully autonomous
  — the I²C interface is accessible immediately regardless, so no driver-side wait is needed.
- Oscillator Stop Flag detection delay (`tOSF`): max 100 ms — hardware-internal, not
  driver-actionable.
- `RST`/pushbutton timing (debounce ≤250 ms, reset active time ≤250 ms) applies to the `RST`
  pin, which this driver does not wire up (see Pin Configuration) — informational only.

## Implementation Notes

- All clock/calendar/alarm register fields are BCD, not binary — every read/write goes
  through `bcd_to_int`/`int_to_bcd` (see Data Conversion).
- This driver always operates the `HOURS` registers in 24-hour mode; the chip's native
  12-hour/AM-PM encoding is never written or exposed.
- The `DAY` register (`0x03`) is a free-running 1–7 counter with no hardware-enforced
  meaning — the datasheet only requires it to be sequential and user-defined. This driver
  defines `1`=Monday … `7`=Sunday (ISO 8601) as its convention for `weekday` in both
  `get_datetime`/`set_datetime` and the alarm day-of-week fields.
- `INT/SQW` is one physical pin multiplexed by the `INTCN` bit — enabling alarm interrupts
  (`enable_interrupt`) and enabling the square wave (`enable_square_wave`) are mutually
  exclusive; whichever call happens last wins. `poll_interrupt()` still reports alarm matches
  correctly regardless of `INTCN`, since `A1F`/`A2F` latch independently of the pin's mode.
- `AGING_OFFSET` (`0x10`) is a two's-complement oscillator trim code, not a value with a
  fixed physical scale — its ppm-per-LSB effect is temperature-dependent (0.1 ppm/LSB
  typical at +25 °C per the datasheet's Electrical Characteristics, ranging 0.1–1.0 ppm/LSB
  across the operating range). It is exposed as a raw signed 8-bit integer rather than
  converted to a physical unit; most applications never need to touch it.
- Time/date and alarm register contents are undefined the first time `VCC`/`VBAT` is ever
  applied to a chip with no prior battery. Detect this with `oscillator_stopped()` rather
  than assuming `get_datetime()` returns anything meaningful before the first
  `set_datetime()` call.
- The chip has no WHO_AM_I/identity register and no soft-reset command; `init()` presence
  detection is a plain register read, and there is no reset sequence to run.

## Sigrok Decoder

Decoder `ds3231` (`sigrok/ds3231/`) stacks on the `i2c` decoder and recognizes the fixed
address `0x68`, tracking the register pointer (auto-increment, wraps at `0x12`→`0x00`)
across multi-byte transactions.

| Row | Annotation | Meaning |
|-----|------------|---------|
| Data | `data` | Register read/write decoded per field: BCD time/date (`0x00`–`0x06`), alarm registers with mask/`DY-DT` decode (`0x07`–`0x0D`), `CONTROL` bit fields (`0x0E`), `AGING_OFFSET` (`0x10`), temperature registers converted to °C (`0x11`–`0x12`) |
| Status | `status` | `CONTROL_STATUS` (`0x0F`) reads decoded to `OSF`/`EN32kHz`/`BSY`/`A2F`/`A1F` flag text |
| Timing | `timing` | `temp_conversion_ready` marker pair: start when `CONV` (bit 5 of a `CONTROL` write) is written `1`; end at the first subsequent `CONTROL_STATUS` read where `BSY` reads `0` |
| Warnings | `warning` | Access to an undefined register address (`0x13`+), or a write to a read-only temperature register |
