# Chip Spec: MCP7940N

**Manufacturer:** Microchip  
**Datasheet:** `datasheets/rtc/mcp7940n.pdf` (MCP7940N DS20005010F)  
**Category:** rtc  
**Transports:** I²C

## Overview

The MCP7940N is a low-power real-time clock/calendar for a 32.768 kHz crystal (or an external 32.768 kHz clock): seconds, minutes, hours (12- or 24-hour), day of week, date, month and year in BCD with automatic leap-year compensation (every year divisible by four is a leap year, valid to 2099), **two independent alarms** with selectable match fields, a multifunction pin (**MFP**: square wave output, alarm interrupt output or general-purpose output), **digital trimming** (≈ ±129 ppm in ≈ 1.017 ppm steps, fine or coarse mode), an **automatic battery switch-over** from VCC to **VBAT** (1.3–5.5 V, 1.5 V typ. trip) with a **power-fail time-stamp** (power-down and power-up minute/hour/date/month) and **64 bytes of battery-backed SRAM** at `0x20`–`0x5F`. VCC 1.8–5.5 V, I²C up to 400 kHz. The MCP7940N differs from the MCP7940M in the VBAT switch-over; neither contains an EEPROM (that is in the MCP79400 family).

## Transport Configuration

### I²C
- **Address:** `0x6F` (7-bit `1101111`; fixed; write byte `0xDE`, read byte `0xDF`)
- **Max clock:** 400 kHz
- **Identity register:** none (`registry/chips.json` entry has `"id_probe": null`; `0x6F` is also used by the MCP7941x family)
- **Probe safety:** `register_pointer` — a 1-byte write only sets the register pointer
- **Register addressing:** 1-byte register address (`RegisterConnection`, `reg_bytes = 1`); reads and writes auto-increment, the address wraps `0x1F` → `0x00` inside the RTCC register block (`0x00`–`0x1F`); the SRAM block `0x20`–`0x5F` is a separate block that wraps `0x5F` → `0x20` (it does not carry over into the RTCC registers)

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| MFP | `ALMPOL`-selectable, open-drain | Multifunction: square wave clock output (`SQWEN` = 1), alarm interrupt (`ALMxEN` = 1, `SQWEN` = 0) or general-purpose output (`OUT`); requires an external pull-up; the alarm output stays available on VBAT |
| X1, X2 | — | 32.768 kHz crystal, or X1 driven by an external clock when `EXTOSC` = 1 |
| VBAT | — | Backup supply 1.3–5.5 V (`VBATEN` must be set to use it) |
| VCC, VSS | — | 1.8–5.5 V supply |
| SDA, SCL | — | I²C; external pull-ups |

| Address | Name | Description |

| `0x04` | RTCDATE | Date tens (5:4) / ones (3:0), BCD |
| `0x05` | RTCMTH | `LPYR` (5, R), month tens (4) / ones (3:0), BCD |
| `0x06` | RTCYEAR | Year tens (7:4) / ones (3:0), BCD (00–99) |
| `0x07` | CONTROL | `OUT` (7), `SQWEN` (6), `ALM1EN` (5), `ALM0EN` (4), `EXTOSC` (3), `CRSTRIM` (2), `SQWFS[1:0]` (1:0) — reset `0x80` |
| `0x08` | OSCTRIM | `SIGN` (7), `TRIMVAL[6:0]` — reset `0x00` |
| `0x09` | — | Reserved |

| `0x10` | — | Reserved |
| `0x11`–`0x16` | ALM1SEC … ALM1MTH | Alarm 1: same layout (`ALM1MSK`, `ALM1IF`; `ALMPOL` read-only, mirrors alarm 0) |
| `0x17` | — | Reserved |
| `0x18`–`0x1B` | PWRDNMIN, PWRDNHOUR, PWRDNDATE, PWRDNMTH | Power-down time-stamp (minutes, hours, date, weekday + month) |
| `0x1C`–`0x1F` | PWRUPMIN, PWRUPHOUR, PWRUPDATE, PWRUPMTH | Power-up time-stamp (same layout) |
| `0x20`–`0x5F` | SRAM | 64 bytes of battery-backed general-purpose RAM |

### Bit Fields

#### `RTCSEC.ST` and the oscillator

`ST` = 1 starts the oscillator, 0 stops it. **A newly powered chip has the oscillator disabled**; set `ST` (together with the time) to start it. `RTCWKDAY.OSCRUN` (read-only) reads 1 when the oscillator is enabled **and running**, 0 if it stopped or is disabled.

#### `RTCHOUR`

Bit 6 `12/24`: 1 = 12-hour (bit 5 = `AM/PM`, 1 = PM; hour tens = bit 4; hours 1–12), 0 = 24-hour (hour tens = bits 5:4; 0–23). The drivers use 24-hour mode.

#### `RTCWKDAY`

`WKDAY` holds 1–7 (the meaning of the day numbers is user-defined; the drivers store `weekday + 1`, i.e. 1 = Sunday … 7 = Saturday, and expose 0–6 with Sunday = 0). `VBATEN` = 1 enables the VBAT input (reset 0: **no battery backup until set**). `PWRFAIL` = 1 means primary power was lost and the power-fail time-stamp registers were loaded; clear it in software (clearing resets the time-stamps to 0; it cannot be written to 1). **Writing `RTCWKDAY` always clears `PWRFAIL`**, so read it first when needed.

#### `CONTROL` (`0x07`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | OUT | MFP level in general-purpose output mode (`SQWEN` = 0 and both alarms disabled) |
| 6 | SQWEN | 1 = square wave clock output on MFP |
| 5 | ALM1EN | Alarm 1 enable |
| 4 | ALM0EN | Alarm 0 enable |
| 3 | EXTOSC | 1 = X1 driven by an external 32.768 kHz source |
| 2 | CRSTRIM | 1 = coarse trim mode (trim every 64 Hz cycle; with `SQWEN` the MFP outputs a trimmed 64 Hz) |
| 1:0 | SQWFS | With `SQWEN` = 1 and `CRSTRIM` = 0: `00` = 1 Hz, `01` = 4.096 kHz, `10` = 8.192 kHz, `11` = 32.768 kHz |

#### `OSCTRIM` (`0x08`)

`SIGN` = 1 adds clocks (slow clock), 0 subtracts clocks (fast clock). `TRIMVAL` n (0–127) adds/subtracts **2n clock cycles per minute** in fine mode (`CRSTRIM` = 0; ≈ 1.017 ppm per step, up to ≈ 129 ppm); in coarse mode (`CRSTRIM` = 1) the same `2n` cycles are applied 128 times per second. `TRIMVAL` = 0 disables trimming. Trimming also runs on the backup supply.

#### `ALMxWKDAY`, alarm registers

| Field | Meaning |
|-------|---------|
| `ALMPOL` (`ALM0WKDAY` bit 7) | MFP asserted level: 1 = high, 0 = low (alarm 1's copy is read-only) |
| `ALMxMSK[2:0]` (bits 6:4) | Match: `000` seconds, `001` minutes, `010` hours, `011` day of week, `100` date, `111` seconds + minutes + hours + weekday + date + month; `101`/`110` reserved |
| `ALMxIF` (bit 3) | Alarm flag, set by hardware on a match; **must be cleared in software** (if cleared while the condition still matches it sets again) |
| `WKDAY` (bits 2:0) | Weekday value for matching |

Alarm time values are BCD; invalid values give undefined operation; the alarm output remains active on VBAT.

## Initialization Sequence

1. Power-up: oscillator disabled (`ST` = 0, `OSCRUN` = 0), `VBATEN` = 0, `PWRFAIL` state from the power-fail logic, `CONTROL` = `0x80` (MFP high as GPO).
2. `set_datetime`: write `0x00`–`0x06` in one burst with `ST` = 1 and 24-hour mode; then (Full) set `VBATEN` to enable the battery.
3. Wait for `OSCRUN` = 1 (crystal start-up; poll up to 5 s, typically < 1 s).

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `MFP` in alarm mode (`ALMxEN` = 1, `SQWEN` = 0); polarity by `ALMPOL` |
| Level | 2 (two selectable alarm sources) |
| Condition(s) | The selected `ALMxMSK` fields of alarm 0 or alarm 1 match the time (`ALMxIF` set) |
| Clear mechanism | Write 0 to `ALMxIF` (preserve the other bits of `ALMxWKDAY`); a cleared flag re-sets while the match persists |

### Interrupt sources

| Constant | Value | Condition |
|----------|-------|-----------|
| `SOURCE_ALARM0` | `0x01` | Alarm 0 flag (`ALM0IF`, enabled by `ALM0EN`) |
| `SOURCE_ALARM1` | `0x02` | Alarm 1 flag (`ALM1IF`, enabled by `ALM1EN`) |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on MFP (edge per `ALMPOL`) via `connection.int_pin` (or `int_pin`), otherwise a 1 s polling task on `poll_interrupt`; `callback(flags)` receives the alarm bitmask |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Reads `ALM0WKDAY` / `ALM1WKDAY`, returns the `ALM0IF` / `ALM1IF` bitmask and clears the set flags |
| `enable_interrupt` / `disable_interrupt` | `(source)` | Set / clear `ALM0EN` / `ALM1EN` (with `SQWEN` forced 0) |

## Implementation Stages

### Minimal

Goal: read and set the clock; no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Reads `RTCSEC`/`RTCWKDAY` to confirm the chip answers; no writes |
| `get_datetime` | — | `(year, month, day, weekday, hour, minute, second)` | One burst read `0x00`–`0x06`; `year` 2000–2099, `hour` 0–23 (converts a 12-hour setting), `weekday` 0–6 with Sunday = 0 |
| `set_datetime` | `year, month, day, weekday, hour, minute, second` | — | Writes `0x00`–`0x06` in one transaction with `ST` = 1, 24-hour mode (`12/24` = 0), `WKDAY` = `weekday + 1` (preserving `VBATEN`; note that writing `RTCWKDAY` clears `PWRFAIL`); starts the oscillator |

**Sensible defaults:** 24-hour format, oscillator started by `set_datetime`, battery input **not** enabled (`VBATEN` untouched), alarms off, MFP left at the power-on GPO high.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `oscillator_running` | — | bool | `OSCRUN` |
| `start_oscillator` / `stop_oscillator` | — | — | `ST` (read-modify-write) |
| `enable_battery` | `on: bool` | — | `VBATEN` (preserves `WKDAY`; clears `PWRFAIL`) |
| `power_failed` | — | bool | `PWRFAIL` |
| `read_power_fail_times` | — | `{power_down, power_up}` | Each `(month, day, hour, minute)` from `0x18`–`0x1F` |
| `clear_power_fail` | — | — | Clears `PWRFAIL` (and the time-stamps) |
| `is_leap_year` | — | bool | `LPYR` |
| `set_alarm` | `index: int` (0/1), `second=None, minute=None, hour=None, weekday=None, date=None, month=None, match: str = "all"`, `active_high: bool = False` | — | Writes the alarm registers and `ALMxMSK` (`match` = `"seconds"`, `"minutes"`, `"hours"`, `"weekday"`, `"date"`, `"all"`), sets `ALMPOL`, clears `ALMxIF` and sets `ALMxEN` |
| `get_alarm` | `index: int` | dict | Decoded alarm registers and flags |
| `disable_alarm` | `index: int` | — | `ALMxEN` ← 0 |
| `alarm_flag` / `clear_alarm_flag` | `index: int` | bool / — | `ALMxIF` |
| `set_square_wave` | `frequency_hz: int \| None` (1, 4096, 8192, 32768, 64 (coarse), or `None` = off) | — | `SQWEN`, `SQWFS`, `CRSTRIM`, with both alarm enables cleared |
| `set_output` | `level: bool` | — | General-purpose output: `OUT` (only effective when `SQWEN` = 0 and both alarms are disabled) |
| `set_trim` | `ppm: float`, `coarse: bool = False` | — | `OSCTRIM` for the nearest achievable correction (≈ 1.017 ppm/step fine, ≈ 129 ppm max; positive ppm = add clocks / speed up); raises beyond the range |
| `get_trim` | — | float | Current trim in ppm |
| `use_external_clock` | `on: bool` | — | `EXTOSC` |
| `read_sram` | `address: int` (0–63), `length: int` | bytes | `0x20 + address` block read (no wrap beyond 63) |
| `write_sram` | `address: int`, `data: bytes` | — | Battery-backed RAM write |
| `on_interrupt` / `off_interrupt` / `poll_interrupt` / `enable_interrupt` / `disable_interrupt` | see Interrupt | | |

**Additional configuration options:** battery enable, two alarms (masks, polarity), MFP mode, trimming (fine/coarse), external clock, SRAM, power-fail time-stamps.

## Data Conversion

```
BCD: value = (reg >> 4) * 10 + (reg & 0x0F);   reg = ((value // 10) << 4) | (value % 10)

seconds = BCD(RTCSEC & 0x7F)      minutes = BCD(RTCMIN & 0x7F)
hours   = BCD(RTCHOUR & 0x3F) if 24-hour (bit 6 = 0)
        = BCD(RTCHOUR & 0x1F) % 12 + 12 * AMPM  if 12-hour (bit 6 = 1, bit 5 = PM)
weekday = ((RTCWKDAY & 0x07) - 1) % 7        (the driver stores weekday 0–6 with Sunday = 0 as register value weekday + 1, i.e. 1 = Sunday)
date    = BCD(RTCDATE & 0x3F)     month = BCD(RTCMTH & 0x1F)     year = 2000 + BCD(RTCYEAR)

trim:   fine   : step = 2 clocks / 60 s of 32768 Hz  = 1.0173 ppm;  ppm = (+1 if SIGN else -1) * TRIMVAL * 1.0173   (SIGN = 1 adds clocks: slow clock)
        coarse : same sign convention, 2*TRIMVAL clocks per 128 Hz period

power-fail time-stamp registers: minute, hour, date, (weekday<<5 | month) — BCD, same encoding as the time registers
```

## Timing Constraints

- **Oscillator start-up:** after `ST` is set the crystal needs time to start; `OSCRUN` signals when it runs (no datasheet bound in the extracted text; the drivers poll up to 5 s).
- **Backup switch-over:** the chip switches to VBAT when VCC falls below the power-fail trip voltage `VTRIP` (1.3–1.7 V, 1.5 V typ.); with VBAT 1.3 V the timekeeping current is ≤ 850 nA.
- **Alarm timing:** an alarm fires when its masked fields match at a one-second tick; clearing `ALMxIF` while the match persists re-sets it.
- **Power-fail time-stamps** are logged when VCC drops below `VTRIP` and when it returns, minute resolution; `PWRFAIL` must be cleared to log new stamps.
- **I²C:** ≤ 400 kHz — a clock-rate property, not an event-to-event delay.
- **Conformance:** none of these has a bus-decodable start/end annotation pair, so `specs/rtc/mcp7940n_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection:** `connection.read(0x00, 7)` / `connection.write(0x00, bytes)`; no chip-local `_read_reg`/`_write_reg`, no `bus_type` branch (see `specs/feature_register_access_design.md`).
- **Oscillator is off after power-up:** time never advances until `ST` is set; `set_datetime` sets it.
- **`VBATEN` is off by default:** without it the clock stops (and the time is lost) when VCC fails; enabling it also needs a battery on VBAT.
- **Writing `RTCWKDAY` clears `PWRFAIL`** (and the time-stamps are lost on clearing): read the time-stamps first, and prefer read-modify-write that knows about this side effect.
- **Alarm flags are not self-clearing**; clear them in software and note the re-set while the condition still matches.
- **Alarm polarity bit** lives in alarm 0's weekday register; alarm 1's copy is read-only.
- **MFP priority:** square wave (`SQWEN`) overrides the alarm interrupt output; with both alarms off and `SQWEN` = 0 it is a general-purpose output.
- **SRAM block** `0x20`–`0x5F` is separate from the registers; multi-byte transfers inside it wrap at `0x5F` → `0x20`.
- **Leap years:** every year divisible by 4 is a leap year (correct to 2099).
- **Datasheet:** Microchip MCP7940N DS20005010F, downloaded from `http://ww1.microchip.com/downloads/en/DeviceDoc/20005010F.pdf`.

## Sigrok Decoder

Decoder id `mcp7940n`, input `['i2c']`. Matches I²C address `0x6F`. Annotates register writes and pointer-set + read transactions by register name, decodes the BCD time/date as `YYYY-MM-DD hh:mm:ss`, `ST`, `OSCRUN`, `PWRFAIL`, `VBATEN`, `LPYR`, the `CONTROL` bits, the trim value in ppm, the alarm registers (match mode, flags, polarity), the power-fail time-stamps and SRAM accesses; warns on writes of `RTCWKDAY` that clear `PWRFAIL` unintentionally (observed as a write with bit 4 clear after a read that showed it set), on invalid BCD and on writes to reserved registers (`0x09`, `0x10`, `0x17`). No timing annotation pair is emitted.
