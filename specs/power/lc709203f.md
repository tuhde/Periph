# Chip Spec: LC709203F

**Manufacturer:** onsemi (ON Semiconductor)  
**Datasheet:** `datasheets/power/lc709203f.pdf` (LC709203F/D, Rev. 17, November 2020; attached to issue #268 — the Mouser URL in the issue is bot-protected)  
**Category:** `power`  
**Transports:** I²C

## Overview

The LC709203F ("Smart LiB Gauge") is a battery fuel gauge for a **single-cell lithium-ion / polymer** battery. It reports the relative state of charge (RSOC, 1 % and 0.1 % resolution) with the HG-CVR algorithm (current-voltage tracking with internal resistance) **without a sense resistor**, plus the cell voltage (±7.5 mV at 25 °C) and cell temperature (from the host or from an attached thermistor). It draws 3 µA in operational mode and 1 µA in sleep mode, supports a low-RSOC / low-voltage alarm on an open-drain ALARMB pin, detects battery insertion (power-on reset) and has two built-in battery profiles chosen by ordering code. The chip is powered **directly from the battery** (VDD 2.5–4.5 V) and talks I²C at up to 400 kHz; every transfer carries a **CRC-8** and the chip stretches the clock. Packages: WDFN8 (`LC709203FQH-0xTWG`) and WLCSP9 (`LC709203FXE-0xMH`).

## Transport Configuration

### I²C
- **Address:** `0x0B` (7-bit, fixed; the first byte on the wire is `0x16` for write, `0x17` for read). `0x0B` is also the Smart-Battery-System gauge address
- **Max clock:** 400 kHz; the chip **stretches the clock**
- **Identity register:** none usable (`0x11` IC Version returns an ID whose value the datasheet does not specify); `registry/chips.json` has `"id_probe": null`
- **Probe safety:** `register_pointer` — a 1-byte write only sends a command code (an incomplete write-word without data bytes and CRC is ignored: "when you do not add CRC-8, the written data become invalid"). A chip in sleep mode does not answer until woken (see Sleep / wake-up)
- **Register addressing:** 1-byte command code, 16-bit little-endian data (low byte first) plus a CRC-8 byte, handled with `RegisterConnection` (`reg_bytes = 1`): a register read is `connection.read(cmd, 3)` → `[low, high, crc]`, a write is `connection.write(cmd, [low, high, crc])`. The datasheet's read-word protocol is exactly write-cmd / repeated START / read 3 bytes, with a NACK on the last (CRC) byte
- **CRC-8 (ATM):** polynomial `x^8 + x^2 + x + 1` (`0x07`), initial value `0x00`, no reflection, no final XOR, computed over **every byte of the transaction starting with the slave address byte**:
  - read word: `0x16, cmd, 0x17, low, high` → CRC byte
  - write word: `0x16, cmd, low, high` → CRC byte
  - Examples from the datasheet: cell voltage 3778 mV (`0x0EC2`): `0x16 0x09 0x17 0xC2 0x0E` → `0x86`; write `0x55 0xAA` to command `0x09`: `0x16 0x09 0x55 0xAA` → `0x3B`
  - **Read without checking the CRC gives unreliable data; a write without a correct CRC is ignored.** The drivers always verify the CRC on reads (raise an error on mismatch, retry once) and always append it on writes

## Initialization Sequence

Power-on: when VDD exceeds VRR (2.4 V max) the chip releases reset and completes initialization within TINIT (90 ms max); all registers are at their initial values. The WDFN8 part (`QH`) then stays in operational mode; the WLCSP9 part (`XE`) enters **sleep mode** automatically TATS (≈ 1 s, max 1.2 s) after initialization. Datasheet starting flow (Figures 20/21):

1. Wait ≥ 90 ms after power-up (TINIT). If the chip may be asleep, wake it with an SDA low pulse (≥ 0.6 µs; the I²C start of a transaction suffices as the pulse, "it can be substituted by writing operational mode twice") and wait TWU ≤ 400 µs.
2. Write `0x15` ← `0x0001` (operational mode) — twice, ignoring a bus error on the first attempt, so the wake-up pulse is guaranteed.
3. Write `0x0B` ← APA for the battery (see Typical APA).
4. Write `0x12` ← profile (`0x0000` or `0x0001`) and wait TINIT (90 ms): this behaves like a battery insertion (re-initialization), and on `XE` parts the chip returns to sleep TATS later, so keep the host awake: write operational mode again afterwards.
5. Temperature source: **I²C mode** (`0x16` ← `0x0000`, then write `0x08` ← current temperature) or **thermistor mode** (`0x16` ← `0x0001`, `0x06` ← thermistor B constant).
6. If the first RSOC after reset is wrong, write `0x07` ← `0xAA55` (Initial RSOC; ≤ 1.5 ms) or `0x04` ← `0xAA55` (Before RSOC, uses the maximum voltage since reset release; do not use if the battery charged in that time).

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `ALARMB` — active-low, open-drain; requires an external pull-up |
| Level | 1 (single fixed output; the source is selected by thresholds, not by a source mask) |
| Condition(s) | RSOC below `0x13` threshold (when non-zero) **or** cell voltage below `0x14` threshold (when non-zero) |
| Clear mechanism | none to clear — the pin releases by itself when RSOC / VDD rises back above the threshold |

There is **no status register**: the host cannot tell which condition fired from the chip, nor read the pin state over I²C.

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on ALARMB (falling edge) via `connection.int_pin` (or `int_pin`), otherwise a 1 s polling task calling `poll_interrupt`; `callback(status)` receives a bitmask (`ALARM_RSOC = 0x01`, `ALARM_VOLTAGE = 0x02`) |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |
| `poll_interrupt` | `poll_interrupt() -> int` | Reads RSOC and cell voltage and evaluates them against the cached thresholds (`rsoc < alarm_rsoc` when enabled, `voltage < alarm_voltage` when enabled), returns the bitmask (0 = no alarm) |

The thresholds are cached by `set_alarm_rsoc` / `set_alarm_voltage` (reset values `8 %` and disabled assumed after `init`, read back from the chip in `init`).

## Data Conversion

```
word        = low | (high << 8)                       # data bytes on the wire: low, high, crc
voltage (V) = word / 1000                             # 1 mV/LSB, register 0x09
percent (%) = word / 10                               # ITE 0x0F, 0..1000 -> 0.0..100.0 %
rsoc (%)    = word                                    # 0x0D, 0..100
temp (°C)   = word / 10 - 273.15                      # 0x08, 0.1 K/LSB (0 °C = 0x0AAC = 2732)
temp word   = round((celsius + 273.15) * 10)          # write range 0x09E4 (-20 °C) .. 0x0D04 (+60 °C)

crc8(bytes) : poly 0x07, init 0x00, MSB first, no reflect, no xor-out
  read  CRC over [0x16, cmd, 0x17, low, high]
  write CRC over [0x16, cmd, low, high]

APA(capacity) = linear interpolation of Table 7 (Type-01/03): 100->0x08, 200->0x0B, 500->0x10,
                1000->0x19, 2000->0x2D, 3000->0x36 (clamped outside 100..3000 mAh)
alarm voltage word = round(volts * 1000)
```

## Timing Constraints

- **Initialization after power-up / battery insertion:** TINIT ≤ 90 ms from reset release (VDD > VRR = 2.4 V max) to operational mode (`QH`), or to the automatic sleep entry after TATS (`XE`).
- **Auto sleep (`XE` / WLCSP9 only):** TATS typ. 1 s (max 1.2 s) after initialization; `QH` does not auto-sleep.
- **Re-initialization after a `0x12` write:** TINIT ≤ 90 ms (like a battery insertion); the chip then runs in operational mode (or sleeps again after TATS on `XE`).
- **Initial RSOC:** ≤ 1.5 ms from the `0x07` write to the initialized RSOC.
- **Wake-up from sleep:** SDA low pulse ≥ 0.6 µs (TSP), I²C usable after TWU ≤ 400 µs; the wake-up condition expires 500 ms after the SDA falling edge (TWR1) and 500 ms after an I²C STOP (TWR2) — send the first command inside that window or pulse SDA again.
- **Time-out:** TTMO 9–11 (unit printed as "s", probably a datasheet typo) between ninth clock pulses resets the I²C state machine; the chip may then lose the transaction — restart from START.
- **Power:** operational 3 µA typ. (4.5 µA max), sleep 1 µA typ. (2 µA max); time measurement accuracy ±3.5 %, voltage accuracy ±7.5 mV at 25 °C (±20 mV over −20…+70 °C).
- **I²C:** TBUF ≥ 1.3 µs, THD:STA ≥ 1.1 µs, TLOW ≥ 1.3 µs, THIGH ≥ 0.6 µs, TSU:STA ≥ 0.6 µs at ≤ 400 kHz — clock-rate properties, not event-to-event delays.
- **Conformance:** none of these has a bus-decodable start/end annotation pair (TINIT and the RSOC initialization are not marked by any bus event), so `specs/power/lc709203f_timing.conf` defines no checks.

## Implementation Notes

- **CRC is mandatory.** Reads without checking the CRC are unreliable, writes without the correct CRC are silently ignored. The CRC covers the address bytes (`0x16`/`0x17`), so it cannot be computed from the data alone — use the helper `crc8_atm(bytes)` shared by the drivers (poly `0x07`, init `0x00`).
- **RegisterConnection mapping:** `connection.read(cmd, 3)` and `connection.write(cmd, [low, high, crc])` match the datasheet protocols exactly (write command, repeated START, read low/high/CRC with NACK on the CRC). No chip-local `_read_reg`/`_write_reg`, no `bus_type` branch (see `specs/feature_register_access_design.md`).
- **Clock stretching:** the chip stretches SCL; the host's I²C controller must tolerate it (Linux `i2c-dev` does; some bit-banged or slow MCU peripherals do not — use ≤ 100 kHz there).
- **Sleep and the first transaction:** a sleeping chip ignores I²C until woken by an SDA low pulse; the first transfer after sleep (or on an `XE` part ≈ 1 s after power-up) can fail or be lost. The driver's `init` and `wake` therefore write operational mode twice, ignoring an error on the first attempt; transfers are retried once on a CRC or bus error.
- **Operational mode on `XE` parts:** after power-up and after every `0x12` write the WLCSP9 part drops to sleep after TATS; the driver re-enters operational mode and tells users that charge counting stops in sleep.
- **Temperature:** in I²C mode the host must keep `0x08` current (update on > 1 °C change, range −20…+60 °C); the default 25 °C is used until written. In thermistor mode the chip reads TSENSE/TSW itself (resistor on TSW must equal the thermistor's resistance; set B via `0x06`; use APT `0x0C` to compensate a capacitor across the thermistor) and the `0x08` register must not be written.
- **APA and profile are battery-specific:** the Minimal default (`capacity_mah = 1000`, profile 1) fits a standard 3.7 V / 4.2 V LiPo on a `-01`/`-03` part. Other ordering codes map the profile bit to different batteries (Table 8 above) and different APA columns — use Full `set_profile` / `set_apa` with `profile_id()` to check. Contact the manufacturer for batteries not covered.
- **RSOC re-initialization:** `0x07` ← `0xAA55` samples the present voltage as OCV, so use it only when the battery current is < 0.025 C; `0x04` ← `0xAA55` (Before RSOC) uses the maximum voltage sampled since reset release and must not be used if the battery charged in that time.
- **Writing RSOC (`0x0D`)** also updates ITE; set sleep mode to keep the written value.
- **Current direction:** keep Auto except for special cases; wrong Charge/Discharge selection creates an RSOC error.
- **Parasitic resistance** between the battery and VDD/VSS degrades the RSOC accuracy (the chip measures the battery's internal impedance); keep the VDD/VSS traces short.
- **Alarm:** one ALARMB pin for both conditions; no status register (see Interrupt). Alarm thresholds `0` disable the respective condition.
- **Address:** `0x0B` is the Smart Battery System address; other gauges / battery chargers may share it.
- **Datasheet:** LC709203F/D Rev. 17, from the issue attachment.

## Sigrok Decoder

Decoder id `lc709203f`, input `['i2c']`. Matches I²C address `0x0B`. Annotates each write-word (command name + 16-bit value decoded per register: voltage mV, RSOC %, ITE ‰, temperature °C, power mode, thermistor/I²C mode, profile, alarm thresholds, `0xAA55` init commands) and each read-word likewise from the command byte sent before the repeated START, and **verifies the CRC-8** (poly `0x07`, init `0x00`, over the address bytes `0x16`/`0x17` as well), flagging a warning on mismatch or on a missing CRC byte; unknown command codes are flagged. No timing annotation pair is emitted (no bus-decodable completion events).
