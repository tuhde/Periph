# Chip Spec: ADE7953

**Manufacturer:** Analog Devices
**Datasheet:** `datasheets/power/ade7953.pdf` (Rev. C)
**Category:** `power`
**Transports:** SPI, I²C, UART

## Overview

The ADE7953 is a high-accuracy, single-phase electrical energy metering IC. It digitizes line voltage and two currents (a "Current Channel A" phase input and a "Current Channel B" neutral input, the second of which enables neutral-current tamper/fault detection) through three second-order Σ-Δ ADCs, then computes active, reactive, and apparent power/energy, RMS voltage and current, power factor, phase angle, and line period/frequency entirely in the digital domain. Two on-chip digital integrators allow the current inputs to be driven directly by di/dt sensors (Rogowski coils) as well as the more common shunt resistors or current transformers (CTs). Two programmable calibration-frequency (CF) pulse outputs, a dedicated reverse-power pin, zero-crossing outputs, and an interrupt pin (`IRQ`) expose power-quality events (sag, overvoltage, overcurrent, no-load, peak, sign changes) without polling every register.

The host communicates with the ADE7953 through one of three interfaces — SPI, I²C, or UART — all of which read and write the same on-chip register bank; only the transport framing differs (see Register Access below). The interface actually used is determined entirely by how three pins (`CS`, `SCLK`, and the shared `MOSI/SCL/Rx` / `MISO/SDA/Tx` pair) are wired/driven at power-up — the chip autodetects it in hardware, the driver does not select it in software. All three current/voltage measurement channels, and every calibration, threshold, and status register, are addressed identically regardless of which physical interface is wired.

Because the ADE7953 is a metering front end, not a self-contained current/voltage sensor, the mapping from its raw ADC codes to real-world amperes and volts depends entirely on the external current sensor (CT + burden resistor, shunt, or Rogowski coil) and voltage-divider network the designer wires to the analog pins — there is no universal default. The driver therefore takes two calibration constants (`voltage_gain`, `current_gain`) at construction time that describe that external scaling; see Data Conversion. This mirrors how the datasheet's own calibration procedure (AN-1118, *Calibrating a Single-Phase Energy Meter Based on the ADE7953*) works: apply a known reference voltage/current, read the raw registers, and derive the scale factors from the ratio.

## Transport Configuration

### Communication autodetection

The interface is selected by hardware pin state, sampled once at power-up (Table 9 of the datasheet) — there is no software command to select it:

| Interface | `CS` (Pin 28) | `SCLK` (Pin 25) | `MOSI/SCL/Rx` (Pin 27) | `MISO/SDA/Tx` (Pin 26) |
|-----------|---------------|------------------|------------------------|-------------------------|
| SPI  | driven low during communication | clock | MOSI | MISO |
| I²C  | pulled high | pulled high | SCL | SDA |
| UART | pulled high | pulled low | Rx | Tx |

Pins not used by the active interface must still be wired as shown (`CS` and `SCLK` pulled high for I²C/UART) so autodetection is unambiguous. The driver must therefore pick the correct register-access framing (see Register Access) based on the concrete connection type passed to the constructor — the same "bus type" dispatch pattern used for chips with more than one transport (see `specs/rfid/mfrc522.md` Register Access, and the pattern referenced there from `specs/pressure/bmp280.md`).

### I²C

- **Address:** `0x38` — fixed, 7-bit, no address pins (the datasheet gives it as an 8-bit pattern `0111000X` where `X` is the R/W bit)
- **Max clock:** 400 kHz (Fast mode)

### SPI

- **Mode:** CPOL=0, CPHA=0 (Mode 0) — MOSI sampled on the SCLK rising edge, MISO shifted out on the SCLK falling edge
- **Max clock:** 5 MHz
- **Bit order:** MSB first
- **CS active:** low; must be driven low for the whole transaction and high before the next one starts (CS also performs a reset-the-transfer function — bringing it high mid-transfer aborts that transfer)

### UART

- **Baud rate:** 4800 bps, fixed — not configurable
- **Frame:** 8N1
- **Timing:** frame-to-frame delay ≤ 4 ms (`t1`, applies between the header/data frames of one command); packet-to-packet delay ≥ 6 ms (`t2`, required idle time before the ADE7953 will accept a new command after finishing a response)
- No RS-485/DE pin — a plain 2-wire (Tx/Rx) `UARTConnection` per `specs/transport_uart.md`, configured to 4800-8N1 by the caller before construction

### Locking the interface

By default the chip re-runs autodetection after every communication is idle for a while, which is normally harmless but can be disabled: clearing `COMM_LOCK` (bit 15 of `CONFIG`, default `1` = locking disabled) causes the interface actually used for the *first* successful communication after power-up to be locked in for good. The Full driver exposes this as `lock_communication_interface()`; it is not required for correct operation and is not called by Minimal.

## Register Access

All three interfaces address the same register bank (8-, 16-, 24-, or 32-bit registers depending on which address is used — see Register Map), but frame the address and R/W direction differently.

| Transport | Read | Write |
|-----------|------|-------|
| I²C | `write_read([addrMSB, addrLSB], n)` — write the 16-bit register address (sets an internal pointer), then a repeated START and read `n` bytes MSB first | `write([addrMSB, addrLSB] + data)` — 16-bit address followed immediately by `n` data bytes, MSB first, in one frame |
| SPI | `write_read([addrMSB, addrLSB, 0x80], n)`, discard the first two received bytes, keep the remaining `n` | `write([addrMSB, addrLSB, 0x00] + data)`, data bytes MSB first |
| UART | Send header `[0x35, addrMSB, addrLSB]` (`0x35` = read), wait ≥ 0.1 ms, then read `n` bytes **LSB first** | Send `[0xCA, addrMSB, addrLSB] + data` (`0xCA` = write) with `data` bytes **LSB first**; no response is sent |

`n` is 1, 2, 3, or 4 bytes depending on whether the target register is 8-, 16-, 24-, or 32-bit.

**UART byte order is the opposite of SPI and I²C.** SPI and I²C always send/receive multi-byte register data MSB first; UART sends/receives it LSB first (the *address* bytes in the UART header are still MSB first — only the register *data* payload is reversed). A driver that reuses the same byte-packing helper across all three transports without special-casing UART will silently corrupt every multi-byte register value. This is the single most common bug when porting between transports.

Any single 24-bit register (`0x2xx` address) and its corresponding 32-bit alias (`0x3xx` address, same register, sign-extended into the upper byte) hold the same value — a write to one immediately updates the other. Drivers should pick whichever width is more convenient per platform; there is no functional difference.

## Required Power-Up Register Setting

For specified accuracy, register `0x120` (16-bit) must be written to `0x30` after every power-up — it is not set by the chip's own reset defaults and is not retained across power cycles. It is write-protected by a one-shot unlock sequence that must be issued immediately before it, in this exact order:

1. Write `0xAD` to 8-bit register `0xFE` (unlocks register `0x120`)
2. Write `0x30` to 16-bit register `0x120`

## Initialization Sequence

### Minimal

1. Wait ≥ 100 ms after VDD reaches its operating range (start-up delay recommended by the datasheet when the reset interrupt is not used to gate the first communication — see Timing Constraints)
2. Write `0xAD` to register `0xFE`, then `0x30` to register `0x120` (Required Power-Up Register Setting, above)
3. Chip is now ready; no other register writes are required — Current Channel A gain (`PGA_IA` = 1), Voltage Channel gain (`PGA_V` = 1), and the high-pass filters (`HPFEN` = 1 in `CONFIG`) are already at their power-on defaults, which are the correct settings for a shunt/CT-driven design (digital integrator off, HPF on)

### Full

Same as Minimal. Calibration (gain/offset/phase registers), PGA gain, accumulation modes, and every other feature default to their power-on values and are configured on demand via the Full API — none of it is required for correct basic operation.

## Data Conversion

All analog inputs share the same ADC full-scale relationship at the default gain of 1: a ±500 mV<sub>peak</sub> differential input produces a 24-bit code that reaches `9,032,007` (decimal) at full-scale RMS input. The full-scale RMS input voltage at the pins is therefore:

```
ADC_FS_VOLTS = 0.5 / sqrt(2)   # ≈ 0.353553 V rms, at PGA gain = 1
ADC_FS_CODE  = 9_032_007       # VRMS / IRMSA / IRMSB full-scale code, at PGA gain = 1
```

If a non-unity PGA gain is selected on a channel (`PGA_IA`/`PGA_IB`/`PGA_V`, see Table 6 of the datasheet: gain settings 1, 2, 4, 8, 16, and — Current Channel A only — 22), the full-scale input voltage at the pins is `0.5 V / gain`, so every formula below carries an extra `/ gain` term for that channel. Minimal never changes gain from its power-on default of 1, so the `/ gain` term is omitted from the Minimal-facing formulas; Full's `set_pga()` must recompute the affected scale factor(s) whenever gain changes (see Implementation Notes).

`voltage_gain` (real volts at the mains per volt present at `VP`–`VN`, i.e. the inverse of the external voltage-divider ratio) and `current_gain` (real amperes per volt present at `IAP`–`IAN`/`IBP`–`IBN`, i.e. the transconductance of the external CT+burden, shunt, or Rogowski+integrator front end) are supplied by the caller — see Overview and Implementation Notes.

```
voltage(V)  = (raw_VRMS  / ADC_FS_CODE) * ADC_FS_VOLTS * voltage_gain
current(A)  = (raw_IRMSx / ADC_FS_CODE) * ADC_FS_VOLTS * current_gain
```

Active, reactive, and apparent power share one scale factor, because at full-scale sinusoidal inputs (both channels at `ADC_FS_VOLTS`, power factor = 1) the `AWATT`/`BWATT`, `AVAR`/`BVAR`, and `AVA`/`BVA` registers all read approximately `4,862,401` (decimal) — call this `POWER_FS_CODE`:

```
POWER_FS_CODE = 4_862_401

active_power(W)   = (raw_AWATT / POWER_FS_CODE) * ADC_FS_VOLTS² * voltage_gain * current_gain
reactive_power(VAR) = (raw_AVAR / POWER_FS_CODE) * ADC_FS_VOLTS² * voltage_gain * current_gain
apparent_power(VA)  = (raw_AVA  / POWER_FS_CODE) * ADC_FS_VOLTS² * voltage_gain * current_gain
```

(`ADC_FS_VOLTS²` = `0.125` V² exactly, since `(0.5/√2)² = 0.25/2`.) The same three formulas apply to `BWATT`/`BVAR`/`BVA` (Current Channel B) with `current_gain` replaced by the Channel B calibration constant if it differs from Channel A's sensor.

Energy registers (`AENERGYA`, `RENERGYA`, `APENERGYA`, and their B counterparts) accumulate one LSB every time the corresponding instantaneous-power signal integrates past a fixed internal threshold. That threshold is sized so that, at exactly `POWER_FS_CODE` of continuous power, one energy LSB accumulates every `T_SAMPLE` = 4.83 µs (1/206.9 kHz — see Timing Constraints). Substituting the power formula above and canceling `POWER_FS_CODE` gives a closed form independent of it:

```
T_SAMPLE = 1 / 206_900   # ≈ 4.83e-6 s

active_energy(Wh)   = accumulated_raw_AENERGYA_LSBs   * (ADC_FS_VOLTS² * voltage_gain * current_gain * T_SAMPLE) / 3600
reactive_energy(VARh) = accumulated_raw_RENERGYA_LSBs  * (ADC_FS_VOLTS² * voltage_gain * current_gain * T_SAMPLE) / 3600
apparent_energy(VAh)  = accumulated_raw_APENERGYA_LSBs * (ADC_FS_VOLTS² * voltage_gain * current_gain * T_SAMPLE) / 3600
```

Power factor (`PFA`/`PFB`): signed, sign-magnitude in a two's-complement 16-bit register with 1 LSB = 2⁻¹⁵ (`0x7FFF` = +1.0, `0x8000` = −1.0):

```
power_factor = raw_PFx / 32768.0
```

Phase angle (`ANGLE_A`/`ANGLE_B`): 1 LSB = 4.47 µs (1/223.75 kHz):

```
angle(degrees) = raw_ANGLE_x * (360.0 * line_frequency_hz) / 223_750.0
```

`line_frequency_hz` is the nominal mains frequency (50 or 60), supplied by the caller or derived from `line_period()` below — this method does not account for harmonics and can disagree slightly with the power-factor-defined angle (see the datasheet's Angle Measurement section).

Line period / frequency (`Period`, 1 LSB = 4.47 µs, 1/223.75 kHz):

```
line_period(s)    = (raw_Period + 1) / 223_750.0
line_frequency(Hz) = 1.0 / line_period(s)
```

Phase calibration (`PHCALA`/`PHCALB`): 10-bit sign-magnitude, bit 9 = sign (`0` = delay, `1` = advance), bits `[8:0]` = magnitude, 1 LSB = 1.117 µs (1/(CLKIN/4) = 1/895 kHz):

```
if sign_bit == 0: phase_shift_s = -magnitude * 1.117e-6   # time delay
else:             phase_shift_s = +magnitude * 1.117e-6   # time advance
```

Peak registers (`VPEAK`, `IAPEAK`, `IBPEAK`) use the same `voltage(V)`/`current(A)` scaling as `VRMS`/`IRMSA`/`IRMSB` above (they are instantaneous absolute-value peaks of the same signal path, not RMS, but share the same ADC full-scale code and gain).

Gain calibration registers (`AIGAIN`, `AVGAIN`, `AWGAIN`, `AVARGAIN`, `AVAGAIN`, `BIGAIN`, `BWGAIN`, `BVARGAIN`, `BVAGAIN`) scale their associated measurement linearly around the default `0x400000` (no adjustment): `effective_reading = raw_reading * (register_value / 0x400000)`. Valid range `0x200000`–`0x600000` (−50 % to +50 %).

## Instantaneous Powers and Waveform Sampling

`AWATT`/`BWATT` (`0x212`/`0x213`, 24-bit — the *instantaneous* register, not to be confused with the energy accumulator `AENERGYA`/`AENERGYB`), `AVAR`/`BVAR` (`0x214`/`0x215`), `AVA`/`BVA` (`0x210`/`0x211`), `IA`/`IB` (`0x216`/`0x217`), and `V` (`0x218`) are all updated at 6.99 kHz (CLKIN/512) and readable at any time using the same `active_power`/`reactive_power`/`apparent_power`/`current`/`voltage` scale factors as their filtered/RMS counterparts. An interrupt (`WSMP`, bit 17 of `IRQENA`/`IRQSTATA`) fires each time a new set is available, for tight synchronization to the 6.99 kHz update rate; polling without the interrupt is also valid since every register always holds the latest sample.

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal — it inherits everything and adds the rest.

### Minimal

Goal: read the primary single-phase metering values — phase voltage, phase current, and active power/energy — with no register configuration beyond the mandatory power-up sequence and the caller's sensor-scaling constants.

Constructor parameters: `connection`, `voltage_gain` (real V per V at `VP`–`VN`), `current_gain` (real A per V at `IAP`–`IAN`, Current Channel A).

## Timing Constraints

- Power-up: VDD must clear 2 V ± 10% before the internal supply monitor starts a fixed ~26 ms hold-off, followed by ~40 ms of internal start-up — communication should not be attempted for at least 100 ms after VDD reaches its operating range if the `Reset` interrupt is not used to gate it (see Reset interrupt below)
- Reset interrupt: `Reset` (bit 20 of `IRQENA`/`IRQSTATA`) is enabled by default and cannot be disabled; it always fires once at the end of every power-up, hardware reset (`RESET` pin held low ≥ 10 µs), or software reset (`SWRST`)
- Required Power-Up Register Setting: the two writes (`0xFE` ← `0xAD`, then `0x120` ← `0x30`) must be issued back-to-back with no other register access in between
- `CF1DEN`/`CF2DEN` writes: two sequential write operations to the same register are required to guarantee the write succeeds (datasheet-documented quirk, not just an implementation nicety)
- SPI: `t_CS` (CS-to-SCLK) ≥ 50 ns, `t_SCLK` period ≥ 200 ns (≤ 5 MHz), CS must be held high ≥ 1200 ns after the last SCLK edge specifically when writing to the `COMM_LOCK` bit (40 ns minimum otherwise)
- I²C: standard timing per `specs/transport_i2c.md`; up to 400 kHz
- UART: fixed 4800 bps; frame-to-frame delay (`t1`) ≤ 4 ms max, ≥ 0.2 ms min between the header and data phases of one command; packet-to-packet delay (`t2`) ≥ 6 ms before the next command is accepted
- RMS measurements (`VRMS`, `IRMSA`, `IRMSB`): ~200 ms settling time after a gain/configuration change before readings are valid
- `Period` register: 30–40 ms settling time after signal acquisition begins
- Checksum (`CRC`) updates at 6.99 kHz (143 µs period) — consecutive reads intended to detect a change must be spaced ≥ 143 µs apart
- Energy accumulator rollover: `AENERGYA`/`AENERGYB`/`RENERGYA`/`RENERGYB`/`APENERGYA`/`APENERGYB` are 24-bit signed and roll over (wrap, not saturate) at continuous full-scale power in ~40.5 s; read frequently enough (or rely on `RSTREAD` = 1, the default) to avoid losing accumulated energy between reads if `RSTREAD` is disabled
- Line-cycle accumulation: maximum `LINECYC` value 65,535 half-cycles ≈ 655 s at 50 Hz / 546 s at 60 Hz; the reading immediately after first enabling line-cycle mode should be discarded (not synchronized to a zero crossing yet)
- Zero-crossing detection runs through a fixed single-pole LPF (`LPF1`, −3 dB at 80 Hz) that adds ~2.2 ms of delay at 50 Hz; this filter can be disabled (`ZXLPF`) but doing so reduces zero-crossing accuracy

## Implementation Notes

- **UART byte order is reversed relative to SPI/I²C** for multi-byte register data (see Register Access) — this is the single easiest correctness bug to introduce when supporting all three transports from shared framing code.
- **`voltage_gain`/`current_gain` are mandatory, hardware-specific calibration constants**, not tunable conveniences — see Minimal's Sensible Defaults note. Do not invent a numeric default; require them at construction (matching `specs/adc_dac/hx711.md`'s `scale_factor` precedent, not `specs/power/ina219.md`'s `r_shunt` precedent, since there the shunt itself is a directly-specifiable physical component with a common breakout-board value, whereas here the whole front end — CT/shunt/Rogowski **and** voltage divider — is design-specific).
- **PGA gain changes must update cached scale factors.** `Full.set_pga()` changes the effective `ADC_FS_VOLTS` for that channel (divided by the new gain); any driver implementation that caches per-LSB scale constants at construction time (a reasonable optimization, since floating-point division per reading is wasteful on MCUs) must invalidate/recompute the affected channel's constants inside `set_pga()`, not just write the register.
- **Energy registers reset on read by default** (`RSTREAD` = 1). `active_energy()`/`active_energy_b()`/etc. therefore return the energy accumulated *since the previous call*, not a running total — callers wanting a running total must accumulate the returned deltas themselves, or call `set_read_with_reset(False)` and track the 24-bit register's own rollovers instead.
- **`AWATT` (instantaneous, 6.99 kHz) is a different register from `AENERGYA` (accumulated).** `active_power()` reads `AWATT`; `active_energy()` reads `AENERGYA`. They are related by integration, not aliasing — a common naming confusion when porting from other single-phase metering ICs where "watt register" sometimes means the accumulator.
- **`IRMSA`/`IRMSB` (RMS current registers) are what `current()`/`current_b()` read** — not the instantaneous `IA`/`IB` waveform-sampling registers, which are exposed separately via `waveform_sample()` for harmonic/waveform analysis, not as the primary reading.
- **`OILVL` (overcurrent threshold) is shared by both current channels** — there is no independent `OILVL` per channel; `configure_overcurrent()` affects both `OIA` and `OIB` interrupt conditions simultaneously.
- **Apparent-power full-scale code (`POWER_FS_CODE` = 4,862,401) is documented explicitly for active and reactive power** in the datasheet; the apparent-power (`AVA`/`BVA`) full-scale code is not separately stated but shares the identical signal chain and gain architecture, so this spec treats it as the same constant. If empirical calibration against a reference meter shows a measurable discrepancy for a given design, adjust `AVAGAIN`/`BVAGAIN` rather than the shared formula.
- **Reset reverts all calibration.** `reset()` (software) and a hardware `RESET` pulse both clear every calibration/gain/offset/threshold register to its power-on default, exactly like a power cycle — the Required Power-Up Register Setting must be redone, and any calibration the caller applied via `set_pga`/`set_gain_calibration`/`set_phase_calibration`/etc. is lost and must be reapplied.
- **The bus-type dispatch pattern** (constructor branches on the concrete connection type to choose I²C, SPI, or UART framing) mirrors `specs/rfid/mfrc522.md` and `specs/pressure/bmp280.md` — reuse that approach rather than inventing a new one.

## Sigrok Decoder

Decoder id `ade7953`, input `['i2c']` (I²C is the most common wiring for this chip in practice; SPI and UART are not decoded). Matches the fixed address `0x38`. Annotates the 16-bit register-address pointer write, subsequent register reads/writes, and decodes the register's symbolic name from the address (using the Register Map above). For registers with a documented physical meaning, the decoded value is additionally annotated in engineering units where a fixed, gain-independent scale exists (power factor as a −1.0…+1.0 ratio, line period/frequency in seconds/Hz, phase angle in raw LSBs) — `VRMS`/`IRMSA`/`IRMSB`/power/energy registers are annotated only with their raw decimal value, since their real-world scale depends on calibration constants the decoder cannot know. Emits a warning annotation on unexpected read/write lengths (i.e. length not matching the target register's declared width) or accesses to an undocumented address.
