# Chip Spec: LM25066

**Manufacturer:** Texas Instruments  
**Datasheet:** `datasheets/power/lm25066.pdf` (SNVS654J, February 2010 – revised December 2015; covers the LM25066 and the LM25066I; the LM25066A is a different datasheet and is not covered)  
**Category:** `power`  
**Transports:** I²C, SMBus

## Overview

The LM25066 is a hot-swap (inrush-limiting) controller with a **PMBus / SMBus** interface that drives an external N-channel MOSFET on a 2.9–17 V rail (24 V transient), limits current and MOSFET power, protects with a circuit breaker and under/over-voltage lockouts, and meanwhile **measures** the system with a 12-bit ADC at 1 kHz: input voltage (VIN), output voltage (VOUT), input current (IIN, from the voltage across an external sense resistor RS), input power (PIN, the true VIN × IIN product of simultaneous samples), auxiliary voltage (VAUX) and the temperature of the external MOSFET (remote diode). It has programmable warning thresholds, a peak-power register, averaging (1…4096 samples), a latched "black box" snapshot taken at the first alert, and an SMBus alert output (SMBA). The telemetry is returned in the PMBus **DIRECT** format and must be converted with coefficients `(m, b, R)` that depend on the sense resistor and the current-limit pin setting (see Data Conversion).

The chip **controls a power switch**: the `OPERATION` command switches the load MOSFET on and off, and `GATE_MASK` can disable fault shut-off of the MOSFET. The driver therefore treats telemetry and control separately (control methods are Full only and documented with warnings).

- **Max clock:** 400 kHz (fast mode), min 10 kHz (SMBus); SMBus clock-low time-out 25–35 ms
- **PEC:** packet error checking is supported (CAPABILITY `0xB0`) but optional; the drivers do not use PEC
- **Identity:** `MFR_ID` (`0x99`) block read returns `03 'N' 'S' 'C'` (`0x03 0x4E 0x53 0x43`); `MFR_MODEL` (`0x9A`) returns `08 "LM25066" 00`. The registry probe reads 4 bytes of `0x99` (`0x034E5343`) — a PMBus MFR_ID shared by the National/TI PMBus parts, so it narrows but does not uniquely identify the LM25066 (`MFR_MODEL` does)
- **Probe safety:** `register_pointer` — a 1-byte write only selects a PMBus command; the probe writes `0x99` (read-only MFR_ID). The PMBus *send-byte* commands (`CLEAR_FAULTS` `0x03`, `CLEAR_PIN_PEAK` `0xD6`) act on a single-byte write, which is why drivers never probe with those
- **Register addressing:** 1-byte PMBus command code (`RegisterConnection`, `reg_bytes = 1`); 16-bit values are **little-endian** (LSB first, SMBus word order); block reads return a leading byte count (read `n + 1` bytes with `read(cmd, n + 1)` — the lengths of the used blocks are fixed: `MFR_ID` 3, `MFR_MODEL` 8, `MFR_REVISION` 2, the telemetry blocks 12); send-byte commands are `write(cmd, b"")`

### Telemetry / warning word

16-bit little-endian; the useful value is the 12-bit field `Y = word & 0x0FFF` (bits 15:12 read 0); the temperature word uses the full 16 bits (signed range −256 … +255 °C). Warning/limit registers use the same coding (write `Y` in the same format; `0x0FFF` or `0x0000` disable as listed).

### Status and diagnostic bits

**STATUS_BYTE (`0x78`):** bit 6 OFF (MOSFET not on), bit 3 VIN UV fault, bit 2 temperature fault/warn, bit 1 CML, bit 0 other. **STATUS_WORD (`0x79`)** adds bit 15 VOUT, bit 13 INPUT, bit 12 MFR, bit 11 POWER GOOD negated. After power-up `0x3849` (off, VIN UV, input, MFR, PG, other) until the input first exceeds the UVLO threshold.

**READ_DIAGNOSTIC_WORD (`0xE1`):**

| Bit | Name | Bit | Name |
|-----|------|-----|------|
| 15 | VOUT_UNDERVOLTAGE_WARN | 7 | CONFIG_PRESET (defaults loaded; cleared by CLEAR_FAULTS) |
| 14 | IIN_OP_WARN | 6 | DEVICE_OFF |
| 13 | VIN_UNDERVOLTAGE_WARN | 5 | VIN_UNDERVOLTAGE_FAULT |
| 12 | VIN_OVERVOLTAGE_WARN | 4 | VIN_OVERVOLTAGE_FAULT |
| 11 | POWER_GOOD | 3 | IIN_OC / PFET_OP_FAULT |
| 10 | OVER_TEMPERATURE_WARN | 2 | OVER_TEMPERATURE_FAULT |
| 9 | TIMER_LATCHED_OFF | 1 | CML_FAULT |
| 8 | EXT_MOSFET_SHORTED | 0 | CIRCUIT_BREAKER_FAULT |

**ALERT_MASK (`0xD8`)** (1 = masked, no SMBA; default `0x0820` = POWER GOOD and VIN UV fault masked): bit 15 VOUT UV warn, 14 IIN limit warn, 13 VIN UV warn, 12 VIN OV warn, 11 POWER GOOD, 10 over-temp warn, 8 over-power limit warn, 6 EXT_MOSFET_SHORTED, 5 VIN UV fault, 4 VIN OV fault, 3 IIN/PFET fault, 2 over-temp fault, 1 CML fault, 0 circuit breaker fault (bits 9, 7 unused).

**DEVICE_SETUP (`0xD9`):** bits 7:5 retry setting (`000` pin, `001` none, `010` 1, `011` 2, `100` 4, `101` 8, `110` 16, `111` unlimited), bit 4 current limit (0 = 25 mV, 1 = 46 mV), bit 3 CB/CL ratio (0 = 1.8×, 1 = 3.6×), bit 2 current-limit config (1 = use bit 4, 0 = pin), bit 1 circuit-breaker config (1 = use bit 3, 0 = pin). The current-limit setting also selects the current/power coefficients.

**GATE_MASK (`0xD7`):** bit 5 VIN UV fault, bit 4 VIN OV fault, bit 2 over-temperature fault (a 1 stops that fault from switching the MOSFET off; bits 3 and 0 must not be written).

## Initialization Sequence

1. At power-up the chip loads defaults and pulls SMBA low once (STATUS_MFR_SPECIFIC bit 4 `Defaults loaded` and diagnostic bit 7 `CONFIG_PRESET`, cleared by `CLEAR_FAULTS`). No delay is specified for SMBus access after the supply is valid; the MOSFET turns on after the insertion-time delay set by the TIMER capacitor when VIN exceeds the UVLO threshold.
2. Telemetry is available as soon as the ADC runs (1 kHz); readings are 0 until the first conversion.
3. `init` stores the connection and the telemetry coefficients (see below); it performs no bus access and **never changes OPERATION, GATE_MASK or DEVICE_SETUP**.
4. Optional (Full): set the warning limits, averaging and ALERT_MASK; `clear_faults()` to release SMBA after power-up.

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on SMBA (falling edge) via `connection.int_pin` (or `int_pin`), otherwise a 1 s polling task on `poll_interrupt`; `callback(diagnostic_word)` receives the READ_DIAGNOSTIC_WORD value |
| `off_interrupt` | `off_interrupt()` | Unsubscribe |

## Implementation Stages

### Minimal

Goal: read the monitored rail — input and output voltage, input current, input power and MOSFET temperature — with one call each. Telemetry needs the sense resistor value, so the constructor takes it; nothing else is configured and the chip is not written.

Constructor parameters: `connection`, `r_sense_mohm` (sense resistor in mΩ, default `1.0`), `current_limit_high` (default `False`: CL pin at GND, 25 mV; `True`: CL pin at VDD, 46 mV).

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection, `r_sense_mohm`, `current_limit_high` | — | Stores connection and coefficients; no bus access |
| `voltage_in` | — | float | VIN in V (`READ_VIN`) |
| `voltage_out` | — | float | VOUT in V (`READ_VOUT`) |
| `current` | — | float | Input current in A (`MFR_READ_IIN`) |
| `power` | — | float | Input power in W (`MFR_READ_PIN`) |
| `temperature` | — | float | MOSFET temperature in °C (`READ_TEMPERATURE_1`) |

**Sensible defaults:** the chip's power-on state is untouched (continuous 1 kHz sampling, no averaging, warnings disabled, MOSFET controlled by the hardware pins).

## Data Conversion

PMBus DIRECT: `X = (Y × 10^(−R) − b) / m` with `Y` the 12-bit field (16-bit for temperature); writes use `Y = (m × X + b) × 10^R`, rounded and clamped to the register's valid range.

| Quantity | Registers | m | b | R | Unit |
|----------|-----------|---|---|---|------|
| VIN, VOUT (and `VIN_OV/UV_WARN_LIMIT`, `VOUT_UV_WARN_LIMIT`) | `0x88` `0x8B` `0xDC` `0xDD` | 22070 | −1800 | −2 | V |
| VAUX | `0xD0` | 3546 | −3 | 0 | V |
| IIN, CL = GND (25 mV) | `0xD1` `0xDE`, `0xD3` | 13661 × RS | −5200 | −2 | A |
| IIN, CL = VDD (46 mV) | | 6854 × RS | −3100 | −2 | A |
| PIN, CL = GND | `0xD2` `0xDF` `0xD5`, `0xD4` | 736 × RS | −3300 | −2 | W |
| PIN, CL = VDD | | 369 × RS | −1900 | −2 | W |
| Temperature (and `OT_*_LIMIT`) | `0x8D`, `0x4F`, `0x51` | 16000 | 0 | −3 | °C |

`RS` is the sense resistor in **mΩ**. The drivers compute in floating point, so `m` is not restricted to the PMBus ±32767 range (a host that stores `m` in a 16-bit field must reduce `R`, e.g. RS = 5 mΩ, CL = VDD: `m = 3427, b = −310, R = −1`).

```
volts       = (Y * 100 + 1800) / 22070
vaux        = (Y + 3) / 3546                                   # full scale 4095 -> 1.156 V
amps        = (Y * 100 + 5200) / (13661 * RS)  [CL = GND]      # or (Y*100 + 3100) / (6854 * RS)  [CL = VDD]
watts       = (Y * 100 + 3300) / (736 * RS)    [CL = GND]      # or (Y*100 + 1900) / (369 * RS)   [CL = VDD]
celsius     = Y / 16                                           # Y = word as unsigned 16-bit, interpreted signed
Y(warn)     = round((m * X + b) * 10^R), clamped to 0 .. 0x0FFE   (0x0FFF = disabled where listed)
```

Examples: `READ_TEMPERATURE_1` default `0x0190` = 400 → 25.0 °C; `OT_FAULT_LIMIT` default `0x0960` = 2400 → 150 °C, `OT_WARN_LIMIT` `0x07D0` → 125 °C; with RS = 5 mΩ and CL = GND, `READ_AVG_IIN` = 648 → (64800 + 5200) / 68305 = 1.02 A (datasheet Table 42 data point for 1 A). The datasheet's worked example "RS = 5 mΩ, CL = VDD → m = 6830, b = −310" mixes the CL = GND slope with the CL = VDD offset; the table formulas above are authoritative.

## Examples

### Demo

**Hot-swap rail monitor.** Using the Full driver on a 12 V rail with a 1 mΩ sense resistor, print `manufacturer_id()`, `model()` and `revision()`, then once per second for a minute print VIN, VOUT, IIN, PIN and MOSFET temperature, keeping the peak power from `power_peak()`. Midway set 64-sample averaging (`set_averaging(6)`) and compare `current()` with `current_avg()`; arm a VIN under-voltage warning at 10 V and an input over-current warning at 20 A (`set_vin_uv_warn`, `set_iin_warn`), unmask the corresponding alert sources and report `poll_interrupt()`; finish with `clear_faults()`. The demo never calls `operation_off()` or `set_gate_mask()` unless an explicit `--control` flag is given.

## Timing Constraints

- **ADC sampling:** 1 kHz (12-bit); instantaneous telemetry registers update every ms; averaged registers update every 2^AVGN ms; the averaged value is the previous one until the interval completes, and a `SAMPLES_FOR_AVG` change takes effect only after the running interval ends.
- **Temperature:** one reading is an average of 16 round-robin cycles — minimum over-temperature fault/warn detection time 16 ms.
- **BLOCK_READ:** the block is refreshed every internal clock cycle (85 ns) while the SMBus is idle, so its values are time-aligned.
- **Insertion time / fault timer / restart:** set by the TIMER capacitor (5.5 µA charge, 1.7 V threshold, 90 µA fault charge, 2.8 µA discharge) — hardware, no host timing.
- **Address capture:** at power-up once VDD > 2.6 V (or VREF > 2.4 V after a VREF release).
- **SMBus:** 10–400 kHz, clock-low time-out 25–35 ms (slave stretch ≤ 25 ms, master ≤ 10 ms), tBUF ≥ 1.3 µs, tHD:STA ≥ 0.6 µs, tLOW ≥ 1.5 µs, tHIGH ≥ 0.6 µs — clock-rate properties, not event-to-event delays.
- **Conformance:** none of these has a bus-decodable start/end annotation pair (sampling and averaging periods are internal; no completion event exists on the bus), so `specs/power/lm25066_timing.conf` defines no checks.

## Implementation Notes

- **This chip switches power.** `OPERATION` `0x00` cuts the load rail; `GATE_MASK` can stop hardware faults from turning the MOSFET off (the datasheet warns it will likely destroy the MOSFET on over-current/circuit-breaker faults); the drivers expose them only in Full, never touch them in Minimal, and the examples keep them behind explicit opt-in.
- **Coefficients depend on the board:** `RS` and the CL pin determine the current and power conversion. A wrong `r_sense_mohm` or CL setting scales the current/power readings; `DEVICE_SETUP` can override the CL pin from software (then the driver must use the matching coefficients — `configure_device(current_limit_high=…)` updates them). The datasheet recommends per-board calibration (linear fit, §8.5.1.4) for best accuracy; `r_sense_mohm` may be set to the calibrated effective value.
- **Little-endian words:** SMBus words are LSB first, unlike most register chips; `RegisterConnection.read(cmd, 2)` returns `[lsb, msb]`.
- **Block reads:** `read(cmd, n + 1)` returns the count byte first; the drivers check it equals `n` (12 for the telemetry blocks, 3 for `MFR_ID`, 8 for `MFR_MODEL`, 2 for `MFR_REVISION`).
- **Send-byte commands:** `CLEAR_FAULTS` and `CLEAR_PIN_PEAK` are a command byte with no data — `write(cmd, b"")` (a bare one-byte write); the PMBus `OPERATION` write is a normal write-byte.
- **After power-up:** SMBA is low and the STATUS bits `Defaults loaded` / `VIN UV` are set until `CLEAR_FAULTS` and the first UVLO crossing; `STATUS_WORD` is `0x3849` until then.
- **Fault handling:** after a fault shut-off, clear the cause, `clear_faults()`, then `operation_off()` + `operation_on()` (OPERATION on alone does not clear the fault registers); depending on RETRY the chip may retry by itself or latch off until UVLO/EN toggles.
- **ARA:** after an Alert Response read the chip masks the faults present until `CLEAR_FAULTS`; the drivers read the diagnostic word directly and always finish a servicing pass with `clear_faults()`.
- **Black box:** the snapshot is taken at the **first** SMBA after `CLEAR_FAULTS` and held until the next `CLEAR_FAULTS`.
- **Temperature range:** `READ_TEMPERATURE_1` is a 16-bit two's-complement-range word (−256 … +255 °C); Python/JS drivers must sign-convert before dividing by 16.
- **Variants:** the LM25066I (industrial) shares this datasheet and the coefficients; the LM25066A has different coefficients and is a separate chip (not covered).
- **Address overlap:** the 27 addresses overlap with many chips (INA2xx and PCF8591-class parts at `0x40`–`0x47`, EEPROMs at `0x50`–`0x57`, …); a wrong-chip PMBus read returns meaningless data, so the discovery registry's MFR_ID probe (`0x034E5343`) is the filter.
- **Datasheet:** SNVS654J, downloaded from `https://www.ti.com/lit/ds/symlink/lm25066.pdf`.

## Sigrok Decoder

Decoder id `lm25066`, input `['i2c']`. Matches the addresses `0x10`–`0x17`, `0x40`–`0x47` and `0x50`–`0x5A`. Annotates every PMBus command by name (send byte, write byte/word, read byte/word via repeated START, block reads with the count byte) and decodes the payloads: READ_VIN/VOUT/IIN/PIN/AVG_* as raw counts and — with the default coefficients (RS = 1 mΩ, CL = GND, the decoder cannot see the pins) — as V/A/W, temperature in °C, VAUX in V, STATUS_* bit names, READ_DIAGNOSTIC_WORD and ALERT_MASK flag names, DEVICE_SETUP fields, SAMPLES_FOR_AVG as 2^n, OPERATION as ON/OFF, the three block-read layouts field by field and the manufacturer ID/model/revision ASCII; warns on writes to read-only commands, on a block-read count byte that differs from the command's fixed length, on writes of `OPERATION` `0x00` and of `GATE_MASK` (control operations), and on unknown command codes. No timing annotation pair is emitted (no bus-decodable completion events).
