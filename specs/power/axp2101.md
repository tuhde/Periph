# Chip Spec: AXP2101

**Manufacturer:** X-Powers  
**Datasheet:** `datasheets/power/axp2101.pdf`  
**Category:** `power`  
**Transports:** I²C

## Overview

The AXP2101 is a single-cell Li-ion / Li-polymer power-management IC (NVDC switch charger with E-Gauge fuel gauge) in a 5 × 5 mm 40-pin QFN. It combines a 3.9–5.5 V input switch charger (up to 1.5 A charge current, 2 A input limit, 50 mΩ BATFET), 15 power outputs — four buck converters (DCDC1–4) and eleven LDOs (ALDO1–4, BLDO1–2, CPUSLDO, DLDO1–2, RTCLDO1–2) — a 14-bit ADC for battery, VBUS, system, thermistor and die-temperature measurement, a battery fuel gauge with percentage output, a power-key controller (short/long press, power on/off, sleep/wake), a watchdog, JEITA battery-temperature protection, a charge-status LED output and an interrupt controller with 24 sources. The host interface is a two-wire serial bus (TWSI = I²C) or RSB (Allwinner Reduced Serial Bus); only I²C is covered. Several defaults (output voltages, start-up sequence, power-key timing, charge current) are programmed into the part's eFuse by the board maker, so the power-on state differs between products (e.g. M5Stack Core2 v1.1 / CoreS3, Waveshare ESP32 boards). Typical uses: battery-powered ESP32 devices, smart speakers, doorbells, IP cameras.

## Transport Configuration

### I²C
- **Address:** `0x34` (7-bit; the datasheet's Table 6-1 gives the 8-bit write / read bytes `0x68` / `0x69` and its text calls this "address 0x68/0x69")
- **Max clock:** 400 kHz (fast mode); 100 kHz standard mode
- **Identity register:** none documented — the datasheet has no chip-ID register (feeds `registry/chips.json` with `"id_probe": null` and `"driver": null` until implemented, see `specs/feature_i2c_discovery.md`)
- **Probe safety:** `register_pointer` — the first byte after the address selects the register; a 1-byte write only sets the pointer

SDA and SCK each need a 2.2 kΩ pull-up to the I/O supply. The bus is active as soon as VBUS or VBAT is above its under-voltage threshold (registers are reset at that moment). VIH = 1.3 V, VIL = 0.8 V.

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| IRQ | low, open-drain | Interrupt output — needs a 4.7 kΩ pull-up to a logic rail; pulled low while any enabled IRQ status bit is set. Also a wake-up / power-on source when held low for more than 16 ms (if enabled) |
| PWRON | low | Power on/off key input (internal 100 kΩ pull-up to VINT); can be customized as an EN pin |
| PWROK | high | Power-good output; held low during start-up, released after all outputs are valid (delay in `REG25`); driving it low externally restarts the PMU when `REG10` bit 4 is set |
| CHGLED | low (LED on) | Charge-status LED output, open-drain / push-pull, > 10 mA drive; function selected in `REG69` |
| TS | analog | Battery thermistor (10 kΩ NTC at 25 °C) input with an injected current of 20 / 40 / 50 / 60 µA; or an external ADC input |
| GPIO1 | low, open-drain | Single open-drain output (Hi-Z or low, `REG1B`); can be customized as RTCLDO2 output |
| VBACKUP | — | Backup (coin) battery input / charge output; source of RTCLDO1 when only the backup cell is present |

Voltage = start + N × step (for DCDC2/3/4 above 1.2 V: 1.22 V + (N − 71) × 20 mV). `0x80` bit 5 selects the DVM ramp (0 = 15.625 µs/step, 1 = 31.25 µs/step), bit 6 forces CCM; `0x83` / `0x84` bit 7 enables dynamic voltage scaling (DVM) for DCDC2 / DCDC3. `0x81` bits 2–5 force DCDC1–4 into always-PWM (0 = automatic PWM/PFM). DLDO1 input is DCDC1, DLDO2 and CPUSLDO input is DCDC4; ALDOIN must be tied to VSYS. RTCLDO1/2 (1.8 / 2.5 / 3.0 / 3.3 V, 30 mA) are not register-controlled.

#### TS / JEITA

| Register | Description |
|----------|-------------|
| `0x50` bit 4 | 0 = TS is the battery thermistor input and affects the charger; 1 = external fixed input, no effect on the charger |
| `0x50` bits 3:2 | TS current source: 00 off, 01 on when the TS ADC channel is enabled, 10 on only while the TS channel is converting, 11 always on |
| `0x50` bits 1:0 | 00 = 20 µA, 01 = 40 µA, 10 = 50 µA (default, for a 10 kΩ NTC), 11 = 60 µA |
| `0x54`–`0x57` | Cold/hot limits as TS voltage: `VLTF` = N × 32 mV, `VHTF` = N × 2 mV (charge: ≈ 0 °C / 55 °C; work: ≈ −10 °C / 60 °C) |
| `0x58` / `0x59` / `0x5A` / `0x5B` | JEITA enable; warm / cool current fall (100 % / 50 %) and voltage fall (0, 1 or 2 gears below the set value); cool threshold T2 = N × 16 mV; warm threshold T3 = N × 8 mV |

TS voltage = N × 0.5 mV for the 50 µA / 10 kΩ NTC; Table 6-5 of the datasheet maps temperature to resistance, TS voltage and ADC code (e.g. 25 °C: 10.00 kΩ, 0.500 V, `0x3E8`; 0 °C: 26.49 kΩ, 1.325 V, `0xA5A`; 60 °C: 3.032 kΩ, 0.152 V, `0x130`).

#### Fast power-on registers (`0x28`–`0x2B`)

Each rail has a 2-bit start-sequence code (00–10) or 11 = disabled: `0x28` DCDC4 [7:6], DCDC3 [5:4], DCDC2 [3:2], DCDC1 [1:0]; `0x29` ALDO3 [7:6], ALDO2 [5:4], ALDO1 [3:2]; `0x2A` CPUSLDO [7:6], BLDO2 [5:4], BLDO1 [3:2], ALDO4 [1:0]; `0x2B` fast power-on enable (bit 7), fast wake-up enable (bit 6), DLDO2 [3:2], DLDO1 [1:0].

## Initialization Sequence

1. Power up (VBUS above 3.75 V or VBAT above 2.4 V resets all registers and activates the TWSI interface). The datasheet gives no register-access delay.
2. Read `STATUS1` (`0x00`) as a bus check; raise a descriptive error if the transfer fails (the chip has no identity register).
3. Read `ADC_ENABLE` (`0x30`) and write it with bits 0–4 set (`0x1F`): battery, TS, VBUS, VSYS and die-temperature channels on, GPADC bit preserved.
4. Read `MODULE_ENABLE` (`0x18`) and write it with bit 3 (fuel gauge) set, all other bits preserved (charger enable and watchdog are left at their power-on values).
5. Wait 20 ms for the first ADC conversions (driver choice; the datasheet gives no conversion time).

Charger, rail and power-key settings are never touched by `init` (they are board-specific, partly eFuse-programmed); a read-modify-write is used for every shared register.

### Status register bit layout (`poll_interrupt()` return value)

Bit *n* of byte *k* of the return value is bit *n* of `IRQ_STATUS<k>`; the constant for each bit is the `SOURCE_*` table above (bit 21, the reserved bit of `IRQ_STATUS2`, is always 0).

## Data Conversion

```
adc14(H, L)      = ((H & 0x3F) << 8) | L                    # read the high byte first, then the low byte

battery_voltage  = adc14(VBAT_H, VBAT_L) * 0.001            # V   (1 mV / LSB)
vbus_voltage     = adc14(VBUS_H, VBUS_L) * 0.001            # V
system_voltage   = adc14(VSYS_H, VSYS_L) * 0.001            # V
ts_voltage       = adc14(TS_H,   TS_L)   * 0.0005           # V   (0.5 mV / LSB)
tdie_mv          = adc14(TDIE_H, TDIE_L) * 0.1              # mV  (0.1 mV / LSB, datasheet Table 6-7)
die_temperature  = 22 + (7274 - adc14(TDIE_H, TDIE_L)) / 20 # °C  (formula from the vendor XPowersLib, not in the datasheet)

battery_percent  = BAT_PERCENT                              # 0-100
```

Datasheet Table 6-7 lists the full-scale code as `0x1FFF` = 8.191 V (a 13-bit span) although the ADC is described as 14-bit and the register holds 14 bits; the driver masks 14 bits. The die-temperature channel is only specified as a voltage; the conversion to °C comes from the vendor library (22 °C at code 7274, 0.05 °C per LSB, i.e. −1 °C per 20 codes) and should be verified on hardware — use the raw millivolt value if accuracy matters.

Charger encodings:

```
ICC code        = round(amps / 0.025)           if amps <= 0.2   (0..8)
                = 8 + round((amps - 0.2) / 0.1) otherwise       (9..21)
IPRECHG / ITERM = round(amps / 0.025)           # 0..8
VINDPM code     = round((volts - 3.88) / 0.08)  # 0..15
MIN_VSYS code   = round((volts - 3.2) / 0.1)    # 0..7
```

Rail encodings:

```
dcdc1 code      = round((v - 1.5) / 0.1)                              # 0..19
dcdc2/3 code    = round((v - 0.5) / 0.01)        for v <= 1.2          # 0..70
                = 71 + round((v - 1.22) / 0.02)  for 1.22 <= v <= 1.54 # 71..87
dcdc4 code      = same, up to 1.84 V                                   # 71..102
aldo/bldo code  = round((v - 0.5) / 0.1)                              # 0..30
cpusldo/dldo2   = round((v - 0.5) / 0.05)                             # 0..19
dldo1 code      = round((v - 0.5) / 0.1)                              # 0..28
```

TS thresholds: register value = round(voltage / LSB) with LSB 32 mV (`VLTF_*`), 2 mV (`VHTF_*`), 16 mV (`JEITA_COOL`, `TS_HYS_L2H`), 8 mV (`JEITA_WARM`), 4 mV (`TS_HYS_H2L`).

## Timing Constraints

- **Register access after power-up:** not specified; the driver relies on the I²C bus working from the first access and retries once on a NACK.
- **ADC first conversion:** not specified; `init` waits 20 ms (driver choice).
- **Key timings:** ONLEVEL 128 ms / 512 ms / 1 s / 2 s, OFFLEVEL 4 / 6 / 8 / 10 s, IRQLEVEL 1 / 1.5 / 2 / 2.5 s; an IRQ pin held low for more than 16 ms wakes / powers on (when enabled).
- **PWROK:** asserted 8 / 16 / 32 / 64 ms after all outputs are good.
- **Watchdog:** 1–128 s timeout (`WATCHDOG_CTRL[2:0]`); `feed_watchdog` must be called at least once per timeout while it is enabled.
- **DVM ramp:** 15.625 µs or 31.25 µs per step; DCDC switching frequency 3 MHz (DCDC1, 4) and 1.5 MHz (DCDC2, 3).
- **Charger timers:** pre-charge 40–70 min, charge-done 5–20 h (halved speed in regulation).
- **I²C:** 400 kHz max; standard-mode setup/hold per datasheet Table 6-2.

No timing constraint is conformance-checked: the datasheet gives no minimum delay between bus operations, so there is no `specs/power/axp2101_timing.conf` and no conformance checker.

## Implementation Notes

- **Register-addressed:** accept `RegisterConnection` (1-byte register address) and call `connection.read(reg, length)` / `connection.write(reg, data)` directly — no chip-local `_read_reg`/`_write_reg` and no `bus_type` branch (see `specs/feature_register_access_design.md`).
- **Read-modify-write everywhere:** nearly every register mixes fields (eFuse-programmed bits, reserved bits, self-clearing bits). Modify only the owned bits. For self-clearing commands (`COMMON_CONFIG` bits 0–1, `SLEEP_CTRL` bits 0–1, `WATCHDOG_CTRL` bit 3, `GAUGE_RESET` bit 3) write the current value with the command bit set; never write them back as read (a read-modify-write that preserves a pending command bit would repeat the action).
- **eFuse defaults vary per product:** output voltages, enables, ONLEVEL, VOFF, charge current, BATFET, TS and CHGLED defaults are programmed per product. Read before use; the driver exposes `get_rail` instead of assuming a default voltage. M5Stack Core2 v1.1 / CoreS3 and Waveshare boards differ in which rail feeds what.
- **Dangerous operations:** `set_rail_enabled(False)` / `set_rail_voltage` on the rail that powers the host MCU (commonly DCDC1 or DCDC3), `power_off`, `configure_power_off` thresholds, `set_charge_voltage` / `set_charge_current` beyond the cell's limits, and `set_batfet_off_enable(False)` can power the board down or damage the battery. The spec for each setter states the chip's range only; the application must know its cell and load. The 4.35 / 4.4 V charge voltages are for high-voltage Li-ion cells only.
- **Charge current vs charge voltage:** the maximum ICC depends on the charge voltage (Table 5-5); `set_charge_current` rejects a value above the limit of the currently programmed `CV`.
- **14-bit ADC read order:** read the high byte first, then the low byte (datasheet §6.10); bits 7:6 of `VBAT_H` and `TS_H` hold read/write debug fields (`ch_dbg_en`) — they are masked on read and never written. The high bit of `TS_H` (low-frequency ADC when powered off on battery) is a real setting: write `TS_H` only through `set_adc_low_frequency`.
- **`REG10` reserved bit 4:** it reads 1 after reset; the read-modify-write helpers preserve it (the PWROK-restart control is bit 3).
- **IRQ status clearing:** status bits are RW1C. `poll_interrupt` reads the three registers, then writes back exactly the bits it saw set (not `0xFF`) so an event arriving between read and write is not lost. Level-type sources stay set until their condition clears.
- **IRQ enable reset values:** `IRQ_EN0` = `0xFF`, `IRQ_EN1` = `0xFC`, `IRQ_EN2` = `0x5F`: after reset the IRQ pin already fires for most sources. `init` does not change them; a driver that handles the IRQ pin should clear the status registers first.
- **`REG49` also reflects live state:** the datasheet says VBUS insertion sets `REG49[7]` (IRQ status); use `STATUS1.VBUS_GOOD` for the current state.
- **Charge-done behaviour:** after charge done the charger stops with the enable bit still set and the BATFET off; it restarts automatically below `VRECHG` (100 mV under the target voltage).
- **TS pin:** with no thermistor fitted, tie TS to GND through 10 kΩ, or set `configure_ts(battery_sensor=False)` (TS becomes an external input that does not affect the charger). A wrong setting inhibits charging (TS out of range suspends charge).
- **Fuel gauge:** `battery_percent` reads `0xA4`; accuracy depends on the battery model in `0xA1` (loaded by the board's boot firmware); the datasheet gives no programming procedure for `0xA1` / `0xA2`, so the driver exposes only gauge enable, reset and warning levels.
- **Not covered:** RSB (Reduced Serial Bus) host interface, the battery-model ROM write (`0xA1` / `0xA2`), `ch_dbg_en` debug muxing, the TS configured-value registers `0x5C` / `0x5D` beyond their description, and customized pin functions (EN instead of PWRON, DC1SW / DC4SW switch mode, RTCLDO2, switch-charger "customization").
- **Siblings:** the AXP192 and AXP2101 are not register-compatible; both appear on M5Stack boards at address `0x34`. No compatibility is assumed. Without an identity register discovery cannot tell them apart.
- **Datasheet revision:** the committed datasheet is "AXP2101 Single Cell NVDC PMU (SWcharge) with E-gauge" revision 1.0 (4 November 2022), 13 pages, supplied by URL in the issue; the register chapter (§6.13) is complete but several descriptions are inconsistent (see above).

## Sigrok Decoder

Decoder id `axp2101`, input `['i2c']`. Matches I²C address `0x34`. The decoder annotates every register of the register map by name; decodes `STATUS1` / `STATUS2` into named flags (VBUS good, charge state, battery direction), `COMMON_CONFIG`, `MODULE_ENABLE`, `ADC_ENABLE`, `PWRKEY_LEVEL`, `SLEEP_CTRL`, the three IRQ enable and status registers (as the `SOURCE_*` names), the charger registers (`MIN_VSYS`, `VINDPM`, `IINLIM`, `ICC`, `IPRECHG`, `ITERM`, `CV` as V / mA), the rail enable registers and the DCDC / LDO voltage registers (as volts with the rail name); assembles reads of `0x34`–`0x3D` as battery, TS, VBUS, VSYS voltages and die temperature at 14-bit resolution; `BAT_PERCENT` as a percentage; flags a low-byte read before the high byte of an ADC pair, and a write to `0x34` / `0x36` with the reserved bits 7:6 set, as warnings. No conformance annotations are emitted (no conformance-checked timing).
