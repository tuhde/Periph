# Chip Spec: PCA6408A (IO Expander)

**Manufacturer:** NXP Semiconductors  
**Datasheet:** `datasheets/io_expander/pca6408a.pdf` (Rev. 1, 27 September 2012 — the NXP and Mouser URLs return 404/blocked; the committed copy is the same NXP document from `https://datasheet.datasheetarchive.com/originals/distributors/Datasheets-SFU4/DSASF4000-5451.pdf`)  
**Category:** `io_expander`  
**Transports:** I²C, SMBus

## Overview

The PCA6408A is an 8-bit general-purpose I/O expander with an I²C / SMBus interface, a single 8-pin port (P0–P7), per-pin direction (Configuration register), input polarity inversion, latched outputs (25 mA sink for LEDs), an open-drain interrupt output, an active-low reset input and a low standby current (1 µA). It has **two supply rails**: VDD(I2C-bus) powers the bus interface (and is the voltage-translation reference for SCL/SDA) while VDD(P) powers the core and Port P, so a 1.8 V microcontroller can talk to 1.8 V–5 V peripherals (1.65–5.5 V on both rails, 5 V tolerant I/O). One address pin gives two I²C addresses. It is the lean sibling of the MCP23008: four registers, **no internal pull-ups**, no interrupt-flag/capture registers and no default-compare interrupt mode.

## Transport Configuration

### I²C / SMBus
- **Address:** `0x20` (ADDR = VSS) — `0x21` (ADDR = VDD(P)); address byte `0100 00 ADDR R/W`. ADDR must be tied directly to VDD(P) or ground
- **Max clock:** 400 kHz (fast mode); 100 kHz standard mode also supported. Drivers use ≤ 400 kHz
- **SMBus:** the protocol is plain "Write Byte / Read Byte" with the command byte as register pointer, so the chip works on an SMBus (the datasheet states SMBus compatibility; PEC is not supported and must not be enabled for this chip). The driver accepts either an `I2CConnection` or an `SMBusConnection` (without PEC) — it only needs byte-register access
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`; it shares `0x20`/`0x21` with the MCP23008/MCP23017 and PCF8574, none of which can be told apart)
- **Probe safety:** `register_pointer` — a 1-byte write only loads the pointer register (command byte); no register changes without a following data byte
- **Register addressing:** 1-byte command byte (`RegisterConnection`, `reg_bytes = 1`). **No auto-increment:** the pointer is not advanced between data bytes — extra data bytes in one write transaction simply rewrite the same register, and a read transaction of n bytes returns the same register n times (the driver always accesses one byte per register)

## Register Map

All registers are 8 bits, selected by the pointer (command byte). Bits 7:2 of the command byte are 0.

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | INPUT | R | `xx` | Actual pin levels (regardless of direction); writes ignored; read clears the interrupt |
| `0x01` | OUTPUT | R/W | `0xFF` | Output latch: drives pins configured as outputs; reads return the latch, not the pin |
| `0x02` | POLARITY | R/W | `0x00` | Polarity inversion of pins configured as inputs: 1 = INPUT bit reads inverted |
| `0x03` | CONFIG | R/W | `0xFF` | Direction: 1 = input (high-Z), 0 = output |

Bit n of every register corresponds to pin Pn. Only registers `0x00`–`0x03` exist; the driver never writes other pointer values.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `INT`, open-drain, active low — requires an external pull-up |
| Level | 1 (single fixed condition) |
| Condition | any pin configured as an input changed state (rising or falling) relative to the last read of the INPUT register |
| Clear mechanism | read the INPUT register (cleared at the ACK/NACK clock of the read), or the pin returns to its original level |

An interrupt that occurs during the ACK/NACK clock pulse of an INPUT read can be lost. A pin configured as an output cannot interrupt; **changing a pin from output to input can raise a false interrupt** when the pin level differs from the last INPUT value.

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on INT (falling edge); `callback(changed_mask)` receives the bitmask of input pins whose level changed since the previous INPUT read. Uses `connection.int_pin` (or `int_pin`), otherwise a 5 ms polling task comparing INPUT reads |
| `off_interrupt` | `off_interrupt()` | Unsubscribe and stop delivery |
| `poll_interrupt` | `poll_interrupt() -> int` | Read INPUT (which clears INT), XOR with the driver's last INPUT value (masked to input pins), store the new value, return the changed-pin mask |

There is no interrupt-status register: the driver derives the changed mask itself (as the PCF8574 driver does) and caches the last INPUT value (initialised in `init`).

### Pin interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `watch` | `watch(handler, trigger=CHANGE)` | Subscribe to this pin's changes; `trigger` filters rising/falling/change in software; all pins share the single INT line |
| `unwatch` | `unwatch()` | Unsubscribe |

## Initialization Sequence

1. Write the reset state to guarantee a known start: OUTPUT ← `0xFF`, POLARITY ← `0x00`, CONFIG ← `0xFF` (all inputs; the user presets OUTPUT before turning pins into outputs).
2. Read INPUT to initialise the cached input value and release any pending interrupt.

No startup delay is required after power-on reset or RESET release (the datasheet gives trst = 600 ns as the maximum time the device needs after a reset event). VDD(P) must go through a defined power cycle for a power-on reset (see Timing Constraints).

## Implementation Stages

### Minimal

Goal: expose all 8 pins as GPIO objects with direction control and value read/write. No interrupt or polarity configuration required.

**Driver API**

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection (`addr=0x20`) | — | Runs the Initialization Sequence; shadow OUTPUT = `0xFF`, shadow CONFIG = `0xFF` |
| `pin` | `n: int` (0–7) | Pin | Pin proxy for Pn |
| `read_port` | `port: int = 0` | int | Read INPUT (actual pin levels) as a bitmask; `port` ignored |
| `write_port` | `port: int = 0`, `mask: int` | — | Write all 8 output bits via OUTPUT; updates the shadow; bits of input pins are stored but only take effect once the pin becomes an output |

**Sensible defaults:** all pins inputs (CONFIG `0xFF`), OUTPUT `0xFF`, no polarity inversion, interrupts not subscribed. Shadows of OUTPUT and CONFIG are kept so a single-pin change is one register write.

## GPIO Interface

The per-platform Pin contracts are identical to the MCP23008's (`specs/io_expander/mcp23008.md`, "GPIO Interface") with these differences: constants and the nested pin class live on `Pca6408aMinimal`; there are **no pull-up resistors**, so every pull-up entry point rejects the request (`AttributeError` / `UnsupportedOperationException` / compile-time absent in Rust) instead of writing a register; the nested pin classes are named per platform convention (`IOExpanderPin` in C++, `ExPin` in Rust, `Pin` in JVM). Interrupt callbacks take `callback(changed_mask)`. The Rust driver is generic over `embedded_hal::i2c::I2c`; re-export `pub use pca6408a::{Pca6408aMinimal, Pca6408aFull, ExPin};`.

## Data Conversion

```
pin n  →  bit n of the single 8-bit port

Read pin n:     value = (read_port() >> n) & 1                     # INPUT register
Write pin n:    shadow_output |= (1 << n)  or  &= ~(1 << n)
                write OUTPUT (0x01) ← shadow_output
Direction:      shadow_config &= ~(1 << n)  (output)  /  |= (1 << n)  (input)
                write CONFIG (0x03) ← shadow_config
Changed mask:   changed = (new_input ^ cached_input) & shadow_config   # input pins only
```

Making a pin an output writes its OUTPUT bit **before** clearing its CONFIG bit so the pin never glitches. Because OUTPUT resets to `0xFF`, a pin turned into an output with no prior write drives high.

### Demo flow

An inject node writes a rotating one-hot pattern to P0–P3 (LEDs, outputs), a second inject reads the full port once a second into a debug node (hex), and with the INT line wired the node emits `{ port: 0, changed: mask, value }` whenever a button on P4–P7 changes.

## Examples

### Demo

Wire four LEDs (active-low: anode to VDD(P) through 220 Ω, cathode to P0–P3 — the outputs sink up to 25 mA) and four push buttons (to ground, **with external pull-ups** because the chip has none) on P4–P7. The demo uses the Full driver: configure P0–P3 as outputs and P4–P7 as inputs, subscribe with `on_interrupt` (INT pin or 5 ms polling), and run a one-LED scanner; when a button interrupt fires the callback prints the changed mask and the INPUT value, and the LED matching the pressed button (P4→P0, …) lights for one second. The loop prints the scanner position and port state each iteration. Optionally enable `configure_polarity(0xF0)` so a pressed button reads as 1.

## Timing Constraints

- No startup delay; after a reset event the device needs trst ≤ 600 ns.
- RESET pulse width tw(rst) ≥ 30 ns; reset recovery before START trec(rst) ≥ 200 ns.
- INT valid after a port change tv(INT) ≤ 1 µs; INT reset after the read ACK/NACK trst(INT) ≤ 1 µs; port output valid after SCL tv(Q) ≤ 400 ns.
- I²C: fSCL ≤ 400 kHz, tLOW ≥ 1.3 µs, tHIGH ≥ 0.6 µs, tBUF ≥ 1.3 µs (fast mode; datasheet Table 16).
- Power-on reset (datasheet §9.2, Table 11): for a power-reset cycle VDD(P) must drop to VSS (or below VPOR(min) − 50 mV) and stay there for the reset delay td(rst) ≥ 1 (unit not legible in the extracted table — read it from Table 11 when implementing) before re-ramping; the reset trip voltage is ≥ 0.7 V falling and ≤ 1.4 V rising. A brown-out that does not cross VPOR does not reset the chip.
- **Conformance:** none of these has a bus-decodable start/end annotation pair (they are pin-level setup/hold and reset-pin events), so `specs/io_expander/pca6408a_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection, one byte per register:** accept `RegisterConnection` (1-byte address), call `connection.read(reg, 1)` / `connection.write(reg, bytes([v]))`; no `_read_reg`/`_write_reg`, no `bus_type` branch. SMBus (without PEC) works through the same API. See `specs/feature_register_access_design.md`.
- **No auto-increment:** unlike the MCP23008, never rely on multi-byte transfers to reach neighbouring registers; two registers need two transactions. A multi-byte read repeats the same register.
- **INPUT reflects pins, OUTPUT reflects the latch:** INPUT shows the real level even for output pins (an overloaded output can read low while OUTPUT = 1). Read-modify-write on outputs must use the shadow (or read OUTPUT), never INPUT.
- **Polarity applies to inputs only** and affects only the INPUT read-back, not the output latch.
- **Interrupt semantics:** edge-based on any input; cleared only by reading INPUT (or returning to the original level). Interrupts raised during the ACK/NACK of an INPUT read can be lost, and an output→input change can raise a false interrupt — after `set_direction` the driver refreshes its cached input value and drops that first spurious event. The first `poll_interrupt` after subscription compares against the value cached at `init`.
- **No pull-ups:** inputs float unless externally pulled; `Pull.UP` requests must raise rather than silently succeed. The chip's own LED-drive guidance (datasheet 9.1): keep the pin at or above VDD(P) when an LED is off to avoid extra supply current.
- **Two supply rails:** VDD(I2C-bus) must match the bus; VDD(P) sets the port logic level. Level translation is hardware — nothing to configure.
- **Relation to siblings:** same I²C addresses as MCP23008/MCP23017/PCF8574 (`0x20`/`0x21`), different register layout (the PCA6408A's 4 registers sit at `0x00`–`0x03` with INPUT/OUTPUT/POLARITY/CONFIG, which resembles the PCA9554/TCA6408A family). A shared GPIO-pin proxy base between the expander drivers is allowed.
- **Datasheet:** NXP Rev. 1 (27 September 2012) from a mirror; the TI TCA6408A (`https://www.ti.com/lit/ds/symlink/tca6408a.pdf`) is a functional equivalent but a different chip, not covered.

## Sigrok Decoder

Decoder id `pca6408a`, input `['i2c']`. Matches I²C addresses `0x20` and `0x21`. Annotates each write as register name + value (INPUT / OUTPUT / POLARITY / CONFIG) decoded into pin masks (CONFIG → `IN=P0,P3…` / `OUT=…`, OUTPUT and INPUT as 8-pin level strings, POLARITY → `INV=P4…`), each read likewise from the pointer set by the preceding write (repeated-start read) or by the last written pointer (stand-alone read, per Figure 11), and flags warnings for writes to INPUT (`0x00`), pointer values above `0x03`, and multi-byte writes or reads that repeat one register (no auto-increment). A change between consecutive INPUT reads is shown as a changed-pin mask. No timing annotation pair is emitted, since the datasheet defines no bus-decodable completion events.
