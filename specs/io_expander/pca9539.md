# Chip Spec: PCA9539 (IO Expander)

**Manufacturer:** Texas Instruments (originally Philips / NXP)  
**Datasheet:** `datasheets/io_expander/pca9539.pdf` (SCPS130H, revised March 2021)  
**Category:** `io_expander`  
**Transports:** I²C (the chip is SMBus-compatible; see Transport Configuration)

## Overview

The PCA9539 is a 16-bit general-purpose I/O expander for I²C / SMBus in a 24-pin package, operating from 2.3 V to 5.5 V. Its pins are split into two 8-bit ports (P00–P07 = port 0, P10–P17 = port 1), each with an Input Port, Output Port, Polarity Inversion and Configuration register. At power-on all I/Os are inputs. Outputs are latched push-pull drivers with LED-capable sink current (25 mA per pin recommended maximum), 5 V-tolerant I/Os, an active-low open-drain interrupt output (`INT`) that fires on any input change, an active-low `RESET` input and two address pins (A0, A1) for four devices on one bus. It is identical to the PCA9555 except that the internal I/O pull-up resistors were removed (much lower power when pins are held low), `A2` was replaced by `RESET`, and the address range moved to `0x74`–`0x77`. Typical uses: keypads, LED banks, board-level enable / reset lines, expansion of microcontroller GPIO.

## Transport Configuration

### I²C
- **Address:** `0x74` (A1 = A0 = GND) … `0x77` (A1 = A0 = VCC); address byte `1110 1 A1 A0 R/W`. A0 and A1 must be tied directly to VCC or ground

| A1 | A0 | Address |
|----|----|---------|
| L | L | `0x74` |
| L | H | `0x75` |
| H | L | `0x76` |
| H | H | `0x77` |

- **Max clock:** 400 kHz (fast mode); 100 kHz standard mode also supported
- **SMBus:** the datasheet title and text call the device "I2C and SMBus"; the protocol is plain "Write Byte / Read Byte" with the command byte as register pointer, so the driver works on an SMBus controller without PEC (not supported by the chip)
- **Identity register:** none; chip has no ID register (feeds `registry/chips.json` with `"id_probe": null` and `"driver": null` until implemented, see `specs/feature_i2c_discovery.md`)
- **Probe safety:** `register_pointer` — a 1-byte write only loads the command byte (register pointer); no register changes without a following data byte
- **Register addressing:** 1-byte command byte (`RegisterConnection`, `reg_bytes = 1`). **Register-pair toggling, not auto-increment:** the eight registers form four pairs (Input 0/1, Output 0/1, Polarity 0/1, Config 0/1). After a byte is written or read, the next byte goes to the *other* register of the pair (a write starting at Output Port 1 sends the 2nd byte to Output Port 0), so a two-byte transfer starting at the port-0 register covers both ports and never crosses into the next pair. There is no limit on the number of bytes; the pair keeps alternating

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| INT | low, open-drain | Interrupt output; requires a pull-up to VCC (4.7–100 kΩ) |
| RESET | low | Reset input; pulse ≥ 6 ns resets the registers and the I²C state machine without removing power; pull up to VCC if unused; **must not be driven above VCC** (current would flow into VCC) |
| A0, A1 | — | Address inputs, tied directly to VCC or GND |
| P00–P07 | — | Port 0 I/O, push-pull, 5 V tolerant, inputs at power-on |
| P10–P17 | — | Port 1 I/O, same |
| SDA, SCL | — | I²C; pull-ups to VCC |

## Register Map

All registers are 8 bits, selected by the command byte (bits 7:3 are 0; bits 2:0 select the register).

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | INPUT0 | R | `xx` | Actual levels of P00–P07 (regardless of direction); writes ignored; read releases the port-0 interrupt |
| `0x01` | INPUT1 | R | `xx` | Actual levels of P10–P17; read releases the port-1 interrupt |
| `0x02` | OUTPUT0 | R/W | `0xFF` | Output latch of port 0; reads return the latch, not the pin |
| `0x03` | OUTPUT1 | R/W | `0xFF` | Output latch of port 1 |
| `0x04` | POLARITY0 | R/W | `0x00` | Polarity inversion of port-0 pins configured as inputs: 1 = INPUT0 bit reads inverted |
| `0x05` | POLARITY1 | R/W | `0x00` | Polarity inversion of port 1 |
| `0x06` | CONFIG0 | R/W | `0xFF` | Direction of port 0: 1 = input (high-Z), 0 = output |
| `0x07` | CONFIG1 | R/W | `0xFF` | Direction of port 1 |

Bit n of a port register corresponds to pin Pxn. Only registers `0x00`–`0x07` exist; the driver never writes other pointer values.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `INT`, open-drain, active low — requires an external pull-up |
| Level | 1 (single fixed condition) |
| Condition | any pin configured as an input changed state (rising or falling) relative to the Input Port register value read last |
| Clear mechanism | read the Input Port register of the port that caused it (cleared at the ACK / NACK clock of the read), or the pin returns to its original level; ports are cleared independently — a read of INPUT1 does not clear a port-0 interrupt |

`INT` is valid within tiv = 4 µs of a port change and released within tir = 4 µs after SCL of the read. An interrupt that occurs during the ACK / NACK clock pulse of an Input Port read can be lost (or be very short). A pin configured as an output cannot cause an interrupt, and **changing a pin from output to input can raise a false interrupt** if the pin level differs from the last Input Port value. Writing to another device does not affect the interrupt circuit.

**Interrupt errata (datasheet §8.2.4.1):** `INT` is wrongly de-asserted if (1) the last command byte written to the PCA9539 was `0x00` (which is the case after any read of the Input Port, until another command byte is written) **and** (2) another slave on the bus acknowledges a read address. The workaround is to leave the command byte at something other than `0x00` after an Input Port read; the Full driver does this whenever an interrupt subscription is active (see Implementation Notes).

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on INT (falling edge); `callback(changed_mask)` receives the 16-bit mask of input pins whose level changed since the previous Input Port read (bit n = pin n; bits 0–7 port 0, 8–15 port 1). Uses `connection.int_pin` (or `int_pin`), otherwise a 5 ms poll of the driver |
| `off_interrupt` | `off_interrupt()` | Unsubscribe and stop delivery |
| `poll_interrupt` | `poll_interrupt() -> int` | Read both Input Port registers (one two-byte read, which releases both ports' interrupts), XOR with the driver's last input value (masked to input pins), store the new value, apply the errata workaround, return the 16-bit changed-pin mask |

There is no interrupt-status register: the driver derives the changed mask itself (as the PCA6408A and PCF8574 drivers do) and caches the last Input Port values (initialised in `init`).

### Pin interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `watch` | `watch(handler, trigger=CHANGE)` | Subscribe to this pin's changes; `trigger` filters rising / falling / change in software; all pins share the single INT line |
| `unwatch` | `unwatch()` | Unsubscribe |

## Initialization Sequence

1. Write the reset state to guarantee a known start: OUTPUT0 / OUTPUT1 ← `0xFF`, POLARITY0 / POLARITY1 ← `0x00`, CONFIG0 / CONFIG1 ← `0xFF` (all inputs; the user presets the output latch before turning pins into outputs). Each is a two-byte write starting at the port-0 register (pair toggling covers port 1).
2. Read INPUT0 / INPUT1 (one two-byte read) to initialise the cached input values and release any pending interrupt.

No startup delay is required after power-on reset or RESET release (the datasheet gives tRESET = 400 ns as the time the device needs to reset, tREC = 0). VCC must go through a defined power cycle for a power-on reset (see Timing Constraints).

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal.

The defining characteristic of an IO expander driver is that it exposes individual **Pin objects** that implement each platform's native GPIO interface — see the GPIO Interface section below. Users obtain a pin from the driver and use it exactly like a hardware GPIO pin.

### Minimal

Goal: expose all 16 pins as GPIO objects with direction control and value read / write. No interrupt or polarity configuration required.

**Driver API**

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection (`addr=0x74`) | — | Runs the Initialization Sequence; shadows OUTPUT = `[0xFF, 0xFF]`, CONFIG = `[0xFF, 0xFF]` |
| `pin` | `n: int` (0–15) | Pin | Pin proxy for pin `n` (0–7 = P00–P07, 8–15 = P10–P17) |
| `read_port` | `port: int` (0 or 1) | int | Read INPUTx (actual pin levels) as an 8-bit bitmask |
| `write_port` | `port: int`, `mask: int` | — | Write all 8 output bits of the port via OUTPUTx; updates the shadow; bits of input pins are stored but only take effect once the pin becomes an output |

**Sensible defaults:** all pins inputs (CONFIG `0xFF`), OUTPUT `0xFF`, no polarity inversion, interrupts not subscribed. Shadows of OUTPUT and CONFIG (both ports) are kept so a single-pin change is one register write.

## GPIO Interface

The per-platform Pin contracts are identical to the PCA6408A's and MCP23008's (`specs/io_expander/pca6408a.md`, `specs/io_expander/mcp23008.md`, "GPIO Interface") with these differences: constants and the nested pin class live on `Pca9539Minimal`; the pin numbers run 0–15 (pin `n` ↔ port `n / 8`, bit `n % 8`); there are **no pull-up resistors**, so every pull-up entry point rejects the request (`AttributeError` / `UnsupportedOperationException` / compile-time absent in Rust) instead of writing a register; the nested pin classes are named per platform convention (`IOExpanderPin` in C++, `ExPin` in Rust, `Pin` in JVM). Interrupt callbacks take `callback(changed_mask)` with a 16-bit mask. The Rust driver is generic over `embedded_hal::i2c::I2c`; re-export `pub use pca9539::{Pca9539Minimal, Pca9539Full, ExPin};`.

## Data Conversion

```
pin n  →  port = n // 8, bit = n % 8        (P00..P07 = pins 0..7, P10..P17 = pins 8..15)

Read pin n:     value = (read_port(n // 8) >> (n % 8)) & 1            # INPUT0 / INPUT1
Write pin n:    shadow_output[port] |= (1 << bit)  or  &= ~(1 << bit)
                write OUTPUT0 + port (0x02 + port) <- shadow_output[port]
Direction:      shadow_config[port] &= ~(1 << bit)  (output)  /  |= (1 << bit)  (input)
                write CONFIG0 + port (0x06 + port) <- shadow_config[port]
16-bit view:    value16 = INPUT0 | (INPUT1 << 8)       # one two-byte read starting at 0x00
Changed mask:   changed = (new_input16 ^ cached_input16) & shadow_config16   # input pins only
```

Making a pin an output writes its OUTPUT bit **before** clearing its CONFIG bit so the pin never glitches. Because OUTPUT resets to `0xFF`, a pin turned into an output with no prior write drives high.

### Demo flow

An inject node writes a rotating one-hot pattern to P00–P07 (LEDs, outputs), a second inject reads port 1 (P10–P17, buttons) once a second into a debug node (hex), and with the INT line wired the node emits `{ changed: mask, value }` whenever a button on port 1 changes. Shows output control on one port and interrupt-driven input on the other.

## Examples

### Demo

Wire eight LEDs (active-low: anode to VCC through 220 Ω, cathode to P00–P07 — each output sinks up to 25 mA, keep the octal ≤ 100 mA) and eight push buttons (to ground, **with external pull-ups** because the chip has none) on P10–P17. The demo uses the Full driver: configure P00–P07 as outputs (`set_direction(0xFF00)`) and P10–P17 as inputs, `configure_polarity(0xFF00)` so a pressed button reads as 1, subscribe with `on_interrupt` (INT pin or 5 ms polling), and run a one-LED scanner with `write_all`. When a button interrupt fires the callback prints the changed mask and the `read_all()` value, and the LED matching the pressed button (P10 → P00, …) lights for one second. The loop prints the scanner position and the 16-bit port state each iteration.

## Timing Constraints

- No startup delay; after a reset event (power-on or RESET) the device needs tRESET ≤ 400 ns; reset recovery tREC = 0 ns.
- RESET pulse width tW ≥ 6 ns.
- INT valid after a port change tiv ≤ 4 µs; INT reset delay after SCL of the read tir ≤ 4 µs; port output valid after SCL tpv ≤ 200 ns; port input setup before SCL tps ≥ 150 ns, hold tph ≥ 1 µs.
- I²C: fSCL ≤ 400 kHz, tSCL (low) ≥ 1.3 µs, tSCH (high) ≥ 0.6 µs, tBUF ≥ 1.3 µs, START setup / hold ≥ 0.6 µs, STOP setup ≥ 0.6 µs, data setup ≥ 100 ns (fast mode, datasheet §6.6).
- Power-on reset: the internal POR releases when VCC reaches VPOR (≤ 1.5 V rising; the reset condition re-arms below ≈ 0.75–1 V falling); for a power-reset cycle VCC must drop below 0.2 V before rising again (§8.2.2).
- **Conformance:** none of these has a bus-decodable start / end annotation pair (they are pin-level setup / hold and reset-pin events), so `specs/io_expander/pca9539_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection, one byte per register:** accept `RegisterConnection` (1-byte address), call `connection.read(reg, n)` / `connection.write(reg, data)`; no `_read_reg`/`_write_reg`, no `bus_type` branch. SMBus (without PEC) works through the same API.
- **Register pairs toggle:** `connection.read(0x00, 2)` returns INPUT0 then INPUT1; `connection.write(0x02, bytes([out0, out1]))` writes OUTPUT0 then OUTPUT1 (likewise `0x04` / `0x06`). Starting at the port-1 register swaps the order (the second byte lands in port 0). Longer transfers keep alternating within the pair — never rely on them to reach the next pair.
- **INPUT reflects pins, OUTPUT reflects the latch:** INPUT shows the real level even for output pins (an overloaded output can read low while OUTPUT = 1). Read-modify-write on outputs must use the shadow (or read OUTPUT), never INPUT.
- **Polarity applies to inputs only** and affects only the INPUT read-back, not the output latch.
- **Interrupt semantics:** edge-based on any input; cleared only by reading the INPUT register of that port (or returning to the original level). Interrupts raised during the ACK / NACK of an INPUT read can be lost, and an output → input change can raise a false interrupt — after `set_direction` or a pin direction change to input, the driver reads the input registers once (refreshing the cache) and the false event is filtered out of the changed mask.
- **Interrupt errata workaround:** while an interrupt subscription is active (`on_interrupt`), the Full driver rewrites OUTPUT0 (`connection.write(0x02, shadow_output0)`, an idempotent write of the shadow value) after every INPUT read so the stored command byte is not `0x00` when another device on the bus acknowledges a read address; without a subscription the extra transaction is skipped. The datasheet notes the workaround is compatible with other versions of the part.
- **No pull-ups:** inputs float unless externally pulled; `Pull.UP` requests must raise rather than silently succeed. Because the pins have no weak pull-up, standby current stays at ≈ 1.5 µA (typ.) even with pins held low.
- **RESET pin:** externally driven; if unused, pull up to VCC. Its voltage must not exceed VCC (errata §8.2.1.1) or current flows RESET → VCC.
- **LED drive:** outputs sink 25 mA max per pin; the device-wide limits (octal 100 mA, device 200 mA, VCC 160 mA) apply.
- **Relation to siblings:** the PCA9555 has the same register map (`0x00`–`0x07`) but internal 100 kΩ pull-ups, an `A2` pin and addresses `0x20`–`0x27`; the PCA9539 uses `0x74`–`0x77`, a `RESET` pin and no pull-ups. A future PCA9555 driver could share a register-level helper. The TCA9539 (TI's redesign, same addresses) is register-compatible; the datasheet notes "compatible with other versions and TI redesigns" for the interrupt workaround only — no other compatibility is assumed.
- **Datasheet:** TI SCPS130H (March 2021), the 10-page PDF returned by the issue URL; the register tables, interface timing and errata used here are all in the committed copy.

## Sigrok Decoder

Decoder id `pca9539`, input `['i2c']`. Matches I²C addresses `0x74`–`0x77`. Annotates each write as register name + value (INPUT0/1, OUTPUT0/1, POLARITY0/1, CONFIG0/1) decoded into pin masks (CONFIG → `IN=P00,P03…` / `OUT=…`, OUTPUT and INPUT as 8-pin level strings, POLARITY → `INV=P14…`); tracks the register-pair toggling so every byte of a multi-byte transfer is named by its own register (e.g. a two-byte read at `0x00` = INPUT0 then INPUT1, combined into a 16-bit value in the long annotation); each read is decoded from the pointer set by the preceding write (repeated-start read) or by the last written pointer (stand-alone read, per Figure 8-11). A change between consecutive INPUT reads is shown as a changed-pin mask. Warnings: write to INPUT0/1 (`0x00`/`0x01`), pointer values above `0x07`, and a read of INPUT0/INPUT1 followed by another device's read address while the stored pointer is `0x00` (interrupt-errata hint: "INT may de-assert"). No timing annotation pair is emitted, since the datasheet defines no bus-decodable completion events.
