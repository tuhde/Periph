# Chip Spec: TCA9554 (IO Expander)

**Manufacturer:** Texas Instruments  
**Datasheet:** `datasheets/io_expander/tca9554.pdf` (SCPS233E, March 2012 – revised February 2017)  
**Category:** `io_expander`  
**Transports:** I²C, SMBus

## Overview

The TCA9554 is an 8-bit general-purpose I/O expander with an I²C / SMBus interface, a single 8-pin port (P0–P7), per-pin direction (Configuration register), input polarity inversion, latched push-pull outputs (up to 25 mA sink for LEDs at Tj ≤ 65 °C), an open-drain interrupt output and low standby current. One supply rail VCC (1.65–5.5 V) powers the chip, and the I/O is 5 V tolerant. **Inputs have a fixed internal 100 kΩ pull-up to VCC** (the one feature that distinguishes it from the TCA9534) that cannot be switched off, and there is **no RESET pin** — the only reset is a power-on reset by cycling VCC. Three address pins give eight I²C addresses. It is register-compatible with the PCA6408A (INPUT/OUTPUT/POLARITY/CONFIG at `0x00`–`0x03`) and the lean sibling of the MCP23008: four registers, no interrupt-flag/capture registers and no default-compare interrupt mode.

The **TCA9554A** is identical except for its fixed address range `0x38`–`0x3F`; the drivers accept any address, but the registry entry and decoder cover the TCA9554 range `0x20`–`0x27` only.

## Transport Configuration

### I²C / SMBus
- **Address:** `0x20` (A2 = A1 = A0 = GND) … `0x27` (all VCC); address byte `0100 A2 A1 A0 R/W`. A2/A1/A0 must be tied directly to VCC or ground
- **Max clock:** 400 kHz (fast mode); 100 kHz standard mode also supported. Drivers use ≤ 400 kHz
- **SMBus:** the protocol is plain "Write Byte / Read Byte" with the command byte as register pointer, so the chip works on an SMBus (the datasheet states SMBus compatibility; PEC is not supported and must not be enabled for this chip). The driver accepts either an `I2CConnection` or an `SMBusConnection` (without PEC) — it only needs byte-register access
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`; it shares `0x20`–`0x27` with the PCA6408A (`0x20`–`0x21`), PCA9536, MCP23008/MCP23017, PCF8574 and others, none of which can be told apart)
- **Probe safety:** `register_pointer` — a 1-byte write only loads the pointer register (command byte); no register changes without a following data byte
- **Register addressing:** 1-byte command byte (`RegisterConnection`, `reg_bytes = 1`). **No auto-increment:** the register that was addressed continues to be accessed by reads until a new command byte is sent — a read transaction of n bytes returns the same register n times and extra data bytes in a write rewrite the same register (the driver always accesses one byte per register)

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| INT | low, open-drain | Interrupt output; requires an external pull-up to VCC |
| A0, A1, A2 | — | Address bits 0–2; tie directly to VCC or GND |
| VCC | — | Supply 1.65–5.5 V (tie SCL/SDA pull-ups to the same VCC) |
| P0–P7 | — | Port pins, push-pull, 5 V tolerant; all inputs (with 100 kΩ pull-up) at power-on |
| SDA, SCL | — | I²C / SMBus |

There is no RESET pin.

## Register Map

All registers are 8 bits, selected by the pointer (command byte). Bits 7:2 of the command byte are 0 (the control register is `0000 0 B2 B1 B0`; the datasheet lists only `0x00`–`0x03`).

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | INPUT | R | `xx` | Actual pin levels (regardless of direction), determined by the applied levels; writes ignored; read clears the interrupt |
| `0x01` | OUTPUT | R/W | `0xFF` | Output latch: drives pins configured as outputs; reads return the latch, not the pin |
| `0x02` | POLARITY | R/W | `0x00` | Polarity inversion of pins configured as inputs: 1 = INPUT bit reads inverted |
| `0x03` | CONFIG | R/W | `0xFF` | Direction: 1 = input (high-Z), 0 = output |

Bit n of every register corresponds to pin Pn. Only registers `0x00`–`0x03` exist; the driver never writes other pointer values.

## Pin Capabilities

| Capability | Support |
|-----------|---------|

| Ports | 1 × 8-bit |
| Direction | per-pin via CONFIG (1 = input, 0 = output) |

| Pull-down | no |
| Open-drain output | no — push-pull output (to VCC/GND) |

| Drive strength | no |

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `INT`, open-drain, active low — requires an external pull-up to VCC |
| Level | 1 (single fixed condition) |
| Condition | any pin configured as an input changed state (rising or falling) relative to the last read of the INPUT register |
| Clear mechanism | read the INPUT register (cleared at the ACK/NACK clock of the read), or the pin returns to its original level |

An interrupt that occurs during the ACK/NACK clock pulse of an INPUT read can be lost. A pin configured as an output cannot interrupt; **changing a pin from output to input can raise a false interrupt** when the pin level differs from the last INPUT value.

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on INT (falling edge); `callback(changed_mask)` receives the bitmask of input pins whose level changed since the previous INPUT read. Uses `connection.int_pin` (or `int_pin`), otherwise a 5 ms polling task comparing INPUT reads |
| `off_interrupt` | `off_interrupt()` | Unsubscribe and stop delivery |
| `poll_interrupt` | `poll_interrupt() -> int` | Read INPUT (which clears INT), XOR with the driver's last INPUT value (masked to input pins), store the new value, return the changed-pin mask |

There is no interrupt-status register: the driver derives the changed mask itself (as the PCF8574 driver does) and caches the last INPUT value (initialised in `init`).

### Pin interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `watch` | `watch(handler, trigger=CHANGE)` | Subscribe to this pin's changes; `trigger` filters rising/falling/change in software; all pins share the single INT line |
| `unwatch` | `unwatch()` | Unsubscribe |

## Initialization Sequence

1. Write the reset state to guarantee a known start: OUTPUT ← `0xFF`, POLARITY ← `0x00`, CONFIG ← `0xFF` (all inputs; the user presets OUTPUT before turning pins into outputs).
2. Read INPUT to initialise the cached input value and release any pending interrupt.

No startup delay is specified after the power-on reset releases (internal POR, VPORR ≤ 1.5 V rising). There is no RESET pin: a reset requires cycling VCC (see Timing Constraints).

## Implementation Stages

### Minimal

Goal: expose all 8 pins as GPIO objects with direction control and value read/write. No interrupt or polarity configuration required.

**Driver API**

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection (`addr=0x20`) | — | Runs the Initialization Sequence; shadow OUTPUT = `0xFF`, shadow CONFIG = `0xFF` |
| `pin` | `n: int` (0–7) | Pin | Pin proxy for Pn |
| `read_port` | `port: int = 0` | int | Read INPUT (actual pin levels) as a bitmask; `port` ignored |
| `write_port` | `port: int = 0`, `mask: int` | — | Write all 8 output bits via OUTPUT; updates the shadow; bits of input pins are stored but only take effect once the pin becomes an output |

**Sensible defaults:** all pins inputs (CONFIG `0xFF`), OUTPUT `0xFF`, no polarity inversion, interrupts not subscribed. Shadows of OUTPUT and CONFIG are kept so a single-pin change is one register write.

### Full

Goal: expose complete chip functionality. Extends Minimal.

**Driver API additions**

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `configure_polarity` | `mask: int` | — | POLARITY ← `mask` (1 = invert that input's INPUT bit); the driver compares interrupts on the inverted values, which is equivalent |
| `get_direction` | — | int | Shadow CONFIG |

**Additional configuration options:** polarity inversion (POLARITY), whole-port direction, interrupt delivery (INT pin or polling).

## GPIO Interface

The per-platform Pin contracts are identical to the MCP23008's (`specs/io_expander/mcp23008.md`, "GPIO Interface") with these differences: constants and the nested pin class live on `Tca9554Minimal`; the **pull-up is fixed and always on**, so a request to enable it is accepted as a no-op and a request to disable it (`Pull.DOWN`, `None`/`False`) is rejected (`AttributeError` / `UnsupportedOperationException` / compile-time absent in Rust) instead of writing a register; the nested pin classes are named per platform convention (`IOExpanderPin` in C++, `ExPin` in Rust, `Pin` in JVM). Interrupt callbacks take `callback(changed_mask)`. The Rust driver is generic over `embedded_hal::i2c::I2c`; re-export `pub use tca9554::{Tca9554Minimal, Tca9554Full, ExPin};`.

## Data Conversion

```
pin n  →  bit n of the single 8-bit port

Read pin n:     value = (read_port() >> n) & 1                     # INPUT register
Write pin n:    shadow_output |= (1 << n)  or  &= ~(1 << n)
                write OUTPUT (0x01) ← shadow_output
Direction:      shadow_config &= ~(1 << n)  (output)  /  |= (1 << n)  (input)
                write CONFIG (0x03) ← shadow_config
Changed mask:   changed = (new_input ^ cached_input) & shadow_config   # input pins only
```

Making a pin an output writes its OUTPUT bit **before** clearing its CONFIG bit so the pin never glitches. Because OUTPUT resets to `0xFF`, a pin turned into an output with no prior write drives high.

### Demo flow

An inject node writes a rotating one-hot pattern to P0–P3 (LEDs, outputs), a second inject reads the full port once a second into a debug node (hex), and with the INT line wired the node emits `{ port: 0, changed: mask, value }` whenever a button on P4–P7 changes.

## Examples

### Demo

Wire four LEDs (anode to VCC through 220 Ω, cathode to P0–P3 — active-low, the outputs sink the current) and four push buttons to ground on P4–P7 (the chip's internal 100 kΩ pull-ups hold the inputs high, so no external pull-ups are needed). The demo uses the Full driver: configure P0–P3 as outputs and P4–P7 as inputs, subscribe with `on_interrupt` (INT pin or 5 ms polling), and run a one-LED scanner; when a button interrupt fires the callback prints the changed mask and the INPUT value, and the LED matching the pressed button (P4→P0, …) lights for one second. The loop prints the scanner position and port state each iteration. Optionally enable `configure_polarity(0xF0)` so a pressed button reads as 1.

## Timing Constraints

- No startup delay is specified after the internal power-on reset releases.
- Output data valid after SCL tpv ≤ 350 ns; input data setup tps ≥ 100 ns and hold tph ≥ 1 µs relative to SCL (read of the port at the ACK clock).
- INT valid after a port change tiv ≤ 4 µs; INT reset delay from the read ACK clock tir ≤ 4 µs (standard and fast mode).
- I²C: fast mode ≤ 400 kHz (tLOW ≥ 1.3 µs, tHIGH ≥ 0.6 µs, tBUF ≥ 1.3 µs per the I²C fast-mode specification; see the datasheet I²C timing table) — clock-rate properties, not event-to-event delays.
- Power-on reset (datasheet §10.1, Table 8): the chip resets when VCC rises through VPORR (1.2 V typ., 1.5 V max). To force a reset VCC must fall below VPORF (0.75 V min, 1 V max; i.e. below VPOR(min) − 50 mV) and stay there for at least 2 µs before re-ramping; recommended fall time 1–2000 ms and rise time 0.1–2000 ms. A glitch down to ≥ 1.5 V, or one shorter than 10 µs that stays above 1.2 V, does not disturb the chip.
- **Conformance:** none of these has a bus-decodable start/end annotation pair (they are pin-level setup/hold, reset and supply events), so `specs/io_expander/tca9554_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection, one byte per register:** accept `RegisterConnection` (1-byte address), call `connection.read(reg, 1)` / `connection.write(reg, bytes([v]))`; no `_read_reg`/`_write_reg`, no `bus_type` branch. SMBus (without PEC) works through the same API. See `specs/feature_register_access_design.md`.
- **No auto-increment:** unlike the MCP23008, never rely on multi-byte transfers to reach neighbouring registers; two registers need two transactions. A multi-byte read repeats the same register.
- **INPUT reflects pins, OUTPUT reflects the latch:** INPUT shows the real level even for output pins (an overloaded output can read low while OUTPUT = 1). Read-modify-write on outputs must use the shadow (or read OUTPUT), never INPUT.
- **Polarity applies to inputs only** and affects only the INPUT read-back, not the output latch.
- **Interrupt semantics:** edge-based on any input; cleared only by reading INPUT (or returning to the original level). Interrupts raised during the ACK/NACK of an INPUT read can be lost, and an output→input change can raise a false interrupt — after `set_direction` the driver refreshes its cached input value and drops that first spurious event. The first `poll_interrupt` after subscription compares against the value cached at `init`.
- **Fixed pull-ups:** every input has a weak 100 kΩ (typ.) pull-up to VCC that cannot be disabled; unused pins need no external termination. Driving an input above VCC (up to 5.5 V) sinks current through that pull-up into VCC. Pull-up *enable* requests succeed as no-ops; *disable* requests raise. With an LED to VCC keep the pin high when off to avoid extra supply current.
- **Single supply:** VCC (1.65–5.5 V) powers the core and sets the port logic level; tie the SCL/SDA pull-ups to the same VCC (an auxiliary supply that can be on while VCC is off raises ICC).
- **Relation to siblings:** same I²C addresses as MCP23008/MCP23017/PCF8574 (`0x20`–`0x27`), different register layout; register-compatible with the PCA6408A (and the TCA9534 minus pull-ups, TCA9554A at `0x38`–`0x3F`, NXP PCA9554). A shared GPIO-pin proxy base between the expander drivers is allowed.
- **Datasheet:** SCPS233E, downloaded from `https://www.ti.com/lit/ds/symlink/tca9554.pdf`.

## Sigrok Decoder

Decoder id `tca9554`, input `['i2c']`. Matches I²C addresses `0x20`–`0x27`. Annotates each write as register name + value (INPUT / OUTPUT / POLARITY / CONFIG) decoded into pin masks (CONFIG → `IN=P0,P3…` / `OUT=…`, OUTPUT and INPUT as 8-pin level strings, POLARITY → `INV=P4…`), each read likewise from the pointer set by the preceding write (repeated-start read) or by the last written pointer (stand-alone read, per Figure 11), and flags warnings for writes to INPUT (`0x00`), pointer values above `0x03`, and multi-byte writes or reads that repeat one register (no auto-increment). A change between consecutive INPUT reads is shown as a changed-pin mask. No timing annotation pair is emitted, since the datasheet defines no bus-decodable completion events.
