# Chip Spec: MCP23008 / MCP23S08 (IO Expander)

**Manufacturer:** Microchip Technology  
**Datasheet:** `datasheets/io_expander/mcp23008.pdf` (DS21919E, shared MCP23008 / MCP23S08 datasheet)  
**Category:** `io_expander`  
**Transports:** I²C (MCP23008) and SPI (MCP23S08)

## Overview

The MCP23008 (I²C) and MCP23S08 (SPI) are 8-bit general-purpose bidirectional I/O port expanders: one 8-bit port (GP0–GP7) with per-pin direction (IODIR), polarity inversion (IPOL), 100 kΩ pull-up (GPPU), output latch (OLAT) and interrupt-on-change (GPINTEN / DEFVAL / INTCON) registers. The two chips have an **identical register map and GPIO/interrupt behavior**; they differ only in the serial interface and the number of hardware address pins (MCP23008: A2/A1/A0, eight I²C addresses; MCP23S08: A1/A0, four SPI device addresses sharing one chip select). Each pin can sink or source up to 25 mA. One INT output (configurable active-high, active-low or open-drain) signals pin changes, either against the previous pin value or against a DEFVAL reference; INTCAP freezes the port state at the interrupt.

This spec covers **both chips** as requested in the issue. They are one driver family sharing a base class: `Mcp23008Minimal` / `Mcp23008Full` (I²C) and `Mcp23S08Minimal` / `Mcp23S08Full` (SPI) — see Implementation Notes. Unlike the 16-bit MCP23017 (`specs/io_expander/mcp23017.md`) there is a single port, no BANK / MIRROR bits, and **all eight pins (including GP7) are true bidirectional I/O**.

## Transport Configuration

### I²C (MCP23008)
- **Address:** `0x20` (default, A2=A1=A0=0) — `0x21`–`0x27` (A2:A0 added to `0x20`); control byte `0100 A2 A1 A0 R/W`
- **Max clock:** 100 kHz @ 1.8–5.5 V; 400 kHz @ 2.7–5.5 V; 1.7 MHz @ 4.5–5.5 V (E-temp). Drivers use up to 400 kHz
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`; it shares `0x20`–`0x27` with the MCP23017, which cannot be told apart either)
- **Probe safety:** `register_pointer` — a 1-byte write only sets the register address pointer
- **Register addressing:** 1-byte register address (`RegisterConnection`, `reg_bytes = 1`); sequential read/write auto-increments (SEQOP = 0) and the pointer rolls over from `0x0A` to `0x00`

### SPI (MCP23S08)
- **Mode:** CPOL=0 CPHA=0 (Mode 0) — Mode 1,1 is also supported by the chip; drivers use Mode 0
- **Max clock:** 5 MHz @ 1.8–5.5 V; 10 MHz @ 2.7–5.5 V
- **Bit order:** MSB first
- **CS active:** low; every transaction is one CS-low frame
- **Framing:** **opcode byte + register address byte, then data** — `[0x40 | (A1A0 << 1) | R/W] [reg] [data…]` with R/W = 1 for read. This is *not* the read-bit-folded-into-address convention of `SPIConnection` (`specs/feature_register_access_design.md` §4, §11.4); the driver builds the two header bytes itself and talks to a plain `Connection` (`write` for writes, `write_read(header, n)` for reads), as the ADXL362 driver does
- **Device address:** A1:A0 pins. At power-up `IOCON.HAEN` = 0 and the address pins are ignored (the device decodes address `00`); the driver sets `HAEN` = 1 in `init` so up to four devices can share one CS line (see Implementation Notes)
- **Sequential access:** same auto-increment / roll-over behavior as I²C (hold CS low and keep clocking)
- **Identity register:** none (SPI is not part of the I²C discovery registry)

| NC (MCP23008) / CS (MCP23S08) | low | Chip select on the MCP23S08 |
| SDA/SI, SCL/SCK | — | I²C data/clock (external pull-ups) or SPI data-in/clock |

## Register Map

All registers are 8 bits, accessed by a 1-byte register address (no banks).

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | IODIR | R/W | `0xFF` | Direction: 1 = input, 0 = output |
| `0x01` | IPOL | R/W | `0x00` | Input polarity: 1 = GPIO bit reads inverted |
| `0x02` | GPINTEN | R/W | `0x00` | Interrupt-on-change enable |
| `0x03` | DEFVAL | R/W | `0x00` | Default compare value (for INTCON = 1) |
| `0x04` | INTCON | R/W | `0x00` | 1 = compare against DEFVAL, 0 = compare against previous pin value |
| `0x05` | IOCON | R/W | `0x00` | Expander configuration (bits 7:6 and 0 read 0) |
| `0x06` | GPPU | R/W | `0x00` | Pull-up enable: 1 = 100 kΩ pull-up on an input |
| `0x07` | INTF | R | `0x00` | Interrupt flag: 1 = pin caused the interrupt |
| `0x08` | INTCAP | R | — | Port state captured at the interrupt (read clears the interrupt) |
| `0x09` | GPIO | R/W | `0x00` | Read: pin levels; write: sets OLAT |
| `0x0A` | OLAT | R/W | `0x00` | Output latch: read = latch value, not pin level |

### Bit Fields

#### `IOCON` (`0x05`)

| Bits | Name | Description |
|------|------|-------------|
| 7:6 | — | Unimplemented, read 0 |
| 5 | SEQOP | 1 = sequential operation disabled (address pointer does not increment); 0 = enabled (default) |
| 4 | DISSLW | SDA slew-rate control: 1 = slew rate disabled (I²C only) |
| 3 | HAEN | Hardware address enable, **MCP23S08 only** (ignored on MCP23008, address pins always active): 1 = A1:A0 pins enabled |
| 2 | ODR | INT open-drain: 1 = open-drain (overrides INTPOL), 0 = active driver |
| 1 | INTPOL | INT polarity when ODR = 0: 1 = active-high, 0 = active-low |
| 0 | — | Unimplemented, read 0 |

The other registers (IODIR, IPOL, GPINTEN, DEFVAL, INTCON, GPPU, INTF, INTCAP, GPIO, OLAT) are plain 8-bit masks with bit n ↔ pin GPn.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `INT`, push-pull active-low by default (`ODR`/`INTPOL`) |
| Level | 1 (single fixed condition: an enabled input pin changed / mismatched DEFVAL) |
| Condition | any pin enabled in GPINTEN differs from its reference (previous value or DEFVAL) |
| Clear mechanism | read INTCAP or GPIO (writes do not clear). In DEFVAL mode the condition persists while the pin still differs |

The first interrupt copies the port into INTCAP; further events do not update INTCAP or re-assert INT until the interrupt is cleared. INTF always shows the current set of pins with a pending condition.

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None, mode='change')` | Subscribe; `callback(status)` receives the INTF bitmask of pins that caused the interrupt. `mode='change'` sets INTCON = 0 for armed pins, `'default'` sets INTCON = 1 (compare vs DEFVAL). Uses `connection.int_pin` (or `int_pin`) if wired, otherwise a 5 ms polling task |
| `off_interrupt` | `off_interrupt()` | Unsubscribe and stop delivery |
| `poll_interrupt` | `poll_interrupt() -> int` | Read INTF, then read INTCAP (clearing the interrupt); returns the INTF mask. The captured value is discarded — use `read_capture` |
| `read_capture` | `read_capture() -> int` | Read INTCAP — the port state at the moment of the interrupt; also clears the interrupt |

`on_interrupt` arms every pin that was enabled with `enable_pin_interrupt` (no pins armed → raises). INT polarity/drive are configured with `configure_int_pin`.

### Pin interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `watch` | `watch(handler, trigger=CHANGE)` | Enable this pin in GPINTEN and subscribe; `trigger` filters rising/falling/change in software (the chip reports changes only) |
| `unwatch` | `unwatch()` | Clear this pin's GPINTEN bit and unsubscribe |

## Initialization Sequence

1. (SPI only) Write IOCON ← `HAEN | …` using the **address-0 opcode** (`0x40`) so a not-yet-addressed device accepts it, then use the real opcode from then on. I²C needs no equivalent step.
2. Write OLAT ← `0x00` — clear output latches before any pin becomes an output.
3. Leave IODIR = `0xFF` (all inputs), GPPU = `0x00`, IPOL = `0x00`, GPINTEN = `0x00`, IOCON = `0x00` (I²C) / `HAEN` (SPI).

No startup delay is required after power-on reset or RESET release (the datasheet gives only a minimum VDD rise rate of 0.05 V/ms for a clean POR).

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal.

The defining characteristic of an IO expander driver is that it exposes individual **Pin objects** that implement each platform's native GPIO interface — see the GPIO Interface section below. Users obtain a pin from the driver and use it exactly like a hardware GPIO pin.

Both transports have the same API; `Mcp23S08*` differs only in construction (SPI `Connection` plus device address `addr` 0–3 instead of an I²C address).

### Minimal

Goal: expose all 8 pins as GPIO objects with direction control and value read/write. No interrupt or pull-up configuration required.

**Driver API**

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection (`addr=0x20` I²C, `addr=0` SPI) | — | Runs the Initialization Sequence; shadow OLAT = `0x00`, shadow IODIR = `0xFF` |
| `pin` | `n: int` (0–7) | Pin | Pin proxy for GPn |
| `read_port` | `port: int = 0` | int | Read GPIO (actual pin levels) as a bitmask; `port` is ignored |
| `write_port` | `port: int = 0`, `mask: int` | — | Write all 8 output bits via OLAT; updates the shadow; bits of input pins are stored but have no effect until the pin becomes an output |

**Sensible defaults:** IODIR = `0xFF` (all inputs), OLAT = `0x00`, pull-ups off, no polarity inversion, interrupts disabled, IOCON = `0x00` (`HAEN` set on SPI). Shadows of OLAT and IODIR are kept so a single-pin change is a one-register write.

## GPIO Interface

This section defines the per-platform contracts for Pin objects. See `AGENTS.md` for implementation patterns. The contracts are identical to the MCP23017's (`specs/io_expander/mcp23017.md`, "GPIO Interface") with these differences: constants and the nested pin class live on `Mcp23008Minimal` (and are inherited by `Mcp23S08Minimal`); there is a single port, so interrupt callbacks take `callback(status)` only; GP7 is a normal bidirectional pin (no output-only restriction).

### Python — MicroPython / CircuitPython / Linux

MicroPython and Linux pins implement a compatible subset of `machine.Pin` (`init(mode[, pull])`, `value([x])`, `on()`, `off()`, `toggle()`, Full: `watch(handler, trigger)`, `unwatch()`; constants `IN`, `OUT`, `PULL_UP`, `IRQ_RISING`, `IRQ_FALLING`). CircuitPython pins implement `digitalio.DigitalInOut` (`direction`, `value`, `switch_to_input()`, `switch_to_output(value=False)`, Full: `pull` — `Pull.UP` or `None`, `Pull.DOWN` raises `AttributeError`; `drive_mode` is push-pull only). Interrupt delivery uses `connection.int_pin.on_edge()` when wired, otherwise a 5 ms polling thread calling `poll_interrupt()`.

### C++

`IOExpanderPin` nested class with `mode(INPUT|OUTPUT|INPUT_PULLUP)`, `write`, `read`, `high`, `low`, `toggle`; Full adds `watch(handler, trigger)` / `unwatch()` (`trigger` = `InputPin::kFalling`/`kRising`/`kChange`) and driver-level `onInterrupt(callback, intPin=nullptr)` / `offInterrupt()` / `pollInterrupt()` / `readCapture()`. Delivery uses the `InputPin` at `connection.intPin()` — no platform `#ifdef` in the driver.

### Node.js

Pins expose `async read()`, `async write(value)`, `async setDirection(direction)`, `direction`, `stop()`, `asGpio()` (synchronous opengpio-shaped facade; input facades are backed by a 5 ms background poll and eventually consistent). Full adds `watch(handler, trigger='change')`, `unwatch()`, `setActiveLow(invert)`; interrupts via the INT line or a 5 ms poll.

### Rust

Output pins implement `embedded_hal::digital::OutputPin`, input pins `embedded_hal::digital::InputPin`; Full adds `StatefulOutputPin`. The bus lives in a `core::cell::RefCell<…>` shared by the pin objects (document the single-context restriction in the module doc). Two driver families generic over `embedded_hal::i2c::I2c` (`Mcp23008*`) and `embedded_hal::spi::SpiDevice` (`Mcp23S08*`); re-export `pub use mcp23008::{Mcp23008Minimal, Mcp23008Full, Mcp23S08Minimal, Mcp23S08Full, ExPin};`.

### JVM

`Pin` is a `public static class` nested in `Mcp23008Minimal` (`setInput()`, `setOutput()`, `setHigh()`, `setLow()`, `read()` → boolean, `toggle()`; Full: `setPullUp(boolean)`, `watch(handler[, EdgeTrigger])`, `unwatch()`). Driver-level Full methods: `configurePullup`, `configurePolarity`, `setDefaultValue`, `enablePinInterrupt`, `configureIntPin`, `onInterrupt(IntConsumer[, InputPin])`, `offInterrupt()`, `pollInterrupt()`, `readCapture()`. Kotlin takes `(Int) -> Unit` / `(Pin) -> Unit` lambdas; Groovy takes `Closure`.

### Go

Pins are small structs with `Mode`, `Write`, `Read`, `Toggle` and Full `SetPullUp`, `Watch`, `Unwatch`, satisfying the project's `connection.InputPin` / `OutputPin` interfaces.

## Data Conversion

```
pin n  →  bit n of the single 8-bit port

Read pin n:     value = (read_port() >> n) & 1                       # GPIO register
Write pin n:    shadow_olat |= (1 << n)  or  &= ~(1 << n)
                write OLAT (0x0A) ← shadow_olat
Direction:      shadow_iodir &= ~(1 << n)  (output)  /  |= (1 << n)  (input)
                write IODIR (0x00) ← shadow_iodir
```

Setting a pin to output writes its OLAT bit **before** clearing its IODIR bit so the pin never glitches to a stale level.

## Timing Constraints

- No startup delay after power-on reset or RESET release.
- RESET pulse width ≥ 1 µs; outputs go high-impedance ≤ 1 µs after RESET low.
- VDD rise rate ≥ 0.05 V/ms for a clean power-on reset.
- I²C: fSCL ≤ 100 kHz / 400 kHz / 1.7 MHz per supply range (datasheet Table 2-2).
- SPI (datasheet Table 2-3): CS setup 50 ns, CS hold 50–100 ns, CS disable 50–100 ns, data setup/hold 10–20 ns, clock high/low ≥ 45–90 ns, output valid ≤ 45–90 ns from clock low (90 ns when the address pointer rolls over `0x0A` → `0x00`).
- **Conformance:** none of these has a bus-decodable start/end annotation pair (they are setup/hold and clock-rate properties, not event-to-event delays), so `specs/io_expander/mcp23008_timing.conf` defines no checks.

## Implementation Notes

- **Shared base, two register layers:** implement an abstract base (`_Mcp23x08Base`) holding the shadows, pin proxies and all GPIO/interrupt logic, with two small hooks `reg_read(reg, n)` / `reg_write(reg, data)`. `Mcp23008*` implements them with a `RegisterConnection` (I²C, 1-byte address — no `_read_reg`/`_write_reg`, no `bus_type` branch; see `specs/feature_register_access_design.md`). `Mcp23S08*` implements them with a plain SPI `Connection`: write = `connection.write([opcode_w, reg, data…])`, read = `connection.write_read([opcode_r, reg], n)` where `opcode = 0x40 | (addr << 1) | rw`. `Mcp23S08*` is not a `RegisterConnection` chip because of the separate opcode byte (§11.4).
- **HAEN / SPI addressing:** `HAEN` resets to 0, so before it is set every MCP23S08 decodes opcode address `00` regardless of its pins (the datasheet describes `HAEN` only as "enables/disables the address pins"). If several devices share one CS, the first IOCON write must go out with address `00` and reaches all of them at once — set `HAEN` on every device that way before any addressed access; a single device with A1:A0 = `00` is unaffected. Exact HAEN = 0 decoding is inferred from the MCP23S17 sibling and should be verified on hardware.
- **Keep SEQOP = 0 (auto-increment) in the drivers:** multi-register accesses rely on it. Roll-over from `0x0A` to `0x00` is expected behavior, not an error.
- **IOCON bit 5 is SEQOP:** Table 1-3 of the datasheet labels bit 5 "SREAD" in the summary row, but the register description (1.6.6) and text call it SEQOP; the spec follows the latter.
- **Use OLAT for output writes:** GPIO writes are equivalent but reading GPIO returns pin levels. A pin driven by an output reads back its actual level (a shorted or overloaded pin can differ from OLAT).
- **Interrupt clearing:** only a read of GPIO or INTCAP clears the interrupt; in DEFVAL mode INT stays asserted while the pin still differs from DEFVAL even after the read. INTCAP is not updated by later events while the interrupt is uncleared (INTF still is).
- **Interrupts only on inputs:** output pins never raise INT; the driver must not allow `watch` on an output pin.
- **Pull-ups apply only to inputs:** the driver should ignore (or reject) `GPPU` bits for output pins in Full.
- **Input range:** GPIO inputs must stay within VSS…VDD.
- **MCP23017 relation:** same register semantics at different addresses (0x00–0x0A vs the MCP23017's interleaved A/B map) and no BANK/MIRROR; a `Mcp23008*` driver must never use the MCP23017 address table, and the two chips share I²C addresses `0x20`–`0x27` without any way to tell them apart.
- **Datasheet:** DS21919E (© 2007 Microchip), from `http://ww1.microchip.com/downloads/en/DeviceDoc/21919e.pdf`.

## Sigrok Decoder

Two decoders sharing one register table: `mcp23008` (input `['i2c']`, matches addresses `0x20`–`0x27`) and `mcp23s08` (input `['spi']`, matches opcodes `0x40`–`0x47`: address bits `A1:A0` and the R/W bit); `sigrok/mcp23s08/` imports the table from `sigrok/mcp23008/`. Annotates every register read/write with its name and value decoded into symbolic fields (IODIR → `IN=GP0,GP3…`, GPPU → `PU=GP4,…`, IOCON → `SEQOP HAEN ODR INTPOL`, GPIO/OLAT/INTF/INTCAP as 8-pin masks), annotates sequential transactions byte by byte using the roll-over `0x0A → 0x00` address progression, and emits warnings for writes to the read-only registers INTF (`0x07`) and INTCAP (`0x08`) and for IOCON writes with bits 7:6 or 0 set. A GPIO read inside the same transaction as the preceding address is shown as the port value. Since the datasheet gives no digital start/end completion events, no timing annotation pair is emitted.
