# Chip Spec: PCA6416A (IO Expander)

**Manufacturer:** NXP Semiconductors  
**Datasheet:** `datasheets/io_expander/pca6416a.pdf` (Rev. 2, 10 January 2013 — the PDF attached to issue #579)  
**Category:** `io_expander`  
**Transports:** I²C, SMBus

## Overview

The PCA6416A is a 16-bit general-purpose I/O expander with an I²C / SMBus interface in a 24-pin package. Its pins are split into two 8-bit ports (P0_0–P0_7 = port 0, P1_0–P1_7 = port 1), each with an Input Port, Output Port, Polarity Inversion and Configuration register (four register pairs). At power-on all I/Os are inputs. Outputs are latched push-pull drivers with 25 mA sink capability for LEDs, I/Os are 5 V tolerant, and there is an open-drain interrupt output (`INT`), an active-low `RESET` input and one address pin (`ADDR`) for two devices on one bus. It has **two supply rails**: VDD(I2C-bus) powers the bus interface (and is the voltage-translation reference for SCL/SDA) while VDD(P) powers the core and Port P, so a 1.8 V microcontroller can talk to 1.8 V–5 V peripherals (1.65–5.5 V on both rails). It is the 16-bit sibling of the PCA6408A (`specs/io_expander/pca6408a.md`): the same dual-supply chip family, same addresses (`0x20`/`0x21`), same electrical characteristics and same interrupt semantics, but with the PCA6416A's register-pair layout (`0x00`–`0x07`, see `specs/io_expander/pca6416a.md`). There are **no internal pull-ups** (the PCAL6416A variant adds pull-ups and drive-strength registers; it is a different chip, not covered).

## Transport Configuration

### I²C / SMBus
- **Address:** `0x20` (ADDR = VSS) — `0x21` (ADDR = VDD(P)); address byte `0100 00 ADDR R/W`. ADDR must be tied directly to VDD(P) or ground

| ADDR | Address |
|------|---------|
| L | `0x20` |
| H | `0x21` |

- **Max clock:** 400 kHz (fast mode); 100 kHz standard mode also supported. Drivers use ≤ 400 kHz
- **SMBus:** the protocol is plain "Write Byte / Read Byte" with the command byte as register pointer, so the chip works on an SMBus controller (the datasheet title states SMBus compatibility; PEC is not supported and must not be enabled). The driver accepts either an `I2CConnection` or an `SMBusConnection` (without PEC) — it only needs byte-register access
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`; it shares `0x20`/`0x21` with the PCA6408A, MCP23008/MCP23017 and PCF8574, none of which can be told apart)
- **Probe safety:** `register_pointer` — a 1-byte write only loads the command byte (register pointer); no register changes without a following data byte
- **Register addressing:** 1-byte command byte (`RegisterConnection`, `reg_bytes = 1`). **Register-pair toggling, not auto-increment:** the eight registers form four pairs (Input 0/1, Output 0/1, Polarity 0/1, Config 0/1). After a byte is written or read, the next byte goes to the *other* register of the pair (a write starting at Output Port 1 sends the 2nd byte to Output Port 0), so a two-byte transfer starting at the port-0 register covers both ports and never crosses into the next pair. There is no limit on the number of bytes; the pair keeps alternating

## Register Map

All registers are 8 bits, selected by the command byte (bits 7:3 are 0; bits 2:0 select the register).

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | INPUT0 | R | `xx` | Actual levels of P0_0–P0_7 (regardless of direction); writes ignored; read releases the port-0 interrupt |
| `0x01` | INPUT1 | R | `xx` | Actual levels of P1_0–P1_7; read releases the port-1 interrupt |
| `0x02` | OUTPUT0 | R/W | `0xFF` | Output latch of port 0; reads return the latch, not the pin |
| `0x03` | OUTPUT1 | R/W | `0xFF` | Output latch of port 1 |
| `0x04` | POLARITY0 | R/W | `0x00` | Polarity inversion of port-0 pins configured as inputs: 1 = INPUT0 bit reads inverted |
| `0x05` | POLARITY1 | R/W | `0x00` | Polarity inversion of port 1 |
| `0x06` | CONFIG0 | R/W | `0xFF` | Direction of port 0: 1 = input (high-Z), 0 = output |
| `0x07` | CONFIG1 | R/W | `0xFF` | Direction of port 1 |

Bit n of a port register corresponds to pin Pxn. Only registers `0x00`–`0x07` exist; the driver never writes other pointer values.

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `INT`, open-drain, active low — requires an external pull-up |
| Level | 1 (single fixed condition) |
| Condition | any pin configured as an input changed state (rising or falling) relative to the Input Port register value read last |
| Clear mechanism | read the Input Port register of the port that caused it (cleared at the ACK / NACK clock of the read), or the pin returns to its original level; ports are cleared independently — a read of INPUT1 does not clear a port-0 interrupt |

`INT` is valid within tv(INT) ≤ 1 µs of a port change and released within trst(INT) ≤ 1 µs after SCL of the read. An interrupt that occurs during the ACK / NACK clock pulse of an Input Port read can be lost (or be very short). A pin configured as an output cannot cause an interrupt, and **changing a pin from output to input can raise a false interrupt** if the pin level differs from the last Input Port value. Interrupts raised during the ACK/NACK clock of an Input Port read can be lost.

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Subscribe on INT (falling edge); `callback(changed_mask)` receives the 16-bit mask of input pins whose level changed since the previous Input Port read (bit n = pin n; bits 0–7 port 0, 8–15 port 1). Uses `connection.int_pin` (or `int_pin`), otherwise a 5 ms poll of the driver |
| `off_interrupt` | `off_interrupt()` | Unsubscribe and stop delivery |
| `poll_interrupt` | `poll_interrupt() -> int` | Read both Input Port registers (one two-byte read, which releases both ports' interrupts), XOR with the driver's last input value (masked to input pins), store the new value, return the 16-bit changed-pin mask |

There is no interrupt-status register: the driver derives the changed mask itself (as the PCA6408A and PCF8574 drivers do; the PCA6416A has no interrupt errata, unlike the PCA9539) and caches the last Input Port values (initialised in `init`).

### Pin interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `watch` | `watch(handler, trigger=CHANGE)` | Subscribe to this pin's changes; `trigger` filters rising / falling / change in software; all pins share the single INT line |
| `unwatch` | `unwatch()` | Unsubscribe |

## Initialization Sequence

1. Write the reset state to guarantee a known start: OUTPUT0 / OUTPUT1 ← `0xFF`, POLARITY0 / POLARITY1 ← `0x00`, CONFIG0 / CONFIG1 ← `0xFF` (all inputs; the user presets the output latch before turning pins into outputs). Each is a two-byte write starting at the port-0 register (pair toggling covers port 1).
2. Read INPUT0 / INPUT1 (one two-byte read) to initialise the cached input values and release any pending interrupt.

No startup delay is required after power-on reset or RESET release (the datasheet gives trst = 600 ns as the time the device needs after a reset event). VDD(P) must go through a defined power cycle for a power-on reset (see Timing Constraints).

## Implementation Stages

Each chip is implemented in two stages. The Full class extends Minimal.

The defining characteristic of an IO expander driver is that it exposes individual **Pin objects** that implement each platform's native GPIO interface — see the GPIO Interface section below. Users obtain a pin from the driver and use it exactly like a hardware GPIO pin.

### Minimal

Goal: expose all 16 pins as GPIO objects with direction control and value read / write. No interrupt or polarity configuration required.

**Driver API**

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection (`addr=0x20`) | — | Runs the Initialization Sequence; shadows OUTPUT = `[0xFF, 0xFF]`, CONFIG = `[0xFF, 0xFF]` |
| `pin` | `n: int` (0–15) | Pin | Pin proxy for pin `n` (0–7 = P0_0–P0_7, 8–15 = P1_0–P1_7) |
| `read_port` | `port: int` (0 or 1) | int | Read INPUTx (actual pin levels) as an 8-bit bitmask |
| `write_port` | `port: int`, `mask: int` | — | Write all 8 output bits of the port via OUTPUTx; updates the shadow; bits of input pins are stored but only take effect once the pin becomes an output |

**Sensible defaults:** all pins inputs (CONFIG `0xFF`), OUTPUT `0xFF`, no polarity inversion, interrupts not subscribed. Shadows of OUTPUT and CONFIG (both ports) are kept so a single-pin change is one register write.

Goal: expose complete chip functionality. Extends Minimal.

**Driver API additions**

## GPIO Interface

The per-platform Pin contracts are identical to the PCA6408A's (16 pins instead of 8) and the MCP23008's (`specs/io_expander/pca6408a.md`, `specs/io_expander/mcp23008.md`, "GPIO Interface"; the 16-pin numbering follows `specs/io_expander/pca6416a.md`) with these differences: constants and the nested pin class live on `Pca6416aMinimal`; the pin numbers run 0–15 (pin `n` ↔ port `n / 8`, bit `n % 8`); there are **no pull-up resistors**, so every pull-up entry point rejects the request (`AttributeError` / `UnsupportedOperationException` / compile-time absent in Rust) instead of writing a register; the nested pin classes are named per platform convention (`IOExpanderPin` in C++, `ExPin` in Rust, `Pin` in JVM). Interrupt callbacks take `callback(changed_mask)` with a 16-bit mask. The Rust driver is generic over `embedded_hal::i2c::I2c`; re-export `pub use pca6416a::{Pca6416aMinimal, Pca6416aFull, ExPin};`.

## Data Conversion

```
pin n  →  port = n // 8, bit = n % 8        (P0_0..P07 = pins 0..7, P1_0..P17 = pins 8..15)

Read pin n:     value = (read_port(n // 8) >> (n % 8)) & 1            # INPUT0 / INPUT1
Write pin n:    shadow_output[port] |= (1 << bit)  or  &= ~(1 << bit)
                write OUTPUT0 + port (0x02 + port) <- shadow_output[port]
Direction:      shadow_config[port] &= ~(1 << bit)  (output)  /  |= (1 << bit)  (input)
                write CONFIG0 + port (0x06 + port) <- shadow_config[port]
16-bit view:    value16 = INPUT0 | (INPUT1 << 8)       # one two-byte read starting at 0x00
Changed mask:   changed = (new_input16 ^ cached_input16) & shadow_config16   # input pins only
```

Making a pin an output writes its OUTPUT bit **before** clearing its CONFIG bit so the pin never glitches. Because OUTPUT resets to `0xFF`, a pin turned into an output with no prior write drives high.

### Demo flow

An inject node writes a rotating one-hot pattern to P0_0–P0_7 (LEDs, outputs), a second inject reads port 1 (P1_0–P1_7, buttons) once a second into a debug node (hex), and with the INT line wired the node emits `{ changed: mask, value }` whenever a button on port 1 changes. Shows output control on one port and interrupt-driven input on the other.

## Examples

### Demo

Wire eight LEDs (active-low: anode to VDD(P) through 220 Ω, cathode to P0_0–P0_7 — each output sinks up to 25 mA, keep the total within the datasheet limits) and eight push buttons (to ground, **with external pull-ups** because the chip has none) on P1_0–P1_7. The demo uses the Full driver: configure P0_0–P0_7 as outputs (`set_direction(0xFF00)`) and P1_0–P1_7 as inputs, `configure_polarity(0xFF00)` so a pressed button reads as 1, subscribe with `on_interrupt` (INT pin or 5 ms polling), and run a one-LED scanner with `write_all`. When a button interrupt fires the callback prints the changed mask and the `read_all()` value, and the LED matching the pressed button (P1_0 → P0_0, …) lights for one second. The loop prints the scanner position and the 16-bit port state each iteration.

## Timing Constraints

- No startup delay; after a reset event the device needs trst ≤ 600 ns.
- RESET pulse width tw(rst) ≥ 30 ns; reset recovery before START trec(rst) ≥ 200 ns.
- INT valid after a port change tv(INT) ≤ 1 µs; INT reset after the read ACK/NACK trst(INT) ≤ 1 µs; port output valid after SCL tv(Q) ≤ 400 ns; port input setup tsu(D) ≥ 0, hold th(D) ≥ 300 ns.
- I²C: fSCL ≤ 400 kHz, tLOW ≥ 1.3 µs, tHIGH ≥ 0.6 µs, tBUF ≥ 1.3 µs, repeated-START setup / hold ≥ 0.6 µs, STOP setup ≥ 0.6 µs (fast mode, datasheet Tables 19–22).
- Power-on reset (datasheet §9.2, Table 15): for a power-reset cycle VDD(P) must drop to VSS (or below VPOR(min) − 50 mV) and stay there for the reset delay td(rst) ≥ 1 µs before re-ramping (the µ glyph is lost in the PDF text extraction; the ramp rates (dV/dt) are 0.1–2000 ms); the reset trip voltage is ≥ 0.7 V falling and ≤ 1.4 V rising. A brown-out that does not cross VPOR does not reset the chip.
- **Conformance:** none of these has a bus-decodable start / end annotation pair (they are pin-level setup / hold and reset-pin events), so `specs/io_expander/pca6416a_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection, one byte per register:** accept `RegisterConnection` (1-byte address), call `connection.read(reg, n)` / `connection.write(reg, data)`; no `_read_reg`/`_write_reg`, no `bus_type` branch. SMBus (without PEC) works through the same API. See `specs/feature_register_access_design.md`.
- **Register pairs toggle:** `connection.read(0x00, 2)` returns INPUT0 then INPUT1; `connection.write(0x02, bytes([out0, out1]))` writes OUTPUT0 then OUTPUT1 (likewise `0x04` / `0x06`). Starting at the port-1 register swaps the order (the second byte lands in port 0). Longer transfers keep alternating within the pair — never rely on them to reach the next pair. (The PCA6408A, by contrast, has four single registers and no multi-byte access.)
- **INPUT reflects pins, OUTPUT reflects the latch:** INPUT shows the real level even for output pins (an overloaded output can read low while OUTPUT = 1). Read-modify-write on outputs must use the shadow (or read OUTPUT), never INPUT.
- **Polarity applies to inputs only** and affects only the INPUT read-back, not the output latch.
- **Interrupt semantics:** edge-based on any input; cleared only by reading the INPUT register of that port (or returning to the original level). Interrupts raised during the ACK / NACK of an INPUT read can be lost, and an output → input change can raise a false interrupt — after `set_direction` or a pin direction change to input, the driver reads the input registers once (refreshing the cache) so the false event is filtered out of the changed mask. Unlike the PCA9539 there is no interrupt errata in this datasheet, so no workaround write is needed.
- **No pull-ups:** inputs float unless externally pulled; `Pull.UP` requests must raise rather than silently succeed. The chip's LED-drive guidance: keep the pin at or above VDD(P) when an LED is off to avoid extra supply current.
- **Two supply rails:** VDD(I2C-bus) must match the bus; VDD(P) sets the port logic level. Level translation is hardware — nothing to configure.
- **Shared abstraction:** the 16-bit register-pair layout is identical to the PCA9539 (`0x00`–`0x07`) and PCA9555; only the addresses, supply scheme and errata differ. Each language implements the driver with its register map and base address as constants/parameters so a later PCA9539 / PCA9555 driver can reuse the same structure. Pin proxy and interrupt-mask logic follow the PCA6408A drivers, extended from one 8-bit port to two (`pin n` ↔ port `n / 8`, bit `n % 8`).
- **Relation to siblings:** same I²C addresses as the PCA6408A, MCP23008/MCP23017 and PCF8574 (`0x20`/`0x21`), different register layout from those. The TI TCA6416A is a functional equivalent (not covered); the PCAL6416A adds pull-up, drive-strength, input-latch and interrupt-mask registers above `0x07` (not covered).
- **Datasheet:** NXP Rev. 2 (10 January 2013), attached to issue #579.

## Sigrok Decoder

Decoder id `pca6416a`, input `['i2c']`. Matches I²C addresses `0x20` and `0x21`. Annotates each write as register name + value (INPUT0/1, OUTPUT0/1, POLARITY0/1, CONFIG0/1) decoded into pin masks (CONFIG → `IN=P0_0,P03…` / `OUT=…`, OUTPUT and INPUT as 8-pin level strings, POLARITY → `INV=P14…`); tracks the register-pair toggling so every byte of a multi-byte transfer is named by its own register (e.g. a two-byte read at `0x00` = INPUT0 then INPUT1, combined into a 16-bit value in the long annotation); each read is decoded from the pointer set by the preceding write (repeated-start read) or by the last written pointer (stand-alone read, per Figure 8-11). A change between consecutive INPUT reads is shown as a changed-pin mask. Warnings: write to INPUT0/1 (`0x00`/`0x01`), pointer values above `0x07`. No timing annotation pair is emitted, since the datasheet defines no bus-decodable completion events.
