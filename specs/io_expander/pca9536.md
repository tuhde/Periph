# Chip Spec: PCA9536 (IO Expander)

**Manufacturer:** Texas Instruments  
**Datasheet:** `datasheets/io_expander/pca9536.pdf` (SCPS125H, Rev. H, March 2022)  
**Category:** `io_expander`  
**Transports:** I²C, SMBus

## Overview

The PCA9536 is a 4-bit general-purpose I/O expander in an 8-pin package (SOIC / VSSOP / NanoFree) with an I²C / SMBus interface, a single 4-pin port (P0–P3), per-pin direction (Configuration register), input polarity inversion, latched outputs with LED-drive capability (25 mA sink), a 1 µA standby current and a 2.3–5.5 V supply (5 V-tolerant I/O). It is the smallest member of the TI/NXP "PCA95xx" family: the same four-register interface as the PCA6408A (`specs/io_expander/pca6408a.md`) but with **only four pins**, a **single fixed address (`0x41`)**, **no interrupt, reset or address pins**, and a **weak 100 kΩ pull-up always present on each I/O pin** (it is part of the I/O structure and cannot be switched). With no signal applied, an input reads 1.

## Transport Configuration

### I²C / SMBus
- **Address:** `0x41` only (7-bit address `1000001`; address byte `1000 001 R/W`; fixed, no address pins — so only one PCA9536 per bus)
- **Max clock:** 400 kHz (fast mode); 100 kHz standard mode also supported
- **SMBus:** the protocol is plain "Write Byte / Read Byte" with the command byte as register pointer, so the chip works on an SMBus (the part is specified for I²C and SMBus; PEC is not supported and must not be enabled for this chip). The driver accepts either an `I2CConnection` or an `SMBusConnection` (without PEC) — it only needs byte-register access
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`; address `0x41` is not shared with any other chip in the registry)
- **Probe safety:** `register_pointer` — a 1-byte write only loads the control register (command byte); no register changes without a following data byte. Only bits 1:0 of the command byte are used; bits 7:2 are 0
- **Register addressing:** 1-byte command byte (`RegisterConnection`, `reg_bytes = 1`). **No auto-increment:** the control register is not advanced between data bytes — extra data bytes in one write transaction rewrite the same register, and once a command byte has been sent the addressed register is read repeatedly until a new command byte is sent (a read transaction of n bytes returns the same register n times). The driver always accesses one byte per register

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| P0–P3 | — | Port pins, push-pull outputs, 5 V tolerant; all inputs with a weak (≈ 100 kΩ) pull-up to VCC at power-on |
| SCL, SDA | — | I²C / SMBus; external pull-ups to VCC |
| VCC, GND | — | 2.3–5.5 V supply |

There is **no INT, RESET or address pin**: the chip can only be reset by a power cycle (see Timing Constraints) and signals nothing to the host.

## Register Map

All registers are 8 bits, selected by the pointer (command byte). Only bits 1:0 of the command byte select a register (B1:B0); bits 7:2 are 0.

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | INPUT | R | `1111 xxxx` | Actual pin levels in bits 3:0 (regardless of direction; bits 7:4 read 1); writes ignored |
| `0x01` | OUTPUT | R/W | `0xFF` | Output latch: drives pins configured as outputs; reads return the latch, not the pin (bits 7:4 unused) |
| `0x02` | POLARITY | R/W | `0x00` | Polarity inversion of pins configured as inputs: 1 = INPUT bit reads inverted (bits 7:4 unused) |
| `0x03` | CONFIG | R/W | `0xFF` | Direction: 1 = input (high-impedance driver, weak pull-up present), 0 = output (bits 7:4 unused) |

Bit n (0–3) of every register corresponds to pin Pn; bits 7:4 are not used (write 1 to OUTPUT/CONFIG and 0 to POLARITY for them — the reset values — and mask them off on reads). Only registers `0x00`–`0x03` exist; the driver never writes other pointer values.

## Interrupt

The PCA9536 has no interrupt output (and no interrupt registers). Drivers expose **no** `on_interrupt`/`off_interrupt`; the Full class offers `poll_changes` (see Full API) for software edge detection by polling INPUT, and `Pin.watch` is implemented on top of it.

## Initialization Sequence

1. Write the reset state to guarantee a known start: OUTPUT ← `0xFF`, POLARITY ← `0x00`, CONFIG ← `0xFF` (all inputs; the user presets OUTPUT before turning pins into outputs).
2. Read INPUT to initialise the cached input value.

No startup delay is specified. The chip resets only through its internal power-on reset: VCC must ramp within the datasheet's power-on-reset cycle limits (Power-On Reset Errata, Figure 10-1) or the reset can be missed and the device can lock up — the only recovery is a power cycle.

## Implementation Stages

### Minimal

Goal: expose all 4 pins as GPIO objects with direction control and value read/write. No polarity configuration required.

**Driver API**

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection (`addr=0x41`) | — | Runs the Initialization Sequence; shadow OUTPUT = `0xFF`, shadow CONFIG = `0xFF` |
| `pin` | `n: int` (0–3) | Pin | Pin proxy for Pn |
| `read_port` | `port: int = 0` | int | Read INPUT (actual pin levels) as a 4-bit bitmask (bits 7:4 masked off); `port` ignored |
| `write_port` | `port: int = 0`, `mask: int` | — | Write the 4 output bits via OUTPUT (bits 7:4 written as 1); updates the shadow; bits of input pins are stored but only take effect once the pin becomes an output |

**Sensible defaults:** all pins inputs (CONFIG `0xFF`), OUTPUT `0xFF`, no polarity inversion. Shadows of OUTPUT and CONFIG are kept so a single-pin change is one register write.

**Pin API — Minimal**

### Full

Goal: expose complete chip functionality. Extends Minimal.

**Driver API additions**

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `configure_polarity` | `mask: int` | — | POLARITY ← `mask` (1 = invert that input's INPUT bit); `poll_changes` compares the already-inverted values, so a polarity change itself does not report a change (the cache is refreshed) |
| `get_direction` | — | int | Shadow CONFIG |
| `set_direction` | `mask: int` | — | CONFIG ← `mask` (1 = input) in one write; for pins turning into outputs the OUTPUT bits are written first so the pin never glitches |
| `read_register` | `reg: int` (0–3) | int | Raw register read |
| `write_register` | `reg: int`, `value: int` | — | Raw register write (reg 1–3); updates shadows; writing reg 0 raises |
| `reset` | — | — | Writes the reset values (OUTPUT `0xFF`, POLARITY `0x00`, CONFIG `0xFF`) and refreshes the input cache; the RESET pin is external and not driven by the driver |
| `poll_changes` | — | int | Read INPUT (masked to the input pins), XOR with the cached previous value, store the new value and return the changed-pin mask (software edge detection; no hardware interrupt exists) |
| `watch_changes` | `callback`, `interval_s: float = 0.005` | — | Start a polling task/thread that calls `poll_changes()` every `interval_s` and invokes `callback(changed_mask)` when non-zero; `unwatch_changes()` stops it |

**Pin API additions — Full**

| Operation | MicroPython | CircuitPython | C++ | Node.js | JVM |
|-----------|-------------|---------------|-----|---------|-----|
| Set pull-up | *(unsupported — raises; the weak pull-up is always on)* | `pin.pull` (`Pull.UP`/`DOWN` raise `AttributeError`; `None` only) | *(`INPUT_PULLUP` rejected)* | *(unsupported)* | `pin.setPullUp(true)` raises |
| Subscribe to edge | `pin.watch(handler, trigger)` *(polling-based)* | `pin.watch(handler, trigger)` | `pin.watch(handler, trigger)` | `pin.watch(handler, trigger='change')` | `pin.watch(handler[, trigger])` |
| Unsubscribe | `pin.unwatch()` | `pin.unwatch()` | `pin.unwatch()` | `pin.unwatch()` | `pin.unwatch()` |

**Additional configuration options:** polarity inversion (POLARITY), whole-port direction, software change detection (polling).

## GPIO Interface

The per-platform Pin contracts are identical to the PCA6408A's (`specs/io_expander/pca6408a.md`, "GPIO Interface") with these differences: four pins instead of eight (`pin(n)` with n in 0–3), the constants and nested pin class live on `Pca9536Minimal`, there is **no interrupt line**, so `watch` is implemented with the polling task of `watch_changes` (no `int_pin` parameter), and every pull-up entry point rejects the request because the weak pull-up is fixed in hardware. The Rust driver is generic over `embedded_hal::i2c::I2c`; re-export `pub use pca9536::{Pca9536Minimal, Pca9536Full, ExPin};`.

## Data Conversion

```
pin n  →  bit n (0..3) of the single 4-bit port (bits 7:4 unused)

Read pin n:     value = (read_port() >> n) & 1                     # INPUT register, n = 0..3
Write pin n:    shadow_output |= (1 << n)  or  &= ~(1 << n)
                write OUTPUT (0x01) ← shadow_output
Direction:      shadow_config &= ~(1 << n)  (output)  /  |= (1 << n)  (input)
                write CONFIG (0x03) ← shadow_config
Changed mask:   changed = (new_input ^ cached_input) & shadow_config & 0x0F   # input pins only
```

Making a pin an output writes its OUTPUT bit **before** clearing its CONFIG bit so the pin never glitches. Because OUTPUT resets to `0xFF`, a pin turned into an output with no prior write drives high.

### Demo flow

An inject node writes a rotating one-hot pattern to P0–P1 (LEDs, outputs), a second inject reads the port once a second into a debug node (hex), and with polling enabled the node emits `{ port: 0, changed: mask, value }` whenever a button on P2–P3 changes.

## Examples

### Demo

Wire two LEDs (anode to VCC through 220 Ω, cathode to P0–P1; the outputs sink up to 25 mA) and two push buttons (to ground) on P2–P3 — the chip's built-in weak pull-up holds an open button input high, so no external resistor is needed. The demo uses the Full driver: configure P0–P1 as outputs and P2–P3 as inputs, start `watch_changes` (5 ms polling), and blink the LEDs alternately; when a button changes the callback prints the changed mask and the INPUT value, and the LED matching the pressed button (P2→P0, P3→P1) is held lit for one second. Optionally enable `configure_polarity(0x0C)` so a pressed button reads as 1.

## Timing Constraints

- No startup, reset-pin or INT timing applies (the chip has none). Port output data valid tpv ≤ 200 ns after the SCL edge of the ACK of the data byte (datasheet §6.7).
- I²C: standard mode ≤ 100 kHz, fast mode ≤ 400 kHz (datasheet "I²C Interface Timing Requirements").
- Power-on reset: VCC rising through VPORR (1.2–1.6 V) releases reset; for a power-reset cycle VCC must fall below VPORF (0.75–1 V) and ramp up again within the allowed ramp conditions — otherwise the reset can be missed and the device can lock up (datasheet §10 errata).
- **Conformance:** none of these has a bus-decodable start/end annotation pair, so `specs/io_expander/pca9536_timing.conf` defines no checks.

## Implementation Notes

- **RegisterConnection, one byte per register:** accept `RegisterConnection` (1-byte address), call `connection.read(reg, 1)` / `connection.write(reg, bytes([v]))`; no `_read_reg`/`_write_reg`, no `bus_type` branch. SMBus (without PEC) works through the same API. See `specs/feature_register_access_design.md`.
- **No auto-increment, persistent pointer:** two registers need two transactions; a multi-byte read repeats the same register. Because the pointer persists, repeated INPUT polls may skip the command byte, but the driver always sends it (robust against other bus masters).
- **INPUT reflects pins, OUTPUT reflects the latch:** INPUT shows the real level even for output pins; read-modify-write on outputs must use the shadow (or read OUTPUT), never INPUT. Bits 7:4 are unused: INPUT reads them as 1 — always mask with `0x0F`.
- **Always-on weak pull-up:** an undriven input reads 1; `Pull.UP` requests raise, `Pull.DOWN` is impossible. For a defined low level use an external pull-down or the polarity inversion plus a strong external drive. The pull-up current (≤ 100 µA at 0 V input) adds to the supply current while a pin is held low.
- **No interrupt:** change detection is polling only; the first `poll_changes` after `init` compares against the value cached at `init`. Polling at 5 ms costs one 2-byte transaction per poll.
- **Polarity applies to inputs only** and affects only the INPUT read-back, not the output latch.
- **Output total current:** the sum of all sourced currents must stay ≤ 85 mA; the sum of sunk currents ≤ 50 mA continuous per pin / the datasheet's package limits.
- **Power-on-reset errata:** a VCC ramp outside the specified limits can leave the chip locked up, with no reset pin to recover — if the chip stops responding the only fix is cycling VCC. `reset()` rewrites the registers but cannot clear a lock-up.
- **Relation to the PCA6408A:** identical register layout and semantics for bits 3:0, but 4 pins, address `0x41`, no ADDR/RESET/INT pins, no second supply rail and an always-on weak pull-up. A shared base class for the PCA95xx-style expanders (parameterised by pin count and address) is allowed.
- **Datasheet:** TI SCPS125H (Rev. H, March 2022), `https://www.ti.com/lit/ds/symlink/pca9536.pdf`. The datasheet's Figure 8-11 still shows an INT line from an older template; the 8-pin device has no such pin.

## Sigrok Decoder

Decoder id `pca9536`, input `['i2c']`. Matches I²C address `0x41`. Annotates each write as register name + value (INPUT / OUTPUT / POLARITY / CONFIG) decoded into 4-pin masks (CONFIG → `IN=P0,P3` / `OUT=…`, OUTPUT and INPUT as 4-pin level strings, POLARITY → `INV=P2…`), each read likewise from the register set by the preceding write (repeated-start read) or the last written command byte (stand-alone read, per Figure 8-11), and flags warnings for writes to INPUT (`0x00`), command bytes with bits 7:2 set, writes to the unused bits 7:4 with values other than the reset values, and multi-byte writes or reads that repeat one register (no auto-increment). A change between consecutive INPUT reads is shown as a changed-pin mask. No timing annotation pair is emitted.
