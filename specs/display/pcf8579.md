# Chip Spec: PCF8579

**Manufacturer:** NXP Semiconductors  
**Datasheet:** `datasheets/display/pcf8579.pdf` (Rev. 05, 11 May 2009 — the NXP URL in the issue now returns 404; the committed copy is the same NXP document from a mirror, `http://images.100y.com.tw/pdf_file/35-PCF8579H.pdf`)  
**Category:** `display`  
**Transports:** I²C

## Overview

The PCF8579 is a low-power CMOS LCD **column driver** for dot-matrix graphic displays, designed as the companion of the PCF8578 row/column driver (`specs/display/pcf8578.md`). It has 40 column outputs C0–C39 and a 32 × 40-bit display RAM (four banks of 40 bytes), so one device drives 40 columns of a display with up to 32 multiplexed rows (1:8, 1:16, 1:24 or 1:32). Up to 16 PCF8579s are distinguished by a 4-bit hardware subaddress (pins A3:A0), and up to 32 (two clusters selected by SA0) on one bus; with a PCF8578 the pair forms a chip set for displays of up to 40 960 dots. It is controlled over I²C by the same five-command stream as the PCF8578 (same opcodes, same RAM-access modes, auto-incrementing data across device boundaries) and has a bank-switching start-bank feature for scrolling.

**The PCF8579 cannot run alone:** it has no oscillator and no row outputs. The row waveforms, the clock (CLK, ≤ 10 kHz) and the frame synchronisation (SYNC) come from a PCF8578 (row driver or mixed mode) or an equivalent external source. This spec covers the PCF8579 as an I²C-controlled RAM + column driver: its driver writes the PCF8579's display RAM and the shared display commands. Wiring the PCF8578 (and its mode) is the system's responsibility; a combined multi-chip display class is out of scope. External bias generation (V3/V4), VLCD and the panel are board-level.

## Transport Configuration

### I²C
- **Address:** `0x3C` (SA0 = VSS) — `0x3D` (SA0 = VDD); 7-bit address `0111 10 0 SA0` — **the same two addresses as the PCF8578**; all devices with the addressed value acknowledge commands in parallel
- **Subaddress:** pins A3:A0 (0–15) select which PCF8579 stores/returns RAM data; written by the driver as `device-select` (it is *not* a bus address)
- **Max clock:** 100 kHz (standard mode only) — the connection must not be configured faster
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`; it shares `0x3C`/`0x3D` with the PCF8578, which cannot be told apart)
- **Probe safety:** `write_sensitive` — every byte after the address is a command or display data; there is no register pointer
- **Protocol:** no register addresses: `[addr+W] [command…, last command (C = 0)] [display data…]`, or `[addr+R] [data…]` (optionally after commands via a repeated START). Commands are acknowledged by **all** addressed devices; each **data byte** is acknowledged only by the device whose subaddress matches, so a NACK on data means "no device at that subaddress". Drivers use the plain `Connection` (`write`, `write_read`), not `RegisterConnection`

## Command Set

The PCF8579 has no register map. Commands are single bytes whose MSB is the **continuation bit C**: `C = 1` means another command byte follows, `C = 0` marks the last command — every byte after it is display data. The last command in a transaction therefore always has `C = 0`.

| Command | Bits 7…0 | Operation |
|---------|----------|-----------|
| set-mode | `C 1 0 T E1 E0 M1 M0` | Display mode, display status, multiplex rate |
| set-start-bank | `C 1 1 1 1 1 B1 B0` | RAM bank shown at the top of the display |
| device-select | `C 1 1 0 A3 A2 A1 A0` | Hardware subaddress counter (0–15) |
| RAM-access | `C 1 1 1 G1 G0 Y1 Y0` | RAM access mode and RAM bank (Y) |
| load-X-address | `C 0 X5 X4 X3 X2 X1 X0` | RAM column address (0–39) |

### set-mode fields

| Bits | Name | Values |
|------|------|--------|
| 4 | T | PCF8578 display mode that this system uses: `0` = PCF8578 row only, `1` = PCF8578 mixed mode (the PCF8579 itself has no row/column mode) |
| 3:2 | E[1:0] | `00` blank, `01` normal, `10` all segments on, `11` inverse video |
| 1:0 | M[1:0] | `01` 1:8 (8 rows), `10` 1:16 (16 rows), `11` 1:24 (24 rows), `00` 1:32 (32 rows) |

### set-start-bank

`B[1:0]` selects bank 0–3 as the top of the display (see Display RAM). Useful for scrolling, pseudo-motion and preparing new content in the background.

### device-select

`A[3:0]` loads the subaddress counter in **every** device on the addressed I²C address. A PCF8579 stores or returns RAM data only when the counter equals the 4-bit hardware subaddress set on its pins A3:A0; the counter increments automatically when the data pointer passes the last column of a device and wraps from 15 to 0. The PCF8578 sharing the bus has the fixed subaddress `0000` (mixed mode only), so PCF8579s used with it must use subaddresses starting at `0001`; in row-mode systems (PCF8578 as pure row driver) subaddress `0000` is free for a PCF8579.

### RAM-access fields

| Bits | Name | Values |
|------|------|--------|
| 3:2 | G[1:0] | `00` character, `01` half-graphic, `10` full-graphic, `11` not allowed |
| 1:0 | Y[1:0] | RAM bank (row address) 0–3 where the first byte goes |

### load-X-address

`X[5:0]` = column 0–39 where the first byte goes.

### Power-on reset defaults (PCF8579)

| Setting | Default |
|---------|---------|
| Display | blank (together with the PCF8578) |
| Multiplex rate | 1:32 |
| Start bank | 0 |
| Data pointer | X = 0, Y = 0 |
| RAM access | character mode |
| Subaddress counter | 0 |
| Display RAM | undefined (the datasheet does not state a reset value) — clear it before enabling the display |


## Display RAM

32 × 40 bits: four banks (Y = 0…3) of 40 bytes (X = 0…39). One byte holds 8 vertical pixels of one column: **bank Y covers display rows 8Y … 8Y+7**, bit 0 being the top row of the bank (Figure 15: LSB at the top of the byte column; confirm orientation on hardware). Unlike the PCF8578, **all 40 columns are displayed**: X = n drives output Cn (n = 0…39). The number of rows scanned is set by the multiplex rate (M field of set-mode), so banks 0 … rows/8 − 1 are visible and the remaining banks are off-screen buffers.

### RAM access modes

After the first byte is placed at (X, Y), the pointers auto-increment per byte, exactly as for the PCF8578:

| Mode | Order of successive bytes |
|------|---------------------------|
| character (`00`) | (X, Y), (X+1, Y), (X+2, Y), … — one bank, consecutive columns |
| half-graphic (`01`) | (X, Y), (X, Y+1), (X+1, Y), (X+1, Y+1), … — two banks per column |
| full-graphic (`10`) | (X, Y), (X, Y+1), (X, Y+2), (X, Y+3), (X+1, Y), … — four banks per column |

When the pointer passes X = 39 the **subaddress counter advances to the next device** (wrapping 15 → 0) and the data continues in that device's RAM at X = 0 (this is what makes one transfer span several cascaded PCF8579s). Bytes that arrive while the counter does not match any device are not acknowledged and are lost. The driver never writes past column 39 of its own device in one transaction. Y wraps within the mode's bank group — start half-graphic at an even bank and full-graphic at bank 0; other starts are not specified.

## Initialization Sequence

1. Wait ≥ 1 ms after power-on for the internal reset (no I²C traffic before that).
2. One write transaction that blanks the display and clears this device's RAM using full-graphic access: `device-select <subaddress>` (`0xE0 | A`, C = 1), `set-mode` (`C = 1`, `T`, `E = blank`, `M` = chosen rate), `set-start-bank 0` (`0xFC`, C = 1), `RAM-access` full-graphic bank 0 (`0xF8`, C = 1), `load-X 0` (`0x00`, C = 0), then **160 zero bytes** (40 columns × 4 banks, full-graphic order).
3. Second write: `set-mode` with `E = normal` (C = 0) to switch the display on.

Example for subaddress 0, mixed mode (T = 1), 1:16: step 2 = `E0 D2 FC F8 00` + 160 × `00`; step 3 = `56` (`set-mode` byte = `C << 7 | 0x40 | T << 4 | E << 2 | M`). With the PCF8578 in row mode (T = 0): `C2` / `46`.

**System note:** `device-select`, `set-mode` and `set-start-bank` commands are executed by *every* device at the I²C address — including the PCF8578 and other PCF8579s. Sending them from one driver instance therefore changes the whole display (multiplex rate, display status, start bank); only the RAM data goes to the one device whose subaddress matches. All drivers sharing a bus must use the same `rows`/`mixed` settings.

## Implementation Stages

### Minimal

Goal: write pixels into one PCF8579's display RAM out of the box. No configuration beyond the connection, subaddress and panel row count.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection, `subaddress: int = 0` (0–15), `rows: int = 16` (8, 16, 24 or 32), `mixed: bool = False` | — | Waits ≥ 1 ms, runs the Initialization Sequence, clears this device's RAM, switches the display on (normal); stores a shadow copy of its 4 × 40 RAM bytes. `mixed` sets the `T` bit (the PCF8578's mode in the system; default: PCF8578 as row driver) |
| `clear` | — | — | Zero this device's whole RAM and shadow (one full-graphic transfer of 160 bytes) |
| `set_pixel` | `x: int`, `y: int`, `on: bool = True` | — | Column `x` (0–39) and row `y` (0 … rows−1) **of this device**; updates the shadow byte and writes that single byte (`device-select`, `load-X`, `RAM-access` character, data); out-of-range coordinates are ignored |
| `write_columns` | `x: int`, `bank: int`, `data: bytes` | — | Write consecutive column bytes in character mode starting at column `x` of bank `bank` (0 … rows/8−1); bit 0 = top row; truncated at column 39; updates the shadow |

**Sensible defaults:** subaddress 0, 1:16 multiplex (16 rows × 40 columns on this device), normal display, start bank 0, character access, RAM cleared, PCF8578 assumed in row mode (`T` = 0).

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `get_pixel` | `x: int`, `y: int` | `bool` | From the shadow (no bus traffic) |
| `fill` | `on: bool = True` | — | Set every displayed pixel (rows × 40) on or off |
| `draw_line` | `x0, y0, x1, y1: int`, `on: bool = True` | — | Bresenham line, written as one batch of changed bytes |
| `draw_rect` | `x, y, w, h: int`, `on: bool = True`, `fill: bool = False` | — | Rectangle outline or filled |
| `show_bitmap` | `x: int`, `y: int`, `columns: bytes` | — | Blit 8-pixel-high column bytes at `y` aligned to a bank boundary (`y % 8 == 0`); other `y` rejected |
| `set_display` | `status: int` (`DISPLAY_BLANK`=0, `DISPLAY_NORMAL`=1, `DISPLAY_ALL_ON`=2, `DISPLAY_INVERSE`=3) | — | `set-mode` E field; RAM preserved. **Affects all devices on the address** |
| `set_mode` | `rows: int`, `mixed: bool = False` | — | Change multiplex rate / `T`; affects all devices; the shadow geometry is updated |
| `set_start_bank` | `bank: int` (0–3) | — | Hardware vertical scroll in 8-row steps (all devices) |
| `scroll` | `banks: int` | — | Add `banks` (may be negative) to the start bank modulo the number of banks in use |
| `write_ram` | `x: int`, `bank: int`, `data: bytes`, `mode: int = ACCESS_CHARACTER` | — | Raw write in character / half-graphic / full-graphic order at column `x` (0–39) and bank (0–3) of **this** device; rejects transfers that would pass column 39 (use `write_ram_cascade` for spanning) |
| `write_ram_cascade` | `data: bytes`, `mode: int = ACCESS_FULL_GRAPHIC` | — | Start at column 0, bank 0 of this device and let the data run on into the following subaddresses (the chip's auto-increment across devices); the shadow only tracks this device's first 40 columns |
| `read_ram` | `x: int`, `bank: int`, `n: int`, `mode: int = ACCESS_CHARACTER` | `bytes` | Raw read from this device: commands `device-select`, `RAM-access`, `load-X`, repeated-start read of `n` bytes |
| `reset` | — | — | Re-run init (clears this device's RAM) |

**Additional configuration options:** multiplex rate, PCF8578 mode bit, display status (blank / normal / all-on / inverse), start bank, RAM access mode, subaddress.

## Data Conversion

```
rows           = 8 | 16 | 24 | 32 (multiplex rate 1:rows)
RAM X          = x                           (x = 0..39; X n drives output Cn)
bank, bit      = y // 8 , y % 8
byte(X, bank)  = shadow[bank][X];  pixel set:  byte |= 1 << bit ; cleared: byte &= ~(1 << bit)
set-mode byte  = (C << 7) | 0x40 | (T << 4) | (E << 2) | M       M: 8->01, 16->10, 24->11, 32->00
RAM-access     = (C << 7) | 0x70 | (G << 2) | Y      (G: character 0, half 1, full 2)
load-X         = (C << 7) | X
device-select  = (C << 7) | 0x60 | A
set-start-bank = (C << 7) | 0x7C | B
```

Global column number in a cascade of k devices (all with 40 columns): `global_x = 40 × device_index + x`, where the device index follows the subaddress order the data stream traverses (subaddress counter 0, 1, 2, …).

An inject node every 500 ms drives a function node that computes a bouncing-pixel position across the 40 columns and sends `{ pixel: { x, y, on } }` (clearing the previous position first) into `periph-pcf8579` (subaddress 0, 16 rows, PCF8578 row-driver system); a second inject toggles `{ display: "inverse" }` / `"normal"`.

## Examples

### Demo

Test pattern for one PCF8579 (subaddress 0, 16 rows × 40 columns, PCF8578 in row mode providing the rows and clock) using the Full driver: draw a one-pixel border with `draw_rect`, both diagonals with `draw_line`, then flash the display with `set_display(DISPLAY_INVERSE)` / `DISPLAY_NORMAL` twice. Write a different pattern to each of the four RAM banks (only banks 0–1 are visible at 1:16; the others are off-screen buffers) and step `set_start_bank` through all four banks once per second to show hardware scrolling, printing the bank and the first column byte. Finish by reading back the first 8 columns of bank 0 with `read_ram` and printing them. If a second PCF8579 (subaddress 1) is wired, additionally send a 160-byte `write_ram_cascade` transfer that fills both devices.

## Timing Constraints

- Wait ≥ 1 ms after power-on before the first I²C transaction (internal reset). **Conformance-checked** as `poweron_ready` (min 1 ms), measured from capture start to the first decoded bus transaction (no power-sense channel — same pattern as the PCF8576/PCF8578) — see `specs/display/pcf8579_timing.conf`.
- I²C: fSCL ≤ 100 kHz, tBUF ≥ 4.7 µs, tLOW ≥ 4.7 µs, tHIGH ≥ 4.0 µs, tSU;DAT ≥ 250 ns (datasheet Table 15).
- Clock: fclk ≤ 10 kHz at 50 % duty (typically 0.9–3.3 kHz from the PCF8578's internal oscillator). A clock must always be present.
- Driver propagation delay ≤ 100 µs at VDD − VLCD = 9 V — a panel property, no driver wait.
- A transaction aborted mid-stream leaves the data pointer undefined: always begin each write with a fresh `device-select`, `load-X` and `RAM-access`.
- Apply and remove VDD and VLCD together to avoid DC build-up across the panel.

## Implementation Notes

- **Companion of the PCF8578:** the two chips share I²C addresses (`0x3C`/`0x3D`), the command set and the RAM geometry. Differences: the PCF8579 has 40 output columns and no row outputs, no oscillator, no bias pins V2/V5, a hardware subaddress on pins A3:A0 and displays all 40 RAM columns (the PCF8578 only 8..39 depending on the multiplex rate). A shared base class (command encoding, shadow RAM, pixel logic) with the PCF8578 driver is allowed.
- **Plain `Connection`, command stream:** same as the PCF8578 — `connection.write(bytes)` / `write_read(commands, n)`; never `RegisterConnection`. Every write ends its command bytes with a `C = 0` byte followed by data.
- **Broadcast commands:** commands reach every device at the address; only data is subaddress-filtered. Mixing devices with different `rows` / `mixed` settings on one bus is not possible, so a driver instance must reflect the system's configuration; Full's `set_mode` / `set_display` / `set_start_bank` act on the whole display.
- **Subaddress counter:** `device-select` is re-sent before every RAM access so a previous transaction (from another driver instance) cannot leave the counter pointing elsewhere. A PCF8579 whose pins A3:A0 do not match gets no data ACK — the driver should surface this as an error on `init` (first data byte NACKed) instead of silently succeeding.
- **Shadow buffer:** keep a 4 × 40 shadow of this device's RAM so `set_pixel` is a single-byte write; valid only after `init` has cleared the RAM (undefined at power-up).
- **No stand-alone operation:** without a PCF8578 (or an external CLK/SYNC and row driver) nothing is displayed even though the I²C interface and RAM work — do not treat a missing display as a bus fault.
- **Orientation unverified:** bit 0 = top row of a bank, bank 0 at the top at start bank 0, X increasing with output number — from Figures 15/18 and pin naming; confirm on a panel.
- **100 kHz limit:** connections created at the default 400 kHz must be reconfigured to ≤ 100 kHz.
- **Read mode:** RAM reads work for the matching subaddress; the master NACKs the last byte; `write_read` implies a repeated START after the command string.
- **Datasheet:** NXP PCF8579 Rev. 05 (11 May 2009). The URL given in the issue (`https://www.nxp.com/docs/en/data-sheet/PCF8579.pdf`) no longer resolves; the committed PDF is the same revision from a mirror.

## Sigrok Decoder

Decoder id `pcf8579`, input `['i2c']`. Matches I²C addresses `0x3C` and `0x3D`. Parses the command stream of every write exactly like the PCF8578 decoder (set-mode → T, status, rows; set-start-bank → bank; device-select → subaddress; RAM-access → access mode and bank; load-X → column; continuation bit tracked so bytes after a `C = 0` command are display data), annotates data bytes with their RAM position (subaddress, X, bank) following the access mode's auto-increment **including the roll-over into the next subaddress after column 39**, and renders each data byte as an 8-pixel column string. Reads are annotated as RAM data from the tracked pointer. Warnings: an access mode `11`, a transaction whose commands never clear `C`, and data that crosses X = 39 into a subaddress above 15 wrapping to 0. The decoder shares its command parsing with `sigrok/pcf8578/`. For the power-on conformance check the first bus transaction after capture start is annotated `poweron_ready` (marker `poweron_start` at capture start) in the `timing` annotation row shaped per `specs/sigrok_annotations.md`'s Variable-Length Annotation Convention; the gap must be ≥ 1 ms (see `specs/display/pcf8579_timing.conf`).
