# Chip Spec: SSD1305

**Manufacturer:** Solomon Systech  
**Datasheet:** `datasheets/display/ssd1305.pdf` (SSD1305 Rev 1.9, May 2008, "Advance Information", 70 pages, from `https://cdn-shop.adafruit.com/datasheets/SSD1305.pdf`)  
**Category:** `display`  
**Transports:** I²C, SPI (4-wire)

## Overview

The SSD1305 is a single-chip CMOS OLED/PLED driver with controller for monochrome dot-matrix graphic panels of up to **132 × 64** pixels: 132 segment (column) outputs, 64 common (row) outputs, 132 × 64 bits of display RAM (GDDRAM), an on-chip oscillator, 256-step contrast control, row/column remapping, hardware horizontal / vertical-and-horizontal scrolling, a display start line, programmable multiplexing and an optional **area-colour** mode (the top 16 rows can use a separate brightness/colour bank). It supports 8-bit 6800/8080 parallel, 3-/4-wire SPI and 400 kHz I²C interfaces; this spec covers **I²C and 4-wire SPI**. It is the chip behind 2.23″ 128 × 32 and 1.3″ 128 × 64 white/blue monochrome OLED modules, which show 128 of the 132 RAM columns (see Display RAM).

Differences from the SSD1306 / SH1106: the SSD1305 has **no internal charge pump** — the OLED supply **VCC (7–15 V) must be supplied externally** (the SSD1306 `0x8D` charge-pump command does not exist); it has **three memory-addressing modes** (horizontal, vertical, page — page is the reset default, as in the SH1106); it has a 132-column RAM; and it adds area-colour / look-up-table commands, a dim mode and a vertical-scroll-area command.

The two transports share one command set. The driver family is therefore a base class holding the command logic and framebuffer with two transport hooks: `Ssd1305Minimal` / `Ssd1305Full` (I²C) and `Ssd1305SpiMinimal` / `Ssd1305SpiFull` (SPI) — see Implementation Notes.

## Transport Configuration

### I²C
- **Address:** `0x3C` (SA0 = VSS) — `0x3D` (SA0 = VDDIO); 7-bit address `0111 10 SA0`, with the D/C# pin acting as SA0 (the same two addresses as the SH1106, PCF8578/PCF8579)
- **Max clock:** 400 kHz (tcycle ≥ 2.5 µs)
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`; it shares `0x3C`/`0x3D` with the SH1106, SSD1306 and PCF8578/PCF8579, which cannot be told apart)
- **Probe safety:** `write_sensitive` — every byte after the address and a control byte is a command or display data
- **Interface select pins:** BS0 = 0 (internally tied to VSS), BS1 = 1, BS2 = 0; CS# tied low. SDAIN (D1) and SDAOUT (D2) are shorted together as SDA (if SDAOUT is left open the chip never ACKs — tie them together)
- **Protocol:** write = `[addr+W] [control byte] [data byte(s)] …`. The **control byte** is `Co D/C# 0 0 0 0 0 0`: `Co = 1` means one data byte follows and then another control byte; `Co = 0` means all remaining bytes in the transaction are data. `D/C# = 0` → the data is a command, `D/C# = 1` → display RAM data. So a command stream is `0x00, cmd, cmd, …` (or `0x80, cmd` per command) and a RAM stream is `0x40, d0, d1, …`. Read = `[addr+R] [data…]`, returning the status byte or RAM data according to the D/C# bit of the last write (see Read access)
- **Register addressing:** none — plain `Connection` (`write`, `read`), not `RegisterConnection`

### SPI (4-wire)
- **Mode:** CPOL=0 CPHA=0 (Mode 0) — SDIN is sampled on the rising SCLK edge; the idle level is not named in the datasheet, Mode 0 is the usual choice (confirm on hardware)
- **Max clock:** 4 MHz (tcycle ≥ 250 ns, clock high/low ≥ 100 ns); drivers default to 2 MHz
- **Bit order:** MSB first
- **CS active:** low (CS# may be hard-wired low on a dedicated bus)
- **Framing:** a plain byte stream — no opcode or address bytes. The **D/C# pin** is sampled on every eighth clock: `D/C# = 0` → the byte is a command, `D/C# = 1` → display RAM data. SPI goes through a `DisplayConnection` (`specs/transport_display.md`), which owns D/C, RES and CS; the driver sends command bytes with `send_command()` and display RAM data with `send_data()`
- **Read:** not possible over SPI ("no data read is provided in serial mode")
- **3-wire SPI (9-bit frames) and the parallel interfaces are not supported** (the byte-oriented SPI connection cannot send 9-bit frames)
- **Interface select pins:** BS0 = 0, BS1 = 0, BS2 = 0; D2 left open, D3–D7, E and R/W# tied to ground

## Command Set

All commands are single bytes sent with D/C# = 0; multi-byte commands are a mode byte followed by data bytes in the same command stream. Reset values are in parentheses. Patterns not in this table "are prohibited to enter the chip as a command; as unexpected results can occur".

| Command | Code | Description |
|---------|------|-------------|
| Set lower column address | `0x00 \| A[3:0]` | Low nibble of the column pointer, **page addressing mode only** (reset `0x00`) |
| Set higher column address | `0x10 \| A[3:0]` | High nibble of the column pointer, page addressing only; columns 0–131 (`0x00`–`0x83`) |
| Set memory addressing mode | `0x20`, then `A[1:0]` | `00` horizontal, `01` vertical, `10` page (reset), `11` invalid |
| Set column address range | `0x21`, then start, end | Horizontal/vertical modes: start 0–131 (reset 0), end 0–131 (reset 131) |
| Set page address range | `0x22`, then start, end | Horizontal/vertical modes: start 0–7 (reset 0), end 0–7 (reset 7) |
| Set display start line | `0x40 \| A[5:0]` | RAM line shown at COM0 (0–63; reset 0) |
| Set contrast (BANK0) | `0x81`, then `00`–`FF` | Contrast of the monochrome background bank (reset `0x80`) |
| Set brightness (colour banks) | `0x82`, then `00`–`FF` | Brightness of the area-colour banks (reset `0x80`) |
| Set look-up table | `0x91`, then X, A, B, C (6 bit each) | Drive pulse width of BANK0 / colours A, B, C = 32…64 clocks (value 31…63; reset BANK0 `0b110001`, A/B/C `0b111111`); colour D fixed at 64 clocks |
| Set bank colour BANK1–16 | `0x92`, then 4 bytes | 2 bits per bank selects colour A–D for PAGE0 banks 1–16 |
| Set bank colour BANK17–32 | `0x93`, then 4 bytes | Same for PAGE1 banks 17–32 |
| Segment re-map (ADC) | `0xA0` / `0xA1` | `0xA0`: column 0 ↔ SEG0 (reset); `0xA1`: column 131 ↔ SEG0 |
| Entire display on | `0xA4` / `0xA5` | `0xA4` follows RAM (reset); `0xA5` forces all pixels on (RAM kept) |
| Normal / inverse | `0xA6` / `0xA7` | `0xA6` RAM 1 = pixel on (reset); `0xA7` inverted |
| Multiplex ratio | `0xA8`, then `0F`–`3F` | Ratio = data + 1: 16…64 MUX (reset `0x3F`); data 0–14 invalid |
| Dim mode setting | `0xAB`, then A (`0x00`), B, C | B = contrast (BANK0), C = colour-bank brightness used in dim mode |
| Master configuration | `0xAD`, then `0x8E` | `0x8E`: external VCC (reset; `0x8F` reserved). Only external VCC is supported |
| Display dim on / off / on | `0xAC` / `0xAE` / `0xAF` | `0xAC` display on in dim mode; `0xAE` off = sleep (reset); `0xAF` on in normal mode |
| Set page start | `0xB0 \| A[2:0]` | Page 0–7, page addressing only (reset 0) |
| COM scan direction | `0xC0` / `0xC8` | `0xC0` COM0→COM[N−1] (reset); `0xC8` reversed |
| Display offset | `0xD3`, then `00`–`3F` | Vertical shift by COM (reset 0) |
| Clock divide / oscillator | `0xD5`, then `A7:A4 osc, A3:A0 div−1` | Divide ratio = A[3:0] + 1; oscillator frequency increases with A[7:4] (reset `0x70`; fOSC 324–396 kHz at reset setting) |
| Area colour / low power | `0xD8`, then `00 X5 X4 0 X2 0 X0` | X[5:4] = `11` area colour on (`00` monochrome, reset); X[2] = X[0] = 1 low-power display mode (`0` normal, reset) |
| Pre-charge period | `0xD9`, then `A7:A4 phase2, A3:A0 phase1` | DCLKs, 1–15, `0` invalid (reset `0x22`) |
| COM pins configuration | `0xDA`, then `00 X5 X4 0010` | X[4] = 0 sequential, 1 alternative (reset `0x12`); X[5] = 1 enables COM left/right remap |
| VCOMH deselect level | `0xDB`, then `A[5:2]` (`00 A5 A4 A3 A2 00`) | `0x00` ≈ 0.43·VCC, `0x34` ≈ 0.77·VCC (reset), `0x3C` ≈ 0.83·VCC |
| Read-modify-write | `0xE0` | Column pointer increments only on writes until `0xEE` |
| End | `0xEE` | Leaves read-modify-write; column pointer returns to its pre-`0xE0` value |
| NOP | `0xE3` | No operation |

### Graphic acceleration (scroll) commands

| Command | Code | Description |
|---------|------|-------------|
| Horizontal scroll setup | `0x26` (right) / `0x27` (left), then A, B, C, D | A[2:0] columns per step (0–4; 0 = none), B[2:0] start page, C[2:0] step interval (`000` 6 frames, `001` 32, `010` 64, `011` 128, `100` 3, `101` 4, `110` 2; `111` invalid), D[2:0] end page (≥ B) |
| Vertical + horizontal scroll setup | `0x29` (right) / `0x2A` (left), then A, B, C, D, E | A–D as above, E[5:0] vertical offset per step in rows (1–63) |
| Deactivate scroll | `0x2E` | Stops scrolling; **RAM data must be rewritten afterwards** |
| Activate scroll | `0x2F` | Starts the scroll configured by the last `0x26/0x27/0x29/0x2A` command |
| Set vertical scroll area | `0xA3`, then A[5:0], B[6:0] | A = rows in the fixed top area (reset 0), B = rows in the scroll area (reset 64); A + B ≤ multiplex ratio |

Do not send `0x26`/`0x27`/`0x29`/`0x2A` while scrolling is active (send `0x2E` first); the setup commands only take effect on `0x2F`.

### Power-on / reset defaults

Display off (segments/commons high-impedance), 132 × 64 mode, page addressing mode, normal segment and scan mapping (SEG0 ↔ address 0, COM0 ↔ address 0), start line 0, column pointer 0, contrast `0x80`, colour-bank brightness `0x80`, monochrome mode, multiplex 64, clock divide 1 at oscillator setting `0111b`, pre-charge/discharge 2/2, COM alternative, VCOMH `0x34`, normal (non-inverted) display, entire display follows RAM, external VCC selected. The display RAM contents are **undefined** at power-up; clear it before the display is switched on.

## Display RAM

132 columns × 8 pages × 8 bits = 132 × 64 bits. One data byte holds 8 vertical pixels of one column of one page: **bit 0 (D0) is the top row of the page**, page 0 is at the top at start line 0. Pages 0 and 1 form the 132 × 16 *area-colour section*, pages 2–7 the monochrome 132 × 48 section; in monochrome mode (the driver default) all eight pages are plain monochrome pixels.

- **Page addressing (reset default; used by the driver):** set the page (`0xB0|p`) and the column pointer (`0x00|low`, `0x10|high`), then write data bytes; the column pointer **auto-increments after every data read/write** but the page does **not** change. Moving to the next page needs a new page + column command.
- **Horizontal addressing (`0x20 0x00`):** the column pointer increments after every data byte and wraps from the column end (set with `0x21`) to the column start while the page pointer advances (range set with `0x22`); after the last page it wraps to the first. The whole screen can be written as one continuous stream.
- **Vertical addressing (`0x20 0x01`):** the page pointer increments first and wraps at the page end, then the column advances.
- In horizontal/vertical mode the page/column-pointer commands `0xB0…`/`0x00…`/`0x10…` have no effect; in page mode `0x21`/`0x22` have no effect.

Segment mapping: with ADC = `0xA0` column `n` drives SEG`n`; with `0xA1` column `131 − n` drives SEG`n`. **128-pixel-wide modules** are normally wired to SEG4…SEG131 (Adafruit's SSD1305 modules begin at RAM column 4) or SEG2…SEG129 depending on the panel — not stated in the datasheet: the driver exposes `column_offset` (default **4**, `0` for a true 132-column panel; a module that shows two shifted garbage columns needs `2`).

## Initialization Sequence

Per the datasheet's power-on sequence (external VCC):

1. Apply VDD/VDDIO. After they are stable pulse RES# low for ≥ 3 µs (`connection.reset()` pulses it low for `reset_pulse_us ≥ 3` and releases it, then waits `reset_settle_ms`). All registers are reset after the pulse.
2. Wait ≥ 3 µs after RES# goes low, then power on VCC (board-level; the driver cannot switch it).
3. Send the setup commands in one command stream with the display off: `0xAE`, `0xD5 0x70` (clock, reset value), `0xA8 height−1` (multiplex), `0xD3 0x00` (offset 0), `0x40` (start line 0), `0xA0|ADC`, `0xC0|(scan<<3)`, `0xDA 0x12` (alternative COM; `0x02` for 32-row sequential panels), `0x81 0x80` (contrast), `0xD9 0x22`, `0xDB 0x34`, `0xAD 0x8E` (external VCC), `0xA4` (follow RAM), `0xA6` (normal), `0x20 0x02` (page addressing).
4. Clear the display RAM (8 pages × 132 bytes of `0x00`, one page + column set per page) before turning the display on.
5. `0xAF` (display on); the datasheet says SEG/COM are on after tAF = 100 ms — wait 100 ms before relying on the picture.

Power-off: `0xAE`, switch VCC off, wait tOFF (typ. 100 ms), then switch off VDD/VDDIO. VDD must never be removed before VCC, and VCC/VDD must never be pulled to ground.

## Implementation Stages

### Minimal

Goal: a 128 × 64 (or 128 × 32) monochrome OLED you can draw pixels on out of the box.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection (I²C: `I2CConnection`, `addr=0x3C`; SPI: a `DisplayConnection` with `busy=None`), `width: int = 128`, `height: int = 64`, `column_offset: int = 4` | — | Runs the Initialization Sequence (with the waits; VCC must already be applied), clears the RAM and framebuffer, switches the display on; `width` ≤ 132, `height` ∈ {16 … 64, multiple of 8}; `height` ≤ 32 selects sequential COM wiring (`0xDA 0x02`) |

## Data Conversion

```
page, bit      = y // 8 , y % 8
fb[page][x]    = framebuffer byte for column x of that page            (x = 0..width-1)
set pixel      : fb[page][x] |=  (1 << bit)     clear: &= ~(1 << bit)
RAM column     = column_offset + x

show() (page mode):  for p in 0..height/8-1:
            cmd stream: 0xB0|p, 0x00|(col & 0x0F), 0x10|(col >> 4)     with col = column_offset
            data stream: fb[p][0..width-1]

show() (horizontal mode):
            cmd stream: 0x21, column_offset, column_offset+width-1, 0x22, 0, height/8-1
            data stream: fb[0][0..width-1], fb[1][0..width-1], …

I²C control bytes:  0x00  = last control byte, following bytes are commands
                    0x80  = command byte follows, then another control byte
                    0x40  = last control byte, following bytes are display data
SPI:  D/C# low for command bytes, D/C# high for data bytes
Frame rate     = fOSC / (D × K × MUX)      D = divide ratio, K = 54 DCLKs per row, MUX = multiplex ratio
Segment current = contrast-dependent; 0xFF ≈ 320 µA, 0x7F ≈ 159 µA, 0x3F ≈ 79 µA (IREF = 10 µA, VCC = 12 V)
```

### Demo flow

An inject node every 100 ms drives a function node computing a bouncing-ball position on the 128 × 64 display and sends `{ clear: true }` then `{ rect … }` messages followed by `{ show: true }`; a second inject toggles `{ invert: true }` / `{ invert: false }`, a third sets `{ contrast: N }` from a slider, a fourth starts/stops `{ scroll: … }`.

### Demo

**Bouncing ball with hardware scroll and dimming.** Using the Full driver on a 128 × 64 panel: draw a one-pixel border with `draw_rect` and a filled 6 × 6 ball with `draw_rect(fill=True)` that bounces around inside it (about 20 frames per second with `show`); after 10 s ramp `set_contrast` from 255 down to 0 and back, flash `set_invert` twice, switch to `set_dim_mode` + `set_dim(True)` for two seconds, then demonstrate hardware scrolling: `set_scroll_horizontal(right=True, 0, 7, interval=0)` with `scroll_start()` for five seconds, then `scroll_stop()`, and finish with `sleep()`. ## Timing Constraints

- **Reset:** RES# low ≥ 3 µs; registers are reset after the pulse.
- **Power sequence:** VDD/VDDIO first, RES# low ≥ 3 µs (t1), wait ≥ 3 µs (t2) after RES# low, then VCC; after VCC is stable send `0xAF` — SEG/COM turn on after tAF = 100 ms. Power-off: `0xAE`, VCC off, tOFF typ. 100 ms (min 0), then VDD/VDDIO off. VDD must not be removed before VCC. These are recommended waits, not hard limits.
- **I²C:** tcycle ≥ 2.5 µs (≤ 400 kHz), start hold/setup ≥ 0.6 µs, stop setup ≥ 0.6 µs, data setup ≥ 100 ns, data hold ≥ 300 ns (SDAIN), bus idle time tIDLE ≥ 1.3 µs between transmissions.
- **SPI:** SCLK cycle ≥ 250 ns (clock high/low ≥ 100 ns), D/C# address setup/hold 150 ns, CS# setup 120 ns / hold 60 ns, data setup 50 ns / hold 15 ns — hence the 2 MHz default (4 MHz maximum).
- **Scrolling:** after `0x2E` (scroll off) the RAM must be rewritten; scroll setup commands must not be issued while scrolling is active.
- **Conformance:** none of these has a bus-decodable start/end annotation pair that the host controls (the delays are recommended waits after commands, not measured events), so `specs/display/ssd1305_timing.conf` defines no checks.

## Implementation Notes

- **One base class, two transports:** implement an abstract base (`_Ssd1305Base`) with the framebuffer, drawing, and command logic and two hooks `write_commands(bytes)` / `write_data(bytes)`. The I²C classes prepend the control byte (`0x00`/`0x40`) to every transaction (one `connection.write` per stream, chunked to the platform's maximum write size; every chunk of data repeats the `0x40` control byte); the SPI classes call `DisplayConnection.send_command()` / `send_data()`, which drive D/C low/high and frame each transfer with CS. SPI RAM data can be sent as a single transaction per page (or per frame in horizontal mode).
- **Plain `Connection`, not `RegisterConnection`:** the control byte is not a register address; the same style as the PCF8576 and SH1106 drivers. The SPI connection must not fold read/burst bits into the first byte.
- **I²C transaction sizes:** some platform I²C layers limit a write to 32 bytes (Arduino `Wire`); chunk RAM data accordingly (each chunk a fresh `0x40` control byte; the column pointer keeps advancing between chunks).
- **No charge pump:** VCC (7–15 V) must be supplied by the board. Never send the SSD1306 charge-pump command `0x8D`; the driver only sends the master-configuration `0xAD 0x8E` (external VCC). The display must not be switched on before VCC is stable.
- **Addressing mode vs. SSD1306/SH1106 code:** the reset mode is *page addressing* (as on the SH1106), so SSD1306 snippets that assume horizontal addressing show garbage unless `0x20 0x00` is sent. In page mode the column pointer stops at 131 and wraps nowhere; never write past the last column. `set_addressing_mode` changes how `show()` writes; mixing modes without it corrupts the picture.
- **Command differences:** `0xAD` here selects the supply (`0x8E` = external VCC), not an on-chip DC-DC (SH1106: `0x8A/0x8B`); the VCOMH code uses bits 5:2 only; the multiplex ratio is limited to 16–64 (values 0–14 invalid); `0xAB`, `0xAC`, `0xD8`, `0x82`, `0x91`–`0x93` and the scroll commands exist only on the SSD1305.
- **132 vs 128 columns:** the visible columns of a 128-wide module start at RAM column 4 on most boards (some start at 2); the offset is not in the datasheet. A wrong offset shifts the picture and shows garbage columns at the edge; configure `column_offset` for the panel.
- **Scrolling:** the scroll engine runs in hardware; after `0x2E` the datasheet requires the RAM to be rewritten, so `scroll_stop` re-sends the framebuffer. Scroll interval codes are not monotonic (`100` = 3 frames, `101` = 4, `110` = 2, `000` = 6) — the driver takes a table index 0–6 mapped to the register codes `{0:6 frames, 1:32, 2:64, 3:128, 4:3, 5:4, 6:2}`.
- **Area-colour mode** only changes the drive strength per bank (pages 0 and 1) on panels that have colour sub-areas; on a plain monochrome panel leave it disabled. `set_lut`, `set_bank_colors` and `set_brightness` have no visible effect in monochrome mode.
- **Read access (I²C only):** RAM reads need one **dummy read** after the column address is set; status is read with the D/C# bit cleared in the last control byte and only bit 6 (display off) is defined. Reading over SPI is impossible. Reading is rarely needed because the driver keeps a framebuffer.
- **Read-modify-write:** `0xE0` … `0xEE` is not used by the driver (the framebuffer replaces it); `send_command` exposes it.
- **Advance Information datasheet:** Rev 1.9 is marked "Advance Information"; the SPI mode and the 128-column offset are not stated in it and are marked above as derived.
- **Not covered:** parallel (6800/8080) and 3-wire SPI interfaces and the external-clock mode (CLS low).
- **Datasheet:** SSD1305 Rev 1.9 (`https://cdn-shop.adafruit.com/datasheets/SSD1305.pdf`, 70 pages).

## Sigrok Decoder

Two decoders sharing one command table: `ssd1305` (input `['i2c']`, addresses `0x3C`/`0x3D`) and `ssd1305_spi` (input `['spi']`; the D/C# line is read from an optional logic channel, otherwise every transfer is shown as raw bytes). The I²C decoder splits each write into control bytes (`Co`, `D/C#`) and payload; command payloads are decoded into named commands with arguments (column nibbles combined into a column number, page, start line, contrast, brightness, ADC, invert, multiplex, master configuration, display on/off/dim, scan direction, offset, clock divide / oscillator, pre-charge, COM config, VCOMH, addressing mode, column/page ranges, scroll setup/activate/deactivate/area, area-colour mode, LUT, bank colours, dim mode, read-modify-write / end); multi-byte commands consume their data bytes, and data payloads are shown with the current page and column (auto-incrementing per the active addressing mode, clamped at 131 in page mode) and a count; each data byte can be rendered as an 8-pixel column. Reads are shown as status (display on/off) or RAM data. Warnings: a command byte not in the table (including the SSD1306-only charge-pump command `0x8D`), a data write that crosses column 131 in page mode, a scroll setup command issued while scrolling is active, and a write whose first control byte has `Co = 0`/`D/C# = 0` but no command bytes. No timing annotation pair is emitted (the datasheet delays are recommendations, not measured events).
