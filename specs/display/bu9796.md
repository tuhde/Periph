# Chip Spec: BU9796

**Manufacturer:** ROHM Semiconductor  
**Datasheet:** `datasheets/display/bu9796.pdf` (the datasheet linked in the issue is **BU97960MUV**, "Low Duty LCD Segment Drivers", Rev. 002, 05.Jan.2021 — the ROHM part this family document describes; the issue names the family "BU9796")  
**Category:** display  
**Transports:** I²C (2-wire serial, write and register-read)

## Overview

The BU97960MUV is a general-purpose low-duty LCD segment driver for consumer and battery products: **1/8 duty (up to 120 segments, SEG0–SEG14 × COM0–COM7) or 1/4 duty (up to 76 segments, 1/3 bias)** selectable by command, with a 15 × 8-bit display RAM (DDRAM), an integrated buffer amplifier and oscillator (no external components), an independent LCD supply (VLCD) and a 32-step **electrical volume register (EVR)** for LCD contrast. Supply VDD 2.5–6.0 V, VLCD 2.5–6.0 V, −40…+85 °C, VQFN28 (5 × 5 mm). It talks a 2-wire serial interface that is I²C-like with a **C bit in every command byte** (no per-byte ACK wait is needed for display data); write mode loads the DDRAM and command registers, read mode returns two of the command registers.

## Transport Configuration

### I²C
- **Address:** `0x3E` (fixed; 7-bit `0111110`, wire bytes `0x7C` write / `0x7D` read)
- **Max clock:** SCL cycle ≥ 2.5 µs (≤ 400 kHz), SCL high ≥ 0.6 µs, low ≥ 1.3 µs, SDA setup/hold ≥ 100 ns, bus free ≥ 1.3 µs; rise/fall ≤ 0.3 µs
- **Identity register:** none (`registry/chips.json` entry has `"id_probe": null`; address `0x3E` is shared with the PCF8566 and PCF8574-family ranges)
- **Probe safety:** `write_sensitive` — the first byte after the address is a command; display data bytes follow
- **Protocol:** `[addr+W] [command byte with C=1]… [last command byte with C=0 or the ADSET byte] [display data byte]… P`. **C** (bit 7 of every command byte): `C = 1` — the next byte is another command; `C = 0` — the next byte starts display data (RAM write). After display data begins no further command is accepted until a new START. A START or STOP in the middle of a command stream cancels that command. The slave address must follow the START immediately. The drivers use the plain `Connection` (`write`; Full also `read` for the register read)
- **Register read:** `S [0x7C] [0x8F|0x90 → ADSET with C=1 selecting REG1/REG2] P`, then `S [0x7D] [data byte] P` (only one register per read; after reading the chip leaves read mode and waits for a slave address)

## Pin Configuration

| Pin | Notes |
|-----|-------|
| SDA, SCL | Serial interface (SD/SCL); external pull-ups |
| VDD, VSS | Logic supply 2.5–6.0 V |
| VLCD | LCD drive supply 2.5–6.0 V; with EVR = 0 VLCD equals V0 (the maximum LCD drive voltage) |
| COM0–COM7 | Common outputs (COM4–COM7 double as SEG18–SEG15 in 1/4 duty) |
| SEG0–SEG14 | Segment outputs |

No interrupt or reset pins (power-on reset plus the software reset command).

## Command Set

Every command byte: bit 7 = **C**, bits 6:0 = opcode. Values below show the opcode with C = 1 added (`0x80`) unless it is the final byte before display data (C = 0).

| Command | Format (D7..D0) | Description |
|---------|-----------------|-------------|
| ADSET | `C 0 P5 P4 P3 P2 P1 P0` | DDRAM address `0x00`–`0x0E` (write mode); `0x0F` = REG1, `0x10` = REG2 (read mode). An out-of-range write address resets to 0 |
| EVRSET | `C 1 0 P4 P3 P2 P1 P0` | EVR 0–31 (reset 0) |
| DISCTL | `C 1 1 0 P3 P2 1 0` | Frame frequency (with FRSEL from MODESET) |
| ICSET | `C 1 1 1 0 P2 P1 P0` | P2 drive waveform (`1` frame inversion — reset, `0` line inversion), P1 software reset, P0 display on |
| APCTL | `C 1 1 1 1 0 P1 P0` | P1 all pixels on (APON), P0 all pixels off (APOFF); both set = all off |
| MODESET | `C 1 1 1 1 1 P1 P0` | P1 frame-frequency mode (`0` normal, `1` 200 Hz mode = FRSEL), P0 duty/bias (`0` = 1/8 duty and 1/4 bias — reset, `1` = 1/4 duty and 1/3 bias) |

### DISCTL frame frequency (P3 P2, FRSEL from MODESET P1)

| P3 P2 | FRSEL = 0 (normal) | FRSEL = 1 (200 Hz mode) |
|-------|--------------------|-------------------------|
| `00` | 80 Hz (reset) | 233 Hz |
| `01` | 71 Hz | 197 Hz |
| `10` | 64 Hz | 160 Hz |
| `11` | 50 Hz | 122 Hz |

The actual frame frequency varies with the internal oscillator (fCLK: 56–104 Hz at 25 °C for the nominal 80 Hz).

### Wire bytes (with C = 1 unless noted)

- ICSET software reset: `0xF2` (P1 = 1; do not combine P1 with P2/P0)
- ICSET display on / off, frame inversion: `0xF5` / `0xF4`; with line inversion: `0xF1` / `0xF0`
- DISCTL 80 Hz: `0xE2`; 71 Hz `0xE6`; 64 Hz `0xEA`; 50 Hz `0xEE`
- EVRSET n: `0xC0 | n`
- MODESET: `0xFC | P1<<1 | P0` (`0xFC` = 1/8 duty, `0xFD` = 1/4 duty)
- APCTL: `0xF8 | P1<<1 | P0`
- ADSET a (final command before display data, C = 0): `a` (`0x00`–`0x0E`); with C = 1 (read mode selection): `0x80 | a`

### Reset (power-on and software reset) defaults

Display off; DDRAM address 0 (DDRAM **contents are not initialised**); EVR = 0; frame frequency 80 Hz normal; frame inversion; 1/8 duty and 1/4 bias; APCTL normal. After power-on **all register values, DDRAM address and DDRAM data are random** until the start sequence ran.

### Readable registers (read mode)

| Register | Address | D7 | D6 | D5 | D4 | D3 | D2 | D1 | D0 |
|----------|---------|----|----|----|----|----|----|----|----|
| REG1 | `0x0F` | frame frequency (FRSEL) | duty and bias | software-reset condition | EVR4 … EVR0 | | | | |
| REG2 | `0x10` | FR (frame frequency) P7:P6 | | `1` | `0` | LCD drive waveform | display on/off | APON | APOFF |

## Initialization Sequence

Datasheet start sequence (Start Sequence Example):

1. Power-on (VDD must rise before VLCD; VDD rise time ≤ 5 ms recommended); wait **≥ 100 µs**.
2. STOP, then START; slave address `0x7C`; ICSET software reset `0xF2`.
3. DISCTL `0xE2` (80 Hz); EVRSET (e.g. `0xC0` = EVR 0, or the contrast chosen); MODESET `0xFC` (1/8 duty, 1/4 bias — or `0xFD`).
4. ADSET `0x00` (C = 0), then 15 display data bytes (addresses `0x00`–`0x0E`; the DDRAM is random after power-up, so write all of it); STOP.
5. START, address, ICSET display on `0xF5`; STOP. Do not send display-off within one frame (≈ 12.5 ms at 80 Hz) of display-on.

## Implementation Stages

### Minimal

Goal: drive a segment LCD in the default 1/8-duty mode: set segments and show them, without any configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Runs the start sequence: software reset, 80 Hz, EVR 0, 1/8 duty and 1/4 bias, clears the RAM, display on |
| `clear` | — | — | Zero all 15 RAM bytes (all segments off) |
| `write_raw` | `address: int` (0–14), `data: bytes` | — | ADSET + display data (1/8 duty: one byte per segment column, bit `n` = COM`n`); raises when `address + len(data) > 15` |
| `set_segment` | `seg: int` (0–14), `com: int` (0–7), `on: bool = True` | — | Updates the driver's 15-byte shadow RAM and writes that column |
| `update` | — | — | Write the whole shadow RAM (15 bytes) in one transaction |

**Constants:** `SEGMENTS = 15`, `COMMONS = 8`.

**Sensible defaults:** 1/8 duty, 1/4 bias, frame frequency 80 Hz (normal mode), frame inversion, EVR 0, RAM cleared, display on.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `display_on` / `display_off` | — | — | ICSET P0 (keeps the waveform bit); the driver waits ≥ 1 frame between on and off |
| `set_contrast` | `evr: int` (0–31) | — | EVRSET; raises outside 0–31 |
| `set_duty` | `duty8: bool` | — | MODESET: `True` = 1/8 duty + 1/4 bias, `False` = 1/4 duty + 1/3 bias |
| `set_frame_rate` | `hz: int` (80, 71, 64, 50, 233, 197, 160, 122) | — | DISCTL + MODESET P1; raises on other values |
| `set_inversion` | `line: bool` | — | ICSET P2 (`True` = line inversion, `False` = frame inversion) |
| `all_pixels` | `mode: str` (`"normal"`, `"on"`, `"off"`) | — | APCTL |
| `software_reset` | — | — | ICSET P1 (`0xF2`); display goes off, address 0 |
| `read_register` | `which: int` (1 or 2) | int | REG1 / REG2 via read mode; raises if the connection cannot `read` |
| `get_pixel` | `seg`, `com` | bool | From the shadow RAM |

**1/4-duty note:** in 1/4 duty each transmitted byte carries two 4-bit columns (bits 0–3 then bits 4–7, COM0–COM3 each) and the address advances by two columns per byte; the datasheet gives the ADSET range as `0x00`–`0x0E` and does not state how SEG15–SEG18 (the COM4–COM7 pins in this mode) are addressed, so the drivers limit 1/4-duty `write_raw` to addresses `0x00`–`0x0E`.

**Additional configuration options:** duty/bias, frame frequency, inversion mode, contrast (EVR), all-pixel on/off, register read-back.

## Data Encoding

```
1/8 duty :  DDRAM address a = SEG a, bit n = COMn  (a = 0..14, n = 0..7)    # byte 'a b c d e f g h' = COM0..COM7 (bit 0 = COM0)
1/4 duty :  DDRAM address a = 4-bit column, bit n = COMn (n = 0..3);        # a transmitted byte fills addresses a (bits 0..3) and a+1 (bits 4..7)
set_segment(seg, com, on):  shadow[seg] |= 1 << com   (or &= ~(1 << com));  write [addr+W][ADSET seg (C=0)][shadow[seg]]
update():                    write [addr+W][ADSET 0x00 (C=0)][shadow[0..14]]
EVR n:                       V0 = VLCD * ratio(n), ratio(0) = 1, ratio(n) ~ 1 / (1 + n/30) down to 0.491 at n = 31
```

EVR ratios (datasheet): `n` = 0: 1.000, 1: 0.967, 2: 0.937, 3: 0.909, 4: 0.882, 5: 0.857, 6: 0.833, 7: 0.810, 8: 0.789, 9: 0.769, 10: 0.750, 12: 0.714, 15: 0.666, 18: 0.625, 20: 0.600, 25: 0.545, 30: 0.500, 31: 0.491 (× VLCD). V0 must not fall below 2.5 V and `VLCD − V0 > 0.6 V` must hold.

## Timing Constraints

- **Power-on:** wait **≥ 100 µs** after VDD rises before the first START (start sequence). Conformance-checked as `poweron_ready` (min 100 µs) in `specs/display/bu9796_timing.conf`, measured from capture start to the first decoded bus transaction (the same pattern as `display/pcf8576`). Recommended supply: tR < 5 ms, tF < 5 ms, tOFF > 20 ms, VBOT < 0.3 V; VDD before VLCD at power-up, VDD off after VLCD at power-down (t1, t2 > 0).
- **Display on/off:** after Display ON the chip completes start-up within one frame; **do not send Display OFF within one frame** of Display ON (it would hold the start-up state and draw abnormal current): frame ≈ 12.5 ms at 80 Hz → wait ≥ 15 ms.
- **Frame frequency:** nominal 80 Hz (56–104 Hz over temperature, spread 72–88 Hz in the second characteristic); 50–233 Hz selectable.
- **Time-out:** none specified for I²C; a START/STOP inside a command stream cancels it.
- **I²C:** tSCYC ≥ 2.5 µs, tSHW ≥ 0.6 µs, tSLW ≥ 1.3 µs, tBUF ≥ 1.3 µs, tHD;STA/tSU;STA/tSU;STO ≥ 0.6 µs, tSDS/tSDH ≥ 100 ns.

## Implementation Notes

- **After power-up everything is random:** run the full start sequence including a write of all 15 RAM bytes (the software reset does not clear the DDRAM data).
- **C bit semantics:** only the **last** command byte before display data has `C = 0`; a transaction that starts with display data directly needs an ADSET (`C = 0`) first. Display data cannot be followed by commands in the same transaction — use a new START.
- **Never combine software reset with other ICSET bits** (P1 with P2/P0); send it as its own command (`0xF2`).
- **Write-then-wait for display off:** keep ≥ 1 frame between display-on and display-off.
- **Read mode:** read the register selection with an ADSET byte `0x8F` / `0x90` (C = 1) in one write transaction, STOP, then a separate read transaction; only one register per read.
- **1/4 duty:** limited to 76 segments; see the note under Full on the SEG15–SEG18 addressing gap in the datasheet.
- **Name:** the issue calls the part "BU9796"; the datasheet and orderable part are BU97960MUV. The spec and drivers are named `bu9796`.
- **Light sensitivity:** bare-die and VQFN parts are fine in housings; avoid direct strong light (general CMOS note).
- **Datasheet:** ROHM BU97960MUV Rev. 002, from `https://fscdn.rohm.com/en/products/databook/datasheet/ic/driver/lcd_segment/bu97960muv-e.pdf`.

## Sigrok Decoder

Decoder id `bu9796`, input `['i2c']`. Matches I²C address `0x3E`. Decodes each command byte with its C bit (ADSET, EVRSET, DISCTL, ICSET with reset/display/waveform fields, APCTL, MODESET with duty/bias and frame-frequency mode) and the following display data bytes (hex, plus the lit COM bits per segment column); in read mode shows REG1/REG2 fields. Warns on commands after display data in the same transaction, on a ICSET software reset combined with P2/P0, on ADSET addresses above `0x0E` (write) or other than `0x0F`/`0x10` (read) and on a Display-OFF within one frame of Display-ON (not detectable without timestamps — no timing pair; the `poweron_ready` check is measured from capture start).
