# Chip Spec: PCF2116

**Manufacturer:** Philips Semiconductors / NXP  
**Datasheet:** `datasheets/display/pcf2116.pdf` (PCF2116 family product specification, 7 April 1997 — covers the PCF2116x, PCF2114x and PCF2116K)  
**Category:** display  
**Transports:** I²C (the chip also has a 4/8-bit parallel interface, not covered)

## Overview

The PCF2116 family are single-chip **character LCD controller/drivers** with an HD44780-style 11-instruction set: 32 row and 60 column drivers for a 1 or 2-line display of up to 24 characters per line or 2/4 lines of 12 characters (5 × 8 dot format with cursor), an 80-character display RAM (DDRAM), a 240-character CGROM (character sets A, C or G, chosen by the type-number letter), a 16-character CGRAM, on-chip generation of the LCD supply voltage and bias levels, an on-chip oscillator (≈ 150 kHz) and a 2-wire I²C interface (≤ 100 kHz). Logic supply 2.5–6 V, LCD supply VDD − VLCD 3.5–9 V. The family is the **PCF2116x** (1 × 24 on MUX 1:16, or 2 × 24 on MUX 1:32, or 4 × 12), the **PCF2114x** (2 × 12 on MUX 1:16 or 2 × 24 on MUX 1:32) and the **PCF2116K** (different VLCD generation; character set C only). Other chips with this I²C control-byte style: the PCF8578/PCF8579 LCD drivers.

## Transport Configuration

### I²C
- **Address:** `0x3A` (SA0 = VSS) — `0x3B` (SA0 = VDD); 7-bit address `011101 SA0`
- **Max clock:** 100 kHz (standard mode); the datasheet gives no fast-mode limits
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`)
- **Probe safety:** `write_sensitive` — every byte after the address is a control byte followed by an instruction or display data; there is no register pointer
- **Protocol:** write = `[addr+W] [control byte] [byte] [control byte] [byte] …`. The **control byte** is `Co RS R/W 0 0 0 0 0` (bit 7 = Co, bit 6 = RS, bit 5 = R/W): `Co = 1` means exactly one data/instruction byte follows and then another control byte; `Co = 0` means all remaining bytes in the transaction use the same RS/R/W. RS = 0 selects the instruction register, RS = 1 the data register (DDRAM/CGRAM). The drivers use the plain `Connection` (`write`) with `Co = 0`: `0x00` + instruction bytes, `0x40` + data bytes
- **Read:** the chip supports read-back (busy flag + address counter, DDRAM/CGRAM data) with `R/W = 1` in the control byte; the drivers are write-only and wait the instruction times instead
- **Register addressing:** none — plain `Connection` (`write`), not `RegisterConnection`

## Pin Configuration

| Pin | Notes |
|-----|-------|
| SDA, SCL | I²C; external pull-ups (the ESD structure has no diode to VDD, partial VDD shutdown is possible) |
| SA0 | Address bit 0 (VSS or VDD) |
| VDD, VSS | Logic supply 2.5–6 V |
| VLCD, V0 | LCD supply: VLCD generated on-chip from the V0 control input (PCF2116x/2114x: VLCD = V0 with G = 0, VLCD = V0 − 0.8·VDD with G = 1; PCF2116K: VLCD = V0 − 1.34·VDD with G = 1, V0 between VSS and VDD − 0.5 V); V0 = VDD switches the generator off for an external VLCD |
| OSC | Oscillator: no components needed (internal ≈ 150 kHz); an external clock (90–225 kHz) can be applied and **must stay present**, otherwise the LCD freezes in a DC state |
| R1–R32, C1–C60 | Row and column driver outputs; unused outputs unconnected |
| DB0–DB7, RS, R/W, E | Parallel interface (unused in I²C mode) |

No interrupt or enable pins.

## Instruction Set

I²C instructions are sent with a control byte `0x00` (RS = 0). In I²C mode the `DL` bit is don't-care (8-bit assumed). Execution times assume the 150 kHz oscillator (3 cycles = 20 µs, 165 cycles = 1.1 ms); at the 90 kHz lower limit 3 cycles = 33 µs.

| Instruction | Code | Cycles | Description |
|-------------|------|--------|-------------|
| NOP | `0x00` | 0 | No operation |
| Clear display | `0x01` | 165 | Fill DDRAM with `0x20`, address 0, I/D = 1 (**wait 2 ms**) |
| Return home | `0x02` | 3 | Address 0, undo display shift; DDRAM unchanged |
| Entry mode set | `0x04 \| I/D<<1 \| S` | 3 | I/D: 1 = increment, 0 = decrement; S: 1 = display shift on write |
| Display control | `0x08 \| D<<2 \| C<<1 \| B` | 3 | D display, C cursor (underline in the 8th line), B blink (period 1 s at 150 kHz) |
| Cursor/display shift | `0x10 \| S/C<<3 \| R/L<<2` | 3 | S/C: 1 = display, 0 = cursor; R/L: 1 = right |
| Function set | `0x20 \| DL<<4 \| N<<3 \| M<<2 \| G<<1` | 3 | N, M: lines and MUX (below); G: voltage generator (below) |
| Set CGRAM address | `0x40 \| ACG` (6 bits) | 3 | Next data goes to CGRAM |
| Set DDRAM address | `0x80 \| ADD` (7 bits) | 3 | Next data goes to DDRAM |
| Read busy flag and address | RS = 0, R/W = 1 | 0 | BF in bit 7, address counter in bits 6:0 (read mode only) |
| Write data | RS = 1 | 3 | Write to DDRAM/CGRAM at the address counter |
| Read data | RS = 1, R/W = 1 | 3 | Read from DDRAM/CGRAM (read mode only) |

An instruction sent while the chip is busy is **not executed**; check BF or wait the required time.

### Function set: N, M, G

| N | M | PCF2116x | PCF2114x |
|---|---|----------|----------|
| 0 | 0 | 1 line × 24 characters, MUX 1:16 | 2 lines × 12 characters, MUX 1:16 |
| 1 | 0 | 2 lines × 24 characters, MUX 1:32 | 2 lines × 24 characters, MUX 1:32 |
| 1 | 1 | 4 lines × 12 characters, MUX 1:32 | 4 lines × 12 characters, MUX 1:32 |
| 0 | 1 | reserved | reserved |

`G = 0`: VLCD = V0 (generator off / external contrast voltage); `G = 1`: VLCD = V0 − 0.8·VDD (PCF2116K: V0 − 1.34·VDD).

## Display RAM

DDRAM holds 80 character codes. Visible line start addresses: 1-line mode `0x00` (range `0x00`–`0x4F`); 2-line mode line 1 `0x00`–`0x27`, line 2 `0x40`–`0x67`; 4-line mode lines 1–4 start at `0x00`, `0x20`, `0x40`, `0x60` (ranges `0x00`–`0x13`, `0x20`–`0x33`, `0x40`–`0x53`, `0x60`–`0x73`). **The end of one line and the start of the next are not consecutive**; writes wrap from `0x4F` to `0x00` (1-line), `0x27` to `0x40` and `0x67` to `0x00` (2-line), `0x13` to `0x20`, `0x33` to `0x40`, `0x53` to `0x60`, `0x73` to `0x00` (4-line). Display shift wraps each line independently.

Character codes `0x20`–`0x7F` follow the selected CGROM set (A, C or G) and `0xA0`–`0xFF` carry the kana/extension patterns; **CGRAM** provides 16 user characters at codes `0x00`–`0x0F`: each is 8 rows of 5 bits (the 8th row is ORed with the cursor); the CGRAM address is `char × 8 + row`, set with Set CGRAM address (bits 5:0, so characters 0–7 directly; characters 8–15 via the auto-increment from bit 6 or Set DDRAM address).

## Initialization Sequence

Internal reset after power-up: the chip initialises itself (display off, entry mode increment, function set 1-line, DDRAM address 0; the busy state lasts 2 ms).

1. Power-up; wait ≥ 2 ms after VDD rises above VPOR.
2. Function set `0x20 | N<<3 | M<<2 | G<<1` (e.g. `0x28` = 2 × 24, MUX 1:32, VLCD = V0; the DL bit is don't-care) — wait 40 µs.
3. Display control `0x0C` (display on, cursor off) — 40 µs.
4. Clear display `0x01` — **wait 2 ms**.
5. Entry mode set `0x06` (increment, no shift) — 40 µs.

Each instruction is sent as its own I²C transaction `[0x00] [instruction]` followed by the wait in the table above (the chip is busy while it executes an instruction and ignores anything sent meanwhile); instructions may be batched into one transaction (`[0x00] [i1] [i2] …`) only when the host can guarantee the per-instruction wait between the bytes.

If the supply does not meet the internal-reset conditions, initialise **by instruction** (datasheet Table 9): wait 2 ms after VDD > VPOR, send function set, wait 2 ms, function set, wait > 40 µs, function set, then continue with step 2's function set including N/M/G, display control, clear and entry mode.

## Implementation Stages

### Minimal

Goal: print text on a 2 × 24 display (PCF2116x, N = 1, M = 0) with the LCD voltage under external V0 control.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Runs the Initialization Sequence for 2 lines × 24, G = 0, display on, cursor off |
| `clear` | — | — | Clear display, 2 ms |
| `home` | — | — | Return home |
| `set_cursor` | `col: int`, `row: int` | — | DDRAM address = line start + col (line starts above); out-of-range ignored |
| `write` | `text: str` | — | Each character as a data byte (RS = 1); ASCII `0x20`–`0x7E` passes through, others become `?` (character sets A/C/G are ASCII-like in that range); data bytes are batched in one transaction `[0x40] [bytes…]` |
| `write_char` | `code: int` | — | One raw character code (0–255) |
| `print_at` | `col`, `row`, `text` | — | `set_cursor` + `write` |

**Sensible defaults:** 2 lines × 24, MUX 1:32, G = 0, display on, cursor off, blink off, increment, no shift.

## Data Conversion

```
control byte         = Co<<7 | RS<<6 | RW<<5                    # drivers: 0x00 (instruction), 0x40 (data)
function set         = 0x20 | DL<<4 | N<<3 | M<<2 | G<<1         # 2 x 24: 0x28 (DL ignored)
DDRAM address(col,row):
    1 line  : col                                              # 0x00 .. 0x4F
    2 lines : col + (0x00, 0x40)[row]                          # 0x00..0x27, 0x40..0x67
    4 lines : col + (0x00, 0x20, 0x40, 0x60)[row]              # 0x00..0x13 ... 0x60..0x73
set DDRAM address    = 0x80 | address
set CGRAM address    = 0x40 | (index * 8 + row)                 # 6 bits
f_frame              = f_osc / 2304                            # 65 Hz at 150 kHz
```

## Timing Constraints

- **Power-on:** wait ≥ 2 ms after VDD rises above VPOR before the first instruction (the busy state after the internal reset lasts 2 ms).
- **Instruction execution:** 3 oscillator cycles ≈ 20 µs at 150 kHz (33 µs at 90 kHz); the drivers wait 40 µs after each instruction. **Clear display** takes 165 cycles ≈ 1.1 ms (1.8 ms at 90 kHz): wait 2 ms. Return home counts 3 cycles in the table.
- **Busy flag:** BF = 1 during execution; an instruction sent meanwhile is ignored.
- **Oscillator:** 150 kHz typ. (90–225 kHz external clock range); frame frequency `f_osc / 2304`; blink period 1 s at 150 kHz (scales with 150 kHz / f_osc).
- **I²C:** fSCL ≤ 100 kHz (tSU;STA 4.7 µs, tSU;DAT 250 ns, tSU;STO 4 µs).
- **Conformance:** none of these has a bus-decodable start/end annotation pair (execution times end without a bus event), so `specs/display/pcf2116_timing.conf` defines no checks.

## Implementation Notes

- **Plain `Connection`, control bytes:** every transaction starts with a control byte; use `Co = 0` for streams of the same type. Instructions and data need different control bytes (RS), so text writes after an instruction need a new transaction.
- **Wait, don't read:** the drivers do not read the busy flag (write-only); delays: 40 µs per instruction, 2 ms for clear (and 2 ms at power-up). A host that can read may use `read_busy` instead.
- **Variants:** PCF2116x vs PCF2114x differ in the N/M meaning (table above); the **PCF2116K** needs a different V0/VLCD setup (G = 1 gives V0 − 1.34·VDD) and has only character set C. The CGROM letter (A, C, G) decides the glyphs above `0x7F`.
- **LCD supply:** contrast is set by the V0 input (resistor/trimmer), not by an instruction; VOP depends on the multiplex rate (datasheet Table 1) and must not exceed 9 V.
- **Oscillator:** if an external clock is used it must always run; stopping it leaves DC on the LCD and damages it.
- **Not consecutive lines:** in 2-/4-line modes the DDRAM address does not wrap into the next line (`0x27` → `0x40`), so write per line with `set_cursor`.
- **Address:** `0x3A`/`0x3B`; unrelated to the PCF8574-based LCD backpacks which use `0x20`–`0x27` / `0x38`–`0x3F`.
- **Datasheet:** NXP/Philips PCF2116 family (1997-04-07), from `https://www.nxp.com/docs/en/data-sheet/PCF2116_FAM.pdf`.

## Sigrok Decoder

Decoder id `pcf2116`, input `['i2c']`. Matches I²C addresses `0x3A`/`0x3B`. Splits each write into control byte (Co, RS, R/W) and following bytes; decodes instruction bytes by name with their bit fields (Clear, Home, Entry mode, Display control, Shift, Function set with N/M/G, Set CGRAM/DDRAM address) and data bytes as characters (printable ASCII) or raw codes; warns for non-zero low bits of the control byte, for instructions following too closely (clear display or power-on without the 2 ms gap is not detectable — no timing pair), for reads (R/W = 1) shown as busy flag + address or data. No timing annotation pair is emitted.
