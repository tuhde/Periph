# Chip Spec: SSD1312

**Manufacturer:** Solomon Systech  
**Datasheet:** `datasheets/display/ssd1312.pdf` (SSD1312 Rev 1.0, Jan 2019, "Advance Information", 53 pages: a 37-page datasheet plus a 19-page "Appendix III: Command Table and Command Descriptions"; copy hosted by Crystalfontz). No module datasheet is committed: the module mapping ("Waveshare 0.96inch Transparent OLED Display Module") comes from the issue's survey and is **unverified**  
**Category:** `display`  
**Transports:** I²C, SPI (4-wire, write-only) — identical to the SSD1306 (`specs/display/ssd1306.md`)

## Overview

The SSD1312 is a single-chip CMOS OLED/PLED driver with controller for monochrome dot-matrix panels of up to **128 × 64** pixels: 128 segments, 64 commons, 128 × 64 bits of display RAM (GDDRAM, 8 pages × 128 columns), an on-chip oscillator, an internal charge pump (VBAT 3.0–4.5 V → VCC 7.5 / 8.0 or 8.5 / 9.0 / 10.0 V), 255-step contrast, row/column remapping and programmable multiplexing (16–64). It is **largely command-compatible with the SSD1306** for what a basic driver needs, so — as the issue requests — **the driver is implemented as a thin alias of the existing SSD1306 driver in every language** (`Ssd1312Minimal` / `Ssd1312Full` and the SPI variants derive from the SSD1306 classes and re-export them under the SSD1312 name), **not** as a duplicate implementation. This spec documents the differences; everything not mentioned behaves as in `specs/display/ssd1306.md` and is **not** repeated (transport details, RAM byte layout, drawing). It is a sibling of the SSD1315 (`specs/display/ssd1315.md`) and SSD1309 (`specs/display/ssd1309.md`) aliases; its differences from the SSD1306 are **larger than theirs** in two places: the charge-pump command codes and the memory-addressing modes.

What differs from the SSD1306 (details below):
- **Charge pump codes differ:** `0x8D` takes `0x12` (7.5 V), `0x52`, `0x72` or `0x92` (10 V); `0x10` disables. **The SSD1306's `0x8D 0x14` is not a valid pattern on this chip.**
- **Memory addressing modes differ:** `0x20` takes `0x02` page (reset), `0x01` **COM-Page H-mode** (equivalent to the SSD1306's vertical mode), `0x09` **SEG-Page H-mode** (a transposed "portrait" layout). **There is no SSD1306-style horizontal mode** (`0x20 0x00` is invalid), so `show()` always uses page addressing.
- **No scroll commands are documented** in this revision's command table (`0x26`–`0x2F`, `0xA3`), although the feature list mentions scrolling: the scroll API is **not available** in the alias until a complete datasheet is obtained.
- **Internal IREF:** `0xAD` (`0x10` enable, `0x00` external) as on the SSD1315 (single value only).
- **Pre-charge counts in units of 2 DCLK** (as the SSD1315), **VCOMH uses bits 5:4** (as the SSD1315), **contrast `0x00` invalid**, **command lock `0xFD`**, and the power-up needs ≥ 20 ms after VDD before RES# (as the SSD1315).
- `0xDA` configures the **SEG** pins (odd/even, left/right swap) instead of the SSD1306's COM pins, with the same default byte `0x12`.
- Faster: SPI cycle ≥ 50 ns (**20 MHz**), fOSC 620–755 kHz (reset divide 1, oscillator `1000b`), segment current up to 480 µA (IREF 10 µA).

## Transport Configuration

Identical to the SSD1306 spec (I²C `0x3C`/`0x3D` with SA0 on the D/C# pad, 400 kHz, `write_sensitive`, `registry/chips.json` entry with `"id_probe": null`; 4-wire SPI Mode 0 through a `DisplayConnection` with `busy = None`, write-only). The datasheet's values for this chip:

- **I²C:** address `0111 10 SA0`; tcycle ≥ 2.5 µs, start hold/setup and stop setup ≥ 0.6 µs, data setup ≥ 100 ns, data hold ≥ 300 ns (SDAIN), tIDLE ≥ 1.3 µs. SDAIN and SDAOUT are tied together as SDA. No read access is described for I²C (the status read exists only on the parallel interface); the driver is write-only.
- **SPI (4-wire):** SCLK cycle ≥ 50 ns (clock low ≥ 15 ns, high ≥ 20 ns → **20 MHz** maximum; the drivers default to 4 MHz), D/C# and CS# set-up/hold 10 ns, data set-up/hold 10 ns (VDD 1.65–3.5 V). Mode 0 is the usual choice (the idle level is not named — confirm on hardware). "The serial interface mode is always in write mode." **Every command and command parameter byte is sent with D/C# low**, exactly as for the SSD1306.
- **Interface select pins:** BS[2:0] = `010` for I²C, `000` for 4-wire SPI. 3-wire SPI and the parallel interfaces are not covered.

Supply: VDD 1.65–3.5 V (≤ VBAT), VBAT 3.0–4.5 V (charge pump, ≤ 12 mA load), VCC 7.5–16.5 V (external or from the pump).

## Command Set

Only the SSD1312's differences from the SSD1306 command set are listed. The following have the SSD1306 meaning and reset values: `0x00`–`0x0F` (low column nibble), `0x40|line`, `0x81`, `0xA0`/`0xA1`, `0xA4`–`0xA8`, `0xAE`/`0xAF`, `0xB0|page`, `0xC0`/`0xC8`, `0xD3`, `0xD5` (reset `0x80`), `0xE3`. Reset values in parentheses.

| Command | Code | Description |
|---------|------|-------------|
| Set higher column nibble | `0x10`–`0x17` | Only three bits (columns 0–127); `0x18`–`0x1F` are not defined. Page addressing only |
| Set memory addressing mode | `0x20`, then `A3 . A1 A0` | `A[3]A[1:0]`: `0 10` page addressing (reset) = byte `0x02`; `0 01` **COM-Page H-mode** = `0x01`; `1 01` **SEG-Page H-mode** = `0x09`; anything else is invalid (including `0x00`, the SSD1306's horizontal mode) |
| Set line address | `0x21`, then A, B | COM-Page H-mode: **row** start/end 0–127 (reset 0 / 127) — equivalent to the SSD1306 column range in vertical mode; SEG-Page H-mode: **column** start/end 0–63 (reset 0 / 63). Not used in page addressing |
| Set page address | `0x22`, then A, B | COM-Page H-mode: page 0–7 (reset 0 / 7); SEG-Page H-mode: **SEG-page 0–15** (reset 0 / 15). Not used in page addressing |
| Set contrast | `0x81`, then `01`–`FF` | Valid range **01h–FFh**; reset `0x7F` |
| Internal IREF selection | `0xAD`, then `0 1 0 A4 0000` | `A[4] = 0` external IREF (reset), `1` internal IREF while the display is on. Data byte `0x40` / `0x50`. (The datasheet's bit pattern shows bit 6 set; the SSD1315 sends `0x00`/`0x10` — **verify on hardware**, see Implementation Notes) |
| Set pre-charge period | `0xD9`, then `A7:A4 phase2, A3:A0 phase1` | Each nibble counts **units of 2 DCLK** ("up to 30 DCLK, i.e. 2, 4, 6 … 30"); `0` invalid; reset `0x22` (the description also says "RESET equals to 2 DCLKs" — see Implementation Notes) |
| Set SEG pins hardware configuration | `0xDA`, then `00 A5 A4 0000` | `A[4]` = 0 sequential, **1 odd/even (reset)**; `A[5]` = 1 SEG left/right swap (reset 0). Reset byte `0x12`. (This is the SSD1306's `0xDA` "COM pins" command byte-for-byte; here it configures the SEG pads) |
| VCOMH deselect level | `0xDB`, then `00 A5 A4 0000` | `0x00` ≈ 0.65 × VCC, `0x10` ≈ 0.71, `0x20` ≈ 0.77 (reset), `0x30` ≈ 0.83 |
| Charge pump setting | `0x8D`, then `A[7:0]` | `0x10` disable (reset); `0x12` enable 7.5 V; `0x52` enable 8.0 V (the datasheet's section 6.10 says 8.5 V — conflict); `0x72` enable 9.0 V; `0x92` enable 10.0 V. Send before `0xAF` (sequence `8Dh`, `12h`/`52h`/`72h`/`92h`, `AFh`). **`0x14` (SSD1306) is not a valid pattern** |
| Set command lock | `0xFD`, then `00010 A2 10` | `0x12` unlock (reset), `0x16` lock: ignore every command and memory access except `0xFD 0x12` |

**Not present in this revision's command table:** `0x26`/`0x27`/`0x29`/`0x2A`/`0x2C`/`0x2D`/`0x2E`/`0x2F` (scrolling), `0xA3` (vertical scroll area), `0xD6` (zoom) and `0xDC` (GPIO) — **not sent by the driver**. The feature list claims "continuous scrolling in both horizontal and vertical direction" and "infinite content scrolling", so the commands may exist in the full datasheet; they are **unspecified here**.

### Power-on / reset defaults

Display off, 128 × 64 mode, **page addressing mode**, normal segment and scan mapping, start line 0, contrast `0x7F`, normal display, entire display follows RAM, charge pump **disabled**, multiplex 64, clock divide 1 / oscillator `1000b`, SEG pins odd/even, VCOMH `0x20`, pre-charge nibbles 2, external IREF, interface unlocked. The display RAM contents are **undefined** at power-up; clear it before the display is switched on.

## Display RAM

128 columns × 8 pages × 8 bits, **bit 0 = top row of the page**, as the SSD1306 (page addressing at reset). Two other modes exist and are exposed by `set_addressing_mode` (Full):

- **Page addressing (`0x20 0x02`, used by the driver):** set the page (`0xB0|p`), the column low/high nibble (`0x00|lo`, `0x10|hi`), then write; the column pointer auto-increments (no wrap documented — write one page at a time with ≤ 128 data bytes).
- **COM-Page H-mode (`0x20 0x01`):** pages as above; after each data byte the **page** pointer increments and wraps at the end page (`0x22`), then the **row (= column)** pointer (`0x21`, 0–127) advances; both wrap to their start values at the end. This is the SSD1306's *vertical* addressing.
- **SEG-Page H-mode (`0x20 0x09`):** "portrait" layout, a **transpose**: a page is a group of **8 SEG outputs on one COM line** (16 SEG-pages × 64 columns, each column along the COM direction), bit 0 = the lowest-numbered SEG of the page. After each byte the column pointer (`0x21`, 0–63) increments, then at its end the SEG-page (`0x22`, 0–15) advances; both wrap. The driver's framebuffer is **not** converted — the mode is exposed for use with `send_command` and raw data only; `show()` stays in page addressing (see Implementation Notes).

## Initialization Sequence

The SSD1306 sequence with these changes, per the datasheet's power-on flows (6.9.1 external VCC, 6.9.2 charge pump):

1. Apply VDD (then VBAT when the charge pump is used). **After VDD is stable wait ≥ 20 ms (t0)**, then pulse RES# low for ≥ 3 µs (`connection.reset()` with `reset_pulse_us ≥ 3`) and release it. Wait ≥ 3 µs after RES# low before the first command (or before powering an external VCC).
2. Setup command stream with the display off: `0xAE`, `0xD5 0x80`, `0xA8 height−1`, `0xD3 0x00`, `0x40`, **`0x8D 0x12`** (charge pump 7.5 V; `0x8D 0x10` for external VCC), `0x20 0x02`, `0xA0|ADC`, `0xC0|(scan<<3)`, `0xDA 0x12`, `0x81 0x7F`, `0xD9 0x22`, `0xDB 0x20`, `0xA4`, `0xA6`. When `internal_iref` is requested add `0xAD` with the internal-IREF byte before `0xAF`.
3. Clear the RAM (8 pages × 128 bytes of `0x00`).
4. `0xAF`; SEG/COM are on after tAF = 100 ms — wait 100 ms.

Power-off with the pump: `0xAE`, **`0x8D 0x10`**, wait tOFF (typ. 100 ms), VBAT off, then VDD off after tOFF2 (typ. 5 ms, min 0). With external VCC: `0xAE`, VCC off, VDD off after tOFF (typ. 100 ms). VDD must never be removed before VCC/VBAT; VCC/VBAT are floated, never grounded.

## Implementation Stages

### Minimal

`Ssd1312Minimal` (I²C) and `Ssd1312SpiMinimal` (SPI) are the SSD1306 Minimal classes under the SSD1312 name with these changes to `init`:

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | as `Ssd1306Minimal.init` (`connection`, `width = 128`, `height = 64`, `external_vcc = False`), plus `internal_iref: bool = False` | — | Runs the Initialization Sequence above: ≥ 20 ms wait before the reset, `0x8D 0x12` (not `0x14`), `0xD9 0x22` (2-DCLK units), `0xDB 0x20`, `0xAD` when `internal_iref` is true. `external_vcc = True` sends `0x8D 0x10` |
| `clear`, `set_pixel`, `show` | as SSD1306 | — | Unchanged (`show()` in page addressing) |

**Sensible defaults:** 128 × 64, charge pump 7.5 V, page addressing, contrast `0x7F`, normal orientation, clock `0x80`, VCOMH `0x20`, normal display, external IREF.

### Full

`Ssd1312Full` / `Ssd1312SpiFull` derive from the SSD1306 Full classes. **Inherited unchanged:** `get_pixel`, `fill`, `draw_line`, `draw_rect`, `blit`, `show_page`, `set_display`, `sleep`, `wake`, `set_invert`, `set_all_on`, `set_flip`, `set_start_line`, `set_display_offset`, `set_multiplex`, `set_clock`, `send_command`.

**Overridden:**

| Operation | Parameters | Notes |
|-----------|------------|-------|
| `set_contrast` | `value: int` (1–255) | `0x81`, value; `0` is rejected (or clamped to 1) |
| `set_precharge` | `phase1: int` (2–30), `phase2: int` (2–30) | **DCLK counts**; code per nibble `ceil(dclk / 2)` (1–15), `0xD9`, `(code2 << 4) \| code1`; odd values round up; reset `4, 4` |
| `set_vcomh` | `value: int` (0–255, bits 5:4 used) | `0xDB`, `value & 0x30` |
| `set_charge_pump` | `enabled: bool`, `voltage: float = 7.5` (7.5, 8.0, 9.0 or 10.0) | `0x8D`, `0x10` (disabled) or `0x12` / `0x52` / `0x72` / `0x92`; send before `set_display(True)`. Needs VBAT 3.0–4.5 V; the higher modes have less load capability (documented, not checked) |
| `set_com_config` | `alternative: bool = True`, `swap: bool = False` | `0xDA`, `(alternative << 4) \| (swap << 5)`; configures the **SEG** pins on this chip (name kept for API compatibility) |
| `set_addressing_mode` | `mode: str` (`"page"`, `"vertical"`, `"seg_page"`) | `0x20`, `0x02` / `0x01` / `0x09`. **`"horizontal"` raises** (not defined on this chip). `"vertical"` is COM-Page H-mode; after it `show()` uses the vertical procedure of the SSD1306 spec with `0x21 0, width−1` and `0x22 0, pages−1`. `"seg_page"` is for raw data only: `show()` and the drawing helpers are **not** valid in it and `show()` raises until `set_addressing_mode("page")` |
| `set_scroll_horizontal`, `set_scroll_vertical`, `set_scroll_area`, `scroll_start`, `scroll_stop` | as SSD1306 | **Not supported:** raise (`NotSupported`) — the commands are not documented in this revision (see Command Set) |

**New:**

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `set_internal_iref` | `enabled: bool` | — | `0xAD`, internal-IREF byte (`0x50` / `0x40`, see Implementation Notes); send with the display off. ISEG = contrast / 255 × 48 × IREF (480 µA at IREF 10 µA, full contrast) |
| `set_command_lock` | `lock: bool` | — | `0xFD`, `0x16` / `0x12`; while locked the chip ignores everything but `0xFD 0x12` |

**Additional configuration options:** everything of the SSD1306 minus scrolling, plus charge-pump voltages, internal IREF, SEG pin swap, COM-Page and SEG-Page addressing and command lock.

## Data Conversion

As the SSD1306 (`page = y // 8`, `bit = y % 8`, bit 0 = top; page-mode `show()`). Differences:

```
charge pump byte  = 0x10 (off) | 0x12 (7.5 V) | 0x52 (8.0 V) | 0x72 (9.0 V) | 0x92 (10.0 V)   (SSD1306: 0x10 / 0x14)
addressing byte   = 0x02 (page) | 0x01 (COM-Page H) | 0x09 (SEG-Page H)                       (SSD1306: 0x02 / 0x00 / 0x01)
pre-charge code   = ceil(dclk / 2)   (1..15), nibble phase2 << 4 | phase1
SEG pin byte (DA) = (alternative << 4) | (swap << 5)
Segment current   = contrast / 255 * 48 * IREF     (IREF = 10 uA -> 480 uA at 0xFF; the IREF resistor R = (VCC - 2 V) / IREF, e.g. 1 MOhm at VCC = 12 V)
Frame rate        = fOSC / (D * K * MUX)           D = divide ratio, K = display clocks per row, MUX = multiplex ratio; fOSC 620..755 kHz (688 typ) at reset
SEG-Page position = SEG-page = seg // 8, bit = seg % 8, column = com   (SEG-Page H-mode, data byte = 8 SEGs of one COM line)
```

## Timing Constraints

- **Reset:** wait **≥ 20 ms after VDD is stable before the reset pulse** (t0); RES# low ≥ 3 µs (t1); wait ≥ 3 µs after RES# low before commands or an external VCC (t2); registers are reset after the pulse.
- **Power sequence (charge pump):** VDD, VBAT (tON min 0), ≥ 20 ms, RES# pulse, `0x8D` + `0xAF`; SEG/COM on after tAF = 100 ms. Power-off: `0xAE`, `0x8D 0x10`, VBAT off after tOFF (typ. 100 ms), VDD off after tOFF2 (typ. 5 ms, min 0). External VCC: `0xAE`, VCC off, VDD off after tOFF (typ. 100 ms). VDD must not be removed before VCC/VBAT. These are recommended waits.
- **I²C / SPI:** see Transport Configuration (SPI ≥ 50 ns cycle, I²C ≤ 400 kHz).
- **Conformance:** none of these has a bus-decodable start/end annotation pair that the host controls (the delays are recommended waits after commands, not measured events), so `specs/display/ssd1312_timing.conf` defines no checks.

## Implementation Notes

- **Alias design:** in every language `Ssd1312*` classes subclass the SSD1306 classes (Python: `Ssd1312Minimal(Ssd1306Minimal)` etc. in `ssd1312.py`; C++: header-only subclasses/templates in `SSD1312.h`; Node.js: `class Ssd1312 extends Ssd1306`; Rust: wrapper type delegating to the SSD1306 driver with overridden command methods; JVM: Java/Kotlin/Groovy subclasses; Go: embedded struct). The SSD1306 classes must make the **initialization sequence and the byte-level command builders overridable** (charge-pump byte, pre-charge, VCOMH mask, addressing-mode byte table, IREF step, scroll methods) so the SSD1312 overrides replace them without copying the framebuffer or transport code. This work is **shared with the SSD1315 and SSD1309 aliases** — implement the overridable init once. The SSD1312 examples and tests use the SSD1312 names; the SSD1306 ones are untouched.
- **SSD1306 code on an SSD1312:** `0x8D 0x14` is not a defined pattern on the SSD1312 (the datasheet: "patterns other than those given in the command table are prohibited … unexpected results can occur"), so a plain SSD1306 driver may leave the pump off or misbehave; `0x20 0x00` (horizontal) is invalid; the scroll commands are undocumented; a pre-charge value is twice as long as intended. That is why the alias overrides these rather than re-exporting the SSD1306 classes.
- **Charge-pump byte inconsistencies (datasheet):** the bit pattern is `A7 A6 A5 1 0 0 A1 0` (so the enable bit is D1 — `0x12`, `0x52`, `0x72`, `0x92` all have D1 = 1, `0x10` has D1 = 0), while the note says "A[2] = 1b enable" and the voltage table lists 8.0 V against section 6.10's "8.5 V". The codes in the table are used; the 8.0/8.5 V label is **unverified**. The power-off text says "8Dh 10h" — the same value as the SSD1306.
- **IREF byte:** the command table shows `0xAD`, then `0 1 0 A4 0 0 0 0` (bits 7:5 = `010`), i.e. `0x40` external / `0x50` internal; the SSD1315 datasheet shows `0 0 A5 A4 0000`. The driver uses **`0x50` / `0x40`** following the SSD1312 table; this is **unverified on hardware**, and the datasheet text (6.8) notes the IREF pad must be left NC when the internal IREF is used. Which modules need the internal IREF is unknown; the default is external, as on the SSD1306.
- **Pre-charge units:** the table says "up to 30 DCLK (i.e. 2, 4, 6 … 30)" for 4-bit values, while the description says "RESET equals to 2 DCLKs" (reset code 2): as for the SSD1315, the 2-DCLK-per-code reading is used consistently — **unverified on hardware**.
- **Page-mode column pointer:** `0x10`–`0x17` only; with 128 columns the high nibble never needs `0x18+`.
- **`0xDA` and orientation:** besides `0xA0/0xA1` and `0xC0/0xC8`, `0xDA` A[5] swaps the left and right SEG halves (the datasheet's eight cases, Table 2-3). Which combination a transparent panel needs is module-specific and **unverified**; `set_flip` and `set_com_config` expose the controls. For a 128 × 32 module `0xDA 0x02` as on the SSD1306 is **not documented** here.
- **Scrolling:** not specified in this revision (see Command Set). If a complete datasheet is obtained, add `set_scroll_*` overrides and drop the `NotSupported` stubs.
- **SEG-Page / portrait mode:** exposed for raw writes only; a portrait-oriented framebuffer would need a transposing `show()`, which is outside this alias.
- **Not covered:** FR (RAM-write synchronisation) pin, dynamic grayscale, parallel (6800/8080) and 3-wire SPI interfaces, the external-clock mode, the status read.
- **No read access:** serial mode is write-only; the status read exists only on the parallel interface.
- **Advance Information datasheet:** Rev 1.0 (Jan 2019); the section-9 timing values and the appendix both say "Advance Information"; the datasheet itself says an official copy is available from Solomon Systech.
- **Datasheet:** SSD1312 Rev 1.0, January 2019 (`https://cdn.shopify.com/s/files/1/0264/7629/files/SSD1312.pdf`, 53 pages).

## Sigrok Decoder

The SSD1306 decoders (`ssd1306`, `ssd1306_spi`) are **extended, not duplicated**: new decoder ids `ssd1312` (input `['i2c']`, addresses `0x3C`/`0x3D`) and `ssd1312_spi` (input `['spi']`) reuse the SSD1306 command table and apply the SSD1312 differences: `0x8D` argument decoded as pump mode (off / 7.5 / 8.0 / 9.0 / 10.0 V) with `0x14` flagged invalid, `0x20` decoded as page / COM-Page H / SEG-Page H with `0x00` flagged invalid, `0x21`/`0x22` ranges interpreted per mode, `0xAD`, `0xD9` in units of 2 DCLK, `0xDA` as SEG pin configuration, `0xDB` limited to bits 5:4, `0xFD` lock, `0x81 0x00` flagged invalid. Warnings: a command byte not in the table (including the scroll commands `0x26`–`0x2F`, `0xA3`, `0xD6`, `0xDC`), a data write in SEG-Page H-mode outside the 16 × 64 window, and any command after `0xFD 0x16` other than `0xFD`. No timing annotation pair is emitted.
