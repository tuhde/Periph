# Chip Spec: PCF8578

**Manufacturer:** NXP Semiconductors  
**Datasheet:** `datasheets/display/pcf8578.pdf` (Rev. 06, 5 May 2009 — the NXP URL in the issue now returns 404; the committed copy is the same NXP document from a mirror, `http://images.100y.com.tw/pdf_file/35-PCF8578H.pdf`)  
**Category:** `display`  
**Transports:** I²C

## Overview

The PCF8578 is a low-power CMOS LCD **row and column driver** for dot-matrix graphic displays, with 40 outputs: R0–R7 are fixed row drivers, C32–C39 fixed column drivers, and the 24 outputs R8/C8–R31/C31 are programmable (in blocks of 8) as rows or columns. It drives multiplex rates of 1:8, 1:16, 1:24 or 1:32, giving stand-alone configurations of 8 rows × 32 columns, 16 × 24, 24 × 16 or 32 × 8 dots. A 32 × 40-bit display RAM (four banks of 40 bytes) stores the pixels, with auto-incrementing addressing in three access modes (character, half-graphic, full-graphic) and bank switching for scrolling. It is controlled by five commands over I²C, has an on-chip oscillator (one external resistor) and can be cascaded as the row driver for up to 32 PCF8579 column drivers (up to 40 960 dots).

This spec covers the **stand-alone** use (mixed mode: the PCF8578 drives both rows and columns, the only mode in which its RAM can be accessed) plus row mode as a configuration option for a PCF8579 system. The PCF8579 itself is a different chip and is not covered; the driver only exposes the `device-select` command needed to address one. External bias generation (resistor divider V2–V5), the LCD supply VLCD and the oscillator resistor are board-level and outside the driver.

## Transport Configuration

### I²C
- **Address:** `0x3C` (SA0 = VSS) — `0x3D` (SA0 = VDD); 7-bit address `0111 10 0 SA0`. The same two addresses are used by the PCF8579
- **Max clock:** 100 kHz (standard mode only) — the connection must not be configured faster
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`)
- **Probe safety:** `write_sensitive` — every byte written after the address is a command or display data; there is no register pointer
- **Protocol:** no register addresses. A write transaction is `[addr+W] [command, command, …, last command (C = 0)] [display data…]`; a read transaction is `[addr+R] [data…]` (optionally after commands: `[addr+W] [commands] [Sr addr+R] [data…]`). Drivers use the plain `Connection` (`write`, `write_read`), not `RegisterConnection`

## Pin Configuration

| Pin | Active | Notes |
|-----|--------|-------|
| SDA, SCL | — | I²C; external pull-ups |
| SA0 | — | Address bit 0 (VSS / VDD) |

| TEST | — | Must be tied to VSS |

## Command Set

The PCF8578 has no register map. Commands are single bytes whose MSB is the **continuation bit C**: `C = 1` means another command byte follows, `C = 0` marks the last command — every byte after it is display data. The last command in a transaction therefore always has `C = 0`.

| Command | Bits 7…0 | Operation |
|---------|----------|-----------|
| set-mode | `C 1 0 T E1 E0 M1 M0` | Display mode, display status, multiplex rate |
| set-start-bank | `C 1 1 1 1 1 B1 B0` | RAM bank shown at the top of the display |
| device-select | `C 1 1 0 A3 A2 A1 A0` | Hardware subaddress counter (0–15) |
| RAM-access | `C 1 1 1 G1 G0 Y1 Y0` | RAM access mode and RAM bank (Y) |
| load-X-address | `C 0 X5 X4 X3 X2 X1 X0` | RAM column address (0–39) |

### set-mode fields

| Bits | Name | Values |
|------|------|--------|
| 4 | T | `0` row mode, `1` mixed mode |
| 3:2 | E[1:0] | `00` blank, `01` normal, `10` all segments on, `11` inverse video |
| 1:0 | M[1:0] | `01` 1:8 (8 rows), `10` 1:16 (16 rows), `11` 1:24 (24 rows), `00` 1:32 (32 rows) |

### set-start-bank

`B[1:0]` selects bank 0–3 as the top of the display (see Display RAM). Useful for scrolling, pseudo-motion and preparing new content in the background.

### device-select

`A[3:0]` loads the subaddress counter. Data is stored only when the counter matches the device's hardware subaddress; the **PCF8578's own subaddress is fixed at `0000`** (mixed mode only), and PCF8579s used with it must use subaddresses starting at `0001`. The counter increments automatically between devices and wraps from 15 to 0 on overflow.

### RAM-access fields

| Bits | Name | Values |
|------|------|--------|
| 3:2 | G[1:0] | `00` character, `01` half-graphic, `10` full-graphic, `11` not allowed |
| 1:0 | Y[1:0] | RAM bank (row address) 0–3 where the first byte goes |

### load-X-address

`X[5:0]` = column 0–39 where the first byte goes.

### Power-on reset defaults

| Setting | Default |
|---------|---------|
| Display | blank |
| Mode / multiplex | row mode, 1:32 |
| Start bank | 0 |
| Data pointer | X = 0, Y = 0 |
| RAM access | character mode |
| Subaddress counter | 0 |
| Display RAM | undefined (the datasheet does not state a reset value) — clear it before enabling the display |

## Display RAM

32 × 40 bits: four banks (Y = 0…3) of 40 bytes (X = 0…39). One byte holds 8 vertical pixels of one column: **bank Y covers display rows 8Y … 8Y+7**, and bit 0 is the top row of the bank (Figure 17: LSB at the top of the byte column; confirm orientation on hardware). The X address corresponds directly to the **column output number** (X = n ↔ Cn). RAM columns 0–7 cannot be displayed (they exist for PCF8579 compatibility and may be used as scratch storage).

Displayed area for a multiplex rate of 1:n in mixed mode (rows R0 … R(n−1), columns the remaining outputs up to C39):

| Rate | Rows | Columns | RAM banks used | RAM X range displayed |
|------|------|---------|----------------|-----------------------|
| 1:8 | 8 | 32 | 0 | 8–39 |
| 1:16 | 16 | 24 | 0–1 | 16–39 |
| 1:24 | 24 | 16 | 0–2 | 24–39 |
| 1:32 | 32 | 8 | 0–3 | 32–39 |

Display column `c` (0-based, left to right) ↔ RAM `X = 40 − columns + c`; display row `r` ↔ bank `r / 8`, bit `r % 8`.

### RAM access modes

After the first byte is placed at (X, Y), the pointers auto-increment per byte:

| Mode | Order of successive bytes |
|------|---------------------------|
| character (`00`) | (X, Y), (X+1, Y), (X+2, Y), … — one bank, consecutive columns |
| half-graphic (`01`) | (X, Y), (X, Y+1), (X+1, Y), (X+1, Y+1), … — two banks per column |
| full-graphic (`10`) | (X, Y), (X, Y+1), (X, Y+2), (X, Y+3), (X+1, Y), … — four banks per column |

At the end of a row the subaddress counter advances to the next device (wrapping 15 → 0); with a lone PCF8578 (subaddress 0) a transfer that runs past X = 39 wraps into the next device address and is **not stored** — the driver must not write past column 39 in one transaction. Y wraps within the access mode's bank group (half: pairs, full: all four — start half-graphic at an even bank, full-graphic at bank 0; behavior for other starts is not specified).

## Initialization Sequence

1. Wait ≥ 1 ms after power-on for the internal reset (no I²C traffic before that).
2. One write transaction that clears the whole RAM using full-graphic access: `device-select 0` (`0xE0`, C = 1), `set-mode` mixed / **blank** / chosen multiplex rate (C = 1), `set-start-bank 0` (`0xFC`, C = 1), `RAM-access` full-graphic bank 0 (`0x78`, C = 1), `load-X 0` (`0x00`, C = 0), then **160 zero bytes** (40 columns × 4 banks, in full-graphic order).
3. Second write: `set-mode` mixed / **normal** / chosen multiplex rate (C = 0) to switch the display on once the RAM is clear.

Example bytes for 1:16: step 2 = `E0 D2 FC F8 00` + 160 × `00`; step 3 = `56`. (`set-mode` byte = `C << 7 | 0x40 | T << 4 | E << 2 | M`; `RAM-access` full-graphic bank 0 with C = 1 = `0x80 | 0x70 | 0x08` = `0xF8`; `set-start-bank 0` with C = 1 = `0x80 | 0x7C` = `0xFC`.)

## Implementation Stages

### Minimal

Goal: drive a stand-alone dot-matrix LCD out of the box — clear it and light pixels. No configuration beyond the connection (and the panel's row count).

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection, `rows: int = 16` (8, 16, 24 or 32) | — | Waits ≥ 1 ms, runs the Initialization Sequence in mixed mode at 1:`rows`, clears RAM, switches the display on (normal); stores a shadow copy of the displayed RAM |
| `clear` | — | — | Zero the whole RAM (all 4 banks × 40 columns) and the shadow |
| `set_pixel` | `x: int`, `y: int`, `on: bool = True` | — | Display column `x` (0 … columns−1), row `y` (0 … rows−1); updates the shadow byte and writes that single byte (`load-X`, `RAM-access` character, data); out-of-range coordinates are ignored |
| `write_columns` | `x: int`, `bank: int`, `data: bytes` | — | Write consecutive column bytes in character mode starting at display column `x` of display bank `bank` (0 … rows/8−1); bit 0 = top row of the bank; the write is truncated at the last column; updates the shadow |

**Sensible defaults:** mixed mode, 1:16 (16 rows × 24 columns), normal display, start bank 0, subaddress 0, character access mode, RAM cleared. `columns = 40 − rows`.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `get_pixel` | `x: int`, `y: int` | `bool` | From the shadow (no bus traffic) |
| `fill` | `on: bool = True` | — | Set every displayed pixel on or off |
| `draw_line` | `x0, y0, x1, y1: int`, `on: bool = True` | — | Bresenham line using `set_pixel` semantics, written as one batch of changed bytes |
| `draw_rect` | `x, y, w, h: int`, `on: bool = True`, `fill: bool = False` | — | Rectangle outline or filled |
| `show_bitmap` | `x: int`, `y: int`, `rows: list[bytes]` or column bytes | — | Blit a column-major bitmap (8-pixel-high columns) at `y` aligned to a bank boundary (`y % 8 == 0`); other `y` rejected |
| `set_display` | `status: int` (`DISPLAY_BLANK`=0, `DISPLAY_NORMAL`=1, `DISPLAY_ALL_ON`=2, `DISPLAY_INVERSE`=3) | — | `set-mode` E field; RAM is preserved |
| `set_mode` | `rows: int`, `mixed: bool = True` | — | Change multiplex rate / row mode; in row mode (`mixed = False`) the RAM can no longer be accessed (the driver raises on pixel/RAM calls until mixed mode is restored) |
| `set_start_bank` | `bank: int` (0–3) | — | Hardware vertical scroll by 8-row steps |
| `scroll` | `banks: int` | — | Add `banks` (may be negative) to the start bank modulo the number of banks in use |
| `write_ram` | `x: int`, `bank: int`, `data: bytes`, `mode: int = ACCESS_CHARACTER` | — | Raw RAM write in character (`0`), half-graphic (`1`) or full-graphic (`2`) order at **RAM** column `x` (0–39) and bank (0–3); updates the shadow; rejects writes that would pass column 39 |
| `read_ram` | `x: int`, `bank: int`, `n: int`, `mode: int = ACCESS_CHARACTER` | `bytes` | Raw RAM read: commands `device-select`, `RAM-access`, `load-X`, then a repeated-start read of `n` bytes |
| `device_select` | `subaddress: int` (0–15) | — | Load the subaddress counter (for cascaded PCF8579 systems; subaddress 0 addresses the PCF8578 itself). Pixel/RAM calls restore subaddress 0 first |
| `reset` | — | — | Re-run init (clears RAM) at the current rows |

**Additional configuration options:** multiplex rate / row count, display status (blank / normal / all-on / inverse), start bank (vertical scroll), RAM access mode, row mode, device subaddress.

## Data Conversion

```
columns        = 40 - rows
RAM X          = rows + x                    (= 40 - columns + x; first displayed RAM column is X = rows)
bank, bit      = y // 8 , y % 8
byte(X, bank)  = shadow[bank][X];  pixel set:  byte |= 1 << bit ; cleared: byte &= ~(1 << bit)
set-mode byte  = (C << 7) | 0x40 | (T << 4) | (E << 2) | M       M: 8->01, 16->10, 24->11, 32->00
RAM-access     = (C << 7) | 0x70 | (G << 2) | Y      (G: character 0, half 1, full 2)
load-X         = (C << 7) | X
device-select  = (C << 7) | 0x60 | A
set-start-bank = (C << 7) | 0x7C | B
```

An inject node every 500 ms drives a function node that computes a bouncing-pixel position and sends `{ pixel: { x, y, on } }` (clearing the previous position first) into `periph-pcf8578` (16 rows); a second inject toggles `{ display: "inverse" }` / `"normal"` to show inverse video.

## Examples

### Demo

Scrolling banner on a 16 × 24 (1:16) panel using the Full driver: draw a one-pixel border with `draw_rect`, draw both diagonals with `draw_line`, then flash the display with `set_display(DISPLAY_INVERSE)` / `DISPLAY_NORMAL` twice. Next write a different 8-row pattern into each of the four RAM banks (even though only banks 0–1 are visible at 1:16, the other banks act as off-screen buffers) and step `set_start_bank` through all four banks once per second to demonstrate hardware scrolling, printing the bank and the first visible column byte each step. Finish by reading back the first 8 RAM columns of bank 0 with `read_ram` and printing them.

## Timing Constraints

- Wait ≥ 1 ms after power-on before the first I²C transaction (internal reset). **Conformance-checked** as `poweron_ready` (min 1 ms), measured from capture start to the first decoded bus transaction, the same no-power-sense pattern as the PCF8576 — see `specs/display/pcf8578_timing.conf`.
- I²C: fSCL ≤ 100 kHz, tBUF ≥ 4.7 µs, tLOW ≥ 4.7 µs, tHIGH ≥ 4.0 µs, tSU;DAT ≥ 250 ns (datasheet Table 18).
- Clock: internal oscillator with Rext = 330 kΩ gives fclk = 1.2–3.3 kHz (typ. 2.1) → frame ≈ 64 Hz; at 1:24 fclk is 0.9–2.5 kHz. A clock must always be present.
- Driver propagation delay ≤ 100 µs at VDD − VLCD = 9 V — a panel property, no driver wait.
- A transaction aborted mid-stream leaves the data pointer undefined: always begin each write with a fresh `load-X` and `RAM-access`.
- Apply and remove VDD and VLCD together to avoid DC build-up across the panel.

## Implementation Notes

- **Plain `Connection`, command stream:** the chip has no register addressing, so the driver uses `connection.write(bytes)` and `connection.write_read(commands, n)` only (as the PCF8576 does), never `RegisterConnection`. Every write transaction ends its command bytes with a `C = 0` byte followed by data; a transaction of only commands must also end with `C = 0`.
- **Mixed mode only for RAM:** the RAM may only be accessed in mixed mode and the PCF8578's subaddress is only defined there; in row mode the chip acts as a pure row driver for PCF8579s and ignores display data. The POR default is row mode — `init` must switch to mixed mode.
- **Subaddress 0:** data is stored only when the subaddress counter equals the device's hardware subaddress (`0000`). POR sets the counter to 0; transfers that run past X = 39 advance the counter to subaddress 1 where nothing listens — data lost. Cascaded PCF8579 support is out of scope; `device_select` exists only as a primitive, and the driver always restores subaddress 0 before its own accesses.
- **Shadow buffer:** keep a shadow of the 4 × 40 RAM bytes so `set_pixel` is a single-byte write without read-modify-write bus traffic. The shadow is only valid after `init` has cleared the RAM (the RAM contents are undefined at power-up).
- **Read mode:** RAM reads work only in mixed mode; the first data byte after the address-set commands is the byte at the data pointer, then pointers auto-increment as for writes. The master NACKs the last byte. `write_read` implies a repeated START between the command string and the read (Fig 15b).
- **Orientation unverified:** the byte-to-row mapping (bit 0 = top row of the bank, bank 0 at the top at start bank 0) and column ordering (X increasing left to right = C-number increasing) follow Figures 17/20 and the pin naming; verify on a physical panel and note if the glass is wired mirrored.
- **Contrast/bias is hardware:** bias voltages V2–V5 come from an external divider (Table 5/6 of the datasheet); there is no software contrast control.
- **100 kHz limit:** connections created at the default 400 kHz must be reconfigured to ≤ 100 kHz for this chip.
- **PCF8576 relation:** same family of NXP LCD drivers and same command-continuation-bit protocol, but the PCF8576 is a segment driver with different commands and RAM geometry; no code is shared.
- **Datasheet:** NXP PCF8578 Rev. 06 (5 May 2009). The URL given in the issue (`https://www.nxp.com/docs/en/data-sheet/PCF8578.pdf`) no longer resolves; the committed PDF is the same revision from a mirror.

## Sigrok Decoder

Decoder id `pcf8578`, input `['i2c']`. Matches I²C addresses `0x3C` and `0x3D`. Parses the command stream of every write: each command byte is annotated by name with decoded fields (set-mode → mode, status, rows; set-start-bank → bank; device-select → subaddress; RAM-access → access mode and bank; load-X → column), tracking the continuation bit so that bytes after a `C = 0` command are shown as display data; data bytes are annotated with their RAM position (X, bank, subaddress) following the current access mode's auto-increment, and as an 8-pixel column bitmap string. Reads are annotated as RAM data from the tracked pointer. Warnings: a write that passes X = 39 (data lost), a RAM-access with G = `11`, a transaction whose commands never clear `C`, data while in row mode, and I²C frames at SCL > 100 kHz are not detectable and are not checked. For the power-on conformance check the first bus transaction after capture start is annotated `poweron_ready` (marker `poweron_start` at capture start), in the `timing` annotation row shaped per `specs/sigrok_annotations.md`'s Variable-Length Annotation Convention; the gap must be ≥ 1 ms (see `specs/display/pcf8578_timing.conf`).
