# Chip Spec: SSD1309

**Manufacturer:** Solomon Systech  
**Datasheet:** `datasheets/display/ssd1309.pdf` (SSD1309 Rev 1.1, Jul 2011, 63 pages; the copy hosted by Crystalfontz, from `https://docs.rs/crate/ssd1309/0.2.1/source/doc/SSD1309_v1.1.pdf`). No module datasheet is committed: the module mapping ("Waveshare 1.54inch and 2.42inch OLED modules") comes from the issue's survey and is **unverified**  
**Category:** `display`  
**Transports:** I²C, SPI (4-wire, write-only) — identical to the SSD1306 (`specs/display/ssd1306.md`)

## Overview

The SSD1309 is a single-chip CMOS OLED/PLED driver with controller for monochrome dot-matrix panels of up to **128 × 64** pixels: 128 segments, 64 commons, 128 × 64 bits of display RAM (GDDRAM, 8 pages × 128 columns), an on-chip oscillator, 256-step contrast, row/column remapping, hardware scrolling (including "infinite content scrolling") and programmable multiplexing (16–64). Unlike the SSD1306 it has **no internal charge pump: the panel supply VCC (7–16 V) must be supplied externally** (the module's boost circuit). It is **command-compatible with the SSD1306** for everything a basic driver needs, so — as the issue requests — **the driver is implemented as a thin alias of the existing SSD1306 driver in every language** (`Ssd1309Minimal` / `Ssd1309Full` and the SPI variants derive from the SSD1306 classes and re-export them under the SSD1309 name), **not** as a duplicate implementation. This spec documents what differs; everything not mentioned behaves exactly as in `specs/display/ssd1306.md` and is **not** repeated (transport details, RAM layout, addressing modes, framebuffer drawing). It is the sibling of the SSD1315 (`specs/display/ssd1315.md`, the same alias design) and, in the external-VCC aspect, of the SSD1305.

What differs from the SSD1306 (details below):
- **No charge pump — external VCC only.** `0x8D` does not exist; the driver must **never send it**, and `external_vcc` is always true.
- **Scroll setup commands have different byte layouts and interval codes:** `0x26`/`0x27` take seven parameter bytes (a dummy and **start / end column**, the SSD1306's trailing `0x00`, `0xFF` pair is wrong), `0x29`/`0x2A` take seven parameters (**column-offset flag, vertical offset, start / end column**), and the step-interval table differs (`000` 5 frames, `001` 64, `010` 128, `011` 256, `100` 2, `101` 3, `110` 4, `111` 1 frame).
- **New commands:** content scroll (`0x2C`/`0x2D`, one column per command), **set GPIO (`0xDC`)** and **set command lock (`0xFD`)**.
- **VCOMH (`0xDB`) is a 4-bit value** (`A[5:2]`, `0x00` ≈ 0.64 × VCC … `0x34` ≈ 0.78 × VCC (reset) … `0x3C` ≈ 0.84 × VCC); the oscillator reset value is `0x70` (SSD1306: `0x80`); K (display clocks per row) is 69, giving ≈ 100 Hz at 64 MUX with the typical 450 kHz oscillator.
- VDD is 1.65–3.3 V, segment current up to 320 µA (IREF 10 µA).

## Transport Configuration

Identical to the SSD1306 spec (I²C `0x3C`/`0x3D` with SA0 on the D/C# pad, 400 kHz, `write_sensitive`, `registry/chips.json` entry with `"id_probe": null`; 4-wire SPI Mode 0 through a `DisplayConnection` with `busy = None`, write-only). The datasheet's values for this chip:

- **I²C:** address `0111 10 SA0`; tcycle ≥ 2.5 µs, start hold/setup and stop setup ≥ 0.6 µs, data setup ≥ 100 ns, data hold ≥ 300 ns (SDAIN), tIDLE ≥ 1.3 µs. SDAIN and SDAOUT are tied together as SDA. No read access is described for I²C (the status read exists only on the parallel interface); the driver is write-only.
- **SPI (4-wire):** SCLK cycle ≥ 100 ns (clock high/low ≥ 50 ns → **10 MHz** maximum; the drivers default to 4 MHz), D/C# set-up/hold 15 ns, CS# set-up 20 ns / hold 50 ns, data set-up/hold 15 ns, data-write time ≥ 55 ns (VDD 1.65–3.3 V). Mode 0 is the usual choice (the idle level is not named — confirm on hardware). "No data read is provided in serial mode operation." **Every command and every command parameter byte is sent with D/C# low** (the command table shows D/C# = 0 for the parameter bytes), exactly as for the SSD1306.
- **Interface select pins:** BS[2:0] = `010` for I²C, `000` for 4-wire SPI. 3-wire SPI and the parallel interfaces are not covered.

Supply: VDD 1.65–3.3 V, **VCC 7–16 V external** (switched on after RES# and off before VDD).

## Command Set

Only the SSD1309's differences from the SSD1306 command set are listed. The commands `0x00`–`0x1F` (column nibbles; the high nibble uses `A[3:0]`, i.e. `0x10`–`0x1F`), `0x20`/`0x21`/`0x22` (addressing), `0x40|line`, `0x81`, `0xA0`/`0xA1`, `0xA3`, `0xA4`–`0xA8`, `0xAE`/`0xAF`, `0xB0|page`, `0xC0`/`0xC8`, `0xD3`, `0xD5`, `0xD9` (1–15 DCLK, reset `0x22`), `0xDA`, `0xE3`, `0x2E`/`0x2F` have the SSD1306 meaning. Reset values in parentheses.

| Command | Code | Description |
|---------|------|-------------|
| **Charge pump** | — | **Does not exist.** The SSD1306's `0x8D` must not be sent; with the pump absent VCC comes from the board |
| Clock divide / oscillator | `0xD5`, then `A7:A4 osc, A3:A0 div−1` | Divide ratio = A[3:0] + 1 (reset 1); oscillator frequency increases with A[7:4] (**reset `0111b`**, i.e. `0x70`); fOSC 360–540 kHz (450 typ) at the reset setting |
| VCOMH deselect level | `0xDB`, then `00 A5 A4 A3 A2 00` | Four-bit value in bits 5:2: `0x00` ≈ 0.64 × VCC, `0x34` ≈ 0.78 × VCC (reset), `0x3C` ≈ 0.84 × VCC |
| Set GPIO | `0xDC`, then `A[1:0]` | **New.** `00` pin HiZ, input disabled; `01` HiZ, input enabled; `10` output low (reset); `11` output high |
| Set command lock | `0xFD`, then `00010 A2 10` | **New.** `0x12` unlock (reset), `0x16` lock: ignore all commands and memory access except `0xFD` itself |
| Horizontal scroll setup | `0x26` (right) / `0x27` (left), then A…G | **Seven parameter bytes:** A dummy `0x00`; B[2:0] start page; C[2:0] step interval (`000` 5 frames, `001` 64, `010` 128, `011` 256, `100` 2, `101` 3, `110` 4, `111` 1 frame); D[2:0] end page (≥ B); E dummy `0x00`; **F start column (reset 0); G end column (reset 127 = `0x7F`, ≥ F)**. One column per step |
| Vertical + horizontal scroll setup | `0x29` (right) / `0x2A` (left), then A…G | **Seven parameter bytes:** A[0] column scroll offset (0 = none, 1 = one column per step); B[2:0] start page; C[2:0] interval (as above); D[2:0] end page; **E[5:0] vertical scroll offset (rows per step, 0 = pure horizontal)**; **F start column; G end column (≥ F)**. E must be < the scroll-area row count of `0xA3` |
| Content scroll setup | `0x2C` (right) / `0x2D` (left), then `0x00`, B, `0x01`, D, `0x00`, F, G | **New.** Seven parameter bytes: A dummy `0x00`; B[2:0] start page; C dummy `0x01`; D[2:0] end page (≥ B); E dummy `0x00`; F start column; G end column (> F). **Each command scrolls the RAM content by exactly one column** (the host then writes the new column at the window edge); successive `0x2C`/`0x2D` commands need a delay of ≥ 2 frame periods |

### Power-on / reset defaults

As the SSD1306 (display off, 128 × 64 mode, page addressing mode, normal segment and scan mapping, start line 0, column pointer 0, contrast `0x7F`, normal display, entire display follows RAM, multiplex 64, clock divide 1, pre-charge 2 + 2 DCLK, COM alternative, shift register cleared) with the oscillator at `0111b` and VCOMH `0x34` (≈ 0.78 × VCC), plus GPIO output low and the interface unlocked. The display RAM contents are **undefined** at power-up; clear it before the display is switched on.

## Display RAM

Identical to the SSD1306: 128 columns × 8 pages × 8 bits, **bit 0 = top row of the page**, page addressing at reset (`0x20 0x02`), horizontal (`0x20 0x00`) and vertical (`0x20 0x01`) addressing available with `0x21`/`0x22` ranges. See `specs/display/ssd1306.md`.

## Initialization Sequence

The SSD1306 sequence **without the charge pump** and with the SSD1309 reset values, per the datasheet's power-on flow (8.8, external VCC):

1. Apply VDD. After it is stable pulse RES# low for ≥ 3 µs (`connection.reset()` with `reset_pulse_us ≥ 3`) and release it. All registers are reset after the pulse.
2. Wait ≥ 3 µs after RES# goes low, then power on VCC (board-level; the driver cannot switch it).
3. Setup command stream with the display off: `0xAE`, `0xD5 0x70` (clock, reset value), `0xA8 height−1`, `0xD3 0x00`, `0x40`, `0x20 0x02`, `0xA0|ADC`, `0xC0|(scan<<3)`, `0xDA 0x12` (`0x02` for 32-row panels), `0x81 0x7F`, `0xD9 0x22`, `0xDB 0x34` (reset value), `0xA4`, `0xA6`. **No `0x8D`.**
4. Clear the RAM (8 pages × 128 bytes of `0x00`).
5. `0xAF`; SEG/COM are on after tAF = 100 ms — wait 100 ms.

Power-off: `0xAE`, switch VCC off, wait tOFF (typ. 100 ms, min 0), then VDD off. VDD must never be removed before VCC, and VCC/VDD must never be pulled to ground.

## Implementation Stages

### Minimal

`Ssd1309Minimal` (I²C) and `Ssd1309SpiMinimal` (SPI) are the SSD1306 Minimal classes under the SSD1309 name, with these changes to `init`:

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection`, `width: int = 128`, `height: int = 64`, `external_vcc: bool = True` | — | Runs the Initialization Sequence above. **`external_vcc` defaults to `True` and `False` is rejected** (`ValueError` / `invalid()` / error — there is no charge pump to enable); the SSD1306's `0x8D` step is omitted, `0xD5` is written with `0x70` and `0xDB` with `0x34` |
| `clear`, `set_pixel`, `show` | as SSD1306 | — | Unchanged |

**Sensible defaults:** 128 × 64, external VCC, page addressing, contrast `0x7F`, normal orientation, clock `0x70`, VCOMH `0x34`, normal display.

### Full

`Ssd1309Full` / `Ssd1309SpiFull` derive from the SSD1306 Full classes. **Inherited unchanged:** `get_pixel`, `fill`, `draw_line`, `draw_rect`, `blit`, `show_page`, `set_contrast`, `set_display`, `sleep`, `wake`, `set_invert`, `set_all_on`, `set_flip`, `set_start_line`, `set_display_offset`, `set_multiplex`, `set_clock`, `set_precharge`, `set_com_config`, `set_addressing_mode`, `set_scroll_area`, `scroll_start`, `scroll_stop`, `send_command`.

**Overridden** (same name, SSD1309 behaviour):

| Operation | Parameters | Notes |
|-----------|------------|-------|
| `set_vcomh` | `value: int` (0–255, only bits 5:2 used) | `0xDB`, `value & 0x3C` |
| `set_charge_pump` | `enabled: bool` | **Not supported:** raises (`NotSupported`) for `True`, no-op for `False`; never sends `0x8D` |
| `set_scroll_horizontal` | `right: bool`, `start_page: int`, `end_page: int`, `interval: int` (0–7), `start_col: int = 0`, `end_col: int = 127` | `0x26`/`0x27`, `0x00`, start page, interval code, end page, `0x00`, `start_col`, `end_col` (seven parameter bytes); `interval` is a table index 0–7 mapped to the register codes `{0: 5 frames, 1: 64, 2: 128, 3: 256, 4: 2, 5: 3, 6: 4, 7: 1}` — **the table differs from the SSD1306's and the SSD1315's** |
| `set_scroll_vertical` | `right: bool`, `start_page: int`, `end_page: int`, `interval: int` (0–7), `rows: int` (0–63), `columns: int = 1` (0/1), `start_col: int = 0`, `end_col: int = 127` | `0x29`/`0x2A`, `columns`, start page, interval code, end page, `rows`, `start_col`, `end_col` (seven parameter bytes) |

**New:**

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `scroll_content` | `right: bool`, `start_page: int`, `end_page: int`, `start_col: int`, `end_col: int` | — | `0x2C`/`0x2D`, `0x00`, start page, `0x01`, end page, `0x00`, start col, end col; scrolls the window by **one column**; waits ≥ 2 frame periods (≈ 20 ms at the default frame rate) before returning so consecutive calls are safe |
| `set_gpio` | `mode: int` (0–3) | — | `0xDC`, mode (0 HiZ/input off, 1 HiZ/input on, 2 output low, 3 output high) |
| `set_command_lock` | `lock: bool` | — | `0xFD`, `0x16` / `0x12`; while locked the chip ignores everything but `0xFD` 0x12 — a locked panel recovers with an unlock (the driver sends the unlock in `init` after the reset only if requested) |

**Additional configuration options:** everything of the SSD1306 (minus the charge pump) plus column-windowed scrolling, content scroll, GPIO and command lock.

## Data Conversion

As the SSD1306 (`page = y // 8`, `bit = y % 8`, bit 0 = top; page-mode and horizontal-mode `show()` procedures). Differences:

```
VCOMH byte (0xDB)  = code << 2          code 0..15 ; 0x34 (code 13) ≈ 0.78 * VCC (reset), 0x00 ≈ 0.64, 0x3C ≈ 0.84
scroll interval    = {0: 5, 1: 64, 2: 128, 3: 256, 4: 2, 5: 3, 6: 4, 7: 1} frames        (SSD1309 code table)
Segment current    = contrast / 256 * IREF * 32       (IREF = 10 uA -> ISEG about 320 uA at 0xFF: 280..340 uA; 0x7F 155 uA, 0x3F 78 uA, 0x0F 20 uA)
IREF resistor      = (VCC - 3 V) / IREF           (e.g. 900 kOhm for VCC = 12 V, IREF = 10 uA)
Frame rate         = fOSC / (D * K * MUX)         D = divide ratio, K = 69 DCLK per row (default), MUX = multiplex ratio ; 450 kHz -> about 102 Hz at 64 MUX
```

## Timing Constraints

- **Reset:** RES# low ≥ 3 µs; wait ≥ 3 µs after RES# low before VCC (t2); registers are reset after the pulse.
- **Power sequence (external VCC):** VDD first, RES# pulse, VCC on, then `0xAF` — SEG/COM turn on after tAF = 100 ms. Power-off: `0xAE`, VCC off, VDD off after tOFF (typ. 100 ms, min 0). VDD must not be removed before VCC. These are recommended waits, not hard limits.
- **I²C / SPI:** see Transport Configuration (SPI ≥ 100 ns cycle, I²C ≤ 400 kHz).
- **Scrolling:** after `0x2E` the RAM must be rewritten; scroll setup commands must not be issued while scrolling is active; `0x2C`/`0x2D` content scroll is a one-column step and needs ≥ 2 frame periods between commands.
- **Conformance:** none of these has a bus-decodable start/end annotation pair that the host controls (the delays are recommended waits after commands, not measured events), so `specs/display/ssd1309_timing.conf` defines no checks.

## Implementation Notes

- **Alias design:** in every language `Ssd1309*` classes subclass the SSD1306 classes (Python: `Ssd1309Minimal(Ssd1306Minimal)` etc. in `ssd1309.py`; C++: header-only subclasses/templates in `SSD1309.h`; Node.js: `class Ssd1309 extends Ssd1306`; Rust: wrapper type delegating to the SSD1306 driver with overridden command methods; JVM: Java/Kotlin/Groovy subclasses; Go: embedded struct). The SSD1306 classes must therefore make the **initialization sequence and the byte-level command builders overridable** (`set_vcomh`, `set_charge_pump`, the two scroll setups, and the init steps for charge pump, oscillator and VCOMH) so the SSD1309 overrides replace them without copying the framebuffer or transport code; where a language's SSD1306 classes are final or sealed, they are changed to allow subclassing as part of this work. This work is **shared with the SSD1315 alias** (`specs/display/ssd1315.md`): implement the overridable init once. The SSD1309 examples and tests use the SSD1309 names; the SSD1306 ones are untouched.
- **SSD1306 code on an SSD1309:** a plain SSD1306 driver runs on an SSD1309 panel but sends `0x8D 0x14`, which is **not a defined command** on the SSD1309 (the datasheet: "patterns other than those given in the command table are prohibited … unexpected results can occur"); the board must supply VCC externally either way. Its **scroll setups send the wrong trailing bytes** (`0xFF` for the end column, one parameter short for the diagonal command) and use the wrong interval codes. This is why the alias overrides these rather than re-exporting the SSD1306 classes unchanged.
- **External VCC and sequencing:** the driver cannot switch VCC. If a module's boost converter is enabled by the display-on command or a GPIO, the board decides; the datasheet's order (RES#, VCC, then `0xAF`) is what `init` assumes (VCC already applied, as for the SSD1305). With the module's VCC absent the display stays dark although every command is accepted.
- **Contrast range:** the SSD1309 documents all 256 steps of `0x81`; `0x00` is a valid (dark) setting here, unlike on the SSD1315.
- **Pre-charge:** `0xD9` counts DCLKs (1–15) as on the SSD1306 — **not** the SSD1315's 2-DCLK units; the base `set_precharge` is inherited unchanged.
- **Content scroll flow:** the datasheet's example (page addressing, window pages 2–5, columns 8–120) is: send `0x2D 0x00 0x02 0x01 0x05 0x00 0x08 0x78`, wait 2 frame periods, then write the new content into the window's first column (the column that was scrolled out) for every page of the window. The driver's `scroll_content` implements the command and the wait; writing the incoming column is left to the caller (`show_page` writes whole pages).
- **GPIO pin:** `0xDC` drives a GPIO pad; modules rarely connect it. It is exposed for completeness.
- **No read access:** as on the SSD1306 the status read exists only on the parallel interface; the I²C/SPI drivers have no `read_*` methods.
- **128 × 32 / 128 × 64 modules, orientation:** as the SSD1306 (`height`, `set_flip`, `0xDA 0x02` vs `0x12`); the SSD1309's MUX range is also 16–64. The Waveshare 2.42inch OLED is a 128 × 64 panel; its I²C address (`0x3C`/`0x3D`) and bus-select straps are module-specific (unverified).
- **Datasheet quality:** the PDF copy carries a Crystalfontz watermark overlay in its first pages; Rev 1.1 (Jul 2011) states the SPI mode only implicitly and its text lists the scroll byte counts in the description paragraphs while the command tables show seven parameter rows (the tables are used).
- **Not covered:** parallel (6800/8080) and 3-wire SPI interfaces, the external-clock mode (CLS low).
- **Datasheet:** SSD1309 Rev 1.1, July 2011 (63 pages).

## Sigrok Decoder

The SSD1306 decoders (`ssd1306`, `ssd1306_spi`) are **extended, not duplicated**: new decoder ids `ssd1309` (input `['i2c']`, addresses `0x3C`/`0x3D`) and `ssd1309_spi` (input `['spi']`) reuse the SSD1306 command table and apply the SSD1309 differences: `0x8D` flagged as **not a command of this chip**, `0xDB` decoded as a 4-bit value (VCOMH ratio), `0xD5` with the `0111b` oscillator default, the seven-parameter `0x26`/`0x27`, `0x29`/`0x2A` and `0x2C`/`0x2D` setups with page, column and interval fields (interval codes decoded from the SSD1309 table), `0xDC` GPIO and `0xFD` lock. Warnings: a command byte not in the table (including `0x8D` and the SSD1305's `0xAD`), a scroll setup with a wrong parameter count (the SSD1306 six-byte form), a scroll setup issued while scrolling is active, `0x2C`/`0x2D` sent twice within 2 frame periods, a data write while scrolling is active, and any command after `0xFD 0x16` other than `0xFD`. No timing annotation pair is emitted.
