# Chip Spec: SSD1315

**Manufacturer:** Solomon Systech  
**Datasheet:** `datasheets/display/ssd1315.pdf` (SSD1315 Rev 1.1, Apr 2017, "Advance Information", 36 pages; the same PDF carries the charge-pump DC characteristics as an appendix). No module datasheet is committed: the module mapping ("several Waveshare 0.96inch OLED modules") comes from the issue's survey and is **unverified**  
**Category:** `display`  
**Transports:** I²C, SPI (4-wire, write-only) — identical to the SSD1306 (`specs/display/ssd1306.md`)

## Overview

The SSD1315 is a single-chip CMOS OLED/PLED driver with controller for monochrome dot-matrix panels of up to **128 × 64** pixels: 128 segments, 64 commons, 128 × 64 bits of display RAM (GDDRAM, 8 pages × 128 columns), an on-chip oscillator, an internal charge-pump regulator (VBAT 3.0–4.5 V → VCC 7.5 / 8.5 / 9.0 V), 256-step contrast, row/column remapping, hardware scrolling and programmable multiplexing (16–64). It is **command-compatible with the SSD1306** for everything a basic driver needs, so — as the issue requests — **the driver is implemented as a thin alias of the existing SSD1306 driver in every language** (`Ssd1315Minimal` / `Ssd1315Full` and the SPI variants derive from the SSD1306 classes and re-export them under the SSD1315 name), **not** as a duplicate implementation. This spec documents what differs and what is added; everything not mentioned here behaves exactly as in `specs/display/ssd1306.md` and is **not** repeated (transport details, RAM layout, addressing modes, initialization skeleton, framebuffer drawing).

What differs from the SSD1306 (details below):
- **Charge pump:** `0x8D` now selects the output voltage: `0x14` = 7.5 V (same as the SSD1306), **`0x94` = 8.5 V, `0x95` = 9.0 V**; `0x10` disables it.
- **`0xAD` exists** (internal / external IREF selection and the internal IREF value) — on the SSD1305 `0xAD` is the master configuration; the SSD1306 has no `0xAD`.
- **Pre-charge periods count in units of 2 DCLK** (code `n` = `2n` DCLK, 2…30; reset code 2 = 4 DCLK); on the SSD1306 the code is the DCLK count (1–15).
- **Scroll setup commands have different byte layouts**: `0x26`/`0x27` take a **start column and an end column** (the SSD1306's trailing `0x00`, `0xFF` bytes would be wrong), `0x29`/`0x2A` take a **column-offset flag, vertical offset and start/end columns**.
- **New commands:** content scroll (`0x2C`/`0x2D`, "infinite content scrolling"), fade-out / blinking (`0x23`), zoom-in (`0xD6`).
- **Contrast** `0x00` is invalid (valid 01h–FFh), **VCOMH (`0xDB`)** uses only bits 5:4 (four levels `00h/10h/20h/30h`), the **power-up needs ≥ 20 ms** after VDD before RES# is pulsed, VBAT is 3.0–4.5 V and segment current can reach 240 µA.
- The datasheet mentions an **FR (RAM-write synchronisation) pin**, "dynamic grayscale" and an optional **internal IREF** (no external resistor) — see Implementation Notes.

## Transport Configuration

Identical to the SSD1306 spec (I²C `0x3C`/`0x3D` with SA0 on the D/C# pad, 400 kHz, `write_sensitive`, `registry/chips.json` entry with `"id_probe": null`; 4-wire SPI Mode 0 through a `DisplayConnection` with `busy = None`, write-only). The datasheet's values for this chip:

- **I²C:** address `0111 10 SA0`; tcycle ≥ 2.5 µs, start hold/setup and stop setup ≥ 0.6 µs, data setup ≥ 100 ns, data hold ≥ 300 ns (SDAIN), tIDLE ≥ 1.3 µs. SDAIN and SDAOUT are tied together as SDA. No read access is described (the status read exists only on the parallel interface); the driver is write-only.
- **SPI (4-wire):** SCLK cycle ≥ 100 ns (clock high/low ≥ 30 ns → **10 MHz** maximum; the drivers default to 4 MHz), D/C# set-up/hold 15 ns, CS# set-up/hold 20 ns, data set-up 15 ns / hold 25 ns (VDD 1.65–3.5 V). Mode 0 is the usual choice (the idle level is not named — confirm on hardware). "Under serial mode, only write operations are allowed." **Every command and every command parameter byte is sent with D/C# low** (the command table shows D/C# = 0 for the parameter bytes), exactly as for the SSD1306; the driver sends them with `send_command()` per byte.
- **Interface select pins:** BS[2:0] = `010` for I²C, `000` for 4-wire SPI (as on the SSD1306). 3-wire SPI and the parallel interfaces are not covered.

Supply: VDD 1.65–3.5 V (≤ VBAT), **VBAT 3.0–4.5 V** (charge pump), VCC 7.5–16.5 V external or from the pump (7.5 V mode ≥ 7 V at 8 mA from VBAT 3.0–4.5 V; **8.5 V mode needs VBAT ≥ 3.6 V**, 12 mA; **9 V mode needs VBAT ≥ 3.8 V**, 12 mA).

## Command Set

Only the SSD1315's differences from the SSD1306 command set are listed; all other commands (`0x00`–`0x17` column nibbles, `0x20`/`0x21`/`0x22` addressing, `0x40|line`, `0x81`, `0xA0`/`0xA1`, `0xA3`, `0xA4`–`0xA8`, `0xAE`/`0xAF`, `0xB0|page`, `0xC0`/`0xC8`, `0xD3`, `0xD5`, `0xDA`, `0xE3`, `0x2E`/`0x2F`) have the SSD1306 meaning and reset values. Reset values in parentheses.

| Command | Code | Description |
|---------|------|-------------|
| Set contrast | `0x81`, then `01`–`FF` | Valid range **01h–FFh** (`0x00` is not valid); reset `0x7F` |
| Internal IREF setting | `0xAD`, then `00 A5 A4 0000` | `A[4] = 0` external IREF (reset), `1` enable the internal IREF while the display is on; `A[5] = 0` internal IREF 19 µA → ISEG max 150 µA (reset value of the field), `1` 30 µA → ISEG max 240 µA. Data byte `0x00` / `0x10` / `0x30`. **Not** the SSD1305's `0xAD 0x8E` |
| Charge pump setting | `0x8D`, then `A[7:0]` | `0x10` disable (reset); `0x14` enable 7.5 V; `0x94` enable 8.5 V; `0x95` enable 9.0 V. Must be sent before `0xAF` (sequence `8Dh`, `14h`/`94h`/`95h`, `AFh`) |
| Set pre-charge period | `0xD9`, then `A7:A4 phase2, A3:A0 phase1` | Each nibble counts **units of 2 DCLK**: `1` = 2 DCLK … `15` = 30 DCLK; `0` invalid; reset `0x22` = 4 DCLK + 4 DCLK (the datasheet states "RESET equals 4 DCLKs") |
| VCOMH deselect level | `0xDB`, then `00 A5 A4 0000` | `0x00` ≈ 0.65 × VCC, `0x10` ≈ 0.71, `0x20` ≈ 0.77 (reset), `0x30` ≈ 0.83; bit 6 must be 0 |
| Horizontal scroll setup | `0x26` (right) / `0x27` (left), then `0x00`, B, C, D, E, F | **Seven bytes in all:** A dummy `0x00`; B[2:0] start page; C[2:0] step interval (`000` 6 frames, `001` 32, `010` 64, `011` 128, `100` 3, `101` 4, `110` 5, `111` 2 frames); D[2:0] end page (≥ B); **E[6:0] start column (reset 0); F[6:0] end column (reset 127 = `0x7F`, ≥ E)**. One column per step. Valid sequence `26h`/`27h` then `2Fh` |
| Vertical + horizontal scroll setup | `0x29` (right) / `0x2A` (left), then A…G | **Eight bytes in all:** A[0] column scroll offset (0 = no horizontal scroll, 1 = one column per step); B[2:0] start page; C[2:0] interval (as above); D[2:0] end page; **E[5:0] vertical scroll offset (rows per step, 0 = pure horizontal)**; **F[6:0] start column (reset 0); G[6:0] end column (reset 127, ≥ F)**. E must be < the scroll-area row count of `0xA3` |
| Content scroll setup | `0x2C` (right) / `0x2D` (left), then `0x00`, B, `0x01`, D, E, F | **New.** Seven bytes: A dummy `0x00`; B[2:0] start page; C dummy `0x01`; D[2:0] end page (≥ B); E[6:0] start column; F[6:0] end column (> E). **Each command scrolls the RAM content by exactly one column** (the host then writes the new column at the window edge); successive `0x2C`/`0x2D` commands need a delay of ≥ 2 frame periods |
| Set fade out / blinking | `0x23`, then `00 A5 A4 A3 A2 A1 A0` | **New.** `A[5:4]` = `00` disabled (reset), `10` fade out (contrast falls gradually to all pixels off; the output follows RAM when disabled again), `11` blinking (fade out, then fade in, repeating); `A[3:0]` interval per fade step: `0000` = 8 frames, `0001` = 16, … `1111` = 128 frames (`8 × (n + 1)`) |
| Set zoom in | `0xD6`, then `0000000 A0` | **New.** `A[0] = 1` zoom in: each of rows 0–31 is shown on two display rows (fills the 64-row panel); requires the alternative COM pin configuration (`0xDA` `A[4] = 1`); `0` disables (reset) |

### Power-on / reset defaults

As the SSD1306 (display off, 128 × 64 mode, page addressing mode, normal segment and scan mapping, start line 0, contrast `0x7F`, normal display, entire display follows RAM, charge pump **disabled**, multiplex 64, clock divide 1 at oscillator `1000b`, COM alternative, VCOMH `0x20`), plus: **external IREF** selected, pre-charge **4 + 4 DCLK**, fade/blink off, zoom off. The display RAM contents are **undefined** at power-up; clear it before the display is switched on.

## Display RAM

Identical to the SSD1306: 128 columns × 8 pages × 8 bits, **bit 0 = top row of the page**, page addressing at reset (`0x20 0x02`), horizontal (`0x20 0x00`) and vertical (`0x20 0x01`) addressing available with `0x21`/`0x22` ranges. See `specs/display/ssd1306.md`.

## Initialization Sequence

The SSD1306 sequence with these changes, per the datasheet's power-on flows (6.9.1 external VCC, 6.9.2 charge pump):

1. Apply VDD (then VBAT when the charge pump is used). **After VDD is stable wait ≥ 20 ms (t0)**, then pulse RES# low for ≥ 3 µs (`connection.reset()` with `reset_pulse_us ≥ 3`, `reset_settle_ms ≥ 20` is conservative) and release it. All registers are reset after the pulse. (The SSD1306 flow has no t0; the alias waits 20 ms before the reset for both chips.)
2. Wait ≥ 3 µs after RES# goes low; with an external VCC power it on now.
3. Setup command stream with the display off: `0xAE`, `0xD5 0x80`, `0xA8 height−1`, `0xD3 0x00`, `0x40`, `0x8D 0x14` (charge pump 7.5 V; `0x8D 0x10` for external VCC), `0x20 0x02`, `0xA0|ADC`, `0xC0|(scan<<3)`, `0xDA 0x12` (`0x02` for 32-row panels), `0x81 0x7F`, `0xD9 0x22` (**the SSD1315 reset value: 4 + 4 DCLK**, not the SSD1306's 2 + 2), `0xDB 0x20`, `0xA4`, `0xA6`. When `internal_iref` is requested (Minimal `init` argument, default off) add `0xAD 0x10` (19 µA) or `0xAD 0x30` (30 µA) before `0xAF`.
4. Clear the RAM (8 pages × 128 bytes of `0x00`).
5. `0xAF`; SEG/COM are on after tAF = 100 ms — wait 100 ms.

Power-off: `0xAE`, **`0x8D 0x10`** (disable the pump), wait tOFF (typ. 100 ms), then VBAT off, then VDD off (tOFF2 typ. 5 ms). With external VCC: `0xAE`, VCC off, tOFF typ. 100 ms, VDD off. VDD must never be removed before VCC/VBAT.

## Implementation Stages

### Minimal

`Ssd1315Minimal` (I²C) and `Ssd1315SpiMinimal` (SPI) are the SSD1306 Minimal classes under the SSD1315 name, with one optional addition to `init`:

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | as `Ssd1306Minimal.init` (`connection`, `width = 128`, `height = 64`, `external_vcc = False`), plus `internal_iref: int \| None = None` | — | Runs the Initialization Sequence above (adds the ≥ 20 ms wait before the reset, `0xD9 0x22` with the 4 + 4 DCLK meaning, and `0xAD` when `internal_iref` is `0` (19 µA) or `1` (30 µA)); `None` leaves the external IREF (reset) — correct for modules that have the IREF resistor, which is what a drop-in replacement of an SSD1306 expects |
| `clear`, `set_pixel`, `show` | as SSD1306 | — | Unchanged |

**Sensible defaults:** as the SSD1306 (128 × 64, charge pump 7.5 V, page addressing, contrast `0x7F`, normal orientation, clock `0x80`, VCOMH `0x20`, normal display).

### Full

`Ssd1315Full` / `Ssd1315SpiFull` derive from the SSD1306 Full classes. **Inherited unchanged:** `get_pixel`, `fill`, `draw_line`, `draw_rect`, `blit`, `show_page`, `set_display`, `sleep`, `wake`, `set_invert`, `set_all_on`, `set_flip`, `set_start_line`, `set_display_offset`, `set_multiplex`, `set_clock`, `set_com_config`, `set_addressing_mode`, `set_scroll_area`, `scroll_start`, `scroll_stop`, `send_command`.

**Overridden** (same name, SSD1315 behaviour):

| Operation | Parameters | Notes |
|-----------|------------|-------|
| `set_contrast` | `value: int` (1–255) | `0x81`, value; `0` is rejected (or clamped to 1) — `0x00` is invalid on this chip |
| `set_precharge` | `phase1: int` (2–30), `phase2: int` (2–30) | **DCLK counts** (the same unit as the SSD1306 API): the code per nibble is `ceil(dclk / 2)` (1–15), `0xD9`, `(code2 << 4) \| code1`; odd values round up; the reset value is `4, 4` |
| `set_vcomh` | `value: int` (0–255, only bits 5:4 used) | `0xDB`, `value & 0x30` |
| `set_charge_pump` | `enabled: bool`, `voltage: float = 7.5` (7.5, 8.5 or 9.0) | `0x8D`, `0x10` (disabled) or `0x14` / `0x94` / `0x95` for 7.5 / 8.5 / 9.0 V; takes effect with the display on — send before `set_display(True)`; `8.5` needs VBAT ≥ 3.6 V, `9.0` needs VBAT ≥ 3.8 V (documented, not checked) |
| `set_scroll_horizontal` | `right: bool`, `start_page: int`, `end_page: int`, `interval: int` (0–7), `start_col: int = 0`, `end_col: int = 127` | `0x26`/`0x27`, `0x00`, start page, interval code, end page, `start_col`, `end_col`; `interval` is a table index 0–7 mapped to the register codes `{0: 6 frames, 1: 32, 2: 64, 3: 128, 4: 3, 5: 4, 6: 5, 7: 2}` (**note the SSD1315 table differs from the SSD1306 one: code 000 = 6 frames, 011 = 128 frames, 110 = 5 frames**) |
| `set_scroll_vertical` | `right: bool`, `start_page: int`, `end_page: int`, `interval: int` (0–7), `rows: int` (0–63), `columns: int = 1` (0/1), `start_col: int = 0`, `end_col: int = 127` | `0x29`/`0x2A`, `columns`, start page, interval code, end page, `rows`, `start_col`, `end_col` (**eight bytes**) |

**New:**

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `set_internal_iref` | `enabled: bool`, `microamps: int = 19` (19 or 30) | — | `0xAD`, `(enabled << 4) \| (microamps == 30) << 5`; `enabled = False` restores the external IREF. Send while the display is off |
| `scroll_content` | `right: bool`, `start_page: int`, `end_page: int`, `start_col: int`, `end_col: int` | — | `0x2C`/`0x2D`, `0x00`, start page, `0x01`, end page, start column, end column; scrolls the window by **one column**; waits ≥ 2 frame periods (≈ 20 ms at the default frame rate) before returning so consecutive calls are safe |
| `set_fade` | `mode: str` (`"off"`, `"fade"`, `"blink"`), `interval: int = 0` (0–15) | — | `0x23`, `(mode << 4) \| interval` with `off` = `0x00`, `fade` = `0x20`, `blink` = `0x30` (steps of `8 × (interval + 1)` frames); `"off"` restores the RAM output |
| `set_zoom` | `on: bool` | — | `0xD6`, `1`/`0`; requires the alternative COM configuration (`set_com_config(alternative=True)`); the driver raises when the 32-row sequential configuration is active |

**Additional configuration options:** everything of the SSD1306 plus the charge-pump voltage, internal IREF, 2-DCLK pre-charge units, column-windowed scrolling, content scroll, fade/blink and zoom.

## Data Conversion

As the SSD1306 (`page = y // 8`, `bit = y % 8`, bit 0 = top; page-mode and horizontal-mode `show()` procedures). Differences:

```
pre-charge code   = ceil(dclk / 2)         (1..15), nibble phase2 << 4 | phase1       (SSD1306: code = dclk)
charge pump byte  = 0x10 (off) | 0x14 (7.5 V) | 0x94 (8.5 V) | 0x95 (9.0 V)
IREF byte (0xAD)  = (enable << 4) | (30 uA << 5)                                      (0x00, 0x10, 0x30)
fade byte (0x23)  = 0x00 | 0x20 (fade) | 0x30 (blink)  |  (interval & 0x0F)           steps of 8 * (interval + 1) frames
scroll interval   = {0: 6, 1: 32, 2: 64, 3: 128, 4: 3, 5: 4, 6: 5, 7: 2} frames       (SSD1315 code table)
Segment current   = contrast / 256 * IREF * 8   (IREF 19 uA -> ISEG max 150 uA, 30 uA -> 240 uA; an external IREF follows the resistor: R = (VCC - 3 V) / IREF)
Frame rate        = fOSC / (D * K * MUX)         D = divide ratio, K = phase 1 + phase 2 + X DCLKs per row, MUX = multiplex ratio
```

## Timing Constraints

- **Reset:** RES# low ≥ 3 µs; **wait ≥ 20 ms after VDD is stable before the reset pulse** (t0); wait ≥ 3 µs after RES# low before commands/VCC (t2); registers are reset after the pulse.
- **Power sequence (charge pump):** VDD, then VBAT, ≥ 20 ms, RES# pulse, `0x8D` + `0xAF`; SEG/COM on after tAF = 100 ms. Power-off: `0xAE`, `0x8D 0x10`, VBAT off after tOFF (typ. 100 ms), VDD off after tOFF2 (typ. 5 ms, min 0). Power-off with external VCC: `0xAE`, VCC off, VDD off after tOFF (typ. 100 ms). VDD must not be removed before VCC/VBAT.
- **I²C / SPI:** see Transport Configuration (SPI ≥ 100 ns cycle, I²C ≤ 400 kHz).
- **Scrolling:** after `0x2E` the RAM must be rewritten; scroll setup commands must not be issued while scrolling is active; no RAM access while scrolling is active (continuous scroll `0x2F` only; `0x2C`/`0x2D` content scroll is a one-column step and needs ≥ 2 frame periods between commands).
- **Conformance:** none of these has a bus-decodable start/end annotation pair that the host controls (the delays are recommended waits after commands, not measured events), so `specs/display/ssd1315_timing.conf` defines no checks.

## Implementation Notes

- **Alias design:** in every language `Ssd1315*` classes subclass the SSD1306 classes (Python: `Ssd1315Minimal(Ssd1306Minimal)` etc. in `ssd1315.py`; C++: header-only subclasses/templates in `SSD1315.h`; Node.js: `class Ssd1315 extends Ssd1306`; Rust: wrapper type delegating to the SSD1306 driver with overridden command methods; JVM: Java/Kotlin/Groovy subclasses; Go: embedded struct). The base class must therefore make the byte-level command builders overridable (`set_contrast`, `set_precharge`, `set_vcomh`, `set_charge_pump`, the two scroll setups) so the SSD1315 overrides replace them without copying the framebuffer or transport code. Where a language's SSD1306 classes are final or sealed, they are changed to allow subclassing as part of this work. The SSD1315 examples and tests use the SSD1315 names; the SSD1306 ones are untouched.
- **SSD1306 code on an SSD1315:** a plain SSD1306 driver runs on an SSD1315 panel with these visible differences: a **scroll setup** sends the wrong trailing bytes (`0xFF` has bit 7 set, which the SSD1315 pattern `0 F6…F0` forbids; the diagonal command is one parameter short), a **pre-charge** value is twice as long as intended, a **contrast of 0** is invalid, and the charge pump cannot produce more than 7.5 V. This is why the alias overrides these methods rather than re-exporting the SSD1306 classes unchanged.
- **IREF:** the reset state selects the **external IREF** resistor, as on the SSD1306, so modules built for the SSD1306 work with `internal_iref=None`. A module designed without an IREF resistor needs `0xAD 0x10` or `0xAD 0x30` (the datasheet: keep the IREF pad NC when the internal IREF is used); which modules this applies to is **not known** — if the picture stays dark, try the internal IREF. A wrong choice (internal IREF with a resistor fitted) is not specified by the datasheet.
- **Charge pump voltage:** 8.5 V and 9.0 V raise the VCC the panel sees and therefore the brightness and ageing; they require a sufficient VBAT (3.6 V / 3.8 V). The default stays at 7.5 V, the SSD1306 value.
- **Pre-charge units:** the datasheet's table text says "up to 30 DCLK (i.e. 2, 4, 6 … 30)" for 4-bit values, while its section 6.6 says "from 1 to 16 DCLKs" for phase 2 and its description says "RESET equals 4 DCLKs" for code 2; the 2-DCLK-per-code reading (reset = 4 DCLK) is used consistently by the driver, and **vendor SSD1306 snippets that write `0xD9 0xF1` give 30 + 2 DCLK on an SSD1315** instead of 15 + 1 — flagged unverified on hardware.
- **Zoom needs the alternative COM configuration** (`0xDA 0x12`, the 128 × 64 default); `set_zoom(True)` on a 32-row sequential panel raises.
- **Content scroll flow:** the datasheet's example (page-addressing, window pages 2–5, columns 8–120) is: send `0x2D 0x00 0x02 0x01 0x05 0x08 0x78`, wait 2 frame periods, then write the new content into the window's first column — the column that was scrolled out — for every page of the window (set page, column, write the page's column byte). The driver's `scroll_content` implements the command and the wait; writing the incoming column is left to the caller (`show_page` is not suitable: it writes whole pages).
- **FR pin / RAM write synchronisation:** the chip outputs a frame-synchronisation pulse (FR) so a fast MCU can time RAM writes to avoid tearing ("fast write MCU: start just after the rising edge of FR, finish before the next rising edge"); **not covered** — the pin is rarely wired to a host, and the framebuffer transfer is short.
- **Dynamic grayscale** is mentioned in the feature list only (no command or description in this revision): **not covered**.
- **No read access:** as on the SSD1306 the status read exists only on the parallel interface; the I²C/SPI drivers have no `read_*` methods.
- **128 × 32 / 128 × 64 modules, orientation:** as the SSD1306 (`height`, `set_flip`, `0xDA 0x02` vs `0x12`); the SSD1315's MUX range is also 16–64.
- **Advance Information datasheet:** Rev 1.1 (Apr 2017) has page footers that still say "Rev 1.0 Dec 2016" in places, the status-register table lists only D6 (display off = 1), the SPI mode (idle level) is not stated, and the "RESET equals 4 DCLKs" statement conflicts with the "1 to 16 DCLKs" text (see above).
- **Not covered:** parallel (6800/8080) and 3-wire SPI interfaces, the external-clock mode (CLS low), the FR pin, dynamic grayscale.
- **Datasheet:** SSD1315 Rev 1.1, April 2017 (`https://github.com/CursedHardware/epd-driver-ic/blob/master/SSD1315.pdf`, 36 pages).

## Sigrok Decoder

The SSD1306 decoders (`ssd1306`, `ssd1306_spi`) are **extended, not duplicated**: new decoder ids `ssd1315` (input `['i2c']`, addresses `0x3C`/`0x3D`) and `ssd1315_spi` (input `['spi']`) reuse the SSD1306 command table and add the SSD1315 differences: `0x8D` argument decoded as pump mode (off / 7.5 / 8.5 / 9.0 V), `0xAD` (IREF enable and value), `0xD9` in units of 2 DCLK, `0xDB` limited to bits 5:4, the 7-byte `0x26`/`0x27`/`0x2C`/`0x2D` and the 8-byte `0x29`/`0x2A` setups with page, column and interval fields, `0x23` fade/blink with the step interval, `0xD6` zoom, `0x81 0x00` flagged as invalid. Warnings: a command byte not in the table (including SSD1305's `0xAD 0x8E`), a scroll setup with a wrong parameter count (the SSD1306 six-byte form), a scroll setup issued while scrolling is active, `0x2C`/`0x2D` sent twice within 2 frame periods, zoom without the alternative COM configuration, and a data write while scrolling is active. No timing annotation pair is emitted.
