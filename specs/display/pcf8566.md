# Chip Spec: PCF8566

**Manufacturer:** NXP Semiconductors  
**Datasheet:** `datasheets/display/pcf8566.pdf` (PCF8566 Rev. 07, 25 February 2009)  
**Category:** display  
**Transports:** I²C (write-only)

## Overview

The PCF8566 is a universal LCD driver for low multiplex rates: it generates the drive signals for an LCD with up to **four backplanes and 24 segments** (up to twelve 7-segment digits, six 14-segment characters or 96 graphic elements). It has a 24 × 4-bit display RAM with auto-incremented addressing across hardware-subaddress boundaries, static / 1:2 / 1:3 / 1:4 multiplex drive with 1/2 or 1/3 bias, internal bias generation, selectable blinking (including alternate-RAM-bank blinking), display RAM bank switching in static and 1:2 mode and a power-saving mode, on a 2.5–6 V supply. It communicates over I²C (**write-only**) and cascades with other PCF8566 (up to 16 on one bus) and with the 40-segment PCF8576C. It is the 24-segment sibling of the PCF8576 with the same command set; differences: 24 instead of 40 segment outputs (RAM addresses 0–23, 5-bit data pointer), slave addresses `0x3E`/`0x3F`.

## Transport Configuration

### I²C
- **Address:** `0x3E` (SA0 = VSS) — `0x3F` (SA0 = VDD); 7-bit address `0111 11 SA0` (the datasheet's two reserved addresses `0111 110` and `0111 111`)
- **Max clock:** 100 kHz nominal; in power-saving mode the chip may stretch SCL (clock synchronization) when large display data is sent. The datasheet states the I²C maximum speed is derated at `fclk < 125 kHz` (power-saving clock 21–48 kHz); the drivers use ≤ 100 kHz
- **Write-only:** the device never transmits; the R/W bit must be 0. The drivers use only `write`
- **Identity register:** none (`registry/chips.json` entry has `"id_probe": null`; it shares `0x3E`/`0x3F` with the PCF8574A range and similar parts)
- **Probe safety:** `write_sensitive` — every byte after the address is a command or display data; there is no register pointer
- **Protocol:** `[addr+W] [command byte]… [display data byte]…`. Each command byte has a continuation bit **C** in bit 7: `C = 1` means another command byte follows, `C = 0` marks the last command byte; all bytes after the last command byte are display data. Plain `Connection` (`write`), not `RegisterConnection`

## Pin Configuration

| Pin | Notes |
|-----|-------|
| SDA, SCL | I²C; external pull-ups |
| SA0 | Slave address bit 0 |
| A0, A1, A2 | Hardware subaddress inputs (tie to VSS or VDD; binary-coded in cascaded setups) |
| OSC | Oscillator: internal ≈ 200 kHz when tied to VDD; with an external clock the pin stays at VSS |
| CLK, SYNC | Clock input/output and cascade synchronization |
| VDD, VSS, VLCD | Logic supply 2.5–6 V; LCD supply VDD − VLCD 2.5–6 V |
| BP0–BP3 | Backplane outputs |
| S0–S23 | Segment outputs |

A clock must always be present; removing it freezes the LCD in a DC state. No interrupt pin.

## Command Set

Every command byte: bit 7 = C (continuation), bits 6:0 = opcode.

| Command | Opcode (bit 7 = C) | Description |
|---------|--------------------|-------------|
| Mode set | `C 1 0 LP E B M1 M0` | LCD drive mode, bias, display enable, power-saving |
| Load data pointer | `C 0 0 P4 P3 P2 P1 P0` | Display RAM address 0–23 |
| Device select | `C 1 1 0 0 A2 A1 A0` | Subaddress counter (0–7) for cascaded devices |
| Bank select | `C 1 1 1 1 0 I O` | Input bank `I` and output bank `O` (static and 1:2 only) |
| Blink | `C 1 1 1 0 A BF1 BF0` | Blink frequency and mode |

### Mode set bit fields

| Bits | Name | Values |
|------|------|--------|
| 4 | LP | `0` = normal mode, `1` = power-saving mode |
| 3 | E | `0` = display disabled (blank), `1` = enabled |
| 2 | B | `0` = 1/3 bias, `1` = 1/2 bias |
| 1:0 | M1:M0 | `01` = static (BP0), `10` = 1:2 (BP0–BP1), `11` = 1:3 (BP0–BP2), `00` = 1:4 (BP0–BP3) |

### Other bit fields

- **Load data pointer:** `P4..P0` = 0–23.
- **Device select:** `A2..A0` = 0–7 (must match the hardware subaddress pins for the data to be stored).
- **Bank select:** `I` = 0 stores arriving data in RAM bit 0 (static) / bits 0–1 (1:2), `I` = 1 in bit 2 / bits 2–3; `O` selects the displayed bank the same way. No effect in 1:3 and 1:4 mode.
- **Blink:** `BF1:BF0` = `00` off, `01` ≈ 2 Hz, `10` ≈ 1 Hz, `11` ≈ 0.5 Hz (at `fclk` = 200 kHz; blink frequency = `fclk / 92160`, `/ 184320`, `/ 368640`; in power-saving mode `fclk / 15360`, `/ 30720`, `/ 61440`); `A` = 0 normal blinking, `A` = 1 alternate-RAM-bank blinking (static and 1:2 only).

### Power-on reset defaults

All backplane and segment outputs at VDD (display off), drive mode **1:4 with 1/3 bias**, blinking off, bank selectors reset (0), data pointer and subaddress counter 0, I²C interface initialised. **Do not transfer data for at least 1 ms after power-on.**

## Initialization Sequence

1. Power-up; wait ≥ 1 ms.
2. Send `[0xC8 | M]`-style command stream in one transaction: mode set (continuation) `0xC8` (E = 1, 1/3 bias, normal mode, 1:4) — then load data pointer `0x00` (last command, C = 0) followed by 12 zero data bytes (the 1:4 data pointer advances 2 columns per byte, covering all 24 columns) to clear the RAM; the driver sends `[0xC8, 0x00, 0x00 × 12]` (`0xC8` = `C=1 | 0x40 | E<<3`; `0x00` = load data pointer 0 with C = 0).
3. The display is now enabled and blank.

For a different mode, the number of zero bytes needed to clear the RAM is `ceil(24 / columns per byte)` with 8 columns per byte in static mode, 4 in 1:2, 3 in 1:3 and 2 in 1:4.

## Data Encoding

### Display RAM layout

The 24 × 4-bit RAM has columns 0–23 (segment outputs S0–S23) and rows 0–3 (backplanes BP0–BP3); a `1` lights the segment.

### Data pointer increment per transmitted byte

Static mode: 8 columns (bit `n` of the byte = column `n`); 1:2 mux: 4 columns (2 bits per column); 1:3 mux: 3 columns (3 bits per column, bit 2 of the third column unchanged); 1:4 mux: 2 columns (4 bits per column). If the pointer overflows 23 it continues in the next subaddress; avoid it in single-device use by writing only the needed bytes.

### 7-segment encoding in 1:4 multiplex mode (default)

Each digit uses two adjacent columns (`S(2p)` and `S(2p+1)`); digit position `p` maps to the data pointer address `p × 2`, up to 12 digits. This is the datasheet's typical wiring (Figure 11): the high nibble of the transmitted byte is column `n` (bits 7:4 = BP0…BP3 as `a c b DP`) and the low nibble is column `n+1` (`f e g d`).

| Bit | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|-----|---|---|---|---|---|---|---|---|
| Segment | a | c | b | DP | f | e | g | d |

Digit lookup (DP = 0): `0` `0xED`, `1` `0x60`, `2` `0xA7`, `3` `0xE3`, `4` `0x6A`, `5` `0xCB`, `6` `0xCF`, `7` `0xE0`, `8` `0xEF`, `9` `0xEB`, blank `0x00`; add `0x10` for the decimal point. (The bit order matches the PCF8576 wiring; a different panel needs a different mapping — use `write_raw`.)

### Static mode

Each byte covers 8 adjacent columns (LSB = lowest-numbered segment of the group); the pointer advances by 8; 3 bytes fill the whole RAM.

## Timing Constraints

- **Power-on:** do not transfer data for at least **1 ms** after power-up (reset action). Conformance-checked as `poweron_ready` (min 1 ms), measured from capture start to the first decoded bus transaction (the same no-bus-decodable-start-event pattern as `display/pcf8576` and `environmental/aht21`); see `specs/display/pcf8566_timing.conf`.
- **Clock:** `fclk` 125–315 kHz (200 kHz typ.) in normal mode, 21–48 kHz (31 kHz typ.) in power-saving mode; frame frequency `fclk / 2880` (69 Hz at 200 kHz) normal, `fclk / 480` (65 Hz at 31 kHz) power-saving.
- **Aborted transfers:** the data pointer state is unknown after an early-terminated transaction; resend a load-data-pointer command before the next display write.
- **I²C:** tBUF 4.7 µs, tHD;STA 4.0 µs, tLOW 4.7 µs, tHIGH 4.0 µs, tSU;DAT 250 ns, tSU;STO 4.7 µs (standard mode).

## Implementation Notes

- **Write-only:** never call `read` or `write_read`; the chip does not acknowledge reads.
- **Subaddress ≠ I²C address:** device select sets the subaddress counter that must match A0–A2; in single-device use it stays 0 after reset, so it can be skipped. In cascaded use send device select before display data; the counter increments automatically when the data pointer overflows.
- **1:3 mode:** bit 2 of the third column of each group is left unchanged by a byte write; rewrite whole groups or account for it.
- **Bank select / alternate-bank blinking** have no effect in 1:3 and 1:4 mode (no spare RAM bank).
- **Blinking at another rate:** toggle the display enable bit (`E`) under host control.
- **Never remove the clock** while the display is active, and switch VLCD with VDD together to avoid DC build-up.
- **Datasheet:** NXP Rev. 07, from `https://www.nxp.com/docs/en/data-sheet/PCF8566.pdf`.

## Sigrok Decoder

Decoder id `pcf8566`, input `['i2c']`. Matches I²C addresses `0x3E`/`0x3F`. Decodes the command bytes (mode set with drive mode/bias/E/LP, load data pointer, device select, bank select, blink with frequency and mode, plus the continuation bit) and the following display data bytes (hex, and for the 1:4 default mode the lit 7-segment glyph); warns on a read access (R/W = 1), on commands with reserved opcodes and on display data that would overflow the 24-column RAM. The `poweron_ready` check needs no annotation pair (measured from capture start).
