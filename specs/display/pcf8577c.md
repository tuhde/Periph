# Chip Spec: PCF8577C

**Manufacturer:** NXP Semiconductors  
**Datasheet:** `datasheets/display/pcf8577c.pdf` (PCF8577C Rev. 5, 10 October 2014)  
**Category:** display  
**Transports:** I²C (write-only)

## Overview

The PCF8577C is an LCD driver that drives up to **32 segments in direct drive** (one backplane BP1) or **64 segments in duplex** (two backplanes BP1/BP2) from a two-line I²C interface, in a VSO40 package, supply 2.5–6 V, with a single-pin built-in oscillator. It uses **auto-incremented loading** across device boundaries (hardware subaddress inputs A0–A2 for up to eight devices = 256 segments), **display memory switching** (BANK A/B) in direct drive mode, a power-on reset that blanks the display, and can also be used as an I²C **output expander**. It is write-only: eight 8-bit segment byte registers plus one control register (MODE, BANK, segment byte vector) and a fixed slave address. It is the simple sibling of the PCF8576 (`specs/display/pcf8576.md`): no command set, just a control byte followed by segment data.

## Transport Configuration

### I²C
- **Address:** `0x3A` (7-bit `0111 010`, fixed; the hardware subaddress pins A0–A2 select the device within a cascade, not the I²C address); every PCF8577C on the bus acknowledges the address and the control byte, but only the device whose subaddress matches the segment byte vector acknowledges and loads the data
- **Max clock:** 100 kHz (standard mode; the datasheet's I²C limits are the standard-mode values)
- **Write-only:** the device never transmits data; never issue a read transaction
- **Identity register:** none (`registry/chips.json` entry has `"id_probe": null`; `0x3A` is shared with the PCF2116 and PCF8574A-range parts)
- **Probe safety:** `write_sensitive` — the byte after the address is the control byte and every following byte is display data
- **Protocol:** `[addr+W] [control byte] [segment byte]… P` — plain `Connection` (`write`), not `RegisterConnection`. The control byte is `MODE BANK V5 V4 V3 V2 V1 V0` (bit 7 = MODE, bit 6 = BANK, bits 5:0 = **segment byte vector** SBV); if a STOP follows the control byte only the display bits change and the segment data stay untouched (this toggles BANK without rewriting data). The SBV auto-increments after every loaded segment byte (by 2 in direct drive, by 1 in duplex) and rolls over from `111111` to `000000`

## Pin Configuration

| Pin | Notes |
|-----|-------|
| SDA, SCL | I²C; external pull-ups; the ESD structure has no diode to VDD (partial VDD shutdown possible) |
| A0, A1, A2/BP2 | Hardware subaddress inputs; in duplex mode the A2/BP2 pin is the second backplane output and A2 (and SBV bit V5) are undefined |
| BP1 (and BP2) | Backplane outputs (BP2 only in duplex mode); in master mode set to VSS at reset, 3-state in cascade mode |
| S1–S32 | Segment outputs |
| OSC | Oscillator (single pin built in) |
| VDD, VLCD, VSS | Logic supply 2.5–6 V and LCD supply; apply and remove VDD and VLCD together |

No interrupt pin.

## Registers

| Register | Content |
|----------|---------|
| Control register | `MODE` (bit 7): `0` direct drive, `1` duplex; `BANK` (bit 6): `0` display bank A (even bytes), `1` bank B (odd bytes) — direct drive only; `V5:V0` segment byte vector |
| Segment byte registers 0–7 | 8 bits each, bit `n` ↔ one segment (see mapping) |

SBV decoding: `V5:V3` are compared with the hardware subaddress `A2:A0` (equal = this device is enabled for loading, otherwise it ignores the data but stays active); `V2:V0` select the segment byte register 0–7 inside the enabled device.

### Segment mapping

| Mode | Register (V2 V1 V0) | Bank | Bits 7…0 |
|------|---------------------|------|----------|
| Direct (MODE 0) | 0 (000) | A | S8 … S1 |
| Direct | 1 (001) | B | S8 … S1 |
| Direct | 2 (010) | A | S16 … S9 |
| Direct | 3 (011) | B | S16 … S9 |
| Direct | 4 (100) | A | S24 … S17 |
| Direct | 5 (101) | B | S24 … S17 |
| Direct | 6 (110) | A | S32 … S25 |
| Direct | 7 (111) | B | S32 … S25 |
| Duplex (MODE 1) | 0 / 1 | — | S8 … S1 on BP1 (even) / BP2 (odd) |
| Duplex | 2 / 3 | — | S16 … S9 on BP1 / BP2 |
| Duplex | 4 / 5 | — | S24 … S17 on BP1 / BP2 |
| Duplex | 6 / 7 | — | S32 … S25 on BP1 / BP2 |

In direct drive the displayed bank selects even (A) or odd (B) registers: only one bit per segment is needed, so two complete display images (A and B) exist and `BANK` swaps them. In duplex mode even bytes drive backplane 1 and odd bytes backplane 2, and `BANK` is ignored. Mapping examples: direct drive, bank B, register 7 bit 0 = segment S25; duplex, register 5 bit 7 = segment S24 on BP2.

### Power-on reset

Both backplane outputs at VSS (3-state in cascade mode), all segment outputs at VSS, segment byte registers and control register cleared, I²C interface initialised: the display is blank.

## Initialization Sequence

1. Power-up (VDD and VLCD together): the chip resets itself, blank display; the datasheet gives no start-up delay.
2. Write the segment data with the control byte first: `[addr+W] [control: MODE 0, BANK 0, SBV 0] [data…]`; in direct drive the SBV advances by two after each byte, so four consecutive data bytes load the bank-A registers 0, 2, 4, 6 (see Data Conversion).
3. `init` writes the control byte `0x00` followed by four zero bytes: direct drive, bank A, all segments off.

## Implementation Stages

### Minimal

Goal: drive a 32-segment direct-drive LCD out of the box; no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | connection | — | Direct drive, bank A, all 32 segments off (`[0x00] [0x00 0x00 0x00 0x00]`) |
| `clear` | — | — | All segments off |
| `set_segment` | `segment: int` (1–32), `on: bool = True` | — | Updates the shadow bank A and writes |
| `write_segments` | `bits: int` (32-bit) | — | Bit `n−1` = segment `n` (bit 0 = S1); one transfer |
| `write_raw` | `data: bytes` (1–4) | — | Raw bank-A bytes starting at register 0 |

**Constants:** `SEGMENTS = 32`.

**Sensible defaults:** direct drive (MODE 0), bank A displayed, hardware subaddress 0 (A0–A2 = VSS), display blank.

### Full

Goal: expose complete chip functionality. Extends Minimal.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| *(inherits Minimal)* | | | |
| `set_mode` | `duplex: bool` | — | Control byte `MODE` bit; duplex doubles the capacity to 64 segments (BP1 + BP2) |
| `write_duplex` | `bp1: int`, `bp2: int` | — | 32-bit segment masks for backplane 1 and 2 (bit 0 = S1), written as 8 bytes `[bp1_0, bp2_0, bp1_1, bp2_1, …]` |
| `set_segment_duplex` | `segment: int` (1–32), `backplane: int` (1/2), `on: bool` | — | Shadow update + write |
| `write_bank` | `bank: int` (0/1), `bits: int` | — | Write the other display memory in direct drive without displaying it (control `BANK` = bank, SBV = 0/1 start) |
| `show_bank` | `bank: int` (0/1) | — | `BANK` bit only: control byte followed by STOP (segment data unchanged) |
| `set_subaddress` | `subaddress: int` (0–7) | — | Target device within a cascade: SBV bits `V5:V3` for the following writes |
| `write_raw_at` | `sbv: int` (0–63), `data: bytes` | — | Raw write with an explicit segment byte vector (auto-increment across devices) |
| `output_expander` | `bits: int` | — | Use the segment outputs as an I²C output expander (same as `write_segments`; a `1` drives the segment output high in the LCD sense) |

**Additional configuration options:** direct vs duplex drive, display bank A/B, cascade subaddress.

## Data Conversion

```
control byte  = MODE << 7 | BANK << 6 | SBV        (SBV = V5..V0 = subaddress<<3 | register)

Direct drive, bank A: segments S1..S32 in registers 0, 2, 4, 6 (bit 0 = S1, S8 = bit 7 of register 0, S9 = bit 0 of register 2, ...)
    write_segments(bits):  [addr+W] [0x00] [bits & 0xFF] [bits>>8 & 0xFF] [bits>>16 & 0xFF] [bits>>24 & 0xFF]
    (the SBV advances by two after each byte, i.e. 0, 2, 4, 6)
Direct drive, bank B: control byte BANK = 1 and SBV = 1: registers 1, 3, 5, 7
Duplex: registers 0..7 in order (SBV +1 per byte): BP1 bytes at even, BP2 bytes at odd registers
show_bank(b): [addr+W] [MODE << 7 | b << 6 | SBV] STOP        # segment data unchanged
```

## Examples

### Demo

**Segment walk with bank flip.** With the Full driver, light segments S1…S32 one at a time (`set_segment`), then prepare an alternative image in bank B with `write_bank` and flip between A and B every 500 ms with `show_bank`, then switch to duplex (`set_mode(True)`) and walk S1…S32 on BP1 then BP2, and finish by clearing the display.

## Timing Constraints

- **Power-on reset:** internal; the display is blank afterwards. The datasheet states no delay before the first I²C transfer (the sibling PCF8576 requires 1 ms; the drivers wait 1 ms after power-up as a precaution — derived).
- **VDD / VLCD:** apply and remove both together (static voltages across the LCD otherwise cause artifacts).
- **I²C:** ≤ 100 kHz — a clock-rate property.
- **Conformance:** the datasheet gives no checkable timing, so `specs/display/pcf8577c_timing.conf` defines no checks.

## Implementation Notes

- **Write-only:** the chip never answers a read; use only `write`.
- **Control byte first:** every transfer starts with the control byte; a transfer that contains only the control byte (STOP right after) changes MODE/BANK without touching the segment registers (use it to flip banks).
- **Auto-increment step:** +2 in direct drive (so a plain 4-byte write loads one bank), +1 in duplex; the SBV rolls over `0x3F` → `0x00` across cascaded devices.
- **Cascading:** up to eight devices (A0–A2 strapped differently) are loaded in a single transfer if their subaddresses are contiguous; the control byte is loaded into **all** of them.
- **Duplex mode:** the A2 pin becomes BP2, so the subaddress range is limited and V5 is undefined (bank/MODE bits still apply to all devices).
- **Output expander:** unused segment outputs can act as simple outputs; the LCD bias levels apply, so this is not a general logic-level output.
- **Datasheet:** NXP PCF8577C Rev. 5, downloaded from `https://www.nxp.com/docs/en/data-sheet/PCF8577C.pdf`.

## Sigrok Decoder

Decoder id `pcf8577c`, input `['i2c']`. Matches I²C address `0x3A`. Decodes the control byte (MODE, BANK, subaddress V5:V3, register V2:V0) and the following segment bytes (hex and the lit segments S1–S32 with the BP1/BP2 split in duplex mode), notes the SBV auto-increment, and warns on read accesses (R/W = 1), on control-byte-only transfers that change nothing but BANK (informational) and on more segment bytes than the cascade accepts. No timing annotation pair is emitted.
