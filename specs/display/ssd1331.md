# Chip Spec: SSD1331

**Manufacturer:** Solomon Systech (module: Waveshare 0.95inch RGB OLED)  
**Datasheet:** `datasheets/display/SSD1331.pdf` (SSD1331 Rev 1.0, Jul 2006)  
**Category:** `display`  
**Transports:** SPI (4-wire, write-only; no BUSY output, RES# optional); the chip also has 6800/8080 parallel interfaces, not covered

## Overview

The SSD1331 is a driver/controller for a **96 x 64 RGB passive-matrix OLED**: 65k-colour (RGB 5-6-5) or 256-colour (RGB 3-3-2) graphic display RAM, a built-in 63-step gray-scale table, an internal oscillator, a **graphic acceleration** engine (line, rectangle with fill, copy, dim window, clear window) that works directly on the display RAM, and continuous horizontal/vertical scrolling. It needs an external OLED supply VCC (about 12 V on the module's boost).

In serial mode the chip is **write-only**. Unlike the e-paper controllers, **command parameters are sent with D/C# low** like the command byte itself; only pixel data is sent with D/C# high.

## Transport Configuration

### SPI (4-wire)
- **Mode:** CPOL=0 CPHA=0 (Mode 0), MSB first
- **Clock:** the datasheet's write cycle is 150 ns (6.6 MHz); the vendor demo ran at about 3 MHz. Driver default 4 MHz
- **CS#:** the vendor demo uses one CS# window per byte; a CS# window may also span many bytes
- **Framing:** D/C# low = command byte **or** command parameter, D/C# high = display data
- **Interface select:** pins BS1/BS0 strap the interface; 4-wire SPI on the module
- **Reset:** RES# low for at least 3 us, then 100 ms before the first command (the vendor holds it 100 ms)
- **BUSY:** none. `DisplayConnection` is used with `busy = None`; the driver never waits
- **Delay:** the display-on command must follow the VCC rise by about 100 ms; the connection offers `delay_ms()`

## Command Set

Graphic acceleration commands act on the display RAM, so a framebuffer kept by the host is **not** updated by them.

## Display RAM

96 x 64 pixels. In 65k mode a pixel is two bytes sent high byte first, **RGB 5-6-5**; in 256-colour mode one byte RGB 3-3-2. After `0x15`/`0x75` the pointer starts at (start column, start row) and increments inside the window (horizontal increment: column first). A whole frame is `96 x 64 x 2 = 12 288` bytes.

## Initialization Sequence

From the vendor capture (`sigrok/tests/ssd1331/SSD1331 Init and Pattern.sr`, 12 MHz) with the datasheet's power-save values:

1. RES# low 100 ms, high; wait 100 ms.
2. `AE`; contrast `81 FF`, `82 FF`, `83 FF`; master current `87 06`; second pre-charge `8A 64`, `8B 78`, `8C 64`.
3. `A0 72` (65k, column remap, COM scan N-1 -> 0, COM split odd/even); `A1 00`; `A2 00`; `A4`; `A8 3F`; `AD 8E`.
4. `B0 0B` (the vendor writes `00`, which the datasheet does not define); `B1 31`; `B3 F0`; `BB 3A`; `BE 3E`; `2E`.
5. Wait 100 ms (the vendor 200 ms for the VCC rise), then `AF`.

`hw_*` colours are RGB565 values converted to 5/6/5 bit operands.

## Data Conversion

```
rgb565(r, g, b) = ((r & 0xF8) << 8) | ((g & 0xFC) << 3) | (b >> 3)
byte order      = high byte first
index           = (y * 96 + x) * 2
hw colour C/B/A = R5 << 1, G6, B5 << 1     # E[5:1], F[5:0], G[5:1]
master current  = (A + 1) / 16
```

## Timing Constraints

- **Reset:** RES# low >= 3 us; wait 100 ms before the first command (vendor).
- **Display on:** about 100 ms after VCC is stable (vendor 200 ms).
- **Frame transfer:** 12 288 bytes; ~33 ms at 3 MHz.
- **Conformance:** no timing bound; see `specs/display/ssd1331_timing.conf`.

## Implementation Notes

- **Parameters with D/C# low:** `DisplayConnection.send_command(cmd, params)` sends the parameters with D/C# **high**, which is wrong for this chip; the driver sends every byte as its own command (`send_command(byte)`).
- **`DisplayConnection.delay_ms`:** added for the display-on wait; no BUSY to poll.
- **Vendor `B0 00`:** undefined in the datasheet; the driver writes `0B`.
- **Contrast channel order:** the datasheet names the channels A, B, C; which of them is red/green/blue on the module is determined on hardware (see Hardware status).
- **No read-back:** serial mode is write-only; there are no `read_*` methods.
- **Power:** the module's boost generates VCC; the OLED ages: keep contrast moderate and use `display_off()` when idle.
- **Hardware status:** C++ demo (STM32Cube) verified on the Waveshare 0.95inch RGB OLED (NUCLEO-F411RE, 3.1 MHz, channel order correct).
