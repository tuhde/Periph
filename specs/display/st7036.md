# Chip Spec: ST7036

**Manufacturer:** Sitronix (module: Electronic Assembly / Display Visions **EA DOGM162W-A**, "DOG series 3.3 V")  
**Datasheet:** `datasheets/display/st7036.pdf` (ST7036 V1.1, 2003-12-24), module `datasheets/display/dog-me.pdf` (DOG series, 02.2022)  
**Category:** `display`  
**Transports:** SPI (4-wire, write-only: SI, SCL, CSB, RS = C/D; XRESET optional; **no BUSY and no read-back**); the chip also has 4-/8-bit 6800 parallel and (ST7036i) I²C interfaces, not covered

## Overview

The ST7036 is a dot-matrix **character LCD controller/driver** (HD44780/ST7066U-compatible instruction set plus an extension table): 80-byte DDRAM, a character generator ROM (240–256 characters, mask option) and a CGRAM for up to 8 user characters (5 x 8 dots), 16 x 5-bit ICON RAM (not wired on the DOG modules), an on-chip **voltage booster, V0 generator with software contrast (6 bit), bias divider and temperature-compensated follower**, so the DOG modules run from 3.3 V or 5 V with only two small capacitors. The DOG series modules combine it with a chip-on-glass FSTN/STN panel: **DOGM081** (1 x 8), **DOGM162** (2 x 16), **DOGM163** (3 x 16). The reference module is the **EA DOGM162W-A** (2 x 16, white/FSTN, 5.57 mm characters) with an optional separate LED backlight (EA LED55x31-x, external series resistor, **not driven by the chip**).

On the DOG modules the interface is strapped to **4-wire serial** (PSB = L; E = H). The chip is **write-only** in serial mode: `R/W` is not available, the busy flag cannot be read, so every instruction is followed by a **fixed wait** (≥ 26.3 µs; 1.08 ms for Clear/Return Home at the slowest oscillator).

## Transport Configuration

### SPI (4-wire serial)
- **Mode:** CPOL=0 CPHA=0 (Mode 0): SI is latched on the rising edge of SCL, SCL idles low, MSB (D7) first
- **Clock:** SCL cycle ≥ 200 ns at 2.7–4.5 V (≤ 5 MHz), ≥ 100 ns at 4.5–5.5 V; the COG outputs are weak, so the driver default is **1 MHz** and the datasheet advises extra waits on long buses
- **CS# (CSB):** active low; **a falling CSB edge resets the 8-bit shift counter**, so every byte is its own CSB window (the `DisplayConnection` already frames every transfer with CS). CSB-to-SCL setup 20 ns, hold ≥ 200–350 ns
- **Framing:** RS = C/D low = instruction byte, RS high = data byte (DDRAM / CGRAM / ICON RAM write); RS setup ≥ 10 ns before and hold ≥ 150–250 ns after the transfer. `DisplayConnection.send_command(byte)` and `send_data(single byte)` give exactly this; **every instruction is one byte with no parameters**
- **Reset:** XRESET low ≥ 100 µs (rise time ≤ 100 ns), then wait ≥ 40 ms before the first instruction. XRESET may be tied high (the internal reset then needs VDD to rise in 0.1–10 ms); the module has a `RESET` pin
- **BUSY:** none. `DisplayConnection` is used with `busy = None`
- **Delays:** needs the connection's `delay_us(us)` and `delay_ms(ms)` (new `delay_us`, see Implementation Notes)

## Pin Configuration

EA DOGM162W-A, 40 pin FPC (datasheet page 8); serial mode uses:

| Module pin | Name | Function |
|-----------|------|----------|
| 23 | PSB | **L** = serial mode (strap to VSS) |
| 26 / 27 | VDD / VSS | supply 3.3–5 V / GND |
| 28 | D7 = **SI** | serial data in |
| 29 | D6 = **SCL** | serial clock |
| 36 | E | tie to VDD in serial mode (application drawing) |
| 38 | CSB | chip select, active low |
| 39 | RS | **C/D**: L = command, H = data |
| 40 | RESET | active low |
| 21 / 22 | CAP1N / CAP1P | booster capacitor 0.1–1 µF between them |
| 24 / 25 | VOUT / VIN | booster output / input; VOUT to GND via 0.47–2.2 µF, VIN to VDD |
| 30–35, 37 | D5–D0, R/W | unused in serial mode; tie to VDD (application drawing, `dog-me.pdf` page 4) |

Two capacitors are required for 3.3 V operation (CAP1N–CAP1P 0.1–1 µF, VOUT–GND 0.47–2.2 µF); at 5 V VIN = VDD and the application drawing shows no capacitors. Backlight pins A1/A2/C1/C2 need an external current-limiting resistor (EA LED55x31: parallel connection 14 Ω at 3.3 V for the amber variant, 1.6 Ω for white/blue; **never connect directly to 3.3/5 V**).

## Instruction Set

All instructions are single bytes sent with RS low. `IS[2:1]` of Function Set selects the instruction table (the DOG modules have the extension option enabled, EXT = L). Execution times are for the slowest specified oscillator (350 kHz); the driver waits **30 µs** after every instruction and **2 ms** after Clear / Return Home.

### Table 0 (IS[2:1] = 00) and always available

| Instruction | Code | Bits | Wait | Description |
|-------------|------|------|------|-------------|
| Clear Display | `0x01` \| | 2 ms \| write `0x20` to all DDRAM, address 0, I/D = 1 |
| Return Home | `0x02` | | 2 ms | address 0, undo display shift; DDRAM unchanged |
| Entry Mode Set | `0x04 \| I/D<<1 \| S` | I/D: 1 = increment (cursor right), S: 1 = shift display on write | 30 µs | `0x06` = increment, no shift |
| Display ON/OFF | `0x08 \| D<<2 \| C<<1 \| B` | D display, C cursor, B blink | 30 µs | `0x0C` display on, `0x0F` + cursor + blink |
| Cursor/Display Shift | `0x10 \| S/C<<3 \| R/L<<2` | S/C: 1 = display, 0 = cursor; R/L: 1 = right | 30 µs | no DDRAM change; display shift moves all lines |
| Function Set | `0x20 \| DL<<4 \| N<<3 \| DH<<2 \| IS2<<1 \| IS1` | DL = 1 (8-bit; irrelevant in SPI), N: 1 = 2 lines (**also set for 3-line modules**), DH: double height, IS: table select | 30 µs | `0x38` = 2 lines, table 0; `0x39` = table 1; `0x3A` = table 2 |
| Set CGRAM Address | `0x40 \| A5..A0` | char `n` (0–7), row `r` (0–7): address `n*8 + r` | 30 µs | following data writes go to CGRAM |
| Set DDRAM Address | `0x80 \| A6..A0` | | 30 µs | following data writes go to DDRAM |

### Table 1 (IS[2:1] = 01)

| Instruction | Code | Bits | Description |
|-------------|------|------|-------------|
| Bias Set | `0x14 \| BS<<3 \| FX` | BS: 0 = 1/5 bias, 1 = 1/4 bias; FX = 1 for the 3-line module, 0 otherwise (bits 2..1 are fixed `10` in the instruction table; the generic init flow chart labels the low bits `F2..F0`, the DOG examples confirm the table) \| `0x14` / `0x15` (3-line) at 3.3 V, `0x1C` / `0x1D` at 5 V |
| Set ICON Address | `0x40 \| AC3..AC0` | ICON RAM address 0–15 (not wired on DOG modules) |
| Power/ICON/Contrast high | `0x50 \| Ion<<3 \| Bon<<2 \| C5<<1 \| C4` | Ion: ICON display, Bon: booster, C5, C4: contrast high bits |
| Follower Control | `0x60 \| Fon<<3 \| Rab2..Rab0` | Fon: voltage follower, Rab: V0 amplification 1 + Rb/Ra = 1, 1.25, 1.5, 1.8, 2, 2.5, 3, 3.75 |
| Contrast low | `0x70 \| C3..C0` | contrast low bits |

Table 2 (IS = 10) holds `Double Height Position Select` (`0x10 | UD<<3` for the 3-line module: UD = 1 double height on COM1–16, 0 on COM9–24). Table 3 is reserved.

### Contrast and supply

Contrast value `C = C5..C0` (0–63); the V0 follower gives `V0 = (1 + Rb/Ra) x VREF` with `VREF = VDD x (C + 36) / 100` (saturating at VOUT; with the booster VOUT ≤ 2 x VDD, and `|VOUT − V0|` must stay > 0.5 V). The booster is only needed at 3.3 V. DOG-series presets (data sheet page 7):

| Module / supply | Function Set | Bias | Power (`0x5x`) | Follower | Contrast low | C5..C0 |
|-----------------|--------------|------|----------------|----------|--------------|--------|
| DOGM081, 3.3 V | `0x31` \| `0x14` \| `0x55` (booster on) \| `0x6D` \| `0x7C` | 0x1C |
| DOGM081, 5 V | `0x31` \| `0x1C` \| `0x51` (booster off) \| `0x6A` \| `0x74` | 0x14 |
| **DOGM162, 3.3 V** | `0x39` \| `0x14` \| `0x55` \| `0x6D` \| `0x78` | 0x18 |
| DOGM162, 5 V | `0x39` \| `0x1C` \| `0x52` \| `0x69` \| `0x74` | 0x24 |
| DOGM163, 3.3 V | `0x39` \| `0x15` \| `0x55` \| `0x6E` \| `0x72` | 0x12 |
| DOGM163, 5 V | `0x39` \| `0x1D` \| `0x50` \| `0x6C` \| `0x7C` | 0x0C |

(The 1-line DOGM081 uses N = 0: Function Set `0x31` / `0x30`.) Bias bit 0 (`FX`) is 1 for the 3-line module and 0 otherwise.

## Display RAM

DDRAM holds 80 character codes; the visible window and line start addresses depend on the module:

| Module | Lines x columns | DDRAM line start addresses |
|--------|-----------------|----------------------------|
| DOGM081 | 1 x 8 | `0x00` (to `0x4F`, scrolls with display shift) |
| DOGM162 | 2 x 16 | `0x00`, `0x40` (line 1 `0x00–0x27`, line 2 `0x40–0x67`) |
| DOGM163 | 3 x 16 | `0x00`, `0x10`, `0x20` |

Writing a data byte stores the character code at the address counter and increments (or decrements) it according to Entry Mode; **the address does not wrap to the next line** (after column 16 of line 1 the cursor is at `0x10`, outside the visible area), so the driver sets the DDRAM address at the start of every line.

Character codes `0x20–0x7F` are ASCII, `0xA0–0xFF` the built-in extension (page 5 of `dog-me.pdf`); **CGRAM** provides 8 user characters at codes `0x00–0x07` (and mirrored `0x08–0x0F`): 8 rows of 5 bits (bit 4 = leftmost pixel) per character.

## Initialization Sequence

From the datasheet's serial-interface flow with the DOGM162 3.3 V preset (`dog-me.pdf` page 7), RS low for every byte:

1. After power-up (or XRESET pulse ≥ 100 µs low) wait ≥ 40 ms.
2. `0x39` Function Set (8-bit, 2 lines, table 1) — wait 30 µs. (The vendor flow sends `0x38` first and then `0x39`; one Function Set is enough on the DOG modules.)
3. `0x14` Bias Set (1/5) — 30 µs; `0x78` Contrast low — 30 µs; `0x55` Power/booster on/C5 C4 — 30 µs; `0x6D` Follower on, Rab = 5 — **wait 200 ms** (booster/V0 settle).
4. `0x38` Function Set back to table 0 — 30 µs; `0x0C` Display on (cursor off) — 30 µs.
5. `0x01` Clear Display — 2 ms; `0x06` Entry Mode (increment) — 30 µs.

## Implementation Stages

### Minimal

Primary use: print text on a 2 x 16 DOGM162 at 3.3 V with a reasonable contrast.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` \| `connection` | - | Runs the Initialization Sequence for DOGM162 at 3.3 V; display on, cursor off |
| `clear` | - | - | Clear Display, 2 ms |
| `home` | - | - | Return Home |
| `set_cursor` \| `col, row` | - | DDRAM address = row start + col; out-of-range ignored |
| `write` \| `text: str` \| - \| each byte as a data transfer with a 30 µs gap; text is encoded to the built-in character set (ASCII passes through; other characters become `?`) |
| `write_char` \| `code` | - | one raw character code |
| `print_at` \| `col, row, text` \| - \| `set_cursor` + `write` |

**Constants:** `COLUMNS = 16`, `ROWS = 2`.

### Full

Extends Minimal with all remaining chip functions and the other DOG modules.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` (constructor options) \| `lines (1,2,3), columns, supply (3.3 V / 5 V), contrast=None` \| - \| module presets from the table above; `contrast` overrides C5..C0 |
| `display` \| `on` \| - \| Display ON/OFF `D` bit |
| `cursor` \| `on, blink` \| - \| `C`, `B` bits |
| `set_entry_mode` \| `increment, shift` \| - \| `I/D`, `S` |
| `shift_cursor` / `shift_display` \| `right: bool` | - | Cursor/Display Shift |
| `return_home` | - | - | Return Home (undoes display shift) |
| `set_ddram_address` \| `address` | - | raw address for scrolling use |
| `set_contrast` \| `value 0..63` \| - \| `C5..C0` via Power high byte + Contrast low byte (keeps `Bon`, `Ion`) |
| `set_booster` \| `on` \| - \| `Bon` |
| `set_follower` \| `on, ratio 0..7` \| - \| `Fon`, `Rab` |
| `set_bias` \| `quarter: bool` \| - \| bias 1/5 or 1/4 (`FX` follows the line count) |
| `create_char` \| `index 0..7, rows[8]` \| - \| writes CGRAM (`0x40 | index*8`), then restores the DDRAM address |
| `set_double_height` \| `on, upper=True` \| - \| `DH` (1-line module) or `DH` + `UD` (3-line module); forbidden on 2-line (`N = 1, DH = 1` in the datasheet) → ignored |
| `icon` \| `on` \| - \| `Ion` (no icons on the DOG modules) |
| `write_icon` \| `address 0..15, value` | - | Set ICON Address + data write |
| `send_command` / `send_data` \| `byte` | - | raw access |

`set_contrast`, `set_booster`, `set_follower` and `set_bias` switch the instruction table (`IS = 01`) and back; the driver caches `N`, `DH`, `Bon`, `Ion`, `C5..C4`, `Fon`, `Rab` so a single field can change.

## Data Conversion

```
ddram_address(col, row) = row_start[row] + col        # row_start: 1 line [0x00], 2 lines [0x00, 0x40], 3 lines [0x00, 0x10, 0x20]
instruction            = bits, e.g. Display ON/OFF = 0x08 | (D << 2) | (C << 1) | B
contrast C5..C0        -> Power byte 0x50 | Ion<<3 | Bon<<2 | C5<<1 | C4 ; Contrast byte 0x70 | C3..C0
V0                     = (1 + Rb/Ra) x VDD x (C + 36) / 100     # clipped to VOUT
cgram_address(n, r)    = n*8 + r, data byte = 5-bit row pattern (bit 4 = leftmost)
```

## Timing Constraints

- **Power-up / reset:** wait ≥ 40 ms after VDD is stable (or after XRESET rises); XRESET low ≥ 100 µs.
- **Between instructions/data bytes:** ≥ 26.3 µs (350 kHz oscillator; 14.3 µs at 700 kHz); the driver and the datasheet's code use 30 µs.
- **Clear Display / Return Home:** 1.08 ms at 380 kHz (up to ~1.2 ms at 350 kHz); the driver waits 2 ms.
- **Booster/follower settle:** 200 ms after Follower Control before the display is switched on (vendor code); on a 5 V supply without booster ≈ 2 ms suffices but the driver keeps the 200 ms.
- **SPI:** SCL cycle ≥ 200 ns (≤ 4.5 V) / 100 ns (≥ 4.5 V); CSB hold ≥ 350 ns / 200 ns; RS hold ≥ 250 ns / 150 ns.
- **Conformance:** no stated bound can be checked as a start/end annotation delta (all are minimum waits); see `specs/display/st7036_timing.conf`.

## Implementation Notes

- **Write-only:** no `read_*` methods, no busy-flag polling; every call waits the fixed time above.
- **30 µs between bytes needs `delay_us`:** at 1 MHz a byte takes 8 µs, so back-to-back `send_data` calls would exceed the chip's rate. `write(text)` therefore sends **one byte per CS window and waits 30 µs between bytes**. The `DisplayConnection` gains a public `delay_us(us)` next to `delay_ms(ms)` (C++ has `delayUs()` protected today). Where the host cannot sleep for microseconds precisely (Linux userspace, MicroPython) the wait is simply longer, which is harmless.
- **`DisplayConnection.send_command(cmd, data)`** sends its parameter bytes with D/C# high; the ST7036 has no parameters, so the driver calls `send_command(byte)` and `send_data([byte])` separately.
- **Never `send_data` with more than one byte per call** (the following bytes would be clocked without the 30 µs gap).
- **RS (C/D) vs the connection's D/C#:** same signal; CS (CSB) is hardware CS of the connection, RESET = RES#.
- **Table switching:** extension instructions (bias, power/contrast, follower) are only valid while `IS1 = 1`; the driver always restores `IS = 00` (and the cached `N`/`DH`) afterwards.
- **3-line module (DOGM163):** `N = 1` in Function Set plus `FX = 1` in the bias byte; the address layout differs (see Display RAM).
- **Supply:** the 3.3 V preset uses the booster (`Bon = 1`) and needs the 2 x 1 µF capacitors; at 5 V the booster is off. Wrong values give a blank or fully dark display, not damage.
- **Backlight:** separate LED unit with an external resistor; not controlled by the driver (power it from a GPIO/PWM through a transistor if dimming is wanted).
- **No hardware verification yet:** nothing is verified on a module.
- **Character set:** the DOG ROM is the `st7036` mask ROM shown on page 5 of `dog-me.pdf`; the `write(text)` helper maps ASCII only.

## Sigrok Decoder

Decoder id `st7036` (`sigrok/st7036/`), stacks on `display_spi` (SI = MOSI, SCL = SCLK, CSB, RS = D/C, RESET): annotation rows `Data` (instructions decoded by name and fields, data bytes accumulated into text per line with the DDRAM address tracked), `Status` (RESET) and `Warnings` (a byte earlier than 26.3 µs after the previous one, 2 ms Clear/Home violations, a data byte with CS not toggled between bytes, DDRAM writes outside the visible window, extension instruction while `IS = 00`). The decoder also decodes CGRAM writes as 5x8 pixel patterns.
