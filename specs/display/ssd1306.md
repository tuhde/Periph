# Chip Spec: SSD1306

**Manufacturer:** Solomon Systech  
**Datasheet:** `datasheets/display/ssd1306.pdf` (SSD1306 Rev 1.1, April 2008, 59 pages, plus the charge-pump application note Rev 0.4, January 2009, appended to the same PDF; from `https://cdn-shop.adafruit.com/datasheets/SSD1306.pdf`)  
**Category:** `display`  
**Transports:** I²C, SPI (4-wire) — the issue requested I²C; the 4-wire SPI interface uses the same command set and is covered like the sibling SH1106 / SSD1305 specs

## Overview

The SSD1306 is a single-chip CMOS OLED/PLED driver with controller for monochrome dot-matrix graphic panels of up to **128 × 64** pixels: 128 segment (column) outputs, 64 common (row) outputs, 128 × 64 bits of display RAM (GDDRAM), an on-chip oscillator, an **internal charge-pump regulator** that makes the 7.5 V OLED supply VCC from the 3.3–4.2 V battery supply VBAT (or VCC can be supplied externally, 7–15 V), 256-step contrast control, row / column remapping, hardware horizontal and diagonal scrolling, a display start line and programmable multiplexing (16–64). It supports 8-bit 6800 / 8080 parallel, 3-/4-wire SPI and 400 kHz I²C interfaces; this spec covers **I²C and 4-wire SPI**. It is the chip behind the very common 0.96″ 128 × 64 and 0.91″ 128 × 32 OLED modules.

Differences from its siblings: unlike the SH1106 and SSD1305 the SSD1306 has an exact 128-column RAM (no column offset) and three memory-addressing modes (page, horizontal, vertical); the reset default is **page addressing**, so snippets that assume horizontal addressing need `0x20 0x00`. The SSD1306 has no dim mode, area-colour or look-up-table commands.

The two transports share one command set. The driver family is therefore a base class holding the command logic and framebuffer with two transport hooks: `Ssd1306Minimal` / `Ssd1306Full` (I²C) and `Ssd1306SpiMinimal` / `Ssd1306SpiFull` (SPI) — see Implementation Notes.

## Transport Configuration

### I²C
- **Address:** `0x3C` (SA0 = VSS) — `0x3D` (SA0 = VDD); 7-bit address `0111 10 SA0`, with the D/C# pin acting as SA0 (the same two addresses as the SH1106, SSD1305, PCF8578 / PCF8579)
- **Max clock:** 400 kHz (tcycle ≥ 2.5 µs)
- **Identity register:** none; chip has no ID register (`registry/chips.json` entry has `"id_probe": null`; it shares `0x3C`/`0x3D` with the SH1106, SSD1305 and PCF8578/PCF8579, which cannot be told apart)
- **Probe safety:** `write_sensitive` — every byte after the address and a control byte is a command or display data
- **Interface select pins:** BS0 = 0, BS1 = 1, BS2 = 0 (tied on the module). SDAIN (D1) and SDAOUT (D2) are shorted together as SDA (if SDAOUT is left open the acknowledge is ignored; the datasheet notes the ITO track resistance can prevent a valid ACK level)
- **Protocol:** write = `[addr+W] [control byte] [data byte(s)] …`. The **control byte** is `Co D/C# 0 0 0 0 0 0`: `Co = 1` means one data byte follows and then another control byte; `Co = 0` means all remaining bytes in the transaction are data. `D/C# = 0` → the data is a command, `D/C# = 1` → display RAM data. So a command stream is `0x00, cmd, cmd, …` (or `0x80, cmd` per command) and a RAM stream is `0x40, d0, d1, …`. The GDDRAM column pointer increments after every data write
- **Read:** this revision of the datasheet describes only the I²C **write** mode (Figure 8-7); the status read exists in the parallel interfaces ("no status read is provided for serial mode"). The driver does **not** read over I²C — it keeps a framebuffer
- **Register addressing:** none — plain `Connection` (`write`), not `RegisterConnection`

### SPI (4-wire)
- **Mode:** CPOL=0 CPHA=0 (Mode 0) — SDIN is shifted in on the rising SCLK edge (D7 first); the idle level is not named in the datasheet, Mode 0 is the usual choice (confirm on hardware)
- **Max clock:** 10 MHz (tcycle ≥ 100 ns, clock high / low ≥ 20 ns); drivers default to 4 MHz
- **Bit order:** MSB first
- **CS active:** low (CS# may be hard-wired low on a dedicated bus)
- **Framing:** a plain byte stream — no opcode or address bytes. The **D/C# pin** is sampled on every eighth clock: `D/C# = 0` → the byte is a command, `D/C# = 1` → display RAM data. SPI goes through a `DisplayConnection` (`specs/transport_display.md`), which owns D/C, RES and CS; the driver sends command bytes with `send_command()` and display RAM data with `send_data()`
- **Read:** not possible over SPI ("Under serial mode, only write operations are allowed")
- **3-wire SPI (9-bit frames) and the parallel interfaces are not supported** (the byte-oriented SPI connection cannot send 9-bit frames)
- **Interface select pins:** BS0 = 0, BS1 = 0, BS2 = 0; D2 left open, D3–D7, E and R/W# tied to ground

## Command Set

All commands are single bytes sent with D/C# = 0; multi-byte commands are a mode byte followed by data bytes in the same command stream. Reset values are in parentheses. Patterns not in this table "are prohibited to enter the chip as a command; as unexpected results can occur".

| Command | Code | Description |
|---------|------|-------------|
| Set lower column address | `0x00 \| A[3:0]` | Low nibble of the column pointer, **page addressing mode only** (reset `0x00`) |
| Set higher column address | `0x10 \| A[3:0]` | High nibble of the column pointer, page addressing only; columns 0–127 (`0x00`–`0x7F`) |
| Set memory addressing mode | `0x20`, then `A[1:0]` | `00` horizontal, `01` vertical, `10` page (reset), `11` invalid |
| Set column address range | `0x21`, then start, end | Horizontal / vertical modes: start 0–127 (reset 0), end 0–127 (reset 127); also sets the column pointer to start |
| Set page address range | `0x22`, then start, end | Horizontal / vertical modes: start 0–7 (reset 0), end 0–7 (reset 7); also sets the page pointer to start |
| Set display start line | `0x40 \| A[5:0]` | RAM line shown at COM0 (0–63; reset 0) |
| Set contrast | `0x81`, then `00`–`FF` | Contrast / segment current (reset `0x7F`) |
| Charge pump setting | `0x8D`, then `0x10` / `0x14` | `0x14` enable, `0x10` disable (reset); must be set before `0xAF` (application note) |
| Segment re-map | `0xA0` / `0xA1` | `0xA0`: column 0 ↔ SEG0 (reset); `0xA1`: column 127 ↔ SEG0 |
| Set vertical scroll area | `0xA3`, then A[5:0], B[6:0] | A = rows in the fixed top area (reset 0), B = rows in the scroll area (reset 64); A + B ≤ MUX ratio |
| Entire display on | `0xA4` / `0xA5` | `0xA4` follows RAM (reset); `0xA5` forces all pixels on (RAM kept) |
| Normal / inverse | `0xA6` / `0xA7` | `0xA6` RAM 1 = pixel on (reset); `0xA7` inverted |
| Multiplex ratio | `0xA8`, then `0F`–`3F` | Ratio = data + 1: 16…64 MUX (reset `0x3F`); data 0–14 invalid |
| Display off / on | `0xAE` / `0xAF` | `0xAE` off = sleep (reset); `0xAF` on |
| Set page start | `0xB0 \| A[2:0]` | Page 0–7, page addressing only |
| COM scan direction | `0xC0` / `0xC8` | `0xC0` COM0→COM[N−1] (reset); `0xC8` reversed (takes effect immediately, flips the picture vertically) |
| Display offset | `0xD3`, then `00`–`3F` | Vertical shift by COM (reset 0) |
| Clock divide / oscillator | `0xD5`, then `A7:A4 osc, A3:A0 div−1` | Divide ratio = A[3:0] + 1 (reset 1); oscillator frequency increases with A[7:4] (reset `0x80` = `1000b`; fOSC 333–407 kHz at the reset setting) |
| Pre-charge period | `0xD9`, then `A7:A4 phase2, A3:A0 phase1` | DCLKs, 1–15, `0` invalid (reset `0x22`) |
| COM pins configuration | `0xDA`, then `00 A5 A4 0010` | A[4] = 0 sequential, 1 alternative (reset `0x12`); A[5] = 1 enables COM left / right remap |
| VCOMH deselect level | `0xDB`, then `0 A6 A5 A4 0000` | `0x00` ≈ 0.65·VCC, `0x20` ≈ 0.77·VCC (reset), `0x30` ≈ 0.83·VCC |
| NOP | `0xE3` | No operation |

### Graphic acceleration (scroll) commands

| Command | Code | Description |
|---------|------|-------------|
| Horizontal scroll setup | `0x26` (right) / `0x27` (left), then `0x00`, B, C, D, `0x00`, `0xFF` | Seven bytes in all: A dummy `0x00`; B[2:0] start page; C[2:0] step interval (`000` 5 frames, `001` 64, `010` 128, `011` 256, `100` 3, `101` 4, `110` 25, `111` 2 frames); D[2:0] end page (≥ B); E dummy `0x00`; F dummy `0xFF`. One column per step |
| Vertical + horizontal scroll setup | `0x29` (right) / `0x2A` (left), then `0x00`, B, C, D, E | Six bytes in all: A dummy; B, C, D as above; E[5:0] vertical offset per step in rows (1–63); E = 0 gives plain horizontal scrolling |
| Deactivate scroll | `0x2E` | Stops scrolling; **RAM data must be rewritten afterwards** |
| Activate scroll | `0x2F` | Starts the scroll configured by the last `0x26/0x27/0x29/0x2A` command (the last setup command wins) |

Send `0x2E` before changing scroll setup (otherwise RAM may be corrupted). While scrolling is active **RAM access (data write or read) and changing the horizontal scroll parameters are prohibited**.

### Power-on / reset defaults

Display off (segments VSS, commons high-impedance), 128 × 64 mode, page addressing mode, normal segment and scan mapping (SEG0 ↔ address 0, COM0 ↔ address 0), start line 0, column pointer 0, contrast `0x7F`, normal (non-inverted) display, entire display follows RAM, charge pump disabled, multiplex 64, clock divide 1 at oscillator setting `1000b`, pre-charge 2 / 2, COM alternative, VCOMH `0x20`, shift register cleared. The display RAM contents are **undefined** at power-up; clear it before the display is switched on.

## Display RAM

128 columns × 8 pages × 8 bits = 128 × 64 bits. One data byte holds 8 vertical pixels of one column of one page: **bit 0 (D0) is the top row of the page**, page 0 is at the top at start line 0 (COM0–COM7).

- **Page addressing (reset default; used by the driver):** set the page (`0xB0|p`) and the column pointer (`0x00|low`, `0x10|high`), then write data bytes; the column pointer **auto-increments after every data write** and wraps from the end column back to the start column **without** changing the page. Moving to the next page needs a new page + column command.
- **Horizontal addressing (`0x20 0x00`):** the column pointer increments after every data byte; at the end column (set with `0x21`) it returns to the start column and the page pointer advances (range set with `0x22`); after the last page both wrap to the start. The whole screen can be written as one continuous stream.
- **Vertical addressing (`0x20 0x01`):** the page pointer increments first and wraps at the end page, then the column advances.
- In horizontal / vertical mode the page / column-pointer commands `0xB0…` / `0x00…` / `0x10…` have no effect; in page mode `0x21` / `0x22` have no effect.

Segment mapping: with `0xA0` column `n` drives SEG`n`; with `0xA1` column `127 − n` drives SEG`n`. Row mapping: `0xC0` normal, `0xC8` reversed. Most 0.96″ modules are mounted so that `0xA1` + `0xC8` gives an upright picture — the driver exposes `set_flip`.

## Initialization Sequence

Per the datasheet's power-on sequence and the charge-pump application note (internal VCC):

1. Apply VDD (and VBAT). After they are stable pulse RES# low for ≥ 3 µs (`connection.reset()` pulses it low for `reset_pulse_us ≥ 3` and releases it, then waits `reset_settle_ms`). All registers are reset after the pulse.
2. Wait ≥ 3 µs after RES# goes low, then power on VCC (board-level when `external_vcc`; with the charge pump VCC is generated by command `0x8D`).
3. Send the setup commands in one command stream with the display off: `0xAE`, `0xD5 0x80` (clock, reset value), `0xA8 height−1` (multiplex), `0xD3 0x00` (offset 0), `0x40` (start line 0), `0x8D 0x14` (charge pump on; `0x8D 0x10` for external VCC), `0x20 0x02` (page addressing), `0xA0|ADC`, `0xC0|(scan<<3)`, `0xDA 0x12` (alternative COM; `0x02` for 32-row panels), `0x81 0x7F` (contrast), `0xD9 0x22`, `0xDB 0x20`, `0xA4` (follow RAM), `0xA6` (normal).
4. Clear the display RAM (8 pages × 128 bytes of `0x00`, one page + column set per page) before turning the display on.
5. `0xAF` (display on); the datasheet says SEG/COM are on after tAF = 100 ms — wait 100 ms before relying on the picture.

Power-off: `0xAE`, switch VCC off (with the charge pump enabled send `0x8D 0x10` first), wait tOFF (typ. 100 ms), then switch off VDD. VDD must never be removed before VCC, and VCC/VDD must never be pulled to ground.

## Data Conversion

```
page, bit      = y // 8 , y % 8
fb[page][x]    = framebuffer byte for column x of that page            (x = 0..width-1)
set pixel      : fb[page][x] |=  (1 << bit)     clear: &= ~(1 << bit)

show() (page mode):  for p in 0..height/8-1:
            cmd stream: 0xB0|p, 0x00, 0x10                                  (column 0)
            data stream: fb[p][0..width-1]

show() (horizontal mode):
            cmd stream: 0x21, 0, width-1, 0x22, 0, height/8-1
            data stream: fb[0][0..width-1], fb[1][0..width-1], …

I²C control bytes:  0x00  = last control byte, following bytes are commands
                    0x80  = command byte follows, then another control byte
                    0x40  = last control byte, following bytes are display data
SPI:  D/C# low for command bytes, D/C# high for data bytes
Frame rate     = fOSC / (D × K × MUX)      D = divide ratio, K = 54 DCLKs per row (2 + 2 + 50), MUX = multiplex ratio
Segment current = contrast / 256 × IREF × 8   (IREF = 12.5 µA → 100 µA at contrast 0xFF; 0xAF ≈ 69 µA, 0x3F ≈ 25 µA)
```

## Timing Constraints

- **Reset:** RES# low ≥ 3 µs; registers are reset after the pulse.
- **Power sequence:** VDD first, RES# low ≥ 3 µs (t1), wait ≥ 3 µs (t2) after RES# low, then VCC; after VCC is stable send `0xAF` — SEG/COM turn on after tAF = 100 ms. Power-off: `0xAE`, VCC off, tOFF typ. 100 ms, then VDD off. VDD must not be removed before VCC. These are recommended waits, not hard limits.
- **I²C:** tcycle ≥ 2.5 µs (≤ 400 kHz), start hold / setup ≥ 0.6 µs, stop setup ≥ 0.6 µs, data setup ≥ 100 ns, data hold ≥ 300 ns (SDAIN), bus idle time tIDLE ≥ 1.3 µs between transmissions.
- **SPI (4-wire):** SCLK cycle ≥ 100 ns (clock high / low ≥ 20 ns), D/C# setup / hold 15 ns, CS# setup 20 ns / hold 10 ns, data setup / hold 15 ns — hence the 4 MHz default (10 MHz maximum).
- **Frame rate:** fOSC 333–407 kHz at the reset setting; frame frequency = fOSC / (D × 54 × MUX), ≈ 100 Hz at 64 MUX.
- **Scrolling:** after `0x2E` (scroll off) the RAM must be rewritten; scroll setup commands must not be issued while scrolling is active; no RAM access while scrolling is active.
- **Conformance:** none of these has a bus-decodable start / end annotation pair that the host controls (the delays are recommended waits after commands, not measured events), so `specs/display/ssd1306_timing.conf` defines no checks.

## Implementation Notes

- **One base class, two transports:** implement an abstract base (`_Ssd1306Base`) with the framebuffer, drawing, and command logic and two hooks `write_commands(bytes)` / `write_data(bytes)`. The I²C classes prepend the control byte (`0x00`/`0x40`) to every transaction (one `connection.write` per stream, chunked to the platform's maximum write size; every chunk of data repeats the `0x40` control byte); the SPI classes call `DisplayConnection.send_command()` / `send_data()`, which drive D/C low/high and frame each transfer with CS.
- **Plain `Connection`, not `RegisterConnection`:** the control byte is not a register address; the same style as the PCF8576, SH1106 and SSD1305 drivers. The SPI connection must not fold read/burst bits into the first byte.
- **I²C transaction sizes:** some platform I²C layers limit a write to 32 bytes (Arduino `Wire`); chunk RAM data accordingly (each chunk a fresh `0x40` control byte; the column pointer keeps advancing between chunks). One RAM page is 128 bytes.
- **Charge pump:** `0x8D 0x14` must be sent **before** `0xAF` (application note); with the pump disabled (`0x10`, reset) the board must supply VCC (7–15 V) externally. The pump needs VBAT 3.3–4.2 V and the capacitors C1/C2 (modules include them). Many vendor sketches combine the pump with pre-charge `0xD9 0xF1` and VCOMH `0xDB 0x40` for a brighter picture — those values are **not in this datasheet**; if a module looks dim, try `set_precharge(1, 15)` and `set_vcomh(0x40)`.
- **Addressing mode:** the reset mode is *page addressing* (same as SH1106 / SSD1305), so snippets that assume horizontal addressing show garbage unless `0x20 0x00` is sent. In page mode the column pointer wraps within the page and the page never advances on its own. `set_addressing_mode` changes how `show()` writes; mixing modes without it corrupts the picture. In horizontal mode `0x21` / `0x22` also reset the pointers.
- **Module differences:** 128 × 32 modules need MUX 32 (`0xA8 0x1F`) and sequential COM wiring (`0xDA 0x02`); 128 × 64 modules use alternative COM wiring (`0xDA 0x12`); some 0.96″ modules are wired so that `0xA1` + `0xC8` is the "upright" orientation. The driver takes `height` and `set_flip` rather than a module name.
- **Scrolling:** the scroll engine runs in hardware; after `0x2E` the datasheet requires the RAM to be rewritten, so `scroll_stop` re-sends the framebuffer. RAM access while scrolling is active is prohibited — `show` and `show_page` raise an error while a scroll is active; the caller must call `scroll_stop` first. The scroll interval codes are not monotonic (`000` = 5 frames, `001` = 64, `010` = 128, `011` = 256, `100` = 3, `101` = 4, `110` = 25, `111` = 2); the datasheet writes "25 frame" for code `110` — taken as 25 frames. The driver takes a table index 0–7. The seven-byte horizontal setup ends with the dummy bytes `0x00`, `0xFF`; the diagonal setup is six bytes (a dummy first).
- **No read access:** this datasheet revision describes no readable serial interface; the driver keeps a framebuffer instead (the SH1106 / SSD1305 drivers' `read_status` / `read_page` are not specified here).
- **Read-modify-write commands (`0xE0` / `0xEE`) do not exist** on the SSD1306 (they are SH1106 / SSD1305 commands); do not send them. The SSD1306 also has no `0xAD`, `0xAB`, `0xAC`, `0xD8`, `0x82`, `0x91`–`0x93` commands.
- **SSD1306 vs SSD1306Z:** the datasheet covers the bare die (SSD1306Z) and the TCP (SSD1306TR1); the command set is the same.
- **Not covered:** parallel (6800/8080) and 3-wire SPI interfaces, the external-clock mode (CLS low), the FR (frame-sync) pin.
- **Datasheet revision:** Rev 1.1 (April 2008) with the charge-pump application note Rev 0.4 (January 2009); Rev 1.1 predates the later "Advance Information" editions. The SPI mode (idle level) is not stated and is marked above as derived.

## Sigrok Decoder

Two decoders sharing one command table: `ssd1306` (input `['i2c']`, addresses `0x3C`/`0x3D`) and `ssd1306_spi` (input `['spi']`; the D/C# line is read from an optional logic channel, otherwise every transfer is shown as raw bytes). The I²C decoder splits each write into control bytes (`Co`, `D/C#`) and payload; command payloads are decoded into named commands with arguments (column nibbles combined into a column number, page, start line, contrast, charge pump enable, ADC, invert, multiplex, display on / off, scan direction, offset, clock divide / oscillator, pre-charge, COM config, VCOMH, addressing mode, column / page ranges, scroll setup / activate / deactivate / area); multi-byte commands consume their data bytes, and data payloads are shown with the current page and column (auto-incrementing per the active addressing mode, wrapping at column 127 in page mode) and a count; each data byte can be rendered as an 8-pixel column. Warnings: a command byte not in the table (including the SSD1305 / SH1106-only commands `0xAD`, `0xAB`, `0xD8`, `0xE0`, `0xEE`), RAM data written while a scroll is active, a scroll setup command issued while scrolling is active, `0xAF` sent before `0x8D 0x14` when the display has only seen the reset charge-pump state ("display on without charge pump — VCC must be external"), and a write whose first control byte has `Co = 0`/`D/C# = 0` but no command bytes. No timing annotation pair is emitted (the datasheet delays are recommendations, not measured events).
