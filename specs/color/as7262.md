# Chip Spec: AS7262

**Manufacturer:** ams OSRAM  
**Datasheet:** `datasheets/color/as7262.pdf` (AS7262 6-Channel Visible Spectral_ID Device, v4-00, 2022-11-30)  
**Category:** color  
**Transports:** I²C (the chip also has a UART/AT-command interface, selected by the `I2C_ENB` pin, not covered)

## Overview

The AS7262 is a 6-channel visible-light spectral sensor: six photodiode channels with 40 nm FWHM centred at 450 nm (violet, V), 500 nm (blue, B), 550 nm (green, G), 570 nm (yellow, Y), 600 nm (orange, O) and 650 nm (red, R), a 16-bit ADC per channel, programmable gain (1×, 3.7×, 16×, 64×), an electronic shutter (integration time 2.8 ms × 1…255), two programmable LED driver outputs (an indicator LED up to 8 mA and a driver LED up to 100 mA), an on-chip temperature sensor, and calibrated single-precision float outputs for every channel next to the raw 16-bit counts. Spectral conversion uses two photodiode banks (V/B/G/Y and G/Y/O/R); a full six-channel result needs two integration times. Typical uses: color matching and identification, spectral-ID of materials, food/plant analysis, light-source classification. The register interface is implemented as **virtual registers** behind three hardware I²C registers (status/write/read), so each access is a small handshake.

## Transport Configuration

### I²C
- **Address:** `0x49` (7-bit, fixed; the datasheet gives the 8-bit write address `0x92` / read `0x93`); one AS7262 per bus (the AS7263/AS7265x family uses the same address)
- **Max clock:** 400 kHz (also standard mode 100 kHz)
- **Hardware registers:** `0x00` STATUS (read-only: bit 1 `TX_VALID`, bit 0 `RX_VALID`), `0x01` WRITE (write-only), `0x02` READ (read-only). All sensor registers are **virtual registers** reached through these three; see Implementation Notes for the handshake. Multi-byte virtual registers (16-bit raw data, 32-bit float calibrated data) are big endian and must be read in ascending address order, one byte at a time
- **Identity register:** virtual `HW_Version` (`0x00`) = `0x40` (device type) and `0x01` = `0x3E`; it needs the virtual-register handshake, so it cannot be described as a single `write_read` and `id_probe` is `null` in `registry/chips.json`
- **Probe safety:** `write_sensitive` — every data byte written to hardware register `0x01` is a virtual register address (bit 7 set = pending write); stray bytes can start a virtual write

## Register Map

### Hardware registers (I²C slave)

| Address | Name | R/W | Description |
|---------|------|-----|-------------|
| `0x00` | STATUS | R | Bit 1 `TX_VALID` (1 = WRITE register occupied, do not write), bit 0 `RX_VALID` (1 = READ register holds a byte) |
| `0x01` | WRITE | W | Virtual register address (bit 7 = 1 for a pending write) and write data |
| `0x02` | READ | R | Virtual register read data |

### Virtual registers

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | HW_VERSION (type) | R | `0x40` | Device type |
| `0x01` | HW_VERSION | R | `0x3E` | Hardware version |
| `0x02`–`0x03` | FW_VERSION | R | — | Firmware version (minor/sub, major/minor) |
| `0x04` | CONTROL_SETUP | R/W | `0x08` | Reset, interrupt enable, gain, bank mode, data ready |
| `0x05` | INT_T | R/W | `0xFF` | Integration time × 2.8 ms |
| `0x06` | DEVICE_TEMP | R | — | Device temperature, °C (byte) |
| `0x07` | LED_CONTROL | R/W | `0x00` | LED enables and current limits |
| `0x08`–`0x13` | V, B, G, Y, O, R raw | R | — | 6 × 16-bit raw counts (high byte first) |
| `0x14`–`0x2B` | V, B, G, Y, O, R calibrated | R | — | 6 × 32-bit IEEE-754 single (big endian) |

Writes use the virtual address with bit 7 set (`0x84`, `0x85`, `0x87`); reads use the plain address.

### Bit Fields

#### `CONTROL_SETUP` (`0x04` / `0x84`)

| Bits | Name | Description |
|------|------|-------------|
| 7 | RST | `1` = soft reset; returns to 0 by itself |
| 6 | INT | `1` = enable the INT pin output |
| 5:4 | GAIN | `00` 1×, `01` 3.7×, `10` 16×, `11` 64× |
| 3:2 | BANK | `00` mode 0 (V,B,G,Y; continuous), `01` mode 1 (G,Y,O,R; continuous), `10` mode 2 (all six; continuous, default), `11` mode 3 (all six; one-shot) |
| 1 | DATA_RDY | `1` = data ready (sets INT active when enabled); cleared when a sensor data register is read |
| 0 | RSVD | reserved |

#### `INT_T` (`0x05` / `0x85`)

| Bits | Name | Description |
|------|------|-------------|
| 7:0 | INT_T | integration time = `value × 2.8 ms` (default `0xFF` = 714 ms; the minimum is 2.8 ms for one bank) |

#### `LED_CONTROL` (`0x07` / `0x87`)

| Bits | Name | Description |
|------|------|-------------|
| 5:4 | ICL_DRV | `LED_DRV` current limit: `00` 12.5 mA, `01` 25 mA, `10` 50 mA, `11` 100 mA |
| 3 | LED_DRV | `1` = enable the driver LED output |
| 2:1 | ICL_IND | `LED_IND` current limit: `00` 1 mA, `01` 2 mA, `10` 4 mA, `11` 8 mA |
| 0 | LED_IND | `1` = enable the indicator LED output |

## Initialization Sequence

1. Power up VDD1/VDD2 (2.7–3.6 V), select I²C with `I2C_ENB` low; the chip boots its firmware (the datasheet gives no boot time: poll the virtual `HW_VERSION` until `0x40` is returned, time-out 2 s).
2. Soft reset (virtual write `CONTROL_SETUP` ← `0x80`), then wait until `CONTROL_SETUP.RST` reads 0 (no time given in the datasheet; time-out 1 s).
3. Write `INT_T` ← `0x3B` (59 × 2.8 ms = 165.2 ms) and `CONTROL_SETUP` ← gain 16× (`0x20`) with bank mode 3 (`0x0C`) → `0x2C` to start a one-shot conversion.
4. Poll `CONTROL_SETUP.DATA_RDY` (or wait for INT); read the six calibrated floats (`0x14`…`0x2B`) or the six raw words (`0x08`…`0x13`).

## Interrupt

| Property | Value |
|----------|-------|
| INT pin | `INT` — active-low, open-drain; requires an external pull-up |
| Level | 1 (single fixed condition: new spectral data ready) |
| Condition(s) | `DATA_RDY` = 1 with `CONTROL_SETUP.INT` = 1 (after the first integration time in bank mode 0/1, after two in mode 2/3) |
| Clear mechanism | read `CONTROL_SETUP` releases the INT line; reading a sensor data register clears `DATA_RDY` |

### Full driver interrupt API

| Method | Signature | Description |
|--------|-----------|-------------|
| `on_interrupt` | `on_interrupt(callback, int_pin=None)` | Enable `CONTROL_SETUP.INT`, subscribe on INT (falling edge) via `connection.int_pin` (or `int_pin`), otherwise a polling task calling `poll_interrupt` every `INT_T`; `callback(status)` receives `1` for data ready |
| `off_interrupt` | `off_interrupt()` | Unsubscribe and clear `CONTROL_SETUP.INT` |
| `poll_interrupt` | `poll_interrupt() -> int` | Reads `CONTROL_SETUP` (releases INT) and returns `DATA_RDY` (0 / 1) |

## Implementation Stages

### Minimal

Goal: read the six spectral channels with one call, no configuration beyond the connection.

| Operation | Parameters | Returns | Notes |
|-----------|------------|---------|-------|
| `init` | `connection` | — | Soft reset, then gain 16×, integration time `0x3B` (165.2 ms), bank mode 3 (one-shot), LEDs off, interrupt off |
| `read` | — | `{violet, blue, green, yellow, orange, red}` | One one-shot conversion (starts mode 3, polls `DATA_RDY`, timeout 1 s), returns the six calibrated float values |
| `temperature` | — | float | Device temperature in °C (`DEVICE_TEMP`) |

**Sensible defaults:** gain 16×, `INT_T = 0x3B` (165.2 ms; the datasheet's characterisation setting), one-shot bank mode 3, both LED outputs off, INT disabled.

## Data Conversion

```
raw[ch]   = (high << 8) | low                 # 16-bit counts, ch in V, B, G, Y, O, R
cal[ch]   = ieee754_single_be(b0, b1, b2, b3) # big endian, registers read in ascending order

integration_time_s = INT_T * 0.0028
one_shot_time_s    = 2 * integration_time_s   # mode 3 / mode 2 need two bank conversions
gain               = (1, 3.7, 16, 64)[GAIN]

irradiance_uw_cm2 ~ raw / (45 * (gain / 16) * (integration_time_s / 0.166))   # indicative, from the optical-characteristics table: 45 counts per uW/cm^2 at gain 16, 166 ms, accuracy +-12 %
temperature_c = DEVICE_TEMP                    # unsigned byte, degrees Celsius
```

The calibrated registers hold the calibrated channel values as floats; the datasheet does not publish their physical unit beyond "calibrated data", so the driver returns them unchanged. The irradiance estimate from the raw counts is indicative only.

## Timing Constraints

| Constraint | Value |
|------------|-------|
| Integration time | `INT_T × 2.8 ms` per bank (min. 2.8 ms) |
| One-shot (mode 3) six-channel conversion | `2 × INT_T × 2.8 ms` (330.4 ms at the Minimal default `INT_T = 0x3B`) |
| Mode 0/1 data ready | after one integration time; mode 2 after two |
| Boot after power-up | not specified; poll the virtual `HW_VERSION` (time-out 2 s) |
| I²C clock | ≤ 400 kHz |

**Conformance-checked constraint:** the one-shot conversion time at the Minimal defaults (`INT_T = 0x3B`, mode 3: 330.4 ms, 350 ms with margin) via the `conversion_start` / `conversion_done` annotation pair (the virtual write of `CONTROL_SETUP` with `BANK = 11` → the first read of `CONTROL_SETUP` with `DATA_RDY = 1`); see `as7262_timing.conf`.

## Implementation Notes

- **Virtual-register handshake:** the I²C slave exposes only STATUS (`0x00`), WRITE (`0x01`), READ (`0x02`). Write a virtual register: poll STATUS until `TX_VALID` = 0; write `reg | 0x80` to `0x01`; poll STATUS until `TX_VALID` = 0; write the data byte to `0x01`. Read a virtual register: poll STATUS until `TX_VALID` = 0; write `reg` (bit 7 clear) to `0x01`; poll STATUS until `RX_VALID` = 1; read `0x02`. Drain a stale byte (`RX_VALID` = 1) from READ before starting a read. Time-out the polls (about 1 s, a read/write takes a few ms).
- **Register-addressed connection:** the hardware registers are plain 8-bit addresses, so accept `RegisterConnection` (see `specs/feature_register_access_design.md`) and implement the virtual layer inside the driver.
- **Two banks, two integrations:** one-shot and mode 2 need two integration times; modes 0 and 1 give four channels per integration time and zero the other two.
- **`DATA_RDY` is cleared by reading a sensor data register,** and INT is released by reading `CONTROL_SETUP`; read the data bytes of one dataset in one burst to keep them consistent.
- **Multi-byte data:** big endian, read in ascending address order; the chip protects the remaining bytes of a multi-byte value after the first byte is read.
- **LED output polarity:** `LED_IND`/`LED_DRV` are open-drain current sinks; the LED anode is connected to the supply.
- **Soft reset** returns the registers to their defaults (including `INT_T = 0xFF`, bank mode 2), so `init` rewrites the configuration afterwards.
- **Address overlap:** `0x49` is shared with the TSL2561 (ADDR pin tied high) and the other AS726x/AS7265x parts; discovery must use the virtual `HW_Version` (`0x40`) to tell AS726x parts apart.
- **UART mode:** pin `I2C_ENB` high selects the UART/AT-command interface; this spec does not cover it.

## Sigrok Decoder

Decoder id `as7262`, input `['i2c']`. Matches I²C address `0x49`. Reassembles the virtual-register accesses from the three hardware registers (STATUS polling, WRITE address/data, READ data), annotates each virtual access with the register name, decodes `CONTROL_SETUP` (RST, INT, GAIN, BANK, DATA_RDY), `INT_T` (ms), `LED_CONTROL` (currents), the raw 16-bit channel values and the calibrated floats per channel, `DEVICE_TEMP` (°C), and the version registers, and warns on a write while `TX_VALID` was set and on reads without a preceding address. It emits the conformance pair `conversion_start` (the virtual write of `CONTROL_SETUP` with `BANK = 11`) and `conversion_done` (the first virtual read of `CONTROL_SETUP` with `DATA_RDY = 1`).
