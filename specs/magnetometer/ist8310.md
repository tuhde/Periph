# Chip Spec: IST8310

**Manufacturer:** iSentek  
**Datasheet:** `datasheets/magnetometer/ist8310.pdf` (IST8310 Datasheet, Version 1.8, 25 November 2025)  
**Category:** magnetometer  
**Transports:** I²C

> **Datasheet gap:** the public IST8310 datasheet (v1.8) documents electrical/magnetic characteristics, pins, the address-select table and the power-on reset, but **contains no register map or measurement protocol**. The register map below is taken from the widely used open-source drivers (e.g. the ArduPilot IST8310 compass backend) and marked *unverified*; it must be checked on hardware (or against iSentek's register application note) before the driver is considered complete. Values from the datasheet itself are not marked.

## Overview

The IST8310 is a 3-axis digital magnetometer based on AMR (anisotropic magnetoresistance) technology in a 3.0 × 3.0 × 1.0 mm 16-pin LGA. It has 14- or 16-bit output, a ±1600 µT range on X/Y and ±2500 µT on Z (0.3 µT/LSB, 3.3 LSB/µT = 330 LSB/G), ultra-low hysteresis (< 0.1 %FS), an on-chip set/reset mechanism (4.7 µF capacitor on C1), temperature compensation, a self-test function, a DRDY output pin and a RSTN reset pin. Output data rate is 1–200 Hz (20 µA at 1 sps to 1.2 mA at 200 sps), 1.72–3.6 V supplies (AVDD 2.8 V and DVDD 1.8 V typical) and an I²C interface up to 400 kHz. Typical uses: drone/flight-controller compasses, AR/VR, navigation and heading.

## Transport Configuration

### I²C
- **Address:** `0x0C` + CAD pins (7-bit): CAD0 = VSS, CAD1 = VSS → `0x0C`; CAD0 = VDD, CAD1 = VSS → `0x0D`; CAD0 = VSS, CAD1 = VDD → `0x0E`; both VDD → `0x0F`. Floating CAD0/CAD1 gives `0x0E` (datasheet v1.8). Tying the pins to different potentials causes IO leakage (46–92 µA)
- **Max clock:** 400 kHz (fast mode)
- **Register addressing:** 8-bit register address *(unverified)*; multi-byte reads auto-increment
- **Identity register:** `0x00` WAI = `0x10` *(unverified)* — feeds `registry/chips.json`; the address range `0x0C`–`0x0F` is shared with AK8975/AK8963 (WIA `0x48` / `0x48`)
- **Probe safety:** `register_pointer` — a 1-byte write sets the register pointer; only writes with data change state

## Register Map

*(unverified — see the datasheet-gap note)*

| Address | Name | R/W | Reset | Description |
|---------|------|-----|-------|-------------|
| `0x00` | WAI | R | `0x10` | Device ID |
| `0x02` | STAT1 | R | `0x00` | bit 0 DRDY (data ready), bit 1 DOR (data overrun) |
| `0x03`–`0x08` | DATAX_L … DATAZ_H | R | — | X, Y, Z, each int16 little-endian (low byte first) |
| `0x09` | STAT2 | R | `0x00` | interrupt/DRDY pin status |
| `0x0A` | CNTL1 | R/W | `0x00` | Operating mode; `0x01` triggers a single measurement |
| `0x0B` | CNTL2 | R/W | `0x00` | bit 0 SRST (soft reset), bit 2 DREN (DRDY enable), bit 3 DRP (DRDY polarity) |
| `0x0C` | STR | R/W | `0x00` | Self-test control |
| `0x41` | AVGCNTL | R/W | `0x24` | Averaging: bits 5:3 Y, bits 2:0 X/Z; `n` → 2ⁿ samples (0 = none … 4 = 16) |
| `0x42` | PDCNTL | R/W | `0xC0` | Pulse-duration control (`0xC0` = normal) |

## Initialization Sequence

1. Power up AVDD/DVDD (1.72–3.6 V); power-on reset completes within 50 ms (max); the chip enters standby. AVDD must have been below 0.1 V for ≥ 10 ms before a power-on reset is guaranteed.
2. Read `WAI` (`0x00`); expect `0x10`.
3. *(unverified)* Write `AVGCNTL` ← `0x24` and `PDCNTL` ← `0xC0` (16-sample averaging, normal pulse duration).
4. Single measurement: write `CNTL1` ← `0x01`, poll `STAT1` bit 0 (DRDY, timeout 50 ms), read 6 bytes from `0x03`.

## Data Conversion

```
raw = signed16(DATA_xH << 8 | DATA_xL)          # little endian
field_ut = raw / 3.3                              # 0.3 µT/LSB (datasheet: 3.3 LSB/µT)
heading_deg = (atan2(y, x) * 180 / pi + declination + 360) % 360
```

Dynamic range ±1600 µT (X, Y) and ±2500 µT (Z); the 14-bit output option is not documented in the public datasheet.

## Implementation Notes

- **Unverified register map:** values marked *(unverified)* come from open-source drivers, not the datasheet — confirm WAI, STAT1, data order and the CNTL/AVGCNTL/PDCNTL values on real hardware first.
- **Little-endian data** (low byte first), axis order X, Y, Z — unlike the HMC5883L (big-endian, X, Z, Y).
- **C1 capacitor:** the set/reset mechanism needs a 4.7 µF ceramic capacitor on C1 close to the chip; without it measurements are wrong.
- **CAD pins:** CAD0/CAD1 must be tied firmly (VSS/VDD); floating pins select `0x0E`.
- **Soft vs hard reset:** RSTN low resets the registers; SRST in `CNTL2` is the software equivalent.
- **Mounting:** keep magnets and steel away; the ±0.3 µT RMS zero-gauss offset is small, the dominant error is hard/soft iron from the host board.
- **Address overlap:** `0x0C`–`0x0F` is shared with AK8975/AK8963; WAI distinguishes them.

## Sigrok Decoder

Decoder id `ist8310`, input `['i2c']`. Matches I²C addresses `0x0C`–`0x0F`. Annotates register names for each access, decodes WAI (verified against `0x10`), `STAT1`, `CNTL1`, `CNTL2` and `AVGCNTL` into fields, and decodes 6-byte data reads from `0x03` into X/Y/Z in µT. No timing annotation pair is emitted.
