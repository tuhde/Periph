# Arduino Library Manager Integration

## Overview

The Arduino library is published to its own repository,
[`tuhde/Periph-Arduino`](https://github.com/tuhde/Periph-Arduino). The Library
Manager needs `library.properties` at a repository root and indexes every tag
of the registered repository, so it can't use this multi-language repo
directly (`library.properties` lives in `cpp/`, and the `vX.Y.Z` tags here
tag the whole project). Arduino's registry maintainers also don't accept a
library on a separate branch of a multi-layout repo, which is what the
earlier orphan `arduino` branch was.

`Periph-Arduino` is generated: never edit it by hand, and its README sends
issues and PRs here.

## Periph-Arduino layout

```
Periph-Arduino/
  library.properties   ← from cpp/, version stamped on each release
  LICENSE              ← from the repo root
  README.md            ← regenerated by cpp/scripts/generate-readme.js
  keywords.txt         ← regenerated by cpp/scripts/generate-keywords.js
  src/                 ← from cpp/src/  (all chips and transports)
    Periph.h           ← umbrella header, generated by cpp/scripts/generate-periph-header.js
  examples/            ← from cpp/examples/arduino/, .ino only, flattened to
                         <Chip>_<Tier>/<Chip>_<Tier>.ino (e.g. BME280_Minimal/)
```

`cpp/scripts/stage-arduino-library.sh <dir> [version]` produces exactly this
layout. The release workflow (repo push and zip) and the CI lint step both
call it, so the published library, the release zip and what CI checks can't
drift apart.

## Why `src/Periph.h`

The Arduino build system puts only the library's top-level `src/` on the
include path and finds a library by a header directly inside `src/`. Our
headers live in `src/connection/` and `src/chips/<category>/`, so sketches
include `<Periph.h>`, which includes all of them. Without it, arduino-lint
fails with LS001 ("Path does not contain a valid Arduino library") and no
installed example compiles.

## Every driver compiles on every core

The Arduino IDE compiles every `.cpp` in the library for every sketch, so one
driver that fails on a core breaks every sketch on that core. CI
(`.github/workflows/ci.yml`, job `arduino`) compiles all examples against
`cpp/` as one library on ESP32-S3 and on AVR (Mega 2560, C++11), and runs
arduino-lint in strict mode on the staged layout. Locally:

```
cpp/test_arduino_examples.sh --fqbn esp32:esp32:esp32s3
cpp/test_arduino_examples.sh --fqbn arduino:avr:mega
```

The AVR portability rules for driver code are in `AGENTS.md`.

## Releases

One branch (`main`), one commit and one tag per release. The tag name is the
same as the main repo's release tag (`vX.Y.Z`), and `library.properties`
carries `version=X.Y.Z`.

The `arduino-publish` job in `.github/workflows/release.yml` runs on every
`vX.Y.Z` tag push in this repo:

1. Checks out `tuhde/Periph-Arduino` with the `ARDUINO_REPO_DEPLOY_KEY` secret
   (an SSH deploy key with write access to that repo only)
2. Replaces its content with `cpp/scripts/stage-arduino-library.sh` (version stamped)
3. Commits "Release vX.Y.Z" (skipped if nothing changed) and tags `vX.Y.Z`
4. Pushes `main` and the tag

Rerunning the job for the same release is safe. If `vX.Y.Z` already exists in
`Periph-Arduino` on a different commit, the job fails instead of moving the
tag: the Library Manager never accepts the same version twice.

`release.sh` doesn't touch `Periph-Arduino`; only CI holds the deploy key.

## Registering with the Arduino Library Manager

Submit a pull request to
[`arduino/library-registry`](https://github.com/arduino/library-registry)
adding the repository URL to `repositories.txt`:

```
https://github.com/tuhde/Periph-Arduino
```

The registry check validates the repo's latest tag
(`git describe --tags $(git rev-list --tags --max-count=1)`); every tag in
`Periph-Arduino` is a library release, so that is always valid.

After the PR is merged, the indexer picks up every new `vX.Y.Z` tag within
about an hour. Then switch the `Arduino Lint` step in
`.github/workflows/ci.yml` from `library-manager: submit` to `update`
(`submit` fails once the name `Periph` is taken — by us).

Requirements to keep in mind:

- The `name=` in `library.properties` (`Periph`) must never change.
- Each release needs a `version=` no earlier release used (the release
  workflow stamps it from the tag).
