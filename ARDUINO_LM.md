# Arduino Library Manager Integration

## Overview

The library uses an orphan `arduino` branch so the Arduino Library Manager
can discover it. The branch has `library.properties` at the repo root, which
is required by the LM — the main branch cannot satisfy this because `library.properties`
lives in `cpp/`.

## Branch layout

```
arduino/
  library.properties   ← version stamped on each release
  README.md            ← regenerated by cpp/scripts/generate-readme.js
  keywords.txt         ← regenerated by cpp/scripts/generate-keywords.js
  src/                 ← from cpp/src/  (all chips and transports)
  examples/            ← from cpp/examples/arduino/, .ino only, flattened to
                         <Chip>_<Tier>/<Chip>_<Tier>.ino (e.g. BME280_Minimal/)
```

## Tagging scheme

Each release creates two tags:

| Tag | Branch | Purpose |
|-----|--------|---------|
| `v1.2.3` | `main` | GitHub Actions release trigger; PyPI, npm, crates.io, JVM artifacts |
| `arduino-v1.2.3` | `arduino` | Arduino Library Manager version index |

## How the branch is updated

### Via release.sh (local)

`release.sh` adds an arduino branch update section after pushing `main`:

1. Fetches `github/arduino` and opens it in a git worktree at `/tmp/periph-arduino`
2. Clears all content, copies `cpp/src/` and the flattened Arduino examples
3. Stamps the version in `library.properties`, regenerates `README.md` and `keywords.txt`
4. Commits, tags `arduino-vX.Y.Z`, removes the worktree
5. Pushes `arduino` branch and tag to both remotes via `git push all`

### Via GitHub Actions (CI)

The `arduino-branch` job in `.github/workflows/release.yml` runs on every
`vX.Y.Z` tag push and performs the same sync, committing and pushing
`arduino-vX.Y.Z` to `origin`.

## Registering with the Arduino Library Manager

Submit a pull request to
[`arduino/library-registry`](https://github.com/arduino/library-registry)
adding the repository URL to `repositories.txt`:

```
https://github.com/tuhde/Periph
```

The registry has no branch setting, and the indexer does not look at branches
at all: it scans **every tag** in the repository and treats each tag whose tree
has a valid `library.properties` at the root as a release. That is why the
`arduino` branch works without any extra configuration:

- `arduino-vX.Y.Z` tags point at `arduino` branch commits, which have
  `library.properties` at the root → indexed as release `X.Y.Z`.
- `vX.Y.Z` tags point at `main` commits, where `library.properties` lives in
  `cpp/` → skipped. The indexer logs an error for each of these tags; this is
  expected and harmless.

Requirements to keep in mind:

- The `name=` in `library.properties` (`Periph`) must not already be taken by
  another library in the registry — check before submitting.
- Each indexed tag must carry a `version=` that no earlier tag used. The release
  workflow stamps the release version, so this holds as long as a version is
  never re-released with different content.
- Registration only needs to happen once. After the PR is merged, every new
  `arduino-vX.Y.Z` tag appears as a new version in the Arduino IDE Library
  Manager (the indexer runs roughly hourly).
